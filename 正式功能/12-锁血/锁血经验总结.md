### 最优 Hook 点
`Entity$$OnEntityHurt`（0x10b3f470）

### 实现逻辑
1. Hook 函数 `Entity$$OnEntityHurt`
2. 校验当前 `this` 指针是否为本地玩家（通过 `GameManager_TypeInfo.static_fields->myPlayer` 对比判断）
3. 若为玩家自身：**跳过原函数执行**，实现不掉血效果
4. 若非玩家：正常执行原函数，不影响其他实体逻辑

## 四、Bug 分析与修复记录

### Bug #1: 栈偏移计算错误 (type字段写错位置) ⚠️

**现象**: 游戏仍然掉血，Hook 无效果

**原因**: `Entity_OnEntityHurt` 是 **`__cdecl`** 调用约定，参数从右到左入栈。在 `onEnter` 时：

```
旧代码: ESP+0x04+0x08 = ESP+0x0C  → 写到了 victim 字段 ❌
新代码: ESP+0x08+0x08 = ESP+0x10  → 正确写 type 字段 ✅

完整栈布局：
  [ESP+0x00] = return address (CALL压入)
  [ESP+0x04] = this (第1个参数)
  [ESP+0x08] = eventData结构体开始
    [ESP+0x08] = attacker     (4B)
    [ESP+0x0C] = victim       (4B)
    [ESP+0x10] = type         (4B) ← 目标位置!
```

**修复**: `espPtr.add(8).add(OFF.Dmg_type)` → 跳过 ret_addr(4B) + this(4B)

### Bug #2: 未 Hook Player 虚函数覆盖

**现象**: 玩家受伤时 Entity_OnEntityHurt 可能不被调用

**原因**: `Player` 类有虚函数表，`OnEntityHurt` 被 `Player` 覆盖。游戏通过虚表调用时，走的是 `Player_OnEntityHurt` (0xB516B0)，而非 `Entity_OnEntityHurt` (0xB3F470)

**修复**: 同时 Hook 两个入口地址，共用同一 handler

### Bug #3: 缺少诊断日志

**现象**: Hook 不生效时无法快速定位原因

**原因**: 原始脚本无任何 onEnter 日志，无法判断是 Hook 未触发、entity 比较失败、还是栈偏移错误

**修复**: 增加前 20 次触发的详细诊断日志：
- Hook触发次数与 entity 地址
- isMyPlayer 比较结果
- 修改前后的 type 值和目标内存地址

## 五、经验总结

### DamageEventData.type 值含义
| type值 | 含义 |
|--------|------|
| 4 | 跳过受伤处理 (Entity_OnEntityHurt 内部判断) |

### Hook 注意事项
1. **IL2CPP x86 调用约定**: 默认 `__cdecl` (参数从右到左入栈，调用者清栈)
2. **onEnter args[0]**: 等价于 __cdecl 的 `[ESP+4]` (this 指针)
3. **栈上结构体 (by value)**: `[ESP+8]` 起，不要忘记跳过 return address 和 this
4. **虚函数覆盖**: 父类 Hook 可能不触发，需同时 Hook 子类同名函数
5. **房间切换**: 玩家指针会变化，需定时刷新 cachedMyPlayer











# 无敌模式（不掉血）实现逻辑与经验总结（基于 `AAAAA-godmode_hp.js`）

## 一、核心原理

**Hook `Entity.OnEntityHurt`，在伤害事件处理前，将 `DamageEventData.type` 字段修改为 `4`，使游戏原生逻辑跳过掉血。**

- `type == 4`：游戏内的“免疫/无效”伤害类型，直接忽略后续扣血。
- 仅对**本地玩家**生效，其他实体（Bot、队友、敌人）正常受伤。

## 二、关键逻辑框图

```
[启用无敌]
    ↓
初始化 NativeFunction (isMyPlayer, isDead, singletonGetter)
    ↓
findMyPlayer() → 遍历 GM 的所有玩家列表，匹配本地玩家
    ↓
installHooks()
    ├─ Hook Entity_OnEntityHurt (0xB3F470)
    └─ Hook Player_OnEntityHurt (0xB516B0)  ← 兜底
    ↓
startRefresh() → 每 2 秒检查 myPlayer 是否仍存活，防止房间切换导致野指针
    ↓
[游戏触发伤害]
    ↓
Hook onEnter:
    - 检查 entity == cachedMyPlayer ?
    - 是 → 修改栈上的 type 字段为 4
    - 否 → 无操作
```

## 三、核心技术要点

### 3.1 定位本地玩家（`findMyPlayer`）

```javascript
function findMyPlayer() {
    var gm = getGM();
    var all = getAllPlayers(gm);   // 合并 allPlayers, playersBL, playersGR
    for (var i = 0; i < all.length; i++) {
        if (isMyPlayerFn(all[i], ptr(0))) return all[i];
    }
    return null;
}
```

- **`isMyPlayer`**：RVA `0xB55FD0`，来自 `Player.get_isMyPlayer()`，直接返回布尔值。
- **多列表合并**：`GM._allPlayers`（数组）存所有注册玩家，`GM._playersBL` 和 `GM._playersGR`（列表）分阵营存储。合并可提高容错。

### 3.2 栈上修改 `DamageEventData.type`

函数签名（__cdecl）：
```c
void Entity__OnEntityHurt(Entity_o* this, DamageEventData_o eventData, const MethodInfo* method);
```

栈布局（32位）：
```
[ESP+0x00] = return address      (4 bytes)
[ESP+0x04] = Entity* this        (第一个参数)
[ESP+0x08] = eventData.attacker  (结构体起始)
[ESP+0x0C] = eventData.victim
[ESP+0x10] = eventData.type      ← 我们要修改的地方
[ESP+0x14] = ...                 (结构体后续字段)
...
```

代码实现：
```javascript
var espPtr = ptr(this.context.esp.toString());
var typeFieldAddr = espPtr.add(8 + 8);  // ESP+0x08(结构体基址) + 0x08(type偏移)
typeFieldAddr.writeS32(4);
```

### 3.3 玩家存活监控与刷新

```javascript
setInterval(function() {
    if (!cachedMyPlayer) { /* 定期 findMyPlayer */ }
    else {
        // 检查 cachedMyPlayer 是否仍在 GM 的玩家列表中
        // 若不在（房间切换），则置空重新查找
    }
}, 2000);
```

避免玩家退出房间后 Hook 仍访问无效指针导致崩溃。

### 3.4 双重 Hook 保障

- `Entity_OnEntityHurt`（RVA `0xB3F470`）是基类虚函数。
- `Player_OnEntityHurt`（RVA `0xB516B0`）是子类重写，某些伤害可能直接调用子类版本。
- 同时 Hook 两者，确保所有伤害路径都被拦截。

## 四、`GameManager_TypeInfo.static_fields` 解释

这是 **Il2Cpp 元数据** 概念。

| 术语            | 说明                                                         |
| --------------- | ------------------------------------------------------------ |
| `TypeInfo`      | Il2Cpp 中每个类型的元数据对象，包含类型名称、大小、父类、静态字段等信息。 |
| `static_fields` | 指针，指向该类型所有**静态字段**的内存区域。在 Il2Cpp 中，静态变量不存储在堆上，而是放在一个由虚表分配的“静态字段池”中。 |
| 用法            | 如果想获取 `GameManager` 单例，可以通过 `TypeInfo.static_fields` 读取其静态字段 `_instance`。 |

在本脚本中，**没有直接使用** `TypeInfo.static_fields`，而是用了更直接的 **`Singleton<GameManager>.get_instance`** 方法（通过 MethodInfo* 调用），这是游戏内部提供的单例获取函数，更稳定。

**何时需要关注 `static_fields`**：当游戏中没有提供单例获取函数时，可以通过 dump.cs 找到 `GameManager_TypeInfo` 静态字段 `static_fields`，然后加上字段偏移（如 `+0x10` 为第一个静态字段）读取实例指针。

**结论**：游戏内部已经预留了一个 “type == 4 时不扣血” 的分支。因此脚本只需在 `onEnter` 中将栈上的 `type` 字段改为 4，就能让本地玩家免疫任何伤害，无需额外写血量或 Hook 其他函数。这就是无敌模式的简洁实现原理。
