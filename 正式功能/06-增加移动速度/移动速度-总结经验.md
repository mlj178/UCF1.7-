# 移动速度修改器 v1 脚本分析

## 1. 概述

`move_speed_v1-3.js` 是一个基于 Frida 的 Unity IL2CPP 游戏修改脚本，用于修改玩家的移动速度。  
核心原理：Hook `PropertyModifier.Get` 方法，拦截玩家 `Modifier_MoveSpeedRatio` 字段的查询，将其返回值修改为指定倍数，从而实现加速。

---

## 2. 关键内存偏移与函数

| 描述                        | 类/结构            | 偏移/RVA       | 说明                                                         |
| --------------------------- | ------------------ | -------------- | ------------------------------------------------------------ |
| 移动速度修改器字段          | `Player`           | `+0x8C`        | `Modifier_MoveSpeedRatio`，类型为 `PropertyModifier`         |
| `PropertyModifier.Get` 方法 | `PropertyModifier` | RVA `0xB17590` | 被 Hook 的函数，传入 `this` 和 `player` 指针，返回速度倍率   |
| 本地玩家判断函数            | `Player`           | RVA `0xB55FD0` | `Player.get_isMyPlayer()`，用于判断某个 Player 是否为本地玩家 |

- `PropertyModifier.Get` 的原型推测：`float Get(PropertyModifier* self, Player* player)`
- 脚本通过 `Interceptor.replace` 替换了原函数，在回调中检查是否属于玩家的 `MoveSpeedRatio` 修改器，若是则返回加速值。

---

## 3. 关键代码逻辑分析

### 3.1 模块定位与工具函数

```javascript
var gameAssembly = Process.findModuleByName("GameAssembly.dll");
// ...
isMyPlayerFn = new NativeFunction(base.add(0xB55FD0), 'bool', ['pointer']);
originalFn = new NativeFunction(hookAddr, 'float', ['pointer', 'pointer']);
```

- 获取 `GameAssembly.dll` 基址。
- 创建 `isMyPlayer` 的 `NativeFunction`，用于后续身份判断。
- 保存原始函数引用，以便在非目标调用时返回原始值。

### 3.2 核心 Hook 逻辑

```javascript
Interceptor.replace(hookAddr, new NativeCallback(function(self, player) {
    var result = originalFn(self, player);  // 先调用原函数获取真实值
    if (player && !player.isNull() && isMyPlayerFn(player)) {
        var moveMod = player.add(0x8C).readPointer();  // Player + 0x8C 获取 Modifier_MoveSpeedRatio 指针
        if (moveMod && !moveMod.isNull() && self.equals(moveMod)) {
            // 确认本次查询的 PropertyModifier 正是玩家的移动速度修改器
            return MOVE_SPEED_MULTIPLIER;  // 返回修改后的倍率
        }
    }
    return result;  // 其他情况返回原始值
}, 'float', ['pointer', 'pointer']));
```

**执行流程**：

1. 每次调用 `PropertyModifier.Get` 时都会进入此回调。
2. 首先执行原始函数，得到该修改器的原始值（可能为 1.0）。
3. 检查传入的 `player` 参数是否有效且为本地玩家。
4. 从玩家实例偏移 `0x8C` 读取 `Modifier_MoveSpeedRatio` 的指针。
5. 比较当前 `self`（即 `PropertyModifier` 实例）是否等于该指针，从而精确过滤出移动速度查询。
6. 如果匹配，直接返回预设的 `MOVE_SPEED_MULTIPLIER`（默认 3.0），覆盖原始返回值。

### 3.3 安全与日志

- 设置了日志计数器 `logCount`，前 10 次调用输出原始值和修改后值，便于调试。
- 启用/禁用控制函数暴露到全局，便于外部动态切换。

## 4. 内存路径图示

```
Player 实例
└─ +0x8C → Modifier_MoveSpeedRatio (PropertyModifier*)
                          │
                          └─ PropertyModifier.Get(this, player) 返回 float
```

当游戏需要计算玩家实际移动速度时，会调用 `Modifier_MoveSpeedRatio.Get(this, player)`，该函数返回一个倍率，再与基础速度相乘。  
Hook 拦截后直接返回 3.0，因此最终速度为原来的 3 倍。

---

## 5. 兼容性与通用性

- **全模式通用**：因为 `Player` 类和 `PropertyModifier.Get` 方法是所有游戏模式共用的基类成员，所以脚本在团队竞技、个人竞技、生化模式等所有模式下都能正常工作。
- **仅影响本地玩家**：通过 `isMyPlayer` 判断确保只有自己的移动速度被修改，不影响其他玩家或 AI。

---

## 6. 总结

该脚本采用了与快刀 v16 相同的“函数替换”策略（`Interceptor.replace`），干净、高效，且不依赖定时器。  
由于 `Modifier_MoveSpeedRatio` 是 UnityCrossFire 游戏引擎内建的属性修改器，其查询入口统一，因此修改稳定可靠。  

此方案可推广到其他 `PropertyModifier` 字段（如换弹速度、近战速度等），只需调整偏移和过滤条件即可。
