## 一、核心问题概述

### 1.1 问题现象

| 脚本 | 团队模式 | 特殊战 | 个人竞技 | 终结者模式 | 生化剑客模式 | 多人终结者模式 |
|------|---------|--------|---------|-----------|-------------|---------------|
| **time_freeze_nano6_modify_memory.js** | ❌ 无效 | ❌ 无效 | ❌ 无效 | ❌ 无效 | ❌ 无效 | ✅ 有效（有人类被感染时） |
| **time_freeze_all_modes_modify_memory.js** | ✅ 有效 | ✅ 有效 | ✅ 有效 | ✅ 有效 | ✅ 有效 | ✅ 有效 |

### 1.2 问题核心

**为什么time_freeze_nano6_modify_memory.js只在有人类被感染时才修改时间？**

**答案**: 脚本只Hook了`ModeBase_Nano.CheckRoundOver`方法，这个方法是生化模式特有的，只有生化模式（继承自ModeBase_Nano）才会调用。

**详细解释**:

1. **类继承关系**:
   ```
   ModeBase (基类)
   ├── Mode_TeamDeath (团队模式)
   ├── Mode_DeathMatch (个人竞技)
   └── ModeBase_Nano (生化模式基类)
       ├── Mode_Nano4 (终结者模式)
       └── Mode_Nano6 (多人生化模式)
   ```

2. **方法调用时机**:
   - `ModeBase_Nano.CheckRoundOver` - 只在生化模式下调用
   - `ModeBase.UpdateTimeUI` - 所有模式都会调用

3. **为什么有人类被感染时才生效**:
   - 生化模式开始时，游戏会创建`Mode_Nano6`实例
   - 当有人类被感染时，会触发`CheckRoundOver`检查
   - 此时脚本才能获取到实例地址并修改时间

## 四、跨模式失效原因

### 4.1 失效流程图

```
time_freeze_nano6_modify_memory.js 在非生化模式:

游戏启动 → 创建模式实例 (Mode_TeamDeath/Mode_DeathMatch等)
  ↓
游戏运行 → 调用 UpdateTimeUI() (基类方法)
  ↓
脚本只Hook了 CheckRoundOver() (生化模式特有方法)
  ↓
CheckRoundOver() 永远不会被调用
  ↓
modeBaseInstance 始终为 null
  ↓
时间修改永远不会执行 ❌
```

```
time_freeze_all_modes_modify_memory.js 在所有模式:

游戏启动 → 创建模式实例 (任意模式)
  ↓
游戏运行 → 调用 UpdateTimeUI() (基类方法)
  ↓
脚本Hook了 UpdateTimeUI() (基类方法)
  ↓
UpdateTimeUI() 每次更新UI时都会调用
  ↓
modeBaseInstance 被正确设置
  ↓
时间修改成功执行 ✅
```

### 4.2 为什么有人类被感染时才生效

**生化模式流程**:
```
游戏启动 → 创建 Mode_Nano6 实例
  ↓
等待游戏开始 → 人类玩家等待感染
  ↓
有人类被感染 → 触发 CheckRoundOver() 检查
  ↓
脚本获取到实例地址 → modeBaseInstance = args[0]
  ↓
开始修改时间 ✅
```

**关键点**:
- `CheckRoundOver()` 只在生化模式的特定事件（如感染）时调用
- 其他模式根本不会调用这个方法
- 所以脚本只在生化模式下，且有人类被感染时才生效

## 五、技术解决方案

### 5.1 方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| **方案 A: Hook基类方法** | 全模式通用 | 调用频率高 | 所有模式 ✅ |
| **方案 B: Hook生化方法** | 调用频率低 | 仅生化模式 | 生化模式 ❌ |
| **方案 C: 双Hook策略** | 兼顾所有模式 | 代码复杂 | 所有模式 ✅ |

### 5.2 推荐方案

**使用 time_freeze_all_modes_modify_memory.js 的双Hook策略**

**原因**:
1. ✅ 全模式通用（Hook基类UpdateTimeUI）
2. ✅ 生化模式额外优化（Hook CheckRoundOver）
3. ✅ 简单有效
4. ✅ 不依赖模式差异

### 5.3 代码实现

```javascript
// 第一部分：基类 ModeBase 方法（全模式通用）
var updateTimeUI = base.add(0xAF6930);  // ModeBase.UpdateTimeUI

Interceptor.attach(updateTimeUI, {
    onEnter: function(args) {
        // 所有模式都会调用
        modeBaseInstance = args[0];
        // 修改时间
    }
});

// 第二部分：生化模式特有方法（ModeBase_Nano）
var checkRoundOver = base.add(0xAEF8A0);  // ModeBase_Nano.CheckRoundOver

Interceptor.attach(checkRoundOver, {
    onEnter: function(args) {
        // 生化模式额外调用
        modeBaseInstance = args[0];
        // 修改时间
    }
});
```

## 六、总结与建议

### 6.1 核心结论

| 结论 | 说明 |
|------|------|
| **1. 基类方法是关键** | ModeBase.UpdateTimeUI 是所有模式共有的方法 |
| **2. 生化方法有限制** | ModeBase_Nano.CheckRoundOver 只在生化模式下调用 |
| **3. 双Hook策略最优** | 同时Hook基类和子类方法，实现全模式覆盖 |

### 6.2 最佳实践

| 实践 | 说明 |
|------|------|
| ✅ **Hook基类方法** | 使用 ModeBase.UpdateTimeUI 实现全模式通用 |
| ✅ **保留子类Hook** | 保留 ModeBase_Nano.CheckRoundOver 用于生化模式优化 |
| ✅ **实例缓存策略** | 缓存 modeBaseInstance，避免重复获取 |
| ✅ **安全检查** | 验证实例地址，避免内存冲突 |
| ❌ **避免单一Hook** | 不要只Hook子类方法，会导致其他模式失效 |

### 6.3 代码规范

```javascript
// ✅ 正确: 双Hook策略（全模式通用）
// 1. Hook基类方法
var updateTimeUI = base.add(0xAF6930);
Interceptor.attach(updateTimeUI, { ... });

// 2. Hook生化模式特有方法
var checkRoundOver = base.add(0xAEF8A0);
Interceptor.attach(checkRoundOver, { ... });

// ❌ 错误: 只Hook生化模式方法
var checkRoundOver = base.add(0xAEF8A0);
Interceptor.attach(checkRoundOver, { ... });
// 其他模式不会调用此方法，导致失效
```
