### 一、performance脚本只在团队模式生效的原因

**问题根源：** `no_recoil_performance.js` 中存在 Bot/玩家区分逻辑，使用了保守策略（只识别前2把武器为玩家武器），在某些模式下可能错误地将玩家武器识别为Bot武器，导致不生效。

**详细分析：**

```javascript
// isPlayerWeapon 函数中的逻辑
if (count < 2) {
    playerWeaponSet[key] = true;  // 只识别前2把武器
    return true;
}
```

**解决方案：**

1. **移除Bot/玩家区分**：直接对所有武器生效（像v4_fix和v14那样）。
2. **改进识别逻辑**：使用更可靠的Player对象查找方式，而不是简单计数。

### 二、三个脚本实现方式评估

| 脚本名称                   | 实现方式                                  | 核心思路                           |
| -------------------------- | ----------------------------------------- | ---------------------------------- |
| `no_recoil_v4_fix.js`      | 替换 `Recoil::OnGunShot`，直接清零4个字段 | 简单粗暴，全模式生效               |
| `no_recoil_performance.js` | 替换 `Recoil::OnGunShot`，区分Bot/玩家    | 试图只对玩家生效，但识别逻辑有缺陷 |
| `AAAAA-no_recoil_v14.js`   | 替换 `Recoil::OnGunShot`，直接清零4个字段 | 最简洁版本，全模式生效             |

### 三、优缺点对比

| 脚本            | 优点                                | 缺点                             |
| --------------- | ----------------------------------- | -------------------------------- |
| **v4_fix**      | 全模式生效，逻辑清晰                | 对Bot也生效（不影响体验）        |
| **performance** | 有降级方案（replace失败时用attach） | 只在团队模式生效，识别逻辑不可靠 |
| **v14**         | 代码最简洁，全模式生效              | 没有日志限制，可能刷屏           |

### 六、推荐方案

推荐使用 `v4_fix` 或 `v14`，因为：

- **全模式生效**：不受游戏模式限制，体验一致。
- **实现简单可靠**：直接修改核心后坐力字段，逻辑清晰，不易出错。
- **对Bot生效不影响玩家体验**：即使对Bot也生效，也不会对玩家的游戏体验造成负面影响。
