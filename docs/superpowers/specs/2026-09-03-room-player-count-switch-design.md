# 全模式房间人数：显式开关设计

## 目标

将整合包 2.5 的“全模式房间人数”改为显式控制：用户打开开关后，仍须点击“应用人数”才会向游戏进程写入人数补丁；关闭开关时立即恢复游戏原本的人数逻辑。

## 交互与状态

- 卡片显示与其它功能一致的开关、人数滑条和“应用人数”按钮。
- 开关打开只记录本次会话的启用意图，不写入 GameAssembly.dll，也不自动应用保存的人数。
- 只有在开关已打开且已连接兼容游戏时，“应用人数”才调用人数补丁。滑条变化只更新待应用值和本地保存的数值。
- 若开关关闭时点击“应用人数”，界面必须给出“请先开启功能”的提示，且不得隐式启用功能或写入补丁。
- 关闭开关立即调用现有恢复路径：停止诊断、恢复此脚本写入的固定代码与基础 100 人补丁，并发布关闭状态。

## 生命周期

- 人数值继续保存，以便下次用户手动开启后使用。
- 不保存“已启用”状态为启动恢复意图；重启修改器或重连游戏后，功能默认关闭，绝不自动写入人数补丁。
- 关闭或脚本清理时保持幂等：从未应用过人数、已恢复、或脚本未接管补丁时都不应报错。

## 实现范围

- 修改 `game_modifier/features/35_room_player_count/panel.py`：增加并管理开关，阻止未启用时的应用。
- 修改该功能的 `manifest.json` 和 `script.js`：使开关状态与运行时生命周期一致，并取消自动恢复。
- 修改/新增该功能的静态测试，覆盖开关存在、手动应用门控、关闭恢复和无自动恢复。

## 验证

- 先执行新增测试并确认其在旧实现上失败。
- 实现后运行该功能静态测试及相关 UI/生命周期测试。
- 检查变更范围，确认只包含本功能、规格和测试文件。
