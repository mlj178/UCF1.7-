# 25-人机暂停：最小实现步骤

## 目标

实现一个独立单功能工具，用开关暂停或恢复所有人机。

## 调用链路

不 Hook 游戏方法，直接写游戏已有的静态字段：

```text
GameAssembly.dll base
  + Bot_TypeInfo
  -> Bot_c
  + static_fields
  -> Bot_StaticFields
  + stopAllBot
```

## 关键地址和偏移

| 项目 | 值 | 来源 |
| --- | --- | --- |
| Bot_TypeInfo | 0xE25F44 | Il2CppDumper/script.json |
| Bot_c.static_fields | 0x5C | Il2CppDumper/il2cpp.h |
| Bot.stopAllBot | 0xC | Il2CppDumper/dump.cs |

## 推荐方案

用 Frida RPC 暴露四个接口：

```text
enable()  -> 写 Bot.stopAllBot = true
disable() -> 写 Bot.stopAllBot = false
status()  -> 读取当前字段值和地址信息
cleanup() -> 恢复 Bot.stopAllBot = false
```

这个功能不需要函数拦截。这里选择静态字段写入，是因为游戏本身已经提供了 `stopAllBot` 作为全局 Bot 暂停开关。

## 测试方式

```powershell
python -m unittest "05-正式功能\25-人机暂停\test_bot_pause_static.py" -v
node --check "05-正式功能\25-人机暂停\AAAAA-bot_pause_min.js"
python -m py_compile "05-正式功能\25-人机暂停\AAAAA-bot_pause_ui.py"
```

## 失败后继续查哪里

1. 如果 `Bot_TypeInfo` 为空，重新确认 `script.json` 中的 `Bot_TypeInfo` RVA。
2. 如果 `static_fields` 为空，确认当前游戏是否已初始化 Bot 类型。
3. 如果写入成功但游戏内无效果，进入有人机的模式后再切换一次，并观察 `status()` 的 `currentValue`。
4. 如果切房间后失效，继续保留当前方案，因为每次开关都会重新解析 TypeInfo 和 static_fields。
