# 直接变身救世主

## 目标

多人生化模式下，一键让本地玩家或存活 Bot 变成救世主。

## 关键 RVA

| 名称 | RVA |
| --- | --- |
| ModeBase.Update | 0x00AF6A00 |
| Mode_Nano4.get_instance3 | 0x00B467A0 |
| ModeBase_Nano.UpdateNanoRole | 0x00AF4FF0 |
| GameManager.GiveWeapon | 0x00AFB390 |
| Player.get_isMyPlayer | 0x00B55FD0 |
| Player.get_nanoRole | 0x00B56200 |
| HealthData.get_isDead | 0x00AE4830 |

## 原理

不直接调 `BecomeSavior`（内部 `BecomeHero` 改完角色后 HUD/雷达会抛 IL2CPP 错，武器也发不出去）。

改为：
1. `ModeBase_Nano.UpdateNanoRole(player, 18)`
2. `GameManager.GiveWeapon(player, 4270, autoGiveUp=0, autoSelect=1)`

已是救世主（18）时尝试补枪。

## 限制

- 仅多人生化相关 nano 模式（gameMode 3-6）
- 目标必须是佣兵；已是英雄/终结者会跳过
- 动作在 ModeBase.Update 主线程执行

## 踩坑（2026-09-11）

1. **nanoRole 偏移**：`SubscribeableProperty.value` 在对象头 `+0x08`，不是 `+0x00`。已优先走 `Player.get_nanoRole`。
2. **BecomeSavior 会抛错**：`BecomeHero` 先 `UpdateNanoRole` 再 HUD，Frida 报 `system error`，但角色可能已变成 18。故改直调。

## RPC

enable / disable / status / cleanup / trigger(`local_savior`|`bot_savior`) / setConfig

## 持久化日志与自动检查

- 调试 UI 每次启动会写 `logs/become_savior_ui_YYYYMMDD_HHMMSS.log`
- 日志包含：UI 操作、Frida 日志、`RPC_STATUS` 完整状态 JSON
- 测完后自动检查：

```powershell
$env:MIMO_PYTHON  # 或 python
& $env:MIMO_PYTHON check_logs.py
& $env:MIMO_PYTHON check_logs.py --all
```

- 结论：`PASS` / `WARN` / `INCOMPLETE` / `FAIL`
- 退出码：0 正常或不完整；1 发现问题；2 无日志
