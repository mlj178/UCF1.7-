# 玩家信息修改器-简要说明

## 功能目标

独立修改 UnityCrossFire 本地 `PlayerData.dat` 里的玩家基础信息：

```ini
[Player]
NickName=内個
Level=30
VipLevel=2
```

如果文件里没有 `[Player]`，工具会把这一段插入到 `[Inven]` 前面。
如果文件里已经有 `[Player]`，工具只更新 `NickName`、`Level`、`VipLevel`。
工具界面显示为中文：昵称、等级、VIP等级；文件内部键名仍保持英文，因为游戏按这些英文键读取。

## 默认文件路径

工具不会写死 `C:\Users\17242`，而是动态取当前 Windows 用户目录：

```text
%USERPROFILE%\AppData\LocalLow\Alexander_GaGa\UnityCrossFire\PlayerData.dat
```

示例：

```text
C:\Users\当前用户\AppData\LocalLow\Alexander_GaGa\UnityCrossFire\PlayerData.dat
```

## 文件说明

```text
player_profile_service.py
```

核心服务，只负责路径定位、读取 `[Player]`、更新文本、保存备份。
后续整合到整合包 2.3 时优先复用这个文件。

```text
AAAAA-player_profile_editor_ui.py
```

独立 CustomTkinter UI，只负责输入、按钮、日志和调用 service。
不注入游戏，不连接 Frida，不修改注册表。

```text
test_player_profile_service.py
```

轻量自动测试，验证路径、插入、更新和备份逻辑。

## 保存行为

保存前会自动备份旧文件：

```text
PlayerData.dat.bak
PlayerData.dat.bak.1
PlayerData.dat.bak.2
```

如果备份名已经存在，会自动递增，不覆盖旧备份。

## 使用建议

建议关闭游戏后再保存。
如果游戏正在运行，游戏自己的保存逻辑可能会把外部修改覆盖掉。

## 后续 2.3 接入建议

整合包 2.3 里不要重写文件读写逻辑。
建议直接复用：

```python
from player_profile_service import PlayerProfile, get_default_player_data_path, load_profile, save_profile
```

2.3 面板只需要收集用户输入，然后调用：

```python
save_profile(get_default_player_data_path(), PlayerProfile(nickname, level, vip_level))
```

这样可以保证独立工具和整合包使用同一套读写规则。
