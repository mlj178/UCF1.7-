# 单功能开发规范：面向正式发行版零改造接入

这份规范用于 `05-正式功能/XX-功能名/` 下的所有新功能。

目标不是只让单功能单独跑通，而是让它从开发第一天起就符合正式发行版结构。

最终要求：

```text
单功能目录 = 一个可迁移功能包
正式发行版 = 复制文件 + 注册功能 + 接 UI
不允许后期重写核心 JS
不允许后期重写 RPC
不允许后期重写状态管理
不允许后期为了整合大改旧功能
```

------

## 1. 核心原则

### 1.1 单功能必须按发行版标准写

以前的错误做法：

```text
05 单功能能跑就行
用自己的 launcher
用自己的 UI 调用方式
用自己的 JS 函数名
后期合并到 04 时再慢慢改
```

新的标准做法：

```text
05 单功能阶段就按 04 发行版接口写
单功能 UI 只是测试壳
JS、RPC、配置、日志、生命周期全部按发行版标准
后期合并只移动文件，不重写逻辑
```

------

## 2. 每个功能必须有唯一 feature_id

每个功能从创建开始就必须确定一个永久 ID。

格式：

```text
snake_case 小写英文
不能用中文
不能随版本变化
不能因为 UI 名称变化而变化
```

例子：

```text
infinite_ammo
no_recoil
fast_reload
third_person_camera
fast_stock
```

这个 `feature_id` 必须同时用于：

```text
JS 文件名
Python feature 文件名
manifest.json
日志前缀
RPC 调用
配置项 key
发行版注册名
UI 控件绑定名
测试文件名
```

错误例子：

```text
JS 叫 fast_stock.js
Python 叫 jisu_qiangtuo.py
UI 里叫 极速枪托
配置里叫 stockSpeed
RPC 里叫 enableFastButt
```

正确例子：

```text
feature_id: fast_stock
JS: fast_stock.js
Python: fast_stock.py
配置 key: fast_stock
RPC: enable / disable / status / cleanup / set_config
日志前缀: [fast_stock]
UI 显示名: 极速枪托
```

------

## 3. 标准单功能目录结构

每个功能目录必须使用这个结构：

```text
05-正式功能/XX-功能名/
├── manifest.json
├── scripts/
│   └── feature_id.js
├── features/
│   └── feature_id.py
├── ui/
│   └── feature_id_panel.py
├── docs/
│   ├── 功能名-最小实现步骤.md
│   ├── 功能名-实现原理.md
│   ├── 功能名-生命周期说明.md
│   └── 经验总结.md
├── tests/
│   ├── test_feature_id_static.py
│   └── check_feature_id.js
└── README.md
```

说明：

```text
scripts/       放正式可迁移 JS
features/      放正式可迁移 Python 功能定义
ui/            放正式可迁移 UI 面板或 UI 描述
docs/          放分析和经验
tests/         放静态检查和语法检查
manifest.json 发行版接入清单
```

临时文件可以存在，但必须放入：

```text
dev/
probe/
archive/
```

临时文件不允许参与发行版接入。

------

## 4. manifest.json 是必须文件

每个功能必须提供 `manifest.json`。

它的作用是告诉正式发行版：

```text
功能叫什么
文件在哪里
复制到发行版哪里
需要注册到哪里
UI 怎么显示
RPC 有哪些
配置项有哪些
依赖哪些 RVA / 字段偏移
测试怎么跑
```

标准模板：

```json
{
  "feature_id": "fast_stock",
  "display_name": "极速枪托",
  "category": "weapon",
  "version": "1.0.0",
  "status": "single_feature_verified",

  "entry": {
    "script": "scripts/fast_stock.js",
    "feature_py": "features/fast_stock.py",
    "ui_panel": "ui/fast_stock_panel.py"
  },

  "release_targets": {
    "script": "scripts/fast_stock.js",
    "feature_py": "features/fast_stock.py",
    "ui_panel": "ui/panels/fast_stock_panel.py"
  },

  "rpc": {
    "required": [
      "enable",
      "disable",
      "status",
      "cleanup",
      "set_config"
    ]
  },

  "config": {
    "enabled_default": false,
    "options": {
      "multiplier": {
        "type": "float",
        "default": 1.5,
        "min": 1.0,
        "max": 5.0,
        "label": "倍率"
      }
    }
  },

  "reverse_info": {
    "module": "GameAssembly.dll",
    "arch": "x86",
    "calling_convention": "mscdecl",
    "rva": [],
    "fields": [],
    "verified_by_ida": false
  },

  "lifecycle": {
    "uses_cached_pointer": false,
    "requires_room_reset": true,
    "requires_weapon_change_reset": true,
    "cleanup_required": true
  },

  "tests": {
    "python_static": "tests/test_fast_stock_static.py",
    "js_check": "tests/check_fast_stock.js"
  },

  "release_notes": {
    "integration_level": "copy_and_register",
    "known_limits": []
  }
}
```

要求：

```text
manifest.json 必须跟代码同步更新
不能等到整合正式版时再补
发行版接入时优先读取 manifest.json
没有 manifest.json 的功能不得直接进入 04 正式发行版
```

------

## 5. JS RPC 必须统一

每个 JS 必须导出同一套 RPC。

固定接口：

```js
rpc.exports = {
    enable() {},
    disable() {},
    status() {},
    cleanup() {},
    setConfig(config) {}
};
```

允许额外增加：

```js
reset(reason) {}
debugDump() {}
```

但正式发行版只依赖固定接口。

### 5.1 enable

职责：

```text
安装 Hook，如果已安装则跳过
设置 Runtime.enabled = true
读取当前配置
记录 enable 日志
```

不允许：

```text
重复 attach Hook
重复启动定时器
缓存 Player/Weapon 后一直用
直接依赖单功能 UI
```

------

### 5.2 disable

职责：

```text
Runtime.enabled = false
停止功能效果
恢复当前 generation 内可安全恢复的原值
清理运行期缓存
清理普通定时器
```

------

### 5.3 cleanup

职责：

```text
关闭功能
清理 Hook
清理定时器
清理缓存
清理原值记录
允许重复调用
```

要求：

```text
cleanup 调用 1 次不能崩
cleanup 调用 10 次也不能崩
UI 退出时必须调用 cleanup
游戏断开时必须调用 cleanup
```

------

### 5.4 status

必须返回结构化状态。

标准返回：

```js
{
    feature_id: "fast_stock",
    enabled: true,
    initialized: true,
    generation: 3,
    hook_hits: 120,
    error_count: 0,
    last_error: "",
    last_reset_reason: "weapon_changed"
}
```

不要只返回字符串。

------

### 5.5 setConfig

正式发行版通过这个接口传配置。

标准：

```js
setConfig(config) {
    Runtime.config = Object.assign(Runtime.config, config || {});
    return true;
}
```

要求：

```text
JS 不能直接读 UI 控件
JS 不能假设配置只在 enable 前设置
配置变化后必须可以实时生效，或者明确写明需要重新 enable
```

------

## 6. JS 内部必须有 Runtime 状态对象

每个 JS 必须有统一 Runtime。

模板：

```js
const Runtime = {
    feature_id: "fast_stock",
    enabled: false,
    initialized: false,
    generation: 0,

    hooks: [],
    timers: [],

    config: {},

    cache: {
        localPlayer: ptr(0),
        currentWeapon: ptr(0)
    },

    originals: {},

    stats: {
        hookHits: 0,
        errorCount: 0,
        cleanupCount: 0,
        lastError: "",
        lastResetReason: ""
    }
};
```

要求：

```text
不要把状态散落成一堆全局变量
不要长期相信 Player* / Weapon*
不要跨房间使用旧指针
必须实现 resetRuntime(reason)
```

------

## 7. Python feature 文件必须按发行版适配器写

单功能阶段不要写只能自己用的 Python 调用方式。

每个 `features/feature_id.py` 必须提供标准 Feature 类。

模板：

```python
class FastStockFeature:
    feature_id = "fast_stock"
    display_name = "极速枪托"
    category = "weapon"

    script_name = "fast_stock.js"

    def __init__(self, frida_manager, logger=None):
        self.frida_manager = frida_manager
        self.logger = logger
        self.enabled = False

    def enable(self, config=None):
        if config:
            self.frida_manager.call_export(self.feature_id, "set_config", config)
        result = self.frida_manager.call_export(self.feature_id, "enable")
        self.enabled = True
        return result

    def disable(self):
        result = self.frida_manager.call_export(self.feature_id, "disable")
        self.enabled = False
        return result

    def status(self):
        return self.frida_manager.call_export(self.feature_id, "status")

    def cleanup(self):
        try:
            return self.frida_manager.call_export(self.feature_id, "cleanup")
        finally:
            self.enabled = False
```

重点：

```text
单功能 UI 也必须通过这个 Feature 类调用
不要 UI 直接乱调 script.exports.xxx
不要 launcher.py 绕过 Feature 类
发行版整合时直接复制这个 Feature 类
```

------

## 8. 单功能 UI 必须模拟正式发行版调用方式

单功能 UI 只是测试壳。

它必须模拟正式发行版流程：

```text
启动 UI
attach 游戏
加载 JS
创建 Feature 类
调用 feature.enable()
调用 feature.disable()
调用 feature.status()
退出时调用 feature.cleanup()
```

不允许：

```text
UI 直接写死 JS 路径但正式版路径不同
UI 直接调 enableFastStock 这种临时 RPC
UI 没有 cleanup
UI 没有 status
```

------

## 9. 文件命名必须和发行版一致

单功能阶段文件名就要和发行版一致。

标准：

```text
scripts/feature_id.js
features/feature_id.py
ui/feature_id_panel.py
tests/test_feature_id_static.py
```

错误：

```text
极速枪托最终版.js
极速枪托测试2.js
fast_stock_new_ok.js
launcher_fixed.py
最终可用.py
```

临时版本必须放入：

```text
dev/
archive/
```

正式可迁移文件必须永远保持固定名字。

------

## 10. 日志必须统一

JS 日志前缀：

```text
[feature_id]
```

Python 日志前缀：

```text
[feature_id]
```

必须记录：

```text
load
enable
disable
cleanup
resetRuntime
hook installed
hook hit
pointer invalid
config changed
error
```

日志必须限频，不能刷屏。

------

## 11. 逆向信息必须写入文档和 manifest

每个功能必须写清：

```text
用到哪些 RVA
用到哪些字段偏移
来源是 dump.cs 还是 IDA
是否已经看过 IDA 汇编/反编译
Hook 点为什么选它
备选 Hook 点是什么
```

不允许：

```text
只在 JS 里写一个 0xB61140
文档不解释地址来源
后期整合时没人知道这个地址干什么
```

------

## 12. 功能完成前必须通过标准检查

单功能进入“可合并”状态前，必须通过：

```text
manifest.json 存在
feature_id 全文件一致
JS 有 enable/disable/status/cleanup/setConfig
JS 有 Runtime
JS 有 cleanupTimers / cleanupHooks / resetRuntime
Python Feature 类存在
单功能 UI 通过 Feature 类调用
node --check 通过
python -m py_compile 通过
静态测试通过
经验总结写完
生命周期说明写完
```

------

## 13. 单功能状态分级

每个功能必须标注状态。

允许状态：

```text
researching              研究中
probe_done               探测完成
single_feature_min       最小实现
single_feature_verified  单功能已验证
release_ready            可进入正式版
released                 已进入正式版
deprecated               废弃
```

只有 `release_ready` 才允许进入 `04-正式发行版`。

------

## 14. release_ready 标准

满足这些条件才可以标记为 `release_ready`：

```text
1. 单功能 UI 能正常开启/关闭
2. JS RPC 完整
3. cleanup 可重复调用
4. 反复开关不会重复 Hook
5. 切房间不会继续用旧指针
6. 死亡/重生不崩
7. 退出游戏不刷异常
8. manifest.json 完整
9. Python Feature 类符合发行版接口
10. UI 调用方式和发行版一致
11. 不依赖 launcher.py
12. 文档写清 RVA / 字段 / Hook 点
```

------

## 15. 一句话要求

```text
05 单功能不是 demo，而是 04 正式发行版的预制功能包。
单功能阶段多写一点标准结构，正式版合并时就少改甚至不改。
```

## 16. 文件编码规范

### 16.1 基本要求

所有新建和修改的文本文件必须使用 UTF-8 编码。

默认使用 UTF-8 无 BOM。

禁止使用 GBK、ANSI、Windows 默认编码保存源码或文档。

### 16.2 适用范围

以下类型的文件必须统一 UTF-8：

```text
.md     文档文件
.py     Python 源码
.js     JavaScript 源码
.json   配置文件
.txt    文本文件
.bat    批处理脚本
.ps1    PowerShell 脚本
.yaml   YAML 配置
.yml    YAML 配置
.ini    配置文件
.cfg    配置文件
.toml   配置文件
```

所有包含中文、emoji、特殊符号的文件，必须确认保存为 UTF-8。

### 16.3 Python 读写规范

Python 读取文本文件时必须显式写：

```python
with open(path, "r", encoding="utf-8") as f:
    content = f.read()
```

Python 写入文本文件时必须显式写：

```python
with open(path, "w", encoding="utf-8") as f:
    f.write(content)
```

### 16.4 JSON 读写规范

Python 写入 JSON 时必须使用：

```python
import json

with open(path, "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
```

Python 读取 JSON 时必须使用：

```python
import json

with open(path, "r", encoding="utf-8") as f:
    data = json.load(f)
```

### 16.5 日志规范

`logging.FileHandler` 必须指定 `encoding="utf-8"`：

```python
import logging

handler = logging.FileHandler(log_path, encoding="utf-8")
```

不允许因为 Windows 中文环境而使用默认编码读取文件。

### 16.6 乱码禁止

不允许出现以下情况：

```text
????    问号代替中文
       Unicode 替换字符
乱码中文
emoji 丢失
```
