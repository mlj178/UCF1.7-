## 当前结论

游戏最终扣血核心围绕 `DamageEventData` 展开。该结构体里最关键字段如下：

| 字段 | 偏移 | 说明 |
| --- | ---: | --- |
| `attacker` | `0x00` | 攻击者实体 |
| `victim` | `0x04` | 受害者实体 |
| `damage` | `0x08` | 本次伤害数值，伤害倍率优先改这里 |
| `type` | `0x34` | `DamageType`：Gun/Knife/Grenade/Infect/Other |
| `damageTag` | `0x38` | 特殊伤害标记，如暴击、幽灵之刃秒杀、MasterHeroSlash、Arcane |
| `wpnIndex` | `0x3C` | 武器 index |
| `wpnSprIndex` | `0x40` | 武器皮肤/显示 index |
| `ignoreDmgRate` | `0x44` | 可能绕过游戏原生伤害倍率 Buff |

`DamageType` 枚举只有五个有效伤害大类：

| 值 | 类型 |
| ---: | --- |
| `1` | `Gun` |
| `2` | `Knife` |
| `3` | `Grenade` |
| `4` | `Infect` |
| `5` | `Other` |

推荐第一版功能不要改每把武器的静态配置，而是在最终伤害事件里改 `DamageEventData.damage`。原因：

- 普通枪、特殊枪、刀、手雷、RPG、部分英雄技能最终都会构造或传递 `DamageEventData`。
- 现有“金刚不坏”功能已经证明 `Entity.OnEntityHurt` hook 点稳定可用。
- 直接乘 `damage` 可以避开武器数据字段分散的问题，比如 `WeaponData_Gun.ammoDamage`、`KnifeAttackData.damage`、`WPN_GRENADE.expDamage` 分别在不同数据类里。

第一版推荐 hook：

| Hook 点 | RVA | 用途 |
| --- | ---: | --- |
| `Entity.OnEntityHurt` | `0xB3F470` | 通用最终受伤入口，适合修改栈上的 `DamageEventData.damage` |
| `Player.OnEntityHurt` | `0xB516B0` | 玩家子类覆写入口，可作为兜底观察/补 Hook |
| `GameManager.TakeDamage` | `0xAFC1C0` | 更靠前的统一伤害入口，适合作为后续方案或诊断点 |

## 伤害来源分类与倍率可行性

| 大类 | 代表武器/情况 | 关键类、字段、入口 | 是否适合统一倍率 | 推荐处理 | 风险/待验证 |
| --- | --- | --- | --- | --- | --- |
| 普通枪械 | M4A1、AK47、Desert Eagle、M82A1、M60、RPK、MG3 等 | `WPN_Gun : Weapon`；`WPN_Gun.Damage(Ray)` RVA `0xB613D0`；`WeaponData_Gun.ammoDamage` `0x14C` | 高 | 第一版直接在 `DamageEventData.damage` 乘倍率。用 `attacker` 是本地玩家、`victim` 不是本地玩家过滤。 | 需要实测霰弹/多段命中是否每段都独立进入事件；若是，每段都会被乘。 |
| 普通枪械的刺刀/枪托近战 | 带近战攻击的枪械、AK 刺刀类 | `WPN_Gun.KnifeAttackEvent` RVA `0xB62730`；`WeaponData_Gun.knifeAttacks`、`knifeDamageBodyRatio` | 高 | 仍按最终 `DamageEventData.damage` 处理，不单独改 `knifeDamageBodyRatio`。 | 命中类型会表现为 `Knife` 或特殊 tag，日志确认即可。 |
| 特殊枪械 | 水枪、能量核心、重机枪、加特林预热、连发/预热组件 | 多数仍继承 `WPN_Gun`，另有 `WPN_MiniGunAnim`、`WPN_Prefire`、`WPN_RepeatFire` 等表现/发射组件 | 高 | 优先统一事件倍率。只要最终调用 `GameManager.TakeDamage` 或 `OnEntityHurt`，无需逐类 Hook。 | 如果某些特殊枪使用 Buff、百分比扣血或非标准 `Other` 事件，需要日志确认。 |
| 榴弹枪 | FN FAL 榴弹版、`WPN_GrenadeGun` | `WPN_GrenadeGun : WPN_Gun`；`GunShootFunction` RVA `0xB5FB30`；`<GunShootFunction>b__19_0(WPN_Missile)` RVA `0xB602A0` | 中高 | 枪械模式走普通枪倍率；榴弹模式若生成导弹/爆炸，仍优先在最终事件倍率处理。 | 榴弹模式的 `attacker` 可能是导弹或 owner，需要实测归属。 |
| RPG/AT4/Nano AT4 | RPG、AT4、Nano AT4 | `WPN_RPG : Weapon`；`Fire()` RVA `0xB670A0`；`<Fire>b__12_0(WPN_Missile)` RVA `0xB597B0` | 中高 | 第一版事件倍率可覆盖最终伤害；后续可补 `WPN_Missile.SetOwner` 记录 owner。 | 若 `DamageEventData.attacker` 是 missile 而不是玩家，本地玩家过滤会漏掉。 |
| 投掷手雷 | HE、诅咒娃娃手雷、生化手雷、幽灵宝宝手雷、奥术手榴弹等 | `WPN_Throw : Weapon`；`Throw()` RVA `0xB6AD80`；`WPN_GRENADE : WPN_Missile`；`Damage()` RVA `0xB5CFB0`；`CreateExplosion()` RVA `0xB5CC40` | 中高 | 第一版统一事件倍率；若要专门调雷伤害/范围，可参考手雷模式在 `CreateExplosion` 参数级处理。 | 爆炸归属需要确认。已有手雷模式证明参数级改伤害可行，但那是手雷专用，不覆盖枪和刀。 |
| 眩晕/状态手雷 | Stun Grenade、StunGrenade2-Nano | `WPN_StunGrenade2.OnCauseDamage(Entity)` RVA `0xB6A440`；`WPN_GRENADE.CauseDamage_Listener` | 部分可行 | 生命伤害若进入 `DamageEventData` 可乘；眩晕、减速、屏幕效果不是伤害倍率负责。 | 倍率不会增强眩晕时间或状态强度。 |
| 普通近战 | Knife、ButterflyKnife、CrazyKnife、NanoKnife 等 | `WPN_Knife : Weapon`；`KnifeAttackEvent` RVA `0xB64050`；`WeaponData_Knife.knifeAttacks`、`KnifeAttackData.damage` | 高 | 统一事件倍率。 | 大刀/重击可能带 `damageTag.isBigshot`，倍率不应破坏 tag。 |
| 英雄/终结者近战 | `WPN_AsceticHero`、`WPN_MasterHero`、`WPN_MasterHunter`、`WPN_MechanicHero`、`WPN_EvilTerminator`、`WPN_ArmoredTerminator`、`WPN_OutlawTerminator`、`WPN_VoidTerminator`、`WPN_GhostBlade`、`WPN_BoxingKing` | 多数继承 `WPN_Knife`；含 `Skill_Common`、Buff、协程伤害；`DamageTag` 有 `isGhostBladeSecKill`、`isMasterHeroSlash`、`isArcane` 等特殊位 | 中高 | 标准生命扣减事件可乘。第一版建议默认覆盖 `Knife/Other/Grenade/Gun`，但保留日志观察特殊 tag。 | 秒杀、护盾反伤、技能 Buff、感染类效果不一定适合乘；部分可能需要白名单/黑名单。 |
| 机械英雄炮台/机枪守卫 | 机械英雄、机枪守卫、SentryGun | `WPN_SentryGun : Weapon`；`WPN_SentryGun.SetSentryGun()` RVA `0xB69CC0`；`SentryGun : Entity`；`owner` `0x64`；`dmgData` `0x74`；`AttackEnemy()` RVA `0xB1C9B0`；`CreateExplosion()` RVA `0xB1CE70` | 中 | 如果 `dmgData.attacker` 保持 owner，本地玩家事件倍率可直接覆盖；如果 attacker 是炮台实体，需要补 `SentryGun.SetData(owner, wpnData, position)` RVA `0xB1E030` 做炮台到 owner 的映射。 | 这是最需要实测的特殊情况。只按 `Player.get_isMyPlayer(attacker)` 可能漏掉本地玩家炮台。 |
| 奥术/特殊投射物 | Arcane、Msl_Arcane、Msl_EvilFire | `WPN_Arcane : Weapon`；`Msl_Arcane.GetBasicDamageEventData()` RVA `0xB4B9C0`；`Msl_EvilFire : WPN_GRENADE` | 中 | 若最终走 `WPN_GRENADE.GetBasicDamageEventData` 或派生实现，统一事件倍率大概率覆盖。 | `DamageTag.isArcane` 需要日志确认；若有持续场/燃烧类伤害，可能是多次事件或 Buff。 |
| 生化感染/感染攻击 | Terminator/Nano 感染、近战感染 | `DamageType.Infect = 4`；`ModeBase_Nano.InvalidDmgCheck/PreDamageEvent/PostDamageEvent` 等模式逻辑 | 低到中 | “提高我造成的普通伤害”第一版建议默认不乘 Infect，避免改感染判定。后续可单独做开关。 | 感染可能不是普通扣血，乘伤害可能无意义或导致模式逻辑异常。 |
| Bot/敌人造成的伤害 | Bot 枪、Bot 雷、怪物/生化攻击 | `Bot.TakeDamageEvent`、各武器 `BotControl` | 可实现但不推荐默认开启 | 本功能目标是“放大玩家造成的输出伤害”，默认排除非本地攻击者。 | 如果用户以后要“全局伤害倍率”，需要另做作用范围选项。 |
| 地图/环境/机关/自伤 | 跌落、地图机关、毒圈、自爆、回合机制 | 可能表现为 `DamageType.Other` 或没有本地 attacker | 低/不建议 | 默认不乘，除非明确识别为本地玩家造成。 | 这类伤害经常没有玩家归属，乱乘容易影响自己或模式规则。 |
| 原生伤害倍率 Buff | 技能伤害加成/削弱、伤害 Buff | `DamageRateBuff.damageRate`；`PlayerData.damageRate`；`PlayerData.SetDamageRate(float subRate, float time)`；`DamageEventData.ignoreDmgRate` | 可行但不推荐第一版 | 不改原生 Buff 系统，直接改最终 `damage` 更可控。 | 改 Buff 可能影响敌我双方、持续时间、UI、模式平衡；`ignoreDmgRate` 也可能让原生倍率失效。 |

## 暂定可实现范围

第一版建议实现范围：

- 默认只放大“本地玩家造成给非本地玩家/敌方实体”的伤害。
- 覆盖 `DamageType.Gun`、`DamageType.Knife`、`DamageType.Grenade`、必要时覆盖部分 `DamageType.Other`。
- 默认跳过 `DamageType.Infect`。
- 默认不处理没有可靠本地玩家归属的环境伤害。

第一版大概率能覆盖：

- 普通枪械。
- 普通近战。
- 枪械附带近战。
- 大部分特殊枪械。
- 大部分手雷和爆炸物。
- 大部分 RPG/AT4 爆炸伤害。
- 大部分英雄/终结者的标准近战扣血。

第一版可能漏掉或需要补充归属映射：

- 机械英雄炮台/机枪守卫。
- 导弹/榴弹/RPG 如果 `attacker` 被写成 missile 对象。
- 奥术、燃烧、持续场等多段特殊投射物。

第一版不建议覆盖：

- 感染判定。
- 纯眩晕/减速/屏幕效果等状态效果。
- 地图环境伤害。
- 游戏原生 Buff 系统本身。

## 下一步实测探针

实现倍率前，建议先写一个诊断版 JS，只记录不修改：

| 探针 | 记录字段 | 目的 |
| --- | --- | --- |
| `Entity.OnEntityHurt` | `attacker`、`victim`、`damage`、`type`、`damageTag`、`wpnIndex`、`wpnSprIndex`、`ignoreDmgRate`、`isMyPlayer(attacker)`、`isMyPlayer(victim)` | 判断各类伤害是否进入最终事件，确认本地玩家过滤是否可靠 |
| `Player.OnEntityHurt` | 同上 | 验证玩家子类覆写是否需要兜底 Hook |
| `WPN_Missile.SetOwner` | missile 指针、owner 指针、`isMyPlayer(owner)` | 为手雷、RPG、榴弹补归属映射 |
| `SentryGun.SetData` | sentry 指针、owner 指针、`isMyPlayer(owner)` | 为机械英雄炮台/机枪守卫补归属映射 |
| `WPN_GRENADE.CreateExplosion` | damage、range、传入的 `DamageEventData.attacker` | 验证爆炸入口是否已经有正确 owner |

建议测试样本：

| 样本 | 预期 |
| --- | --- |
| M4A1/AK47 | `type = Gun`，`attacker` 为本地玩家 |
| M82A1/狙击 | `type = Gun`，高伤害单次事件 |
| 普通 Knife/重击 | `type = Knife`，可能带 `isBigshot` |
| HE/生化手雷 | `type = Grenade`，验证 `attacker` 是否为 owner |
| RPG/AT4 | `type = Grenade` 或 `Other`，重点看 missile owner |
| FN FAL 榴弹版 | 枪械模式和榴弹模式分别测试 |
| 机械英雄机枪守卫 | 重点看 `attacker` 是 owner 还是 sentry |
| MasterHero/GhostBlade/BoxingKing | 重点看 `damageTag` 特殊位和是否存在秒杀/技能伤害 |

## 推荐实现分期

| 版本 | 范围 | 说明 |
| --- | --- | --- |
| v1 | `Entity.OnEntityHurt` 统一事件倍率 | 最小可用版本：本地玩家攻击、非本地受害者、乘 `damage`、记录关键日志 |
| v1.1 | `Player.OnEntityHurt` 兜底和诊断增强 | 如果实测发现玩家/特殊实体不走基类入口，再补 |
| v1.2 | missile/sentry owner 映射 | 解决手雷、RPG、榴弹、炮台归属不稳定问题 |
| v2 | 分类开关 | UI 加普通枪、近战、爆炸物、炮台、特殊技能等分类倍率开关 |

当前建议：先做 v1 的诊断日志，再根据日志决定是否直接进入倍率写入，还是先补 owner 映射。
