「调整伤害倍率」UI 方案样板

纯 HTML 模拟（不是真实 APP 界面）。本页只定 UI 长什么样，不写任何真实逻辑；开关、滑块、档位按钮都可以随便点着玩。确认方案后再改 30_damage_multiplier 的 panel.py 与 manifest.json。

一、这次要满足的三件事

三个阵营分开调

敌人 / 自己 / 队友，各有一条独立倍率，互不影响。

能调高，也能调低

范围 0.1x ~ 10.0x，步进 0.1。1.0x 是原版，低于 1.0x 就是削弱。

每个阵营可单独开关

不想动的阵营单独关掉，保持游戏原样。

二、先确认一个关键歧义：倍率是"谁打出的"还是"谁挨的"？

两个都做得到（伤害事件里同时有 attacker 和 victim），但 UI 文案和用户预期完全不同，必须先定一个。点下面切换看差别。

倍率乘在"伤害来源"上：即某一方打出去的伤害。

滑块含义例子
敌人敌人（含 Bot）打出的伤害调 0.2x → 敌人几乎打不动你
自己你打出的伤害调 3.0x → 你一枪一个
队友队友打出的伤害调 0.5x → 队友别抢你人头
例：敌人 0.2x ＋ 自己 3.0x ＝ 敌人挠痒痒，你输出爆炸。

倍率乘在"伤害承受者"上：即某一方挨打时受到的总伤害。

滑块含义例子
敌人敌人挨打时受到的伤害调 5.0x → 敌人秒死
自己你挨打时受到的伤害调 0.2x → 你几乎不掉血
队友队友挨打时受到的伤害调 0.5x → 队友更耐打
例：敌人 5.0x ＋ 自己 0.2x ＝ 敌人脆如纸，你硬如铁。

方案 A：单卡片 · 三行独立控制推荐

「调整伤害倍率」还是一张卡（占半行），卡里三行：阵营名 + 滑块 + 数值微调 + 独立开关。底部一行实时汇总当前设置。

方案 B：三张独立卡片最贴合现有卡片体系

每个阵营一张独立的 simple_feature_card，各自带开关和滑块。改动最小，但占 1.5 行，且没有"一键全关"。

方案 C：档位优先 + 微调适合不想拖滑块的人

每行先给常用档位按钮（一点即到），右边保留滑块做微调。削弱档和增强档都直接可见，不用猜滑块位置。

三、三个方案都要定的共同细节

范围与步进

上限已定 10.0x，下限 0.1x（不允许 0）。最小要不要允许 0（0 = 完全不造成 / 不承受伤害，等于另一种无敌）。目前按 0.1x 下限。

低于 1.0x 的视觉提示

削弱时数值转蓝并显示"削弱"，增强转橙，1.0x 为灰白原版，避免用户以为只有调高。

和"金刚不坏"重叠

把敌人调到很低 ≈ 变相无敌。是否需要在 UI 上提示，或与金刚不坏互斥。

生效状态行

参考"天机傀儡"，卡片底部可加状态行：未连接 / 等待进游戏 / 已生效，让用户知道调了到底有没有生效。

持久化

三个倍率分别写入 user_config.json，开关是否进 feature_state.json 按现有持久化规范决定。

"队友"怎么判定

真人队友、人机队友、生化模式下的阵营关系不同，需要明确口径后再写逻辑。

四、需要你先拍板的几个问题

  1. 作用方向：倍率是"谁打出的伤害"，还是"谁挨的伤害"？（第二节可直接切换对比）
  2. 选哪个方案：A 单卡片三行 / B 三张独立卡 / C 档位优先。
  3. 开关粒度：统一一个总开关，还是每个阵营各一个开关，还是两者都要？
  4. 范围：0.1x ~ 10.0x 是否合适？要不要允许 0x？上限要不要更高？
  5. 队友口径：只算真人队友，还是人机队友也算？
