# 游戏模式切换-简要说明

## 1. 目标

提供一个最小化的游戏模式替换功能。玩家在 CustomTkinter UI 中选择模式，点击游戏原本的“开始游戏”后自动生效。

第一版不支持对局中热切换，不做复杂界面，不增加独立“应用”按钮。

## 2. 文件

```text
AAAAA-game_mode_override_min.js
AAAAA-game_mode_override_ui.py
游戏模式切换-简要说明.md
```

## 3. UI

UI 只提供：

1. “启用模式替换”开关。
2. 单选模式下拉框。
3. 当前连接和生效状态文本。

选择变化通过 `setConfig` 发送给 JS。选择只更新下一局配置，真正覆盖发生在游戏原本的开始流程中。

## 4. 模式映射

| UI 选项 | 游戏内说明 | GameMode | WeaponLimited |
| --- | --- | ---: | ---: |
| 团队竞技 | 团队竞技 | `TeamDeath = 0` | `None = 0` |
| 刀战 | 按当前地图分流 + 刀限制 | 个人/团队地图沿用原 `GameMode`；生化类地图转 `TeamDeath = 0` | `Knife = 1` |
| 生化4（普通生化） | 普通生化 | `Nano4 = 4` | `None = 0` |
| 生化6（剑客模式） | 剑客模式 | `Nano6 = 5` | `None = 0` |
| 生化4终结者（多人生化） | 多人生化模式 | `Nano4_Terminator = 6` | `None = 0` |
| 狙击战 | 按当前地图分流 + 狙击限制 | 个人/团队地图沿用原 `GameMode`；生化类地图转 `TeamDeath = 0` | `Sniper = 3` |
| 手枪战 | 按当前地图分流 + 手枪限制 | 个人/团队地图沿用原 `GameMode`；生化类地图转 `TeamDeath = 0` | `HandGun = 2` |

刀战、狙击战、手枪战都是带分流的武器限制模式：个人竞技地图里选择它们，仍然是个人竞技规则、不分 BL/GR 组队，只改变武器限制；团队竞技地图里选择它们，仍然是团队分阵营、人头比分；终结者、生化剑客、多人生化等生化类地图里选择它们，会转成团队竞技规则，走 BL/GR 分阵营和人头比分。

bot 发枪兜底：狙击战使用 `2568`，手枪战使用 `1168`（沙鹰-修罗），刀战使用 `244`。这些兜底只影响 bot 发枪流程，不改变地图原规则。

正式使用时默认关闭探测日志，不再输出 `[probe]`、`[life]`、背包采样和逐个 bot 发枪替换日志；只保留脚本加载、模式套用、规则同步、失败和必要警告。需要继续排查时，可临时通过 RPC 打开 `probe_enabled`。

当前正式 UI 不提供 `个人竞技（DeathMatch = 1）` 和 `生化3（Nano3 = 3）` 选项。

## 5. 拦截流程

流程入口：

```text
UI_GameRoom.OnStartGameBtnDown
RVA: 0xB25F40
```

正常流程中，`UI_GameRoom.OnStartGameBtnDown` 会先调用当前 `MapAsset` 的虚方法 `ApplyGameSetting`，再启动场景加载协程。

实际 Hook 分两层：

```text
MapAsset.ApplyGameSetting
RVA: 0xAE82B0

UI_GameRoom.OnStartGameBtnDown
RVA: 0xB25F40
```

该方法会正常写入：

```text
GameManager.gameMode
GameManager.gameModePrefab
GameManager.weaponLimited
```

JS 在 `MapAsset.ApplyGameSetting` 的 `onLeave` 覆盖目标模式需要的 `GameManager.gameMode`、`GameManager.gameModePrefab` 和 `GameManager.weaponLimited`，保证后续 bot 生成和规则预制体实例化看见目标模式。刀战、狙击战、手枪战会先看当前地图原 `GameMode`：个人/团队地图只覆盖 `weaponLimited`，生化类地图额外改成团队竞技 `gameModePrefab`。

`MapAsset_Nano` 和 `MapAsset_TeamDeath` 的派生实现都会先调用这个基础方法；基础方法返回后，派生实现只继续设置比分、时间、回合等规则参数，不再覆盖 `GameManager.gameMode`、`GameManager.gameModePrefab` 或 `GameManager.weaponLimited`。

因此 JS 会在 `UI_GameRoom.OnStartGameBtnDown` 的 `onLeave` 再同步一次目标模式规则参数，避免“生化预制体 + 团队规则参数”或“团队预制体 + 生化回合参数”的混搭。刀战、狙击战、手枪战只有在生化类地图转团队规则时才同步团队人头比分参数；在个人/团队地图里会跳过这一步，继续沿用当前地图原规则。

## 6. 目标规则预制体

不能只覆盖 `GameManager.gameMode`，否则游戏可能仍实例化原模式规则。

JS 从当前 `UI_GameRoom.mapDatas` 中扫描 `MapAsset.gameMode`，找到目标模式对应的 `MapAsset`，读取其默认 `gameModePrefab`，然后一起写入 `GameManager.gameModePrefab`。

不假定 `mapDatas` 的数组顺序固定。

武器限制模式需要额外注意：刀战不再是固定 `Special = 2` 的完整模式切换，狙击战和手枪战也不再只是无条件沿用原规则。脚本固定写入对应的 `GameManager.weaponLimited`；如果当前地图原模式是 `Nano3` 到 `Nano4_Terminator` 之间的生化类模式，则额外改写为团队竞技 `gameMode` 和 `gameModePrefab`，让终结者、生化剑客、多人生化地图进入刀战、狙击战或手枪战后按团队人头规则运行。这里优先读取 `MapAsset.ApplyGameSetting` 入口处的原地图 `gameMode` 做判断，读不到时才回退看 `GameManager.gameMode`，避免某些生化图在字段读回时机不稳定时误走“只覆盖武器限制”。

## 7. 失败处理

出现以下情况时放弃本次覆盖，让游戏继续使用原始设置：

- 找不到 `UI_GameRoom` 或 `mapDatas`。
- 找不到目标模式对应的 `MapAsset`。
- 目标 `gameModePrefab` 为空。
- 游戏进程或脚本已断开。

JS 记录失败原因，但不阻断游戏正常开始。

## 8. 第一版范围

第一版只实现：

- 自动连接 `UnityCrossFire.exe`。
- 模式替换开关和 7 项单选下拉框。
- 开始游戏时进行一次模式、规则预制体和武器限制覆盖。
- 开始流程末尾同步目标模式的基础规则参数。
- RPC 配置、状态查询和 cleanup。

第一版不实现：

- 对局中途热切模式。
- 后台定时锁值。
- 复杂地图兼容性修复。
- UI 中额外暴露模式专属时间、比分、回合数配置。
- 测试文件或复杂交付物。

跨模式使用某张地图时，地图是否具备目标规则需要的出生点和场景对象，仍由游戏原始地图资源决定。现版只做出生点数组兜底，不为不兼容地图补场景资源。

## 9. 规则参数兼容处理

跨模式切换时，目标规则预制体和原地图规则参数可能不一致：

- 生化模式进入团队类地图时，原地图可能把 `ModeBase.targetRound` 写成 `0`，导致回合结束后不正常进入下一回合。
- 团队、特殊等计人头模式进入生化类地图时，原地图可能保留生化回合制参数，导致死亡复活和胜负结算异常。

现版在开始按钮流程末尾同步：

- 生化类：`revengeEnable = 0`、`targetRound > 0`、`targetScore = 0`、生化时间。
- 计人头类：`revengeEnable = 1`、`targetRound = 0`、团队击杀/限时参数。
- 个人/团队地图里的武器限制模式（刀战、狙击战、手枪战）：跳过规则同步，只保留当前地图原规则。
- 生化类地图里的武器限制模式（刀战、狙击战、手枪战）：同步团队类 `revengeEnable = 1`、`targetRound = 0`、团队击杀/限时参数。
- 所有目标模式：重置 `GameManager.gameRoundOver = false`，并同步 `ModeBase.respawnTime`。

## 10. 出生点兼容处理

根因判断：跨模式切换后，“bot 没出现”不一定是 bot 没生成，也可能是场内 Player 创建后找不到目标模式需要的出生点。

已确认的关键点：

- `UI_GameRoom.GenerateBotClient` 仍会按 bot 数量生成 bot 的 `ClientData`，并写入 `UI_GameRoom.players`。
- bot 初始 `joinTeam` 通常是 `0/1` 交替。
- `MapManager.GetSpawnPoint(BL/GR)` 会读取 `SP_BL/SP_GR`；团队类规则套到只有中立出生点的地图时，`SP_BL/SP_GR` 可能为空。
- `MapManager.GetSpawnPoint(Neutral)` 会读取 `SP_Netural`；个人竞技规则套到没有中立出生点的地图时，`SP_Netural` 可能为空。

现版采用最小修法：

- `SP_Netural` 为空时，临时借用已有的 `SP_BL` 或 `SP_GR`。
- `SP_BL/SP_GR` 为空但 `SP_Netural` 可用时，临时把 `SP_Netural` 借给缺失的 `SP_BL/SP_GR`。

该兜底只解决“出生点数组缺失导致无法出生”的问题，不补地图专属物件或场景触发器。验证跨模式地图时，需要重点观察借用出生点后是否有重叠、卡点或出生位置不合理。

## 11. 实施步骤

1. 参考现有最小功能模板，确定 Frida 自动连接、RPC、日志和 cleanup 写法。
2. 编写 `AAAAA-game_mode_override_min.js`：安装 `MapAsset.ApplyGameSetting` Hook，扫描目标 `MapAsset`，覆盖模式、规则预制体和武器限制。
3. 在 `UI_GameRoom.OnStartGameBtnDown` 流程末尾同步目标模式规则参数，避免原地图派生 `ApplyGameSetting` 留下错误回合/比分配置。
4. 为跨模式出生点缺失增加 `MapManager` 兜底：捕获 `MapManager.Awake` 的实例，在 `MapManager.GetSpawnPoint` 前检查目标队伍出生点，必要时在 `SP_BL/SP_GR/SP_Netural` 之间临时借用。
5. 编写 `AAAAA-game_mode_override_ui.py`：自动连接游戏，提供启用开关、7 项模式下拉框和状态文本。
6. 执行 JS 语法检查、Python 编译检查和 RPC/地址静态核对，不创建测试文件。
7. 游戏实测时依次验证团队、刀战、普通生化、剑客模式、多人生化、狙击和手枪；不兼容地图只记录现象，不补资源。
