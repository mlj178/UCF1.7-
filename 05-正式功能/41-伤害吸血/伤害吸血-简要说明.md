# 伤害吸血 - 简要说明

> 单功能目录：`05-正式功能/41-伤害吸血/`
> feature_id：`lifesteal`
> 状态：单功能版（待实机测试），测试合格后再迁移到整合包 2.8
> 日期：2026-11-07

---

## 1. 功能目标

玩家对敌人造成生命伤害时，按「**实际扣掉的血量 × 吸血比例**」回复本地玩家血量。

- 吸血比例是一个滑块：`0% ~ 100%`，默认 `10%`，步进 `1%`。
- 100% 表示「掉多少血就回多少血」，不是倍率叠加。
- 回血走游戏原生 `HealthData.Heal`，**封顶在当前最大血量**，不会把血条顶出上限。
- 吸血来源可以按类型分别开关：主武器 / 副武器 / 枪托重击 / 近战武器 / 投掷爆炸 / 特殊技能 / 感染。
- 默认只对「敌人」生效：打自己、打队友不吸血。

---

## 2. 核心原理（一句话版）

Hook 游戏最终扣血入口 `HealthData.Hurt`，拿到的整数伤害就是「这一击真正扣掉的血量」；
再用之前 Hook `Entity.OnEntityHurt / Player.OnEntityHurt` 建立的伤害来源上下文，判断这一击是不是本地玩家打的、属于哪种武器来源；
是就给本地玩家调一次 `HealthData.Heal(伤害 × 比例)`。

### 2.1 游戏扣血链路（IDA 反汇编确认）

```text
GameManager.TakeDamage(data)
  -> damage = min((int)(data.damage × victim.damageRate), victim 剩余血量)   // 先乘防御率，再钳到剩余血量
  -> victim.OnEntityHurt(data)                  // Player / Entity 覆写
       -> int dmg = (int)data.damage            // float -> int，向零截断
       -> HealthData.Hurt(healthData, dmg)      // 真正执行 currentHealth -= dmg
```

### 2.2 为什么选 `HealthData.Hurt` 作为结算点

1. **它拿到的就是最终伤害**：已经过伤害倍率功能（`TakeDamage` 入口 / `OnEntityHurt` 收尾）、受害者防御率、剩余血量钳制、float→int 截断。
2. **天然和其它功能配合**：
   - 「调整伤害倍率」把自己调到 2.0x → Hurt 收到双倍伤害 → 吸血也按双倍回。
   - 「调整伤害倍率」把敌人/自己调到 0.5x → 吸血同步变少。
   - 「开火直伤」只改射线方向/弹体速度，不伪造伤害 → 按实际伤害吸血。
   - 「增加血量」抬高 maxHealth → 吸血能回的上限也跟着变高。
   - 30 号功能在 `GameManager.TakeDamage` 入口乘、刀在 `OnEntityHurt` 乘，两条路最终都汇聚到 Hurt，本功能不需要区分。
3. **不会重复计算**：不在 `OnEntityHurt` 里读 `data.damage` 乘比例，避免「倍率功能改一次、自己再乘一次」的叠加歧义；也不写 `DamageEventData.damage`，不改游戏伤害结果。
4. **不用写加密字段**：`currentHealth / maxHealth` 是 `ObscuredInt`，直接 `writeS32` 会破坏加密结构；本功能只读（用于显示），写血全部走 `HealthData.Heal`。

### 2.3 伤害来源上下文怎么建立

`DamageEventData` 在 x86 cdecl 下按值放在栈上（`[esp+4]=this`，`[esp+8]` 起是结构体）。
在两个 `OnEntityHurt` 的 `onEnter` 里读：

| 字段 | 偏移 | 用途 |
| --- | ---: | --- |
| attacker | 0x00 | 伤害来源（可能是玩家、导弹、炮台） |
| victim | 0x04 | 受害者 |
| type | 0x34 | Gun(1) / Knife(2) / Grenade(3) / Infect(4) / Other(5) |
| damageTag | 0x38 | 暴击、重击、秒杀等特殊标记（诊断用） |
| wpnIndex | 0x3C | 武器索引（与 `WeaponData.wpnIndex` 同值） |

处理顺序：

1. `attacker` 先还原成真正的玩家：本身就是 Player 就直接用；若是 missile / 炮台实体，则读它自己的 owner 字段（`+0x30` / `+0x64`，纯内存读、零 Hook）。
2. 与本地玩家指针比较；不是本地玩家 → 不建立上下文（Bot 互殴、敌人打你都不处理）。
3. 受害者是本地玩家 → 跳过（自己炸自己、摔伤不吸血）。
4. `only_enemy_victim` 开启时，受害者与本地玩家同队（且都不是 Neutral）→ 跳过。
5. 用 `wpnIndex -> WeaponClass` 映射把伤害分类，来源开关关闭 → 跳过。
6. 通过后把上下文压栈；`HealthData.Hurt` 命中时按「受害者 HealthData 指针 + 2 秒时间窗」匹配，
   取到 `type / wpnIndex / 分类`，结算吸血。

> `Player.OnEntityHurt` 会调用基类 `Entity.OnEntityHurt`，同一个伤害事件会压两层上下文。
> 这没有副作用：Hurt 只会命中最近的一层，并用 `consumed` 标记避免重复吸血。

## 4. 伤害来源分类与覆盖范围（重点）

### 4.1 UI 上的分类

```text
0% ~ 100% 吸血比例
[√] 主武器     步枪 / 狙击 / 机枪 / 冲锋枪 / 霰弹枪
[√] 副武器     手枪
[√] 枪托重击   枪械近战（枪托 / 刺刀）
[√] 近战武器   刀 / 英雄近战
[√] 投掷/爆炸  手雷 / RPG / 榴弹
[√] 特殊/技能  其它伤害类型
[ ] 感染       生化感染（默认关）
[√] 只吸敌人
```

### 4.2 「用户分类 → 游戏数据 → 是否覆盖」对照表

| 用户说的分类 | 游戏里怎么识别 | 覆盖 | 说明 |
| --- | --- | --- | --- |
| 主武器 | `type=Gun` + `wpnIndex` 映射到 Rifle/Sniper/MachineGun/SubmachineGun/ShotGun | ✅ | 映射来自本地玩家 `PlayerWeapons` 里每把武器 `Weapon.data -> WeaponData.wpnClass`。映射不到时按「主武器」兜底，不会漏吸。 |
| 副武器 | `type=Gun` + `wpnClass=Pistol(5)` | ✅ | 同上；补给箱/赋予武器只要进了玩家武器列表并在 2 秒内刷新到，就能分到副武器。 |
| 枪托重击 | `type=Knife`（或 `Other`）+ `wpnIndex` 映射到枪械类 | ⚠️ 需实测确认 | `WPN_Gun.KnifeAttackEvent` 用 `WeaponData_Gun` 构造伤害，wpnIndex 指向枪本身，因此能识别成「枪械近战」。若实测发现枪托是 `Other` 且 wpnIndex 不是枪械，会落到「特殊/技能」桶（仍然吸血，只是分类不同）。 |
| 近战武器（刀 / 英雄近战） | `type=Knife` + `wpnClass=Knife` 或映射不到 | ✅ | GhostBlade、MasterHero、BoxingKing 等标准扣血都走 Hurt。秒杀类 tag 不影响吸血管道，按最终扣血吸。 |
| 投掷武器 / 手雷 | `type=Grenade`，`attacker` 由 `WPN_GRENADE.GetBasicDamageEventData` 写成 `missile.owner`（玩家） | ✅ | IDA 确认：`GetBasicDamageEventData` 直接把 `[missile+0x30] owner` 写进 `DamageEventData.attacker`。 |
| RPG / AT4 / 榴弹枪 / 导弹类 | `type=Grenade` 或 `Other`，attacker 可能是 missile | ✅ 大概率 | `Weapon.ProjectMissile` 在发射时把 owner 直接写进 `missile+0x30`；结算时若 attacker 仍是 missile 实体，再读 `[missile+0x30]` 兜底（零 Hook）。 |
| 特殊武器 / 技能伤害 | `type=Other` 且 wpnIndex 不是枪械 | ✅ | 默认允许；如果某个技能伤害不走 `HealthData.Hurt`，会自然漏掉（见 4.3）。 |
| 炮台 / 机械英雄机枪守卫 | attacker 可能是 `SentryGun` 实体 | ✅ 有映射时 | 结算时若 attacker 是炮台实体，读 `[sentry+0x64]` 还原 owner（零 Hook）。炮台打敌人 = 你打敌人。 |
| 感染伤害 | `type=Infect(4)` | ❌ 不支持 | `Entity.OnEntityHurt` 对 `type==4` 直接 return，**不会调用 HealthData.Hurt**，普通扣血链路里拿不到感染伤害。默认关闭，说明见 4.3。 |
| 敌方 SentryGun / TombStone 作为受害者 | 覆写了 `OnEntityHurt` | ❌ 不吸 | `SentryGun.OnEntityHurt` 会把 `eventData.damage` 强制改成 1 并自行处理；`TombStone` 也自己调 Hurt。它们不走本功能的上下文，所以「打掉敌方炮台/墓碑」不产生吸血。 |
| 地图机关 / 环境伤害 / 摔伤 | attacker 为空或不是玩家 | ❌ 不吸 | 没有本地玩家归属，一律跳过。 |
| 自己打自己（自己的雷） | attacker=本地玩家，victim=本地玩家 | ❌ 不吸 | 固定跳过，避免调高比例后自伤反而回血。 |
| 打队友（友伤开启时） | 同队且都不是 Neutral | ❌ 默认不吸 | `only_enemy_victim` 开启时跳过；关闭后可以和打敌人一样吸。 |

### 4.3 明确「弄不进来」的情况

1. **感染伤害（DamageType.Infect）**
   `Entity.OnEntityHurt` 第一行就是 `if (type == 4) return;`，感染不进入普通扣血；游戏在模式层单独处理感染（可能不是扣血，而是感染判定/角色转换）。因此本功能无法用通用链路吸感染血。默认关闭，不破坏生化玩法。

2. **敌方可破坏物（SentryGun / TombStone）**
   它们覆写了 `OnEntityHurt`，绕开基类；SentryGun 甚至把伤害强制改成 1。没有 `DamageEventData` 上下文就没有「谁打的」和「什么武器」，所以不吸。若要支持，需要单独 Hook 它们的 `OnEntityHurt` 并接受「伤害=1」的口径——第一版不做。

3. **找不到 owner 的投射物**
   如果某个特殊投射物既不是 `WPN_Missile` 子类，也没有把 owner 写进 `DamageEventData.attacker`，attacker 就无法还原成玩家 → 不吸。日志里会表现为 `skipped_not_local`。

4. **纯状态效果**
   眩晕、减速、闪光、烟雾、燃烧 buff 等不是生命伤害，不产生 Hurt → 不吸（这不是 bug）。

5. **治疗/护盾类数值**
   `tempHealth`（临时护甲）由 Hurt 内部优先扣，本功能按传入 Hurt 的整数伤害计算，不区分「扣的是护甲还是血」。也就是说：打有护盾的目标时，吸血按「伤害值」算，而不是按「实际掉的血量」算。

6. **主武器 / 副武器的细分依赖武器映射**
   `DamageEventData` 只有 `wpnIndex`，没有「槽位」字段。本功能通过本地玩家的 `PlayerWeapons` 建立 `wpnIndex -> WeaponClass` 映射来区分主/副/枪托：
   - 映射是 2 秒刷新一次；刚捡起的新武器最多 2 秒内可能归到兜底分类（Gun→主武器、Knife→近战）。
   - 玩家不再持有的武器 60 秒后从映射里过期；投掷物/延迟爆炸如果超过这个时间才结算，会走兜底分类。
   - 兜底分类仍然吸血，只是统计/分类开关可能不如预期精确。

7. **刀伤重写 / 致死一击**
   生化模式会按角色重写刀伤（`CalKnifeDmg`），本功能按最终 Hurt 收到的整数吸；如果游戏在 Hurt 前没有把伤害钳到剩余血量，致死一击会按面板伤害吸（比实际掉血多）。这是边角差异，实测确认即可。

## 6. 生命周期与安全设计

- **Hook 只装一次**：`initializeFeature` 有 `initialized` 保护；`enable` 不重复 attach。
- **开关与 Hook 分离**：`disable` 只把 `enabled` 置 false 并清空上下文/待结算量；Hook 保留到 `cleanup`。
- **上下文栈**：`resetRuntime`、`disable`、`cleanup` 都会清空；上下文超过 2 秒自动丢弃。
- **玩家指针不长期相信**：本地玩家每秒最多刷新一次；回合结束/新回合/房间销毁直接清空。
- **不在 RPC 线程调游戏方法**：本地玩家只用 `GameManager.myPlayer` 静态字段纯内存读定位（`get_isMyPlayer` 内部实现就是这个比较，见 IDA 0x00B55FD0）。原生调用只剩 `Heal` / `get_isDead` 两个，且都只在 `HealthData.Hurt` 的 Hook 回调里执行（游戏线程）。这样 RPC 的 `status()` 轮询无论从哪个线程进来都只做内存读，避免了 2.7 修过的“在错误线程里调游戏函数”隐患。
- **武器映射**：2 秒刷新、60 秒过期；清房间时整体清空。
- **绝不写加密字段**：只读 `currentHealth/maxHealth` 用于 UI 显示；回血只调 `HealthData.Heal`。
- **死亡保护**：`HealthData.get_isDead` 为真时清空待结算量并跳过，避免「死了还被加血」。
- **异常兜底**：连续 20 次异常自动关闭功能并清缓存，避免在坏指针上反复调用原生函数。
- **cleanup 可重复调用**：detach 全部 Hook、清缓存、清待结算、清上下文，重复调用不崩。

### 8.2 实机测试清单（按节点）

1. **连接**：启动 `AAAAA-lifesteal_ui.py`，自动连上 `UnityCrossFire.exe`，日志出现 `script loaded`。
2. **进房前开 → 进房生效**：不手动关开，进房后打敌人确认回血。
3. **退房重进**：退出房间再开一局，功能仍然生效（生命周期 Hook 清缓存后自动重识别）。
4. **死亡 / 重生**：死亡时不回血、不报错；重生后继续吸血。
5. **切武器**：主武器 ↔ 副武器 ↔ 刀 ↔ 手雷，确认对应来源开关生效。
6. **补给箱 / 赋予武器**：捡起新枪后 2 秒内确认分类正确（日志 `wpn_name`）。
7. **枪托重击**：对着敌人用枪托/刺刀，确认分类是「枪托重击」（若落到特殊桶，记录日志）。

## 11. 回退方案

### 11.1 如果 Hurt 结算点有兼容问题

如果实机发现「在 Hurt 里调 Heal」有兼容问题（例如某些模式下 HUD 不刷新、或与其它功能冲突）：

1. 把 `onHealthHurt` 里的 `native.heal(...)` 改成只累加 `Runtime.pendingHeal`；
2. 新增 `Player.Update`（RVA `0x00B551D0`）Hook，命中本地玩家时消费 `pendingHeal` 并调 `Heal`；
3. RPC 行为、配置、状态字段保持不变，不影响外部调用方式。

这也是「增加血量」功能已经在用的主线程排水方式。

### 11.2 如果 `HealthData.Hurt` 根本没命中

实机先看 `status.hurt_hook_hits`：

- 持续为 0：说明这个版本里 Entity.OnEntityHurt 没有调用 `HealthData.Hurt`（或被内联）。
  退路是在 `Entity/Player.OnEntityHurt` 的上下文里直接读 `DamageEventData.damage`（float）乘比例，
  即把 `onHealthHurt` 的结算挪到 `pushContextFromStack` 成功后立刻执行。
  代价是：伤害值是乘过伤害倍率、但可能还没经过「剩余血量钳制 / int 截断」的值，吸血会略有偏差；
  这也是第一版没有直接采用它的原因。

### 11.3 如果主/副武器分不出来

先看 `status.last_wpn_index / last_wpn_class / last_wpn_name`：

- `wpn_index` 一直是 -1 或 `wpn_class` 一直是 -1：说明 `WeaponData` 映射没建立，
  先检查 `Player.wpns` / `PlayerWeapons.all` / `Weapon.data` 三个偏移，
  必要时在 `dev/` 下加一个只读探针确认。
- 分类不对但吸血正常：只是 UI 分类开关的粒度问题，不影响核心回血。

## 12. 与整合包 2.8 其它功能的关系（同址 Hook 审计）

本功能现在只有 6 个挂点（3 个伤害链 + 3 个生命周期），扫描 `04-正式发行版/全功能整合包2.8/game_modifier/features/*/script.js` 后，
同址的功能全部是 `Interceptor.attach`，**没有任何功能对本功能的挂点做 `replace`**（replace 才会互相覆盖）。

| 地址 | 函数 | 同址功能（2.8） | 挂法 | 结论 |
| --- | --- | --- | --- | --- |
| 0xB3F470 | `Entity.OnEntityHurt` | 12 金刚不坏、30 伤害倍率 | attach | 兼容：它们只改 `DamageEventData.damage`，本功能只读 `type / wpnIndex`，伤害取 `Hurt` 的 int |
| 0xB516B0 | `Player.OnEntityHurt` | 12 金刚不坏、30 伤害倍率 | attach | 同上 |
| 0xAE45B0 | `HealthData.Hurt` | 无 | — | 独占 |
| 0xAE44F0 | `HealthData.Heal` | 无 | — | 独占（只调用，不 Hook） |
| 0xB663C0 | `WPN_Missile.SetWeaponData` | 26 手雷模式、29 子弹穿墙、40 开火直伤 | — | **本功能已不挂**（原唯一同址点，已改为结算时读 `[missile+0x30]`） |
| 0xB1E030 | `SentryGun.SetData` | 30 伤害倍率 | — | **本功能已不挂**（已改为结算时读 `[sentry+0x64]`） |
| 0xAFAA40 | `GameManager.GameRoundEnd` | 03 / 07 / 08 / 10 / 16 / 30 / 31 / 37 | attach | 低风险（各自清缓存） |
| 0xAEBCB0 | `GameManager.NewGameRoundStart` | 08 / 21 / 30 / 31 / 37 | attach | 同上 |
| 0xAEBD40 | `GameManager.OnDestroy` | 03 / 26 / 30 / 31 / 37 | attach | 同上 |

血量类功能的协同：

- **30 伤害倍率**：本功能吃 `Hurt` 的最终 int，倍率翻倍时吸血同步翻倍，属设计内协同。
- **36 增加血量**：走 `HealthData.AddHealthMax` 抬高上限；本功能每次按当前 `maxHealth` 封顶，抬高后可以吸到更高。
- **12 金刚不坏**：把受伤伤害写 0，只影响「本地玩家挨打」，不影响本功能按输出结算。
