# 亮度调节探针-经验记录

## 目标

验证游戏中的画面亮度是否可以通过 Unity URP 的真实后处理参数调节，而不是走屏幕覆盖层式提亮。

本探针只验证两件事：

1. 当前主相机是否存在 `UniversalAdditionalCameraData`、`VolumeStack` 和 `ColorAdjustments`。
2. 如果 `volumeStack` 为空，是否可以通过 `CameraManager.volumeProfile -> VolumeProfile.components -> ColorAdjustments` 找到同一个 URP 后处理组件。
3. `ColorAdjustments.postExposure` 写入后能否读回，并由用户在游戏内目测是否真的改变画面。

## 运行方式

1. 启动游戏并进入实际对局或能看到地图画面的场景。
2. 运行 `AAAAA-brightness_probe_ui.py`。
3. 连接成功后可直接调整“曝光/对比度/饱和度/Gamma/Gain”滑块并点“应用参数”。
4. 回到游戏内目测画面是否变亮。
5. 测完点“恢复游戏初始值”，关闭 UI 时也会调用 `cleanup()` 尝试恢复。

## 游戏内实测记录

当前状态：首次实机探针返回 `volumeStack is null`。

已修复记录：

1. UI 侧调用 Frida RPC 时需要使用小写方法名。`rpc.exports.setConfig` 在 Python `exports_sync` 侧会按 `setconfig` 查找；探针现在同时导出驼峰名和小写别名，UI 固定调用 `setconfig`、`applybrightness`、`resetbrightness`。
2. UI 侧不能连续调用两个独立 `_call_rpc()` 来完成“先配置再应用”，因为第一个调用会设置 `rpc_busy`，第二个调用会被跳过。现在改为 `_call_rpc_sequence()` 顺序执行。
3. `volumeStack is null` 不等于亮度调节不可行，只说明当前 `Camera.main` 的 `UniversalAdditionalCameraData.volumeStack` 为空。探针会同时返回 `cameraManagerVolumeProfile`，用于判断 `CameraManager.volumeProfile` 是否存在以及 `VolumeProfile.components` 数量。
4. 已新增推荐路线：当 `Camera.main -> volumeStack -> ColorAdjustments` 失败时，自动兜底走 `CameraManager.volumeProfile -> VolumeProfile.components -> ColorAdjustments`，找到后直接写 `postExposure`。
5. 已加入 `ColorAdjustments.saturation`、`LiftGammaGain.gamma`、`LiftGammaGain.gain`。其中 Gamma/Gain 保留原 RGB 分量，只写 `Vector4Parameter.w`，降低破坏原调色的风险。
6. “恢复游戏初始值”恢复的是本次探针首次写入前读到的游戏原始值，包括 float 参数和 Vector4 参数。

## 后续判断

如果探针失败：

1. `Camera.main` 为空：需要改成从 CinemachineBrain 或 CameraManager 获取实际输出相机。
2. `UniversalAdditionalCameraData` 为空：说明主相机可能不是 URP 相机，继续查相机列表。
3. `volumeStack` 为空：先看日志中的 `CameraManager profile=... components=...`。如果 profile 存在且组件数大于 0，探针会自动尝试 `CameraManager.volumeProfile -> VolumeProfile.components -> ColorAdjustments` 路线；如果 profile 也为空，再考虑在正确渲染时机 Hook `UniversalRenderPipeline.UpdateVolumeFramework` 或相机渲染入口。
4. `ColorAdjustments` 为空：说明当前 VolumeStack 没有颜色调节组件，可能需要查 VolumeProfile 或创建组件。

如果探针成功但画面无变化：

1. 先确认 `renderPostProcessing` 是否为 `true`。
2. 勾选“强制开启相机后处理”再试。
3. 如果仍无变化，说明参数层可写，但 PostProcessPass 没有消费该参数，问题会接近热成像失败案例里的 URP 管线限制。

如果画面会变化：

1. 记录有效曝光范围。
2. 做反复开关、切房间、退出游戏测试。
3. 再考虑把探针改成正式 `brightness_adjustment` 单功能。

## 覆盖层式提亮

本探针明确不做覆盖层式提亮，也不修改 ESP/ImGui/D3D Hook。

原因：覆盖层式提亮只能证明“画面上叠一层浅色滤镜可行”，不能证明游戏自己的亮度、曝光、后处理链路可控；这次要保留的经验重点是 URP 真实后处理是否可用。
