# 手雷模式最终修复记录

## 0. 当前最终标准

当前最终以这个版本为标准：

```text
grenade_mode_v2_12_7_safe_give_argfix_ctk.zip
```

说明：

```text
v2.12.4 是稳定基线。
v2.12.7 是在 v2.12.4 基础上，继续修复“部分 Bot 不会扔手雷”后的当前最终版本。
```

当前最终目标：

```text
1. 滑块数值修改后立即生效。
2. 某个字段打勾后立即生效，不需要重新开关功能。
3. 玩家手雷数量稳定锁 999。
4. 玩家当前手雷对象不被 Remove 错误删除。
5. Bot 可以端枪，但不能开枪。
6. Bot 进入枪械 BotControl 后，要尽量转成扔手雷。
7. 如果 Bot 没有缓存到 Grenade 指针，先补记录。
8. 如果仍然没有 Grenade 指针，就主动给当前 Bot 补发普通 Grenade。
9. 补发成功后，再 Select(3) + WPN_Throw.Throw。
10. 不再采用激进删除 AI / 状态机的路线。
```

最终原则：

```text
v2.12.4 是安全基线。
v2.12.7 是当前最终标准。
只做安全补强，不再激进删除。
Bot 扔雷链路宁可保留一点冗余，也不要删到影响投掷。
```

# 2.7.1 部分 Bot 不会扔手雷问题

## 用户测试反馈

```text
游戏里仍然能看到部分 Bot 端着枪。
这些 Bot 不开枪，但也不丢手雷。
用户需求不是放行开枪，而是继续禁枪，并让这些 Bot 也能切换成扔手雷。
```

## 问题表现

日志里出现过：

```text
BotGrenadeRecord跳过
Bot手雷补记录失败
Bot投掷驱动跳过
VirtualBotControl未接管
当前还没有可安全调用的 Grenade weapon ptr
```

说明：

```text
VBC 已经触发。
禁枪逻辑已经生效。
但当前 Bot 没有可安全调用的 Grenade 指针。
所以脚本不能直接调用 WPN_Throw.Throw。
```

## 初步原因

不是所有 Bot 都一定能在同一时间被脚本记录到 Grenade。

可能原因：

```text
1. 这个 Bot 当前生命周期只暴露了 Rifle / Sniper / MachineGun / Pistol / Knife。
2. 这个 Bot 的普通 Grenade 没有经过 PlayerWeapons.SetWeapon / SetCurrentWeapon / GameManager.GiveWeapon 的记录点。
3. Bot 复活 RemoveAll 后，旧 Grenade 记录被清掉，新 Grenade 还没重新记录。
4. 记录 Grenade 时使用的 key，和 VBC 投掷时查找的 key 对不上。
5. 这个 Bot 当前确实没有普通 Grenade，需要主动补发。
```

## 最终结论

```text
这个问题不是 VBC 不工作。
也不是禁枪逻辑错误。
真正问题是：部分 Bot 在投掷时没有可安全调用的 Grenade weapon ptr。
```

# 2.7.2 v2.12.5 safe-grenade-reacquire 修复

## 修复目标

解决：

```text
明明记录过 Grenade，但 VBC 查不到 Grenade。
```

## 最终修复方案

新增多 key 缓存：

```text
storeBotGrenadeRecordAliases
getBotGrenadeRecordEx
ensureBotGrenadeBeforeThrow
```

同一个 Bot Grenade 同时按这些 key 记录：

```text
playerWeapons key
owner player key
bot key
grenade weapon 反向索引
```

VBC 投掷前执行：

```text
1. 先按 playerWeapons 查 Grenade。
2. 再按 bot 查 Grenade。
3. 再按 owner/player 查 Grenade。
4. 再从 Bot.thisPlayer -> Player.wpns 反查。
5. 再尝试 Select(3)。
6. Select(3) 后再查一次。
```

如果找到 Grenade：

```text
Select(3)
force throwReady
WPN_Throw.Throw
```

如果仍然找不到：

```text
不调用空指针 Throw。
继续禁枪。
等待后续补记录。
```

## 保留原则

```text
不放行 Bot 枪械开火。
不强行 Throw 空指针。
不伪造 Grenade 指针。
```

# 2.7.3 v2.12.6 safe-bot-grenade-give 修复

## 修复目标

解决：

```text
这个 Bot 当前生命周期确实没有 Grenade 记录。
多 key 查找也找不到。
Select(3) 后也查不到。
```

## 最终修复方案

新增主动补发普通 Grenade。

新增：

```text
rememberGrenadeWeaponIndex
getKnownGrenadeWeaponIndex
tryGiveBotGrenadeForThrow
```

## 记录 Grenade weaponIndex

在 GameManager.GiveWeapon 中，如果发现某个 weaponIndex 是普通 Grenade，就保存：

```text
knownGrenadeWeaponIndexes
lastBotGrenadeWeaponIndex
```

作用：

```text
后续某个 Bot 没有 Grenade 指针时，可以用已知普通 Grenade weaponIndex 给当前 Bot 补发一个真实 Grenade。
```

## 主动补发逻辑

VBC 投掷前：

```text
查缓存
多 key 查
从 Bot 反查 PlayerWeapons
Select(3) 后再查
仍然没有 Grenade：
    用 lastBotGrenadeWeaponIndex 调 GameManager.GiveWeapon_Original
    给当前 Bot 主动补发普通 Grenade
    记录新 Grenade
    再 Select(3)
    再 WPN_Throw.Throw
```

## 最终原则

```text
补发的是当前 Bot 自己的真实 Grenade。
不能拿其他 Bot 的 Grenade 指针给它用。
不能伪造 Grenade 指针。
不能对 0x0 调 WPN_Throw.Throw。
```

# 2.7.4 v2.12.7 safe-give-argfix 修复

## 用户测试反馈

v2.12.6 仍然不行，日志里出现：

```text
已记录普通Grenade weaponIndex
knownGrenadeWeaponIndex = 416
knownGrenadeIndexes = ["6", "210", "416"]

异常：tryGiveBotGrenadeForThrow.activeGive
Error: expected an integer
```

## 原因

v2.12.6 的主动补发方向是对的，但调用参数类型写错了。

错误写法：

```text
GameManager_GiveWeapon_Original(playerPtr, idx, false, false, ptr(0))
```

Frida NativeFunction 对这里的参数要求整数，`false, false` 会触发：

```text
Error: expected an integer
```

## 最终修复方案

改成：

```text
GameManager_GiveWeapon_Original(playerPtr, (idx | 0), 0, 0, ptr(0))
```

含义：

```text
weaponIndex 强制转 int
autoGiveUp 传 0
autoSelect 传 0
methodInfo 传 ptr(0)
```

## 最终测试结果

v2.12.7 日志显示：

```text
bot_throw_drive_skipped_no_grenade = 0
vbc_skipped_no_grenade = 0
vbc_suppress_no_grenade = 0
bot_throw_gate_block_no_grenade = 0
```

说明：

```text
部分 Bot 没有 Grenade 指针的问题已经解决。
```

主动补发结果：

```text
bot_grenade_active_give_attempts = 7
bot_grenade_active_give_success = 7
bot_grenade_active_give_failed = 0
```

说明：

```text
主动补发 Grenade 成功。
补发失败为 0。
```

VBC 投掷结果：

```text
bot_throw_drive_success = 75
vbc_success = 75
error_count = 0
```

说明：

```text
VBC 接管正常。
Bot 能通过 VBC 扔手雷。
没有 JS 错误。
```

## 最终结论

```text
v2.12.7 作为当前最终标准。
部分 Bot 不会扔手雷的问题，最终通过“多 key 缓存 + 投掷前补记录 + 主动补发普通 Grenade + GiveWeapon 参数修复”解决。
```

```text
彻底删除状态机后，Bot 扔雷不稳定。
出现玩家手雷扔一个就没了，Bot 也不会继续丢手雷。
```

## 最终结论

不删除状态机相关主结构。

原因：

```text
状态机或其相关路径承担过临时 Select(3)、投掷节奏、冷却衔接等作用。
删除过多会影响 Bot 扔雷。
```

最终原则：

```text
可以隐藏部分 UI。
但不要激进删除状态机相关核心链路。
```
