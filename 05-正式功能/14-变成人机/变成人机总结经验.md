# 变成人机 总结经验

## 玩家身份判断（踩坑记录）

### 错误方式：attach 看返回值

```javascript
Interceptor.attach(addr, {
    onLeave: function(retval) {
        if (retval.toInt32() === 0) return;  // ❌
        // 以为返回1就是自己，实际BOT也可能返回1
    }
});
```

`attach` 只是旁观，拿不到原始函数的真实结果，只能猜。

### 正确方式：replace + origIsMy

```javascript
let orig = new NativeFunction(addr, 'bool', ['pointer', 'pointer']);

Interceptor.replace(addr, new NativeCallback(function(playerPtr, methodInfo) {
    let result = orig(playerPtr, methodInfo);  // 让游戏自己判断
    if (result) { /* 这才是本地玩家 */ }
    return result;
}, 'bool', ['pointer', 'pointer']));
```

| 方法 | 原理 | 准确率 |
|------|------|--------|
| `attach` | 旁观猜返回值 | 可能抓到 BOT ❌ |
| `replace` + `origIsMy()` | 调用原始函数，让游戏判断 | 100% ✅ |

### 教训
之前用 `attach` 一直抓到 BOT 的地址，导致 isBot 写入到 BOT 身上，玩家自己没效果。

## Hook 的作用

Hook 的唯一目的：**获取动态地址（Player 指针）**。

游戏运行时，Player 对象的地址每次启动都不一样。Hook `Player$$get_isMyPlayer` 可以在游戏调用该方法时抓到 Player 对象地址，从而得到 `ClientData` 地址，后续直接读写内存。

Hook 只在**获取地址阶段**起作用，写入 isBot 的操作在 Hook 外部独立运行。

## 写入时机

一次性写入，没有定时器。

```
UI 点击"开始" → modify() → writeBot(1)
UI 点击"关闭" → stop()   → writeBot(0)
```

## 技术总结

| 阶段 | 方法 | 时机 |
|------|------|------|
| 获取地址 | `replace` + `origIsMy()` | 脚本加载后下一次游戏调用 |
| 修改 isBot | `writeU8(1)` | UI 点击时一次性写入 |
| 恢复 isBot | `writeU8(0)` | UI 点击时一次性写入 |
