一、核心功能与设计

两个脚本都是 Frida 注入脚本，用于将游戏中的 Bot 传送至出生点（spawn = {x:13.6, y:14.1, z:0.1}）。核心流程：

    通过 Hook 获取 GM（GameManager）和 MM（MapManager）单例。

    通过 Hook Bot_Update 捕获 Bot 组件实例，进而获得对应的 Player 指针。

    通过 GM->allPlayers 扫描所有玩家。

    调用 CC.disable → Transform.set_position → CC.enable 完成传送。

二、主要区别
特性	gather.js (v1.2)	AAAAA-bot_to_spawn_v24.js (v24)
Bot 跟踪策略	recentBotPlayers 对象，记录最近 5 秒内出现的 Bot，每次传送后清空。	trackedBots + trackedPlayers 对象，永久保留所有曾见过的 Bot 和 Player，从不清理。
玩家列表维护	传送时动态扫描 GM->allPlayers + 5 秒内的 recentBot，不保留长期缓存。	永久累积 trackedPlayers，每次传送前将扫描结果和新 Bot 中的 Player 合并进去，从不删除过期条目。
去重方式	使用时间戳（5 秒窗口），trackFromBot 不判断是否已记录。	使用 botUpdateSeen 对象，每个 Bot 组件只记录一次。
生命周期管理	提供 enable() / disable()，禁用时 detach 所有 Hook，清空全局变量。	无 disable 功能，脚本注入即永久运行，无法干净卸载。
对外接口	导出 modules.gather 对象（enable/disable/gather），通过 send 发送 JSON 消息。	通过 rpc.exports 暴露 teleport/status/list 方法。
额外功能	无。	提供 list() 打印所有玩家，status() 查询状态，teleportSinglePlayer() 单独传送。
主动获取 GM/MM	仅依赖 Hook 捕获。	额外使用 setTimeout 主动调用 getGM()/getMM()。
日志方式	调用 sendLog（推测会转发至控制台/UI）。	直接 console.log 带前缀 [v24]。
传送计数	每次执行后 tn++，并发送 {type:'done',n,bots,fail}。	同样 tn++，发送 {t:'done',n,bots,fail}。
三、指针泄露分析

结论：两个脚本均不会导致传统意义上的 Native 内存泄露，但 v24 存在 JS 堆内存无限增长问题。

    Native 内存：脚本只调用游戏原生的 CC.set_enabled、set_position 等函数，不主动分配需释放的 Native 资源。Memory.alloc(16) 分配的缓冲区在脚本生命周期内复用，无泄露。

    JS 堆内存：

        gather.js：recentBotPlayers 在每次传送后清空，且条目带 5 秒过期，大小可控，无泄露。

        v24：trackedBots、trackedPlayers、botUpdateSeen 三个对象无限增长。每局游戏新产生的 Bot 都会永久记录，即使对应游戏对象已被销毁。长期运行会导致 JS 堆占用持续增加（例如 1000 局后可能存有数万个无效指针）。每个键为指针字符串（如 "0x7ff123456789"），值仅为 NativePointer 或普通对象，虽不直接泄露 Native 内存，但会造成性能下降和内存膨胀。

四、线程问题分析

结论：不存在数据竞争，但长时间阻塞主线程的风险存在。

    Frida 回调模型：Interceptor 的回调在目标线程中执行，但 JavaScript 代码是同步且单线程的。同时触发的多个回调会被排队，不会并发修改共享数据，因此没有竞态条件。

    阻塞风险：

        两个脚本的传送逻辑都会遍历大量玩家（尤其是 v24 的 trackedPlayers 可能很大），并为每个活 Bot 调用多个 Native 函数（getCC, cSE, spi 等）。这些操作在游戏主线程（如 Player.Update）中执行，若玩家数量过多（例如 200+），可能导致明显卡顿。

        v24 由于累积的玩家列表更庞大，阻塞风险更高。

    Hook 重入：set_position 等 Native 操作可能间接触发其他 Hook（例如 Player.Update），但脚本中未对此做防护，理论上可能造成递归调用。不过实际游戏中这些函数通常不会触发已 Hook 的事件，风险较低。
