objectInPV / objectInCV 为 0 的分析
===================================

问题描述:
  运行时日志显示：objectInPV count=0, objectInCV count=0
  即使成功切换到第三人称，这两个列表仍然为空。

JS 中的读取逻辑:
  pvListPtr = character.add(0x34).readPointer()
  pvItems = pvListPtr.add(0x10).readPointer()
  pvCount = pvListPtr.add(0x18).readU32()

可能原因分析:
  1. CharacterModel 偏移是否正确？
     - 当前 JS 使用 Model_objectInPV = 0x34, Model_objectInCV = 0x38
     - 需 dump.cs 确认 CharacterModel 继承 Model 后字段偏移是否有变化

  2. 字段是否位于父类？
     - Model 类定义中有 objectInPV 和 objectInCV，子类 CharacterModel 继承后偏移应保持

  3. 当前对象基址是否正确？
     - Player.currentCharacter 读取的指针已用于获取 spine/spine1，说明对象基本有效

  4. List<T> 布局是否正确？
     - 使用 0x10 = _items, 0x18 = _size (Il2CPP List<T> 标准布局)

  5. 列表是否尚未初始化？
     - 可能游戏在 CharacterModel 初始化时未填充这些列表

  6. 是否读取了错误实例？
     - 可能 Player.currentCharacter 不是真正的 CharacterModel，而是其他类型

  7. 是否应在 Weapon 的 Model 上读取？
     - 武器模型也有 objectInPV/objectInCV，但当前代码在 CharacterModel 上读取

诊断建议:
  - 在 debugmodel 中输出 character 的 klass 名称，确认类型
  - 直接读取 character + 0x34 的内存值，确认是否为有效 List 对象指针
  - 对比 dump.cs 中 CharacterModel 和 Model 的字段偏移
