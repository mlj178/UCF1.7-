交接摘要（Handoff Summary）
==========================

1. 当前项目架构
   Python UI (customtkinter + frida + psutil) + Frida JS 注入 Unity IL2CPP 游戏

2. 当前已正常工作的功能
   - 自动连接和注入 Frida JS
   - 捕获 GameManager / CameraManager
   - 激活 CinemachineFreeLook
   - 显示全身模型和武器
   - 状态机、断线重连、日志限流
   - 瞄准诊断 Hook 已安装

3. 当前主要问题
   - 准星与枪口方向不一致
   - 实际子弹可能仍用第一人称 Ray
   - 角色遮挡准星
   - 相机俯视感明显
   - objectInPV/CV 数量为 0
   - set_modelVisible 报错
   - Singleton 越界

4. 已确认根因
   - CameraManager Singleton 在 Awake 前调用会越界（已确认）
   - set_modelVisible 缺少 MethodInfo* 参数（已确认，IDA 验证）
   - 4 个射击相关 Hook 地址错误（已确认，与 IDA 相差 0x1000）
   - 进程为 32 位（x86），pointerSize=4（已确认）

5. 尚未确认的问题
   - objectInPV/CV 为 0 的根因
   - 真实枪口 Transform 运行时枚举
   - 修改射击 Ray 后的实际效果

6. 当前 GameAssembly.dll 版本信息
   大小: 15925248 bytes
   运行时基址: 0x6be70000 (ASLR，每次不同)
   Unity 版本: 2020.3.30f1

7. 进程位数和 pointerSize
   32 位 (x86), pointerSize=4
   调用约定: __cdecl
   Frida 应使用: 'mscdecl'

8. 已验证 RVA
   见 13_verified_addresses.txt

9. 已验证字段偏移
   见 13_verified_addresses.txt 和 04_dump_classes.txt

10. 已验证 NativeFunction 签名
    见 11_nativefunction_signatures.txt

11. Ray ABI 结论
    32 位 __cdecl:
    - GetShootRay 返回值通过隐藏 retBuf 传递（24 bytes）
    - Damage 中 Ray 通过栈内联传递（24 bytes inline）

12. 真实枪口节点结论
    未运行时确认，代码中通过枚举 Transform 子节点搜索关键词

13. objectInPV/objectInCV 为 0 的原因
    可能原因：偏移错误（32 位布局需确认）、对象类型错误、列表未初始化

14. set_modelVisible 报错原因
    已确认：缺少 MethodInfo* 参数
    修复: new NativeFunction(base.add(RVA), 'void', ['pointer', 'bool', 'pointer'])
         调用: setModelVisible(pcm, false, ptr(0))

15. CameraManager Singleton 越界原因
    Awake 前 IL2CPP 对象未初始化，禁止提前调用 Singleton 获取
