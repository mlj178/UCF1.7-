# 第三人称视角 — 实现步骤与目标

## 目标

将 UCF1.7 从第一人称视角修改为**完整第三人称视角**，支持：
- 相机在角色身后上方，可见全身模型
- 鼠标控制相机环绕角色
- 滚轮调节相机距离
- 射击射线从枪口发出，准星与命中点一致
- 可随时开关切换

## 技术方案

利用游戏已有的 **CinemachineFreeLook** 相机 + **PV/CV 双视角框架**，通过 Frida Hook 实现视角切换和参数修改。

#### 1.7 ObscuredBool 加密机制（已完成）

```
ObscuredBool 结构体（ACTk 反作弊）
├── 0x0 currentCryptoKey  (byte)   — 当前加密密钥
├── 0x4 hiddenValue       (int)    — 加密后的值
├── 0x8 inited            (bool)   — 是否已初始化
├── 0x9 fakeValue         (bool)   — 伪造值（反作弊诱饵）
└── 0xA fakeValueActive   (bool)   — 是否启用伪造值
```

**加密原理**：`hiddenValue = 真实值 XOR currentCryptoKey`，读取时通过 `InternalDecrypt()` 解密

**关键方法**：
- `Encrypt(bool value)` → RVA: 0x7F9330 — 加密
- `Decrypt(int value)` → RVA: 0x7F9290 — 解密
- `GetEncrypted()` → RVA: 0x7F9580 — 获取加密值
- `SetEncrypted(int)` → RVA: 0x7F9750 — 设置加密值
- `GetDecrypted()` → RVA: 0x7F9570 — 获取解密值
- `InternalDecrypt()` → RVA: 0x7F95D0 — 内部解密

**修改策略**：不要直接改内存，而是调用 `SetEncrypted()` 方法，或 Hook `InternalDecrypt()` 返回 false

#### 1.8 Model.SetModelLayer() 模型分层（已完成）

```
Model.Type 枚举：
  Character = 0  — 全身角色模型（CV可见）
  PlayerView = 1 — 第一人称手臂模型（PV可见）

Model 关键字段：
├── 0x30 owner          (Player)        — 所属玩家
├── 0x34 objectInPV     (List<GameObject>) — PV模式可见的对象
├── 0x38 objectInCV     (List<GameObject>) — CV模式可见的对象
└── 0x3C sockets        (List<Socket>)  — 插槽

SetModelLayer(Model.Type mdlType, int layer) → RVA: 0xB4B4C0
OnOwnerObserveModeChange(Model.Type mode) → RVA: 0xB4B300
```

**关键发现**：游戏通过 `objectInPV` 和 `objectInCV` 两个列表分别管理第一人称和观战视角的可见对象。切换视角时，`OnOwnerObserveModeChange` 会根据模式显示/隐藏对应列表中的对象。

#### 1.9 射击射线来源（已完成）

```
WPN_Gun (继承 Weapon → CFAnimator)
├── Damage(Ray ray) → RVA: 0xB603D0  — 射击伤害计算，接收 Ray 参数
├── GunShoot()      → RVA: 0xB614C0  — 开火入口
├── GunShoot_Logic() → RVA: 0xB61170 — 开火逻辑
├── GenerateBullet() → RVA: 0xB61F40 — 生成子弹

PlayerController
├── UseWeapon()     → RVA: 0xB13450  — 使用武器入口
└── CameraRotation() → RVA: 0xB12420 — 相机旋转（含鼠标速度控制）

```

**关键发现**：`WPN_Gun.Damage(Ray ray)` 直接接收一个 `Ray` 参数，射线是在调用前构造的。这意味着射线的构造逻辑在 `GunShoot_Logic()` 或 `GunShoot()` 中，Hook `Damage` 方法可以替换 Ray 的 origin 和 direction。v9 瞄准诊断通过 Hook `Recoil.GetShootRay`（RVA: 0xB185C0）观察射击射线构造过程。

## 风险与难点

1. ~~**ObscuredBool 加密**~~：已解决，改用 Hook ChangePVandCV + SetObserveMode 方案，不再直接修改 playerView
2. **射击射线适配**：FPS 射线从相机中心发出，第三人称需要从枪口发出，v9 瞄准诊断已采集数据，偏差原因待分析
3. ~~**动画同步**~~：已解决，通过 OnOwnerObserveModeChange 触发游戏原生 PV/CV 动画切换
4. **相机碰撞**：第三人称相机可能穿墙，需要碰撞检测（可选）
5. **网络同步**：虽然是单机游戏，但联机时服务器可能校验视角数据
6. **IL2CPP x64 ABI**：值类型返回（Vector3/Quaternion/Ray）需要特殊处理，必须使用 _Injected 版本或正确处理返回缓冲区

## v3 修复记录

### 问题1: CameraManager 获取方式完全错误 (严重)

**现象**: `tryGetCameraManager()` 只检查缓存，没有主动获取 CameraManager 单例的逻辑。如果 Awake Hook 没触发，CameraManager 永远为 null。

**根因**: `CameraManager` 是 `Singleton<CameraManager>` 全局单例，与 `Player.cameraManager`（类型是 `PlayerCameraManager`）是完全不同的两个类。

**修复**:
- 添加 `CameraManager_SingletonMethodInfo: 0xE1CE68`（通过 script.json 验证）
- `tryGetCameraManager()` 改为通过 `Singleton_GetInstance(methodInfo)` 主动获取
- 保留 Awake Hook 作为辅助缓存

### 问题2: CameraManager.Awake RVA 错误 (严重)

**现象**: Hook 无法捕获 CameraManager 实例。

**根因**: RVA 写错为 `0xB366F0`，实际应为 `0xB35550`（dump.cs 和 script.json 均验证）。

**修复**: 修正 RVA 为 `0xB35550`。

### 问题3: ChangePVandCV Hook 方式导致崩溃 (严重)

**现象**: 开启第三人称后游戏崩溃。

**根因**: 使用 `args[0] = ptr(0)` 破坏 this 指针，函数内部访问 this 成员时访问非法内存。

**修复**: 改用 `Interceptor.replace`，第三人称时直接返回空函数体，第一人称时调用原函数。

### 问题4: 未使用的变量残留 (轻微)

## v9 修复记录 — 瞄准诊断系统 + IL2CPP x64 ABI 修复

### 修复1: IL2CPP x64 值类型 ABI 错误 (严重 — 诊断数据全部为垃圾值)

**现象**: 瞄准诊断输出的 `actualCamera.position`、`cameraRay.origin`、`muzzle.position` 等所有 Vector3/Quaternion/Ray 数据均为零或随机值。

**根因**: IL2CPP x64 调用约定中，返回值大于 8 字节的结构体（Vector3=12B, Quaternion=16B, Ray=24B）不通过寄存器返回，而是由调用者分配返回缓冲区，将缓冲区指针作为第一个隐藏参数传入。原代码将这些函数声明为返回 `pointer`，导致：
- Frida 将返回值解释为指针，实际是垃圾地址
- 从垃圾地址读取 Vector3/Quaternion 数据，得到零或随机值
- `ScreenPointToRay`、`WorldToScreenPoint`、`Physics.Raycast` 同样受影响

**修复**:
- 优先使用 `_Injected` 版本（签名更清晰：`void(this, ..., ret, methodInfo)`）
- `Transform.get_position_Injected` → `void(Transform*, Vector3* ret, MethodInfo*)`
- `Transform.get_rotation_Injected` → `void(Transform*, Quaternion* ret, MethodInfo*)`
- `Transform.get_forward/right/up` → `void(Vector3* retBuf, Transform*, MethodInfo*)`
- `Camera.ScreenPointToRay_Injected` → `void(Camera*, Vector2*, int eye, Ray* ret, MethodInfo*)`
- `Camera.WorldToScreenPoint_Injected` → `void(Camera*, Vector3*, int eye, Vector3* ret, MethodInfo*)`
- `Physics.Raycast` → `bool(Ray*, RaycastHit*, float, MethodInfo*)`（Ray 通过引用传递）
- 所有调用处改为：先 `Memory.alloc` 分配返回缓冲区，调用后从缓冲区读取结果

### 修复2: Python UI 未处理 aim_diag 消息 (严重 — 诊断日志丢失)

**现象**: 点击"开始瞄准诊断"后，JS 端正常采集数据并发送 `aim_diag` 消息，但 Python 端未处理，诊断日志文件为空。

**根因**: `_on_message()` 只处理了 `log` 和 `state_changed` 两种消息类型，缺少 `aim_diag` 和 `aim_diag_complete` 的处理。

**修复**:
- 新增 `aim_diag` 消息处理：将日志行追加到 `self._aim_diag_lines` 缓冲
- 新增 `aim_diag_complete` 消息处理：将缓冲中的日志写入独立文件
- 初始化 `self._aim_diag_lines = []`

### 修复3: Camera 属性方法缺少 MethodInfo 参数 (中等)

**现象**: `cameraGetFieldOfView`、`cameraGetPixelWidth` 等调用时未传入 `MethodInfo*` 参数。

**根因**: IL2CPP 非静态方法需要 `this` 和 `MethodInfo*` 两个参数，原代码只传了 `this`。

**修复**: 所有 Camera 实例方法调用添加 `ptr(0)` 作为 MethodInfo 参数。

### 修复4: Transform.GetChild/GetChildCount/GetParent 缺少 MethodInfo 参数 (中等)

**修复**: 所有 Transform 实例方法调用添加 `ptr(0)` 作为 MethodInfo 参数。

## 瞄准诊断系统

### 功能概述

独立的诊断功能，通过 Hook 射击相关函数采集准星射线、枪口位置、射击 Ray 等数据，生成详细日志文件，用于分析射击偏差原因。

### RPC 接口

| RPC | 参数 | 说明 |
|-----|------|------|
| `startaimdiagnostic` | durationSeconds (默认15) | 启动诊断，采集初始静态快照 |
| `stopaimdiagnostic` | — | 停止诊断，写入日志文件 |
| `captureaimsnapshot` | tag (字符串) | 手动采集一次静态快照 |
| `getaimdiagstatus` | — | 获取当前诊断状态 |

### 射击观察 Hook

| Hook 函数 | RVA | 说明 |
|-----------|-----|------|
| Recoil.GetShootRay | 0xB185C0 | 获取射击射线，x64 ABI: `void(Ray* retBuf, Recoil*, MethodInfo*)` |
| WPN_Gun.GunShoot | 0xB614C0 | 开火入口 |
| WPN_Gun.GunShoot_Logic | 0xB61170 | 开火逻辑 |
| WPN_Gun.Damage | 0xB603D0 | 射击伤害，Ray 通过引用传递 |

### 诊断数据结构

每次静态快照包含以下节：

```
[Session]        — 会话信息 (sessionId, PID, 状态机状态)
[Pointers]       — 关键指针 (GameManager, CameraManager, Player, Weapon 等)
[Camera]         — 实际 Unity Camera 数据 (position, rotation, forward, FOV)
[FreeLook]       — CinemachineFreeLook 参数 (Follow, LookAt, Orbits, Composer)
[CrosshairRay]   — 准星射线 (ScreenPointToRay + Physics.Raycast)
[WeaponMuzzle]   — 武器和枪口数据 (weaponRoot, muzzle, rightHand)
[Skeleton]       — 骨骼数据 (spine, spine1, neck, characterRoot)
[AnimatorState]  — 动画器状态 (cameraRotation, Animator 类型)
[ScreenProjection] — 屏幕投影误差 (muzzle, muzzleForward, desiredDirection, hitPoint)
[PV_CV_Anomaly]  — PV/CV 异常检查
```

每次射击快照：

```
========== SHOT 0001 BEGIN ==========
sessionId / shotId / timestamp / hookName
actualCamera.position / forward
crosshair / cameraRay (origin, direction, hitPoint)
weapon / muzzle (position, forward)
desiredDirection / angle.muzzle_to_target / angle.shootRay_to_cameraRay
errorPixels.muzzleForward100
inputRay.origin / direction (仅 GetShootRay 和 Damage Hook)
========== SHOT 0001 END ==========
```

## IL2CPP x64 值类型 ABI 规则

在 IL2CPP x64 编译下，函数调用的参数传递和返回值处理遵循以下规则：

### 返回值

| 返回类型 | 大小 | 传递方式 | NativeFunction 声明 |
|---------|------|---------|-------------------|
| int, float, bool, 指针 | ≤ 8B | 通过 rax/xmm0 返回 | 正常声明返回类型 |
| Vector3 | 12B | 调用者分配 retBuf，作为第一隐藏参数 | `'void'` 返回，第一参数为 `pointer` |
| Quaternion | 16B | 同上 | 同上 |
| Ray | 24B | 同上 | 同上 |
| RaycastHit | >24B | 同上 | 同上 |

### 参数

| 参数类型 | 大小 | 传递方式 |
|---------|------|---------|
| int, float, bool | ≤ 8B | 通过寄存器传递 |
| 指针 (Transform*, Camera* 等) | 8B | 通过寄存器传递 |
| Vector3 | 12B | 通过引用传递（指针） |
| Quaternion | 16B | 通过引用传递（指针） |
| Ray | 24B | 通过引用传递（指针） |

### _Injected 版本

Unity 内部生成的 `_Injected` 版本函数签名更清晰，值类型返回值和参数都通过指针传递：

```
// 非 _Injected: 返回 Vector3，x64 ABI 需要隐藏 retBuf 参数
Vector3 Transform_get_forward(Transform* __this, MethodInfo* method)
→ 实际调用: void Transform_get_forward(Vector3* retBuf, Transform* __this, MethodInfo* method)

// _Injected: 显式声明返回值指针
void Transform_get_position_Injected(Transform* __this, Vector3* ret, MethodInfo* method)
→ 实际调用: void Transform_get_position_Injected(Transform* __this, Vector3* ret, MethodInfo* method)
```

**建议**: 优先使用 `_Injected` 版本，签名更明确，不易出错。
