# 第三人称视角 — 实现步骤与目标

## 目标

将 UCF1.7 从第一人称视角修改为**完整第三人称视角**，支持：
- 相机在角色身后上方，可见全身模型
- 鼠标控制相机环绕角色
- 滚轮调节相机距离
- 射击射线从枪口发出，准星与命中点一致
- 可随时开关切换

## 技术方案

利用游戏已有的 **CinemachineFreeLook** 相机 + **PV/CV 双视角框架**，通过 Frida Hook 实现视角切换和参数修改。

**关键发现**：

- `m_Orbits`(0x194) 控制三个轨道的半径（距离），可通过修改此值调整相机距离
- 已有 `set_Follow()`(RVA: 0x439270) 和 `set_LookAt()`(RVA: 0x2E7E10) 可直接调用

#### 1.7 ObscuredBool 加密机制（已完成）

```
ObscuredBool 结构体（ACTk 反作弊）
├── 0x0 currentCryptoKey  (byte)   — 当前加密密钥
├── 0x4 hiddenValue       (int)    — 加密后的值
├── 0x8 inited            (bool)   — 是否已初始化
├── 0x9 fakeValue         (bool)   — 伪造值（反作弊诱饵）
└── 0xA fakeValueActive   (bool)   — 是否启用伪造值
```

**加密原理**：`hiddenValue = 真实值 XOR currentCryptoKey`，读取时通过 `InternalDecrypt()` 解密

**关键方法**：
- `Encrypt(bool value)` → RVA: 0x7F9330 — 加密
- `Decrypt(int value)` → RVA: 0x7F9290 — 解密
- `GetEncrypted()` → RVA: 0x7F9580 — 获取加密值
- `SetEncrypted(int)` → RVA: 0x7F9750 — 设置加密值
- `GetDecrypted()` → RVA: 0x7F9570 — 获取解密值
- `InternalDecrypt()` → RVA: 0x7F95D0 — 内部解密

**修改策略**：不要直接改内存，而是调用 `SetEncrypted()` 方法，或 Hook `InternalDecrypt()` 返回 false

#### 1.8 Model.SetModelLayer() 模型分层（已完成）

```
Model.Type 枚举：
  Character = 0  — 全身角色模型（CV可见）
  PlayerView = 1 — 第一人称手臂模型（PV可见）

Model 关键字段：
├── 0x30 owner          (Player)        — 所属玩家
├── 0x34 objectInPV     (List<GameObject>) — PV模式可见的对象
├── 0x38 objectInCV     (List<GameObject>) — CV模式可见的对象
└── 0x3C sockets        (List<Socket>)  — 插槽

SetModelLayer(Model.Type mdlType, int layer) → RVA: 0xB4B4C0
OnOwnerObserveModeChange(Model.Type mode) → RVA: 0xB4B300
```

**关键发现**：游戏通过 `objectInPV` 和 `objectInCV` 两个列表分别管理第一人称和观战视角的可见对象。切换视角时，`OnOwnerObserveModeChange` 会根据模式显示/隐藏对应列表中的对象。

#### 1.9 射击射线来源（已完成）

```
WPN_Gun (继承 Weapon → CFAnimator)
├── Damage(Ray ray) → RVA: 0xB613D0  — 射击伤害计算，接收 Ray 参数
├── GunShoot()      → RVA: 0xB624C0  — 开火入口
├── GunShoot_Logic() → RVA: 0xB62170 — 开火逻辑
├── GenerateBullet() → RVA: 0xB61F40 — 生成子弹
└── GunShoot_NoCheck() → RVA: 0xB621F0 — 无检查开火

PlayerController
├── UseWeapon()     → RVA: 0xB13450  — 使用武器入口
└── CameraRotation() → RVA: 0xB12420 — 相机旋转（含鼠标速度控制）
    └── SpeedRemap() → RVA: 0xB13050 — 鼠标速度重映射
```

**关键发现**：`WPN_Gun.Damage(Ray ray)` 直接接收一个 `Ray` 参数，射线是在调用前构造的。这意味着射线的构造逻辑在 `GunShoot_Logic()` 或 `GunShoot()` 中，Hook `Damage` 方法可以替换 Ray 的 origin 和 direction。

## 风险与难点

1. **ObscuredBool 加密**：playerView 使用 ACTk 反作弊加密，直接内存修改可能被检测
2. **射击射线适配**：FPS 射线从相机中心发出，第三人称需要从枪口发出，逻辑复杂
3. **动画同步**：第一人称手臂动画和第三人称全身动画的切换
4. **相机碰撞**：第三人称相机可能穿墙，需要碰撞检测
5. **网络同步**：虽然是单机游戏，但联机时服务器可能校验视角数据

## v3 修复记录

### 问题1: CameraManager 获取方式完全错误 (严重)

**现象**: `tryGetCameraManager()` 只检查缓存，没有主动获取 CameraManager 单例的逻辑。如果 Awake Hook 没触发，CameraManager 永远为 null。

**根因**: `CameraManager` 是 `Singleton<CameraManager>` 全局单例，与 `Player.cameraManager`（类型是 `PlayerCameraManager`）是完全不同的两个类。

**修复**:
- 添加 `CameraManager_SingletonMethodInfo: 0xE1CE68`（通过 script.json 验证）
- `tryGetCameraManager()` 改为通过 `Singleton_GetInstance(methodInfo)` 主动获取
- 保留 Awake Hook 作为辅助缓存

### 问题2: CameraManager.Awake RVA 错误 (严重)

**现象**: Hook 无法捕获 CameraManager 实例。

**根因**: RVA 写错为 `0xB366F0`，实际应为 `0xB35550`（dump.cs 和 script.json 均验证）。

**修复**: 修正 RVA 为 `0xB35550`。

### 问题3: ChangePVandCV Hook 方式导致崩溃 (严重)

**现象**: 开启第三人称后游戏崩溃。

**根因**: 使用 `args[0] = ptr(0)` 破坏 this 指针，函数内部访问 this 成员时访问非法内存。

**修复**: 改用 `Interceptor.replace`，第三人称时直接返回空函数体，第一人称时调用原函数。

### 问题4: 未使用的变量残留 (轻微)

**现象**: `playerViewAddr`, `originalHiddenValue`, `originalCryptoKey` 三个变量声明但未使用。

**修复**: 移除这些变量（v3 已改用 Hook ChangePVandCV 阻止切回，不再直接修改 playerView）。

### 问题5: 房间结束时未清理 CameraManager 缓存 (中等)

**现象**: 房间切换后 CameraManager 缓存可能指向已销毁的对象。

**修复**: 在 `OnRoomShutdown` 和 `OnGameEnd` 中将 `cameraManager = null`。

### 新增 Singleton MethodInfo 地址

| 单例类 | MethodInfo 地址 | 说明 |
|--------|----------------|------|
| GameManager | 0xE1CE64 | 已验证，与正式版一致 |
| CameraManager | 0xE1CE68 | v3 新增，通过 script.json 验证 |

两个单例都使用同一个 `Singleton_GetInstance` 函数 (RVA: 0x4A8170)。

### 问题6: Interceptor.replace 导致无限递归崩溃 (严重)

**现象**: 程序打开就卡死，Frida 附加后无更多日志。

**根因**: `Interceptor.replace` 替换目标地址后，原函数指针 `origChangePVandCV` 仍指向该地址，调用它会进入替换后的函数，导致无限递归。

**修复**:
- 改用 `Interceptor.attach` 仅监控 `ChangePVandCV`，不阻止执行
- 主循环每 500ms 重新激活 FreeLook，抵消 `ChangePVandCV` 切回 PV 的效果

### 问题7: 主循环未持续激活 FreeLook (中等)

**现象**: `ChangePVandCV` 被调用后，FreeLook 被停用，第三人称失效。

**根因**: 主循环只检查 Follow 指针，没有重新激活 FreeLook。

**修复**: 主循环每 10 次 (500ms) 调用 `setFreeLookActive(camMgr, 1)` 保持激活。

## v6 修复记录 (JS) + v4 修复记录 (Python)

### 修复1: OnRoomStart 高频触发 (严重 — 第一优先级)

**现象**: 日志中"房间开始"在几秒内出现数千次。

**根因**: RVA `0xAF6A00` 实际是 `MonoBehaviour.Update()`，不是 `OnRoomStart`。Update 每帧调用，导致每秒数十次触发。

**修复**:
- 移除错误的 `OnRoomStart` Hook (RVA: 0xAF6A00)
- 改用 `GameManager.NewGameRoundStart()` (RVA: 0xAEBCB0)，通过 dump.cs 验证
- 添加 `roomStartLogged` 标志，同一房间只输出一次"房间开始"
- 辅助使用 `AddPlayer` (0xAF9A90) 和 `SpawnEvent` (0xB36A30) 检测房间状态

### 修复2: GameManager 构造函数重复触发 (严重 — 第一优先级)

**现象**: `GameManager.ctor` 被捕获多次，日志刷屏。

**根因**: RVA `0xAF9A90` 实际是 `GameManager.AddPlayer()`，不是构造函数。每次有玩家加入都会触发。

**修复**:
- 改用 `GameManager.Awake()` (RVA: 0xAFA250) 捕获单例，通过 dump.cs 验证
- Awake 只在对象初始化时调用一次
- 保留 `Singleton<GameManager>.get_instance()` 作为备用获取方式

### 修复3: CameraManager Singleton MethodInfo 地址错误 (严重)

**现象**: CameraManager 无法通过 Singleton 获取。

**根因**: MethodInfo 地址写错为 `0xE1CE68`，实际应为 `0xE1CD68`（通过 script.json Address: 14798184 验证）。

**修复**: 修正为 `0xE1CD68`。

### 修复4: Python 日志重复写入 (严重 — 第一优先级)

**现象**: 同一条 JS 日志在文件中写入两次。

**根因**: `_on_message()` 先写 `file_log`，随后 `_safe_log()` → `_log()` 又写一次 `file_log`。

**修复**:
- `_log_ui()` 只写 UI，不再写文件日志
- `_on_message()` 中文件日志只写一次
- 分离 UI 日志和文件日志的写入路径

### 修复5: enable() 失败后状态仍为 true (严重 — 第一优先级)

**现象**: GameManager 未就绪时，`enable()` 返回 `{ ok: false, enabled: true }`。

**根因**: 先设置 `state.thirdPerson=true`，再执行启用步骤，失败后未恢复。

**修复**:
- `enableThirdPerson()` 先执行所有步骤
- 全部成功后才调用 `setState(STATE.TP_ENABLED)`
- 任一步骤失败直接返回 `{ ok: false, enabled: false, error: ... }`
- 不再使用独立的 `state.thirdPerson` 标志，直接用 `fsm.current === STATE.TP_ENABLED` 判断

### 修复6: 空 catch 隐藏真实错误 (严重 — 第一优先级)

**现象**: JS 中存在大量 `catch (e) {}`，隐藏了 RVA 错误、字段偏移错误、无效指针等关键信息。

**修复**:
- 所有关键路径的 catch 都调用 `logError(key, msg)` 记录错误
- 关键操作包括：GameManager 获取、CameraManager 获取、FreeLook 获取、Follow/LookAt 设置、playerView 修改、模型 Layer 设置、CameraRotation Hook
- 日志格式包含模块和操作：`[Camera] set_Follow failed: ...`
- 高频错误每 3 秒最多记录一次（`logError` 限流）

### 修复7: NativePointer 比较方式错误 (第二优先级)

**现象**: 使用 `currentFollow !== charContainer` 比较指针，Frida NativePointer 直接用 `!==` 比较的是对象引用而非地址值。

**修复**:
- 统一使用 `ptrEquals(a, b)` 函数，内部调用 `a.equals(b)`
- 比较前检查指针非空
- 涉及 Follow、LookAt、GameManager、CameraManager、Player、FreeLook 等所有指针比较

### 修复8: Python/JS 状态不同步 (第二优先级)

**现象**: JS 因退出房间、对象失效或异常自动关闭后，Python UI 仍显示第三人称已开启。

**修复**:
- JS 增加 `getstatus()` RPC，返回 `enabled`、`state`、`haveGM`、`haveCameraManager`、`lastError`、`stats`
- Python 新增 `_status_sync_loop()` 后台线程，每 1 秒调用 `getstatus()`
- JS 状态变化时主动发送 `state_changed` 事件
- Python 收到后同步 `is_enabled`、按钮文字、按钮颜色、状态标签
- Frida 断开时立即将连接和启用状态设为 false

### 修复9: 主循环频率和重复操作过高 (第二优先级)

**现象**: 每 50ms 重复执行对象查找、playerView 写入、Follow/LookAt 设置等操作。

**修复**:
- 引入状态机：`NO_GAME` → `WAITING_ROOM` → `ROOM_READY` → `TP_ENABLED`
- 主循环只在 `TP_ENABLED` 状态下运行
- 对象未就绪时不进入 TP_ENABLED，不反复查找
- Follow/LookAt 只在指针变化时重新设置
- FreeLook 激活每 500ms 执行一次（10 个循环周期）
- 不在高频循环中输出普通日志

### 修复10: Frida 断线和重连不完整 (第二优先级)

**现象**: 游戏关闭或重启后，UI 无法自动重新连接。

**修复**:
- Python 注册 `session.on('detached', callback)` 回调
- 断开后立即清理：`is_connected=False`、`is_enabled=False`、`script=None`、`session=None`
- 保存 `attached_pid`，防止同一 PID 重复 attach
- PID 改变时先 `_cleanup_session()` 清理旧 session
- JS 加载失败时主动 unload 和 detach
- 程序退出时先 disable() 恢复游戏状态，再清理 Frida

### 修复11: 按钮操作可能并发 (第二优先级)

**现象**: 连续点击开启/关闭可能导致 enable 和 disable 同时执行。

**修复**:
- RPC 调用放到后台线程，不阻塞 Tk 主线程
- 开启或关闭过程中暂时禁用按钮 (`state="disabled"`)
- 增加 `operation_in_progress` 标志
- 操作完成后恢复按钮 (`state="normal"`)
- RPC 异常后重新查询真实状态

### 修复12: 关闭第三人称时恢复不完整 (第三优先级)

**现象**: 关闭后模型 Layer 未恢复，角色可能不可见。

**修复**:
- 启用前保存原始值到 `savedState`
- 关闭时调用 `setModelLayer(character, 1, 8)` 恢复 PlayerView 模式
- 停用 FreeLook (`setFreeLookActive(camMgr, 0)`)
- 重置 `savedState.followSet` 和 `savedState.lookAtSet`
- 房间退出、脚本卸载、连接断开时统一调用 `disableThirdPerson()`

### 修复13: 灵敏度滑块没有实际生效 (第三优先级)

**现象**: `setsensitivity()` 只保存 `cameraSensitivity`，实际相机旋转代码没有使用。

**分析**: CinemachineFreeLook 的 XAxis/YAxis 灵敏度由 `AxisState` 内部的 `m_InputAxisProvider` 控制，当前架构无法直接修改输入轴的缩放系数。需要找到 `IInputAxisProvider` 的实现并 Hook 其 `GetInputAxis()` 方法。

**修复**:
- 保留 `setsensitivity()` RPC 接口，但标注"暂未生效"
- Python UI 灵敏度标签标注"(暂未生效)"
- 返回值包含 `note: '灵敏度暂未生效，需要进一步实现'`
- 不删除滑块，但明确告知用户当前状态

## v8 修复记录 (JS 重写 + Python v5 适配)

### 核心修改：调用游戏原生 PV→CV 切换函数

**问题根因**：v6/v7 仅调用 `SetModelLayer` 修改模型 Layer，未触发游戏原生的 PV/CV 切换逻辑。`objectInPV` 中的第一人称手臂和枪械未被隐藏，`objectInCV` 中的第三人称模型未被显示。

**修复方案**：

1. **调用 `PlayerData.SetObserveMode(0)`** — 将观察模式设为 Character（第三人称），触发 ObserveMode_Listener
2. **调用 `Model.OnOwnerObserveModeChange(0)`** — 直接触发游戏原生的 PV→CV 切换回调，自动隐藏 PV 对象、显示 CV 对象、切换动画器
3. **显式遍历 `objectInPV` 调用 `GameObject.SetActive(false)`** — 双重保险，确保第一人称枪模消失
4. **显式遍历 `objectInCV` 调用 `GameObject.SetActive(true)`** — 确保第三人称全身模型显示
5. **设置 `PlayerCameraManager.modelVisible = false`** — 关闭第一人称手臂相机渲染
6. **设置 `PlayerData.playerViewModelVisible = false`** — 通知武器系统切换到第三人称视图
7. **调用 `Weapon.SynchronizeHand()`** — 同步第三人称武器到角色手部骨骼

### 相机修正：肩后 TPS 视角

**问题根因**：v7 错误修改 `CinemachineTransposer.FollowOffset`，导致相机位置与轨道参数冲突，产生俯视效果。

**修复方案**：

1. **不再修改 `FollowOffset`**，CinemachineFreeLook 的轨道系统已控制相机位置
2. **降低轨道高度**：Top=1.8, Middle=1.4, Bottom=0.6（原 Top=4.5, Mid=2.0, Bot=0.5）
3. **通过 Composer 的 `m_ScreenX=0.4`** 实现角色偏左（右肩视角）
4. **通过 Composer 的 `m_TrackedObjectOffset=(0.5, 0.3, 0)`** 微调注视点偏移
5. **减小死区** `m_DeadZoneWidth=0.03`, `m_DeadZoneHeight=0.03` 让相机更跟手

### 关闭时完整恢复

**修复方案**：

1. **调用 `OnOwnerObserveModeChange(1)`** 恢复 PV 模式
2. **调用 `SetObserveMode(savedObserveMode)`** 恢复原始观察模式
3. **恢复 `playerViewModelVisible`** 到原始值
4. **逐项恢复 PV/CV 对象的 `active` 和 `Layer`**（从保存的数组）
5. **调用 `SetModelLayer(PlayerView, 8)`** 恢复模型 Layer
6. **恢复 `PlayerCameraManager.modelVisible = true`**
7. **调用 `Weapon.PlayerViewSetting()`** 恢复第一人称武器设置
8. **停用 FreeLook**，恢复轨道参数和 Composer 参数

### 新增诊断 RPC：debugmodel()

输出以下信息用于定位模型和相机问题：
