# 定点瞬移-简要说明

feature_id: fixed_point_teleport

## 目标

第一版只做单保存点：玩家点击“保存当前位置”后记录本地玩家当前世界坐标，之后点击“瞬移到保存点”把本地玩家送回该坐标。

## 实现原理

1. Hook `Player.Update` 捕获当前本地 `Player`。
2. 保存时通过 `Component.get_transform` 和 `Transform.get_position_Injected` 读取本地玩家位置。
3. 瞬移时调用原游戏 `Player.SetPos(Vector3)`，不直接写 Transform。
4. 只处理本地玩家，不处理人机、其他玩家和多保存点。

## 关键 RVA 和字段

| 名称 | 地址/偏移 | 来源 |
| --- | --- | --- |
| `Player.Update` | RVA 0xB551D0 | dump.cs + IDA 汇编索引 |
| `Player.get_isMyPlayer` | RVA 0xB55FD0 | dump.cs + 项目常用判断点 |
| `Player.SetPos` | RVA 0xB534C0 | dump.cs + IDA 汇编确认 |
| `Component.get_transform` | RVA 0x32CF40 | 已有自由视角/穿墙功能验证 |
| `Transform.get_position_Injected` | RVA 0x3F4280 | 已有自由视角/穿墙功能验证 |
| `Player.characterController` | 0x2C | dump.cs 字段偏移 |

IDA 汇编里 `Player.SetPos` 会读取 `Player + 0x2C`，先关闭碰撞器，再取 Transform 并设置位置，最后恢复碰撞器。因此第一版优先调用原游戏接口，风险低于直接写 Transform。

## RPC

标准 RPC：

- `enable()`
- `disable()`
- `status()`
- `cleanup()`
- `setconfig(config)`

额外调试/动作 RPC：

- `savepoint()`
- `teleporttopoint()`
- `clearpoint()`

## 当前边界

- 不做快捷键。
- 不做多点列表。
- 不自动寻找地面或修正高度。
- 保存点只在当前脚本生命周期内存在。
- 切房、死亡、重生后需要重新捕获本地玩家；开关状态保留，但运行时指针不长期信任。

## 测试

自动检查：

```powershell
python -m unittest "05-正式功能\31-定点瞬移\test_fixed_point_teleport_static.py" -v
node --check "05-正式功能\31-定点瞬移\AAAAA-fixed_point_teleport_min.js"
python -m py_compile "05-正式功能\31-定点瞬移\AAAAA-fixed_point_teleport_ui.py"
```

游戏内验证：

1. 启动 UI，等待连接 `UnityCrossFire.exe`。
2. 进房后开启功能。
3. 移动一下，确认状态显示“已捕获”。
4. 点击“保存当前位置”。
5. 离开原位置后点击“瞬移到保存点”。
6. 反复开关 5 次，确认不重复 Hook、不崩溃。
7. 切房、死亡/重生后重新移动并再次保存/瞬移。
