# 穿墙-简要说明

## 目标

实现本地玩家横向穿过墙体/障碍物。

第一版只做最小闭环：

```text
只影响本地玩家
只处理水平 x/z 位移
开启功能后仍需按住 Alt 才允许穿墙
保留 y 方向给游戏原始 CharacterController.Move
不提供上升/下降控制
不改 Bot
不改地图
不改 Entity layer
不直接接入正式整合包
```

## feature_id

```text
wall_noclip
```

## 当前实现原理

1. Hook `Player.MoveByLocalDirection` 捕获本地玩家。
2. 通过 `Player + 0x2C` 读取本地玩家的 `CharacterController`。
3. 通过 WinAPI `GetAsyncKeyState(VK_MENU)` 检测 Alt 是否正在按下。
4. Hook `UnityEngine.CharacterController.Move`。
5. 如果 `Move` 的 `this` 是本地玩家 controller：
   - 如果功能未开启，或未按住 Alt，直接返回，保留游戏原始碰撞。
   - `onEnter` 先记录 Move 前的 `Transform.position`。
   - 从栈参数读取原始 `motion.x` 和 `motion.z`。
   - 不修改原始 `Move` 入参，让游戏正常处理重力、落地和垂直方向。
   - `onLeave` 在原始 `Move` 返回后，把 `x/z` 改成“Move 前位置 + 原始水平位移”。
   - `y` 使用原始 `Move` 返回后的结果，避免做成飞天或悬空。

这样第一版只在“功能开启 + Alt 按住”的瞬间绕开墙体对水平移动的阻挡，不把角色做成自由移动模式。

这个顺序也避免了一个实测问题：如果在 `Move` 执行前写坐标，并把 `motion.x/z`
清零，后续原始 `Move` 可能会用零水平位移覆盖结果，表现为开启后 WSAD 被固定在原地。

## 为什么不用 Entity.UpdateColliderLayer

`Entity.UpdateColliderLayer` 会根据实体死亡、幽灵状态等切换 `GameObject.layer`。

它不是单纯的墙体碰撞开关，可能影响：

```text
受击判定
阵营显示
雷达/目标识别
地图触发器
死亡层级
```

所以第一版不改 layer，只在本地玩家移动时处理水平位移。

## 游戏内测试

```text
1. 启动 UnityCrossFire.exe。
2. 启动 AAAAA-wall_noclip_ui.py。
3. 进入房间后开启功能。
4. 不按 Alt，对着墙体横向/正向移动，确认仍会被墙体阻挡。
5. 按住 Alt，对着墙体横向/正向移动，确认可穿过。
6. 松开 Alt，再次移动，确认墙体重新阻挡。
7. 从高处落下，确认仍会下落，不会悬空。
8. 跳跃后确认仍按游戏原逻辑落地。
9. 关闭功能后确认墙体重新阻挡。
10. 反复开关 5 次，确认 Hook 不重复安装。
11. 退出房间再进房，确认重新捕获本地玩家。
12. 退出游戏，确认 UI 不持续刷异常。
```

## 如果失败，下一步查哪里

```text
1. 看 UI 状态是否显示已捕获 controller。
2. 看 controller_move_hits 是否增长。
3. 看 `alt_key_down` 是否在按住 Alt 时变为 true。
4. 看 `alt_gate_skipped` 是否在不按 Alt 移动时增长。
5. 看 noclip_writes 是否只在按住 Alt 移动时增长。
6. 如果 controller 已捕获但写入无效，检查 CharacterController.Move 的栈参数位置是否为 x/y/z。
7. 如果写入后抖动，优先确认 `onLeave` 是否执行，以及 `beforePosition/afterPosition` 是否合理。
8. 如果穿墙后卡住，考虑临时加极小水平偏移阈值或只在 x/z 非零时写入。
```
