# 轻重力/高跳修改器实现经验总结（基于 `AAAAA-gravity_modifier-v8.js`）

## 一、功能目标

在不触发游戏反作弊、保持物理稳定性的前提下，修改游戏内角色的**重力**和**跳跃高度**：
- 降低重力 → 角色下落变慢，实现“轻重力”效果。
- 提高跳跃那一刻的向上初速度 → 跳跃更高，实现“高跳”效果。
- 可选择仅对本地玩家生效，或对所有玩家生效。

## 二、整体架构

```
游戏启动
    ↓
Hook GameManager.AddPlayer (0xAF9A90) → 捕获 GM 指针
    ↓
RPC installhook → 启动定时器 (setInterval 50ms)
    ↓
每 50ms 执行 loop() 函数
    ↓
通过 GM → allPlayers 数组遍历所有玩家
    ↓
根据生效模式过滤玩家（仅自己/全部）
    ↓
读取每个玩家的：接地状态 (0x70)、Velocity 结构体指针 (0x90)
    ↓
根据地面状态变化和当前速度方向，修改 Velocity.y
    ↓
定期输出调试日志 (每 4 秒打印一次本地玩家垂直速度)
```

## 三、核心实现逻辑详解

### 3.1 关键偏移量与函数

| 名称                    | 地址/偏移          | 说明                                                  |
| ----------------------- | ------------------ | ----------------------------------------------------- |
| `isMyPlayer`            | `0xB55FD0`         | 判断 Player* 是否为本地玩家，返回 bool                |
| `GameManager.AddPlayer` | `0xAF9A90`         | Hook 此函数，参数 `[0]` 即为新创建的 GameManager 实例 |
| `GM → allPlayers`       | `gm + 0x1C`        | 指向 `Player[]` 数组的指针                            |
| `allPlayers 长度`       | `[ptr + 0xC]`      | 数组元素个数                                          |
| `allPlayers 元素`       | `ptr + 0x10 + i*8` | 每个元素是一个 `Player*`                              |
| `Player.grounded`       | `pp + 0x70`        | `byte`，是否为接地状态（非0为接地）                   |
| `Player.velocityPtr`    | `pp + 0x90`        | 指向 `Vector3` 结构体的指针                           |
| `velocity.y`            | `[vd + 0x10]`      | `float`，垂直速度分量                                 |

### 3.2 重力修改逻辑（核心算法）

重力通过**改变下落时的垂直速度**来实现，而不是修改全局物理参数。具体做法：

```javascript
// 跳跃瞬间：从 grounded 变为 !grounded 且 向上速度 > 0.1
if (lastGrounded && !isGrounded && curY > 0.1 && state.jumpScale !== 1.0) {
    vd.add(0x10).writeFloat(curY * state.jumpScale);
}

// 下落中：向下的速度 < -0.1 且 重力缩放 < 1.0
if (curY < -0.1 && state.gravityScale < 1.0) {
    vd.add(0x10).writeFloat(curY * state.gravityScale);
}
```

**为什么这样设计？**
- **跳跃修改**：只在起跳瞬间对速度进行倍率放大，不影响空中速度变化，跳跃更自然。
- **下落修改**：每帧持续将下落速度乘以一个小于1的系数（如0.5），使坠地变慢，实现缓降感。
- **不修改水平速度**：只动 Y 轴，避免影响移动手感。

### 3.3 关键状态管理

```javascript
var playerState = {}; // 记录每个玩家的 grounded 状态
playerState[key] = { lastGrounded: isGrounded };
```

- 用于存储**上一帧**的接地状态，以检测“刚刚起跳”的瞬间。
- 房间切换时（GM 指针变化），清空 `playerState`，避免旧玩家数据干扰。

### 3.4 生效模式

| 模式     | 值              | 行为                                      |
| -------- | --------------- | ----------------------------------------- |
| 仅自己   | `'player_only'` | 遍历时只处理 `isMyPlayer(pp)=true` 的玩家 |
| 全部玩家 | `'all'`         | 遍历所有玩家，全部生效                    |

### 3.5 配置与启用时机

通过 RPC `setconfig(gravity, jump, mode)` 配置参数：
- `gravityScale`：重力系数，合法范围 `[0, 1]`（1 为正常）
- `jumpScale`：跳跃系数，合法范围 `[1, 5]`（1 为正常）
- `mode`：`'player_only'` 或 `'all'`

**自动启用逻辑**：
```javascript
state.enabled = (state.gravityScale < 1.0 || state.jumpScale !== 1.0);
```
只要重力或跳跃有一个不是默认值，即启用修改；否则定时器虽然运行但不做任何修改，减少 CPU 开销。

## 四、工程经验总结

### 4.1 稳定性保障措施

1. **使用定时器 + 指针有效性检查**  
   - 每帧（50ms）遍历一次，不依赖 Hook，稳定性高。  
   - 每次访问内存前都进行 `!ptr || ptr.isNull()` 检查，避免崩溃。

2. **GM 指针存活检测**  
   - `hasGm()` 函数每次访问前验证 `gm.add(0x1C).readPointer()` 是否有效。  
   - 若失效（玩家退出房间），立即将 `gm = null` 并清空 `playerState`，下次遍历时重新捕获。

3. **玩家状态重置**  
   - 通过 Hook `AddPlayer` 检测到新 GameManager 实例时，重置 `playerState`。  
   - 防止跨房间错误使用旧玩家的接地历史。

4. **边界值限制**  
   - 重力系数限制 `[0, 1]`，跳跃系数限制 `[1, 5]`，防止数值溢出或不合理效果。

### 4.2 性能与日志

- **定时器间隔 50ms**（20 FPS），足够平滑，且消耗极低。  
- **日志节流**：每 4 秒打印一次本地玩家的速度与接地状态，避免刷屏。  
- **不修改全局物理引擎**：仅修改实时速度值，不触碰物理资源，对其他玩家无副作用（除非模式为 `all`）。

### 4.3 与同类修改器的协同

- 本模块与**无限时间、无后座、聚怪**等其他功能完全独立，通过 `gm` 指针共享机制（Hook `AddPlayer`）可共存。  
- 注意：如果其他模块也 Hook `AddPlayer`，需确保不会相互覆盖；本模块采用 `Interceptor.attach`（非 replace），安全叠加。

### 4.4 常见陷阱及规避方法

| 陷阱                          | 现象                                     | 规避方法                                                     |
| ----------------------------- | ---------------------------------------- | ------------------------------------------------------------ |
| 直接修改 `Transform.position` | 角色瞬移但物理引擎不同步，导致卡地或穿墙 | 本模块不修改位置，只改速度                                   |
| 不记录接地状态直接改跳跃      | 每帧都乘跳跃系数，导致跳跃高度无限增加   | 只在 `lastGrounded && !isGrounded` 瞬间修改一次              |
| 重力系数为 0                  | 角色永远不落地，浮空失控                 | 限制最小值 0（实际效果：静止漂浮）                           |
| 玩家离开后指针残留            | 访问已销毁的对象，进程崩溃               | 每次访问前用 `try-catch` + 有效性检查，并定期清空 `playerState` |

## 五、可移植性建议

若要将此逻辑应用到其他 Unity 游戏：
1. 使用 **IDA Pro** 或 **Il2CppDumper** 找到类似字段：
   - 玩家接地标志（通常在 `Player` 类中）
   - 速度向量指针（可能为 `CharacterController.velocity` 或 `Rigidbody.velocity`）
2. 确认游戏是否使用 **Il2Cpp**，如果是，则需要调用 `get_velocity` 等 API 而非直接读偏移。
3. 遍历玩家通常可通过 `GameManager` 中的 `allPlayers` 或类似 `playerList` 字段实现。
4. 定时器频率建议为 30~60 FPS（33ms~16ms），过慢会感觉不跟手，过快增加 CPU 负担。

## 六、总结

`AAAAA-gravity_modifier-v8.js` 实现了一个**轻量、安全、可配置**的轻重力/高跳修改器，其核心经验可以概括为：

> **通过定时器持续监控玩家的垂直速度，在起跳瞬间倍增速度实现高跳，在下落过程中持续减速实现轻重力；严格过滤玩家身份、校验指针有效性、及时重置状态，确保长期稳定运行。**

这种设计模式非常适合需要实时修改玩家运动属性的脚本，且对其他功能模块侵入性低，是 Unity-il2cpp 游戏修改的优秀范例。
