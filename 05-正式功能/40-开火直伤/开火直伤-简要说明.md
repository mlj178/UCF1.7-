# 开火直伤（direct_damage）— 简要说明

> 位置：`05-正式功能/40-开火直伤/`（05 单功能阶段）
> 定位：第一版最小可用实现，跑通后再整目录迁移到 `04-正式发行版/全功能整合包x.x/game_modifier/features/40_direct_damage/`

## 1. 功能是什么

开火时**不再走子弹射线**，直接把伤害结算到「选中的敌人」身上。
全程**不修改镜头、不修改准星、不控制射线方向**。

原版链路：

```
开火 -> Recoil.GetShootRay 生成射线 -> WPN_Gun.Damage(Ray)
     -> RaycastAll 找命中体 -> 构造 DamageEventData -> 结算伤害
```

本功能链路：

```
开火 -> WPN_Gun.Damage 被替换 -> 选目标 -> 构造 DamageEventData -> 结算伤害
```

## 2. 打谁 —— 目标选择设计（重点）

### 2.1 候选集

来源：`GameManager.allPlayers`（Il2Cpp 数组）+ `playersBL` / `playersGR`（两个 List）
合并去重（`allPlayers` 实测不全，必须三处合并，与自瞄同口径）。

逐个过滤：

| 过滤 | 条件 |
|---|---|
| 不是自己 | 指针 != 本地玩家 |
| 敌对 | `isEnemyTeam(myTeam, team)`，team==2 视为自由混战，所有人都算敌人 |
| 存活 | `Entity.get_isDead` 为 false |
| 位置有效 | transform 位置可读，且坐标绝对值 < 5000 |
| 距离 | `max_distance`（默认 80 米，0 = 不限） |
| 准星锥 | 夹角 <= `max_angle_deg`（默认 30°，仅 `nearest` 模式跳过） |

### 2.2 方向基准（准星方向）

读取本地玩家 `Player.cameraRotation`（+0x4C 的 yaw、+0x50 的 pitch），**只读**。
角度约定与游戏/自瞄一致：

```
yaw   = atan2(dx, dz)
pitch = atan2(dy, sqrt(dx^2 + dz^2))
夹角  = sqrt(yawDiff^2 + pitchDiff^2)
```

### 2.3 目标命中点

优先胸部骨骼 `currentCharacter.spine1`（+0x60），退化到 `spine`（+0x5C），
最后退化到「玩家坐标 + 身高偏移(`chest_fallback_height`=1.1)」。
命中点同时写入 `DamageEventData.hitPos`，用于命中反馈/飘字定位。

### 2.4 排序策略 `target_mode`

| 值 | 含义 | 说明 |
|---|---|---|
| `angle_then_distance`（默认） | 先卡准星锥，再在锥内取**距离最近** | 完全对应"准星方向里的敌人 + 距离最近的人" |
| `weighted` | `score = 夹角(度) x angle_weight + 距离(米) x distance_weight`，取最小 | 兼顾"更正对"与"更近"，权重可调 |
| `nearest` | 忽略角度，取全场最近 | 仅调试/对照 |

> 目标结果带 `target_cache_ms`（默认 25ms）短缓存，
> 避免霰弹/多段命中在同一帧里反复重扫全场。

## 3. 伤害怎么打进去 `damage_entry`

`DamageEventData` 是 **0x48 字节、按值压栈** 的 struct（x86 cdecl）。
Frida 的 `NativeFunction` 不支持"按值结构体"参数，因此本实现把 72 字节拆成
**18 个 4 字节标量参数**依次压栈（cdecl 下栈连续，逐 4 字节完全相同），
`MethodInfo*` 统一传 `ptr(0)`（与项目其它 NativeFunction 一致）。

| 值 | 调用 | 说明 |
|---|---|---|
| `hurt`（**默认**） | `Player.OnEntityHurt(DamageEventData)` 0xB516B0 | 已被验证的入口，见下方证据链 |
| `gamemanager` | `GameManager.TakeDamage(DamageEventData)` 0xAFC1C0 | 静态统一伤害入口，先过观察者管线（可能被 InvalidCheck 否决） |
| `health` | `HealthData.Hurt(int)` 0xAE45B0 | 纯标量参数、最不容易失败，但只扣血不走死亡/击杀流程 |
| `dry_run` | 不调用 | 只选目标 + 打日志，安全验证用（配合 `fallback_to_original` 即"探针模式"） |

**为什么默认是 `hurt`（两条独立证据）**：

1. IDA 反汇编 `Entity.OnEntityHurt`（0x10B3F470，仅 0x40 字节）的真实指令序列是：

   ```
   cmp  [ebp+40h], 4          ; DamageEventData.type == 4(Infect) ?
   jz   <epilogue>
   mov  eax, [ebp+8]          ; this
   mov  ecx, [eax+1Ch]        ; this.healthData   (Entity.healthData = +0x1C)
   test ecx, ecx / jz
   movss xmm0, [ebp+14h]      ; DamageEventData.damage (struct+0x08, float)
   cvttsd2si eax, xmm0        ; (int)damage
   push 0 / push eax / push ecx
   call 0x10AE45B0            ; HealthData.Hurt(healthData, (int)damage)
   ```

   也就是说：**`OnEntityHurt` 内部真的扣血**，而且 `damage` 就是 struct +0x08 的 float，
   本文件的结构体偏移完全对得上。

2. 整合包 2.7 的「增加伤害倍率」功能（`30_damage_multiplier`）就是 attach 在
   `Player.OnEntityHurt` / `Entity.OnEntityHurt` 上、直接改写 `+0x08` 的 float 生效的，
   属于**生产环境已验证**的入口。

同时 `Player.OnEntityHurt`（0x80 字节）反汇编显示它先把自己的 eventData 拷贝一份，
**直接 call `Entity.OnEntityHurt`（→ 扣血）**，之后才做 `currentCharacter` 相关的受击表现。
所以调 `Player.OnEntityHurt` 不会漏掉扣血，也不会重复扣血。

结构体字段（`DamageEventData`）：

```
+0x00 attacker      +0x04 victim        +0x08 damage(float)
+0x0C origin(Vec3)  +0x18 hitPos(Vec3)  +0x24 hitTag
+0x28 hitSndName    +0x2C hitEffect     +0x30 wallThrough
+0x34 type          +0x38 damageTag     +0x3C wpnIndex
+0x40 wpnSprIndex   +0x44 ignoreDmgRate          (size 0x48)
```

`type`：`Gun=1 / Knife=2 / Grenade=3 / Infect=4 / Other=5`。

字符串字段（hitTag / hitSndName / hitEffect）：

1. 优先使用**只读观察钩子**从真实伤害事件（`Entity/Player.OnEntityHurt`）里抓到的原版字符串指针；
2. 没抓到就现场用本地玩家 `ClientData.nickname` 的 klass 构造一个**空 IL2CPP String**；
3. 再不行才传 null。

## 4. 三个独立开关

| 开关 | config key | 默认 | 作用 |
|---|---|---|---|
| 常规枪械直伤 | `enable_guns` | 开 | 替换 `WPN_Gun.Damage`，跳过射线直伤 |
| 榴弹/手雷/RPG 直伤 | `enable_explosives` | 开 | 触发时追加直伤 |
| 特殊技能弹直伤 | `enable_skill_projectiles` | 开 | 触发时追加直伤 |

**枪械**：`Interceptor.replace(WPN_Gun.Damage)`；非本地武器、或开关关闭时，
原样调用原函数，保证人机/关闭状态完全透明。找不到目标时默认**不造成任何伤害**
（可通过 `fallback_to_original` 改成回退原版射线）。

**爆炸物 / 技能弹**：第一版是**追加直伤** —— 原版投射物仍会正常发射并爆炸。
需要"完全不打投射物"的版本放到 v1.1（要处理武器状态机，风险更高）。

## 6. 生命周期

- 只安装固定 RVA Hook，命中时按 `enabled/config` 实时判断，
  因此 `requires_room_ready_reapply = false`（无需进房后二次应用）。
- `cleanup` 可重复调用：`Interceptor.revert` 还原替换、detach 全部 attach 钩子、
  清空缓存与指针。
- 切换房间不缓存跨房间的游戏对象（每次开火重新读 GameManager）。

### 7.2 关键探针（日志里按前缀搜）

| 前缀 | 回答什么问题 |
|---|---|
| `[probe:load]` | 脚本到底有没有被注入；模块基址；期望的 GameAssembly.dll md5 |
| `[probe:rva]` | 每个待 hook 地址是否可执行（出现 `NOT EXECUTABLE` = 版本/RVA 不匹配） |
| `[probe:enable]` | `enable()` 入参、钩子安装成功还是失败 |
| `[probe:snap:*]` | 世界快照：gm / staticFields / myPlayer（含来源路径）/ players / enemies |
| `[probe:beat]` | 每 5 秒一次计数器快照（UI 不刷新也能看到卡在哪一步） |
| `[probe:gunDamage#N]` | 第 N 次开火进了 `WPN_Gun.Damage` 替换，附带射线原点/方向 |
| `[probe:sel]` / `[probe:candN]` | 目标选择的候选集、准星参数、**每个候选为什么被接受/拒绝** |
| `[probe:apply]` | 实际调用了哪个伤害入口、参数是什么 |
| `[probe:hp]` | **最终判据**：伤害前后 HP 对照，一行给出 `HP DROPPED **WORKS**` 或 `HP UNCHANGED **NO EFFECT**` |
| `[probe:gunShoot]` / `[probe:gmTakeDamage]` / `[probe:entityHurt]` / `[probe:playerHurt]` / `[probe:healthHurt]` | 游戏自身伤害管线的观察点；`[ours]` = 我们调的，`[game]` = 游戏自己调的 |

HP 对照怎么做的：`HealthData.get_rate()`（HP 百分比）前后对比，
同时把 `currentHealth`（`ObscuredInt`）的原始字段 `key/hidden/fake/inited` 也前后对比，
即使 `get_rate` 取不到也能证明血量有没有被改写。

### 7.4 已踩过的坑（务必保留这段，别再犯）

**Frida 的 `NativeFunction` 对 `'bool'` 返回值给的是 JS `number(0/1)`，不是 JS `boolean`。**

实测（frida **17.9.1**，ia32 与 x64 结果一致）：

```js
new NativeFunction(IsProcessorFeaturePresent, 'bool', ['int'])(10)
// -> 1            typeof === "number"
// -> (1 === true) === false     <-- 恒为 false！
```

早期版本本功能写的是 `native.isMyWeapon(weapon, ptr(0)) === true`，
于是 `isLocalWeapon()` **恒返回 false**：替换后的 `WPN_Gun.Damage`
每一次都把调用原样转给原函数，**任何武器、任何入口都不会有任何效果**，
而且不报错、日志上也看不出异常（唯一线索是 `[probe:gunDamage#N] isMyWeapon=false`）。

正确写法（与整合包 2.7 的 `26_grenade_mode` 一致）是真值判定：

```js
native.isMyWeapon(weapon, ptr(0)) ? true : false      // 或 Boolean(...)
```

本文件已统一收敛到 `toFlag()` 辅助函数，凡是 `bool` 返回值一律走它，
并且探针会把**原始返回值**一起打出来（`true(raw=1)`），以后再遇到类型问题一眼可见。

> 顺带一提：`29_bullet_wall_penetration/script.js:370` 里也有一处
> `native.isMyWeapon(...) === true`，但那个辅助函数没被任何地方调用（死代码），
> 它钩子内部用的是 `if (!native.isMyWeapon(...))`，所以那个功能不受影响。

### 7.3 按日志定位问题

| 现象 | 结论 |
|---|---|
| 没有 `[probe:load]` | 脚本没被注入 |
| `[probe:rva]` 有 `NOT EXECUTABLE` | RVA 与当前游戏版本不匹配 |
| `[probe:enable] installHooks FAILED` | 功能根本没开启，看紧随其后的 `lastError` |
| `[probe:beat] gunCalls=0` | `WPN_Gun.Damage` 不是这条版本的开火路径（先看 `pipeShoot`） |
| `gunCalls>0` 但 `selected=0` | 目标选择问题，看 `[probe:cand*]` 的拒绝原因 |
| `selected>0` 但 `hpDrop=0` | 伤害入口没被接受，看 `[probe:apply]` / `[probe:hp]` 换入口 |
| `hpDrop>0` | 功能是通的，剩下的只是手感/参数问题 |
| `[probe:snap] via=list-miss(N)` 且 `myPlayer=0x0` | `isMyPlayer` 判定失效（见 7.4） |
| `[probe:gunDamage#N] isMyWeapon=false(raw=1)` | 同上：`bool` 返回值被 `=== true` 判成 false |
| `localFires=0` 而 `gunCalls` 一直在涨 | 枪械钩子每次都原样放行原函数 —— 这个功能的头号故障 |

## 8. 测试步骤

1. 启动 `UnityCrossFire.exe`，运行 `AAAAA-direct_damage_ui.py`（自动连接、自动载入 script.js）。
   连接成功后日志里会有一条 **游戏模块 md5 校验**：与逆向分析版本不一致的话，
   script.js 里所有 RVA 都可能失效，这种情况不用再折腾逻辑。
2. **第一步：开「探针模式（不改玩法，只记录）」+ 总开关**，进房间对着敌人开枪。
   - 看「钩子命中」是否 > 0 —— 这一列是 `WPN_Gun.Damage` 替换被调用的次数；
   - 再看「选中目标 / 无目标 / 最近夹角」，确认"打谁"选对了；
   - 这个模式**不会改玩法**，原版弹道照常生效，可以放心测。
3. 关掉探针模式，入口选 `实体受伤入口(推荐)`，开枪看敌人是否掉血，
   看「HP对照(降)」是否 > 0（格式 `下降次数/对照次数`）。
4. 不透血：依次试 `统一伤害入口` -> `仅扣血(兜底)`，并看 `[probe:hp]` 那几行。
5. 单独验证两个副开关：只开「榴弹/手雷/RPG 直伤」扔雷 / 打 RPG；
   只开「特殊技能弹直伤」用奥术手雷 / 地狱终结者火球。
6. 如果还是不行：点 **拉取脚本日志**，把 `logs/` 目录下的
   `direct_damage_ui_*.log` / `direct_damage_script_*.log` 给我。

## 9. 已知限制（第一版）

- 爆炸物 / 技能弹是**追加直伤**，原版投射物仍会飞出去并爆炸（可能多打一次）。
- 跳过射线后，原版「墙上弹孔 / 着弹特效」由 `WPN_Gun.Damage` 内的
  `EffectManager.CreateBulletHole` 生成，本功能不再产生。
- 找不到目标时默认什么都不做（子弹"消失"）；这是设计选择，可用
  `fallback_to_original` 改回原版行为。
- 伤害部位倍率 / 距离衰减不会复刻，固定使用武器基础伤害 x 倍率。
