# DLL 注入失败复盘

## 问题现象
在 1.7 修复版中重新编译并注入 DLL，注入失败。

## 根本原因
**编译出的 DLL 架构与目标进程不一致。**

| 项目 | 架构 |
|------|------|
| 游戏进程 | 32 位 (x86) |
| 注入器 | 32 位 (x86) |
| 旧 DLL（可正常注入） | 14C machine (x86) |
| 新 DLL（注入失败） | 8664 machine (x64) |

## 失败机理
远程线程成功创建，但 `LoadLibraryW` 无法将 64 位 DLL 加载到 32 位游戏进程中，返回 `NULL`。

## 判断依据
- `dumpbin /headers` 显示新 DLL 为 `8664 machine (x64)`
- 调试路径中包含 `x64\Release\Universal-ImGui-Hook.pdb`

## 解决方法
1. 在 Visual Studio 中将解决方案平台切换为 **Release + Win32**（或 x86）。
2. 重新编译项目。
3. 复制新生成的 DLL 前，使用以下命令验证：
   ```bash
   dumpbin /headers Universal-ImGui-Hook.dll
   ```
   确认输出为 `14C machine (x86)`。

## 结论
此次注入失败并非代码修改或注入器故障导致，纯粹是编译目标平台选择错误。
