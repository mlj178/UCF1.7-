# 方框透视 DLL 闪退修复 —— 双引擎重复挂钩

- **日期**：2026-10-15
- **对象**：Universal-ImGui-Hook.dll（x86 / Release / Visual Studio 2022 v143）
- **源码**：05-正式功能/18-Universal-ESP盒子/Universal-Dear-ImGui-Hook/
- **关联取证**：
  - 06-测试/_crash20_37/崩溃分析-2026-10-11-2037.md（0xC0000005 执行违规，双引擎重复挂钩 + 内存损坏）
  - 06-测试/_crash18_26/崩溃分析-2026-10-14-1826.md（把方框透视 DLL 列为次要嫌疑）

## 一、问题

2026-10-11 多人生化（终结者）模式在补给箱拾取流程闪退，异常 0xC0000005 / ExceptionInformation[0]=8
（执行违规）：Mode_Nano4_Terminator 类的方法指针被写成了游戏 GC 运行时的代码地址。

取证结论：调用链上唯一能往游戏内存写「代码地址」的，只有 Frida Hook（修改器）与 MinHook（方框透视 DLL），
而两者当时**同时给同一批函数打了内联钩子**。

## 二、根因（双引擎重复挂钩）

旧版 esp/game_manager.cpp 用 MinHook 内联挂钩 GameAssembly.dll 的函数：

| 目标函数 | RVA | MinHook（DLL） | Frida（修改器） |
|---|---|---|---|
| ModeBase.OnStartNewGameRound | 0xAF5B30 | 有 | 11_aim（自瞄，开） |
| ModeBase_Nano.OnStartNewGameRound | 0xAF15D0 | 有 | 19_battle_round（脚本加载即挂钩） |
| Bot.Update | 0xB33370 | 有 | 无 |
| GameManager.OnDestroy | 0xAFB6F0 | 有 | 无（03 用的是 0xAEBD40） |

前两行是**同一段 5 字节函数头被两个引擎先后改写/搬运**（Frida 内联 trampoline + MinHook trampoline），
属未定义行为；时间线也与闪退吻合（20:37:13 Nano 新回合钩子触发、12 秒卡顿，37 秒后在同一模式补给箱虚调用崩溃）。

## 三、修复（新版做法）

**DLL 不再改写 GameAssembly.dll 的任何代码字节。**

1. **删除全部游戏函数 MinHook**：InitializeBotHook() / InitializeRoomHooks() 及其回调
   （HookedBotUpdate / HookedRoundStart / HookedNanoRoundStart / HookedGameDestroy）整体移除。
2. **会话改为渲染帧轮询**：GameManager::RefreshSession() 每帧经 IL2CPPBridge::GetGameManagerInstance()
   取单例（内部缓存 + 逐次结构校验），实例出现/更换/消失即换 s_SessionEpoch 并清理缓存；
   不再需要 OnDestroy/回合开始回调，也不再需要 s_BlockSessionRefresh 封锁位。
3. **Bot 不再单独挂钩采集**：玩家统一来自 GameManager 的玩家容器
   （allPlayers / playersBL / playersGR / *_Alive），删除了带时间戳的 Bot 缓存。
4. **DLL 里剩下的 Hook 只有**：D3D11 Present/ResizeBuffers、kernel32 LoadLibraryA/W —— 都在系统 DLL 上，
   Frida 侧不碰，**不存在重复挂钩**。

因此 DLL 与 Frida 修改器之间不再共享任何被改写的函数头。

## 四、顺带新增：血量显示选项 + 方框轮廓开关

通过命名管道新增三个字段（血量两项协议 2 → 3，方框轮廓 4 → 5）：

| 字段 | 取值 | 含义 |
|---|---|---|
| esp_health_mode | 0 / 1 | 0 = 百分比（85%），1 = 剩余数值（85，只显示当前血量） |
| esp_health_display | 0 / 1 / 2 | 0 = 仅血条，1 = 仅数值，2 = 血条 + 数值 |
| esp_box_outline | true / false | true = 画方框（默认），false = 不画方框，只保留血条/数值 |

- 剩余数值来自 HealthData.currentHealth / maxHealth / tempHealth，三者都是 CodeStage AntiCheat 的
  ObscuredInt；DLL 只做**只读解密**（明文 = hiddenValue ^ currentCryptoKey，
  currentCryptoKey == 0 时用静态密钥 0x6C81C），**不写回任何字段**。
- 修改器界面「方框透视」卡片新增两个下拉框：**血量显示**（百分比 / 剩余数值）与
  **显示内容**（仅血条 / 仅数值 / 血条和数值），另加一个 **方框轮廓** 开关（关掉后只画血条/数值，
  方框不画；血量覆盖层与方框共用同一份投影几何，位置不变）。改动经
  panel.py → feature_command_service → game_session_manager → universal_hook_manager 实时下发到 DLL。
- 管道字段缺省时 DLL 沿用当前值；Python 侧要求 DLL 显式回读 esp_box_outline，字段缺失即判失败，
  防止方框开关静默失效。
- **所选即所得（2026-10-15 补）**：修掉了「界面下拉框选 A、游戏里生效 B」。根因是会话层
  用 `UniversalHookManager` 的内部缓存下发（`set_esp_box()`），而"游戏没开时改的选项"
  只落盘没下发，下次连接就推了旧缓存。现在所有下发路径先按持久化配置校准、再带完整选项
  下发；下发失败则把配置回退成 DLL 生效值，面板回读控件。

## 七、遗留与边界

- **协议版本 2 → 3 → 4 → 5**（4 = 数值模式只显示剩余血量，5 = 新增方框轮廓开关）：如果游戏里已经注入了旧版 DLL，新修改器会因协议不匹配拒绝复用，
  ESP 需要**重启游戏**后重新注入新 DLL。这是刻意的，避免继续使用带闪退风险的旧镜像。
- **Bot 覆盖略有收敛**：不再有 Bot.Update 单点补充，Bot 依赖 GameManager 的玩家容器；
  这是为了彻底移除游戏函数改写所付的代价，必要时后续可用只读方式（如 Bot.hangoutList）单独补，
  但不得再对 GameAssembly 打内联钩子。
- ReadObscuredInt 只读；如果游戏改密钥/结构，剩余数值会退回百分比显示（仍然只显示血条/百分比，不会崩）。
- 数值模式只显示剩余血量（current），不显示 `当前/上限`；maxHealth 仅参与百分比反推。
- 只想要血条/数字的用户：把「方框轮廓」关掉即可；此时不调用 `DrawBox()`，但仍会读取血量并画覆盖层。
