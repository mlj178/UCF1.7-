- 独立脚本：同目录 AAAAA-fast_reload.js

## 一、总览：三种形态、两条路径

| 形态 | 换弹入口 | 时长由谁决定 | 本功能做法 |
|---|---|---|---|
| 普通枪械（WPN_Gun 系） | WPN_Gun.Reload(0xB62CB0) | 每次换弹算 GetAnimSpeed(reloadAnimRatio) × PlayerWeapons.ReloadSpeed，写进 Animator 的 "ReloadSpeed" | 在 CFAnimator.SetFloat 里把该参数乘倍率 |
| **步枪的榴弹模式**（WPN_GrenadeGun 的 changeMode） | 同样走 WPN_Gun.Reload | 动画名被改写成 "reload_A"（另一条 clip），**不吃 "ReloadSpeed" 参数** | 换弹前把武器/手部 Animator.speed 设为倍率，动画结束复位 |
| WPN_RPG（火箭筒 / AT4） | WPN_RPG.OnReloadBtnDown(0xB67AF0) | 只播放动画，从不写 "ReloadSpeed" | 同上，改 Animator.speed |

三类换弹结束都是「reload 动画播完」事件（WPN_Gun.OnAnimationEnd → ReloadOver()、
WPN_RPG.OnAnimationEnd → AmmoData.Reload()），所以缩短动画就能缩短换弹与补弹时间。

## 二、榴弹模式（步枪切榴弹）为什么没效果（2026-11-08 追加定位）

WPN_GrenadeGun.OnSpecialBtnDown(0xB5FCF0) 切模式时只做三件事：
changeMode(!) → ammoData = gunAmmo/grenadeAmmo → 播一个切换动画。**动画器没有换**。

但它注册了 CFAnimator.AnimName_Modifier(WPN_GrenadeGun 版 0xB602D0)：

    if (this.changeMode &&
        (*value == "fire" || *value == "reload"))
        *value = *value + "_A";      // 后缀 StringLiteral @0x10E28EB8

于是榴弹模式的换弹播放的是 "reload_A"，是另一条动画状态。实测这条状态不吃
"ReloadSpeed" 参数（普通模式 "reload" 吃），所以乘参数只对步枪模式有效、榴弹模式无效。
→ 解决办法：榴弹模式下改用 Animator.speed（对任何 clip 都成立），并在换弹结束/切模式时复位。

判定是否榴弹模式：CFAnimator.changeMode(+0x54) != 0。

## 三、RPG / AT4 为什么没效果（上一轮定位）

1. 入口找错：WPN_RPG.Reload(0xB67C40) 是死代码（全 DLL 无 call 指向），真实入口是
   WPN_RPG.OnReloadBtnDown(0xB67AF0)。早期把钩子挂在 0xB67C40 上等于没挂。
   （2.8 的 01_ammo 也把 RPG 弹匣维护挂在同一个死函数上。）
2. 参数无效：RPG 换弹过程不写 "ReloadSpeed"，该参数只在 Deploy 的 AnimSpeedSetting 写一次。
3. 日志被吞：日志辅助函数每模块只放行 10 条，实测被前面的消息用完，AT4 阶段一条日志都没有。
   现在诊断日志统一走 send({type:'log_file'}) 通道，不受上限影响。

## 四、当前实现细节

### 参数路径（普通枪械）
- Interceptor.replace(CFAnimator.SetFloat @0xB34E40)。
- 命中条件：参数名 == "ReloadSpeed" && Weapon.get_isMyWeapon(self) && 非榴弹模式 && 非 RPG。
- 动作：value ×= 倍率。只对本地玩家，bot / 其他玩家不受影响。

### 动画器速度路径（榴弹模式 + RPG）
- 入口：WPN_Gun.Reload(0xB62CB0) 且 changeMode != 0；WPN_RPG.OnReloadBtnDown(0xB67AF0)。
- 动作：weapon.animator(CFAnimator+0x40) 与 owner.characterModel.handAnimator(+0x5C→+0x4C)
  的 Animator.speed = 倍率。
- 复位时机（缺一不可）：
  WPN_Gun.OnAnimationEnd(0xB627A0) / WPN_RPG.OnAnimationEnd(0xB67640) 且 tag=="reload"；
  WPN_GrenadeGun.OnSpecialBtnDown(0xB5FCF0)（切模式）；WPN_RPG.Deploy(0xB67030)；
  关闭功能；5 秒看门狗（换弹被切枪/死亡打断时）。
  另外游戏 CFAnimator.AnimatorInit 每次部署都会把这两个 Animator.speed 置 1.0，是第二道保险。
- 参数路径与动画器速度路径互斥，避免倍率平方。

### RPG 判定
Weapon.data(+0x68) 与 WPN_RPG.realData(+0xF0) 指向同一个 WD_RPG 实例；
WPN_Gun 的 +0xF0 是 bool（isSemiGun），不会是有效指针，因此不会误判。

## 五、游戏原生「快速换弹」BUFF 的底层逻辑（多人生化 · 人类）

    Mode_Nano4_Terminator.AddPropertyModifier(Player)  @0xB42930
      wpns.Modifier_ReloadSpeed.modifier =
          Delegate.Combine(existing, new CustomEvent_PlayerRefFloat(this, RapidReload))

    Mode_Nano4_Terminator.RapidReload(Player, ref float speed)  @0xB45270
      if (player.playerData.nanoRole.value != 0) return;   // 只有人类(0)
      if (this.attribute_Human.id != 15) return;           // 人类特性 id 15 = 快速换弹
      speed *= 2.5f;                                       // 常量 @0x10B99D74

- 它乘的是 PlayerWeapons.ReloadSpeed，只影响普通枪械那条链；榴弹模式与 RPG 都不受影响。
- 特性 ID 读取方式与 2.8 的 15_nano4t 一致：mode+0xE4(attribute_Human) → +0x0C(id)。
- 不直接搬它的原因：要伪造 Il2CppDelegate 才能进委托链，版本敏感，且覆盖不了上面两条路径。

| RVA | 符号 | 用途 |

## 七、覆盖范围与限制

- 模式：无限制（函数级 Hook，与模式无关）。
- 武器：WPN_Gun 系（步枪/冲锋枪/狙击/手枪/霰弹/榴弹枪）+ 步枪的榴弹模式 + WPN_RPG（火箭筒/AT4/Nano AT4）。
  投掷 / 一次性 / 哨戒炮 / 近战没有换弹动画，天然不涉及。
- 仅本地玩家：bot / 其他玩家不变速。
- 叠加：多人生化人类 BUFF「快速换弹」(id 15) 的 ×2.5 只作用于普通枪械；榴弹模式与 RPG 的最终倍率就是滑块值。

## 八、验证步骤

1. 连接游戏 → 开关打开 → 日志出现「已启用 — 4.0x（枪械=动画参数 / 榴弹模式+RPG=动画器速度）」。
2. 普通步枪换弹 → 「GUN 换弹动画速度 1.00 → 4.00（4.0x）」。
3. **切到榴弹模式再换弹 → 「榴弹模式换弹加速 ×4.0（动画器速度）」，动作与补弹都应明显变快**，
   换弹结束后切回步枪模式，动作恢复正常。
4. 拿 AT4/RPG 换弹 → 「RPG 换弹加速 ×4.0（动画器速度，共 2 个 animator）」。
5. 拖滑块 → 下一次换弹立即按新倍率；1.0 = 原速。
6. 换弹中途切枪/切模式/死亡 → 速度复位（切模式与重新部署即时复位，最迟 5 秒）。
7. 关闭功能 → 全部恢复原速。
