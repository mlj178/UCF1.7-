# 23-无限背包：最小实现步骤

## 目标

实现“任何时候、任何位置都能打开背包并更换武器”。

重点场景：

- 超出出生点背包范围，也能打开和切换。
- 正在开枪、移动、跳跃时，也尽量不影响背包切换。
- 只先做玩家自己，不考虑人机。
- 先做最小可用，不急着整合进正式发行版。

## 已定位到的关键代码

先围绕这条链路做：

```text
HUD_BagButton.OnPointerDown
  -> HUD_Bag.SelectBag
  -> Player.SelectWeaponBag
  -> GameManager.GiveWeaponByBag
```

关键类和地址：

| 类/方法 | RVA | 作用 |
| --- | --- | --- |
| `Player.SelectWeaponBag(int index)` | `0xB52830` | 真正执行背包换武器 |
| `HUD_Bag.Update()` | `0xB00360` | 控制背包 HUD 状态，里面会读背包限制 |
| `HUD_Bag.SelectBag(int bagID)` | `0xB000E0` | 点击背包按钮后调用 |
| `HUD_Bag.SetVisible(bool visible)` | `0xB00290` | 控制背包界面显示 |
| `HUD_BagButton.OnPointerDown(...)` | `0xAFF650` | 背包按钮点击 |
| `GameManager.GiveWeaponByBag(Player, int)` | `0xAFB2A0` | 根据背包武器 ID 赋予武器 |

关键字段：

| 类 | 字段 | 偏移 | 说明 |
| --- | --- | --- | --- |
| `Player` | `weaponBag` | `0xA4` | 玩家背包对象 |
| `WeaponBag` | `disabled` | `0x8` | 背包禁用状态 |
| `WeaponBag` | `tooFarFromSpawnPos` | `0x14` | 是否离出生点太远 |
| `WeaponBag` | `available` | `0x20` | 背包可用列表 |
| `WeaponBag` | `weaponID` | `0x24` | 背包里的武器 ID |
| `WeaponBag` | `currentBagID` | `0x28` | 当前背包编号 |
| `HUD_Bag` | `bag` | `0x2C` | HUD 当前绑定的 WeaponBag |

`WeaponBag.disabled` 和 `WeaponBag.tooFarFromSpawnPos` 是第一优先级限制点。

## 推荐方案

### 方案 A：清掉背包限制字段，再走原函数

这是第一版推荐方案。

思路：

1. Hook `Player.SelectWeaponBag`。
2. 在 `onEnter` 里拿到 `this + 0xA4` 的 `WeaponBag`。
3. 把 `disabled` 和 `tooFarFromSpawnPos` 改成 false。
4. 让游戏继续执行原本的 `SelectWeaponBag`。
5. 在 `onLeave` 看返回值，确认是否从失败变成成功。

优点：

- 不改背包赋予逻辑。
- 不自己调用 `GiveWeaponByBag`。
- 不复制游戏逻辑，风险最低。

缺点：

- 需要正确写入 `ObscuredBool`。
- 如果还有别的限制，比如 UI 焦点或射击状态，需要继续补 Hook 点。

### 方案 B：Hook `HUD_Bag.Update`，持续清限制

如果方案 A 只在点击时清一次不够，就加这个。

思路：

1. Hook `HUD_Bag.Update`。
2. 读取 `HUD_Bag.bag`。
3. 如果功能开启，每帧把 `bag.disabled` 和 `bag.tooFarFromSpawnPos` 改成 false。

优点：

- 能持续压住“离出生点太远”这类实时更新限制。

缺点：

- 每帧执行，要控制日志，不能刷屏。

### 方案 C：直接替换 `Player.SelectWeaponBag`

这是备选，不作为第一版。

思路：

1. 用 `Interceptor.replace` 重写 `SelectWeaponBag`。
2. 自己遍历 `WeaponBag.weaponID`。
3. 调用 `GameManager.GiveWeaponByBag`。
4. 返回 true。

缺点：

- 要重写游戏自己的背包逻辑。
- 容易漏掉 UI、音效、当前背包状态、特殊武器处理。
- 风险比方案 A/B 高。

只有 A/B 都失败时再考虑。

## 第 1 步：写探测脚本

文件：

```text
05-正式功能/23-无限背包/AAAAA-unlimited_bag_probe.js
```

只做日志，不改行为。

Hook 点：

- `Player.SelectWeaponBag`：记录 index、player、weaponBag、返回值。
- `HUD_Bag.SelectBag`：记录 UI 选择的 bagID。
- `HUD_Bag.Update`：低频记录 `HUD_Bag.bag` 是否存在。

预期日志：

```text
[无限背包][SelectBag] bagID=2
[无限背包][SelectWeaponBag] player=0x..., index=2, bag=0x...
[无限背包][SelectWeaponBag] return=false
```

测试方式：

1. 在出生点附近打开背包，点不同背包。
2. 走远后再打开背包或切换背包。
3. 一边开枪一边切背包。
4. 对比返回值什么时候是 true，什么时候是 false。

判断：

- 如果远离出生点时 `SelectWeaponBag` 没被调用，说明限制在 UI/HUD 层。
- 如果远离出生点时被调用但返回 false，说明限制在 `Player.SelectWeaponBag` 或 `WeaponBag` 字段。
- 如果开枪时被调用但返回 false，说明射击状态或 `disabled` 影响了换包。

## 第 2 步：确认 `ObscuredBool` 写法

`WeaponBag.disabled` 和 `tooFarFromSpawnPos` 是 `ObscuredBool`，不是普通 bool。

`ObscuredBool` 结构：

```text
currentCryptoKey  0x0  byte
hiddenValue       0x4  int
inited            0x8  bool
fakeValue         0x9  bool
fakeValueActive   0xA  bool
```

推荐写法：

1. 读取字段当前 `currentCryptoKey`。
2. 调用 `ObscuredBool.Encrypt(false, currentCryptoKey)`。
3. 把返回值写到 `hiddenValue`。
4. `inited = 1`。
5. `fakeValue = 0`。
6. `fakeValueActive = 0`。

相关 RVA：

| 方法 | RVA |
| --- | --- |
| `ObscuredBool.Encrypt(bool value, byte key)` | `0x7F93D0` |
| `ObscuredBool.op_Implicit(ObscuredBool value)` | `0x7F9960` |

注意：

- 不要直接把 `WeaponBag.disabled + 0x0` 写 0，这不是普通 bool。
- 如果 `Encrypt(false, key)` 调用签名不对，就用 IDA MCP 确认参数。
- 32 位 IL2CPP 调用一般要注意最后的 `MethodInfo*`，不确定就先用日志验证，不要硬写。

## 第 3 步：写最小实现脚本

文件：

```text
05-正式功能/23-无限背包/AAAAA-unlimited_bag_min.js
```

最小逻辑：

```text
enable()
  -> 安装 Player.SelectWeaponBag Hook
  -> 安装 HUD_Bag.Update Hook
  -> enabled = true

disable()
  -> enabled = false
  -> 不强行恢复背包状态

cleanup()
  -> 解除 Hook
  -> 清空缓存
```

Hook 行为：

1. `Player.SelectWeaponBag.onEnter`
   - 如果功能没开，直接返回。
   - 读取 `player + 0xA4` 得到 `WeaponBag`。
   - 清 `disabled`。
   - 清 `tooFarFromSpawnPos`。
   - 记录低频日志。

2. `Player.SelectWeaponBag.onLeave`
   - 记录返回值。
   - 如果返回 false，提示“还存在其他限制，需要看下一层”。

3. `HUD_Bag.Update.onEnter`
   - 读取 `hud + 0x2C` 得到 `WeaponBag`。
   - 清 `disabled`。
   - 清 `tooFarFromSpawnPos`。
   - 不要每帧刷日志。

## 第 4 步：最小测试

先只测这些，不扩大范围：

1. 出生点附近：
   - 打开背包。
   - 切换 1、2、3 号背包。
   - 预期：能换武器。

2. 离出生点很远：
   - 按原本方式打开背包。
   - 切换背包。
   - 预期：能打开、能换武器。

3. 正在开枪：
   - 按住开火。
   - 尝试打开背包、切换背包。
   - 预期：至少能完成切换；如果 UI 打不开，看 `SelectWeaponBag` 是否被调用。

4. 切房间：
   - 退出房间再进房间。
   - 再开功能测试。
   - 预期：不闪退，Hook 仍能命中。

5. 关闭功能：
   - 关闭后回到原始限制。
   - 如果没有恢复，也要记录，因为第一版可以先不处理恢复。

## 第 5 步：如果失败，按这个顺序加 Hook

### 情况 A：`SelectWeaponBag` 没被调用

说明卡在 UI 层。

继续看：

- `HUD_Bag.Update`
- `HUD_Bag.SetVisible`
- `HUD_Bag.PlayerController_FocusHUD_Listenner`
- `PlayerController.get_FocusHUD`

处理方向：

- 让 HUD_Bag 始终认为背包可见。
- 或者让 B 键触发时不受 FocusHUD 限制。

### 情况 B：`SelectWeaponBag` 被调用但返回 false

说明卡在 `Player.SelectWeaponBag` 内部。

优先确认：

- `disabled` 是否清掉。
- `tooFarFromSpawnPos` 是否清掉。
- `available` 数组是否对应背包为 true。
- `weaponID` 数组里目标背包是否有武器。

处理方向：

- 继续清 `available`。
- 或者 Patch 掉 `Player.SelectWeaponBag` 里的限制跳转。

### 情况 C：返回 true 但武器没变

说明 `GameManager.GiveWeaponByBag` 或武器 ID 有问题。

继续看：

- `GameManager.GiveWeaponByBag`
- `WeaponBag.weaponID`
- 当前背包 index 是否从 0 开始还是从 1 开始。

处理方向：

- 在 `GiveWeaponByBag` 上加日志，确认 weaponIndex。
- 不要马上 replace，先看传参。

## 最小代码原则

第一版不要做这些：

- 不做整合包接入。
- 不做快捷键配置。
- 不做复杂恢复。
- 不直接重写 `Player.SelectWeaponBag`。
- 不直接调用 `GiveWeaponByBag`。

第一版只做：

- 探测日志。
- 清 `WeaponBag.disabled`。
- 清 `WeaponBag.tooFarFromSpawnPos`。
- 做一个最小 CustomTkinter UI 开关。
- 验证任意位置、射击中能不能切背包。
