## 十八、注意事项

1. **ScriptableObject 共享问题**：`WeaponData_Gun` 是共享资源，直接修改会影响所有玩家
2. **运行时字段覆盖问题**：`nextAllowedShootTime` 每次射击后会被重新计算
3. **玩家判断问题**：必须通过 `get_isMyPlayer` 判断本地玩家
4. **武器所有者获取**：`WPN_Gun` 实例需要获取 `owner` 字段才能判断玩家
5. **动画速度问题**：射速和动画速度需要配合修改，否则会出现动画不匹配
6. **半自动武器问题**：半自动武器通过 `semiGunFireLinkState` 状态机控制，需要特殊处理
7. **RPG/投掷物问题**：RPG和投掷物使用不同的射速逻辑，需要单独处理

---

## 二十、补给箱RPG/AT4立即生效问题与解决方案

### 20.1 问题描述

**现象**：多人生化模式中，从补给箱捡到 RPG 榴弹和 AT4 后，射速加快和动画加快**不会立即生效**，需要切换枪械重新 deploy 才能生效。

### 20.2 原因分析

#### 1. 函数调用时机问题
- 原代码依赖 `WPN_RPG.AnimSpeedSetting` 函数
- 该函数**只在武器部署时被调用**
- 补给箱捡武器**不触发部署**，因此函数不会被调用

#### 2. 错误的条件判断
```javascript
if (wpnClass === 4) {  // ❌ 错误！4是霰弹枪，不是RPG/AT4
    // RPG/AT4处理代码
}
```
- `wpnClass === 4` 实际上是霰弹枪（ShotGun）
- RPG/AT4 的 wpnClass 值不是 4，导致条件永远不成立

### 20.3 解决方案（A方案）

#### 核心思路
借鉴无限子弹代码，使用 **`WPN_RPG.Fire`** 函数，在**每次发射时**确保动画速度正确。

#### 关键函数地址
```
WPN_RPG.Fire (0xB670A0)  // RPG/AT4发射函数
```

#### 实现代码
```javascript
// ====== WPN_RPG.Fire — RPG/AT4 发射时确保动画速度（补给箱立即生效）======
Interceptor.attach(base.add(0xB670A0), {
    onEnter: function(args) {
        this.self = args[0];
        try {
            if (isMyWeaponFn(this.self, ptr(0))) {
                // 设置动画速度
                var anim = getCharAnim(this.self, ptr(0));
                if (!anim.isNull()) {
                    setAnimSpeed(anim, 10.0, ptr(0));
                }
                
                // 设置 fireAnimRate 和 reloadAnimRate
                var realData = this.self.add(0xF0).readPointer();
                if (!realData.isNull()) {
                    realData.add(0xF0).writeFloat(10.0);  // fireAnimRate
                    realData.add(0xEC).writeFloat(10.0);  // reloadAnimRate
                }
            }
        } catch(e) {}
    }
});
```

### 20.4 修改内容

#### 1. 删除无效代码
删除了 `TryPickUpWeapon` 中错误的 `wpnClass === 4` 判断。

#### 2. 新增拦截代码
添加了 `WPN_RPG.Fire` 拦截，在每次发射时确保动画速度正确。

### 20.5 效果对比

| 场景 | 修改前 | 修改后 |
|------|--------|--------|
| **补给箱捡RPG/AT4** | ❌ 需要deploy | ✅ 立即生效 |
| **触发时机** | 初始化时 | 每次发射时 |
| **依赖性** | 依赖AnimSpeedSetting | 不依赖初始化 |

### 20.6 总结

**问题根源**：AnimSpeedSetting 只在部署时调用，补给箱捡武器不触发部署。

**解决方案**：在 WPN_RPG.Fire 中设置动画速度，每次发射时都确保正确。

**效果**：补给箱捡到 RPG/AT4 后，第一次发射时就会设置动画速度，无需切换武器重新 deploy。

## 二十一、狙击枪第一发不立即生效问题与解决方案

### 21.1 问题描述

**现象**：狙击枪（及其他半自动武器）**第一发子弹**射速和动画速度不生效，需要射击第二发后才开始加速。

### 21.2 原因分析

#### 1. Hook时机错误
- 原代码在 `GunShoot` 的 `onLeave` 中修改参数
- `onLeave` 在函数执行**后**触发，此时第一发已经发射完成
- 第一发子弹使用的是**原始参数**（未修改）

#### 2. 射击流程时序
```
第一发流程：
GunShoot.onEnter  ← 此时参数未修改
    ↓
GunShoot执行      ← 使用原始速度和间隔发射
    ↓
GunShoot.onLeave  ← 此时才修改参数（已晚）

第二发流程：
GunShoot.onEnter  ← 参数已修改（第一发后修改的）
    ↓
GunShoot执行      ← 使用修改后的速度和间隔
```

### 21.3 解决方案（方案一）

#### 核心思路
将所有修改逻辑从 `onLeave` 移到 `onEnter`，在射击**前**就设置好所有参数。

#### 修改内容

##### 1. GunShoot Hook (0xB624C0)
```javascript
Interceptor.attach(base.add(0xB624C0), {
    onEnter: function(args) {
        this.self = args[0];
        try {
            if (isMyWeaponFn(this.self, ptr(0))) {
                // 立即清除射击间隔（在射击前）
                this.self.add(0xF0).writeU8(0);        // 清除标志
                this.self.add(0x110).writeFloat(0.0);  // 清除间隔时间
                this.self.add(0x108).writeS32(0);      // 清除计数
                
                // 立即设置动画速度（在射击前）
                var anim = getCharAnim(this.self, ptr(0));
                if (!anim.isNull()) {
                    setAnimSpeed(anim, 10.0, ptr(0));
                }
                
                // 立即清除半自动标志
                var realData = this.self.add(0xEC).readPointer();
                if (!realData.isNull()) {
                    realData.add(0x1BC).writeU8(0);
                }
            }
        } catch(e) {}
    },
    onLeave: function(retVal) {
        // 所有修改已在onEnter完成
    }
});
```

##### 2. AnimSpeedSetting Hooks (共3个)
- `WPN_Gun.AnimSpeedSetting` (0xB60B00)
- `WPN_RPG.AnimSpeedSetting` (0xB66CA0)
- `WPN_GrenadeGun.AnimSpeedSetting` (0xB5F7A0)

**修改**：在 `onEnter` 和 `onLeave` 中都设置动画速度，确保覆盖。

##### 3. RPG OnFireBtnPressed Hook (0xB67700)
**修改**：在 `onEnter` 中立即修改RPG状态和动画速度。

### 21.4 效果对比

| 项目 | 修改前 | 修改后 |
|------|--------|--------|
| **第一发动画速度** | 原始速度 | ✅ 10倍速度 |
| **第一发射击间隔** | 原始间隔 | ✅ 0间隔 |
| **第一发半自动** | 需松开再按 | ✅ 连续射击 |
| **修改时机** | 射击后（onLeave） | ✅ 射击前（onEnter） |
| **生效范围** | 第二发起 | ✅ 第一发起 |

### 21.5 关键原理

#### onEnter vs onLeave
- **onEnter**：函数执行**前**触发，可以预先修改参数
- **onLeave**：函数执行**后**触发，修改已晚

#### 射击前的关键参数
1. **射击间隔**：`nextAllowedShootTime` (0x110)
2. **动画速度**：通过 `setAnimSpeed` 设置
3. **半自动标志**：`realData + 0x1BC`
4. **射击计数**：0x108

### 21.6 总结

**问题根源**：Hook时机在射击后，第一发已使用原始参数。

**解决方案**：在 onEnter 中立即修改，确保射击前参数已正确。

**效果**：狙击枪第一发就生效，无需等待第二发。

**适用范围**：所有武器（主武器、副武器、狙击枪、RPG、榴弹枪）。




为什么这个FAL CAMO赋予武器之后就是立即生效了射速加快,而FN FAL榴弹版和Nano AT4却不是立即生效呢，是不是这前者和后者不在同一个类里面，机制不太一样呢，好像后者是属于PRG一类，前者是wpn一类，寻找前后者一个可以立即生效，一个不能立即生效的原因，其他普通武器也都是立即生效，后者的特殊武器就不行


FAL CAMO：普通 WPN_Gun，数据类为 WeaponData_Gun，realData 位于 +0xEC，赋予返回时通常已经初始化完成。
FN FAL榴弹版：WPN_GrenadeGun : WPN_Gun，数据类是 WD_GrenadeGun，有枪械/榴弹双模式和独立 Init、AnimSpeedSetting。
Nano AT4：WPN_RPG : Weapon，不属于 WPN_Gun，realData 位于 +0xF0，射速字段也是独立的 reloadAnimRate/fireAnimRate。
