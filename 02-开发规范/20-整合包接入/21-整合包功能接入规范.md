# 正式发行版功能接入规范

这份规范用于 `04-正式发行版/`，当前重点适配：

```text
04-正式发行版/全功能整合包x.x/game_modifier/
```

目标是让 `05-正式功能/XX-功能名/` 里的单功能成果，按正式发行版插件架构低成本接入 `全功能整合包x.x`。

正式发行版接入原则：

```text
只接验证过的功能成果
优先完整复制单功能 JS
不重写游戏核心逻辑
不把多个功能合并成一个大 JS
不为单个功能修改中心架构
只做插件壳、manifest、UI、RPC、配置、生命周期适配
```

一句话：正式版接入不是重新开发功能，而是把已经验证过的 JS 能力装进整合包的插件体系。


## 2. 接入前置条件

一个功能进入正式发行版前，至少要满足：

```text
JS 文件存在，且功能逻辑已经单功能验证
JS 提供 rpc.exports
JS 至少提供 enable / disable / status / cleanup
cleanup 可以重复调用
退出或关闭时能恢复游戏状态
单功能说明或经验总结存在
关键偏移、字段、Hook 点来源清楚
功能边界和失败条件清楚
```

如果源功能已经是标准功能包，还应满足：

```text
manifest.json 存在
manifest.json 中 status = release_ready
Python Feature 文件存在
UI Panel 或 UI 描述存在
RPC 接口完整
生命周期说明完整
单功能测试通过
```

如果源功能不是标准包，不允许因为缺少标准文件而重写功能逻辑。正确做法是：保留原 JS 核心，补齐整合包插件壳。

## 3. 整合包标准插件目录

每个功能必须独立放在一个插件目录中：

```text
game_modifier/features/<feature_dir>/
├── __init__.py
├── manifest.json
├── feature.py
├── panel.py
├── script.js
└── events.py
```

要求：

```text
每个功能一个目录
每个功能一个 manifest.json
每个功能一个 script.js
script.js 必须自包含
feature.py 继承 PluginFeatureBase
panel.py 只通过通用 callbacks 调用功能
events.py 只处理本功能事件，没有事件也保留空处理
```

目录命名建议：

```text
24-人机暂停       -> 24_bot_pause
25-自由视角       -> 25_free_camera
```

`feature_id` 使用稳定英文标识，不能随意改名。例如：

```text
bot_pause
free_camera
```

## 4. manifest.json 规范

整合包通过 `core/plugin/manifest_loader.py` 自动扫描：

```text
features/*/manifest.json
```

manifest 必须包含以下字段：

```text
feature_id
canonical_id
display_name
category
tab
tab_title
tab_order
order
desc
script
runtime
layout
controls
config
rpc
lifecycle
state
```

可选字段：

```text
hotkey               功能是否可绑定快捷键
source               记录单功能 JS 来源和整合包内运行脚本路径
ui_text              卡片说明文本（多行）
ui_handles           UI 控件句柄绑定名
```

推荐模板：

```json
{
  "feature_id": "bot_pause",
  "canonical_id": "bot_pause",
  "display_name": "人机暂停",
  "category": "game_test",
  "tab": "game_test_tab",
  "tab_title": "游戏测试",
  "tab_order": 70,
  "order": 95,
  "desc": "所有人机停止行动。",
  "script": "script.js",
  "hotkey": {
    "enabled": true
  },
  "runtime": {
    "type": "plugin_script"
  },
  "layout": {
    "card_type": "simple",
    "columnspan": 1,
    "title_color": "#93c5fd"
  },
  "controls": [
    {
      "type": "switch",
      "action": "enable"
    }
  ],
  "config": {},
  "rpc": [
    "enable",
    "disable",
    "setConfig",
    "setconfig",
    "status",
    "cleanup"
  ],
  "lifecycle": {
    "cleanup": true,
    "restore": true,
    "requires_room_ready_reapply": true,
    "room_ready_retry": true
  },
  "source": {
    "single_feature_js": "05-正式功能/24-人机暂停/AAAAA-bot_pause_min.js",
    "runtime_script_js": "features/24_bot_pause/script.js"
  },
  "ui_handles": {
    "switch": "bot_pause_switch"
  },
  "ui_text": {
    "lines": [
      "所有人机停止行动。"
    ]
  },
  "state": {
    "sync_enabled_from_config": true
  }
}
```

字段说明：

```text
hotkey.enabled              是否允许在设置页快捷键下拉框中绑定本功能；固定专用快捷键（如 Alt+1~4）不写此字段
layout.title_color          卡片标题颜色（十六进制色值），用于按 tab 或功能类型区分视觉风格
source.single_feature_js    记录本功能在 05-正式功能/ 下的原始 JS 路径，便于追溯
source.runtime_script_js    记录整合包内运行脚本相对路径
ui_text.lines               卡片说明文字，按行展示；与 desc 配合使用，desc 是一句话简介
```

要求：

```text
script 必须指向本插件目录内的 script.js
runtime.type 必须为 plugin_script
controls 只描述 UI 控件，不包含游戏逻辑
rpc 中必须列出 JS 暴露的所有 action
config 中只放本功能配置
state.sync_enabled_from_config 必须明确 true 或 false，用作显式标注/兼容；普通开关恢复以 data/feature_state.json 和 lifecycle.restore 为准
新增或迁移功能时，必须同步更新 `20-整合包接入/22-功能开关与参数持久化记录.md`，记录开关、按钮、参数、是否写入 data/feature_state.json、是否写入 data/user_config.json，以及为什么这样设计
```

持久化总表索引：

```text
功能开关与参数持久化记录.md 是功能开关和参数记录的最终总表。
接入新功能时，先按本规范完成 manifest/UI/RPC/lifecycle，再回到该总表补一行。
如果总表和本文档出现冲突，以总表为准，并同步修正本文档。
```

## 5. JS 接入规范

### 5.1 完整复制优先

从 `05-正式功能` 接入时，JS 处理顺序必须是：

```text
1. 先完整复制原 JS 到 features/<feature_dir>/script.js
2. 保留原偏移、Hook、字段读写、算法和状态机
3. 再补整合包所需 RPC 别名、配置入口、cleanup 参数兼容
4. 最后只删除明显无关的独立 UI 启动代码或测试代码
```

不允许：

```text
为了风格统一重写 JS
把功能核心逻辑改成另一个实现
把多个功能的 JS 合并
把 JS 放进中心 dispatcher
让 JS 依赖全局 modules.xxx
让 JS import / require 外部 helper
```

### 5.2 RPC 标准

整合包通过 `RpcClient` 和 `ScriptManager` 调用插件 JS。标准 RPC：

```text
enable
disable
setConfig
setconfig
status
cleanup
```

要求：

```text
enable 开启功能
disable 关闭功能
status 返回结构化状态
cleanup 负责恢复游戏状态和释放 Hook/timer
setConfig/setconfig 用于接收 UI 配置
```

如果原 JS 已经使用其他配置接口，例如：

```text
configure(input)
```

可以保留原函数，并增加别名：

```javascript
rpc.exports.setConfig = rpc.exports.configure;
rpc.exports.setconfig = rpc.exports.configure;
```

这属于整合包接口适配，不属于重写游戏逻辑。

### 5.3 cleanup 参数兼容

整合包 cleanup 可能传入原因参数：

```javascript
cleanup({ reason: "shutdown" })
```

如果原 JS 的 cleanup 不接收参数，可以只做兼容，不改变功能逻辑：

```javascript
cleanup: function (payload) {
  // payload 可忽略，但函数必须能接收。
  return cleanupOriginal();
}
```

## 6. Python Feature 规范

`feature.py` 必须继承 `PluginFeatureBase`：

```python
from core.plugin.plugin_base import PluginFeatureBase


class PluginFeature(PluginFeatureBase):
    feature_id = "bot_pause"
    js_filename = "script.js"
    name = "人机暂停"
    category = "other"
    desc = "暂停或恢复所有人机。"
```

要求：

```text
不使用旧 FeatureBase
不使用 register_feature
不 import core.feature_registry
不自己 attach Frida
不自己管理 session
RPC 调用只通过 PluginFeatureBase / feature_service / rpc_client
```

如果功能需要特殊 action，可以在 `PluginFeature` 内封装，但仍然必须走通用 RPC 客户端。

## 7. UI Panel 规范

`panel.py` 只能负责显示和触发通用回调。

允许：

```text
显示开关
显示滑块
显示下拉框
显示状态文字
callbacks["toggle"](feature_id)
callbacks["set_config"](feature_id, key, value)
callbacks["action"](feature_id, action)
```

禁止：

```text
panel.py 直接 import FridaManager
panel.py 直接调用 script.exports.xxx
panel.py 直接写 RVA / 偏移 / Hook 地址
panel.py 访问 app._xxx 私有字段
panel.py 使用 context._app / context.legacy
panel.py 使用 get_state / set_state / get_handle / set_handle
panel.py 为某个功能改 ui/app.py
```

如果需要完整页面，必须在 manifest 里声明：

```json
"ui": {
  "mode": "special_page",
  "tab_title": "功能页名称",
  "tab_order": 60,
  "lazy_build": true
}
```

不要为了一个功能在 `ui/app.py` 中写特殊页面分支。

## 8. 配置规范

配置必须属于本功能 manifest：

```json
"config": {
  "moveSpeed": 18.0,
  "lockPlayerMove": true
}
```

要求：

```text
UI 修改配置后走 callbacks["set_config"]
Python Feature 负责把配置传给 JS
JS 不直接读取 data/user_config.json
JS 只接收 RPC 传入的配置
配置字段命名要与 JS 接口一致
```

如果原 JS 使用驼峰字段，例如 `moveSpeed`，正式版 manifest 和 panel 也优先保持 `moveSpeed`，不要无意义改成 `move_speed`。

## 9. 生命周期规范

生命周期的完整规则（generation 机制、指针验证、Hook 安装与分离、pendingApply / room-ready 二次应用、cleanup 标准行为、禁止 replace 生命周期函数、各类功能特殊要求等）见 `10-单功能开发/13-单功能生命周期规范.md`，该文档是生命周期规范的唯一权威。

本节仅补充整合包接入侧的 manifest.lifecycle 字段要求。

每个功能的生命周期需求写入 manifest：

```json
"lifecycle": {
  "cleanup": true,
  "restore": true,
  "requires_room_reset": false,
  "uses_cached_pointer": false
}
```

字段补充说明：

```text
requires_room_ready_reapply   功能是否需要在房间就绪后再次应用（依赖房间内对象时为 true）
room_ready_retry              是否启用短周期重试作为兜底
room_ready_reapply_exempt_reason  如果不适用 room_ready 机制，必须写明不适用原因
```

如果功能不需要 room_ready 机制，必须在 manifest 或功能说明里写明不适用原因：

```json
"lifecycle": {
  "cleanup": true,
  "restore": true,
  "requires_room_ready_reapply": false,
  "room_ready_retry": false,
  "room_ready_reapply_exempt_reason": "只安装固定 RVA Hook，不依赖房间内对象；Hook 命中时自然按 enabled 状态生效"
}
```

判断标准：

```text
能在连接后一次性安装固定地址 Hook，且 Hook 命中时会读取 enabled 状态再执行：
可以不做 pendingApply，但必须写 exempt_reason。

enable 会立即写玩家、Bot、相机、武器、房间对象字段：
必须做 pendingApply 或 pendingEnable，并按 13 的 room-ready 触发源选择标准实现。

功能是一次性按钮动作，例如跳过当前回合：
通常不应该 restore，manifest.lifecycle.restore 应为 false。
```

交付测试必须覆盖：

```text
1. 未进入游戏前开启功能
2. 再连接或进入游戏房间
3. 不手动关闭再开启，功能也能自动生效
4. 退出房间再进入，功能能再次按 UI 开关状态恢复
5. UI 关闭时 pendingApply 不会继续生效
```

## 11. 整合包正式版接入流程

### 11.1 文档按需读取

新增功能接入整合包时，本规范是主入口。其他文档按需读取，不要为了一个小功能把所有文档都翻一遍。

```text
功能有开关、按钮、滑块、下拉框：
读取 20-整合包接入/22-功能开关与参数持久化记录.md

功能可能需要快捷键：
读取 20-整合包接入/23-快捷键参考.md
```

快捷键判断一句话：

```text
战斗中常按、简单开关、误触风险低，可以考虑放快捷键。
模式切换、ESP、复杂配置页、开局前设置一次的功能，一般不要放快捷键。
```

### 11.2 接入流程

每次从 `05-正式功能` 接一个功能到 `全功能整合包x.x`，按这个顺序：

```text
1. 阅读单功能 JS、说明文档、经验总结
2. 确认原 JS 的 enable / disable / status / cleanup 行为
3. 从 game_modifier/features/_template/ 复制新插件目录
4. 将原 JS 完整复制为 features/<feature_dir>/script.js
5. 补齐或兼容 setConfig / setconfig / cleanup(payload)
6. 编写 manifest.json，声明 tab、config、rpc、lifecycle、state
7. 编写 feature.py，继承 PluginFeatureBase
8. 编写 panel.py，只使用通用 callbacks
9. 如有 JS 事件，编写 events.py
10. 不修改 ui/app.py、core/frida_manager.py 等中心文件
11. 运行 JS 语法检查
12. 运行 Python 编译检查
13. 运行 tools/check_architecture.py
14. 运行插件架构相关测试
15. 启动正式版 UI，测试开启/关闭/status/cleanup
16. 测试退出 UI、游戏断开、重开游戏、切房间
17. 更新发行版 CHANGELOG 或接入记录
18. 更新 `20-整合包接入/22-功能开关与参数持久化记录.md`
19. 如新功能可能需要快捷键，再参考 `20-整合包接入/23-快捷键参考.md`
```

## 14. 硬规则

```text
正式版不是功能试验田。
整合包新功能必须走插件目录。
JS 核心逻辑先完整复制，再做最小适配。
中心文件不能出现具体功能 ID 分支。
独立单功能 UI 不能直接接入正式版。
能通过插件壳、manifest、配置、UI、RPC、生命周期完成接入，才说明功能适合进入正式版。
```
