# 功能开关与参数持久化记录

更新时间：2026-09-09

## 记录规则

| 项目 | 含义 |
|---|---|
| 参数记录 | 下拉框、滑条、勾选项等配置写入 `data/user_config.json`，普通开关不再往这里写 `enabled`。 |
| 开关恢复 | 普通持续开关写入 `data/feature_state.json`；启动时只从这里恢复 UI 开关，连接游戏后再按规则调用 `enable`。 |
| 默认关闭 | 参数可以保留，但开关不写入/不读取 `data/feature_state.json`，程序启动和连接游戏后都不会自动打开。 |
| 特殊恢复 | 不走普通 `restore_enabled()`，但功能自己有单独机制记录用户意图或预约状态。必须在本表单独写清楚。 |
| 关键字段 | `lifecycle.restore` 控制是否进入普通开关恢复；`state.sync_enabled_from_config` 只保留显式标注/兼容，不再作为 `user_config.json` 恢复开关入口。 |

## 不走普通恢复的功能

这些功能没有走统一的 `restore_enabled()` 普通恢复逻辑。注意：这里不等于全部“启动默认关闭”，有些是功能自己做特殊恢复。

| 功能 | 保存位置 | 实际行为 |
|---|---|---|
| 15-多人生化Buff选择 | `data/user_config.json` | 保存幽灵/人类两个下拉框：`nano4t.ghost`、`nano4t.human`。`features/15_nano4t/state.py` 负责读取/保存，`selection.py` 在选择变化时触发保存，`panel.py` 打开页面时加载上次选择；不会启动自动应用，用户进房后点应用。 |
| 16-赋予武器 | `data/user_config.json`、`data/weapon_hotkeys.json` | 保存复活自动装备开关和武器快捷键；赋予动作本身不会启动自动执行。 |
| 18-方框透视 | `data/desired_states.json` | ESP 特殊 desired state；上次开着，下次启动会继续按用户意图尝试开启 ESP。 |
| 19-强制决战回合 | `data/user_config.json` | 保存预约开关；连接游戏或进入多人生化后，由本功能自己同步到游戏。 |
| 25-自由视角 | `data/user_config.json` | 只保存移动速度等参数；开关不写 `feature_state.json`，启动默认关闭。 |
| 26-手雷模式 | `data/user_config.json` | 只保存手雷参数；主开关不写 `feature_state.json`，启动默认关闭。 |
| 27-游戏模式切换 | `data/user_config.json` | 只保存上次选择的模式；开关不写 `feature_state.json`，启动默认关闭。 |
| 32-亮度调节 | `data/user_config.json` | 只保存亮度等参数；探针开关不写 `feature_state.json`，启动默认关闭。 |
| 33-玩家信息修改 | 直接读写 `PlayerData.dat` | 不走 Frida、不写 `feature_state.json`；纯文件操作，不参与普通恢复。 |

## 特殊机制检查记录

本次检查过的功能级特殊持久化机制：

| 机制 | 涉及功能 | 结论 |
|---|---|---|
| ESP 特殊 desired state | 18-方框透视 | 唯一使用 `GameSessionManager.set_desired_state()` 的功能；状态写入 `data/desired_states.json`。 |
| 特殊页配置 | 15-多人生化Buff选择、16-赋予武器、19-强制决战回合、26-手雷模式 | 都通过 `ConfigManager` 写入 `data/user_config.json`，但不一定走普通开关恢复。 |
| 武器快捷键 | 16-赋予武器 | 武器绑定单独写入 `data/weapon_hotkeys.json`，不是普通功能参数。 |
| 普通功能开关 | 普通持续开关 | 只写入 `data/feature_state.json`；`lifecycle.restore=false` 的功能不会写入。 |
| 普通快捷键/声音/Universal revision | 设置页、声音、Universal DLL | 属于程序设置或内部缓存，不算功能总表里的功能开关恢复。 |

## 新功能填写要求

新增或迁移功能时，必须同步更新本文件，至少写清楚：

1. 功能卡片上的中文名称。
2. 开关、按钮、下拉框、滑条等用户可操作项。
3. 哪些参数会写入 `data/user_config.json`。
4. 开关是否允许写入 `data/feature_state.json`。
5. `lifecycle.restore` 是 true 还是 false。
6. 有没有 `desired_states.json`、`weapon_hotkeys.json` 等特殊保存文件。
7. 为什么选择恢复开关、默认关闭，或特殊恢复。

内部目录和 ID 继续在功能接入规范、架构检查映射里维护；本表主要给人看，优先写界面中文。
