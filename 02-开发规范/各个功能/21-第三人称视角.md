# 21｜第三人称视角（Third Person Camera）

**来源**：`features/21_third_person_camera/`（script.js）+ 开发素材 `05-正式功能/21-第三人称视角/以v3_14_owner_perf为基础.md`、`third_person_basic_v3_14_owner_perf.js`

## 核心原理

- **一句话**：Hook Cinemachine `Brain.PushStateToUnityCamera`（相机渲染出口），在其返回后把最终相机 Transform 的位置/旋转直接设置到本地玩家背部肩后（并接管 FreeLook 相机 LookAt/Follow），本质是“就地改写最终相机 Transform”类方案；同时修正 `Recoil.GetShootRay` 让子弹从枪口出射而不是从相机。
- **手段归类**：Hook 相机渲染函数 + 主动调用 Transform set_position/set_rotation + 生命周期 Hook 驱动刷新。

**特殊处理**：
- **生命周期事件合并队列**：`SetWeapon/Respawn/Spawn` 短时间连续触发只合并一次刷新（`refreshQueue`），避免高频重复改模型/相机。
- **顺序强约束**：`PushStateToUnityCamera.onLeave` 里“先应用独立俯仰，再采样最终相机”，注释明言顺序不能交换，否则射击和 WASD 用不到真实镜头方向。
- **热路径优化**：不在热路径调 `Transform.get/set_rotation`；移动方向改 Hook 返回 Vector3 的辅助函数实现；相机指针低频健康检查（`cameraCacheHealthCheckMs=1000`）替代每帧内存页可读性检查。
- **相机配置精简**：v3.7 起只保留 4 项（shoulder/distance/pivotHeight/invertY），不再读写 ScreenY/FOV/俯仰倍率，避免与游戏自身实时相机状态互相争夺。
- **可逆卸载**：`restoreCameraState/restoreModelMode` 在 disable/切房间时恢复 m_YAxis、观察模式、模型可见性与 FreeLook 状态；用缓存但每次验证有效性，绝不写陈旧角色/武器指针。
- **参数钳制**：移动速度、俯仰角（`maxCameraPitchDegrees=75`、单步 ≤10°）、距离上限等。
- **身份校验**：`focusPlayer` 与 `Player.get_isMyPlayer` 双重校验，只作用于本地玩家。

## 作用范围

仅本地玩家。相机只挂到 `focusPlayer`（即本地玩家），Recoil/移动/模型处理都有 isMyPlayer 或 localPlayer 指针对照；不触碰 Bot 或他人相机。

## 产品设计巧思

- 开启即把视角切到身后，随人物移动/转身自动跟住，不用手动拖镜头。
- 距离/高度/左右肩/鼠标反转可实时调，贴合个人习惯。
- 换枪、复活、切回合后自动重建视角，不需要每次重开。
- 切回第一人称或退出功能时，相机与模型状态自动还原，不留残影。

## 开发历程（重点）

### 踩过的坑

1. **第三人称下子弹“从相机射出”**
   - 一开始没考虑到：把相机拉远后，射击射线（`Recoil.GetShootRay`）的起点还在原第一人称枪口位置，视觉上子弹从相机方向出射，可能穿墙或打偏。
   - 出问题：近距离开火明显不对。
   - 怎么修：Hook `Recoil.GetShootRay`，真实开枪时从角色枪口取点并 `Physics.Raycast` 构建新的 origin/direction 写回返回缓冲区。

2. **与游戏自身相机状态互相争夺**
   - 一开始没考虑到：游戏每帧/换模式会重算相机 FOV、俯仰倍率、ScreenY。
   - 出问题：我们写入的 ScreenY/FOV 被游戏覆盖，或反过来干扰游戏，视角抖动/失焦。
   - 怎么修：v3.7 起删除对这些字段的读写，只保留肩位/距离/枢轴高度/反转四项，让游戏相机状态自治。

3. **WASD 移动方向不随相机**
   - 一开始没考虑到：移动速度计算基于世界坐标（或旧朝向）。
   - 出问题：第三人称下按 W 不朝屏幕前方走，手感割裂。
   - 怎么修：Hook `Player.GetWalkVelocity`，在 onLeave 只改写最终水平速度方向为相机相对方向。

4. **热路径性能与指针失效**
   - 一开始没考虑到：每个相机帧做内存页可读性检查 + 频繁 Transform 读写。
   - 出问题：帧率下降；切房/换模式后缓存相机指针失效。
   - 怎么修：改为低频健康检查 + 生命周期事件驱动刷新 + 合并队列，避免每帧重复调用。

### 方案迭代

- **早期（直接写相机 Transform 跟随）**：简单把最终相机绑定人物背后，但无法处理射击射线、移动方向、游戏相机状态重写，效果不完整。
- **中间（Hook 相机渲染 + 各修正）**：引入 `PushStateToUnityCamera` 接管最终相机，逐个补 Recoil/GetWalkVelocity/输入分离修正，功能成型但配置过多、性能开销大。
- **最终（v3.7+ 精简 + 生命周期驱动）**：只保留 4 项配置，生命周期 Hook（CameraManager/GameManager/MapManager/Player）+ 合并队列驱动刷新，热路径只做必要写操作，可逆恢复完整。

### 一开始没考虑到的点

- 相机拉远后射击射线起点与视觉不符——需同步改射线。
- 游戏自身会持续重写相机参数，接管要“少写、只写必要”。
- 换枪/复活/切回合都会重建相机或模型，需生命周期 Hook 驱动而不是一次性初始化。
- 高频事件（SetWeapon/Respawn/Spawn 连续触发）会重复刷新，需合并。

### 经验教训

- 相机/渲染类功能的核心是**与游戏自身相机状态解耦**：能不改的字段坚决不改，只接管真正需要的 Transform。
- 改视角类功能必须**联动修改射击射线与移动方向**，否则视觉与手感分离。
- 相机对象生命周期长于单帧，用**生命周期 Hook + 事件合并**驱动，避免每帧轮询或频繁失效。

## 一句话总结

通过 Hook `CinemachineBrain.PushStateToUnityCamera` 直接接管最终相机位置/旋转实现第三人称，并联动修正 `Recoil.GetShootRay`（枪口出射）与 `Player.GetWalkVelocity`（相机相对移动）、用生命周期合并队列驱动换枪/复活刷新；踩坑集中在“相机拉远后射线/移动不同步”和“与游戏自身相机参数互相争夺”，最终以精简配置 + 可逆恢复收尾。
