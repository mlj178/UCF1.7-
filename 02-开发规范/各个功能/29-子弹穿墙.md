# 29｜子弹穿墙/弹体穿墙（Bullet & Projectile Wall Penetration）

**来源**：`features/29_bullet_wall_penetration/`（script.js）+ 开发素材 `05-正式功能/29-子弹穿墙/子弹穿墙-简要说明.md`
**卡片名（2.7 起）**：子弹穿墙/弹体穿墙（原「子弹穿墙」）
**关联**：`40-开火直伤/弹体追踪`（弹体穿墙覆盖的正是它的 5 种投射物）

功能拆成两段，共用一个开关：

| 段 | 对象 | 做什么 |
|---|---|---|
| A 子弹穿墙 | `WPN_Gun.Damage`（本地玩家枪械） | 开火瞬间临时把 `LayerConstant.LM_GunShoot` 改成 HitBox-only，让原版 `RaycastAll` 拿到墙后 hitbox，交回原版结算 |
| B 弹体穿墙 | `WPN_Missile` / `WPN_GRENADE`（本地玩家投射物） | **主动探路**：物理步里提前发现"前方是墙面"就关掉这一颗弹体的物理碰撞，穿过去再恢复；碰撞回调作为兜底 |

## A 段核心原理（子弹穿墙，未改）

- **一句话**：Hook `WPN_Gun.Damage`（不 replace），仅在本地玩家武器进入 Damage 的短窗口内把 `LayerConstant.LM_GunShoot` 临时改成 `HitBox-only` 掩码，让原版 `RaycastAll` 能拿到墙后的 hitbox，Damage 返回后立即恢复；`WeaponLogic.CheckWall` 保持原样，穿墙伤害衰减（`wallShotDamageRatio`）与 `wallThrough` 标记继续由游戏原逻辑执行。
- **手段归类**：Interceptor.attach（不 replace）+ 静态字段读改写 + 原版函数复用。
- **为什么弹体不能照搬这一套**：子弹的命中判定是**射线**，射线掩码是**全局静态字段** `LM_GunShoot`，所以"开火瞬间改掩码"就能生效。弹体是**物理刚体**，它撞不撞墙由 Unity 物理引擎按**每对 collider** 决定，**不读任何全局掩码**（实测 `WPN_GRENADE.OnCollisionEnter` 里也没有任何 `LM_*` 引用）。所以弹体只能换一套 API：`Rigidbody.detectCollisions` / `Physics.IgnoreCollision`；语义保持一样（只对本地玩家、只对墙面、随时可还原）。

## B 段核心原理（弹体穿墙）

### B1 反汇编结论（0x10B5D0F0 = WPN_GRENADE.OnCollisionEnter 尾部机器码）

```
mov edi,[esi+44h] / test edi,edi / jz ret
call Rigidbody.get_velocity ... call Rigidbody.set_velocity   ; 原版自己改速度
cmp byte [esi+74h],0        ; expWhenTouchSth
jz  ret
push [eax+118h] / push esi / call eax   ; vtable slot11 = TryExplosion
```

两点：
1. 弹体**完全不读 `LayerConstant.LM_GunShoot`**，"子弹穿墙那套放开门掩码"对弹体无效。
2. "撞墙即爆"藏在 **虚表间接调用** 里，`get_callees` 看不到（那段只显示 `SoundManager` / `get_velocity` / `set_velocity`）。**判断"原版函数做了什么"不能只看 callees。**

### B2 主路径：主动穿墙（2.7 实测第一版失败后改成这个）

第一版只在 `OnCollisionEnter` 里兜底（抑制 `expWhenTouchSth` + `IgnoreCollision`），
**实测火箭筒完全没反应，且整场没有任何弹体日志** —— 说明卡在了某条静默 return 上
（最可能是 `Collision.get_contacts()` 或层判定）。因此改成"不依赖碰撞回调"的主动式：

每一物理步（`WPN_Missile.FixedUpdate` 钩子，本地玩家弹体）：

1. 读位置 + 速度；沿飞行方向用 `Physics.Raycast` 探路 `projectileProbeLookahead`(默认 3.5m)。
   起点前移 0.35m，避免打到弹体自己的 collider。
2. 命中物用 `RaycastHit.m_Collider`(instanceID) → `Object.FindObjectFromInstanceID`
   → `GameObject.layer` 反查所在层：
   - 不是可穿透层（默认只有 `Environment`=layer 0）→ 不处理（敌人 HitBox、他人弹体都走这里）；
   - `|normal.y| >= projectileWallMaxNormalY`(0.6) → 地板/斜面，不处理；
   - 否则判定为墙面。
3. 命中墙面 → **在真正接触之前**摘掉这次碰撞，分两档：
   - **主选（作用域最小）**：`Physics.IgnoreCollision(弹体自身 collider, 这一面墙 collider, true)`。
     只影响"这一颗弹 × 这一面墙"，**地板完全不受影响**（滚地雷安全）。
     墙 collider 直接来自 `RaycastHit` 的 instanceID 反查，不用等碰撞回调。
   - **备选**（拿不到墙 collider / 反查不到弹体自身 collider 时）：
     `Rigidbody.set_detectCollisions(rb, false)`，把这一颗弹体的物理碰撞整体关掉，窗口结束后还原。
   两条路都让弹体在接触前就穿过去，不会进 `OnCollisionEnter`，也就不会"撞墙即爆"。
4. 结束穿墙态（任一，两条路共用）：
   - 已走过"入态时到墙面的距离 + `projectileGhostExtra`(0.8m)"**且** `OverlapSphere(中心,0.08)`
     不再压着"不是自己"的关卡几何；
   - 到达 `projectileIgnoreMaxMs`(1200ms) 硬上限（保证不会永久关着）；
   - 弹体回池 / 功能关闭（`dropMissileState` / `releaseEveryIgnore` 里强制还原）。
   然后 `set_detectCollisions(rb, true)`。

> **必须还原**：`detectCollisions` 留在 false 会被对象池的下一颗弹继承，直接飞穿全场。所以
> SetWeaponData / Recycle / sweep / disable / cleanup 五条路径都调 `restoreGhost()`。

### B3 兜底路径：碰撞回调（保留）

万一探路没赶上（弹体一个物理步就跨过了探路距离），碰撞回调里还会做一次：

1. 本地玩家弹体 + 撞到 `Environment` 层 + 接触法线偏水平；
2. onEnter 把 `WPN_GRENADE.expWhenTouchSth(+0x74)` 临时写 0（onLeave 按原字节写回）→ 原版本体读不到爆炸分支；
3. `Physics.IgnoreCollision(弹体自身 collider, 墙 collider, true)`。自身 collider 三级来源
   （v3 起）：**接触点 `m_ThisColliderInstanceID` > `st.selfColliders` 缓存 > OverlapSphere 反查**；
4. 把 `FixedUpdate` 缓存的碰撞前速度写回 `Rigidbody.set_velocity`（碰撞已被求解器削弱）。

### B5 v3：修掉"穿墙时卡墙减速 / 悬在空中迟迟不引爆"（2.7 第二次实测后）

第二次实测（17:56 那局）日志把根因指得很清楚：

```
反查弹体自身 collider 失败 ×19 条（该 WARNING 限频 2s/条，采样）
弹体穿墙：missile=0x8d1dc80 wall=0x43929d60 layer=2 忽略=0对   ← 2.3 秒内同一面墙连撞 14 次
弹体碰撞：… 对象=ALPHA_Blocker.bmp 判定=墙面→穿墙            ← 判定对了，但没忽略掉
```

- 采样 `弹体穿墙：` 84 条里 `忽略=0对` 有 38 条 → **约 45% 的墙碰撞根本没被忽略**。
- 根因：`collectMissileColliders()` 用 `Physics.OverlapSphere(弹体位置,1.2m,全层,Collide)`
  + `Collider.attachedRigidbody == 弹体Rigidbody` 反查"弹体自己的 collider"，**会间歇性返回空**。
  失败的那一次 `ignoreWallForMissile` 返回 0，而反应式路径**没有兜底**（只有主动探路路径有
  `detectCollisions` 备选，而这局 `主动穿墙=0`，一次都没走到）→ 这面墙照撞不误。
- 撞一次的代价是硬编码的：`WPN_Missile.OnCollisionEnter`/`WPN_GRENADE.OnCollisionEnter` 尾部
  `movss xmm1,[0x10BAC054] / mulss / call Rigidbody.set_velocity`，常量 **0.6f** →
  **每撞一次速度 ×0.6**，连撞几次就卡在墙里，看起来就是"变慢 / 卡住 / 悬在空中"。
- "迟迟不引爆"是连锁反应，不是另一个 bug：撞墙不炸是我们**故意**抑制的
  （`expWhenTouchSth` 写 0），弹体被卡住到不了敌人，只能等 `RecyclableObject` 的生命计时器
  （`lifeTime` 默认 **2.0s**：`RecyclableObject..ctor` 把 +0x14 写成 `0x40000000`）
  → `WPN_GRENADE.OnLifeTimerEnd` → `TryExplosion` → 原地自爆。
  上一局那串"同一面墙 2.3 秒内 14 次碰撞"正好等于一发弹的整个寿命。

**v3 的三处修改：**

1. **自己的 collider 改从碰撞接触点直接拿**（正解，不再依赖物理查询时序）。
   `ContactPoint.m_ThisColliderInstanceID(+0x18)`（对方是 +0x1C）
   → `Object.FindObjectFromInstanceID` → 验证 `attachedRigidbody == rb` 后直接用。
   三级来源：**接触点 hint > `st.selfColliders` 缓存 > OverlapSphere 反查**。
2. **忽略失败不再"算了"**：`completeWallPenetration` 把这一面墙排进 `st.pendingWalls`，
   下一个物理步在 `tickPendingWalls()` 里补忽略（`WPN_Missile.FixedUpdate` 一定早于
   本次 `Physics.Simulate`，所以补上的 `IgnoreCollision` 下一帧就生效）。
   超过 `projectilePendingRetryMs`(400ms) 仍失败才放弃并计 `projectilePendingExpired`。
3. **探路射线不再被"非墙层"吃掉**：敌人(Entity 7)/命中盒(HitBox 3)/尸体(8)/幽灵(10)
   经常正好挡在墙前面，一发射线就被吃掉（实测占探路的 29%：`其他层=288/995`）。
   现在命中不可穿透层就跳过它继续往后探（最多 `projectileProbeMaxSkips`(3) 段），
   仍然只有"可穿透层 + 法线偏水平"才判为墙。

### B4 诊断（排查"没生效"必看）

每 5 秒一条 `[beat] 弹体穿墙 ...`，读法：

| 现象 | 含义 |
|---|---|
| `FixedUpdate=(…本地0…)` 且 `isMy原始=number:1` | **原生 bool 类型坑**：`isMyPlayer` 返回的是数字 1，代码里用 `=== true` 判就恒 false → 必须用 `toFlag()` |
| `FixedUpdate=(…本地0…)` 且 `isMy原始=owner=null` | 弹体 owner 字段没读到（对象池/时序问题） |
| `探路射线=0` | 前方一直没东西（或弹体没在飞） |
| `探路射线>0 墙=0 地>0` | 前方都被判成地板/斜面 → 调 `projectileWallMaxNormalY` |
| `其他层>0` + `命中层=N` | 前方的墙不在可穿透掩码里，N 就是它所在的层 → 改 `projectilePenetrableLayers` |
| `探路层分布=2(AirWall):37 0(Default):20 …` | **最有用的一行**：探路到底打在哪些层上（带层名） |
| 启用时的 `本工程层名表：0=Default 2=AirWall …` | 直接回答"layer N 是什么" |
| `主动忽略=0` | 没有提前摘掉墙面碰撞（看探路/层/法线几项） |
| `反查失败`（新增） | 三条路都没拿到弹体自己的 collider 的次数。**正常应接近 0**；持续增长说明接触点也拿不到 |
| `接触点collider`（新增） | 成功从 `ContactPoint.m_ThisColliderInstanceID` 拿到自己 collider 的次数，正常应接近"本地碰撞数" |
| `缓存兜底`（新增） | OverlapSphere 反查失败、靠 `st.selfColliders` 缓存顶住的次数 |
| `补忽略=N(排队M/超时K/未决L)`（新增） | 排队是**累计**次数 M、下一物理步补成功 N 次、超时放弃 K 次、当前还压着没补上的 L 条。**K 应该远小于 M；L 不应长期不为 0** |
| `反查失败现场：… contacts=/thisID=/thisRB=/overlap=`（新增） | 只在"三条路全失败"时打一行（约 2%），一次给出死因：contacts 读不到 / thisID=0 / FindObjectFromInstanceID 拿不到 / attachedRigidbody 对不上 / OverlapSphere 返回空 |
| `主动穿墙=0` | 没退化成"关整颗弹碰撞"（正常，主选能走通就不会走它） |
| `主动穿墙>0` 但穿不过去 | `detectCollisions` 写入没被物理引擎接受 |
| `还原失败>0` | `set_detectCollisions` 调用报错 |
| 每次本地弹体碰撞一行 `弹体碰撞：… 判定=…` | 兜底路径的实际判定结果 |

开启功能时还会打三行自检：参数（探路 / 法线阈值 / 窗口 / raycast=OK …）、
**可穿透层掩码 + 层名**、**本工程完整层名表**。

## 作用范围

A 段：仅本地玩家武器（`Weapon.get_isMyWeapon`），对墙后目标生效，遵循原版衰减。
B 段：仅本地玩家发射的投射物（`WPN_Missile.owner` + `Player.get_isMyPlayer`），
只对"墙面"（在 `projectilePenetrableLayers` 掩码内 + 法线偏水平）生效；地板、角色、他人/人机弹体一概不动。

## 开发历程（重点，别重复踩）

### A 段踩过的坑

1. **RaycastAll 命中顺序不稳定**：想自己补伤害会重复结算 → 改成只临时改层，交回原版。
2. **射线层被永久修改污染**：改 `LM_GunShoot` 后不恢复会影响所有射击 → onLeave 无条件恢复 + 计数配对。
3. **误伤非本地武器**：`WPN_Gun.Damage` 对所有人开火都进 → `Weapon.get_isMyWeapon` 过滤。

### B 段踩过的坑

1. **以为"弹体穿墙"也是放开门掩码**：机器码证明弹体不读任何 `LM_*`，照样撞墙即爆。
2. **以为 `OnCollisionEnter` 只播个音效**：`get_callees` 看不到虚表调用，实际尾部就是
   `expWhenTouchSth → vtable slot11 = TryExplosion`。**虚调用必须看机器码。**
3. **第一版只做碰撞回调兜底 → 实测火箭筒完全没反应**：日志里 8 个钩子都装上了，但整场
   没有一条弹体日志 —— 说明卡在静默 return 上，而且没有诊断可看。
   教训：**新机制第一次上机必须带 "计数器 + 周期 beat + 每次事件一行" 的可观测性**，
   否则只能靠猜，浪费一轮实测。
4. **原生 bool 类型坑（v2 实测"还是不行"的真凶）**：日志里
   `FixedUpdate=300(本地0/非我300)`、`探路射线=0`、`lastReject=notMine` ——
   8 个钩子都装上了、参数自检 `raycast=OK findObject=OK`，但**所有判定都失败**。
   原因是 `native.isMyPlayer(...) === true`：Frida 的 `'bool'` 返回值不保证是 JS `true`
   （这里是数字 `1`），严格相等恒 false；`native.raycast(...) !== true` 同理恒"没命中"。
   修法：统一走 `toFlag()`（40_direct_damage 里早就有同名的这个函数，本项目踩过同一个坑），
   并把原始返回值 `typeof:值` 打进 beat 日志（`isMy原始=`）。
   **教训：native bool 一律按真值判定，并且第一次上机就把"原始返回值+类型"打出来。**

5. **只认 `Environment`(layer 0) 导致"怎么都不穿"**：bool 修好后探路/忽略都跑起来了
   （`主动忽略=10`、`反应式穿透=9`），但日志显示 **16 次碰撞打在 layer 2 上被判 `layer` 拒绝**、
   探路 128/198 次命中"其他层" —— 这张图的物理阻挡并不都在 layer 0。
   修法：把"可穿透层"做成掩码 `projectilePenetrableLayers`，默认**除角色/命中盒层外全部可穿**；
   同时加了 `LayerMask.LayerToName` + `Object.get_name` 诊断，启用时打印整张层名表、
   beat 里打印"探路层分布"，**从此"墙到底在哪个层"不用再猜**。
   顺带把探路射线换成 6 参 `Raycast(..., QueryTriggerInteraction.Ignore)`，避免打到 trigger 误判。
6. **`Physics.CheckSphere` 判断"还在墙里"永远为 true**：弹体自己就在 layer 0，
   CheckSphere 只看 layerMask → 改成 `OverlapSphere + attachedRigidbody 过滤自己`。
7. **永久 `IgnoreCollision` 会连地板一起忽略**：单 MeshCollider 关卡里手雷掉出地板
   → 改成"窗口 + 离开墙体即还原 + 硬上限"。
8. **`detectCollisions` 只关不还原**：对象池复用会让下一颗弹继承"什么都不碰"的状态
   → SetWeaponData / Recycle / sweep / disable / cleanup 五条路径都还原。
9. **`Interceptor.replace` 不合适**：40 的诊断探针 attach 在同一批地址上，replace 会抢控制流，
   而且 replace 后要自己回 call 原函数，异常路径更危险 → 用"attach + 临时改字段"。
10. **忽略失败必须补，不能"算了"（v3 实测"卡墙减速"的根因）**：bool/层都修对之后，
    日志显示"穿墙正常"，但玩家反馈**穿墙时明显变慢、卡住、到最后悬在空中才自爆**。
    实测日志（17:56 局）给出链条：
    `反查弹体自身 collider 失败` → `忽略=0对`（**采样 84 条里 38 条，约 45%**）
    → 同一面 layer 2 的墙 2.3 秒内连撞 14 次 → 游戏原版每次碰撞
    `velocity *= 0.6`（常量在 `0x10BAC054`）→ 卡在墙里
    → 撞墙爆炸被我们按设计抑制 → 只能等 `lifeTime`(2.0s) 到点 `OnLifeTimerEnd → TryExplosion` 原地炸。
    **教训一：`Physics.OverlapSphere` 这类"在物理步中途做的查询"结果不可靠，
    能用碰撞数据本身（`Collision` 的接触点实例 ID）就不要用查询。**
    **教训二：判断一个"阻止型"操作是否成功，不能只看它有没有被调用，
    要看"失败之后会发生什么" —— 忽略失败必须补，否则失败会被物理引擎放大成可见故障。**
    **教训三：日志限频会把故障率藏掉（45% 的失败只露出 19 条警告），
    关键计数必须进 beat，而不是只进 WARNING。**

### 经验教训

- 能复用原版逻辑就不要重写结算；但**"复用"的前提是搞清楚原版到底怎么判定的**
  （射线掩码 vs 物理碰撞，是两种完全不同的机制）。
- 静态字段改动要**窗口化 + 成对恢复**，并用计数校验配对完整性。
- 涉及物理的开关优先选**作用域最小、可还原**的 API（单弹体的 detectCollisions），
  而不是改 layer / 碰撞矩阵这类全局状态。
- **callees 只能证明"有直接调用"，证明不了"没有虚调用"。**
- **原生返回值先验类型再用**：Frida 的 `'bool'` 不保证是 JS `true`，
  用 `===` 判定会得到"功能开着但全部判定失败"这种最像"Hook 没生效"的假象。
  同理浮点参数统一传位模式。**这类坑静态看不出来，只有把原始值+类型打出来才能一眼定位。**
- 上机前先想清楚"这次失败了我能看出是哪一步失败吗"，然后**先把诊断做进去**。
- **"操作失败"和"操作没生效"要分开设计**：忽略/还原/写字段这类动作都要有明确的失败返回值，
  并且失败必须有下一步（重试、兜底、降级），否则失败会被引擎/游戏逻辑放大成完全不同的现象
  （例如"忽略失败"最终表现成"弹体悬在空中 2 秒后原地爆炸"）。
- **限频日志只能当"存在性证据"，不能当"频率证据"**；要算比率就把计数放到 beat 汇总里。
- **引擎查询（OverlapSphere / Raycast / CheckSphere）在物理回调与物理步中途的时序不可依赖**；
  碰撞事件本身携带的数据（`Collision` 的 `m_Collider` / 接触点的 `m_ThisColliderInstanceID`）
  永远更可靠。

## 一句话总结

A 段：Hook `WPN_Gun.Damage`，本地武器进入时短窗口内把 `LM_GunShoot` 临时改为 HitBox-only、
返回后恢复，交回原版 `WeaponLogic.CheckWall` 走衰减与 wallThrough；
B 段：物理步里 `Physics.Raycast` 提前 3.5m 探路（命中非可穿透层就跳过继续往后探），
命中"墙面"（在 `projectilePenetrableLayers` 掩码内 + 法线偏水平）就用
`Physics.IgnoreCollision(弹体自身 collider, 这一面墙, true)` 只摘掉这一对碰撞，直接穿过去；
弹体自己的 collider 首选碰撞接触点里的 `m_ThisColliderInstanceID`（不用物理查询），
失败退缓存 / OverlapSphere，仍失败则把墙排队、下一物理步补忽略；真拿不到墙 collider 时才
退化成"关这一颗弹的 `detectCollisions`"。离开墙体 / 硬上限 / 回池 / 关功能时立刻还原。
碰撞回调再兜底一次（抑制 `expWhenTouchSth` + `IgnoreCollision` + 写回速度）。
全程只作用于本地玩家弹体，地板 / 他人弹体一律不动，并带 `[beat]` 汇总日志可排查。
