# 18｜方框透视（ESP Box）

**来源**：`features/18_esp_box/`（script.js，标准 RPC 适配）+ `plugins/universal_hook/`（本体 `Universal-ImGui-Hook.dll`）+ 开发素材 `05-正式功能/18-Universal-ESP盒子/Universal-Dear-ImGui-Hook/`（C++ 源码 + 失败经历.md + 问答总结.md + ESP空跑优化修改记录.md）

## 核心原理

- **一句话**：本体是注入的 C++ DLL（非 Frida JS），Hook D3D11 `Present`，在每一帧用 ImGui DrawList 把敌人/全体玩家的世界坐标经 `Camera.WorldToScreenPoint_Injected` 投影成屏幕方框并绘制，本质是“就地读取 + 覆盖渲染帧”类方案。
- **手段归类**：DLL 注入 + D3D11 Present Hook（+ kernel32 LoadLibrary Hook）+ 只读 IL2CPP 调用 + ImGui 覆盖层绘制；script.js 只是 RPC 开关适配层，真正逻辑在 C++。**不对 GameAssembly.dll 打任何内联 Hook**。

## 关键调用表（D3D11 / kernel32 Hook + GameAssembly 只读调用）

| RVA/符号 | 目标 | 手段 | 作用 |
|---|---|---|---|
| D3D11 `Present` / `ResizeBuffers` | d3d11hook | MinHook（系统 DLL） | 注入绘制帧，驱动 ESP 每帧渲染 |
| `LoadLibraryA/W` | kernel32 | MinHook（系统 DLL） | 捕获晚加载的 DirectX 后端 |
| `GameManager.Singleton.get_instance` 0x4A8170（MethodInfo 0xE1CE64） | il2cpp bridge | 直接调用 | 取 GameManager 实例 |
| 0x3F42B0 | Transform.get_position | NativeFunction 调用 | 读玩家坐标 |
| 0xAB85E0 | Collider.get_bounds_Injected | NativeFunction 调用 | 取碰撞体 AABB 边框 |
| 0x327EE0 | Camera.WorldToScreenPoint_Injected | NativeFunction 调用 | 世界→屏幕 |
| 0x328310 | Camera.get_main | NativeFunction 调用 | 取主相机 |
| 0xB400E0 | Entity.get_isDead | NativeFunction 调用 | 过滤死亡玩家 |
| 0x1D7B00 / 0xAE4950 | Entity.get_healthData / HealthData.get_rate | NativeFunction 调用 | 读血量条 |
| `HealthData` +0x08 / +0x1C / +0x30 | ObscuredInt 字段 | 直接读字段（异或解密） | 读血量剩余数值 |

> **2026-10-15 起 DLL 不再对 GameAssembly.dll 打任何 MinHook**（上表 GameAssembly 行全部是只读调用，不是 Hook）。
> 旧版曾内联挂钩 0xAFB6F0 `GameManager.OnDestroy`、0xAF5B30 `ModeBase.OnStartNewGameRound`、
> 0xAF15D0 `ModeBase_Nano.OnStartNewGameRound`、0xB33370 `Bot.Update`；其中前两者与 Frida 的
> 「自瞄」「强制决战」重复挂钩（同一段 5 字节函数头被两个内联引擎先后改写），
> 被定性为 10-11 多人生化闪退的根因。现在改用渲染帧轮询 GameManager 单例刷新会话。
> 详见 `05-正式功能/18-Universal-ESP盒子/Universal-Dear-ImGui-Hook/闪退修复-双引擎重复挂钩.md`。

## 修改的关键字段

| 偏移 | 字段 | 值/说明 |
|---|---|---|
| `GameManager_TypeInfo` 0x0E2933C → klass → static_fields(+0x5C) +0x00 | myPlayer | 本地玩家 |
| `GM_allPlayers` +0x1C / playersBL_Alive +0x24 / playersGR_Alive +0x2C | 玩家集合 | 只读取全部/存活玩家 |
| `E_team` +0x20 / `E_characterController` +0x2C | 队伍 / 角色控制器 | 敌我区分/取碰撞体 |
| `P_characterContainer` +0x58 / `P_currentCharacter` +0x5C | 身体根 / 角色模型 | 取坐标与命中箱 |
| `CM_spine/spine1/neck` +0x5C/0x60/0x64、`CM_helmet` +0x6C、`CM_hitboxes` +0x74 | 命中箱 Transform[] | 后备画框点 |
| `Arr_len` +0x0C、`Arr_data` +0x10、`List_items` +0x08、`List_size` +0x0C | IL2CPP 数组/List | 遍历结构 |

**特殊处理**：
- **安全读内存** `SafeReadMemory`：`VirtualQuery` 查 MEM_COMMIT、非 NOACCESS/GUARD、跨区越界检查，再 SEH `__try/__except` 包裹 memcpy（防 GC/回收对象崩溃）。
- **每玩家独立 SEH 保护**：`SafeDrawPlayer` 对单个玩家包 `__try`，一个坏实体不拖垮整帧。
- **位置合理性过滤** `IsSanePosition`：近零、超 ±1000、离参考点过远都丢弃。
- **Box 尺寸/宽高比钳制**：宽 ≤300、高 ≤600、宽高比 0.15–5.0、高 <4px 丢弃；过窄框补宽到 0.4×高。
- **会话轮询（2026-10-15 起，不再依赖任何 Hook）**：`RefreshSession()` 每帧经 `IL2CPPBridge::GetGameManagerInstance()` 取 GameManager 单例；桥接层缓存实例并逐次做结构校验，缓存有效时不重复调用 `SingletonGet`。实例出现/更换/消失即递增 `s_SessionEpoch` 并清缓存，重开局后自动恢复方框。
- **不再有 Bot 缓存**：旧的 `s_BotPlayers`/epoch/超时/回合冷却随 MinHook 一起移除；玩家统一来自 GameManager 的玩家容器（`allPlayers` / `playersBL` / `playersGR` / `*_Alive`），渲染时逐帧重新枚举，天然不会跨局残留。
- **不再有会话封锁位**：`s_BlockSessionRefresh` 随 OnDestroy/回合钩子一起删除；离开房间时单例结构校验失败会立刻断开会话，不继续持有旧指针。
- **渲染开关空跑优化**：ESP 关闭时不建 ImGui Frame、不遍历玩家、不查坐标（保留一次 D3D/ImGui 初始化以建立命名管道与 Hook）。
- **模块地址核对**：`IL2CPPBridge::IsGameAssemblyReady()` 每次用 `GetModuleHandleA("GameAssembly.dll")` 与缓存基址比较，防止模块重载/ASLR 后地址漂移。
- **命名管道外部控制**：`esp_box` 开关状态由外部修改器经命名管道下发，DLL 不内置菜单输入。

## 血量显示选项（2026-10-15 新增）

命名管道 `set_state` 新增两个字段（协议版本 2 → 3 引入；只显示剩余值的语义调整随协议 3 → 4 生效），由修改器「方框透视」卡片上的两个下拉框下发：

| 字段 | 取值 | 下拉框文案 | 含义 |
|---|---|---|---|
| `esp_health_mode` | 0 / 1 | 百分比 / 剩余数值 | 0 = `85%`；1 = 剩余数值 `85`（只显示当前血量，不显示上限） |
| `esp_health_display` | 0 / 1 / 2 | 仅血条 / 仅数值 / 血条和数值 | 0 = 只画血条；1 = 只画文字；2 = 血条 + 文字 |

- **剩余数值来源**：`HealthData.currentHealth / maxHealth / tempHealth`（偏移 0x08 / 0x1C / 0x30）
  都是 CodeStage AntiCheat 的 `ObscuredInt`；DLL 只做**只读解密**：
  明文 = `hiddenValue ^ currentCryptoKey`（`currentCryptoKey == 0` 时用静态密钥 `0x6C81C`），
  **不写回任何字段**。取不到剩余数值时自动退回百分比。
  `maxHealth` 只用于缺失 `rate` 时反推百分比，**不在界面上显示**（2026-10-15 调整：数值模式只显示剩余血量）。
- **渲染**：`ESPRenderer::DrawHealthOverlay()` 按 `ESPState::GetHealthMode()/GetHealthDisplay()` 分支；
  主方案（Bounds）与后备方案（固定身高）都会画。
- **配置流转**：`panel.py`（两个 CTkComboBox）→ `feature_command_service.set_config()` →
  `GameSessionManager.set_esp_health_options()` → `UniversalHookManager.set_esp_state()` → DLL。

## 作用范围

全局无区分的“所有玩家 + Bot”，绘制目标是全部可见的存活玩家。数据源是 `GameManager` 静态/实例字段（玩家列表全局共享），故可枚举房间内所有玩家，且按 `team` 相对本地玩家着敌我色。

（2026-10-15 起不再用 `Bot.Update` 钩子补充 Bot：Bot 一律走 `allPlayers` / `*_Alive` 玩家容器，彻底避免对游戏代码打内联钩子。）

## 开发历程（重点）

### 踩过的坑

1. **DLL 架构不匹配导致注入失败**
   - 一开始没考虑到：VS 编译目标平台。
   - 出问题：1.7 修复版重编译后注入失败，`LoadLibraryW` 返回 NULL；远程线程是能创建的。
   - 怎么发现：`dumpbin /headers` 显示新 DLL 是 `8664 machine (x64)`，游戏进程是 32 位（`14C machine`）。
   - 怎么修：VS 切到 `Release + Win32(x86)` 重编译，用 `dumpbin /headers` 确认 `14C` 后再注入。

2. **ESP 未开启时仍每帧空跑 ImGui**
   - 一开始没考虑到：DLL 无条件每帧建 ImGui Frame + Present Hook，即使方框关着也在跑。
   - 出问题：白耗 CPU，占用持续存在。
   - 怎么修：`Render()` 开头先查 `ESPState::IsBoxEnabled()`，关闭直接 return；再关掉 F10/内置菜单/鼠标输入 Hook 路径（源码保留），仅保留首次初始化、Present Hook、命名管道与低频 ping。

3. **GameManager 查询频率不当**
   - 一开始没考虑到：一帧内可能重复查多次单例（Render 的 RefreshSession + GetAllPlayers 各一次）。
   - 出问题：房间外每帧 `SingletonGet` 无效空查；完全不查又会导致进房后找不到新 GameManager、切房后沿用旧对象、重开局方框不恢复。
   - 怎么修：存在则缓存实例不重复查、不存在则低频重试、回合/销毁事件驱动刷新（配合 `s_BlockSessionRefresh` 防止 teardown 期间误拾旧指针）。

4. **退出房间后仅部分模式能恢复方框**
   - 一开始没考虑到：普通模式与 Nano 生化使用不同的新回合入口；早期只 Hook `ModeBase.OnStartNewGameRound`（+0xAF5B30），而 Nano 调用 `ModeBase_Nano.OnStartNewGameRound`（+0xAF15D0），不会经过普通入口。
   - 出问题：退出房间时 `GameManager.OnDestroy` 会封锁会话刷新并清除旧缓存；团队/个人竞技重开后能从普通入口解除封锁并恢复方框，但生化系列仍处于封锁状态，无法重新获取新房间的 GameManager 和玩家。
   - 原因：早期只有普通模式的新回合入口能解除 `s_BlockSessionRefresh`，Nano 生化的新回合路径无法解除封锁，后续渲染刷新也就不能重新获取新房间数据。
   - 怎么修：同时 Hook 普通与 Nano 两个新回合入口，任一真实新回合到来都解除封锁、更新 epoch 并清除旧 Bot 缓存，从而允许后续渲染路径的 `RefreshSession` 重新获取新 GameManager，再由 `GetLocalPlayer` / `GetAllPlayers` 读取当前玩家，覆盖团队、个人竞技和生化模式。

5. **双引擎重复挂钩导致闪退（P0，2026-10-11 取证）**
   - 一开始没考虑到：修改器用 Frida 内联 Hook，DLL 又用 MinHook 内联 Hook，两者会命中同一批游戏函数。
   - 出问题：2026-10-11 多人生化（终结者）补给箱拾取时 `0xC0000005/8` 执行违规，`Mode_Nano4_Terminator` 方法指针被写成游戏 GC 运行时地址；取证定性为「双引擎重复挂钩 + 内存损坏」。
   - 原因：`ModeBase.OnStartNewGameRound`(0xAF5B30) 与 `ModeBase_Nano.OnStartNewGameRound`(0xAF15D0) 同时被 Frida（自瞄 / 强制决战）和 MinHook（DLL）改写同一段 5 字节函数头，trampoline 互相覆盖，属未定义行为。
   - 怎么修：DLL 彻底删除对 GameAssembly 的所有 MinHook，会话改为渲染帧轮询单例；只保留 D3D11/kernel32 系统 DLL 上的 Hook。详见 `闪退修复-双引擎重复挂钩.md`。

### 方案迭代

- **最初（纯 Hook 拿玩家）**：只从 `GameManager.allPlayers`（+0x1C）数组枚举。问题：个别玩家/Bot 不在数组或为空，方框断。
- **中间（Bot.Update 补充，2026-10-15 已移除）**：曾 Hook `Bot.Update`(0xB33370) 把 Bot 缓存进 `s_BotPlayers` 作为补充数据源；因不能对 GameAssembly 打内联 Hook（见坑 5），该路径整体删除，Bot 回到玩家容器枚举。
- **边界框从“命中箱 Transform”到“CharacterController Bounds”**：先用命中箱 Transform[]（CM_*）+ 颈/脊/头盔补充点；后新增主法 `Collider.get_bounds_Injected`(+0x2C) 直接取 AABB 8 角投影，失败再回退命中箱法（method 1 / 2 标记）。
- **最终**：主法 Bounds + 后备命中箱，全部走 SEH 保护 + 位置/尺寸合理性过滤，配生命周期会话管理。

### 一开始没考虑到的点

- 32 位 vs 64 位编译目标——架构选错直接导致 DLL 无法注入（纯编译层面，非代码问题）。
- Unity `WorldToScreenPoint` 原点在左下，ImGui 覆盖层原点是左上，需 `screenY = clientH - screenY` 翻转；且不能用 `ScreenToClient`。
- 相机可能在初始化时取不到（进房后才创建），需每帧 `GetMainCamera()` 重试而非只初始化一次。
- GameManager 的静态指针在 OnDestroy 与真正新回合之间处于“残留”状态，渲染线程抢在 teardown 前重拾旧指针有崩溃风险。（历史做法用 `s_BlockSessionRefresh` 封锁位 + OnDestroy/回合 Hook 解决；2026-10-15 起改为每帧轮询 + 结构校验，单例校验失败即断会话，不再需要封锁位与任何游戏 Hook。）

### 经验教训

- 注入类方案先核验**目标进程位数 vs 编译架构**，注入失败先 `dumpbin /headers`。
- 只读大量 IL2CPP 对象指针时，务必**安全读（SEH + VirtualQuery）+ 合理值过滤**，把“一个坏指针拖垮整帧”变成“丢弃该实体”。
- 渲染/绘制类功能要把**开关判定前置**，关闭时不建帧、不遍历、不投影，避免空跑。
- 会话类对象（GameManager）要做**实例缓存 + 变化检测**，别每帧重复查，也别完全依赖单点获取。
- **铁律：不要和 Frida 抢同一段游戏代码。** 外部 DLL 只应对系统 DLL（D3D/kernel32）打内联 Hook，对游戏函数的刷新/事件需求优先用「渲染帧轮询 + 结构校验」实现，避免双引擎重复挂钩导致内存损坏。

## 一句话总结

用注入的 C++ DLL Hook D3D11 Present，通过 IL2CPP 桥接只读玩家/Bot 集合并投影成屏幕方框（主法 CharacterController Bounds、后备命中箱），靠 SEH 安全读、位置/尺寸过滤与渲染帧轮询会话管理压住崩溃与空跑，并按开关显示血条 / 百分比 / 剩余数值；最难的是注入后 32/64 位架构不匹配、GameManager 生命周期，以及与 Frida 的双引擎重复挂钩——最终靠「DLL 不再改写游戏代码 + 轮询会话 + 结构校验」根治闪退。
