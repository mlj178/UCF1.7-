# 13｜射速变快与连狙（Rapid Fire / 连发狙击）

来源：`features/13_speedgun/`（script.js + panel.py + launcher.py）。开发素材：`05-正式功能\13-射速变快+连狙\` 下的 `射速修改-经验总结.md`（IDA 全流程 + 两个"不立即生效"复盘）、`AAAAA-speed_gun_final.js`。

---

## 核心原理

**一句话**：在**实例化武器层（WPN_\*）**多 Hook——①每发真实射出后（`GunShoot_NoCheck.onLeave`）按**射速滑块倍率**用绝对值整体重写射击间隔闸门 `+0x110`，并同步写开火动画倍率 `+0xD0` + 调游戏原生 `AnimSpeedSetting`（SetFloat "FireSpeed"）实现双控；射击前（`GunShoot.onEnter`）只清半自动标志实现连狙。②特殊武器（RPG/AT4/榴弹枪）分别 Hook 各自的 `AnimSpeedSetting` 与 `WPN_RPG.Fire` 保证动画/射速持续生效。全程用 `isMyWeapon` 限定本地玩家。

**手段归类**：多 Hook 时序（`onEnter` 先改参数）+ 就地写字段（清 `nextAllowedShootTime`/计数/半自动标志/动画速度）。

> 关键取舍：**不打共享层**。`WeaponData_Gun` 是共享 ScriptableObject，直接改 `get_shootIntervalTime` 会作用到所有玩家；必须下移到实例化 `WPN_Gun` 层，用 `isMyWeapon` 天然区分敌我。

## 修改的关键字段

> 字段名以 Il2CppDumper dump.cs 为准（2.6 起校正）。滑块倍率 M = `fire_rate` 配置（1.0~10.0）。

| 偏移 | 字段（dump.cs 校正） | 值 |
|---|---|---|
| `WPN_Gun+0xF0` | `isSemiGun` 标志 | 写 **0**（半自动→全自动） |
| `WPN_Gun+0x110` | `nextAllowedShootTime`（射击间隔闸门，**滑块核心①**） | 每发真实射出后（`GunShoot_NoCheck.onLeave`）整体重写：**`lastShootTime(+0xFC) + base·((11-M)/10)^1.7`**（幂曲线，加速度越来越快；M=1→原速，M=9≈×0.065，M=10≈×0.019）。base：全自动枪=原间隔（`get_shootIntervalTime` 只读）；半自动/狙击枪 RPM=0 → 类型基准兜底（`isSniper`→**1.5s**，其余半自动→**0.25s**，script.js 头部常量可调）。任何异常 fail-open 写 **0**（绝不锁死） |
| `WPN_Gun+0x108` | `semiGunFireLinkState` 状态机 | 写 **0**（连狙） |
| `realData(+0xEC)+0xD0` | `fireAnimMultiplier`（开火动画倍率，**滑块核心②**） | 写 M，部署/赋予/捡枪时写 + **每发**调 `AnimSpeedSetting` 实时刷新 `SetFloat("FireSpeed", M)` |
| `realData(+0xEC)+0x1BC` | 半自动相关标志（实测清后可连狙；dump 中落在 `zoomAcion` 结构范围，命名待考） | 写 **0** |
| `RPG realData(+0xF0)+0xEC` | `reloadAnimRate` | 写 **30.0**（固定，不随滑块） |
| `RPG realData(+0xF0)+0xF0` | `fireAnimRate` | 写 **30.0**（固定，不随滑块） |

**双控分工**：全自动枪控速靠①闸门（原间隔经幂曲线缩放）；半自动/狙击枪 RPM=0，原版靠"正式开火动画挡下一发"节流，但连狙清 `isSemiGun` 后改走"临时动画"不再挡发（节拍器失效），故同样统一走①闸门 + 类型基准节奏经幂曲线缩放（狙击 1.5s / 其余半自动 0.25s）；②FireSpeed 只负责让动画观感与实际射速同步（跟手）。间隔 = 基准·((11-M)/10)^1.7：M=1 时狙击≈拉栓节奏、半自动≈手枪节奏连发，M 越大越加速（末段最快）。

**特殊处理（具体到逻辑）**：
- **先改后射**：半自动标志/状态机清零放 `onEnter`（射击前），而非 `onLeave`（射击后已晚）——这是"第一发立即生效"的关键（详见坑2）。**例外**：射速闸门 `+0x110` 必须在**真实射出后**（`GunShoot_NoCheck.onLeave`）用绝对值整体重写——`GunShoot` 按住时每帧被调（含未射出的帧），挂在它身上会每帧重复扣减；且半自动枪会被游戏写 +Inf，必须覆盖（详见坑5、坑6）。
- **身份**：`isMyWeapon(self)` 为主判据，非本地武器不动。
- **半自动绕过**：清除 `realData+0x1BC` 半自动标志，让狙击/半自动可连续射击（连狙本质）。
- **特效武器独立分支**：`getCharAnim`/`setAnimSpeed`/`AnimSpeedSetting` 按 `WPN_Gun / WPN_RPG / WPN_GrenadeGun` 分类处理，`fireAnimRate`/`reloadAnimRate` 分开写。
- **异常处理**：每个 Hook `try-catch`；可逆卸载 `detach`。
- **特殊情况记录**：赋予武器的 `Nano AT4`(WPN_RPG) 与 `FN FAL 榴弹版`(WD_GrenadeGun) 在整合包中无法做到赋予即生效，只能"**赋予两次**"触发射速（见开发历程坑3）。

## 作用范围

**仅本地玩家（人类）**：全部处理挂在 `WPN_*` 实例层并用 `isMyWeapon` 限定，bot 武器/他人不受影响。覆盖主/副武器、狙击枪（连狙）、RPG/AT4、榴弹枪（半自动绕过）。

## 开发历程（重点）

### 踩过的坑（问题 → 原因 → 解决）

1. **改共享数据层影响所有玩家**
   - 问题：在 `get_shootIntervalTime`(+0xB78EF0，`return 60/shotsPerMinute`) 返回小间隔，或用 `WeaponData_Gun` 层字段 → 改变影响所有玩家。
   - 原因：`WeaponData_Gun` 是**共享 ScriptableObject**，所有玩家的武器共享同一数据；射速本身"所有玩家相同"，改它即全局。
   - 解决：**下移到实例化 `WPN_Gun` 层**，用 `isMyWeapon` 判定本地，天然区分敌我。尽量少碰共享数据。

2. **狙击/半自动第一发不生效（onLeave 时序错误）**
   - 问题：狙击枪第一发仍原速，第二发起才加速。
   - 原因：修改逻辑写在 `GunShoot.onLeave`（函数执行后），第一发已用原始参数发射完毕。
   - 解决：**全部移到 `onEnter`**（射击前）——立即清 `+0xF0/+0x110/+0x108`、设动画、清 `realData+0x1BC` 半自动标志；`AnimSpeedSetting` 三个 Hook 也在 `onEnter`/`onLeave` 都设一遍兜底。

3. **补给箱 RPG/AT4 不立即生效**
   - 问题：从补给箱捡到 RPG 榴弹/AT4 后射速、动画不立即生效，要切枪重新 deploy 才行。
   - 原因：动画加速依赖 `WPN_RPG.AnimSpeedSetting`，但它**只在武器部署时调用**，补给箱捡武器不触发部署；且原判 `wpnClass===4` 是错的（4 是霰弹枪，不是 RPG/AT4）。
   - 解决：借鉴无限子弹，`attach WPN_RPG.Fire`(+0xB670A0)，**每次发射时**补写 `fireAnimRate(+0xF0)/reloadAnimRate(+0xEC)=10.0` 并设动画——不依赖部署时机，捡到即下次发射生效。

4. **特殊武器（Nano AT4 / FN FAL 榴弹版）赋予不生效，只能赋予两次**
   - 分析：`FAL CAMO`（普通 `WPN_Gun`，`realData+0xEC`）赋予即生效；而 `FN FAL 榴弹版`（`WD_GrenadeGun`，有枪/榴双模式和独立 `Init/AnimSpeedSetting`）、`Nano AT4`（`WPN_RPG`，`realData+0xF0`，独立 `fireAnimRate/reloadAnimRate`）机制不同、数据对象在赋予时未就绪。
   - 现状：因这类特殊武器数据对象/射速字段就绪时机晚于 Hook 触发点，整合包只能通过 **`赋予武器` 执行两次**来实现射速加快（记录为待继续研究的已知限制）。

5. **滑块初版只改 +0xD0 无效（字段性质误判，2.6 射速滑块）**
   - 问题：射速滑块第一版只同步 `realData(+0xEC)+0xD0`（原写死 10.0），拖动滑块实际射速完全不变。
   - 原因：dump.cs 证实 `+0xD0` 是 `WeaponData_Gun.fireAnimMultiplier`（**射击动画倍率，不是射速**）。真正限制射速的是 `WPN_Gun+0x110 nextAllowedShootTime` 射击间隔闸门——原脚本在 `GunShoot` 的 `onEnter/onLeave` 无条件清零，射速恒为极速（仅受帧率限制），`+0xD0` 改成多少都不影响实际射速；且 `AnimSpeedSetting` 只在部署时读取 `+0xD0`，运行中改也不会被重新应用。
   - 解决：滑块改控 `+0x110`——`onEnter` 不再清闸门；`onLeave`（游戏写完新闸门后）读原间隔（`get_shootIntervalTime` 只读调用）按倍率前移：实际间隔=原间隔/M；M=10 清零（连点即发）、M=1 完全不干预。`+0xD0` 动画倍率继续跟随滑块（部署时生效）。RPG 的 `fireAnimRate/reloadAnimRate` 保持固定 30 不联动。（此版引入新的锁死问题，见坑6 迭代。）
   - 经验：改字段前先对 dump.cs 核实字段语义；"写死清零"和"按倍率调速"是两种互斥策略，做滑块必须去掉无条件清零路径，否则任何参数化都无效。

6. **半自动枪中间档位永久锁死（+Inf 闸门 + 每帧重复扣减，2.6 射速滑块）**
   - 问题：滑块第二版（挂在 `GunShoot.onLeave` 按倍率前移闸门）下，狙击枪/半自动手枪只在 M=10 能连发，1.0~9.9 任意值只出第一发就锁死；全自动枪中间档还偏快。
   - 根因（IDA 反汇编闭环）：①连狙实现清了 `+0xF0 isSemiGun`，把半自动枪硬推进全自动路径——`GunShoot_NoCheck` 内 `if(!isSemiGun) 闸门=Time.time+60/RPM`，而半自动枪 RPM=0 → 写 **+Infinity**；②滑块逻辑读 interval 见 +Inf 被 `isFinite` 拦截直接放弃 → +Inf 无人覆盖 → `GunShoot` 门口 `闸门>当前时间` 永真 → 永久锁死（M≥9.95 分支因不读 interval 无条件清零而幸存，形成 10 与 9.9 的悬崖）；③`GunShoot` 按住时每帧被 `WPN_Gun.Update`→`GunFireChecking` 调用（含未射出的帧），onLeave 扣减每帧执行 → 全自动枪中间档被拖向帧率射速。
   - 解决：①闸门改挂 `GunShoot_NoCheck(+0xB621F0).onLeave`——只有真实射出一发才走这里，天然解决重复扣减；②改**绝对值整体重写** `闸门=lastShootTime(+0xFC)+base/M`（base 非法时兜底 0.02，后经坑7 证实不足，改为类型基准节奏），不读不依赖脏值，+Inf 必然被覆盖；③异常 fail-open 写 0（宁可回到连点即发也不锁死）；④引入 **FireSpeed 双控**：反汇编发现 `AnimSpeedSetting` 内是 `CFAnimator.SetFloat(weapon,"FireSpeed",fireAnimMultiplier(+0xD0))`——游戏原生"只缩放开火动画"通道（区别于因 TPS 抖动被注释的 `setAnimSpeed` 全局动画器倍率），每发调用后半自动/狙击枪的开火动画（即其原始射速）按 M 缩放，M=1 即原枪节奏。（④的前提判断有误，见坑7。）
   - 经验：给"原版不走某字段的武器"打开该字段路径时（半自动→全自动），要预想该字段在它身上的脏值（RPM=0→Inf）并主动覆盖；调速逻辑挂在"必然对应真实事件"的函数（NoCheck=射出一发）而非"高频轮询"函数（GunShoot=每帧），避免副作用按帧累积；fail-open 优于 fail-safe——锁死玩家武器比放行一发更伤体验。

7. **半自动/狙击枪滑块仍极速（原版节拍器被连狙绕过，2.6 射速滑块）**
   - 问题：坑6 双控版下，狙击/半自动手枪任何档位都接近极速，滑块形同虚设（全自动枪正常）。
   - 根因：这两类枪 RPM=0，原版射速限制是"**正式开火动画播放期间不许射下一发**"；连狙清 `isSemiGun` 后走全自动路径，开火改用 `PlayTempAnim` 临时动画——临时动画**不挡下一发**，节拍器失效；兜底 0.02s 等于没有（间隔=0.02/M≈帧率极速）。FireSpeed=M 只改动画观感，不产生任何节流。反汇编依据：`GunShoot_NoCheck` 尾部全自动分支才播 `prefire/fire` 临时动画，半自动分支播正式动画并靠 `semiGunFireLinkState` 状态机挡发。
   - 解决（方案A，用户拍板）：保留现架构，闸门公式对 RPM 无效的枪改用**类型基准节奏**并经幂曲线 `((11-M)/10)^1.7` 缩放——`isSniperFn(+0xB63AE0，只读 wpnClass==1，不受清除字段影响)` 为真取 1.5s（拉栓节奏），否则 0.25s（手枪节奏）。M=1 狙击≈原拉栓节奏、手枪≈0.25s/发；偏快/偏慢调 script.js 头部 `SEMI_BASE_SNIPER/SEMI_BASE_DEFAULT` 两个常量即可。
   - 备选（方案B，未采用）：不清 `isSemiGun`、只清状态机，保留"正式动画挡发"原生节拍器，FireSpeed=M 缩放动画即缩放节奏——M=1 手感最正、免标定，但连狙链路需重新验证，改动面大。
   - 经验：给武器"打开原版不走的数据路径"时，必须先问它**原版靠什么节流**——绕过 A 机制（动画挡发）后若 B 机制（闸门）对它是空值，就等于完全无节流；兜底值必须取**业务量级**（秒级射击节奏），不能用**技术量级**（帧间隔 0.02s）；"动画即节拍器"的前提是动画真的挡发（临时动画不挡）。

### 方案迭代

1. **方案A（共享层源头 `get_shootIntervalTime`）**：在射速计算源头返回小间隔 → 命中共享 ScriptableObject，影响所有玩家、且只作用于全自动武器、半自动不走此路径 → **弃用**。
2. **方案B（实例层多 Hook，最终采用）**：`GunShoot.onEnter` 清间隔/计数/半自动 + 动画加速 + 特殊武器 `Fire` 补写。优点：按玩家独立、支持连狙、第一发生效、特殊武器有兜底。代价：Hook 点多、需按武器类分门别类。

### 一开始没考虑到的点

- **共享 ScriptableObject 不能改**（改即全局），要找实例化层。
- **`onEnter` vs `onLeave`**：要在射击前改参数，`onLeave` 已晚（第一发不生效）。
- **半自动武器有独立状态机**（`semiGunFireLinkState`），要单独清标志才能连狙。
- **RPG/AT4/榴弹枪是不同类**（`WPN_RPG`/`WPN_GrenadeGun`），各有独立 `AnimSpeedSetting`/`fireAnimRate`/`reloadAnimRate`，不能套用 `WPN_Gun`。
- **补给箱捡武器不触发部署** → 不能依赖 `deploy` 时机，要挂在 `Fire` 每发补写。
- **特殊武器数据对象就绪时机晚** → "赋予两次"这类变通。

### 经验教训

- **改实例层而非共享层**，防止功能影响所有玩家。
- **时序敏感的操作（射击前参数）放 `onEnter`**，先改后射。
- **连狙/加速要多点协同**：射速间隔、动画速度、半自动状态、特殊武器动画字段，各管一段。
- **不同武器类和/数据层分开 Hook**，别用一个 `wpnClass` 一刀切（`wpnClass===4` 踩过坑）。
- **不依赖一次性初始化时机**，把保证逻辑挂到高频/必然触发的点（`Fire`）。

## 一句话总结

射速滑块核心是"`GunShoot_NoCheck.onLeave` 闸门重写 + FireSpeed 观感同步"：`GunShoot.onEnter`(+0xB624C0) 清 `+0xF0 isSemiGun`/`+0x108 semiGunFireLinkState`/半自动标志 `realData+0x1BC` 实现连狙；每发真实射出后在 `GunShoot_NoCheck`(+0xB621F0) 的 onLeave 用绝对值重写闸门 `+0x110 = lastShootTime(+0xFC) + base·((11-M)/10)^1.7`（**幂曲线：加速度越来越快**，M=1→原速、M=9≈×0.065、M=10≈×0.019；base：全自动枪=`get_shootIntervalTime`(+0xB78EF0) 只读，半自动/狙击枪 RPM=0 且其原版节拍器"正式动画挡发"已被连狙绕过 → `get_isSniper`(+0xB63AE0) 区分狙击 1.5s/其余 0.25s 类型基准；异常 fail-open 写 0），并写 `realData+0xD0=M` + 调原生 `AnimSpeedSetting`(+0xB60B00, SetFloat "FireSpeed") 同步动画观感——全自动枪原间隔经幂曲线缩放、半自动/狙击枪基准节奏经幂曲线缩放，一个滑块全枪型生效；RPG/AT4 用 `WPN_RPG.Fire`(+0xB670A0) 每发补写固定 30 的 `fireAnimRate/reloadAnimRate`；踩坑是共享 `WeaponData_Gun` 不能改、`onLeave` 晚了第一发、`wpnClass===4` 误判、`+0xD0` 是动画倍率不是射速、半自动枪 +Inf 闸门锁死 + `GunShoot` 每帧重复扣减（闸门逻辑必须挂"射出一发"的 NoCheck），以及**临时动画不挡发→兜底必须取业务量级的类型基准节奏（0.02s 帧量级=没有兜底）**；特殊武器需"赋予两次"（已知限制）。
