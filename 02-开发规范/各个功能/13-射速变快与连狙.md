# 13｜射速变快与连狙（Rapid Fire / 连发狙击）

来源：`features/13_speedgun/`（script.js + panel.py + launcher.py）。开发素材：`05-正式功能\13-射速变快+连狙\` 下的 `射速修改-经验总结.md`（IDA 全流程 + 两个"不立即生效"复盘）、`AAAAA-speed_gun_final.js`。

---

## 核心原理

**一句话**：在**实例化武器层（WPN_\*）**多 Hook——①每次射击前（`GunShoot.onEnter`）清零射击间隔/计数/半自动标志并设动画速度，实现"射速加快 + 半自动连发(连狙)"；②特殊武器（RPG/AT4/榴弹枪）分别 Hook 各自的 `AnimSpeedSetting` 与 `WPN_RPG.Fire` 保证动画/射速持续生效。全程用 `isMyWeapon` 限定本地玩家。

**手段归类**：多 Hook 时序（`onEnter` 先改参数）+ 就地写字段（清 `nextAllowedShootTime`/计数/半自动标志/动画速度）。

> 关键取舍：**不打共享层**。`WeaponData_Gun` 是共享 ScriptableObject，直接改 `get_shootIntervalTime` 会作用到所有玩家；必须下移到实例化 `WPN_Gun` 层，用 `isMyWeapon` 天然区分敌我。

## 修改的关键字段

| 偏移 | 字段 | 值 |
|---|---|---|
| `WPN_Gun+0xF0` | 射击标志 | 写 **0**（清除） |
| `WPN_Gun+0x110` | `nextAllowedShootTime`（射击间隔） | 写 **0.0**（连射） |
| `WPN_Gun+0x108` | 射击计数 | 写 **0** |
| `realData(+0xEC)+0x1BC` | 半自动标志（semiGunFireLinkState） | 写 **0**（连狙） |
| 动画 | `setAnimSpeed(anim, 10.0)` | 写 **10.0**（动画提速） |
| `RPG realData(+0xF0)+0xEC` | `reloadAnimRate` | 写 **10.0** |
| `RPG realData(+0xF0)+0xF0` | `fireAnimRate` | 写 **10.0** |

**特殊处理（具体到逻辑）**：
- **先改后射**：所有修改放 `onEnter`（射击前），而非 `onLeave`（射击后已晚）——这是"第一发立即生效"的关键（详见坑2）。
- **身份**：`isMyWeapon(self)` 为主判据，非本地武器不动。
- **半自动绕过**：清除 `realData+0x1BC` 半自动标志，让狙击/半自动可连续射击（连狙本质）。
- **特效武器独立分支**：`getCharAnim`/`setAnimSpeed`/`AnimSpeedSetting` 按 `WPN_Gun / WPN_RPG / WPN_GrenadeGun` 分类处理，`fireAnimRate`/`reloadAnimRate` 分开写。
- **异常处理**：每个 Hook `try-catch`；可逆卸载 `detach`。
- **特殊情况记录**：赋予武器的 `Nano AT4`(WPN_RPG) 与 `FN FAL 榴弹版`(WD_GrenadeGun) 在整合包中无法做到赋予即生效，只能"**赋予两次**"触发射速（见开发历程坑3）。

## 作用范围

**仅本地玩家（人类）**：全部处理挂在 `WPN_*` 实例层并用 `isMyWeapon` 限定，bot 武器/他人不受影响。覆盖主/副武器、狙击枪（连狙）、RPG/AT4、榴弹枪（半自动绕过）。

## 开发历程（重点）

### 踩过的坑（问题 → 原因 → 解决）

1. **改共享数据层影响所有玩家**
   - 问题：在 `get_shootIntervalTime`(+0xB78EF0，`return 60/shotsPerMinute`) 返回小间隔，或用 `WeaponData_Gun` 层字段 → 改变影响所有玩家。
   - 原因：`WeaponData_Gun` 是**共享 ScriptableObject**，所有玩家的武器共享同一数据；射速本身"所有玩家相同"，改它即全局。
   - 解决：**下移到实例化 `WPN_Gun` 层**，用 `isMyWeapon` 判定本地，天然区分敌我。尽量少碰共享数据。

2. **狙击/半自动第一发不生效（onLeave 时序错误）**
   - 问题：狙击枪第一发仍原速，第二发起才加速。
   - 原因：修改逻辑写在 `GunShoot.onLeave`（函数执行后），第一发已用原始参数发射完毕。
   - 解决：**全部移到 `onEnter`**（射击前）——立即清 `+0xF0/+0x110/+0x108`、设动画、清 `realData+0x1BC` 半自动标志；`AnimSpeedSetting` 三个 Hook 也在 `onEnter`/`onLeave` 都设一遍兜底。

3. **补给箱 RPG/AT4 不立即生效**
   - 问题：从补给箱捡到 RPG 榴弹/AT4 后射速、动画不立即生效，要切枪重新 deploy 才行。
   - 原因：动画加速依赖 `WPN_RPG.AnimSpeedSetting`，但它**只在武器部署时调用**，补给箱捡武器不触发部署；且原判 `wpnClass===4` 是错的（4 是霰弹枪，不是 RPG/AT4）。
   - 解决：借鉴无限子弹，`attach WPN_RPG.Fire`(+0xB670A0)，**每次发射时**补写 `fireAnimRate(+0xF0)/reloadAnimRate(+0xEC)=10.0` 并设动画——不依赖部署时机，捡到即下次发射生效。

4. **特殊武器（Nano AT4 / FN FAL 榴弹版）赋予不生效，只能赋予两次**
   - 分析：`FAL CAMO`（普通 `WPN_Gun`，`realData+0xEC`）赋予即生效；而 `FN FAL 榴弹版`（`WD_GrenadeGun`，有枪/榴双模式和独立 `Init/AnimSpeedSetting`）、`Nano AT4`（`WPN_RPG`，`realData+0xF0`，独立 `fireAnimRate/reloadAnimRate`）机制不同、数据对象在赋予时未就绪。
   - 现状：因这类特殊武器数据对象/射速字段就绪时机晚于 Hook 触发点，整合包只能通过 **`赋予武器` 执行两次**来实现射速加快（记录为待继续研究的已知限制）。

### 方案迭代

1. **方案A（共享层源头 `get_shootIntervalTime`）**：在射速计算源头返回小间隔 → 命中共享 ScriptableObject，影响所有玩家、且只作用于全自动武器、半自动不走此路径 → **弃用**。
2. **方案B（实例层多 Hook，最终采用）**：`GunShoot.onEnter` 清间隔/计数/半自动 + 动画加速 + 特殊武器 `Fire` 补写。优点：按玩家独立、支持连狙、第一发生效、特殊武器有兜底。代价：Hook 点多、需按武器类分门别类。

### 一开始没考虑到的点

- **共享 ScriptableObject 不能改**（改即全局），要找实例化层。
- **`onEnter` vs `onLeave`**：要在射击前改参数，`onLeave` 已晚（第一发不生效）。
- **半自动武器有独立状态机**（`semiGunFireLinkState`），要单独清标志才能连狙。
- **RPG/AT4/榴弹枪是不同类**（`WPN_RPG`/`WPN_GrenadeGun`），各有独立 `AnimSpeedSetting`/`fireAnimRate`/`reloadAnimRate`，不能套用 `WPN_Gun`。
- **补给箱捡武器不触发部署** → 不能依赖 `deploy` 时机，要挂在 `Fire` 每发补写。
- **特殊武器数据对象就绪时机晚** → "赋予两次"这类变通。

### 经验教训

- **改实例层而非共享层**，防止功能影响所有玩家。
- **时序敏感的操作（射击前参数）放 `onEnter`**，先改后射。
- **连狙/加速要多点协同**：射速间隔、动画速度、半自动状态、特殊武器动画字段，各管一段。
- **不同武器类和/数据层分开 Hook**，别用一个 `wpnClass` 一刀切（`wpnClass===4` 踩过坑）。
- **不依赖一次性初始化时机**，把保证逻辑挂到高频/必然触发的点（`Fire`）。

## 一句话总结

射速加快与连狙核心是"实例化层多 Hook、先改后射"：`GunShoot.onEnter`(+0xB624C0) 清 `+0xF0/+0x110/+0x108` 与半自动标志 `realData+0x1BC` 实现连射连狙，`WPN_Gun/RPG/GrenadeGun` 三个 `AnimSpeedSetting`(+0xB60B00/0xB66CA0/0xB5F7A0) 设动画 10x，`WPN_RPG.Fire`(+0xB670A0) 每发补写 `fireAnimRate/reloadAnimRate` 解决补给箱不生效；踩坑是共享 `WeaponData_Gun` 不能改、`onLeave` 晚了第一发、`wpnClass===4` 误判，以及特殊武器需"赋予两次"（已知限制）。
