# 37｜增加防化服（Nano Cloth）

**来源**：`04-正式发行版/全功能整合包2.7/game_modifier/features/37_nano_cloth/`（script.js + manifest.json + panel.py + status_monitor.py）

> 本文以**整合包 2.7** 的代码为准。`05-正式功能/37-增加防化服/` 只保留单功能阶段的开发素材，不作为实现依据。

## 核心原理

- **一句话**：复用游戏自己"捡补给箱加防化服"的原生方法 `Player.AddNanoClothCount(count)`，每点一次加 N 件、可无限累计；应用对象可选"仅本地玩家"或"全体人类"；回合边界把"不是游戏原生拥有"的防化服清零，避免越叠越多。
- **手段归类**：一次性动作 + 主线程排水（RPC 只置 pending，`Player.Update` 里执行原生调用）+ 回合边界 Hook 做清零。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 符号 | 手段 | 作用 |
|---|---|---|---|
| 0x00B551D0 | `Player.Update` | Interceptor.attach | 主线程排水口；`all_humans` 也在这里执行 |
| 0x00B55FD0 | `Player.get_isMyPlayer` | NativeFunction | `local_player` 模式认定本地玩家 |
| 0x00B56050 | `Player.get_isNanoGhost` | NativeFunction | `all_humans` 排除生化幽灵 / 终结者 |
| 0x00B4FA00 | `Player.AddNanoClothCount(int count)` | NativeFunction | 累加防化服（内部加密累加 + 刷新 HUD） |
| 0x00B533A0 | `Player.SetNanoClothCount(int count)` | NativeFunction | 回合边界把数量写回 0 用 |
| 0x00AFAA40 | `GameManager.GameRoundEnd` | Interceptor.attach | 回合结束清理 |
| 0x00AEBCB0 | `GameManager.NewGameRoundStart` | Interceptor.attach | 新回合开始清理 |
| 0x00AEBD40 | `GameManager.OnDestroy` | Interceptor.attach | 房间销毁时复位内部记录 |

## 修改的关键字段

| 偏移 | 字段 | 说明 |
|---|---|---|
| Player +0xE4 | `nanoClothCount` | `ObscuredInt`：key@+0x00、hiddenValue@+0x04、inited@+0x08，真实值 = `hiddenValue ^ currentCryptoKey`；**只读**用于状态显示 |
| Player +0x94 | `clientData` | `ClientData.haveNanoCloth`（+0x2C）标记"这件防化服是游戏自己发的" |
| GameManager +0x1C | `allPlayers` | `all_humans` 遍历对象（数组长度 +0x0C、items +0x10） |

**特殊处理**：
- **两种应用对象**：`local_player` 先校验 `get_isMyPlayer`；`all_humans` 遍历全体玩家，用 `get_isNanoGhost` 排除幽灵/终结者（本地玩家也在其中）。
- **回合边界清零**：只清 `haveNanoCloth == false`（即"我们额外加出来的"）的防化服，含本地玩家；游戏自己发过的人类保持原样，出生时由游戏重置为 1。
- **HUD 封顶**：游戏原生数字贴图只有 3 张（`min(3, count)`），超过 3 件时判定值真实生效并继续累计，界面数字按游戏规则封顶显示。
- **状态轮询单链**：`status_monitor.py` 停止时必须 `after_cancel`，否则重连后会出现两条 status 轮询链（P0 修过）。

## 作用范围

只影响防化服数量：不写血量、不改伤害、不改阵营。`local_player` 只给本地玩家；`all_humans` 给所有人类（不含生化幽灵/终结者）。跨回合不叠加，退出房间自然清空。

## 产品设计巧思

- 复用原生 `AddNanoClothCount` 而不是自己 XOR 写 `ObscuredInt`：加密、上限、HUD 刷新全都由游戏负责。
- "全体人类"只按 `isNanoGhost` 反选，天然不会把防化服加到幽灵身上。
- 回合结束自动清零，避免"越玩越厚"破坏平衡，用户不用记着手动还原。
- 卡片上直接显示当前防化服数量（走 status 轮询），加没加一眼能看到。

## 开发历程（重点）

### 踩过的坑

1. **加密字段不能直写**
   - 一开始没考虑到：`nanoClothCount` 是 `ObscuredInt`。
   - 出问题：直接写偏移会破坏 `key/hiddenValue` 结构，游戏读到脏值，HUD 乱跳。
   - 怎么修：只读（解密用于显示），写一律走 `AddNanoClothCount`。

2. **跨回合越叠越多**
   - 出问题：加出来的防化服不属于"游戏发的"，回合切换不会自动重置，几局下来数量离谱。
   - 怎么修：Hook `GameRoundEnd` / `NewGameRoundStart`，把 `haveNanoCloth == false` 的玩家写回 0；游戏自己发的不动。

3. **状态轮询在断线重连后变两条**
   - 出问题：`stop()` 只丢句柄不 `after_cancel`，重连后旧回调又排一条链，出现双倍 status RPC，句柄被覆盖后再也取消不掉。
   - 怎么修（2.7 P0）：按 `10_roundskip/monitor.py` 的写法，停止时取消挂起的 `after`。

### 方案迭代

- **早期（自己写数量）**：直接改 `ObscuredInt`。缺点：要自己维护 key，HUD 不刷新，容易和游戏结算打架。
- **最终（原生累加 + 边界清零）**：加用 `AddNanoClothCount`，清用 `SetNanoClothCount`，读走解密只做展示。

### 经验教训

- 有"游戏原生拥有"标记的字段（`haveNanoCloth`）一定要利用起来，否则没法区分"我们加的"和"游戏发的"。
- 轮询型 UI 组件的 `stop()` 必须能把挂起的 `after` 一起取消，否则重连就是双链。

## 一句话总结

用原生 `AddNanoClothCount` 累加、`SetNanoClothCount` 在回合边界把"非原生拥有"的防化服清零，`all_humans` 用 `get_isNanoGhost` 反选人类；坑在 `ObscuredInt` 不能直写、跨回合会越叠、轮询停止没取消 after 会变双链。
