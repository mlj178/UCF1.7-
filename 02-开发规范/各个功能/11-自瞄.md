# 11｜自瞄（Aim Assist）

来源：`features/11_aim/`（script.js + events.py + test_aim_*）。开发素材：`05-正式功能\11-自瞄\` 下的 `自瞄经验总结.md`（内部流 vs 外部流选型）、`自瞄-Physics可见性打空气问题复盘.md`（核心 bug 复盘）。

---

## 核心原理

**一句话**：**内部流（DLL）方案**，双通道作用在本地玩家视角上——①读相机旋转/位置，对目标胸部点计算所需偏转，用 `Player_AddCameraRotation` 直接改本地相机旋转逼近目标；②Hook `Recoil.GetShootRay` 把**真实子弹射线**吸附/修正到目标胸部点并做命中验证。

**手段归类**：改操作（改相机旋转）+ 改返回值（吸附射击射线）+ Physics 可见性筛选；事件驱动（相机更新 Hook）为主 + 16ms 瞄准循环定时器兜底。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 函数 | 手段 | 作用 |
|---|---|---|---|
| +0x82B750 | `Brain.PushStateToUnityCamera` | Interceptor.attach | 相机主流程，`onLeave` 缓存相机实例（扫描挂此处，替代独立高频定时器） |
| +0x82CDB0 | `Brain.get_OutputCamera` | NativeFunction | 从 Brain 取相机 transform，用于取位置/朝向 |
| +0xB4F790 | `Player.AddCameraRotation` | NativeFunction | 写本地相机视角旋转（偏转逼近目标） |
| +0xB195C0 | `Recoil.GetShootRay` | Interceptor.attach | 拿真实射击射线，`onLeave` 修正/吸附到目标胸部 + 命中验证 |
| +0xAB8C20 | `PhysicsScene.Physics_Internal_Raycast` | NativeFunction（`mscdecl` + `scheduling:'exclusive'`） | 可见性射线（选中/命中两阶段） |
| +0xAB85E0 | `Collider.get_bounds` | NativeFunction | 取目标部件包围盒中心（胸部/头盔点） |
| — | `setInterval` | 定时器（16ms） | 瞄准主循环：读当前旋转→算目标偏转→ `AddCameraRotation` |

## 修改的关键字段 / 配置

| 项 | 值 | 说明 |
|---|---|---|
| `localEyeHeight` | 1.55 | 本地视角原点高度 |
| `maxCameraPlayerDistance` | 4.0 | 相机位置与本地眼眶距离上限（判定缓存相机有效） |
| `visibilityCheck` | true | 是否启用可见性筛选 |
| `selectionVisibilityQueryTriggerInteraction` | 1（Ignore） | 目标筛选：忽略 trigger（只看环境/水面阻挡） |
| `shotVisibilityQueryTriggerInteraction` | 2（Collide） | 开枪命中验证：允许 hitbox 触发器参与 |
| `visibilityHitBoxLayer` | 3 | 命中可击中层（HitBox） |
| `AIRaycast` 结果 | `no_shootable_hitbox` 即跳过修正 | 命中验证失败不吸附，避免打空气修正 |

**特殊处理（具体到逻辑）**：
- **Physics `NativeFunction` 用 `scheduling:'exclusive'`**：防止与射击流程的 Physics 查询交叉重入。
- **每次扫描/每次开枪创建独立 scratch buffer**（`createPhysicsScratch`），`resolveRaycastHit` 只读本次结果，**不跨流程共用全局缓冲区**。
- **扫描频率 30ms 节流**，但**挂相机更新 Hook（+0x82B750）**执行，而非独立 `setInterval` 硬扫。
- 相机缓存带有效期判定（`cameraCacheMaxAgeMs` + `maxCameraPlayerDistance`）。
- 仅改准星/方向、命中验证；不改伤害流程。
- 可逆卸载：`handle.detach()`。

## 作用范围

**仅本地玩家（人类）**：作用对象是本地玩家的相机旋转与本地发射的真实射线，属于**玩家私有**的视角状态；bot/他人视角不受影响。不修改任何伤害数值。

## 开发历程（重点）

### 踩过的坑（问题 → 原因 → 解决）

1. **选型：内部流 vs 外部流**
   - 问题：自瞄能做"改数据（内部 DLL）"或"改操作（外部 Overlay 模拟鼠标/屏幕坐标）"，选错方向差异大。
   - 对比：内部流改内存/寄存器，引擎内部上帝视角、几乎不掉帧，但需逆向找 RVA、隐蔽性低；外部流模拟鼠标/像素、纯黑盒只读较隐蔽，但要截图绘制、性能一般。
   - 决策：本项目用**内部流 DLL**（契合集成包，性能优先），代价是 RVA 需逆向维护。

2. **个人竞技没有阵营，早期版本自瞄失效（v1.5 修复）**
   - 问题：v1.4 的自瞄在有阵营的模式中可用，但进入个人竞技后无效。
   - 来源结论：v1.4 更新说明将该失效现象归因于个人竞技没有阵营；更新说明没有披露更具体的 Hook、过滤条件或筛选实现，因此这里只记录行为演进，不反推底层代码。
   - 解决：v1.5 优化自瞄并确认支持个人竞技模式，v1.6 的保留功能说明继续确认其支持无阵营模式。

3. **v2.2 只转镜头，准星对准但不保证真实命中**
   - 问题：v2.2 主要通过修改相机旋转让镜头对准敌人，但没有同步修正真实射击射线，因此准星视觉上对准不等于子弹真正命中。
   - 伴随问题：目标部位按固定高度偏移取点、遮挡判断较简单、视角范围只有 30°、会抢玩家手动转镜头的操作，且目标容易反复切换。
   - 解决（v2.3 重做）：Hook `Recoil.GetShootRay` 重定向真实射击射线；读取敌人真实头部/胸部骨骼并结合头盔碰撞体取点；使用 Physics 射线判断墙体遮挡；将视角范围扩大到 60°并加入距离判断；检测到玩家手动转镜头时暂停自瞄；增加目标保持与切换判定，降低乱跳。
   - 经验：完整自瞄需要同时处理镜头、真实射击射线、目标点、遮挡、玩家输入和锁定稳定性；只修改相机旋转只能解决视觉对准，不能形成完整命中链路。

4. **Physics 可见性打空气（核心 bug，整合包 2.3）**
   - 问题：开启自瞄后部分可见敌人**打不掉血**，关闭可见性筛选则正常。
   - 根因（逐步定位）：不是胸部坐标、也不是角度计算问题，而是 **Physics 可见性检测与射击射线共用同一批 native 缓冲区，Unity Physics 查询互相污染**：
     1. 目标扫描用独立 `setInterval` 每 30ms 调一次 Unity Physics Raycast；
     2. 开枪 `Recoil.GetShootRay` Hook 里也调 Physics Raycast；
     3. 两者共用 `physicsSceneBuffer`/`visibilityRayBuffer`/`visibilityHitBuffer`；
     4. `NativeFunction` 默认调度可能释放 JS 锁，两个 Physics 调用交叉执行；
     5. 缓冲区被覆盖 → 筛选/射击修正拿到错误 hit → 打空气。
   - 解决（保留可见性、降低副作用）：目标扫描移到相机更新 Hook 后跑（30ms 节流）；Physics NativeFunction 改 `scheduling:'exclusive'`；每次扫描/开枪**各自创建 scratch buffer**；目标筛选只检测环境阻挡（`Ignore` 触发器），开枪命中验证允许 HitBox 触发器（`Collide`）。

### 方案迭代

1. **2.2 老方案**：未默认开可见性、无重 Physics 射线筛选 → 无"打空气"但不挡墙后目标。
2. **2.3 加可见性**：开启 Physics 可见性 → 挡墙后目标，但**引入缓冲区交叉污染 → 打空气**。
3. **修复版（当前）**：可见性保留，但"事件驱动（相机 Hook）+ exclusive 调度 + 每调用 scratch buffer + 筛选/命中分配置（Ignore 看墙 / Collide 看 hitbox）" → 既挡墙后目标又不污染、不打空气。

### 一开始没考虑到的点

- **native 返回结构体/RaycastHit/Ray 的 buffer 不能在多个流程共用**：一旦与射击流程交叉，筛选与修正全错。
- **Physics `NativeFunction` 默认调度可重入**：需显式 `scheduling:'exclusive'`。
- **目标筛选与开枪命中要分开配置**：筛选看墙（Ignore 触发器），开枪看 hitbox（Collide 触发器），不能混用一个 TriggerInteraction。
- **不要过度依赖 Physics 结果一票否决**：可见性只能做辅助，别让单个 Raycast 结果直接判死刑。
- **独立的 30ms 扫描定时器不贴合游戏主流程**：应挂相机更新 Hook 附近跑，减少调度偏差。

### 经验教训

- **自瞄只该改准星/射击方向，不改原版伤害流程**。
- **Unity Physics 查询尽量放游戏主流程附近执行**，别用高频独立定时器乱扫。
- **涉及返回结构体/RaycastHit 的 native 调用，杜绝跨流程共享同一内存块**。
- **Physics 调度用 `exclusive` 防重入**，是低成本的稳定手段。

## 一句话总结

内部流（DLL）自瞄：`Brain.PushStateToUnityCamera`(+0x82B750，相机 hook) 驱动目标扫描 + 16ms 瞄准循环用 `Player_AddCameraRotation`(+0xB4F790) 改本地相机旋转，`Recoil.GetShootRay`(+0xB195C0) 吸附真实射线并命中验证；踩的深坑是可见性 Physics 用共享 native 缓冲区与射击流程交叉污染导致"打空气"，用 exclusive 调度 + 每调用 scratch buffer + Ignore/Collide 分离筛选与命中共修。
