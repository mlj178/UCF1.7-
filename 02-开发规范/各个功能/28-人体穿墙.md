# 28｜人体穿墙（Wall Noclip）

**来源**：`features/28_wall_noclip/`（script.js）+ 开发素材 `05-正式功能/28-人体穿墙/穿墙-简要说明.md`

## 核心原理

- **一句话**：Hook `UnityEngine.CharacterController.Move`，只在“功能开启 + 按住 Alt”时，于 `onEnter` 记录 Move 前位置与栈上的原始水平位移（x/z），`onLeave` 把最终位置 x/z 改写成“Move 前位置 + 原始水平位移”，y 保留原游戏 Move 的结果，从而绕过墙体对水平移动的阻挡、但不破坏重力/落地，本质是“就地改写 Move 结果”类方案。
- **手段归类**：Hook 移动物理函数（onEnter 记录 + onLeave 改写结果）+ WinAPI 键盘输入（GetAsyncKeyState 判断 Alt）+ Transform get/set_position NativeFunction。

## 关键 Hook 表（GameAssembly.dll / user32.dll）

| RVA | 符号 | 手段 | 作用 |
|---|---|---|---|
| 0xAB8210 | UnityEngine.CharacterController.Move | Interceptor.attach(onEnter/onLeave) | 穿墙核心：记录位移、改写 x/z |
| 0xB50A00 | Player.MoveByLocalDirection | attach | 捕获本地 Player 与其 CharacterController |
| 0xB55FD0 | Player.get_isMyPlayer | NativeFunction | 确认只处理本地玩家 |
| 0x32CF40 | Component.get_transform | NativeFunction | 取 Transform |
| 0x3F4280 / 0x3F4810 | Transform.get_position / set_position_Injected | NativeFunction | 读 Move 前位置 / 写最终位置 |
| user32.dll GetAsyncKeyState | （导出） | NativeFunction | 读 Alt（VK_MENU=0x12）是否按下 |

## 修改的关键字段

| 偏移 | 字段 | 值/说明 |
|---|---|---|
| Player +0x2C | characterController | 读取本地玩家 CharacterController |
| 最终 Transform.position | x / z | 改写为“Move 前位置 + 原始水平位移” |
| 最终 Transform.position | y | 保留原游戏 Move 结果（不飞天/不悬空） |

**特殊处理**：
- **双门控**：功能开启（Runtime.enabled）且按住 Alt（GetAsyncKeyState 高电平）才执行穿墙改写，否则原样返回保留碰撞。
- **不修改 Move 入参**：让原游戏正常处理重力、落地和垂直方向，只对结果做水平补偿。
- **身份校验**：`Move` 的 this 必须是指向本地玩家 controller 才处理，Bot/他人不受影响。
- **架构校验**：只支持 32 位（ia32 且 pointerSize==4），否则拒绝。
- **可逆卸载**：disable 时 detach hooks、清缓存，恢复游戏原生碰撞。

## 作用范围

仅本地玩家（且仅按住 Alt 时）。不提供上升/下降控制；不改 Bot、不改地图、不改 Entity layer；关闭功能或松开 Alt 后墙体恢复阻挡。

## 产品设计巧思

- 按住 Alt 才穿墙，日常移动完全不受影响，想穿就穿、松开即恢复，误触率低。
- 只绕水平方向，垂直方向仍按游戏物理（跳/落正常），不会做成飞天或卡在天上。
- 一键开关 + 可逆卸载，进/出房重新捕获本地玩家，切房后无需重开。

## 开发历程（重点）

### 踩过的坑

1. **开启后 WSAD 被固定在原地**
   - 一开始没考虑到：如果在 `Move` 执行前写坐标，并把 `motion.x/z` 清零，后续原始 `Move` 会用零水平位移覆盖结果。
   - 出问题：开启功能后 WASD 移动无效，角色被钉在原地。
   - 怎么修：改为 onEnter 只记录位置与原始位移、不写坐标；onLeave 在 `Move` 返回后按“Move 前位置 + 原始水平位移”写 x/z。

2. **误用 Entity.UpdateColliderLayer 导致判定错乱**
   - 一开始没考虑到：`UpdateColliderLayer` 会根据死亡/幽灵状态切换 GameObject.layer，它不是单纯的墙体碰撞开关。
   - 出问题：若用它实现穿墙，会影响受击判定、阵营显示、雷达/目标识别、地图触发器、死亡层级。
   - 怎么修：第一版不改 layer，只在本地玩家移动时处理水平位移。

3. **穿墙后抖动/卡住**
   - 一开始没考虑到：onLeave 是否真的执行、beforePosition/afterPosition 是否合理，直接影响写入质量。
   - 出问题：写入后位置抖动或卡住。
   - 怎么修：排查 onLeave 执行与位置合理性；必要时加极小水平偏移阈值或只在 x/z 非零时写入。

### 方案迭代

- **早期（改 layer 思路）**：考虑用 Entity.UpdateColliderLayer 关闭碰撞。缺点：副作用大，影响受击/阵营/雷达。
- **最终（Hook Move 结果）**：Hook `CharacterController.Move`，onEnter 记录、onLeave 改写水平结果，y 交给原游戏。缺点：没有上升/下降控制（设计上明确不做）。

### 一开始没考虑到的点

- “先写坐标再清零位移”会被原始 Move 用零水平位移覆盖，必须**在 Move 返回后改写**。
- 改碰撞层不等于穿墙，会牵连受击判定、阵营、雷达、触发器等多套系统。
- 需要区分 Move 的 this 是否本地玩家，否则会误伤 Bot/他人移动。

### 经验教训

- 位移/碰撞类功能，**优先在 Move 结果上做补偿**，而不是干预 Move 入参。
- “碰撞开关”类字段往往耦合多套系统，改前先查全引用再决定用不用。
- 事件回调里写坐标时，**先记录原始值、后改写结果**，避免被原逻辑覆盖。

## 一句话总结

Hook `CharacterController.Move`，开启 + 按住 Alt 时在 onLeave 把最终位置 x/z 改写为“Move 前位置 + 原始水平位移”、y 保留原游戏结果，绕过墙体水平阻挡且不破坏重力；踩坑集中在“先写坐标被零位移覆盖导致原地”“误用 layer 开关牵连判定”，最终以结果补偿 + Alt 双门控 + 仅本地玩家收尾。
