# 27｜游戏模式切换（Game Mode Override）

**来源**：`features/27_game_mode_override/`（script.js）+ 开发素材 `05-正式功能/27-游戏模式切换/游戏模式切换-简要说明-整合版2.2.md`

## 核心原理

- **一句话**：在房间开始流程中（`MapAsset.ApplyGameSetting` 后）覆盖 `GameManager.gameMode / gameModePrefab / weaponLimited` 三个静态字段，并同步 `ModeBase` 的胜利条件/时间/回合等规则字段，实现开局前把地图切成目标模式；个人竞技图切生化采用“先按个人竞技流程生成 Bot、再套生化模式”的延迟套用；多人生化额外补 `SupplyBox / UpgradeBox / attribute` 链路，本质是“开局静态字段覆盖 + 流程时机控制 + 资源链路补齐”类方案。
- **手段归类**：固定 RVA → TypeInfo → static_fields 指针链读写 + 生命周期 Hook（开局/生成 Bot/加玩家/取出生点/取补给点）驱动 + NativeFunction 主动调用（StartCoroutine / List<int> 构造）。

## 修改的关键字段

| 偏移 | 字段 | 值/说明 |
|---|---|---|
| GameManager +0x04 | gameMode | 目标模式（0=团队 / 2=刀 / 4=生化4 / 5=生化6 / 6=终结者） |
| GameManager +0x08 | weaponLimited | 0=不限 / 1=刀 / 2=手枪 / 3=狙 |
| GameManager +0x10 | gameModePrefab | 目标模式 prefab 指针 |
| GameManager +0x0C | revengeEnable | 团队=1 / 生化=0 |
| ModeBase +0x00 / +0x04 | targetRound / targetScore | 目标回合 / 目标分数 |
| ModeBase +0x10 | respawnTime | 3.0 秒 |
| ModeBase +0x34 / +0x38 | restGameTime_X / _Y | 剩余时间（从 MapAsset 读） |
| Mode_Nano4_Terminator +0xE0 / +0xE4 | attribute_Nano / attribute_Human | 写 ID 8（终结者出现）/ ID 18（英雄出现） |
| MapManager +0x1C~+0x30 | SP_SupplyBox / SP_RedBox / SP_BlueBox / IDList_* | 补给点数组 + 随机索引表补齐/借用 |
| MapAsset_Nano +0x00~+0x10 | GameTime_Nano4 / GameTime_Nano4Terminator / RoundDatas | 读取生化时间/回合配置 |
| MapAsset_TeamDeath +0x00~+0x10 | KillDatas / KillConditionTime / TimeDatas | 读取团队胜利条件配置 |

**特殊处理**：
- **延迟套用（个人竞技图 → 生化）**：`ApplyGameSetting.leave` 只标记延迟，不立刻改 mode；等 `GenerateBotClient.leave` 再写目标生化模式与 prefab（`AddPlayers.enter` 兜底），否则 Bot 在生化上下文里生成会被跳过。
- **出生点借用**：请求 Neutral 但 `SP_Netural` 为空时借用 `SP_BL/SP_GR`；请求 BL/GR 但数组为空时借用 `SP_Netural`；切团队/生化后把 bot 交替分到 BL/GR。
- **多人生化升级箱链路**：精确校验实例为 `Mode_Nano4_Terminator` 后写 attribute（8/18）；补 `SP_*` 并重建干净的 `List<int>` 填 `IDList_*`（`getListSize===null` 才重建，避免旧无效指针）；监听原生 `UpgrandeBoxGenerator`，未启动则按 62s/team0、91s/team1 兜底启动。
- **GetSupplyBoxPoint 参数陷阱**：其参数布局不是普通实例方法（`args[0]` 是 out SpawnPoint 临时地址，`args[1]` 才是 SupplyBox.Type），因此不在 `GetSupplyBoxPoint.enter` 覆盖 `Runtime.mapManager`，只用 Awake/GetSpawnPoint 缓存的真实对象；补点前校验 SP 字段形状（null 或类托管数组指针）。
- **规则同步条件化**：刀/狙/手枪战在个人/团队图只写 `weaponLimited` 且跳过规则同步（沿用原图胜利条件）；生化类源图切武器限制模式则先转团队规则再套限制，固定限时 12:00。
- **静态配置兜底**：读不到 MapAsset 配置时用兜底值（生化回合 9/11/13/15/17 默认 13、普通生化 2:30、终结者 3:30、团队时间 5:00/8:00/10:00/12:00 等）；Bot 发枪兜底武器索引（刀 244 / 狙 2568 / 手枪 20）。
- **高风险 Hook 不收**：未恢复死亡事件、回合结束、CheckRoundOver 等高风险 Hook，避免对局中热切换引发状态错乱。
- **可逆清理**：disable 时恢复 ModeBase 规则字段、清运行时缓存（mapManager/modeBase/defer 标记）。

## 作用范围

全房间。目标模式、武器限制、胜利条件/时间/回合作用于所有玩家与 Bot；出生点/补给点补齐属于房间级资源；本地与 Bot 无差别处理。

## 产品设计巧思

- 开局前一把切模式，覆盖团队/刀/狙击/手枪/生化 4/生化 6/终结者 7 种目标，进房即生效。
- 从任何源地图都能切：个人竞技图切团队/生化自动重分队、补出生点，不用重建房间。
- 选多人生化自动补出红/蓝升级箱链路，玩家拿到与原生一致的终结者/英雄变身体验。
- Bot 发枪自动给限制模式对应武器（刀/狙/手枪），避免 bot 首枪拿错武器。

## 开发历程（重点）

### 踩过的坑

1. **个人竞技图切生化后没有 Bot**
   - 一开始没考虑到：在 `ApplyGameSetting.leave` 立刻把 gameMode 改成生化，后续 `GenerateBotClient` 会在生化上下文运行，个人竞技图原本靠这个阶段生成 Bot 的流程被跳过。
   - 出问题：进入地图后没有 Bot。
   - 怎么修：仅对“个人竞技 `GameMode=1` → 生化 `4/5/6`”延迟套用，`ApplyGameSetting.leave` 只标记，`OnStartGameBtnDown.leave` 不消费，等 `GenerateBotClient.leave` 后写入目标生化模式，`AddPlayers.enter` 兜底；随后把 bot 交替分到 BL/GR、借 `SP_Netural`。

2. **多人生化没有专属升级箱（或只有普通补给箱）**
   - 一开始没考虑到：只切 mode 字段不够，红/蓝升级箱需要本回合 `attribute_Nano/attribute_Human` 配合；个人/团队图还缺 `SP_*`；且 `GetSupplyBoxPoint` 还要 `IDList_*` 随机索引表，只补 `SP_*` 原生生成器仍取不到点。
   - 出问题：选多人生化后没有终结者/英雄变身箱。
   - 怎么修：精确校验 `Mode_Nano4_Terminator` 实例后写 attribute（8/18），补 `SP_*` 与 `IDList_*`，并按原生延迟（62s/91s）兜底启动 `UpgrandeBoxGenerator`。

3. **红/蓝箱卡在取点阶段（SP 为 0、IDList 不可用）**
   - 一开始没考虑到：`MapManager.GetSupplyBoxPoint` 每次先随机取 IDList 索引再到 SP 取点，而日志显示取点现场 `SP_RedBox/SP_BlueBox` 数量为 0、`IDList_*` 不可用。
   - 出问题：红/蓝升级箱取不到点、不出现。
   - 怎么修：最终兜底前移到 `GetSupplyBoxPoint.enter`，每次原生取点前刷新当前 MapManager 并补齐 SP/IDList。

4. **`IDList_*` 存在“非空但无效”旧指针**
   - 一开始没考虑到：`IDList_RedBox/BlueBox` 可能是非空但不是有效 `List<int>` 的旧指针，旧逻辑只在空指针时新建列表。
   - 出问题：红/蓝索引表无法补齐。
   - 怎么修：改为 `getListSize(listPtr) === null` 时直接重建干净的 `List<int>` 并写回 `IDList_*`。

5. **`GetSupplyBoxPoint` 参数布局陷阱污染缓存**
   - 一开始没考虑到：`args[0]` 是 out `SpawnPoint` 临时地址，`args[1]` 才是 `SupplyBox.Type`；旧逻辑把 `args[0]` 写成 `Runtime.mapManager`。
   - 出问题：缓存被临时地址污染，读 SP 出现 `0x1/0x5` 这类非法指针，触发 `access violation`。
   - 怎么修：`GetSupplyBoxPoint` 不再覆盖 `Runtime.mapManager`，只用 Awake/GetSpawnPoint 缓存对象，补点前校验 SP 字段形状。

6. **团队竞技图切多人生化被“补点校验”误杀**
   - 一开始没考虑到：团队图可能本来没有 `SP_*` 但有 `SP_BL/SP_GR`，若校验把待补目标字段也当必须有效，会直接跳过补箱。
   - 出问题：团队图切多人生化补不上补给箱。
   - 怎么修：只校验可借用来源点（`SP_BL/SP_GR/SP_Netural/SP_SupplyBox`），任一有效即可补 `SP_SupplyBox/Red/Blue` 和 `IDList_*`。

### 方案迭代

- **早期（只切 mode 字段）**：改 `GameManager.gameMode/gameModePrefab/weaponLimited`。缺点：生化/个人图兼容差、没补给箱。
- **中期（加规则字段 + 延迟套用）**：补 ModeBase 规则字段、个人竞技图延迟套生化。缺点：多人生化升级箱缺失。
- **最终 v2.2（完整链路补齐）**：模式覆盖 + 规则同步 + 出生点/补给点/IDList 补齐 + attribute + UpgradeBox generator 兜底，且把取点兜底前移到 `GetSupplyBoxPoint.enter`。

### 一开始没考虑到的点

- 改 `gameMode` 的**时机**比改的值更关键——Bot 生成阶段依赖原模式上下文。
- 胜利条件/时间/回合是独立字段，切换模式必须同步它们，否则只换模式不换规则。
- 补给箱系统依赖 `SP_*` + `IDList_*` 双结构，且 IDList 可能是无效旧指针。
- IL2CPP 某些方法参数布局不是标准实例方法布局，Hook 前必须核对汇编。
- 团队/个人图缺资源时要用“可借用来源点”而非“全部字段都有效”来判定。

### 经验教训

- 模式切换类功能核心是**流程时机 + 字段覆盖 + 资源链路**三位一体，缺一不可。
- 字段校验要区分“待补字段”与“可借用来源字段”，别用同一套有效性要求。
- 对非标准参数布局的方法，**优先只读不改入参**，用已缓存对象做兜底。
- 一次成功的“看起来只改了模式”，背后需要补齐队伍/出生点/补给箱/attribute 一整条资源链。

## 一句话总结

在房间开局流程覆盖 `GameManager.gameMode/gameModePrefab/weaponLimited` 并同步 `ModeBase` 规则字段实现模式切换；个人竞技图切生化延迟到 `GenerateBotClient.leave` 套用，多人生化补 attribute/SP/IDList/UpgradeBox 链路；踩坑集中在“模式切换时机破坏 Bot 生成”“补给箱双结构缺失”“GetSupplyBoxPoint 参数布局陷阱”，最终以延迟套用 + 取点前兜底 + 完整资源链补齐收尾。
