# 40｜开火直伤 / 弹体追踪（Direct Damage）

**来源**：`04-正式发行版/全功能整合包2.7/game_modifier/features/40_direct_damage/`（script.js + manifest.json + panel.py）

> 本文以**整合包 2.7** 的代码为准。`05-正式功能/40-开火直伤/` 只保留单功能阶段的开发素材。旧的"注入版"实现（自合成伤害 + `Interceptor.replace` + 死亡兜底）已经从仓库移除，**没有保留副本**；脚本头注释里提到的 `_备份_40_direct_damage_注入版_2.7/` 目录当前不存在，不要去找它，也不要把注入链路恢复回来。

## 核心原理

- **一句话**：只改两个**输入**——常规枪械在 `WPN_Gun.Damage` 的入参里把射线方向掰向敌人；投射物在物理步末尾改写 `Rigidbody.velocity` 让它拐弯。伤害、命中、死亡、复活全部由游戏原函数跑完。
- **手段归类**：attach 改写参数 / 改写刚体速度 + 目标选择（与自瞄同一套锥形策略）。**绝不**合成伤害事件、不 `Interceptor.replace`、不跳过原函数、不接管死亡与复活。

## 修改的关键字段

| 偏移 | 字段 | 说明 |
|---|---|---|
| 玩家相机 | `Player.cameraRotation`（+0x4C yaw / +0x50 pitch） | 只读，用于算准星方向 |
| 骨骼 | `character +0x60` spine1、+0x5C spine | 目标命中点，逐级退化到"坐标 + 身高偏移" |
| 投射物 | 速度 `+0x4C`（shootSpeed）、`sprIndex` | 读速度，写 `Rigidbody.velocity` |
| Entity +0x14 / +0x18 | `damageRate`（float）/ `isInvincible`（bool） | 只在"突破复活无敌"开启时复位 |
| HealthData +0x44 | `invinsibleEndTime`（float） | 同上，结束"完全免疫" |

**特殊处理**：
- **写栈前先校验**：这 6 个数像不像一条射线（起点分量有限、方向接近单位向量），不像就一个字节都不写，让原版射线照原样跑。
- **登记前先清记录**：弹体对象池会复用指针，每次 `SetWeaponData` 先无条件清掉旧记录，避免"敌人的手雷被掰到我们的目标上"。
- **只清"完全免疫"**：`pierce_respawn_invincible` 只处理 `damageRate == 0 && isInvincible` 的复活保护，范围和数值校验都在一个小区间里，避免误清正常减伤。
- **目标策略与自瞄一致**：外锥 30° → 内锥 20° 优先 → 角度优先 → 角度差 ≤1° 时比距离 → 换目标需优势 >1.2° 且连续 1 次确认、100ms 冷却。

## 作用范围

只对**本地玩家**开火/发射生效，且只选敌对、存活目标；不改队友、不改 Bot 的属性，不写血量。四个子开关分别控制：普通枪械自动跟枪、榴弹/手雷/RPG 追踪、特殊技能弹追踪、突破复活无敌。锥内没人时枪械默认不回退（可选近距保底），投射物默认回退最近。

## 产品设计巧思

- "只改输入"是这一版的核心取舍：原函数一行不改地跑完，击杀提示、死亡广播、复活计时全是游戏自己的代码，从根上消掉"扣了血但躺尸不复活"。
- 四个子开关让用户按需取舍：只想准一点就只开枪械，不想要爆炸拐弯就关掉对应项。
- 目标选择直接复用自瞄那套参数与手感，两个功能同时开时不会互相抢目标。

## 开发历程（重点）

### 踩过的坑

1. **旧注入版：自己合成伤害 + 跳过原函数**
   - 一开始没考虑到：原版链路是"射线 → `WPN_Gun.Damage` 内 RaycastAll → 构造伤害事件 → 结算 → `DeathEventBroadcast` → 模式记账 → 复活调度"。
   - 出问题：跳过原函数等于只跑了后半截，扣了血但死亡流程没走完，表现就是"躺尸不复活"；为了补洞又加 `death_fix_broadcast` / `death_fix_respawn`，坑越补越大。
   - 怎么修（2.7 C 路线）：整条注入链路删除，只改 rayDir / velocity，死亡与复活交回游戏；旧的 injection 版文件已从仓库移除，只保留下面这些结论。

2. **追踪完全不生效：`SetOwner` 全二进制 0 处直接调用**
   - 一开始没考虑到：以为弹体 owner 是在 `WPN_Missile.SetOwner` 里写的。
   - 出问题：在 `SetOwner` 里登记制导永远不触发，`homingArmed` 一直是 0。
   - 怎么修：反汇编 `Weapon.ProjectMissile`(0x10B6D080) 找到真实链路——owner 是直接写字段（+0x30），登记挂点改到 `WPN_Missile.SetWeaponData`（五种投射物都会经过）。

3. **弹体为什么能"拐弯"**
   - 关键结论：`WPN_Missile.FixedUpdate`(0x10B660C0) 只做 `Rigidbody.AddForce(extraGravity)`，`Work()` 用 `velocity = forward * shootSpeed` 发射。所以改写 velocity 就能拐，不需要碰任何游戏逻辑。

4. **`WPN_Gun.Damage` 是 cdecl，参数在栈上**
   - 出问题：按普通函数参数读会读错。
   - 怎么修：onEnter 里改 `[esp+0x14]`/`[esp+0x18]`/`[esp+0x1C]`，改前先做射线形态校验。

### 方案迭代

- **注入版（已废弃）**：`Interceptor.replace` + 自造 `DamageEventData` + `GameManager.TakeDamage` + 死亡兜底。缺点：接管了游戏最复杂的链路，任何一处漏掉就是"躺尸"或崩溃。
- **C 路线（当前）**：只改输入（rayDir / velocity），其余全放行。缺点：受制于原函数的射线/物理行为，特殊武器需要逐个挂发射入口。

### 经验教训

- 想改"伤害"，先问一句：能不能只改**输入**（方向、速度），让原函数自己算？能改输入就不要接管函数。
- 二进制里"看起来该有的调用点"可能一次都不存在（`SetOwner`），挂点必须用反汇编确认调用链，而不是按类名猜。
- 栈参数（cdecl）改写前必须做形态校验，写错一个 float 就是把整发子弹打飞。

## 一句话总结

枪械改 `WPN_Gun.Damage` 的 rayDir、投射物在 `SetWeaponData` 登记后在物理步改写 velocity，伤害与死亡复活全部交回游戏；坑在旧版注入链路导致躺尸不复活、`SetOwner` 根本不是挂点、cdecl 栈参数要校验后再写。
