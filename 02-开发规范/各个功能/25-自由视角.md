# 25｜自由视角（Free Camera）

**来源**：`features/25_free_camera/`（script.js）+ 开发素材 `05-正式功能/25-自由视角/free_camera_v1_3.js`、`free_camera_ui_v1_3.py`

## 核心原理

- **一句话**：Hook `CinemachineBrain.PushStateToUnityCamera`，每帧把最终相机的位置/旋转改写成脚本自己维护的 `freeCam.x/y/z + yaw/pitch`（开启瞬间只从当前相机取一次初始位置，之后完全独立），本质是“独立维护相机状态 + 就地改写最终相机 Transform”类方案（灵魂相机模式）。
- **手段归类**：Hook 相机渲染出口 + 主动调用 Transform set_position/set_rotation + WinAPI 键盘输入 + 生命周期 Hook 驱动。

## 修改的关键字段

| 偏移 | 字段 | 值/说明 |
|---|---|---|
| Player +0x4C | cameraRotation | 读取鼠标 Yaw/Pitch 作为视角输入 |
| （运行时）freeCam.x/y/z、yaw/pitch | 脚本自维护 | 开启瞬间初始化一次，之后每帧独立推进 |
| 最终相机 Transform | position / rotation | 每帧覆写为 freeCam 状态 |

**特殊处理**：
- **灵魂相机（独立位置）**：只从当前最终相机取一次初始位置（`initFreeCamFromCurrentCamera`），之后位置完全由脚本维护，不再依赖人物 CharacterContainer/CameraManager/跟随人物。
- **输入双路径**：优先 WinAPI `GetAsyncKeyState`（WASD，含垂直飞行：W=沿 forward 上/下飞）；解析失败才降级为 `Player.GetWalkVelocity` displayClass 输入（140ms 陈旧判定）。
- **移动锁定**：自由视角时把玩家移动向量归零（`lockPlayerMove`），人物原地不动。
- **开启才装 Hook**：点击开启才 `installHooks`，不预装。
- **生命周期重置**：CameraManager.Awake/GameManager.Awake/ModeBase.Update 触发相机重置，ExitGame/OnDestroy 清状态；切房/重开局自动恢复可用。
- **参数钳制**：moveSpeed 1–80、pitch ±88°、dt 钳制 0.001–0.05s、位置/朝向合理性过滤（isFinite、长度校验）。
- **架构校验**：只支持 32 位（`arch==ia32` 且 `pointerSize==4`），否则直接拒绝。
- **可逆卸载**：disable/cleanup 重置运行时、detach 全部 hooks，相机交还游戏。

## 作用范围

仅本地玩家（本地最终相机）。所有处理都过 `isLocalPlayer`/本地相机实例，不含 Bot 与他人视角；锁定移动也只针对本地玩家。

## 产品设计巧思

- 一键开启即“灵魂出窍”视角，鼠标转向复用游戏习惯，WASD 沿镜头飞行（含垂直升降），操作零学习成本。
- 开启瞬间从当前位置起飞，不用手动设置起点；关闭后相机交还游戏，不留残留。
- 换房间/重开局自动重置并继续可用，不用反复开关。

## 开发历程（重点）

### 踩过的坑

1. **相机跟随人物模型，无法真正“自由”**
   - 一开始没考虑到：把人物 CharacterContainer / CameraManager 作为相机位置来源、相机跟随人物，人物动相机就跟着动。
   - 出问题：无法实现脱离人物位置的自由飞行（灵魂相机）。
   - 怎么修：v1.3 改为开启瞬间只取一次初始位置，之后 `freeCam` 完全独立维护，彻底不依赖人物模型。

2. **游戏输入源不稳定（GetWalkVelocity）**
   - 一开始没考虑到：用 `Player.GetWalkVelocity` 的 displayClass 读输入，逻辑上绑定游戏角色移动。
   - 出问题：自由视角下玩家输入/移动状态异常时，飞行输入不稳定。
   - 怎么修：优先用 WinAPI `GetAsyncKeyState` 直读键盘（含多种解析方式），解析不到才降级回 GetWalkVelocity，并做陈旧判定。

3. **相机未就绪/切房后指针失效**
   - 一开始没考虑到：最终相机在进房后才创建，切房/重开局会重建。
   - 出问题：一次性初始化失败后相机一直失效。
   - 怎么修：CameraManager.Awake/GameManager.Awake 触发重置，ModeBase.Update 750ms 限频兜底重应用，ExitGame/OnDestroy 清状态。

### 方案迭代

- **早期（跟随人物）**：自由相机绑定人物（CharacterContainer/CameraManager 来源）。缺点：无法真正独立飞行，人物一动相机就动。
- **中期（Hook + 输入修正）**：Hook 相机渲染出口改相机位置，但输入仍依赖 GetWalkVelocity。缺点：输入源不稳定。
- **最终 v1.3（灵魂相机 + WinAPI 输入）**：开启瞬间取一次初始位置，之后完全独立维护 `freeCam`；输入改 WinAPI 键盘 + 兜底降级；生命周期 Hook 驱动重置；移动锁定让玩家原地。

### 一开始没考虑到的点

- “自由视角”的关键不是改相机，而是**切断相机与人物位置/朝向的绑定**（取一次初始值后独立维护）。
- 输入源要**独立于游戏角色移动系统**（WinAPI 直读键盘），否则角色状态会干扰飞行。
- 相机/房间生命周期重建需要事件驱动重置，不能一次性初始化。

### 经验教训

- 自由相机类功能核心是**位置自治**：初始化一次性采样，之后状态归脚本管，不与人物模型绑定。
- 外部输入优先用系统级 API（GetAsyncKeyState），游戏内部输入源只作兜底。
- 相机对象生命周期长于单帧，用**生命周期 Hook + 限频兜底**处理重建与切房。

## 一句话总结

通过 Hook `CinemachineBrain.PushStateToUnityCamera` 每帧改写最终相机 Transform，采用“开启瞬间采样一次初始位置、之后 freeCam 完全自治”的灵魂相机方案，输入用 WinAPI WASD + 鼠标视角复用、失败降级 GetWalkVelocity，并锁定本地玩家移动；踩坑集中在“相机绑人物无法独立飞行”与“游戏输入源不稳定”，最终以生命周期重置 + 可逆卸载收尾。
