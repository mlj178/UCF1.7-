# 41｜伤害吸血（Lifesteal）

**单功能开发目录**：`05-正式功能/41-伤害吸血/`（含独立调试 UI、持久化日志模块、完整说明文档）

**整合包运行位置**：`04-正式发行版/全功能整合包2.8/game_modifier/features/41_lifesteal/`

> 本文以**整合包 2.8 的实际代码**为准。整合包里的 `script.js` 与 05 目录**逐行一致**（只改了文件头注释），
> 逻辑改动请两边同步，否则会出现"单功能好了、整合包里没好"。

## 核心原理

- **一句话**：在 `HealthData.Hurt`（游戏真正扣血的那一步）拿到"这一击实际扣掉的血量"，
  按比例**给本地玩家**调 `HealthData.Heal`。伤害怎么算出来的完全不管。
- **手段归类**：`Interceptor.attach` 观察 + 调游戏原生方法。**零内存写入**
  （全脚本 `write*()` 调用数为 0）、**零 `Interceptor.replace`**，不改伤害事件、不跳过原函数。
- **为什么不在 `OnEntityHurt` 里加血**：那时 `damage` 已经过
  `×受害者防御率 → min(剩余血量)` 两道处理，在斩杀线上加血会"回了血但没救回来"，
  而且拿不到"实际扣了多少"。`Hurt` 的入参天生就是最终值。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 符号 | 手段 | 作用 |
|---|---|---|---|
| 0x00B3F470 | `Entity.OnEntityHurt` | attach | 建立伤害来源上下文（通用实体） |
| 0x00B516B0 | `Player.OnEntityHurt` | attach | 建立伤害来源上下文（玩家覆写入口） |
| 0x00AE45B0 | `HealthData.Hurt(int)` | attach | **最终扣血入口**：匹配上下文、结算吸血 |
| 0x00AE44F0 | `HealthData.Heal(int)` | NativeFunction | 给本地玩家回血（游戏自己封顶 maxHealth） |
| 0x00AE4830 | `HealthData.get_isDead` | NativeFunction | 死亡状态不调 Heal，避免绕过复活流程 |
| 0x00E2933C | `GameManager.myPlayer` 静态字段 | 只读 | 本地玩家：`[0xE2933C] -> Il2CppClass* -> +0x5C static_fields -> +0x00` |
| 0x00AFAA40 / 0x00AEBCB0 / 0x00AEBD40 | 回合结束 / 新回合 / 房间销毁 | attach | 清上下文、待结算、武器映射与本地玩家缓存 |

## 伤害来源怎么识别

1. **建上下文**：`OnEntityHurt` 是按值传 `DamageEventData`，x86 cdecl 下结构体从 `[esp+8]` 起，
   读 attacker / victim / type / damageTag / wpnIndex。只有 **attacker 是本地玩家**才入栈（其余早退，不分配对象）。
2. **还原归属**：attacker 若是 missile / 炮台实体，读它自己的 owner 字段（`missile+0x30` / `sentry+0x64`），
   再和 `GameManager.myPlayer` 比。**零 Hook**——不去挂 `SetWeaponData` / `SetData`，避免和 26 / 30 抢同一地址。
3. **分类**：`type`（Gun=1 / Knife=2 / Grenade=3 / Infect=4 / Other=5）+ `wpnIndex` →
   本地玩家 `PlayerWeapons` 里每把武器 `Weapon.data -> WeaponData.wpnClass` 建映射 →
   主武器 / 副武器 / 枪托重击 / 近战 / 投掷 / 特殊 / 感染 七个桶。
   映射缺失时 Gun 归主武器、Knife 归近战，宁可粗分也不漏吸。
4. **配对结算**：`Hurt` 命中时用「受害者 HealthData 指针 + 2 秒时间窗」找回上下文（栈上限 16 条，防泄漏）。

## 修改的字段

**一个字节都没写。** 只读以下结构，写入只有一个动作：调游戏自己的 `Heal`。

| 偏移 | 字段 | 用途 |
|---|---|---|
| `DamageEventData` +0x00 / +0x04 / +0x34 / +0x38 / +0x3C | attacker / victim / type / damageTag / wpnIndex | 归属与分类 |
| `Entity` +0x1C / +0x20 | healthData / team | 受害者血量、队友判定 |
| `Player` +0xA0 | `wpns` | 武器分类映射（2 秒刷新） |
| `Weapon` +0x68 → `WeaponData` +0x0C / +0x10 / +0x14 | wpnIndex / wpnClass / weaponName | 分类与日志 |
| `HealthData` +0x08（ObscuredInt）/ +0x1C | currentHealth / maxHealth | 只为算实际回血量与日志 |

## 作用范围与边界

- 只对**本地玩家造成的伤害**吸；只给**本地玩家**回血。人机互相打、人机打你都不触发。
- 打队友 / 自己不掉血也不吸（`only_enemy_victim` 默认开）。
- **感染伤害（type=4）不走 `Hurt`**，物理上无法从这条链路吸 → 该分类默认关闭，不是 bug。
- 敌方 `SentryGun` / `TombStone` 覆写了 `OnEntityHurt` 并自行处理，打掉它们不产生吸血。
- 地图机关、环境伤害、摔伤没有玩家归属 → 不吸。
- `Hurt` 的 onEnter 在**减血之前**执行，所以吸血**救不了命**（满血 10 挨 50 伤害，先回 5 再扣 50 照样死）。

## 产品设计巧思

- **结算点选在 `Hurt`**，于是「30-调整伤害倍率」「26-手雷模式」的爆炸伤害强化、「40-开火直伤」
  改出来的伤害**自动**被算进吸血，不需要任何叠加适配——这是本功能与整合包其它功能共存的关键。
- **七个来源开关 + 比例滑块**：既能"全类型 10%"当续航，也能"只拿刀吸 100%"当吸血刀玩法。
- **日志按对账设计**：明细与汇总共用一道 400ms 闸门（成对出现，不会错位配对），
  外加 15 秒周期 `[统计]` 行（命中数 / 跳过原因 / 各分类回血）。掉血不掉帧，事后能对账。

## 开发历程（踩过的坑）

1. **单次回血上限被砍**：`max_pending_heal` 原设 5000，实机终结者刀 7000/9000/13000/15000 全被压到 5000，
   表现为"一刀 15000 只回 5000"。改成 **20000** 后 15000 一刀回 15000（未满血时）。三处默认值必须一致
   （script.js / manifest.json / 独立 UI），否则注入后被旧值覆盖。
2. **明细与汇总各自节流 → 对不上账**:diag 400ms、汇总 500ms 两个闸门，实测出现
   "diag damage=21 后面跟的是另一发的 damage=36"和"只有汇总没有明细"。改成 `shouldLog('heal_outcome', 400)` 单一闸门。
3. **"回得比伤害少"分不清成因**:撞单次上限与撞满血表现一样。明细补 `hp_max` 后一眼可判。
4. **独立 UI 的持久化日志不能带进整合包**:2.8 的 `core/log_manager.py` 在发行版（exe）里
   **一律不落盘**（策略性关闭），功能侧也不该绕过。所以整合包版走 `send({type:'log'})`：
   开发版进 `logs/game_modifier.log`（`audience` 默认 dev，不进界面面板），发行版不产生任何 .log。

## 实机验证结论（2026-11-14 12:57~13:08，100% 吸血，独立 UI）

- 链路闭合：`hurt_hits 4474 = no_ctx 4268 + bad_dmg 146 + local_events 60`，
  各分类事件合计 60 = `local_events`，`healed_total 20154 = gun 302 + knife 19252 + grenade 600`。
- 满血不回血：`damage=35 heal=0 hp_before=100 hp_after=100`（游戏 `Heal` 自己封顶）。
- 分类正确：M4A1 雷神 `wpn_class=0 → gun_primary`（72 → +19）；钢铁终结者 `type=2 → knife`（270/2024/344 全等额回血）。
- 队友过滤生效（`skip.mate=4`）、跨回合重置正常（13 次 `resetRuntime`、`pending` 全程 0、`dup=0`）。
- 感染类 `skip.cat_off=24` 全部落在关闭的 infect 桶 —— 按用户决定保持关闭。
- **未测**（用户决定后续需要时再补）：枪托重击的 type/wpnIndex、副武器分类、炮台 owner 还原、
  致死一击的吸血量、与「30-调整伤害倍率」同时开启的叠加实测。

## 经验教训

- 想"按实际伤害回血"，就去**最终扣血那一层**取数，不要在更上层自己算一遍——上层改了伤害你还得同步改公式。
- 观察类功能优先 `attach` + 调原生方法；一旦 `replace` 就会和数据改写类功能（26 / 30 / 40）互相踩。
- 同一个 Hook 地址被多个功能 `attach` 是安全的，但**每个监听者都要早退得足够早**（本功能对非本地玩家伤害在分配对象前就返回）。
- 日志是这类"数值手感"功能的最后证据：没有 `[统计]` 行，事后无法判断"没生效"到底是没命中、还是被过滤、还是被上限截断。

## 一句话总结

在 `HealthData.Hurt` 里拿"实际扣掉的血量"按比例调 `Heal`，零写入零 replace 所以天然与倍率 / 手雷强化 / 直伤叠加；
坑在单次回血上限曾经只有 5000、明细与汇总各自节流导致对不上账、以及感染伤害根本不走这条链路。
