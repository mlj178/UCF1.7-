# 39｜直接变身剑客（Become Ghost Blade）

**来源**：`04-正式发行版/全功能整合包2.7/game_modifier/features/39_become_ghostblade/`（script.js + manifest.json + panel.py + events.py）

> 本文以**整合包 2.7** 的代码为准。`05-正式功能/39-直接变身剑客/` 只保留单功能阶段的开发素材，不作为实现依据。

## 核心原理

- **一句话**：只在生化6 / 剑客模式（`gameMode == 5`）下，对存活且仍是佣兵（`nanoRole == 0`）的目标调用游戏静态方法 `Mode_Nano6.BecomeGhostBlade(player)`，一次变身成功返回 `true`。
- **手段归类**：一次性动作 + 主线程排水；原生调用在 `ModeBase.Update` 钩子里执行，RPC 线程不碰游戏对象。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 符号 | 手段 | 作用 |
|---|---|---|---|
| 0x00AF6A00 | `ModeBase.Update` | Interceptor.attach | 主线程排水口 |
| 0x00E2933C / 0x004A8170 / 0x00E1CE64 | `GameManager` TypeInfo / `Singleton.get_instance` / MethodInfo | NativeFunction + 静态字段 | 取 GameManager |
| 0x00B4A310 | `Mode_Nano6.get_instance3` | NativeFunction | 取剑客模式实例 |
| 0x00B47740 | `Mode_Nano6.BecomeGhostBlade` | NativeFunction（static） | 真正执行变身，返回 bool |
| 0x00B55FD0 | `Player.get_isMyPlayer` | NativeFunction | 认定本地玩家 |
| 0x00B56200 | `Player.get_nanoRole` | NativeFunction | 读当前角色（失败退回 `PlayerData.nanoRole`） |
| 0x00AE4830 | `HealthData.get_isDead` | NativeFunction | 跳过死亡目标 |

## 修改的关键字段

| 偏移 | 字段 | 说明 |
|---|---|---|
| GameManager +0x00 / +0x04 / +0x1C | myPlayer / gameMode / allPlayers | 本地玩家、模式、遍历人机 |
| Player +0x1C / +0x94 / +0x98 | healthData / clientData / playerData | 判死、判人机、读角色 |
| ClientData +0x1C | isBot | 只处理人机 |
| PlayerData +0x60 → +0x00 | nanoRole（`SubscribeableProperty`） | 兜底读角色 |

**特殊处理**：
- **模式门控最严**：`gameMode` 必须严格等于 5，其它模式直接拒绝（剑客只存在于生化6）。
- **目标门控**：必须存活、且 `nanoRole == 0`（佣兵）；已变身/非佣兵跳过，跳过日志按角色值限频只记一次。
- **信任原生返回值**：`BecomeGhostBlade` 返回 false 就按失败处理，不自己再补写字段。
- 变身是一次性动作，执行后即清 pending，不跨房间重放。

## 作用范围

只影响当前房间内的目标角色，不改血量、伤害、武器数据。仅生化6（gameMode 5）生效；其它模式点按钮只会得到"不适用"的提示。

## 产品设计巧思

- 严格模式门控：不适用范围直接拒绝，比"点了没反应"更容易理解。
- 本地玩家 / 人类人机两个按钮分开，避免误把人机变成剑客影响对局体验。
- 固定快捷键 `Alt+D`（玩家）/ `Alt+F`（人机），和救世主那组 `Alt+A`/`Alt+S` 排在一起，形成肌肉记忆。

## 开发历程（重点）

### 踩过的坑

1. **在错误模式下调用变身**
   - 一开始没考虑到：`Mode_Nano6` 的单例只在 gameMode 5 存在。
   - 出问题：别的模式调用会拿到无效实例，触发原生调用异常。
   - 怎么修：入口先判 `gameMode === 5`，不满足就拒绝。

2. **对已变身/死亡目标重复调用**
   - 出问题：游戏对非佣兵调用 `BecomeGhostBlade` 会返回 false 甚至产生副作用。
   - 怎么修：先读 `nanoRole` 与 `isDead`，不符合直接跳过，并按角色值限频记录。

3. **`get_nanoRole` 读不到时的误判**
   - 怎么修：退回 `PlayerData.nanoRole` 的 `SubscribeableProperty.value`，两条路都失败才判定"未知"。

### 方案迭代

- **早期**：想套用救世主那套"改 `UpdateNanoRole` + 发武器"。缺点：剑客的武器/形态由 `BecomeGhostBlade` 内部处理，绕开它会缺装备。
- **最终**：直接调游戏静态方法，返回值即结果。

### 经验教训

- 游戏已经提供了"一步到位"的变身方法时，不要自己拆成"改角色 + 发武器"。
- 一次性动作要信任原函数的布尔返回值，不要用"事后读字段有没有变"来猜。

## 一句话总结

仅 `gameMode == 5` 下对存活佣兵调用静态 `Mode_Nano6.BecomeGhostBlade`，主线程执行、按返回值判成败；坑在错误模式拿无效单例、对非佣兵重复调用、`get_nanoRole` 读不到要兜底。
