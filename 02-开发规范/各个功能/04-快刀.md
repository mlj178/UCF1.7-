# 04｜快刀（Speed Knife / 挥刀加速）

来源：`features/04_knife/`（script.js）。开发素材：`05-正式功能\04-快刀\` 下的 `AAAAA-speed_knife_v16.js`（v16，方案5 修复版，最终采用）。

---

## 核心原理

**一句话**：`Interceptor.replace` 替换 `PlayerWeapons.get_KnifeSpeed`(+0xB170A0)，本地玩家直接返回固定倍速（整合包默认 **5.0**，v16 源脚本为 **10.0**），非本地玩家/异常走原 getter。

**手段归类**：函数替换（返回值覆写放大器）—— `Interceptor.replace` + `NativeCallback`（签名 `float`，入参 `['pointer']`），纯开关，倍率可选。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 函数 | 手段 | 作用 |
|---|---|---|---|
| +0xB170A0 | `PlayerWeapons.get_KnifeSpeed` | **Interceptor.replace** | 挥刀速度 getter，被整体替换 |
| +0xB55FD0 | `Player.get_isMyPlayer` | NativeFunction（bool） | 判断 owner 是否本地玩家 |

## 修改的关键字段

| 偏移 | 字段 | 值 |
|---|---|---|
| `PlayerWeapons+0x8` | owner（`Player*`） | 读取用于身份判断 |
| get_KnifeSpeed 返回值 | 挥刀速度倍率 | 本地玩家 **5.0**（整合包，可动态改）；其余调用原函数 |

**特殊处理**：
- **动态倍率**：整合包 `setSpeed(speed)` 更新 `currentSpeed`，开启状态下实时生效，无需重新 hook。
- **空 owner/异常兜底**：owner 为空（null）或回调抛异常一律返回**原函数**，不返回放大值（防止对未知对象误加速）。
- **身份判断**：仅 `isMyPlayer(owner)` 为 true 才返回放大倍率。
- **日志限流**：只打前 10 次识别日志。
- **可逆卸载**：`Interceptor.revert`。

## 作用范围

**仅本地玩家（人类）**：`isMyPlayer(owner)` 为 false（含 bot）走原函数原速。对所有调用 `get_KnifeSpeed` 的挥刀动作统一生效，**无武器特判**。`PlayerWeapons` 为核心类 → **全模式通用**。空 owner/异常兜底走原函数（与 05-快速换弹的空 owner 兜底返回放大值不同，本功能更保守）。

## 产品设计巧思

- **倍率运行时实时可调**：`setSpeed(speed)` 更新 `currentSpeed`，开启状态下改滑块即时生效、无需重启 hook。
- **换武器自动继承**：改的是玩家级属性 getter（`get_KnifeSpeed`），切换/拾取任意刀具都自动生效，全模式通用。

## 开发历程（重点）

### 踩过的坑（问题 → 原因 → 解决）

1. **身份判断失败 → 加速对所有人或对谁都没生效**
   - 问题：不判断本地玩家时，加速要么波及 bot、要么完全不生效。
   - 原因：getter 的 `self` 是 `PlayerWeapons`，owner 在 `self+0x8`，需用 `Player.get_isMyPlayer`(+0xB55FD0) 判定。
   - 解决：`owner = self.add(0x8).readPointer()` → `isMyPlayer(owner)` 为 true 才返回倍速，否则原函数；空 owner/异常兜底返回原函数。

2. **替换 getter 必须"该放大才放大、不该放大走原函数"**
   - 问题：若对空 owner 也返回放大值，可能误加速异常/未初始化对象。
   - 原因：构造阶段 `owner` 可能尚未赋值。
   - 解决：空 owner、异常走原函数；仅在确认本地玩家时放大（比 05 更严谨）。

3. **早期"直接改速度数据/单武器"方案不通 → 迭代到 getter 替换**
   - v16 脚本自身标注为"**方案5 修复版**"，说明此前已历经多版尝试（具体早版方案在素材中无留存，细节待核实）。
   - 最终落点是"替换 getter、返回值覆写"——符合游戏通过属性 getter 取加成的设计模式，所有挥刀统一、切换武器自动继承、无需重新触发。

### 方案迭代

1. **前期尝试（版本 1~4，脚本标注"修复"隐含）**：最终前多版因身份判断 / 替换方式不可靠而失败，因此出现"方案5 修复版"。
2. **方案5 修复版（NativeCallback Replace getter，最终采用）**：`Interceptor.replace get_KnifeSpeed(+0xB170A0)`，本地玩家返回 `SPEED`、其余原函数。
   - 优点：改**属性访问器**（玩家级），全局统一、切换武器自动生效、可 revert、可动态调速、身份与异常兜底完备。
   - 与「05-快速换弹」同构：都是替换 `PlayerWeapons` 的属性 getter（`get_ReloadSpeed`/`get_KnifeSpeed` 相邻 RVA），走同一模板。

### 一开始没考虑到的点

- **getter 的 `self` 是 `PlayerWeapons`、owner 在其 `+0x8`**，要先解引用取 owner 再判本地玩家。
- **空 owner / 异常 window 必须兜底原函数**，否则可能误加速未初始化对象。
- **倍率应可动态调整**（`setSpeed`）而非写死，便于运行中切换不重启 hook。

### 经验教训

- **改属性 getter（玩家级）优于改武器数据（武器级）**：全局统一、切换自动生效、符合游戏加成模式。
- **返回值覆写要"有条件放大"**：确认本地玩家才放大，空/异常一律走原函数，避免对未知对象误加速。
- **Hook getter 通用模板**：`owner = self.add(0x8)` → `isMyPlayer(owner)` → 本地返回自定义值 / 其他返回原函数，全程 try-catch 兜底。（同 05）

## 一句话总结

`Interceptor.replace` 包 `PlayerWeapons.get_KnifeSpeed`(+0xB170A0)，用 `isMyPlayer`(+0xB55FD0) 判定 owner（`PlayerWeapons+0x8`）：本地玩家返回倍速（整合包 5.0、可 `setSpeed` 动态调）、其余走原函数，空 owner/异常兜底加可逆卸载；与 05-快速换弹同构，是"替换属性 getter + 返回值覆写"的玩家级方案。
