# 35｜全模式房间人数（Room Player Count）

**来源**：`04-正式发行版/全功能整合包2.7/game_modifier/features/35_room_player_count/`（script.js + manifest.json + panel.py）

> 本文以**整合包 2.7** 的代码为准。`05-正式功能/35-全模式房间人数/` 只保留单功能阶段的开发素材，不作为实现依据。

## 核心原理

- **一句话**：不碰游戏逻辑，只在二进制里打「代码洞」（code cave）——把机器人数量常数、模式分支、以及普通模式"人数→下拉索引"的转换分支改掉，让任意总人数（2~100）在下一局生效；关闭开关立刻把字节还原。
- **手段归类**：静态内存补丁（写 `.text` 字节 + 还原），不用 Frida trampoline，避免在热点函数里插跳板破坏栈和调用约定。

## 关键补丁表（GameAssembly.dll）

| RVA | 原字节 / 语义 | 改成 | 作用 |
|---|---|---|---|
| 0x00B30F3C | 机器人数量常数（`BF imm32`，偏移 +10 是 imm32） | 写入 `总人数 - 1` | 决定这一局生成多少 Bot |
| 0x00B67F07 | 名字列表分支（`74 05`，偏移 +21） | 仅 gameMode 6 跳过 RemoveAt | 保证多人模式下名字够用 |
| 0x00B25C68 | `75 0F`：普通模式会把人数转成下拉索引 | `EB 0F`（无条件跳） | 让普通模式也用配置的人数，而不是被下拉索引覆盖 |
| 0x00B30F3C 附近代码洞 | 游戏本身已把 `GenerateBotClient` 调用路由到洞内 | — | 所以改常量即可，不需要 hook 热点函数 |

**必须清理的历史遗留**：

| RVA | 内容 | 处理 |
|---|---|---|
| 0x00B44895 → 0x2BF6F8 → 0x1553BA | 旧 v3 profile 夹带的"本地玩家捡补给箱送武器"跳转 | 从写入 profile 移除，并在 apply/disable 时用 `clearLegacySupplyBoxCheat()` 还原 |
| 0x12AF7F / 0x3D18E2 / 0x72BE79 / 0x9DA472 | 旧 profile 夹带的四段与人数无关的作弊 payload（预开火 / 后坐散布 / 跳跃 / RPG 动画速度） | 从 profile 移除，`clearLegacyCheatCaves()` 还原成 int3 |

## 修改的关键字段与参数

| 项 | 说明 |
|---|---|
| `total_players` | 滑条 2~100，默认 50；整数（面板层强制取整，兼容旧的小数存档） |
| 机器人数量 | 总人数 - 1（本地玩家占 1 个位置） |
| 开关 | 门控是否允许写入/还原；关闭立即恢复官方字节 |
| 生效时机 | **下一局**（建房前设置并点「应用人数」），当前局不变 |

**特殊处理**：
- 写入前记录原字节，关闭/退出时按记录还原；被别的会话写过的洞也会被识别并接管或还原。
- 人数只在用户点「应用人数」时写入，不随开关自动重放，重连游戏不会偷偷改。
- 识别旧版本写进进程的作弊跳转并还原，避免"上一个会话留下的脏字节"继续生效。

## 作用范围

只改"这一局生成多少 Bot"，不改玩家属性、不改伤害、不改武器。所有模式（团队、爆破、个人、生化、多人生化）都按同一份人数生效；上限 100，超过会被游戏自身逻辑限制。

## 产品设计巧思

- 用代码洞改常量而不是 hook 热点函数：不插跳板、不改栈，稳定性最好。
- 明确"下一局生效"，并在面板上给出反馈文字，用户不会以为点完立刻变人。
- 只保留与人数有关的补丁，其它 payload 全部剔除——这条是踩过崩溃后立的规矩。

## 开发历程（重点）

### 踩过的坑

1. **v3 profile 夹带补给箱跳转，本地玩家捡箱直接 DEP 闪退**
   - 一开始没考虑到：`0xB44895 → 0x2BF6F8 → 0x1553BA` 这条跳转的终点 `0x1553BA` 不是指令边界（它是 `83 3D 7C 98 E6 10 00` 的最后一个字节）。
   - 出问题：跳进去后主线程在 il2cpp/GC 运行时里错位执行，最后 `mov edi,[ebp+8]` / `call edi` 把 `ModeBase_Nano` 实例当函数调用 → `0xC0000005`。因为分支条件是 `Player.get_isMyPlayer`，所以人类/终结者/幽灵捡任何补给箱都会中招。
   - 怎么修：从写入 profile 删除这四个 RVA，新增 `clearLegacySupplyBoxCheat()`，在应用和禁用路径都调用，把旧进程里的跳转还原。

2. **v3 profile 还夹带四段与人数无关的作弊 payload**
   - 出问题：`0x12AF7F`（预开火/切枪）、`0x3D18E2`（后坐散布）、`0x72BE79`（跳跃）、`0x9DA472`（RPG 动画速度）——原版二进制里没有任何引用，写了也不会被调用；其中三处跳的是函数中间地址，真被执行只会把状态搞坏。
   - 怎么修：全部移出 profile，放进 `LEGACY_CHEAT_CAVES` 用于还原，并加静态测试锁死"profile 不得包含这四个 RVA"。

### 方案迭代

- **早期（hook 热点函数）**：想 hook 生成 Bot 的函数改参数。缺点：热点函数里插 trampoline 容易破坏栈/调用约定。
- **最终（代码洞 + 常量）**：利用游戏本身已有的代码洞改常量与分支，最稳。缺点：强依赖这个版本的二进制布局，换游戏版本必须重做。

### 经验教训

- 补丁类功能要把"写了什么字节、原字节是什么"当成契约存下来，否则下一个会话（甚至别的版本）会带着脏字节运行。
- 不要在一个功能的 profile 里夹带别的功能的 payload——崩溃时很难定位是谁的锅。

## 一句话总结

用代码洞改「Bot 数量常数 + 模式分支 + 人数转换分支」让 2~100 人全模式生效，下一局应用；踩坑集中在 v3 profile 夹带的补给箱跳转（非指令边界 → DEP 闪退）和四段无关 payload，最终全部剔除并加了还原函数与静态测试。
