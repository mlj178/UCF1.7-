# 26｜手雷模式（Grenade Mode）

**来源**：`features/26_grenade_mode/`（script.js）+ 开发素材 `05-正式功能/26-手雷模式/grenade_runtime_filter_design.md`、`grenade_mode_lock999_keep_weapon_tuner.js`、`要求.md`

## 核心原理

- **一句话**：玩家侧锁定 `WPN_Throw.ammoData` 数量为 999 并保护当前手雷对象不被 `PlayerWeapons.Remove` 删除；Bot 侧用 `VirtualBotControl` 接管枪械 `BotControl`（禁枪不放行），查不到 Grenade 指针就用已知普通 Grenade weaponIndex 主动补发，最后 `Select(3)+WPN_Throw.Throw`；手雷运行时参数（伤害/范围/飞行速度）只在 `WPN_Throw.<Throw>b__10_0` 捕获的 missile 上改，本质是“锁数值 + 保护对象 + 接管投掷链路 + 运行时改参数”类方案。
- **手段归类**：Interceptor.attach + NativeFunction 主动调用（WPN_Throw.Throw / GameManager.GiveWeapon / Animator.set_speed）+ 固定 RVA 指针链 + 定时器（投掷冷却/补发冷却）。

**特殊处理**：
- **统一投掷许可层（canBotThrowNow）**：出生保护（spawnGrace 3s）、首次额外延迟（1s）、目标稳定（700ms）、冷却、是否有 Grenade、是否 Bot 全部统一判断，任何投掷路径（AI 状态机 / Bot.UseWeapon / VirtualBotControl / 底层 Throw 驱动）都先过这一层，避免单点保护被绕过。
- **复活重置（resetBotLifeState）**：RemoveAll / GiveWeapon / Grenade 变化时重置 Bot 生命周期，复活后重新进入出生保护，不把复活 Bot 当老 Bot。
- **多 key Grenade 缓存**：同一 Bot Grenade 同时按 playerWeapons / owner player / bot / 反向索引 4 种 key 记录；VBC 投掷前按序查缓存 → 反查 PlayerWeapons → Select(3) 后再查，仍无则主动补发。
- **主动补发普通 Grenade（tryGiveBotGrenadeForThrow）**：无 Grenade 指针时用 `lastBotGrenadeWeaponIndex` 调 `GameManager_GiveWeapon_Original(playerPtr, idx|0, 0, 0, ptr(0))`，给当前 Bot 补发自己的真实 Grenade，绝不伪造指针或对 0x0 调 Throw。
- **VirtualBotControl**：替换 Gun/Sniper/RPG 的 BotControl，成功扔雷则跳过原 BotControl，暂时不能扔雷则继续禁枪，绝不放行原枪械开火。
- **官方发枪优先**：默认不拦截非 Grenade 发枪、不全局强制 slot=3，Bot 平时像正常 Bot（端枪正常），只在投掷阶段临时 Select(3)，减少木桩/空枪/聚堆。
- **运行时参数即时同步**：UI 滑块/勾选改动即同步 JS Runtime（实际写入值 = UI 显示值 × 10），无需重开功能；伤害/范围/速度都有 my_player / all_players 作用域。
- **参数钳制**：伤害/范围/速度只对 `b__10_0` 捕获的 Grenade missile 生效（RPG/AT4/Nano 不入库）；锁雷前读当前值，相同则跳过写（防抖）；错误计数超阈值（14）自动关闭防失控。
- **可逆卸载**：disable 时 detach 全部 hooks、清除 trackedMissiles/protectedWeapons 等运行时缓存。

## 作用范围

本地玩家 + 全部 Bot（Bot 手雷模式）。锁 999 只作用于本地玩家手雷；Bot 侧只做“禁枪 + 驱动投雷 + 必要时补发”，不改 Bot 模型/动作/阵营。手雷参数默认只改本地玩家（my_player），可切 all_players。

## 产品设计巧思

- 手雷数量恒定 999，扔一个立刻锁回，玩家无脑丢雷不担心消耗。
- Bot 也全员进入手雷模式：端枪但不开枪，攻击统一转手雷，观感统一。
- 伤害/范围/速度滑块实时生效，且默认只改自己、可一键切全场，误伤可控。
- 出生保护 + 首次延迟 + 目标稳定，Bot 不会“刚出生秒丢雷”，行为自然。
- 复活自动重置生命周期，不会因为重复复活而漏掉保护。

## 开发历程（重点）

### 踩过的坑

1. **Bot 强制“只用手雷”导致木桩/空枪/聚堆**
   - 一开始没考虑到：强制 Bot 永远 slot=3、强制拦截非 Grenade 发枪，会让 Bot 拿不到官方武器、模型/动作不同步。
   - 出问题：Bot 像木桩、端空枪、聚堆不攻击。
   - 怎么修：v2.11 改为官方发枪优先，Bot 正常获得 Rifle/Pistol/Knife/Grenade，脚本只记录 Grenade，只在投掷阶段临时 Select(3)。

2. **Select/SetCurrentWeapon 入口强重定向触发 RangeError**
   - 一开始没考虑到：在 `Select/SetCurrentWeapon` onEnter 改 args 强重定向到 slot=3，会触发 RangeError。
   - 出问题：错误计数增加，功能自动关闭，甚至影响玩家锁 999 失效。
   - 怎么修：v2.5.1 彻底删除 onEnter 改 args / 入口重定向，改为只在投掷前安全地临时 Select(3)。

3. **部分 Bot 不会扔手雷（没有可安全调用的 Grenade 指针）**
   - 一开始没考虑到：VBC 已触发、禁枪已生效，但当前 Bot 没被记录到 Grenade（生命周期只暴露枪械、复活后记录被清、记录 key 对不上）。
   - 出问题：日志 `当前还没有可安全调用的 Grenade weapon ptr`，这些 Bot 端着枪既不开枪也不扔雷。
   - 怎么修：v2.12.5 加多 key 缓存 + 投掷前补记录；v2.12.6 加主动补发普通 Grenade；v2.12.7 修复补发参数类型。

4. **主动补发 Grenade 报 `expected an integer`**
   - 一开始没考虑到：Frida NativeFunction 对 `GameManager_GiveWeapon` 参数要求整数，`false, false` 不合法。
   - 出问题：`Error: expected an integer`，补发失败。
   - 怎么修：改为 `(idx | 0), 0, 0, ptr(0)`（weaponIndex 转 int，autoGiveUp/autoSelect 传 0）。

5. **复活后乱扔雷 / 保护失效**
   - 一开始没考虑到：复活后 PlayerWeapons 复用，`botLifeStates` 没重置，复活 Bot 被当老 Bot。
   - 出问题：后续复活后不再吃出生保护，刚复活就丢雷。
   - 怎么修：v2.11.6 在 RemoveAll / GiveWeapon / Grenade 变化时 `resetBotLifeState`，复活后重新触发保护。

6. **SmartAI 实验残留 + 开启失败**
   - 一开始没考虑到：JS 删了逻辑但 Python UI 文案没删、`_collect_config` 残留 `max_d/min_d`、`setupNatives` 还在初始化已删除的 `Bot_IsPathLengthToEnemyLess`。
   - 出问题：UI 显示已删除的旧实验文案；开启报 `cannot access local variable 'max_d'` / `Error: missing argument at addrOf`。
   - 怎么修：同步清理 Python UI、`_collect_config`、`setupNatives` 三处残留。

7. **激进删除 AI 链路导致投掷崩坏**
   - 一开始没考虑到：`remove-ai-path` 删了 AI 触发链路，连带破坏了投掷状态机和投掷前临时切雷路径。
   - 出问题：手雷扔一个就没了，Bot 不再继续丢雷。
   - 怎么修：不以 v2.12.5 为基准，恢复状态机/AI 相关主结构，UI 可隐藏但不激进删底层。

### 方案迭代

- **早期（锁999 + 保护）**：只锁 ammoData 数量、保护当前手雷对象。缺点：没有 Bot 手雷、没有参数修改。
- **中期（观察 + 强制手雷）**：观察切枪链路 → 强制 Bot 只用手雷 / 入口重定向。缺点：木桩、RangeError、行为不自然。
- **v2.7–v2.9（VirtualBotControl + 驱动投雷）**：接管枪械 BotControl 转手雷、Bot.UseWeapon 兜底、AI 触发投掷。缺点：部分 Bot 没 Grenade 指针扔不出。
- **最终 v2.12.7/2.12.8（安全补强）**：官方发枪优先 + 统一投掷许可层 + 复活重置 + 多 key 缓存 + 主动补发 Grenade + GiveWeapon 参数修复，所有投掷路径过 `canBotThrowNow`。

### 一开始没考虑到的点

- “让 Bot 只丢雷”不能靠强制发枪/强制 slot 实现，会破坏 Bot 原生行为。
- 入口 onEnter 改 args 在 IL2CPP NativeFunction 场景下有 RangeError 风险，且牵连其他功能。
- Bot 有 Grenade 记录 ≠ 投掷时还能拿到有效指针（复活/记录 key 变化都会丢）。
- 主动补发武器必须用该 Bot 自己的真实 weaponIndex，且 NativeFunction 参数要严格按整数。
- 复活会复用 PlayerWeapons，生命周期状态必须重置，否则保护一次性。
- 删 UI 不等于删逻辑，三处（JS/UI/配置收集）要同步删，否则开启失败。

### 经验教训

- 多入口的 Bot 行为改动，**必须收敛到统一许可层**判断，否则总有路径绕过保护。
- 对 IL2CPP 原生调用，**参数类型严格按整数/指针**写，别用布尔字面量。
- Bot 链路“宁可保留一点冗余，也不要删到影响行为”——删除前先确认各路径是否共用该结构。
- 缓存类状态（Grenade 记录、生命周期）要**多 key 冗余 + 复活重置**，防止指针/生命周期变化后失效。

## 一句话总结

玩家侧锁 999 + 保护当前手雷，Bot 侧用 VirtualBotControl 接管枪械 BotControl（禁枪不放行）、以统一许可层（出生/冷却/目标稳定）+ 多 key 缓存 + 主动补发 Grenade 驱动 `Select(3)+Throw`，手雷伤害/范围/速度只在 b__10_0 捕获的 missile 上运行时修改；踩坑集中在“强制手雷破坏 Bot 行为”“入口重定向 RangeError”“部分 Bot 无 Grenade 指针”“补发参数类型”，最终以官方发枪优先 + 安全补强 + 参数即时同步收尾。
