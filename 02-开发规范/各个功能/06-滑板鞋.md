# 06｜滑板鞋（MoveSpeed / 移动速度提升）

来源：`features/06_movespeed/`（script.js + manifest.json + panel.py）。开发素材：`AAAAA-move_speed_v1-3.js`。

---

## 核心原理

**一句话**：`Interceptor.replace` 替换 `PropertyModifier.Get`(+0xB17590)，**先调用原函数拿原值**，再校验"第二个参数 `player` 是本地玩家 + 本次 `self` 正是该玩家的 `Modifier_MoveSpeedRatio` modifier"双条件，命中才返回预设倍率 —— 属于"**先读后改（返回覆盖）**"，只对移动速度这一条 modifier 生效。

**手段归类**：`Interceptor.replace` + `NativeCallback`（签名 `float`，入参 `['pointer','pointer']`），默认倍率 3.0x（滑块 1.0~4.0）。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 符号 | 手段 | 用途 |
|---|---|---|---|
| +0xB17590 | `PropertyModifier.Get`（拦截 `Modifier_MoveSpeedRatio` 查询） | **Interceptor.replace** | 被替换目标，原函数 `originalFn` 用于取原值 |
| +0xB55FD0 | `Player.get_isMyPlayer` | NativeFunction（`bool` `['pointer']`） | 判断传入的 `player` 是否本地玩家 |

数据偏移：`Player+0x8C` = `Modifier_MoveSpeedRatio`（`PropertyModifier*`）。`PropertyModifier.Get` 原型 `float Get(self, Player* player)`，返回倍率，游戏用它乘基础速度得到实际移速。

## 修改的关键字段 & 特殊处理

**双条件校验**（比 04/05 多一层指针比对）：
1. `isMyPlayerFn(player)`（+0xB55FD0）→ 判定本地玩家；
2. `moveMod = player.add(0x8C).readPointer()`；`self.equals(moveMod)` → 确认本次查询的 `self` 正是该玩家的 `Modifier_MoveSpeedRatio`，防止误改其他属性。

| 处理 | 实现 |
|---|---|
| 原函数兜底 | 未命中条件一律返回 `originalFn(self, player)` 原值 |
| 空指针兜底 | `player` 空或 `moveMod` 空则不覆盖 |
| 日志限流 | `logCount <= 10`，记录"原值=1.000 修改后=3.0x" |
| 可逆卸载 | `Interceptor.revert(+0xB17590)` |

## 作用范围

**仅本地玩家（人类）**，且只作用于移动速度。`PropertyModifier.Get` 带两个参数 `(self, player)`，`player` 由调用方直接传入，非本地玩家 `isMyPlayer(player)` 为 false → 返回原值；再通过 `Player+0x8C` 比对 modifier 指针，确保只改 `MoveSpeedRatio` 这一条。bot 不受影响。因 `Player`/`PropertyModifier.Get` 是全模式共用基类成员，**所有游戏模式通用**。作用对象是玩家的移动速度 modifier（不是武器），无武器概念、无特判。

## 产品设计巧思

- **滑块实时调参**：1.0~4.0（默认 3.0），`setSpeed` 运行中即时生效，开关状态可**持久化**（下次启动沿用）。
- **只改移速、不误伤**：双重条件校验只覆盖 `Modifier_MoveSpeedRatio`，同一入口下的近战/换弹等其他 modifier 完全不受影响；非本地玩家透传原值。

## 开发历程（重点）

### 踩过的坑（问题 → 原因 → 解决）

1. **角色会瞬移/物理不同步 → 放弃改坐标**
   - 问题（早期尝试）：想过直接改 `Transform.position` 提升移速，结果角色瞬移、物理不同步。
   - 原因：改的是"位置结果"，没有动移动速度的计算来源。
   - 解决：改用"改速度倍率来源"——拦截 `PropertyModifier.Get` 返回值，干净、稳定、不碰物理。

2. **误改其他 `PropertyModifier`（如近战/换弹速度）**
   - 问题：只判断 `isMyPlayer` 时，可能把本不该管的 modifier 也改掉。
   - 原因：`PropertyModifier.Get` 是所有属性修改器（移速、近战、换弹等）的公共入口，仅身份判断不足以区分是哪一条 modifier。
   - 解决：加**第二重指针比对**——`self.equals(player+0x8C)`，确认本次 `self` 就是 `Modifier_MoveSpeedRatio` 才覆盖，精确命中"只改移速"。

3. **加入滑块实时调参时踩到 `isMyPlayer` 与 `self` 的取值细节**
   - 问题：早期在回调里取错 player/self，导致判定不命中，功能时灵时不灵。
   - 原因：回调签名 `(self, player)`，`self` 是 `PropertyModifier`，`player` 才是目标玩家；一度把 `self` 当 player 用。
   - 解决：严格区分 `self`（PropertyModifier）与 `player`（Player*），身份判断用 `player`，modifier 比对用 `self`。

### 方案迭代

1. **初版（v1-3）**：直接 `Interceptor.replace` `PropertyModifier.Get`，先 `originalFn` 取原值 → `isMyPlayer` 命中 → 比对 `self==moveMod` → 返回 `MOVE_SPEED_MULTIPLIER`（默认 3.0）。主架构从头稳定，后续只加滑块/开关控制与日志。
2. **整合包版**：`replace` 保持不变，外加滑块（1.0~4.0，默认 3.0）实时调参 `setSpeed`、开关持久化、未连接游戏友好提示、可逆卸载。

**设计要点**：移速的修改不是"覆盖游戏给的值"，而是"**先读原值、命中条件再覆盖**"，未命中透传原始倍率，保证其他属性/其他玩家完全不受影响。

### 一开始没考虑到的点

- **`PropertyModifier.Get` 是"所有属性修改器"的公共入口**：同一函数服务移速、近战、换弹等多条 modifier，光有身份判断不够，必须再比对具体 modifier 指针。
- **回调参数 `self` 与 `player` 是两个不同对象**：`self` 是 PropertyModifier，`player` 是目标玩家，不能混用。
- **改"倍率来源"比改坐标稳**：移速由 `Modifier_MoveSpeedRatio.Get × 基础速度` 决定，拦截 getter 返回值即可全局生效，无需每帧改坐标。

### 经验教训

- 对公共入口类 Hook（如 `PropertyModifier.Get`），**"身份判断 + 目标指针比对"双重条件**才能精确命中，避免误改。
- 回调签名要先弄清每个参数对象，再谈取值。
- 返回值篡改优先"先读原值、条件覆盖、未命中透传"，比无条件覆盖更安全。

## 一句话总结

`Interceptor.replace` 包住 `PropertyModifier.Get`(+0xB17590)，先读原值，`isMyPlayer`(+0xB55FD0) + `Player+0x8C` 指针比对双条件命中才覆盖返回 3.0x 移速倍率，未命中透传原值，仅作用于本地玩家且只改移动速度，可逆卸载、全模式通用；开发关键是把"所有属性修改器的公共入口"精确限定到 `Modifier_MoveSpeedRatio` 那一条（双重条件校验）。
