# 24｜人机暂停（Bot Pause）

**来源**：`features/24_bot_pause/`（script.js）+ 开发素材 `05-正式功能/24-人机暂停/经验总结.md`、`人机暂停-最小实现步骤.md`、`AAAAA-bot_pause_min.js`

## 核心原理

- **一句话**：不 Hook 任何行动逻辑，而是直接写 `Bot` 类静态字段 `stopAllBot`（true=全员暂停 / false=恢复），本质是“定位静态字段 + 直接写内存”类方案；全程不调用 IL2CPP 反射 API，纯固定 RVA + 指针链。
- **手段归类**：固定 RVA → TypeInfo → static_fields 指针链读写 + 房间就绪事件驱动重应用 + 写后读回校验。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 符号 | 手段 | 作用 |
|---|---|---|---|
| 0xAFA250 | GameManager.Awake | Interceptor.attach(onLeave) | 房间创建后立即重应用暂停 |
| 0xAF6A00 | ModeBase.Update | attach(onEnter) | 主线程兜底重应用（限频） |
| 0xB33370 | Bot.Update | attach(onEnter) | 检测 Bot 已就绪后重应用 |
| 0xAEE850 | ModeBase.ExitGame | attach(onEnter) | 退出房间清状态 |
| 0xAFB6F0 | GameManager.OnDestroy | attach(onEnter) | 场景销毁清状态 |

## 修改的关键字段

| 偏移 | 字段 | 值/说明 |
|---|---|---|
| GameAssembly +0xE25F44 | Bot_TypeInfo（读指针） | 定位 Bot 类 |
| Bot_TypeInfo +0x5C | static_fields（读指针） | 定位静态字段区 |
| static_fields +0xC | Bot.stopAllBot（U8） | 写 1=暂停 / 0=恢复 |

**特殊处理**：
- **用户规则：禁用反射 API**：不调 `il2cpp_class_*`/`il2cpp_field_*`/类初始化，只用固定 RVA + 指针链。
- **每次操作重新解析**：不缓存陈旧指针，`enable/status/disable` 每次重新走 `Bot_TypeInfo → static_fields` 链（切房/重载后地址可能变化）。
- **指针与大小校验**：`Process.pointerSize` 必须为 4（32 位）；每步指针非空校验。
- **读先于写、跳过重复写**：当前值已是目标值则直接返回，避免无意义写。
- **写后读回验证**：写入后立即 `readU8` 确认一致，失败置错误。
- **房间就绪重试**：未进入有人机模式时 `static_fields` 可能为 null，保留用户意图 `pendingApply=true`，500ms 定时重试，直到可写；进房事件（GameManager.Awake/Bot.Update/ModeBase.Update）触发即时重应用（限频 1s）。
- **可逆卸载**：`disable`/`cleanup` 恢复 `stopAllBot=false` 并 detach 全部房间 Hook；退出房间（ExitGame/OnDestroy）自动进入恢复待办。

## 作用范围

全局无区分（影响所有人机）。`stopAllBot` 是 Bot 类的静态字段（全局共享），写一次对房间内全部 Bot 生效；不区分敌方/队友/具体 Bot，也不作用于玩家。

## 产品设计巧思

- 一键暂停/恢复所有人机，无需逐个操作。
- 进房后自动生效：在没进房间时先开开关，进入有人机模式后会自动重试补上，不用重新点。
- 关闭功能或退出房间自动恢复人机，不留后遗症。

## 开发历程（重点）

### 踩过的坑

1. **进房前 `static_fields` 为 null，写不进去**
   - 一开始没考虑到：Bot 类未初始化时静态字段区指针为空。
   - 出问题：开启开关瞬间写入失败，用户以为功能无效。
   - 怎么修：写入失败时保留 `pendingApply` 意图，500ms 定时重试 + 进房事件（GameManager.Awake/Bot.Update）触发即时重应用，直到可写为止。

2. **切房/重载后指针失效**
   - 一开始没考虑到：静态字段区随房间/类型重载变化。
   - 出问题：缓存旧 TypeInfo/static_fields 指针，切房后写错位置。
   - 怎么修：每次操作重新解析指针链，不缓存陈旧指针；ExitGame/OnDestroy 清房间状态。

3. **不调用反射 API 的限制**
   - 一开始没考虑到：集成环境规定不能用 IL2CPP 反射 API（类初始化/字段 API）。
   - 出问题：传统“运行时找字段”的思路被禁，需固定地址方案。
   - 怎么修：改用固定 RVA（`Bot_TypeInfo 0xE25F44`）+ 指针链直接读写，同时保留 32 位指针大小与每步非空校验。

### 方案迭代

- **最早（反射 API 查字段）**：用 `il2cpp_class_get_static_fields` 等运行时 API 找字段。缺点：违反用户“禁用反射 API”规则，且依赖元数据可读。
- **最终（固定 RVA + 指针链 + 就绪重试）**：`GameAssembly+0xE25F44 → +0x5C → +0xC` 直接读写，叠加“读先于写、写后读回、房间就绪重试、切房重解析”保证可靠。

### 一开始没考虑到的点

- 静态字段区指针可能因类型未初始化/房间切换而为空或变化——需要重试 + 每次重解析。
- 写内存要**写后读回验证**，不能只写不查（防止写入被拒或写错地址）。
- 全局静态字段影响所有人机，属于“全局无区分”，需明确这正符合功能预期。

### 经验教训

- 纯静态字段功能最简单有效：**找到 TypeInfo 固定 RVA，一次指针链就够**，不必 Hook 逻辑函数。
- 对可能未就绪的全局状态，用“**保留意图 + 事件触发 + 定时重试**”代替一次性写入。
- 涉及内存写入务必**读先于写（幂等）+ 写后读回**，减少无效写与静默失败。

## 一句话总结

用固定 RVA 指针链（`Bot_TypeInfo 0xE25F44 → static_fields +0x5C → stopAllBot +0xC`）直接写全局静态字段实现人机暂停，绕开反射 API 限制；靠“进房事件触发 + 500ms 重试 + 每次重解析 + 写后读回”解决未就绪与切房失效，关闭自动恢复 false。
