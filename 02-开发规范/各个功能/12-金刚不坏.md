# 12｜金刚不坏（God Mode / 不掉血 / 无敌）

来源：`features/12_godmode/`（script.js + panel.py）。开发素材：`05-正式功能\12-金刚不坏\` 下的 `锁血经验总结.md`（IDA 分析与 bug 修复记录）、`AAAAA-godmode_hp.js`。

---

## 核心原理

**一句话**：`Interceptor.attach` 本地玩家的 `Entity.OnEntityHurt`/`Player.OnEntityHurt`，在 `onEnter` 里把栈上的 `DamageEventData.type` 字段就地改成 **4**（Infect 感染伤害）——游戏函数入口有 `cmp type,4; jz ret` 的**免伤害分支**，等于 4 时直接 `return` 跳过全部扣血逻辑。

**手段归类**：时点钩子（attach onEnter）+ 就地改写栈上结构体字段（改 `DamageEventData.type`），利用游戏自带的免疫分支。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 函数 | 手段 | 作用 |
|---|---|---|---|
| +0xB3F470 | `Entity.OnEntityHurt` | Interceptor.attach | 基底受伤函数，`onEnter` 改栈 type=4 |
| +0xB516B0 | `Player.OnEntityHurt` | Interceptor.attach | 玩家子类虚函数覆盖，**兜底**（虚表走子类时不触发父类） |
| +0xB55FD0 | `Player.get_isMyPlayer` | NativeFunction（bool） | 判断实体是否本地玩家 |
| +0xB400E0 | `Entity.get_isDead` | NativeFunction（bool） | 存活判定 |
| +0x4A8170 | `Singleton<GameManager>.get_instance` | NativeFunction | 取 GameManager 单例找玩家 |
| — | `setInterval`（2s） | 定时器 | 定期刷新/校验 `cachedMyPlayer`（防切房野指针） |

## 修改的关键字段

| 偏移 | 字段 | 值 |
|---|---|---|
| `ESP+0x10` | `DamageEventData.type`（栈上，`attacker`+0x08 / `victim`+0x0C / `type`+0x10） | 写 **4**（Infect，跳过受伤处理） |
| `GameManager+0x1C` | `allPlayers`（Player[]） | 读，合并找玩家 |
| `GameManager+0x20/0x28` | `playersBL` / `playersGR`（List\<Player\>） | 读，合并找玩家 |
| 数组 `+0x0C`/`+0x10` | IL2CPP 数组 len / data | 遍历玩家 |
| List `+0x08`/`+0x0C` | items / size | 遍历列表 |

**特殊处理（具体到偏移/逻辑）**：
- **栈偏移**（`__cdecl` 32-bit）：`[ESP+0x00]=ret_addr`、`[ESP+0x04]=this`、结构体基址 `[ESP+0x08]`；`type = espPtr.add(8).add(Dmg_type=0x08)` = **ESP+0x10**。
- **身份判断**：仅当 `entity === cachedMyPlayer` 才改 type；非本地玩家不动。`isMyPlayer` 判定 + 双列表合并 `findMyPlayer`。
- **生命周期**：每 2s 校验 `cachedMyPlayer` 仍在 GM 玩家列表中，切房则置空重找。
- **双入口 Hook**：父类 `Entity_OnEntityHurt` + 子类 `Player_OnEntityHurt` 同一 handler。
- **诊断日志**：前 20 次触发打印 entity / isMyPlayer 结果 / 修改前后 type 与地址。
- 可逆卸载：`detach` + `clearInterval`。

> 说明：素材文档记载 `Dmg_type=0x08`（事件内偏移），与 30-伤害倍率文档中 `type=+0x34` 存在口径差异，**待核实**统一。

## 作用范围

**仅本地玩家（人类）**：只对 `entity==cachedMyPlayer` 的玩家自身改 type=4，使其免疫所有伤害类型（枪/刀/雷/感染）；bot/队友/敌人正常掉血（bot 受伤走 `Bot.TakeDamageEvent`(+0xB32680) 独立路径，也不受影响）。HP 是玩家私有数据 → 全模式通用。

## 开发历程（重点）

### 踩过的坑（问题 → 原因 → 解决）

1. **Bug#1：栈偏移计算错误，type 写错位置 → Hook 无效**
   - 问题：游戏照常掉血。
   - 原因：`Entity_OnEntityHurt` 是 `__cdecl`（参数从右到左入栈、调用者清栈），`onEnter` 时 `espPtr+0x04+0x08=ESP+0x0C` **写到了 victim 字段**；正确应 `espPtr+0x08+0x08=ESP+0x10` 写 type。完整栈：`[ESP+0]=ret`、`[ESP+4]=this`、`[ESP+8]=attacker`、`[ESP+0xC]=victim`、`[ESP+0x10]=type`。
   - 解决：`espPtr.add(8).add(OFF.Dmg_type)`（跳过 ret 4B + this 4B）。

2. **Bug#2：未 Hook Player 虚函数覆盖 → 有时不触发**
   - 问题：玩家受伤时 `Entity_OnEntityHurt` 可能不被调用。
   - 原因：`Player` 类有虚函数表，`OnEntityHurt` 被覆盖，虚表调用走 `Player_OnEntityHurt`(+0xB516B0) 而非父类。
   - 解决：**同时 Hook 两个入口**，共用同一 handler（父类钩子可能不触发，子类兜底）。

3. **Bug#3：缺诊断日志 → 无法定位**
   - 原因：无 onEnter 日志，分不清是"Hook 没触发"还是"entity 比较失败"还是"栈偏移错误"。
   - 解决：加前 20 次详细诊断（触发次数/次数 entity 地址/isMyPlayer 结果/type 修改前后值与地址）。

4. **切房玩家指针变化 → 野指针**
   - 原因：`cachedMyPlayer` 在房间切换后失效。
   - 解决：2s 定时器在玩家列表中校验，不在列表则置空重查。

### 方案迭代

1. **早期直觉（改血量/写 HP）**：直接把玩家 HP 锁定为大值 → 需持续写、易被秒杀瞬间击穿、字段为 HealthData 复杂。
2. **方案（最终采用）：利用游戏自带免伤分支**——IDA 发现 `Entity_OnEntityHurt` 入口 `cmp [type],4; jz return`，等于 4 直接跳过扣血，故只需在 `onEnter` 把栈上 `type` 改成 4 即可 0 写血量、0 Hook 原函数。简洁且原生语义正确。

### 一开始没考虑到的点

- **`__cdecl` 栈布局**：`onEnter` 里取栈上结构体要手动跳过 `ret_addr(4B)+this(4B)`。
- **虚函数覆盖**：父类 Hook 可能不触发，需同时 Hook 子类同名函数。
- **`DamageEventData.type` 偏移有口径差异**（不同文档记录不同，需核实）。
- **房间切换**：缓存的玩家指针会变化，必须定时校验/刷新。
- **错误写栈可能误伤 victim 字段**：偏移算错会写到别的参数。

### 经验教训

- **谋定后动：先对函数做 IDA 反编译**，找游戏自带的"免疫/提前返回"分支，能"改一个字段跳过整段逻辑"就优于"持续写血量"。
- **栈上按值传参的结构体**，`onEnter` 取偏移必须按 `ret_addr + this + 参数` 顺序精算，别漏跳 8 字节。
- **多态虚函数**：父类 Hook 要防"子类覆盖导致不触发"，必要时双层 Hook。
- **持缓存指针持续操作必配生命周期刷新**（切房置空重查）。
- **IL2CPP x86 默认 `__cdecl`**，`args[0]` ≈ `[ESP+4]`（this）。

## 一句话总结

`attach`（`onEnter`）`Entity.OnEntityHurt`(+0xB3F470) 与 `Player.OnEntityHurt`(+0xB516B0，兜底)，仅当实体为本地玩家（`isMyPlayer`+0xB55FD0）时把栈上 `DamageEventData.type`（`ESP+0x10`）改成 4，利用游戏 `type==4` 的免伤分支跳过扣血；啃下的坑是 `__cdecl` 栈偏移（写错会到 victim）、虚函数覆盖需双 Hook、切房野指针要定时刷新、与 30-伤害倍率的 type 偏移口径待核实。
