# 07｜剑气化丝（Knife Range / 扩大近战攻击距离）

来源：`features/07_range/`（script.js + manifest.json + panel.py）。开发素材：`AAAAA-knife_range_v22.js`、`knife_range_v21_技术总结.md`。

---

## 核心原理

**一句话**：分两步 —— 先用 `Interceptor.attach` 挂 `get_KnifeSpeed` 的 onLeave 捕获本地玩家指针；再挂 `GetKnifeAttackData` 的 onLeave，把返回结构体里的攻击距离字段就地乘倍率写回 —— 属于"**就地改写返回值结构体字段（写内存）**"，不是 replace 返回值，也不是定时器。

**手段归类**：`Interceptor.attach`（onEnter/onLeave），默认倍率 50.0x（滑块 1.0~50.0）。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 符号 | 手段 | 用途 |
|---|---|---|---|
| +0xB170A0 | `PlayerWeapons.get_KnifeSpeed` | attach | onLeave 捕获本地玩家指针（`self+0x8` → isMyPlayer），只捕获一次 |
| +0xB63EC0 | `WPN_Knife.GetKnifeAttackData` | attach | 所有近战武器攻击数据的统一底层入口，onLeave 修改返回结构体 +0x4 攻击距离 |
| +0xB55FD0 | `Player.get_isMyPlayer` | NativeFunction（`bool`） | 判定 owner 是否本地玩家 |
| +0xAFAA40 | `GameManager.GameRoundEnd` | attach | 房间切换时重置捕获状态 |
| +0xAF5B30 / +0xAF15D0 | （房间相关） | attach | 房间切换时重置捕获状态 |

数据偏移：`WPN_Knife+0x30` = owner（`Player*`）；`get_KnifeSpeed` 侧 `self+0x8` = owner（捕获用）。攻击数据返回结构体 `+0x4` = 攻击距离（float）。

## 修改的关键字段 & 特殊处理

| 处理 | 实现 |
|---|---|
| 攻击距离字段 | 返回结构体 `retval+0x4`（float）`writeFloat(orig × KNIFE_RANGE_MULTIPLIER)` |
| 数值合法性校验 | 只有 `orig > 0.3 && orig < 500` 才改写，防脏数据/溢出 |
| 单次捕获 | `myPlayerFound` 置位后跳过重复捕获，防覆盖 |
| 房间切换重置 | 3 个 cleanup Hook（+0xAFAA40/+0xAF5B30/+0xAF15D0）onEnter 清空 `myPlayer`、`myPlayerFound`、计数 |
| 双 Hook 兜底 | `get_KnifeSpeed` 捕获失败不影响主 Hook（try/catch 隔离）；主 Hook 失败整体报错提示重试 |
| 日志限流 | 攻击距离日志最多 10 条；回调异常最多 5 条 |
| 可逆卸载 | `disable()` 先 detach `get_KnifeSpeedHook` 再遍历 `hookHandles` 逐一 detach |

## 作用范围

**仅本地玩家（人类）**。攻击距离数据是武器攻击记录的私有字段，只有 `GetKnifeAttackData` 的 owner 与捕获到的 `myPlayer` 相等时才改写，bot 直接跳过。`GetKnifeAttackData` 是所有近战武器（刀、斧、铲等）获取攻击数据的统一底层函数，团队/生化/个人竞技/挑战模式挥刀必调 → **全模式通用，无武器特判**。

## 产品设计巧思

- **滑块实时调参**：1.0~50.0 倍攻击距离，运行中即时生效。
- **可多功能共存**：特意从 `replace` 改为 `attach`，使本功能与「快刀」（同用 `replace` 的脚本）可同时开启不冲突，用户能自由叠加。
- **切房自动重置**：房间/回合切换自动清空捕获状态，新房间无需重开即可继续生效。

## 开发历程（重点）

### 踩过的坑（问题 → 原因 → 解决）

1. **v8 Hook 点不对，部分模式不生效**
   - 问题：早期 Hook `WPN_Knife.PlayKnifeAttackAnim`(0xB642B0)，部分模式（生化/挑战）不生效。
   - 原因：`PlayKnifeAttackAnim` 是**动画函数**，只覆盖轻击（Combo1/2）；**重击（Bigshot）走 `OnSpecialBtnDown`**(0xB64240)，不经过它；某些模式攻击判定链路直接取数据算伤害，跳过动画函数。
   - 解决：改用 `WPN_Knife.GetKnifeAttackData`(0xB63EC0)——**只要游戏需要知道攻击距离就必然调它**的底层数据函数，无论什么模式、什么攻击类型。
2. **`Interceptor.replace` 与快刀脚本冲突**
   - 问题：原实现用 `replace`，与同时用 `replace` 的快刀（speed_knife_v16）不兼容。
   - 原因：多脚本对同一函数/邻近区域 replace 会互相覆盖。
   - 解决：改为 `Interceptor.attach`（onLeave 就地改写返回结构体字段），与快刀共存。
3. **捕获与应用阶段 owner 偏移不一致**
   - 问题：身份判断时灵时不灵。
   - 原因：捕获阶段 owner 在 `get_KnifeSpeed` 的 `self+0x8`；应用阶段 owner 在 `GetKnifeAttackData` 的 `args[1]+0x30`——同一玩家在两个函数里的偏移不同，拿错就判不中。
   - 解决：分两个偏移分别读 owner：捕获用 `+0x8`，应用用 `+0x30`。
4. **房间切换后 `myPlayer` 残留**
   - 问题：换房后还沿用旧玩家的 `myPlayer`，新房间不生效或误判。
   - 解决：挂 3 个房间切换 Hook（`GameRoundEnd`+0xAFAA40 等）onEnter 清空捕获状态。

### 方案迭代

1. **v8**：Hook `PlayKnifeAttackAnim`(0xB642B0) → 只覆盖轻击、部分模式无效。
2. **v12+/v21**：换 Hook `GetKnifeAttackData`(0xB63EC0)（数据函数，全模式必调）+ `get_KnifeSpeed`(0xB170A0) 旁路捕获 myPlayer → 全模式生效。
3. **v22（最终）**：`replace` 改 `attach` 兼容快刀；通过 `get_KnifeSpeed` onLeave 捕获本地玩家指针，不再自行遍历；加数值合法性校验（orig>0.3 && <500）、3 个房间切换重置 Hook、单次捕获。

### 一开始没考虑到的点

- **"动画函数"≠"数据函数"**：选 Hook 点要选"任何情况下都被调用"的底层数据入口，而不是高层表现函数——重击不走动画、部分模式跳过动画直接取数据。
- **多脚本共存时 `replace` 会冲突**：同区域 replace 互相覆盖，`attach` 更安全。
- **同一玩家在不同函数里的 owner 偏移不同**：捕获 `+0x8` vs 应用 `+0x30`，不能想当然用同一个。
- **攻击距离是浮点字段，要校验数值合法性**再改写，防脏数据/溢出。

### 经验教训

- 选择 Hook 点优先**底层数据函数**（任何路径都会调），别选高层动画/表现函数。
- 多功能共存注意 Hook 手段冲突（`replace` vs `attach`）。
- 捕获"本地玩家指针"用**旁路监听**（get_KnifeSpeed onLeave）比主动遍历更稳。
- 身份判断用的偏移要跟着"所在函数"走，逐函数核对。

## 一句话总结

先用 `get_KnifeSpeed`(+0xB170A0) onLeave 旁路捕获本地玩家（`self+0x8`→isMyPlayer），再在 `WPN_Knife.GetKnifeAttackData`(+0xB63EC0) onLeave 对返回结构体 `+0x4` 攻击距离就地乘 50.0x 写回，只认捕获到的本地玩家（应用侧 owner `+0x30`），带数值校验、单次捕获与 3 个房间切换重置 Hook、可逆卸载；开发关键教训是"动画函数 Hook 覆盖面不足 → 换底层数据函数"、"replace 改 attach 保共存"、"owner 偏移逐函数核对"。
