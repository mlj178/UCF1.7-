# 09｜轻重力 / 高跳（Gravity + Jump）

来源：`features/09_gravity/`（script.js + manifest.json + panel.py）。开发素材：`AAAAA-gravity_modifier-v8.js`（独立版）与整合版 `09_gravity/script.js`。

---

## 核心原理

**一句话**：开一个 50ms 的 `setInterval` 定时器，遍历 GameManager 玩家列表，读每个玩家的 `velocity.y`（重力速度）并按重力倍率/跳跃倍率**就地写回**；再配一个跳跃 Hook 伪造"地面"状态实现空中二段跳 —— 属于"**定时器轮询 + 写内存（velocity.y）**"。

**手段归类**：`setInterval(loop, 50)` 轮询 + 写内存；默认参数 gravity=0.9（滑块 0~1）、jump=5.0（滑块 1~5）、mode=player_only；附加开关 **airJump（空中跳跃）、airMove（空中移动）** 默认开启。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 符号 | 手段 | 用途 |
|---|---|---|---|
| +0xAF9A90 | `GameManager.AddPlayer` | attach | onEnter 捕获 GM 单例、解除房间关闭态 |
| +0xB51780 | `Jump`（跳跃函数） | attach | airJump 时把未落地玩家 `pp+0x70`（grounded）临时写 1，模拟地面触发跳 |
| +0xAF6A00 | `ModeBase.Update` | attach | onEnter 解除房间关闭态 |
| +0xAEE850 / +0xAFB6F0 | `ModeBase.ExitGame` / `GameManager.OnDestroy` | attach | onEnter 进入房间关闭态并清 GM/状态 |
| +0xB55FD0 | `Player.get_isMyPlayer` | NativeFunction | player_only 模式下过滤自己 |
| +0x4A8170 | `singletonGetter` | NativeFunction | 兜底读 GM 单例 |
| 0xE1CE64 | GM 单例 MethodInfo | 数据地址 | 兜底路径读取 GM |

## 数据偏移（相对 Player）

| 偏移 | 字段 | 用途 |
|---|---|---|
| +0x70 | grounded（U8） | 落地标志，判断起跳瞬间 / 被跳跃 Hook 伪造 |
| +0x88 | airMove 浮点 | 空中移动，非落地时写 999999.0 |
| +0x90 | →VelocityData 指针 | +0x10 即 velocity.y（重力速度） |
| +0x9C | →PlayerInput 指针 | +0xC 读 jumpBtn 状态（==2 表示按下） |
| GM+0x1C | 玩家数组 | 长度 +0xC、元素 +0x10+i*8；`hasGm()` 校验总数限 1~64 防越界 |

## 修改逻辑与特殊处理

| 处理 | 实现 |
|---|---|
| 落地→起跳瞬间高跳 | 记录上一帧 `lastGrounded`；`lastGrounded && !isGrounded && curY>0.1` 时 `vy = curY × jumpScale` |
| 下落重力缩放 | `curY < -0.1` 时 `vy = curY × gravityScale`（0.9 → 轻重力） |
| 空中跳跃（airJump） | 轮询读 `playerInput+0xC`，jumpBtn==2 时 `vy = 5.0 × jumpScale`；另用 +0xB51780 Hook 伪造 grounded=1 |
| 空中移动（airMove） | 非落地时 `pp+0x88` 写 999999.0 |
| 参数钳制 | gravity 钳到 [0,1]；jump 钳到 [1,5]；参数无效自动停用 |
| 房间状态守护 | `roomShuttingDown` 标志 + 生命周期 Hook 清理；`hasGm()` 校验 GM+0x1C 有效、总数限 1~64 |
| 双路径取 GM | 优先 AddPlayer Hook 捕获；无则 `singletonGetter(0xE1CE64)` 兜底 |
| 日志限流 | 每 4 秒打一次 vy/grounded/grav/jump 状态 |
| 可逆卸载 | `disable()/resetall()` 清定时器并 detach 全部 Hook，`resetall` 复位所有参数 |

## 作用范围

**默认仅本地玩家（mode=player_only）**；可切到 all 对所有人（含 Bot）生效。`mode !== 'all'` 时只处理 `isMyPlayer(pp)`(+0xB55FD0) 命中的玩家；all 模式无 bot/人类之分，全部玩家统一吃重力/跳跃修改（该数据是每个玩家各自的 VelocityData 私有字段，逐个列表遍历修改）。

## 产品设计巧思

- **滑块实时调参 + 防呆钳制**：gravity(0~1)/jump(1~5) 即时生效，数值被钳制在合法区间，用户把参数拉到底也不会失控。
- **默认参数即达标**：默认 gravity=0.9、jump=5.0，`airJump`/`airMove` 默认开启，开箱即有"轻重力+高跳+空中操作"完整体验。
- **范围可配（仅自己/所有人）**：`mode=player_only`（默认，只改自己）与 `all`（含 Bot）可选，兼顾单人体验与整场效果。

## 开发历程（重点）

### 踩过的坑（问题 → 原因 → 解决）

1. **直接改坐标 → 物理不同步，卡地/穿墙**
   - 问题：一开始想改 `Transform.position` 让角色"飘"，结果瞬移但卡地/穿墙。
   - 原因：改的是"位置结果"，CharacterController 物理状态没跟上。
   - 解决：**放弃改坐标，只改速度**——持续改写 `velocity.y` 实现轻重力/高跳，不动位置。这个方向从头贯彻到底。
2. **跳跃倍率每帧放大 → 高度无限增加、不可控**
   - 问题：不记录接地状态、每帧都对垂直速度乘跳跃系数，角色越跳越高完全失控。
   - 原因：跳跃是"起跳瞬间的一次性事件"，下落过程中也一直乘系数就会无限叠加。
   - 解决：用 `playerState[key].lastGrounded` 记录上一帧接地状态，只在**起跳瞬间**（`lastGrounded && !isGrounded && curY>0.1`）乘一次 `jumpScale`。
3. **重力系数设 0 → 永不落地、浮空失控**
   - 问题：重力系数拉满/设 0 时角色永远不落地。
   - 原因：参数没做限幅。
   - 解决：参数钳制 `gravityScale∈[0,1]`、`jumpScale∈[1,5]`（v8 独立版 jump 上限只到 2.0，整合版放开到 5.0），从源头防溢出。
4. **空中不能连续跳、不能像地面一样移动**
   - 问题：轻重力后有滞空时间，但空中按跳不触发、按方向键移动不顺畅。
   - 原因：游戏只有"接地（grounded）"才放行跳跃和地面移动，空中状态天然受限。
   - 解决：补两个开关——**airJump**（Hook 跳跃函数 +0xB51780，起跳时把 `pp+0x70`(grounded) 临时写 1，伪造在地面放行空中连跳）；**airMove**（非接地时写 `pp+0x88=999999.0`，让"地面移动"判定始终成立，天上如履平地）。
5. **玩家退房后指针残留 → 崩溃**
   - 问题：玩家离开/销毁后，`playerState` 和玩家指针仍保留，下次访问已销毁对象直接崩。
   - 解决：`hasGm()` 每次遍历前校验 `GM+0x1C` 有效；`total` 限 1~64 防越界；GM 失效立即 `gm=null` 并清空 `playerState`；整段遍历 try-catch；整合版再加 `roomShuttingDown` 房间关闭态 + 4 个生命周期 Hook。
6. **进房后 GM 还没被捕获，功能不生效**
   - 问题：只靠 `AddPlayer` Hook 事件捕获 GM，进房后事件没触发时 GM 为空。
   - 解决：**双路径取 GM**——AddPlayer Hook 捕获 + `singletonGetter`(0x4A8170) 读 GM 单例 MethodInfo(0xE1CE64) 兜底，`tryGetGM()` 在定时器循环里主动重试，不依赖运气。

### 方案迭代

1. **v1 思路**：定时器轮询遍历玩家 + 就地写 `velocity.y`——主架构从头保持到尾，从未推翻。
2. **早期错误尝试**：改 `Transform.position` → 物理不同步，放弃 → 确立"**只改速度、不改位置**"原则。
3. **跳跃修正**：从"每帧乘系数"改为"起跳瞬间乘一次"（引入 `lastGrounded` 状态记录），解决无限叠加。
4. **参数钳制**：gravity/jump 加范围限制，防失控。
5. **v8（独立版）**：新增 **airJump**（Hook +0xB51780 伪造 grounded）+ **airMove**（写 +0x88）；空中跳速度硬编码 10.0。
6. **整合版（最终）**：空中跳改为 `5.0×jumpScale`（随滑杆缩放，不再写死）；加 `roomShuttingDown` 房间关闭态 + 生命周期 Hook（`AddPlayer`/`ModeBase.Update` 解除关闭、`ExitGame`/`OnDestroy` 进入关闭并清状态）；`singletonGetter` 兜底取 GM；enable/disable/resetall 可逆卸载。

### 一开始没考虑到的点

- **空中移动/连跳需要"伪造接地状态"而不是只改速度**——airJump/airMove 是后期补的，最初只想到轻重力/高跳本身。
- **GM 单例不能只靠事件时序捕获**，要主动兜底扫描（`singletonGetter` + 0xE1CE64）。
- **房间切换后旧玩家指针全部失效**，需要生命周期 Hook 清理 + 房间关闭态，否则跨房间误用旧指针。
- **"改速度"比"改坐标/改全局物理引擎参数"更稳、副作用更小**——只动 Y 轴，不碰水平速度与物理资源。
- 默认参数定在 gravity=0.9 / jump=5.0（轻重力为主、高跳拉满），airJump/airMove 默认开启。

### 经验教训

- 改玩家运动属性，优先**改"速度/状态"而非"改坐标"**。
- 连续型修改要区分"**瞬间事件**"（起跳乘一次）与"**持续状态**"（下落持续减速），用状态记录避免叠加。
- 所有对外可调参数一律**钳制范围**，防用户/配置把数值搞失控。
- **指针校验 + 生命周期管理**是长期运行不崩的前提。
- 单例/实例捕获要有"**事件捕获 + 主动兜底**"双保险，别依赖时序运气。

## 一句话总结

50ms 定时器遍历玩家列表，就地改写 `velocity.y` 实现轻重力（×0.9）与高跳（×5.0），配合 Jump Hook(+0xB51780) 伪造 grounded 实现空中跳跃，默认只改自己（可切 all），带参数钳制、房间状态守护与可逆卸载；开发核心教训是"改坐标物理不同步 → 只改速度"、"跳跃要区分瞬间事件与持续状态防叠加"、"airJump/airMove 后期补伪造接地"、"GM 捕获要事件 + 主动扫描双保险"。
