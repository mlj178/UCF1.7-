# 34｜角色变身（Role Transform）

**来源**：`04-正式发行版/全功能整合包2.7/game_modifier/features/34_role_transform/`（script.js + manifest.json + panel.py）

> 本文以**整合包 2.7** 的代码为准。`05-正式功能/34-角色变身/` 只保留单功能阶段的开发素材，不作为实现依据。

## 核心原理

- **一句话**：多人生化（nano 模式）里，本地玩家走游戏自带的「大师角色选择」入口 `NanoRoleSelect.OpenMasterRole`（1=英雄 / 0=终结者），人类 Bot 走 `Mode_Nano4_Terminator.BecomeRandomMasterHero`、幽灵 Bot 走 `TryBecomeRandomMasterTerminator`，一次给整个阵营随机变身。
- **手段归类**：RPC 只提交动作，真正的原生调用全部在 `ModeBase.Update` 主线程钩子里执行（原生 UI/角色逻辑都必须在主线程调用）；不自己造角色、不直接改 nanoRole 字段，全部复用游戏原生方法。

## 修改的关键字段

只读为主，不写游戏字段：

| 偏移 | 字段 | 说明 |
|---|---|---|
| GameManager +0x00 / +0x04 / +0x1C | myPlayer / gameMode / allPlayers | 取本地玩家、判断模式、遍历全体玩家 |
| Player +0x1C | healthData | 配合 `get_isDead` 判死 |
| Player +0x94 | clientData | 读 `ClientData.isBot`（+0x1C）区分人机 |
| Player +0xA8 | nanoRoleSelect | 本地玩家选择器的宿主对象 |
| Player +0xD8 | isRespawning | 复活中跳过 |
| Il2CppArray +0x0C / +0x10 | length / items | 遍历 `allPlayers`，最多扫 64 个槽 |

**特殊处理**：
- **模式门控**：`gameMode` 必须在 3~6（nano 模式）才允许执行。
- **Bot 额外的门控**：Bot 变身调用的是 `Mode_Nano4_Terminator` 的私有方法，只有 `gameMode == 6` 时单例才是该类型实例，所以 `bot_hero` / `bot_terminator` 在别的模式下直接拒绝并说明原因。
- **目标筛选**：Bot 必须 `isBot`、非本地玩家、未死亡、不在复活中，并且阵营匹配（英雄→人类 Bot，终结者→幽灵 Bot）。
- **失败要说话**：每一步失败都写明确原因（`not in multiplayer-nano mode` / `NanoRoleSelect is unavailable` / `bot transform requires ...`），状态栏能看到。

## 作用范围

只影响当前房间内的角色选择：本地玩家 2 个按钮、Bot 2 个按钮；不写血量、不改伤害、不改武器数据（武器由游戏变身流程自己发）。退出房间后状态自然回到游戏管理，不跨房间重放。

## 产品设计巧思

- 开关只做门控，四个按钮各管一件事，用户不用理解"阵营"这种内部概念——按钮文字直接写"人类 Bot：随机英雄"。
- Bot 变身一次处理整个阵营，而不是点一次变一个，减少反复点击。
- 变身前把"本地玩家/死亡/复活中"全部排除，避免把人机变成玩家或者把尸体变活。

## 开发历程（重点）

### 踩过的坑

1. **把基类实例当子类用，日志实证 system error**
   - 一开始没考虑到：`Mode_Nano4` 是所有 nano 模式的基类，`Mode_Nano4_Terminator` 只是 gameMode 6 的实例类型。
   - 出问题：在其它 nano 模式点 Bot 变身，拿着基类实例去调终结者的私有方法，直接崩。
   - 怎么修（2.7 P0）：`bot_hero` / `bot_terminator` 增加 `gameMode === 6` 门控，不满足就明确拒绝，不再"试试看"。

2. **测试期望没跟上补丁**
   - 出问题：集成测试断言"运行脚本 = 源脚本 + 两处补丁"，P0 加了第三处门控后测试红。
   - 怎么修：把第三处补丁写进期望值，并用 anchor 计数断言防止替换错位置。

### 方案迭代

- **早期**：想直接改 `PlayerData.nanoRole` 字段。缺点：等于绕过游戏的角色初始化，武器、UI、模式记账全都不跟着走。
- **最终**：本地玩家复用 `NanoRoleSelect.OpenMasterRole`，Bot 复用终结者的随机变身方法，游戏自己把武器和 UI 补齐。缺点：Bot 路径受模式类型限制（gameMode 6）。

### 经验教训

- 调游戏私有方法前，先确认**单例的真实类型**，别拿基类指针当子类用。
- 能复用原生入口就不要直接写字段：变身的连带逻辑（发枪、UI、记账）比一个 int 多得多。

## 一句话总结

本地玩家走 `NanoRoleSelect.OpenMasterRole`、Bot 走 `Mode_Nano4_Terminator` 的两个随机变身方法，动作全部排进 `ModeBase.Update` 主线程执行；关键是模式门控 3~6 且 Bot 变身必须 gameMode 6，否则基类实例被子类方法调用会直接崩。
