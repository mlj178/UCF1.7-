# 31｜定点瞬移（Fixed Point Teleport）

**来源**：`features/31_fixed_point_teleport/`（script.js）+ 开发素材 `05-正式功能/31-定点瞬移/定点瞬移-简要说明.md`

## 核心原理

- **一句话**：Hook `Player.Update` 捕获当前本地 Player，保存时读其 `Transform.position` 存入点位1或点位2，瞬移时调用原游戏 `Player.SetPos(Vector3)`（由原版处理碰撞器禁用/恢复），RPC 只置 pending 动作、真正的保存/瞬移在下次 `Player.Update` 内执行，本质是“调原游戏接口 + 事件驱动消费命令”类方案。
- **手段归类**：Hook 玩家生命周期（Player.Update 捕获/执行）+ NativeFunction 调用 `Player.SetPos` + Transform get_position + 生命周期 Hook 清点。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 符号 | 手段 | 作用 |
|---|---|---|---|
| 0xB551D0 | Player.Update | Interceptor.attach | 捕获本地 Player、消费 pending 保存/瞬移动作 |
| 0xB55FD0 | Player.get_isMyPlayer | NativeFunction | 本地玩家判断 |
| 0xB534C0 | Player.SetPos | NativeFunction | 原游戏瞬移接口（处理 Collider.enabled） |
| 0x32CF40 | Component.get_transform | NativeFunction | 取玩家 Transform |
| 0x3F4280 | Transform.get_position_Injected | NativeFunction | 读取当前坐标用于保存 |
| 0xAF6930 | ModeBase.UpdateTimeUI | attach | 捕获模式实例 / 房间就绪信号 |
| 0xAFAA40 / 0xAEBCB0 / 0xAEBD40 | GameManager.GameRoundEnd / NewGameRoundStart / OnDestroy | attach | 回合结束/新回合仅取消 pending；房间销毁完整清点 |

## 修改的关键字段

| 偏移 | 字段 | 值/说明 |
|---|---|---|
| Player +0x2C | characterController | 供 Player.SetPos 内部读取（不动） |
| （运行时）savedPoints[1/2] | Vector3 坐标 | 脚本自维护的保存点 |
| Player Transform.position | 由 SetPos 改写 | 瞬移目标位置 |

**特殊处理**：
- **RPC 只置 pending**：`savepoint()/teleporttopoint()` 不直接操作，只在下一帧 `Player.Update` 内消费，保证与游戏主线程同步、避免非主线程写游戏对象。
- **绑定 roomGeneration**：点位1、点位2都绑定当前房间 `roomGeneration`；普通回合结束/新回合只取消尚未执行的 pending 动作，`savedPoints` 跨同一房间内的普通回合保留。只有 `mode_base_changed`、房间销毁、关闭功能或 `cleanup()` 才完整清点；其中真正的房间边界会递增 `roomGeneration`，disable/cleanup 则递增运行时 `generation`，切房后旧点不可用。
- **本地玩家持续捕获与校验**：由 `Player.Update` 持续捕获并刷新本地玩家；执行保存或瞬移前校验指针可读性与本地玩家身份，失效时拒绝使用，死亡/重生后在后续 `Player.Update` 中重新捕获。
- **只处理本地玩家**：不处理人机/其他玩家；当前固定支持点位1和点位2，不扩展为任意数量的点位列表。
- **可逆卸载**：disable 时清 `savedPoints` / pending 与缓存，`cleanup()` 时再 detach hooks 并完成同类清理。

## 作用范围

仅本地玩家，当前固定支持点位1和点位2。不自动找地面、不修正高度；只做“当前位置 ↔ 对应保存点”往返，不改 Bot/他人坐标。

## 产品设计巧思

- 两组“保存当前位置 / 瞬移到保存点”操作：`Alt+1` 保存点位1、`Alt+2` 瞬移到点位1，`F1` 保存点位2、`F2` 瞬移到点位2；按钮也提供相同动作，探图/跑图超方便。
- 瞬移走原游戏 `Player.SetPos`，碰撞器自动处理，不会卡墙或坠落穿模。
- 同一房间内跨普通回合保留点位，减少重复保存；模式实例变化、房间销毁、关闭功能或 cleanup 时完整清点，避免跨房“瞬移到上一房间坐标”。

## 开发历程（重点）

### 踩过的坑

1. **直接写 Transform 瞬移风险高**
   - 一开始没考虑到：直接 `Transform.set_position` 会绕过 CharacterController 的碰撞器禁用/恢复逻辑。
   - 出问题：瞬移可能卡进墙里、碰撞状态残留。
   - 怎么修：改调原游戏 `Player.SetPos(Vector3)`——IDA 汇编确认它先关碰撞器、再设位置、最后恢复碰撞器，风险最低。

2. **RPC 非主线程操作游戏对象**
   - 一开始没考虑到：Frida RPC 回调可能不在游戏主线程，直接改坐标/存指针不稳。
   - 出问题：偶发瞬移失败或指针读取异常。
   - 怎么修：RPC 只写 pending（saveSlot/teleportSlot），真正执行放到下一帧 `Player.Update` 主线程内。

3. **切房后旧点失效**
   - 一开始没考虑到：保存点跨房仍被复用，会瞬移到不存在的旧坐标。
   - 出问题：进入另一房间后仍可能尝试瞬移回上一房间的点。
   - 怎么修：保存点绑定 `roomGeneration`，`mode_base_changed` 或 `GameManager.OnDestroy` 触发房间边界清理并递增 `roomGeneration`；死亡/重生后重新捕获本地玩家。

4. **回合边界清理过度，同一房间内保存点也会丢失（整合包 v2.5）**
   - 问题：旧版在 `GameRoundEnd` / `NewGameRoundStart` 做完整重置，导致同一房间进入下一普通回合后也必须重新保存点位。
   - 原因：没有区分“普通回合边界”和“房间边界”，把短暂的回合切换当成了保存点生命周期结束。
   - 怎么修：这两个回合 Hook 现在只清 `pending.saveSlot` / `pending.teleportSlot`，不清 `savedPoints`、不递增 `roomGeneration`；完整清理由 `mode_base_changed`、`GameManager.OnDestroy`、disable 或 `cleanup()` 承担。
   - 经验：回合边界只应取消尚未执行的动作，房间边界才使房间级保存点失效；生命周期粒度不能混用。

5. **F1/F2 在游戏前台时不响应（整合包 v2.5）**
   - 问题：点位2按钮正常，修改器在前台时 F1/F2 也正常，但游戏切到前台后 F1/F2 无响应；把游戏与修改器调成相同权限仍无效。
   - 原因：Tk 局部按键绑定只能覆盖修改器前台，第三方 `keyboard` 全局钩子在当前游戏前台环境中不能可靠接收 F1/F2；这不是 RPC、Frida 脚本或点位2按钮逻辑故障。
   - 怎么修：改用 Windows `RegisterHotKey`，由独立线程处理 `WM_HOTKEY`，并启用 `MOD_NOREPEAT`；若某个按键原生注册失败，则按键级回退到 `keyboard.add_hotkey` 并记录 Windows 错误码，退出或重新应用快捷键时调用 `UnregisterHotKey`，同时删除 Tk 层的重复 F1/F2 绑定。
   - 结果：最终映射为 `Alt+1` 保存点位1、`Alt+2` 瞬移到点位1、`F1` 保存点位2、`F2` 瞬移到点位2；移除 F3、Alt+3、Alt+4。实测游戏位于前台时 F1/F2 均可生效。
   - 经验：游戏前台快捷键应优先使用系统级注册并保留逐键回退与错误码，前台局部绑定不能当作全局热键验证。

### 方案迭代

- **早期（直接写 Transform）**：读当前位置、set_position 瞬移。缺点：绕过碰撞器处理，易卡墙。
- **最终（原游戏 SetPos + 双点位 pending 消费）**：Hook `Player.Update` 按槽消费 pending，调 `Player.SetPos` 瞬移，两个保存点绑定 roomGeneration；普通回合边界只清 pending，房间边界才清保存点。缺点：不做任意数量的点位列表/自动找地（设计边界明确）。

### 一开始没考虑到的点

- 瞬移接口要**复用原版 SetPos**，自己处理碰撞器开关容易遗漏状态。
- RPC 回调与游戏主线程的关系要先确认，动作要延迟到主线程执行。
- 保存点是房间级数据，必须绑定房间生命周期；普通回合边界只清 pending，不能误清同房间仍有效的保存点。
- 点位2的 F1/F2 需要在游戏前台可靠触发，不能只依赖 Tk 局部绑定或第三方全局钩子。

### 经验教训

- 位移类功能优先**调用游戏自身移动接口**，而不是绕过它直接改 Transform。
- 跨线程的命令一律**置 pending + 主线程消费**，避免竞态。
- 任何保存的状态都要想清楚“何时失效”：pending 动作绑定普通回合边界，savedPoints 绑定房间边界，比笼统地统一重置更准确。
- 游戏前台全局快捷键需要系统级注册、清理和失败回退，且要避免与窗口局部绑定重复触发。

## 一句话总结

Hook `Player.Update` 捕获本地玩家并按槽消费 pending 动作，保存时读 `Transform.position` 存入点位1或点位2、瞬移时调原游戏 `Player.SetPos`（碰撞器由原版处理）；`Alt+1` / `Alt+2` 操作点位1，`F1` / `F2` 操作点位2并优先使用 Windows 原生全局注册、注册失败时支持逐键回退，同房间普通回合只清 pending 并保留 `savedPoints`，房间边界才清点并递增 `roomGeneration`，关闭功能或 cleanup 也会完整清点。
