# 01｜无限子弹（Infinite Ammo / Zero Ammo Consumption）

来源：`features/01_ammo/`（script.js）。开发素材：`05-正式功能\01-无限子弹\` 下的 `plan1_memory_lock.js`（内存锁）、`plan2_nop_consume.js`（NOP）、`AAAAA_plan4_replace_consume.js`（最终采用）。

---

## 核心原理

**一句话**：`Interceptor.replace` 替换 `WPN_Gun.ConsumeAmmo` 与基类 `Weapon.ConsumeAmmo`，对本地武器返回 true（假"已扣弹"），但根本不执行扣弹逻辑；RPG/AT4 不走 ConsumeAmmo，单独在 `Fire`/`Reload` 里用 `writeObscuredInt` 把 clip/maxClip 加密写死为 **10**。

**手段归类**：函数替换（假成功真不扣）+ 加密写（ObscuredInt 全结构写入并读回校验），配合 `Interceptor.attach` 兜底 RPG/AT4。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 函数 | 手段 | 作用 |
|---|---|---|---|
| +0xB61140 | `WPN_Gun.ConsumeAmmo` | **Interceptor.replace** | 本地武器→返回 true（不扣弹） |
| +0xB6C310 | `Weapon.ConsumeAmmo`（基类） | **Interceptor.replace** | 兜底，同上 |
| +0xB6E1D0 | `Weapon.get_isMyWeapon` | NativeFunction（bool） | 身份判断路径1 |
| +0xB55FD0 | `Player.get_isMyPlayer` | NativeFunction（bool） | 身份判断路径2（owner 兜底） |
| +0xB670A0 | `WPN_RPG.Fire` | Interceptor.attach | 进入时 FillAmmo + 写 clip=10，离开再补写 |
| +0xB67070 | `WPN_RPG.FillAmmo` | NativeFunction（void） | Fire 前填满 |
| +0xB67C40 | `WPN_RPG.Reload` | Interceptor.attach | reload 离开时写 clip=10 |

## 修改的关键字段

| 偏移 | 字段 | 值 |
|---|---|---|
| `weapon+0xEC` | ammoData（RPG） | 读取，用于写 ObscuredInt |
| `ammo+0x08` 起 | clip（`ObscuredInt`） | 写 **10** |
| `ammo+0x30` 起 | maxClip（`ObscuredInt`） | 写 **10** |
| 身份路径 | `isMyWeapon` / `owner+0x8→isMyPlayer` | 双重验证本地武器 |

**特殊处理（写到具体偏移/数值）**：
- `writeObscuredInt` 全结构写：`+0` 读 key → `+0x4` 写 `value^key` → `+0x8` 写 1（隐藏状态位）→ `+0xC` 写裸 `value` → `+0x10` 写 0（有效位），写后再读 `+0x4` 回读校验是否等于 `value^key`。
- 身份双重校验：优先 `isMyWeapon`，失败兜底读 `owner(+0x8)` 再 `isMyPlayer`；空指针直接 false。
- 全函数 `try-catch` 兜底；`isReadablePtr` 前置校验指针可读。
- 可逆卸载：`Interceptor.revert`（replace）＋ `handle.detach()`（attach）。

## 作用范围

**仅本地玩家（人类）**：`isLocalWeapon(thisPtr)` 为 false（含 bot）时走原逻辑正常扣弹。对所有武器统一生效，**无武器特判**（仅 RPG/AT4 走独立分支）。无限弹药本质是"玩家侧扣弹动作被拦截"，bot 弹药不受影响。

**武器分类说明（谁走 `WPN_Gun.ConsumeAmmo` 路径、谁走 `WPN_RPG.Fire` 兜底）**：

| 武器 | 继承链 | 数据类 | 走哪条路径 |
|---|---|---|---|
| FAL CAMO | `WPN_Gun → Weapon` | `WeaponData_Gun` | 普通枪械路径 → `ConsumeAmmo` 拦截 |
| FN FAL 榴弹版 | `WPN_GrenadeGun → WPN_Gun → Weapon` | `WD_GrenadeGun` | 普通射击走枪械分支 → `ConsumeAmmo` 拦截；**榴弹模式有独立状态与弹药数据**，但**不是** `WPN_RPG` |
| Nano AT4 | `WPN_RPG → Weapon` | `WD_RPG` | **不经过 `WPN_Gun`** → `Fire`/`Reload` 兜底写弹 |

> `WPN_RPG.Fire` 覆盖的是**运行时实例化为 `WPN_RPG`** 的 RPG/AT4 家族（含补给箱 RPG、AT4、Nano AT4），**不包含** FAL CAMO 与 FN FAL 榴弹版。某把外观像发射器的武器是否受影响，最终取决于其运行时类是否为 `WPN_RPG`（继承关系 ≠ 运行时实例化）。

## 开发历程（重点）

### 踩过的坑（问题 → 原因 → 解决）

1. **ObscuredInt 不能直接写裸值（如 9999）**
   - 问题：把 clip 写成裸数字会造成数值异常/闪退或无效。
   - 原因：弹药字段是 `ObscuredInt`（加密整数），裸 `fakeValue` 写入会被解码层覆盖。
   - 解决：V6 经验确立了"必须锁定加密值"的写法。plan1 直接锁定 `hiddenValue`（clip `+0x0C`、ammo `+0x20`）原样写回；plan4 则用 `writeObscuredInt` 一次性写全 key/encrypted/fakeValue 并回读校验。

2. **只 Hook `ConsumeAmmo` 对 RPG/AT4 无效**
   - 问题：RPG/AT4 照常扣弹、打空。
   - 原因：`WPN_RPG` 不在 `ConsumeAmmo` 路径上，发射逻辑内联操作弹药的 ObscuredInt 扣减。
   - 解决：单独 `attach` `WPN_RPG.Fire`(+0xB670A0)，进入时调用 `FillAmmo`(+0xB67070) 填满并写 clip/maxClip=10，`onLeave` 与 `Reload`(+0xB67C40) 再补写一次。

3. **肉搏内存锁方案的状态管理 / 切房失效**
   - 问题：plan1 用定时器轮询写，需要缓存武器指针；切房后指针失效，持续写会导致崩溃。
   - 原因：定时器写的是**缓存的内存地址**，房间/回合切换后对象被重建或释放。
   - 解决：plan1 里 Hook `GameRoundEnd`(+0xAFAA40)/`OnStartRound`(+0xAF5B30)/`NanoStart`(+0xAF15D0) 触发 `clearAll()` 清空白/黑名单；写失败即删除该缓存（防陈旧写）。

4. **改 `.text` 段的风险**
   - 问题：plan2 用 `Memory.protect + writeByteArray` 打 `mov eax,1; ret`（字节 `B8 01 00 00 00 C3`），直接改 `.text`。
   - 原因/风险：改 `.text` 可能触发反外挂 CRC/段校验；切房后补丁可能被重置（需读首字节 `0xB8` 判断是否丢失并重新打）。
   - 解决：最终 plan4 改用 `Interceptor.replace`，纯 Frida 层拦截、**不碰 .text**、无状态（切房天然保持）、可 revert。

5. **无身份判断会波及 bot / 全无效**
   - 问题：不判断就把所有人（含 bot）的扣弹都拦截，或身份判断失败导致完全不生效。
   - 原因：扣弹发生在武器实例上，必须区分该武器是否归属本地玩家。
   - 解决：`isLocalWeapon` 双重路径（`isMyWeapon` → `owner+0x8` 再 `isMyPlayer`）。

### 方案迭代

1. **方案1（内存锁，V6 思路）**：`setInterval` 每 2s 把 `hiddenValue` 原样写回；需缓存武器指针白/黑名单、靠开火函数 hook 发现新武器、切房 `clearAll`。
   - 缺点：有状态（缓存）、定时器轮询、依赖"先开火被发现"、残留指针要清理。是"加密字段原样写回"的雏形。
2. **方案2（NOP ConsumeAmmo）**：patch `.text` 为 `mov eax,1; ret`。
   - 缺点：改 `.text` 有反外挂风险、切房可能被重置需重新校验、无法区分身份、会跳过换弹动画。
3. **方案4（replace ConsumeAmmo，最终采用）**：`Interceptor.replace` 两层 `ConsumeAmmo`，本地武器返回 true 不执行扣弹。
   - 优点：纯 Frida 层（安全）、零性能开销、无状态无需缓存、切房天然保持、可 revert；RPG/AT4 用 attach+加密写补齐。
   - 代价（已知副作用）：武器弹药永不空 → **换弹动画永不触发**。
   - 取舍：改内存（plan1/plan2，有状态/有风险）→ 改函数返回（plan4，无状态/安全），最终选函数返回 + 加密写兜底。

### 一开始没考虑到的点

- **项目符号弹药字段是 `ObscuredInt` 而非普通 int**：需要专门的加密写结构，不能只写一个数字。
- **RPG/AT4 不在 `ConsumeAmmo` 路径**：策划层面以为拦截"扣弹函数"就覆盖所有武器，实际发射器内联扣弹。
- **`.text` 段写补丁的检测/重置风险**：纯 Frida 层 `replace` 更安全。
- **换弹动画副作用**：弹药永不空 → 换弹永不触发，属于设计副作用，需知晓而非回避。
- **切房/换回合缓存失效**：任何"持指针 + 定时器写"的方案都要配生命周期清理。

### 经验教训

- **改内存 vs 调函数**：能"改函数返回值/跳过函数体"就别去"写内存补丁"——前者无状态、安全、可逆、切房天然保持。
- **加密字段必须按结构整全写**：`ObscuredInt` 要 key/encrypted/fakeValue/flag 一起写并**回读校验**，不能只写裸值。
- **身份双重校验**：`isMyWeapon` 为主、`owner→isMyPlayer` 兜底，空指针拦截，防止波及 bot 或全无效。
- **别假设扣弹是唯一路径**：先搞清楚"谁调用/走哪条路径"，再决定 Hook 点（reference/xref 分析）。

## 一句话总结

`Interceptor.replace` 包 `WPN_Gun.ConsumeAmmo`(+0xB61140) 与基类(+0xB6C310)让本地武器"假扣弹真不扣"，RPG/AT4 用 `Fire`/`Reload` attach + `writeObscuredInt` 写 clip/maxClip=10 兜底；从"内存锁定时器(plan1)"到"NOP .text(plan2)"再到"replace(plan4)"一路迭代，最终选无状态、安全的函数替换，附带加密结构与身份双重校验的踩坑经验。
