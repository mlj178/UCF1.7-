# 30｜调整伤害倍率（Damage Multiplier）

**来源**：`features/30_damage_multiplier/`（`script.js` + `panel.py` + `manifest.json`）+ 开发素材 `05-正式功能/30-增加伤害倍率/伤害来源分类与倍率可行性.md`

## 核心原理

- **一句话**：两段式 Hook `GameManager.TakeDamage`（入口段，枪/雷/技能/炮台）与 `Entity.OnEntityHurt` / `Player.OnEntityHurt`（收尾段，刀），在 x86 cdecl 栈上定位按值传入的 `DamageEventData`；先把 `attacker`（或导弹/炮台的 owner）解析成真正的伤害来源，再按阵营分成 **self（自己）/ mate（队友）/ enemy（敌人）**，各自乘对应倍率后写回 `damage`。倍率可调高（>1.0x）也可调低（<1.0x），最低 `0.1x`，**不允许 0**。
- **手段归类**：Interceptor.attach + 栈参数定位（DamageEventData 按值传入）+ owner 映射表 + 玩家/阵营缓存 + 生命周期 Hook 清理。
- **口径**：最终生命伤害 = 这一击的原始伤害 × 倍率（再受游戏自身的防御率、剩余血量上限约束），**与目标剩余血量无关**。

## 阵营判定口径

伤害来源按队伍关系分类，口径与游戏自身的 `ExpandUtil.IsSameTeam` / `IsEnemy` 完全一致（IDA 反编译核对）：

| 判定 | 游戏实现 | 本功能用法 |
|---|---|---|
| 本地玩家 | `Player.get_isMyPlayer` | `isLocalPlayer(attacker)` 为真 → self |
| 同队 | `IsSameTeam(a, b) = a!=2 && b!=2 && a==b` | team 相同且都不是 Neutral(2) → mate |
| 敌对 | `IsEnemy(a, b) = a==2 \|\| b==2 \|\| a!=b` | 其余已知来源 → enemy |
| 无法判断 | —— | 不计入任何阵营，跳过不修改 |

队伍字段是 `Entity.team`（`+0x20`）。玩家列表通过 `GameManager.allPlayers`（`+0x1C` 数组）、`playersBL`（`+0x20` List）、`playersGR`（`+0x28` List）建立缓存，缓存只用来**定位本地玩家**；`team` 本身在每次判定时**实时读取**，不吃缓存快照。

### 变身 / 换队（人类 ↔ 生化幽灵）怎么处理

游戏换角色时会同步换队伍（IDA 反编译 `ModeBase_Nano.UpdateNanoRole`）：

```c
int Team = NanoRoleExpand.GetTeam(newRole);  // 人类 = GlobalRisk(1)，幽灵/终结者 = BlackList(0)
player.set_nanoRole(newRole);
if (player.team != Team) player.SetTeam(Team);   // 变身当帧就改 Entity.team
```

并且 `Player.get_isNanoGhost()` 的实现本身就是 `team == BlackList`——游戏自己就是**用 team 定义谁是幽灵**的。

所以本功能的阵营判定跟着游戏走，会随变身自动切换，不需要额外配置：

| 你的状态 | 谁算「队友」 | 谁算「敌人」 |
|---|---|---|
| 人类（GlobalRisk=1） | 其他人类 | 幽灵/终结者（BlackList=0） |
| 生化幽灵（BlackList=0） | 其他幽灵/终结者 | 人类 |
| 中立（Neutral=2） | 没有（不与任何人同队） | 除自己以外所有人 |

- **自己**这一行永远是你（`Player.get_isMyPlayer`），变身不影响。
- 判定用**实时 team**，所以变身当帧就生效，不会出现"刚变幽灵还被当成人类队友"的两秒窗口。
- 若某个模式里所有人都是 `Neutral(2)`（例如自由混战），那"队友"这一行不会命中任何人，只剩下敌人分类——这与游戏自身的 `IsSameTeam` 口径一致。

| DamageEventData +0x3C / +0x40 | wpnIndex / wpnSprIndex | 武器索引判断 |

| Entity +0x1C → HealthData +0x08 / +0x0C | currentHealth（ObscuredInt） | **只读**：解密 `hidden ^ (key \|\| 0x6C81C)`，用于刀的「致死一击不削弱」判定 |

## 三个倍率与三个分组开关

| 配置键 | 默认 | 说明 |
|---|---|---|
| `enemy_multiplier` | `1.0` | 敌人造成的伤害倍率 |
| `self_multiplier` | `2.0` | 自己造成的伤害倍率 |
| `mate_multiplier` | `1.0` | 队友造成的伤害倍率 |
| `enemy_enabled` | `true` | 敌人这一行是否生效 |
| `self_enabled` | `true` | 自己这一行是否生效 |
| `mate_enabled` | `true` | 队友这一行是否生效 |
| `min_multiplier` / `max_multiplier` | `0.1` / `10.0` | 作用域钳制，**最低 0.1，不允许 0** |

- 兼容旧配置：老的单倍率键 `multiplier` 会自动映射成 `self_multiplier`，且 `self_multiplier` 优先。
- `skip_local_victim` 语义收窄为「只拦自己打自己」：仅当阵营是 self、且 victim 也是本地玩家时跳过（例如自己的手雷炸自己），**不会**再拦敌人/队友打本地玩家。

## 特殊处理

- **两段式分工**：`GameManager.TakeDamage` 入口只乘非刀伤害（钳血之前）；`Entity/Player.OnEntityHurt` 收尾段只乘刀伤害（`CalKnifeDmg` 会重写刀伤）。入口钩子安装失败时自动退回「全部在收尾段处理」。
- **防二次修改（playerHurtDepth）**：`Player.OnEntityHurt` 会调用基类 `Entity.OnEntityHurt`，用深度计数让同一调用链内的 `Entity.OnEntityHurt` 跳过，避免刀伤害被乘两次。
- **owner 映射 + TTL**：missile/炮台 owner 记录带 15s 过期（ownerTtlMs）；命中时先按 owner 解析真实来源，再判阵营。
- **玩家缓存 + TTL**：玩家列表缓存 2s，遇到未知 attacker 时限频（1s）强制刷新一次；缓存为空时阵营判定退回直接读 team 字段。
- **伤害类型过滤**：默认放大/缩小 Gun/Knife/Grenade 并允许 Other（特殊技能），Infect（生化感染）默认不参与，可配置 `include_infect`。
- **作用域钳制**：每个倍率 0.1–10.0、damage ≤ 999999。
- **安全读字段**：team 用 Frida 直接读内存（非法地址抛 JS 异常可捕获），比调 NativeFunction 更不容易崩进程。
- **统计与限频**：记录各阵营乘算次数、各跳过原因（unknown_attacker / category_disabled / self_victim / invalid 等）便于诊断。
- **可逆卸载**：回合结束/新回合/房间销毁时清空 owner 映射与玩家缓存，disable 时 detach 全部 hooks。

## 为什么必须分两段乘（2026-11 修复：斩杀线几何衰减）

游戏真正扣血前的链路（IDA 反汇编 `GameManager.TakeDamage`，RVA `0xAFC1C0`）：

```text
data.damage（原始伤害）
  → intDamage = (int)(data.damage × victim.damageRate)      ; 受害者防御率
  → damage = Mathf.Max(0, Mathf.Min(intDamage, 剩余血量))   ; ★ 先钳到剩余血量
  → victim.OnEntityHurt(data)                                ; 旧 Hook 点
      → (int)data.damage → HealthData.Hurt
```

也就是说，`OnEntityHurt` 里拿到的 `damage` 已经是 `min(伤害, 剩余血量)`。

如果在这里乘 `<1` 的倍率：

- 血量充足（剩余血量 > 原始伤害）：`最终 = 原始 × 倍率`，线性，正常。
- 到达斩杀线（剩余血量 ≤ 原始伤害）：`最终 = 剩余血量 × 倍率`；下一击又按新的剩余血量算 → **血量几何级衰减**，永远逼近 0 却不到 0；只有「保底 1 点」让它在 1 滴血时才能被打死。实测日志：同一把武器在 0.1x 下连续命中，`raw_damage` 是 19→18→15→12（这是目标剩余血量，不是武器伤害），每发只掉 1 点。

修复：把乘倍率提前到钳血之前。

- **入口段**：`GameManager.TakeDamage` 入口（`data` 在 `esp+4`，`damage` 在 `esp+0xC`）先乘倍率，游戏随后才做防御率和钳血 → `最终 = min(原始×倍率×防御率, 剩余血量)`，与剩余血量无关。
- **收尾段**：刀继续留在 `OnEntityHurt`。因为生化模式 `ModeBase_Nano.PreDamageEvent` 会调 `CalKnifeDmg`，按攻击者 NanoRole 把刀伤**重写**成固定值（1000/1500/2500/3000/8000…），入口段乘的倍率会被覆盖；只有在最后一步乘才保得住。同时刀在收尾段如果发现 `data.damage >= 剩余血量`（游戏已经把它钳成致死一击），就不再削弱，避免刀也出现几何衰减。

> 诊断字段：`pre_cap_hook_installed` / `pre_cap_multiplied` / `post_cap_multiplied` / `skipped_lethal_capped` / `victim_hp_read_failures`；日志 `damage_diag` 增加 `stage=` 与 `victim_hp=`。

## 保底 1 点伤害（重要，v2.1 修复）

游戏扣血是在 `Entity.OnEntityHurt` 里把 float 伤害**截断成 int** 之后才做的（IDA 反汇编）：

```asm
movss  xmm0, [ebp+eventData.damage]   ; 读 float damage
cvtps2pd xmm0, xmm0
cvttsd2si eax, xmm0                   ; float -> int，向零截断
push   eax
call   HealthData.Hurt                ; currentHealth -= value，无任何下限钳制
```

后果：倍率 <1 时，只要 `damage * 倍率 < 1.0`，游戏收到的是 **0 点伤害**。当目标只剩 1 点血时，最后一击被截断成 0，就会表现为「敌人一直打不死人、永远剩一滴血」。旧版倍率下限是 1.0，所以从没触发过这个问题。

修复：原始伤害 ≥ `min_applied_damage`（默认 1.0）时，乘完倍率后保底到 `min_applied_damage`，保证一击至少造成 1 点伤害；原始伤害本来就 <1 的不动（游戏本来就会截断成 0，不能反向加伤）。状态里 `floored_to_min` 记录被保底的次数。

> 两段式改造后，保底仍然保留：
> - 入口段（枪/雷等）保底的是「原始×倍率」；游戏随后还会 ×`damageRate`。正常 `damageRate=1.0` 时最终仍是 1 点；带减伤 Buff（`damageRate<1`）的受害者仍可能被游戏自身防御截断成 0，这属于游戏防御机制，和改动前乘在最后一步时的表现略有差异。
> - 收尾段（刀）的保底语义不变。

## 作用范围

三个阵营各自独立作用，默认只有「自己」是 2.0x，敌人和队友都是 1.0x（等于不改变游戏原样）。把敌人调到 0.2x 就是削弱敌人输出，把队友调到 2x 就是增强队友输出；任何一方调到 1.0x 都等于原版。无法判断归属的伤害、无效/0/负伤害不修改。

## 产品设计巧思

- 不是「全场倍率」，而是三个可分别开关的阵营倍率：想只增强自己就关掉敌人/队友两行，想顺手削弱敌人就单独把敌人拉低。
- 倍率可升可降：1.0x 是原版，低于 1.0x 是削弱；数值按颜色区分（蓝=削弱、灰=原版、橙=增强），避免用户误以为只能调高。
- 最低 0.1x 而不是 0：保留「几乎免伤/几乎免伤输出」的玩法，同时避免 0 造成伤害流程异常。
- 覆盖范围广：枪、刀、手雷、RPG/AT4/榴弹、炮台/守卫的 owner 都能映射回玩家再判阵营。
- 默认避开感染伤害，生化玩法不被破坏。

## 开发历程（重点）

### 踩过的坑

1. **玩家伤害被放大两次**
   - 一开始没考虑到：`Player.OnEntityHurt` 会调用基类 `Entity.OnEntityHurt`，两个 Hook 各自放大一次。
   - 出问题：本地玩家造成的伤害明显高于设置倍率（平方级）。
   - 怎么修：引入 `playerHurtDepth`，Player 入口期间同一调用链的 Entity.OnEntityHurt 跳过不二次修改。

2. **RPG/AT4/榴弹/炮台等特殊来源放大不到**
   - 一开始没考虑到：这些伤害的 `attacker` 不是玩家本体（是 missile/炮台）。
   - 怎么修：Hook `WPN_Missile.SetOwner` / `SentryGun.SetData` 记录 owner 映射，命中时按 owner 回查；v2 里 owner 解析改成对所有来源都做，再判阵营。

3. **DamageEventData 栈定位与字段偏移**
   - 按值传入 x86 cdecl 栈，字段偏移与实例布局不同；按 dump.cs + IDA 汇编核对栈布局（attacker/victim/damage/type…）。

4. **感染伤害（Infect）被误放大破坏生化玩法**
   - 默认 `include_infect=false`，Infect 类型跳过，可配置放开。

5. **v2 三分类新增的坑：怎么可靠区分队友和敌人**
   - 一开始只想着比 team 字段，但 `Neutral(2)` 在多个模式里被当作敌对处理。
   - 怎么修：与游戏自身的 `ExpandUtil.IsSameTeam` 完全对齐——只有两边都不是 2 且相等才算队友；并用 GameManager 玩家列表建立缓存找本地玩家，避免每个伤害事件都遍历。

6. **倍率 <1 时把最后一击压成 0，敌人打不死人**
   - 现象：敌人倍率调到 0.6x 后，敌人无法击杀玩家和队友，目标一直剩 1 点血。
   - 原因：`Entity.OnEntityHurt` 用 `cvttsd2si` 把 float damage 截断成 int 再传给 `HealthData.Hurt`，`damage < 1` 等于 0 点伤害；`HealthData.Hurt` 只做整数相减，没有下限钳制。
   - 怎么修：新增 `min_applied_damage`（默认 1.0），原始伤害 ≥1 时乘完倍率保底 1 点。

7. **倍率 <1 到达斩杀线时血量几何衰减，必须磨到最后一滴血**
   - 现象：开启伤害降低、滑块 <1.0 后，目标血越少这一击伤害越小；最后每发只掉 1 点，要磨到 1 滴血才击杀。
   - 原因：`GameManager.TakeDamage` 在调用 `OnEntityHurt` 之前就执行了 `min((int)(damage×damageRate), 剩余血量)`；旧实现把倍率乘在这个"已钳血"的值上，等于每击只扣剩余血量的百分之几。
   - 怎么修：枪/雷/技能/炮台改到 `TakeDamage` 入口乘（钳血之前）；刀因为 `CalKnifeDmg` 会把刀伤按角色重写，留在 `OnEntityHurt` 并对致死一击不削弱。

### 方案迭代

- **v1（旧版）**：只放大「本地玩家造成」的伤害，其余一律跳过。
- **v2（当前）**：解析真实来源 → 按 self/mate/enemy 三分类 → 各自倍率；新增玩家/阵营缓存、三个分组开关、倍率下限 0.1x，支持调低。

## 一句话总结

枪/雷/技能/炮台在 `GameManager.TakeDamage` 入口（游戏钳血之前）乘倍率，刀在 `Entity/Player.OnEntityHurt` 收尾段乘；先把 attacker（或其 missile/炮台 owner）解析成真实来源，再按 `Entity.team` 与 `IsSameTeam` 口径分成自己/队友/敌人，各自乘 0.1x–10x 的独立倍率；用 playerHurtDepth 防二次修改、玩家缓存找本地玩家、Infect 默认排除，倍率可升可降但不允许 0。最终生命伤害只由原始伤害和倍率决定，与目标剩余血量无关。
