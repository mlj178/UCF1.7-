# 20｜时间加速（Timescale）

**来源**：`features/20_timescale/`（script.js）+ 开发素材 `05-正式功能/20-Unity时间加速/经验总结.md`、`AAAA-game_template.js`、`AAAA-ui_template.py`

## 核心原理

- **一句话**：不 Hook 任何函数，而是定位 `Time.timeScale` 变量的真实内存地址直接 `writeFloat` 改写，本质是“定位变量 + 直接写内存”类方案（因为没有 `set_timeScale` setter，也无需函数调用时机）。
- **手段归类**：`il2cpp_resolve_icall` 解析 icall → 反汇编引擎函数机器码提取变量地址 → 定时/事件驱动的内存写入 + ABI `mscdecl`。

## 关键 Hook 表（GameAssembly.dll / UnityPlayer.dll）

| 地址/符号 | 目标 | 手段 | 作用 |
|---|---|---|---|
| `il2cpp_resolve_icall`（GameAssembly.dll 导出） | 解析 icall | NativeFunction 调用 | 拿 `UnityEngine.Time::get_timeScale()` 的真引擎函数指针 |
| 引擎函数机器码（UnityPlayer.dll） | `fld [eax+0xEC]` / `movss [eax+0xEC]` | 反汇编字节 | 提取结构体偏移 0xEC，定位 timeScale 地址 |
| 0xAF6A00 | ModeBase.Update | Interceptor.attach | 主线程/稳定房间时应用倍速 |
| 0xAEE850 | ModeBase.ExitGame | attach | 退出房间封锁状态 |
| 0xAFB6F0 | GameManager.OnDestroy | attach | 场景销毁开始封锁 |

## 修改的关键字段

| 偏移 | 字段 | 值/说明 |
|---|---|---|
| `structPtr + 0xEC` | `Time.timeScale`(float) | 写入目标倍速（钳制 0.1–10.0）；恢复时写 1.0 |

**特殊处理**：
- **数值钳制** `normalizeSpeed`：非有限数回落、下限 0.1、上限 10.0、保留一位小数。
- **地址合法性校验**：`hasMemoryProtection` 查地址 >0x10000、内存页可读（写时需可写 w）、区域覆盖写 4 字节；`isPlausibleTimeScale` 校验值 0–100；写前全部通过才 `writeFloat`。
- **结构体模式不缓存最终地址**：`TimeManager` 实例可能随场景重建，只缓存 `helperAddr + offset`，每次写前重新调 helper 取最新实例再 +0xEC（类比 gravity 的 tryGetGM）。
- **地址失效自动重初始化**：`safeWriteTimeScale` 若解析/校验失败，`resetInitCache` 后重新 `initTimeScale()` 再试。
- **房间/模式就绪门控**：`_modeReadyAt = now + 750ms`；退出房间时 `beginRoomShutdown` 封锁，切房宽限期后才应用，防止在 tear down/不稳定期写无效地址。
- **主线程节流重试**：`processPendingTimeScaleWrite` 由 ModeBase.Update 驱动，失败后 `REAPPLY_INTERVAL_MS=1000` 重试，成功记 `_lastApplyAt`。
- **可逆卸载**：disable 时置 `_restorePending`，`_pendingSpeed=1.0`，可选立即 `restoreNormalTimeScaleNow()` 写回 1.0；cleanup 时置 `restoreNow:true`。
- **倍速预选**：未开启时 `setSpeed` 只存预选值，开启后生效。
- **初始化不在场景切换瞬间直调函数验证**：改用机器码解析 + 内存页校验确认地址，规避切房瞬间调游戏原生函数的不稳定。

## 作用范围

全局无区分（`Time.timeScale` 影响整个 Unity 场景的时间流速，所有玩家/Bot/动画全局共享）。数据不是某个玩家私有，而是引擎级全局状态。

## 产品设计巧思

- 输入想加速的倍速即可，滑块/输入即时生效，不依赖回合或武器状态。
- 退出房间/切场景自动停止并在新房间恢复，不用手动反复开关。
- 关功能自动把时轴写回 1.0，不遗留加速状态。

## 开发历程（重点）

### 踩过的坑

1. **`unable to find method 'setTimeScale'`**
   - 一开始没考虑到：Frida Python 绑定会把 `snake_case` 转 `camelCase`。
   - 出问题：Python 调 `set_time_scale()` → Frida 找 JS 的 `setTimeScale`，可 JS 定义的是 `set_time_scale`，找不到报错。
   - 怎么修：JS `rpc.exports` 方法名一律用 camelCase。

2. **`invalid abi specified`**
   - 一开始没考虑到：Frida 不认识 `'cdecl'` 这个 ABI 字符串。
   - 出问题：实例化 NativeFunction 直接报错。
   - 怎么修：Windows 32 位 cdecl 正确值是 `'mscdecl'`。

3. **从 GameAssembly.dll 桩函数找不到 `fld [addr]` 模式**
   - 一开始没考虑到：GameAssembly 里的 `get_timeScale` 是**延迟解析桩**（`cmp/jnz/push offset .../call il2cpp_resolve_icall/add esp,4/mov/jmp`），没有真正的 `fld` 指令。
   - 出问题：按旧经验去桩函数里搜 `fld dword ptr [imm32]` 搜不到。
   - 怎么修：改用 `il2cpp_resolve_icall` 直接拿引擎 DLL（UnityPlayer.dll）里的真实实现函数，再去分析引擎函数机器码。（解析的 DLL 划分：GameAssembly 拿 icall，UnityPlayer 找变量）

4. **引擎函数不是全局变量模式，而是结构体成员模式**
   - 一开始没考虑到：只匹配了 `D9 05`（`fld [imm32]` 全局变量），实际是 `call GetTimeManager(); fld dword ptr [eax+0xEC]`。
   - 出问题：识别不到地址。
   - 怎么修：新增 `call + fld[eax+disp32]` 模式匹配——E8 取 helper、D9 80 取偏移 0xEC，调 helper 拿实例指针再 +0xEC 得 timeScale 地址。

### 方案迭代

- **最初（找 setter/Hook）**：想 Hook `set_timeScale`，但 dump.cs 确认 `Time` 只有 `get_timeScale` 没有 setter；Hook `get_timeScale` 只改返回值，游戏内部读取值不变，效果不完整。
- **中间（搜桩函数机器码）**：在 GameAssembly 桩里搜 `fld [imm32]` 全局变量模式，发现桩函数没有浮点加载，走不通。
- **最终（icall 解析 + 引擎机器码 + 直写内存）**：`il2cpp_resolve_icall` → UnityPlayer 真函数 → 按“call+fld[eax+disp]”结构体模式定位 → 直写 float，并配合定时/事件驱动刷新与恢复。

### 一开始没考虑到的点

- ICall 桩函数 vs 真引擎函数：解析后跳到的是别的 DLL，分析对象错了搜不到指令。
- 引擎函数可能走**结构体成员**（`call helper + [eax+offset]`）而非全局变量（`[imm32]`），匹配模式需覆盖 `D9 05 / D9 80 / F3 0F 10 05 / F3 0F 10 80` 四种。
- `TimeManager` 实例指针会随场景重建——不能缓存最终地址，要缓存 helper+offset 每次重取。
- 刷新间隔 500ms vs 5s 影响不大：游戏并不每帧重写 timeScale，只在特定时机（场景加载/暂停恢复）设置，写在目标值后基本保持到游戏主动改回。

### 经验教训

- **定位变量直写内存（icall 反汇编）** 适合“无 setter、全局状态”的场景，比 Hook 返回值彻底。
- 区分**桩函数（lazy stub）与真实现（引擎 DLL）**：icall 类要解析到真函数再分析。
- 引擎代码可能用 `D9 / F3 0F` 多种浮点加载字节，分析要覆盖 global 与 struct 两种寻址。
- 对会重建实例的结构体成员，**缓存 helper+偏移**而非最终地址，每次现取实例指针。

## 一句话总结

因 `Time.timeScale` 没有 setter，放弃 Hook 而改走 `il2cpp_resolve_icall` 解析到 UnityPlayer 真引擎函数、反汇编机器码识别出“call helper + [eax+0xEC]”结构体模式定位变量再直接写 float，配合房间就绪门控与恢复 1.0，实现了可逆的全局时间加速；坑集中在 icall 桩/真函数之分、ABI 拼写与结构体成员寻址。
