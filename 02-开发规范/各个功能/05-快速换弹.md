## 核心原理

GUN 与 RPG 的实现路径完全不同，必须分别处理：

| 武器 | 换弹入口 | 时长由谁决定 | 本功能手段 |
|---|---|---|---|
| WPN_Gun 系 | WPN_Gun.Reload(0xB62CB0) | 每次换弹算 GetAnimSpeed(reloadAnimRatio) × PlayerWeapons.ReloadSpeed → CFAnimator.SetFloat("ReloadSpeed", v) | Interceptor.replace CFAnimator.SetFloat，把 v 乘倍率 |
| WPN_RPG | WPN_RPG.OnReloadBtnDown(0xB67AF0) | 只播放 "reload" 动画，**不写 "ReloadSpeed"**（该参数只在 Deploy 的 AnimSpeedSetting 写一次，RPG 换弹不吃它） | 换弹前把武器/手部 Animator.speed 设为倍率，动画结束复位 1.0 |

两类换弹结束都是「reload 动画播完」事件 → 缩短动画即缩短换弹。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 函数 | 手段 | 作用 |
|---|---|---|---|
| +0xB34E40 | CFAnimator.SetFloat(this, name, value, character, method) | **Interceptor.replace** | GUN：对 "ReloadSpeed" 乘倍率 |
| +0xB6E1D0 | Weapon.get_isMyWeapon(this) | NativeFunction bool | 只处理本地玩家的武器 |
| +0xB67AF0 | WPN_RPG.OnReloadBtnDown(this) | Interceptor.attach | RPG：设 Animator.speed |
| +0xB67640 | WPN_RPG.OnAnimationEnd(this, animName, animTag) | Interceptor.attach | 换弹结束（tag=="reload"）复位 */
| +0xB67030 | WPN_RPG.Deploy(this) | Interceptor.attach | 重新部署复位 |
| +0xAA8C30 | UnityEngine.Animator.set_speed(animator, value, method) | NativeFunction void(pointer,float,pointer) | 改动画器速度 |
| +0xB67C40 | WPN_RPG.Reload | —— | **死代码，无任何调用点，不要挂钩子** |
| +0xB170E0 | PlayerWeapons.get_ReloadSpeed | —— | v1 落点，已弃用（只覆盖 GUN） |

## 关键字段

| 偏移 | 字段 | 说明 |
|---|---|---|
| Weapon+0x30 | owner（Player*） | 归属判断 / 取手部动画器 |
| Weapon+0x68 | data（WeaponData*） | 与 +0xF0 比较，用于判定 RPG |
| WPN_RPG+0xF0 | realData（WD_RPG*） | 与 +0x68 指向同一实例 → RPG 判定依据 |
| CFAnimator+0x40 | animator（UnityEngine.Animator*） | RPG 换弹时改 speed |
| Player+0x5C → +0x4C | characterModel → handAnimator | RPG 第一人称换弹动画 |
| WeaponData_Gun+0xD4 | reloadAnimRatio | GUN 换弹动画倍率（只读） |
| WD_RPG+0xEC | reloadAnimRate | RPG 换弹动画倍率（只读） |

## 作用范围

- 模式：无限制。
- 武器：WPN_Gun 系（步枪/冲锋枪/狙击/手枪/霰弹/榴弹枪）+ WPN_RPG（火箭筒 / AT4 / Nano AT4）。
  投掷 / 一次性 / 哨戒炮 / 近战不涉及。
- 仅本地玩家：bot 与其他玩家不变速。
- 叠加：多人生化人类「快速换弹」BUFF（attribute_Human.id == 15）×2.5 只作用于 GUN 链；
  RPG 不受该 BUFF 影响，最终倍率就是滑块值。
- RPG 的 Animator.speed 一定会在换弹结束 / 重新部署 / 关闭功能 / 5s 看门狗四个时机之一复位，
  不会残留导致后续动作一直加速。

## 参数

| 名称 | 范围 | 默认 | 说明 |
|---|---|---|---|
| multiplier | 1.0 ~ 5.0（步进 0.1） | 4.0 | 1.0 = 不加速；滑块拖动即时生效 |

manifest.controls 声明 slider（key=multiplier）；panel.py 自绘滑块行并返回
ui_handles.slider_var / slider_label 供 app 回填配置。

## 开发历程（重点）

### 踩过的坑

1. Hook get_isInfinityAmmo() 无效：只被 HUD_Weapon.Update 调用，纯 UI 显示。
2. IL2CPP bool 返回值要用 "int" 传 1/0。
3. v1 用 get_ReloadSpeed 只覆盖 GUN，且覆盖式返回值会冲掉原生 BUFF → 改为在最终值上乘。
4. **v2：RPG 仍然无效**，原因三层：
   a. WPN_RPG.Reload(0xB67C40) 是死代码，挂在上面的"参数刷新"从不执行；
   b. RPG 的换弹动画不吃 "ReloadSpeed" 参数（该参数只在 Deploy 写一次）；
   c. 日志辅助函数每模块只放行 10 条，实测恰好被前面的消息用完，
      AT4 测试阶段一条日志都没有 → 误以为"钩子没命中"。诊断日志改走 log_file 通道后解决。
   → 最终 RPG 改用 Animator.speed 方案，并在参数路径里显式跳过 RPG，避免倍率平方。
5. 2.7/2.8 早期：originalGetReloadSpeed 漏写 var → Frida 17 严格模式 ReferenceError，
   enable() 在装 Hook 前中断，功能 100% 不生效，而 UI 乐观更新不回滚 → 表现为"开关开着没效果"。
   现在所有跨闭包变量显式 var，enable() 失败会回传 {ok:false, reason}。

### 经验教训

- 同一语义可能有多条实现路径（GUN / RPG），要按"谁最终消费这个值"分流。
- "函数存在"不等于"函数被调用"：改之前先扫全 DLL 的 call 指令确认调用点。
- 日志要有独立通道，且不能被 UI 层限流吞掉，否则排查时是瞎的。
- 能乘就不要覆盖；改动画器速度必须在结束/打断/重部署时复位。

## 一句话总结

GUN 用 Interceptor.replace 包住 CFAnimator.SetFloat(+0xB34E40)，对 "ReloadSpeed" 乘倍率；
RPG 在 WPN_RPG.OnReloadBtnDown(+0xB67AF0) 里把武器与手部 Animator.speed 设为倍率，
换弹结束/重新部署/关闭/8s 看门狗复位；倍率 1.0~5.0 由滑块下发。
