# 05｜快速换弹（AmmoPlus / Fast Reload / 换弹加速）

来源：`features/05_ammoplus/`（script.js + manifest.json + panel.py）。开发素材：`AAAAA-infinite_ammo_rapid_reload_test.js` 及原换弹方案对比文档。

---

## 核心原理

**一句话**：`Interceptor.replace` 替换 `PlayerWeapons.get_ReloadSpeed` getter，本地玩家固定返回 **4.0** 倍换弹速度，其余返回 **1.0**（原速）。

**手段归类**：返回值篡改（固定放大）—— `Interceptor.replace` + `NativeCallback`（签名 `float`，入参 `['pointer']`），纯开关、无参数可调。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 函数 | 手段 | 作用 |
|---|---|---|---|
| +0xB170E0 | `PlayerWeapons.get_ReloadSpeed` | **Interceptor.replace** | 换弹速度 getter，被整体替换 |
| +0xB55FD0 | `Player.get_isMyPlayer` | NativeFunction（`bool` `['pointer']`） | 判断 owner 是否本地玩家 |

## 修改的关键字段

| 偏移 | 字段 | 值 |
|---|---|---|
| `PlayerWeapons+0x8` | owner（`Player*`） | 读取用于身份判断 |
| `PlayerWeapons+0x3C` | `Modifier_ReloadSpeed`（`PropertyModifier`） | 换弹速度来源（参照字段） |
| get_ReloadSpeed 返回值 | 换弹倍率 | 本地玩家 **4.0x**；其余 **1.0x** |

注：脚本注释与成功日志写"2x"，但回调实际 `return 4.0`，以实际为准。

## 作用范围

**仅本地玩家（人类）**：`isMyPlayer(owner)` 为 false（含 bot）走 else 分支返回 1.0 原速。对所有调用 `get_ReloadSpeed` 的武器统一生效，**无武器特判**。`PlayerWeapons` 为核心类 → **全模式通用**。空 owner/异常兜底返回 4.0（null 对象也会被加速，潜在小风险）。

## 产品设计巧思

- **换武器自动继承**：改的是玩家级属性 getter（`get_ReloadSpeed`），任意武器换弹都统一加速、切换武器自动继承，全模式通用，用户无需逐把武器设置。
- **无参纯开关**：不设可调参数（固定 4.0），开即是"标准最快档"，用户无需纠结调参。

## 开发历程（重点）

### 踩过的坑（问题 → 原因 → 解决）

1. **Hook `get_isInfinityAmmo()` 无效**
   - 问题：Hook `PlayerWeapons.get_isInfinityAmmo`(0xB17120) 返回 true 后，UI 显示无限符号，但弹匣照样打空、打空后无法继续射击。
   - 原因：该 getter **只被 UI(HUD) 调用**用于显示无限符号；射击逻辑 `WPN_Gun` 不调它，直接操作 `AmmoData.clip` 字段。Hook 它只改 UI 显示，不影响实际弹药消耗。
   - 解决：删除该无效 Hook（2026-05-23 删除记录）。教训：**判断功能要看谁在调用它（xref），不能只看名字像不像**。

2. **IL2CPP bool 返回值不能用 `"bool"` 类型**
   - 问题：`NativeCallback` 返回类型写 `"bool"`、回调 `return true`，报错 `expected an integer`。
   - 原因：IL2CPP 的 bool 在原生层以 **int** 表示。
   - 解决：返回类型写 `"int"`，用 `return 1`（true）/`return 0`（false）；float 返回值才用 `"float"`。

3. **快速换弹对玩家判断失败 / 波及 bot**
   - 问题：不加身份判断时，换弹加速要么对所有人（含 bot）生效，要么完全无效。
   - 原因：getter 的 `self` 是 `PlayerWeapons`，owner 在 `self+0x8`；必须用 `Player.get_isMyPlayer`(+0xB55FD0) 判定本地玩家。
   - 解决：`owner = self.add(0x8).readPointer()` → `isMyPlayer(owner)` 为 true 才返回加速倍率，否则返回 1.0；空 owner/异常兜底返回加速值，加 try-catch 防崩。

4. **Hook 地址/函数名对不上导致无效**
   - 原因：RVA 地址或函数名写错时功能不生效（或静默失败）。
   - 解决：先 IDA 反编译定位准确 RVA，再用 dump.cs 核对类结构与字段偏移；必须进实际游戏模式验证。

### 方案迭代

1. **方案A（武器级，早期）**：Hook `GunShoot_NoCheck`（每次射击时），从 `self+0xEC` 读 `realData`（`WeaponData_Gun*`），把 `reloadAnimRatio`（偏移 **0xD4**，装填动画速度比例）写 **5.0**（校验当前值 0~100 之间才写）。
   - 缺点：只对**当前持有的武器**生效，换武器/重新触发才生效；本质是一次性内存写入。
2. **方案B（玩家级，最终采用）**：`Interceptor.replace` 替换 `PlayerWeapons.get_ReloadSpeed`(+0xB170E0)，每次游戏查询换弹速度时对本地玩家返回固定倍数（脚本 2.0，整合包实际 **4.0**），其余 1.0。
   - 优点：**所有武器统一、切换武器自动继承**；符合游戏"通过属性 getter 取加成"的设计模式，是更优雅的实现。
3. **对比结论**：方案A 改**数据**（武器级 reloadAnimRatio），方案B 改**属性访问器**（玩家级 get_ReloadSpeed）；后者全局生效、代码更贴合游戏设计 → 采用 B。

### 一开始没考虑到的点

- **`get_isInfinityAmmo` 只是 UI 显示层**：以为返回 true 就是真无限弹匣，实际它是纯 UI 效果、不参与射击逻辑——分析功能要看**谁在调用它**。
- **通用 BUFF 字段定义在 Player/PlayerWeapons 核心类**：生化专属的 `Mode_Nano4_Terminator`、`attributeAsset`、`attribute_Nano/Human`、`AddPropertyModifier` 只存在于生化模式；但 `PlayerWeapons.Modifier_ReloadSpeed`(0x3C)、`Player.Buff_InfinityAmmo`(0x128)、`Player.Modifier_MoveSpeedRatio`(0x8C) 等定义在核心类中，**所有模式都有** → 一开始局限于生化模式，后来发现直接用核心类字段即可迁移到全模式。

### 经验教训

- 方案对比要看"修改层次"：武器级（单武器、需重新触发）vs 玩家级（全局、切换自动生效），优先选更贴合游戏设计的属性 getter。
- IL2CPP 返回 bool 的 Hook 一律用 `"int"` 类型、返回 1/0。
- 判断功能"是否真有效"必须进实际游戏模式实测（UI 符号 ≠ 实际效果）。
- Hook getter 通用模板：`owner = self.add(0x8)` → `isMyPlayer(owner)` → 本地玩家返回自定义值 / 其他返回默认值，全程 try-catch 兜底。

## 一句话总结

`Interceptor.replace` 包住 `get_ReloadSpeed`(+0xB170E0)，用 `isMyPlayer`(+0xB55FD0) 判定 owner：本地玩家固定返回 4.0、其余 1.0，带空指针/异常兜底与可逆卸载；走过的弯路是"UI 显示 Hook(get_isInfinityAmmo) 无效"、"IL2CPP bool 用 int 返回"、以及"武器级改数据 vs 玩家级改 getter"的迭代，最终选玩家级属性 getter。
