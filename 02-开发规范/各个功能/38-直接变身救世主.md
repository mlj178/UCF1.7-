# 38｜直接变身救世主（Become Savior）

**来源**：`04-正式发行版/全功能整合包2.7/game_modifier/features/38_become_savior/`（script.js + manifest.json + panel.py + events.py）

> 本文以**整合包 2.7** 的代码为准。`05-正式功能/38-直接变身救世主/` 只保留单功能阶段的开发素材，不作为实现依据。

## 核心原理

- **一句话**：多人生化里把目标的 `nanoRole` 从佣兵（`Soldier = 0`）直接改成救世主（`Savior = 18`），再用 `GameManager.GiveWeapon` 发救世主专属武器（ID 4270）；本地玩家和人类人机各一个按钮。
- **手段归类**：一次性动作 + 主线程排水。RPC 只置 pending，所有原生调用在 `ModeBase.Update` 钩子里执行一次后即清。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 符号 | 手段 | 作用 |
|---|---|---|---|
| 0x00AF6A00 | `ModeBase.Update` | Interceptor.attach | 主线程排水口 |
| 0x00E2933C / 0x004A8170 / 0x00E1CE64 | `GameManager` TypeInfo / `Singleton.get_instance` / MethodInfo | NativeFunction + 静态字段 | 取 GameManager |
| 0x00B467A0 | `Mode_Nano4.get_instance3` | NativeFunction | 取 nano 模式实例（改角色的宿主） |
| 0x00AF4FF0 | `ModeBase_Nano.UpdateNanoRole` | NativeFunction | 真正把角色改成救世主 |
| 0x00AFB390 | `GameManager.GiveWeapon` | NativeFunction | 发救世主武器 4270 |
| 0x00B55FD0 | `Player.get_isMyPlayer` | NativeFunction | 认定本地玩家 |
| 0x00B56200 | `Player.get_nanoRole` | NativeFunction | 读当前角色（失败时退回读 `PlayerData.nanoRole`） |
| 0x00AE4830 | `HealthData.get_isDead` | NativeFunction | 跳过死亡目标 |

## 修改的关键字段

| 偏移 | 字段 | 说明 |
|---|---|---|
| GameManager +0x00 / +0x04 / +0x1C | myPlayer / gameMode / allPlayers | 取本地玩家、模式判断、遍历人机 |
| Player +0x1C / +0x94 / +0x98 | healthData / clientData / playerData | 判死、判人机、读角色 |
| ClientData +0x1C | isBot | 只处理人机 |
| PlayerData +0x60 → +0x00 | nanoRole（`SubscribeableProperty`） | `get_nanoRole` 不可用时的兜底读取 |

**特殊处理**：
- **模式门控**：`gameMode` 必须在 3~6（nano 模式），否则拒绝并说明原因。
- **角色门控**：只有 `nanoRole == 0`（佣兵）才能变；已经是救世主（18）时不再改角色，只补一次武器；其它角色（英雄/终结者）直接跳过。
- **死亡/复活中**跳过，Bot 只处理 `isBot` 且非本地玩家。
- **部分成功也算成功**：角色改成功后如果发枪失败，不整体判负，日志写 `role set, weapon failed`——用户至少能变身。
- **跳过日志限频**：同一个 `nanoRole` 只记一次，避免每点一次刷屏。

## 作用范围

只影响目标角色与随身武器：不改血量、不改伤害、不改阵营。仅在多人生化相关模式（gameMode 3~6）生效；退出房间不跨房间重放。

## 产品设计巧思

- 两个按钮直接写"玩家变身救世主 / 人类人机变救世主"，不要求用户理解 `nanoRole` 编号。
- 已经变身成功后再点不会重复改角色，只补枪，避免反复改状态导致动作重置。
- 固定快捷键 `Alt+A`（玩家）/ `Alt+S`（人机），战斗中手不用离开鼠标。

## 开发历程（重点）

### 踩过的坑

1. **只改字段不补枪**
   - 一开始没考虑到：救世主的强度一半在专属武器上。
   - 出问题：变身后站着没枪，或者还拿着原来的武器。
   - 怎么修：改完角色立刻 `GiveWeapon(4270, autoSelect=1)`，游戏自己完成切枪。

2. **重复变身把状态打乱**
   - 出问题：对已经是救世主的目标再走一次"改角色"，部分动作会重置。
   - 怎么修：先读 `nanoRole`，等于 18 时只补枪、不改角色。

3. **`get_nanoRole` 偶发读不到**
   - 出问题：某些时机方法调用失败，导致误判"不是佣兵"。
   - 怎么修：失败时退回读 `PlayerData.nanoRole` 的 `SubscribeableProperty.value`。

### 方案迭代

- **早期**：想直接调 `Mode_Nano4_Terminator.BecomeSavior`。缺点：该入口对当前角色有额外前置状态要求，走不通时没有任何反馈。
- **最终**：`UpdateNanoRole(18)` + `GiveWeapon(4270)` 两步走，各自 try/catch，部分成功可解释。

### 经验教训

- 变身类功能一定要把"改角色"和"给装备"拆开，任何一步失败都要能说清失败在哪一步。
- 读不到状态时要有兜底路径（方法读不到就退回读字段），否则判定会误杀。

## 一句话总结

`nanoRole 0 → 18` 用 `UpdateNanoRole` 改、再 `GiveWeapon(4270)` 补枪，动作在 `ModeBase.Update` 主线程执行；已是救世主只补枪、部分成功要能解释、模式必须 3~6。
