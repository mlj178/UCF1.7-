# 32｜亮度调节（Brightness Adjustment）

**来源**：`features/32_brightness_probe/`（script.js）+ 开发素材 `05-正式功能/32-亮度调节探针/亮度调节探针-经验记录.md`

## 核心原理

- **一句话**：不走屏幕覆盖层提亮，而是走 Unity URP 真实后处理参数：取 `Camera.main` → `GetUniversalAdditionalCameraData` → `volumeStack.GetComponent<ColorAdjustments>`，直接读写 `postExposure/contrast/saturation` 的 `VolumeParameter`；当相机 `volumeStack` 为空时兜底走 `CameraManager.volumeProfile → VolumeProfile.components → ColorAdjustments`，本质是“定位 URP 后处理对象并改 VolumeParameter”类方案（探针态，验证参数层可控）。
- **手段归类**：固定 RVA → 原生方法主动调用（GetUniversalAdditionalCameraData / UpdateVolumeStack / VolumeStack.GetComponent）+ 指针链遍历（VolumeProfile.components → List） + VolumeParameter 读改写。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 符号 | 手段 | 作用 |
|---|---|---|---|
| 0x328310 | Camera.get_main | NativeFunction | 获取主相机 |
| 0x490500 | CameraExtensions.GetUniversalAdditionalCameraData | NativeFunction | 读取 URP 相机附加数据 |
| 0x490820 | CameraExtensions.UpdateVolumeStack | NativeFunction | 尝试刷新 VolumeStack |
| 0x7D3570 + 0xE24EEC | VolumeStack.GetComponent<ColorAdjustments> + MethodInfo | NativeFunction | 获取颜色调节组件 |
| 0x7D3570 + 0xE24FE8 | VolumeStack.GetComponent<LiftGammaGain> + MethodInfo | NativeFunction | 获取 Gamma/Gain 组件 |
| 0xE263C0 | CameraManager_TypeInfo | 指针链 | 从全局 CameraManager 侧兜底找 VolumeProfile |

## 修改的关键字段

| 偏移 | 字段 | 值/说明 |
|---|---|---|
| UniversalAdditionalCameraData +0x4C | volumeStack | 读取当前 VolumeStack |
| CameraManager +0x10 | volumeProfile | 相机栈为空时兜底读取全局 Profile |
| VolumeProfile +0x0C | components（List） | 遍历组件找 ColorAdjustments |
| ColorAdjustments +0x1C / +0x20 / +0x2C | postExposure / contrast / saturation | 曝光/对比度/饱和度（VolumeParameter<float>） |
| LiftGammaGain +0x20 / +0x24 | gamma / gain | 中间调/亮部增益（Vector4Parameter，只写 w 分量） |
| VolumeParameter +0x08 / +0x0C | overrideState / floatValue | 让参数覆盖生效 / float 参数值 |

**特殊处理**：
- **双路线兜底**：优先 `Camera.main → volumeStack → ColorAdjustments`；失败则自动走 `CameraManager.volumeProfile → components → ColorAdjustments`（`UpdateVolumeStack` 先尝试刷新栈）。
- **只写 w 分量**：Gamma/Gain 是 Vector4Parameter，保留原 RGB 分量只写 `.w`，降低破坏原调色的风险。
- **overrideState 置位**：改参数同时把 `VolumeParameter.overrideState` 置 1 让覆盖生效。
- **原值记录与恢复**：应用前记录首次读到的原始值（float + Vector4），“恢复初始值”/disable/cleanup 时写回。
- **探针态**：写入能读回只证明参数层可控，最终是否影响画面需游戏内目测确认。
- **小写 RPC 别名 + 顺序调用**：JS 同时导出驼峰名与小写别名，UI 固定 `setconfig/applybrightness/resetbrightness`，并用顺序调用避免 `rpc_busy` 跳过。

## 作用范围

全局画面（主相机 URP 后处理），对所有玩家/Bot 视角一致；不修改 ESP/ImGui/D3D Hook，不做覆盖层滤镜。

## 产品设计巧思

- 曝光/对比度/饱和度/Gamma/Gain 五个滑块实时调，玩家按需提亮画面（暗图/夜间场景更清晰）。
- “恢复游戏初始值”一键还原，不会把调色永久留在游戏里。
- 优先真实后处理而不是叠滤镜，观感接近原生亮度调节，不糊画面。

## 开发历程（重点）

### 踩过的坑

1. **Frida RPC 方法名大小写不匹配**
   - 一开始没考虑到：JS 导出 `setConfig`，Python `exports_sync` 侧按小写 `setconfig` 查找。
   - 出问题：UI 调用 RPC 找不到方法。
   - 怎么修：同时导出驼峰名和小写别名，UI 固定调用小写。

2. **UI 连续两次独立 RPC 被 rpc_busy 跳过**
   - 一开始没考虑到：先“配置”再“应用”两次独立调用，第一个调用会设置 `rpc_busy`，第二个被跳过。
   - 出问题：参数没真正应用。
   - 怎么修：改为 `_call_rpc_sequence()` 顺序执行。

3. **`volumeStack is null` 不等于不可行**
   - 一开始没考虑到：`Camera.main` 的 `UniversalAdditionalCameraData.volumeStack` 为空，但 `CameraManager.volumeProfile` 可能仍有组件。
   - 出问题：首次实机探针返回 `volumeStack is null`，差点误判功能不可行。
   - 怎么修：新增兜底路线 `CameraManager.volumeProfile → VolumeProfile.components → ColorAdjustments`，探针同时返回 `cameraManagerVolumeProfile` 供判断。

4. **Gamma/Gain 是 Vector4Parameter，直接写破坏原调色**
   - 一开始没考虑到：`LiftGammaGain.gamma/gain` 是 Vector4 参数，整体覆写会破坏原 RGB 调色。
   - 出问题：调 Gamma 后画面颜色整体偏移。
   - 怎么修：保留原 RGB 分量，只写 `.w`（Vector4Parameter.w）。

5. **只改参数不置 overrideState 不生效**
   - 一开始没考虑到：URP Volume 参数需要 `overrideState=true` 才会覆盖默认值。
   - 出问题：写入后画面无变化。
   - 怎么修：写参数时同步置 `VolumeParameter.overrideState=1`。

6. **后处理可能未开启（renderPostProcessing）**
   - 一开始没考虑到：URP 相机需开启后处理才会消费这些参数。
   - 出问题：参数可写但画面不变化。
   - 怎么修：探针记录 `renderPostProcessing`，失败时建议强制开启相机后处理再试。

### 方案迭代

- **早期（只走 Camera.main → volumeStack）**：一次探针发现 `volumeStack is null`。
- **中期（加 CameraManager.volumeProfile 兜底）**：栈为空也能找到 ColorAdjustments。
- **最终（双路线 + 参数/恢复完善）**：UpdateVolumeStack 刷新 + profile 兜底 + overrideState 置位 + Gamma/Gain 只写 w + 原始值恢复 + 小写 RPC 别名与顺序调用。

### 一开始没考虑到的点

- Frida RPC 导出名与 Python 查找名的大小写约定不一致。
- UI 侧连续 RPC 会被 rpc_busy 跳过，需要顺序封装。
- 相机栈为空不代表没有 URP 后处理，还有全局 VolumeProfile 兜底路线。
- Vector4 参数（Gamma/Gain）不能整体覆写，要按分量写。
- URP 参数生效依赖 overrideState 与 renderPostProcessing。

### 经验教训

- 探针类功能**先验证参数层可达**再谈效果，`null` 结果要区分“不可行”与“换条路”。
- 后处理链路有“相机栈 / 全局 Profile”两条数据源，定位失败要主动兜底。
- 写参数要考虑**覆盖开关（overrideState）与消费前提（renderPostProcessing）**，否则白写。
- RPC 层要统一大小写约定 + 顺序调用封装，避免 UI 层踩坑。

## 一句话总结

走 URP 真实后处理：`Camera.main → GetUniversalAdditionalCameraData → volumeStack.GetComponent<ColorAdjustments>` 读写 postExposure/contrast/saturation，栈为空时兜底 `CameraManager.volumeProfile → components`，Gamma/Gain 只写 w 分量并置 overrideState；踩坑集中在“RPC 大小写/rpc_busy”“volumeStack 为空误判不可行”“Vector4 整写破坏调色”“overrideState/renderPostProcessing 未置位”，最终以双路线兜底 + 原值恢复 + 顺序调用收尾。
