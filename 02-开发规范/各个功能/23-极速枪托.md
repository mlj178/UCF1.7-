# 23｜极速枪托（Fast Gunstock）

**来源**：`features/23_fast_gunstock/`（script.js）+ 开发素材 `05-正式功能/23-极速枪托/经验总结.md`、`极速枪托-最小实现步骤.md`、`AAAAA-fast_gunstock_v3_1_formal_safe.js`

## 核心原理

- **一句话**：不加速动画，而是在 `WPN_Gun.OnSpecialBtnDown` 放行右键后，预约 100ms 主动调用 `KnifeAttackEvent` 提前出伤害、再延迟 40ms 主动调用 `OnKnifeAttackExit` 并清 `knifeAttackAnim` 状态锁，压缩“右键→伤害”节奏，本质是“主动注入伤害事件 + 就地清状态锁”类方案。
- **手段归类**：Hook 右键入口 + 定时器预约主动调用原生函数 + attach-only（不 replace）+ 状态锁写内存。

## 关键 Hook 表（GameAssembly.dll）

| RVA | 符号 | 手段 | 作用 |
|---|---|---|---|
| 0xB629F0 | WPN_Gun.OnSpecialBtnDown | Interceptor.attach(onEnter) | 右键枪托入口：放行 + 预约提前伤害 |
| 0xB62730 | WPN_Gun.KnifeAttackEvent(int index) | attach + NativeFunction 主动调用 | 记录/触发真实伤害事件 |
| 0xB62990 | WPN_Gun.OnKnifeAttackExit | attach + NativeFunction 主动调用 | 解锁时让原游戏清自身状态 |
| 0xB62800 | WPN_Gun.OnAnimationExit | attach | 原游戏动画退出回调（仅观察） |
| 0xB6E1D0 | Weapon.get_isMyWeapon | NativeFunction 调用 | 判断是否本地玩家武器 |

## 修改的关键字段

| 偏移 | 字段 | 值/说明 |
|---|---|---|
| WPN_Gun +0x118 | knifeAttackCount | 只读，判断是否有枪托攻击 |
| WPN_Gun +0xEC | realData（WeaponData_Gun） | 只读，访问 knifeAttacks |
| WeaponData_Gun +0x180 | knifeAttacks 数组 | 只读，数组长度 >0 判定有枪托 |
| WPN_Gun +0x11C | knifeAttackAnim（状态锁） | 解锁时写 0；防打断时写 1 |

**特殊处理**：
- **时序预约**：`earlyDamageDelayMs=100`（提前伤害）、`unlockDelayMs=40`（解锁）、`maxGuardMs=900`（最大保护窗口，超时强制恢复）、`observeNaturalAfterUnlockMs=250`（解锁后观察自然重复伤害）。
- **attach-only 不 replace**：`KnifeAttackEvent` 只 attach 记录，不改写伤害逻辑。
- **防打断保护**：上一击未解锁时再次右键，先把 `knifeAttackAnim` 置 1 防动画重播打断伤害，等当前攻击结束。
- **状态锁残留清理**：开始前发现残留锁（`knifeAttackAnim!=0`）先自动清 0，避免被游戏挡掉。
- **自然/提前双路径**：原游戏自然 `KnifeAttackEvent` 先到则走自然路径排解锁；提前伤害调用带 `manualCallingDamage` 标记防自触发。
- **可逆卸载**：disable/cleanup 时 `forceClear` 清当前攻击状态、清锁、detach 全部 hooks；关闭/异常/强制恢复都清状态锁。
- **身份校验**：`isMyWeapon` 只处理本地玩家武器；`hasKnifeAttack` 判定无枪托的枪直接跳过。
- **日志限流**：每模块 3 条上限。

## 作用范围

仅本地玩家（本地武器）。`OnSpecialBtnDown/KnifeAttackEvent/OnKnifeAttackExit/OnAnimationExit` 都先过 `isLocalWeapon` 才处理；不含人机/其他玩家。

## 产品设计巧思

- 倍率/节奏参数由 UI 预设并随开关即时生效，无需改脚本。
- 关闭或异常时自动清掉状态锁，避免枪托卡死不动。
- 只对带枪托的本地武器生效，普通刀、左键射击、无枪托枪不乱触发。

## 开发历程（重点）

### 踩过的坑

1. **右键入口提前清 `knifeAttackAnim`，点太快时伤害被取消**
   - 一开始没考虑到：第一次枪托还没走到伤害事件（`KnifeAttackEvent`），第二次右键已经重播动画。
   - 出问题：上一下伤害被取消，动作变快但实际打不出伤害。
   - 怎么修：不再在入口清锁；让原游戏先走完 `KnifeAttackEvent`，只在确认伤害触发后、动画退出阶段才清锁（v3.0 思路），最终 v3.1 改为“预约提前伤害 + 40ms 后主动解锁”。

2. **动画加速后伤害判定不完全跟动画速度走**
   - 一开始没考虑到：`Animator.speed` 提速只让动画播放更快，伤害事件不一定按动画节奏提前。
   - 出问题：动作明显变快但伤害频率没变快（视觉效果与伤害不同步）。
   - 怎么修：v3.1 放弃改 `Animator.speed`，改为直接预约调用 `KnifeAttackEvent`（100ms）主动出伤害，节奏由定时器控制而非动画速度。

3. **状态锁残留导致右键被挡**
   - 一开始没考虑到：切武器/异常中断后 `knifeAttackAnim` 可能残留非 0。
   - 出问题：之后右键枪托失效。
   - 怎么修：`OnSpecialBtnDown` 开始时检测残留锁自动清 0；最大保护窗口 900ms 兜底强制恢复。

### 方案迭代

- **v1-v2（Animator.speed 动画加速）**：右键时把角色/手部 Animator.speed 设高倍，让动画播快。缺点：动作快但伤害频率不跟动画走；改全局动画易误伤其他动作。
- **v3.0（动画加速 + 状态锁清锁）**：补清 `knifeAttackAnim` 提升连击。缺点：入口清锁导致点太快时动画重播、伤害被取消。
- **v3.1（最终：提前伤害 + 主动解锁，安全版）**：完全放弃动画加速，`attach-only` 不 replace；右键后 100ms 主动调 `KnifeAttackEvent` 出伤害，再 40ms 主动调 `OnKnifeAttackExit` + 清锁，配 900ms 保护窗口与防打断置锁；只影响本地武器、无枪托枪跳过。

### 一开始没考虑到的点

- “加速”不一定只靠动画：伤害事件本身可以**主动提前触发**，比加速动画更直接、更可控。
- 状态锁（`knifeAttackAnim`）是节奏的真正闸门，清锁时机（何时清/谁清）决定会不会打断伤害。
- `attach-only`（观察 + 主动调用）比 `replace` 安全：不重写原逻辑，出问题只需 detach。

### 经验教训

- 对“重复瞬间事件”类功能，用**定时预约提前触发**比改动画速度可靠，且可精确控制节奏。
- 状态锁类字段要**想清楚生命周期**：谁负责置位、谁负责清位、异常时兜底清位，否则残留锁会“卡死”功能。
- 同一功能从“改全局速度”演进到“只改目标实例 + attach-only”，稳定性显著提升。

## 一句话总结

从“Animator.speed 动画加速”（伤害不跟节奏、易误伤）演进到 v3.1“右键后 100ms 主动调 `KnifeAttackEvent` 提前伤害 + 40ms 主动解锁清 `knifeAttackAnim`”，attach-only 不 replace，配 900ms 保护窗口与防打断置锁，实现只对本地带枪托武器的极速枪托且完全可逆。
