# 23｜极速枪托（Fast Gunstock）

**来源**：`features/23_fast_gunstock/script.js`（2.7 实际运行 **v3.2「原始伤害完成后解锁」**）+ 开发素材 `05-正式功能/23-极速枪托/经验总结.md`、`极速枪托-最小实现步骤.md`、`AAAAA-fast_gunstock_v3_1_formal_safe.js`
**文档版本**：2026-10-20 按 2.7 实际代码（v3.2）校正。注意：v3.1 的「右键后 100ms 主动补伤害 + 40ms 主动解锁 + 入口清残留锁」**已废弃**，只在「方案迭代」里保留作历史，不再代表当前行为。

## 核心原理

- **一句话**：不改动画速度、不伪造伤害；右键放行后等游戏自己的 `KnifeAttackEvent` 完整返回，立刻调用 `OnKnifeAttackExit` 把 `knifeAttackAnim` 清 0，将原本「动画播完才解锁」提前到「伤害事件完成即解锁」，从而缩短下一次右键的间隔。
- **手段归类**：Hook 右键入口 + attach-only 观察伤害事件 + 伤害完成后主动调用游戏清锁函数 + 状态锁写内存（正常解锁只写 0；防打断时写 1）。
- **明确不做**：不 replace 任何游戏函数；不主动调用 `KnifeAttackEvent`；不改 `Animator.speed`；不合并 v2.9 的动画加速。

## 当前版本行为（v3.2）

1. `OnSpecialBtnDown` onEnter：过身份/本地武器/枪托数据校验后 `startAttack` 记录本次攻击；上一击未解锁时进入防打断保护。
2. `KnifeAttackEvent` onLeave（自然伤害）：`unlockAttack` → 调用 `OnKnifeAttackExit` → `knifeAttackAnim=0`，并进入 250ms 观察窗。
3. 900ms 内没等到伤害事件：定时器只置 `pendingForceUnlock`，由主线程 `ModeBase.Update` 下一帧执行强制解锁（Frida 定时器线程不能直接调游戏函数）。
4. 看门狗 1200ms：脚本自己写进去的锁最多保留 1.2s，超时由 `ModeBase.Update` 归还。
5. 角色变化（`Player.set_nanoRole`）、生化幽灵、关闭/清理：归还自写锁并清运行态。
6. `disable` 只同步归还自写锁、清 JS 运行态，**不挂 pending、不补调游戏函数**；Hook 保留到 `cleanup` 才 detach，且每个回调第一步都判 `st.enabled`。
7. `enable` 先 `resetRuntime`，不带上一轮状态。

## 正常/异常时序

- **正常**：右键 → 游戏起手并置 `knifeAttackAnim=1` → 约 170ms 后 `KnifeAttackEvent` → 立即 `OnKnifeAttackExit` 清 0 → 可再次右键。
- **防打断**：`st.current` 未解锁时再次右键 → `protectReentry`；若当前锁为 0 则写 1，等上一击结束。
- **入口发现残留锁**：`knifeAttackAnim != 0` → **拒绝本次右键并记日志，不主动清 0**（与 v3.1 相反，避免清锁导致动画重播、伤害被取消）。
- **幽灵**：硬门控直接不生效，先归还自写锁，再清 `current`。
- **关闭**：归还自写锁、清运行态；没打完的一击交回游戏自己的 `OnAnimationExit → OnKnifeAttackExit` 清理。

## 已知边界（v3.2，2026-10-20 实测）

- **「攻击没有真正起手」无法区分**：切枪掏枪期间 `_currentAnimTag == "Select"`，游戏侧 `OnSpecialBtnDown` 因 `isSelecting` 拒绝起手，但脚本 onEnter 在游戏判断之前就已经 `startAttack`，把这个没发生的攻击记成「等待伤害」；`OnAnimationExit:select/empty` 又按「伤害事件前到达，暂不解锁」忽略，只能等 900ms 兜底。
- 实测日志：20:23:53.518 右键 → 20:23:54.434 强制解锁，**916ms**；游戏 select 在 53.903（385ms）已结束，脚本多锁了约 530ms。
- **跨武器**：上一把枪未结算就切枪，新枪右键的防打断锁会写到新枪上；旧枪的 900ms 解锁清不到它，最坏要等 1200ms 看门狗。
- 结论：切枪后第一下右键会被放大成约 **0.9~1.2s** 的不可用窗口。同类行为在 2.6 已存在（同样是 `startAttack` + `protectReentry` + 900ms 窗口）；2.7 只是把强制解锁改到主线程下一帧执行，所以日志里是 916ms ≈ 900ms + 一帧。**不要只靠调小 `maxGuardMs` 掩盖**。
- 2026-10-20 已实施最小修复（第 3 条）：`select` 退出立即取消，上述 916ms 路径已消除；跨武器 1200ms 路径与入口预防（第 1、2 条）仍待做。

## 后续修复方向（第 3 条已实施；1、2 待做；常量保持 900/1200）

> **最小修复已实施（2026-10-20）**：第 3 条 `OnAnimationExit:select` 且未出伤害时立即取消，直接消掉本次日志 916ms 里多出来的约 530ms。第 1、2 条是预防同类问题，完整修复再一起做。

1. 入口先判 `CFAnimator.get_isSelecting`(0xB353D0)：为 true 就**不** `startAttack`，让游戏自己拒绝这一下。
2. `st.current` 与武器绑定：右键的武器与 `st.current.weapon` 不同时，丢弃旧状态、不写新枪的保护锁。
3. 【已实施】`OnAnimationExit` 收到 `select` 且 `!damageDone` 时立即 `unlockAttack`，不再死等 900ms。**只认 `select`，不认 `empty`/`run`**（`run` 在真实攻击起手后 3ms 就到，认了会误杀）。
4. 以上落地后，900/1200 只作异常兜底，稳定运行一段时间后再评估降到 600/900ms；不要低于 500/800ms（正常解锁仍由约 170ms 的伤害事件完成，不依赖该窗口）。

## 开发历程

### 踩过的坑

1. **右键入口提前清 `knifeAttackAnim`，点太快时伤害被取消**
   - 第一次枪托还没走到 `KnifeAttackEvent`，第二次右键已经重播动画；动作变快但打不出伤害。
   - v3.0 的入口清锁因此被撤掉；v3.2 改为「入口发现残留锁只拒绝、不清 0」。
2. **动画加速后伤害判定不跟动画速度走**
   - `Animator.speed` 只让画面变快，伤害事件不提前，视觉与伤害不同步；v3.1 起放弃改动画。
3. **状态锁残留导致右键被挡**
   - 切武器/异常中断后 `knifeAttackAnim` 可能残留非 0。v3.1 在入口清 0；v3.2 改为拒绝 + 900ms 兜底 + 1200ms 看门狗，优先保证不打断真实攻击。
4. **切枪 select 期右键被误判为攻击**
   - 见「已知边界」；这是当前版本最大的误伤点，也是后续修复方向 1~3 的来源。
5. **在 Frida 定时器线程直接调游戏函数**
   - 会闪退/卡死。v3.2 改为只置 pending，由 `ModeBase.Update` 在主线程执行。
6. **Weapon 对象池复用**
   - 变身时旧武器被回收，内存可能复用成别的武器类；解锁前必须核对 `klass` + `m_CachedPtr`，否则会对刀等对象越界写 `+0x11C`。
7. **生化幽灵状态改写攻击/动画**
   - 会卡动作；v3.2 加硬门控，幽灵状态下完全不介入，并归还自写锁。

### 方案迭代

- **v1-v2（Animator.speed 动画加速）**：只快画面，伤害频率不跟手。
- **v3.0（动画加速 + 清锁）**：补清锁提升连击，但入口清锁导致点太快伤害被取消。
- **v3.1（提前伤害 + 主动解锁，已废弃）**：右键后 100ms 主动调 `KnifeAttackEvent`、再 40ms 调 `OnKnifeAttackExit` 清锁，配 900ms 保护窗口；属于「伪造/补发伤害」路线。
- **v3.2（当前）**：`attach-only`，不主动补伤害；等原始 `KnifeAttackEvent` 完整返回后再解锁；主线程 pending、幽灵门控、对象池复用防护、disable 彻底还原、enable 重置。

## 一句话总结

v3.2 只做一件事：等游戏自己的枪托伤害事件完整返回，立刻清 `knifeAttackAnim`。代价是必须用 900ms 兜底窗口处理「攻击没有真正起手」的异常；切枪 select 期的第一下右键是目前已知的最大误伤点，修复方向是入口先判 `isSelecting` + 状态按武器隔离，而不是继续调小窗口。
