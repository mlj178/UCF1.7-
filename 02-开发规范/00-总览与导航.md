## 3. 开发顺序总览

```text
说清需求 -> 查 dump/IDA -> 可选写简要说明 -> 讲清原理 -> 停下等确认
-> 写插件包（script.js + manifest + feature.py + panel.py + events.py + __init__.py）
-> 写 AAAAA-xx_ui.py 本地调试壳 -> 自动验证语法 -> 进游戏实测
-> 稳定后按 21 整目录接入整合包（删 AAAAA-xx_ui.py，不拷 dev/）-> 同步更新 22 持久化总表
```

不要跳过单功能验证直接改整合包。

## 4. 文档同步节奏

这一节约束"什么时候改文档、按什么代码改文档"，避免文档被半成品版本带偏。

1. **版本收尾后统一同步**：一个整合包版本（当前 2.7）打包发布完成、代码定稿之后，才统一更新 `各个功能/` 和本目录其余版本相关文档。**不要**整合包改一点就同步一次——正在改的代码随时会变，提前写进文档等于制造两套事实。
2. **以最新整合包代码为准**：`各个功能/` 里的代码解释，一律对照最新整合包（`04-正式发行版/全功能整合包x.x/game_modifier/features/`）的实际代码写，**不从 `05-正式功能/` 的单功能阶段代码出发**。`05-正式功能/` 只保留开发过程与经验记录，不作为功能设计说明的依据。
3. **版本相关字段集中刷新**：版本号、更新日期、exe 名称、数据目录、页签归属、快捷键、功能数量这类"跟着版本走"的内容，在发布收尾时一次性全部核对，不要零散改。
4. **历史版本不动**：`04-正式发行版/全功能整合包x.x/更新说明vX.X.md` 是当时的历史记录，新版本不回头改它。
