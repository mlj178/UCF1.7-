## 1. 这个项目是什么

项目是 `UnityCrossFire 1.7` 的游戏修改器。

- 游戏进程：`UnityCrossFire.exe`
- 游戏路径：`D:\BaiduNetdiskDownload\UnityCrossFire1.7.1\UnityCrossFire1.7.1\UnityCrossFire.exe`
- 游戏引擎：Unity 2020.3.30f1
- 编译方式：IL2CPP
- 位数：32 位 x86
- 核心 DLL：`GameAssembly.dll`
- Frida 调用约定：Windows x86 IL2CPP 通常用 `'mscdecl'`
- IDA 基址：`0x10000000`
- 实际地址：`IDA基址 + RVA`

一句话理解：这是一个用 Frida 改 IL2CPP 游戏逻辑的项目，Python/CustomTkinter 负责界面，JS 负责 Hook 和内存修改。

## 2. 数据去哪里找

核心逆向资料都在：

`01-游戏逆向分析-相关信息/`

里面主要有三块：

### Il2CppDumper

路径：

`01-游戏逆向分析-相关信息/Il2CppDumper/`

常用文件：

- `dump.cs`：看类名、方法名、字段偏移、方法签名。
- `script.json`：看方法 RVA。
- `stringliteral.json`：查游戏字符串。
- `il2cpp.h`：看 IL2CPP 结构。

用法：先用 `dump.cs` 找类和字段，再用 `script.json` 找 RVA。

### IDA 汇编代码

路径：

`01-游戏逆向分析-相关信息/IDA-汇编代码/`

常用位置：

- `切分输出/`：IDA 导出的汇编代码，按 part 和 chunk 切分。
- `索引文件/ida_index_v3_1/`：IDA 索引。
- `索引文件/ida_index_v3_1/indexes/`：函数、类、方法、交叉引用等 JSON/JSONL 索引。
- `索引文件/ida_index_v3_1/IDA Index V3.1 最终报告.md`：索引说明和统计。

重要索引：

- `ida_functions.jsonl`：IDA 函数索引。
- `ida_methods.jsonl`：IDA 方法索引。
- `ida_classes.json`：IDA 类索引。
- `ida_xrefs.jsonl`：交叉引用。
- `ida_dumpcs_map.jsonl`：IDA 和 dump.cs 的对应关系。
- `dumpcs_methods.jsonl`：dump.cs 方法索引。
- `dumpcs_fields.jsonl`：dump.cs 字段索引。

如果索引查询脚本不存在，就直接用 `rg` 搜索 JSONL，或者用 IDA MCP 查询。

### AssetStudio

路径：

`01-游戏逆向分析-相关信息/AssetStudio/`

用途：

- 查资源、武器名、角色名、UI 名、MonoBehaviour 导出内容。
- 不要一上来全量读取，文件很多，按关键词搜索。

## 3. 最重要的技术红线

这些不要犯：

- 不要只看 `dump.cs` 就下结论，关键逻辑必须用 IDA MCP 反编译确认。
- 不要自己随便换 Hook 点，先解释为什么选它。
- 不要缓存容易失效的对象指针，切房间、换模式、重生后可能崩。
- 不要高频定时器硬写内存，容易卡顿或闪退。
- 不要在不确定线程安全时乱调 Unity API。
- 不要整合新功能时顺手改旧功能。
- 不要把正确的旧代码重构成另一套写法。
- 不要省略日志，测试阶段日志要能看出 Hook 是否命中、对象是否有效、玩家/人机是否识别正确。

## 4. 常用判断点

常用函数：

| 名称 | RVA | 用途 |
| --- | --- | --- |
| `Weapon.get_isMyWeapon` | `0xB6E1D0` | 判断武器是否属于玩家 |
| `Player.get_isMyPlayer` | `0xB55FD0` | 判断 Player 是否是本地玩家 |
| `ModeBase.Update` | `0xAF6A00` | 主线程 Update，常用于安全调度 |
| `Entity.OnEntityHurt` | `0x10B3F470` | 实体受伤 |

## 5. 和用户沟通时怎么输出

用户偏好：简洁、说人话、结构化。

建议输出格式：

```text
目标：
我理解你要做的是...

我查了什么：
1. ...
2. ...

目前判断：
...

推荐方案：
...

风险：
...

下一步：
...
```

如果还没查 IDA，就明确说"这里只是初步判断，还没用 IDA MCP 确认"。

如果需要用户手动测试，就说清楚测试点，不要说"应该没问题"。
