# 单功能目录与交付标准

这份规范用于 `05-正式功能/XX-功能名/` 下的所有新功能。

目标是让单功能用最少文件稳定跑通，同时保留后续迁移到正式发行版时需要的标准 RPC 和生命周期口径。

## 0. 本文档职责

本文档只规定单功能目录应该交付什么、RPC 怎么统一、UI 和 JS 怎么分工。

它不重复维护开发顺序、运行期细节、整合包具体字段：

```text
开发顺序：看《11-单功能开发流程.md》
运行期生命周期：看《13-单功能生命周期规范.md》
项目背景：看《01-项目背景与游戏信息.md》
整合包最终接入：看 20-整合包接入/21-整合包功能接入规范.md
编码规范：看 90-通用规范/91-编码与文件规范.md
```

如果本文档和正式发行版接入规范冲突，以正式发行版接入规范为准。

最终要求：

```text
单功能目录默认 = 整合包同构插件包 + 必选本地调试 UI
必选文件 = AAAAA-xx_ui.py + script.js + manifest.json + feature.py + panel.py + events.py + __init__.py
简要说明文档 = 可选，但建议保留目标、RVA、字段、Hook 点和测试结果
测试文件 = 默认不需要
生命周期说明 / 经验总结 / README / manifest.release-draft.json = 默认不需要补

AAAAA-xx_ui.py 仅供 05 本地调试，整合包不接入该文件
不允许后期重写核心 JS
不允许后期重写 RPC
不允许后期重写状态管理
不允许后期为了整合大改旧功能
不允许恢复旧 scripts/、features.json、core/feature_registry.py 接入方式
```

------

## 1. 核心原则

### 1.0 所有新功能第一版必须最小化实现

任何新功能开始开发时，都先完成最小可用闭环，不做复杂设计。

第一版只保留验证核心效果必需的 Hook、RPC 和 UI 控件；复杂界面、额外自动化、兼容扩展和非必要配置，等核心功能在游戏内验证稳定后再决定是否增加。

### 1.1 单功能必须按插件包标准写

以前的错误做法：

```text
05 单功能能跑就行
用自己的 launcher
用自己的 UI 调用方式
用自己的 JS 函数名
只写一个 AAAAA-xx_min.js + 一个独立 UI，没有 manifest/feature/panel
写很多临时脚本和重复文档
```

新的标准做法：

```text
05 单功能阶段默认按整合包插件包结构写（对齐 36-增加血量 / 37-增加防化服）
script.js + manifest.json + feature.py + panel.py + events.py + __init__.py
另加必选 AAAAA-xx_ui.py 作为 05 本地调试壳（整合包不接入）
JS、RPC、配置、日志、生命周期按统一标准写
可以保留一个简要说明文档，测试文件不需要
```

## 2. 每个功能必须有唯一 feature_id

每个功能从创建开始就必须确定一个永久 ID。

格式：

```text
snake_case 小写英文
不能用中文
不能随版本变化
不能因为 UI 名称变化而变化
```

例子：

```text
infinite_ammo
no_recoil
fast_reload
third_person_camera
fast_stock
```

这个 `feature_id` 必须同时用于：

```text
核心 JS 注释和日志
日志前缀
RPC 调用
配置项 key
2.1 正式 manifest.feature_id
UI 控件绑定名
```

错误例子：

```text
JS 叫 fast_stock.js
Python 叫 jisu_qiangtuo.py
UI 里叫 极速枪托
配置里叫 stockSpeed
RPC 里叫 enableFastButt
```

正确例子：

```text
feature_id: fast_stock
05 核心 JS: 05-正式功能/XX-极速枪托/script.js
05 调试 UI: 05-正式功能/XX-极速枪托/AAAAA-fast_stock_ui.py（整合包不接入）
整合包 JS: features/<feature_dir>/script.js
整合包 Python: features/<feature_dir>/feature.py
配置 key: fast_stock
RPC: enable / disable / status / cleanup / setConfig
日志前缀: [fast_stock]
UI 显示名: 极速枪托
```

## 3. 标准单功能目录结构

每个功能目录必须使用这个结构（对齐 36-增加血量 / 37-增加防化服）：

```text
05-正式功能/XX-功能名/
├── AAAAA-功能名_ui.py     # 必选：05 本地调试 UI，整合包不接入
├── script.js              # 必选：Hook / 内存 / RPC
├── manifest.json          # 必选：tab、控件、配置、rpc、lifecycle
├── feature.py             # 必选：继承 PluginFeatureBase
├── panel.py               # 必选：整合包卡片 UI
├── events.py              # 必选：插件事件（无事件也保留空处理）
├── __init__.py            # 必选：包标记
├── 功能名-简要说明.md      # 可选，记录目标、原理、地址、测试结果
└── dev/                   # 可选：探针、旧稿、日志
```

说明：

```text
AAAAA-功能名_ui.py     只作为 05 本地调试壳：自连游戏、加载 script.js、显示日志；整合包不接入
script.js              核心 JS，完整复制进整合包 features/<feature_dir>/script.js
manifest.json          整合包 manifest，接入时按需改 order / source 路径
feature.py             继承 PluginFeatureBase，接入时整文件复制
panel.py               整合包卡片 UI，接入时整文件复制
events.py              插件事件，接入时整文件复制
__init__.py            包标记，接入时整文件复制
功能名-简要说明.md      可选，内容短即可
dev/                   可选，临时文件与探针日志
manifest.release-draft.json / tests/ / README.md / 经验总结 = 默认不需要
```

整合包正式接入后目标目录：

```text
04-正式发行版/全功能整合包x.x/game_modifier/features/<feature_dir>/
├── __init__.py
├── manifest.json
├── feature.py
├── panel.py
├── script.js
└── events.py
```

注意：整合包目录里没有 AAAAA-xx_ui.py。接入时整目录复制 05 插件包后，删除 AAAAA-功能名_ui.py 与 dev/ 即可。

临时文件不允许参与发行版接入。

### 3.1 单功能代码口径

代码层默认交付：

```text
05-正式功能/XX-功能名/
├── AAAAA-功能名_ui.py     # 05 本地调试壳，整合包不接入
├── script.js              # 唯一核心 JS
├── manifest.json
├── feature.py
├── panel.py
├── events.py
└── __init__.py
```

轻量口径下：

```text
不再额外开发 launcher.py
不再额外拆 probe.js / debug.js / 多个临时 JS（临时探针放 dev/）
不再额外拆多个 Python UI
Python 分工：panel.py 给整合包；AAAAA-xx_ui.py 给 05 本地调试
真正游戏逻辑必须全部留在 script.js
```

## 4. manifest.release-draft.json 默认不需要

单功能阶段默认不需要提供 `manifest.release-draft.json`。

如果以后确实要单独记录整合包接入草稿，可以临时补这个文件，但它不是默认交付物，也不是单功能验证通过的前置条件。

简要说明文档可以记录这些信息：

```text
功能叫什么
UI 怎么显示
RPC 有哪些
配置项有哪些
依赖哪些 RVA / 字段偏移
生命周期是否需要进房后二次应用
是否同步上一次 enabled 状态
游戏内测试结果
```

## 5. JS RPC 必须统一

每个 JS 必须导出同一套 RPC。

固定接口：

```js
rpc.exports = {
    enable() {},
    disable() {},
    status() {},
    cleanup() {},
    setConfig(config) {}
};
```

允许额外增加：

```js
reset(reason) {}
debugDump() {}
```

但正式发行版只依赖固定接口。

### 5.1 enable

职责：

```text
安装 Hook，如果已安装则跳过
设置 Runtime.enabled = true
读取当前配置
记录 enable 日志
```

不允许：

```text
重复 attach Hook
重复启动定时器
缓存 Player/Weapon 后一直用
直接依赖单功能 UI
```

------

### 5.2 disable

职责：

```text
Runtime.enabled = false
停止功能效果
恢复当前 generation 内可安全恢复的原值
清理运行期缓存
清理普通定时器
```

------

### 5.3 cleanup

职责：

```text
关闭功能
清理 Hook
清理定时器
清理缓存
清理原值记录
允许重复调用
```

要求：

```text
cleanup 调用 1 次不能崩
cleanup 调用 10 次也不能崩
UI 退出时必须调用 cleanup
游戏断开时必须调用 cleanup
```

------

### 5.4 status

必须返回结构化状态。

标准返回：

```js
{
    feature_id: "fast_stock",
    enabled: true,
    initialized: true,
    generation: 3,
    hook_hits: 120,
    error_count: 0,
    last_error: "",
    last_reset_reason: "weapon_changed"
}
```

不要只返回字符串。

------

### 5.5 setConfig

正式发行版通过这个接口传配置。

标准：

```js
setConfig(config) {
    Runtime.config = Object.assign(Runtime.config, config || {});
    return true;
}
```

要求：

```text
JS 不能直接读 UI 控件
JS 不能假设配置只在 enable 前设置
配置变化后必须可以实时生效，或者明确写明需要重新 enable
```

------

## 6. JS 内部必须有 Runtime 状态对象

每个 JS 必须有统一 Runtime。

模板：

```js
const Runtime = {
    feature_id: "fast_stock",
    enabled: false,
    initialized: false,
    generation: 0,

    hooks: [],
    timers: [],

    config: {},

    cache: {
        localPlayer: ptr(0),
        currentWeapon: ptr(0)
    },

    originals: {},

    stats: {
        hookHits: 0,
        errorCount: 0,
        cleanupCount: 0,
        lastError: "",
        lastResetReason: ""
    }
};
```

要求：

```text
不要把状态散落成一堆全局变量
不要长期相信 Player* / Weapon*
不要跨房间使用旧指针
必须实现 resetRuntime(reason)
```

## 7. Python feature 文件按整合包插件适配器写

单功能阶段可以有 `AAAAA-功能名_ui.py` 作为测试壳，但不能把只能自己用的 Python 调用方式当成交付标准。

正式迁移到整合包后，每个插件目录的 `feature.py` 必须继承 `PluginFeatureBase`。

整合包目标模板：

```python
from core.plugin.plugin_base import PluginFeatureBase


class PluginFeature(PluginFeatureBase):
    feature_id = "fast_stock"
    js_filename = "script.js"
    name = "极速枪托"
    icon = "*"
    category = "weapon"
    desc = "一句话说明功能效果。"
```

重点：

```text
不要在单功能 UI 里发明和整合包不同的 RPC 名称
不要写死旧 call_export / scripts 路径作为正式接口
正式版 feature.py 只做插件元数据和通用基类适配
真正游戏逻辑留在 script.js
```

重点：

```text
单功能 UI 必须模拟 enable/disable/status/cleanup/setConfig 调用
不要 UI 直接乱调 script.exports.xxx
不要 launcher.py 绕过标准 RPC
发行版整合时按整合包插件模板生成 feature.py
```

------

## 8. 单功能 UI 必须模拟正式发行版调用方式

单功能 UI 只是测试壳。

它必须模拟正式发行版流程：

```text
启动 UI
attach 游戏
加载 JS
创建 Feature 类
调用 feature.enable()
调用 feature.disable()
调用 feature.status()
退出时调用 feature.cleanup()
```

单功能 UI 可以保留调试按钮、滑块或参数，但必须区分用途：

```text
正式版要给用户使用的入口：按正式发行版 manifest / panel / JS / 测试准备。
单功能调试用、正式版暂不接入的入口：可以保留在 05 单功能 UI，但必须在说明文档里标注“仅单功能调试使用，正式版是否接入待定”。
已经确认废弃或不对用户开放的入口：JS RPC、单功能 UI、正式版 manifest/panel 和测试都要同步清理。
```

不允许：

```text
UI 直接写死 JS 路径但正式版路径不同
UI 直接调 enableFastStock 这种临时 RPC
UI 没有 cleanup
UI 没有 status
```

### 8.1 CustomTkinter UI 交互要求

`AAAAA-功能名_ui.py`（05 本地调试壳）必须使用 `customtkinter`，并且默认承担这些职责：

```text
启动后自动查找并连接 UnityCrossFire.exe
游戏未启动时持续等待，不要求用户手动输入进程名
连接成功后自动 attach 游戏进程
attach 成功后自动加载当前目录下的 script.js
加载后调用标准 RPC：enable / disable / status / cleanup / setConfig
窗口关闭、游戏断开、脚本卸载时调用 cleanup
该文件整合包不接入，只用于 05 本地调试
```

`panel.py`（整合包卡片）职责见第 7 节与第 8 节；它不自连游戏、不加载 JS，只走通用 callbacks。

UI 控件生成原则：

```text
能做成开关的选项，尽量在界面上显示为 CTkSwitch，让用户自行选择
需要数值调整的配置，使用 CTkSlider，并显示当前数值
枚举/模式类配置，使用 CTkOptionMenu
普通动作命令，使用 CTkButton
状态和日志，使用 CTkLabel / CTkTextbox
```

注意：

```text
UI 可以把可配置项尽量展示出来，但不要绕过 JS 的 setConfig 直接改内存。
开关和滑块必须通过 setConfig 或 enable/disable 进入 JS Runtime。
默认是否开启某个功能或子选项，以 JS Runtime.config 为准；UI 文件顶部可以写 DEFAULT_CONFIG 作为界面默认值。
```

## 9. 文件命名必须稳定

单功能阶段文件名要稳定，迁移到整合包时只去掉 AAAAA-xx_ui.py 和 dev/。

标准：

```text
AAAAA-功能名_ui.py
script.js
manifest.json
feature.py
panel.py
events.py
__init__.py
功能名-简要说明.md（可选）
```

整合包目标文件名固定为：

```text
features/<feature_dir>/manifest.json
features/<feature_dir>/feature.py
features/<feature_dir>/panel.py
features/<feature_dir>/script.js
features/<feature_dir>/events.py
features/<feature_dir>/__init__.py
```

整合包不包含 AAAAA-功能名_ui.py。

错误：

```text
极速枪托最终版.js
极速枪托测试2.js
fast_stock_new_ok.js
launcher_fixed.py
最终可用.py
```

临时版本必须放入：

```text
dev/
archive/
```

正式可迁移代码文件必须永远保持固定名字。

## 10. 日志必须统一

JS 日志前缀：

```text
[feature_id]
```

Python 日志前缀：

```text
[feature_id]
```

必须记录：

```text
load
enable
disable
cleanup
resetRuntime
hook installed
hook hit
pointer invalid
config changed
error
```

日志必须限频，不能刷屏。

## 12. 功能完成前必须通过标准检查

单功能进入“可合并”状态前，必须通过：

```text
feature_id 在 JS / UI 中一致
JS 有 enable/disable/status/cleanup/setConfig
JS 有 Runtime
JS 有 cleanupTimers / cleanupHooks / resetRuntime
单功能 UI 通过标准 RPC 调用
node --check 通过
python -m py_compile 通过
```

## 14. release_ready 标准

满足这些条件才可以标记为 `release_ready`：

```text
1. 单功能 UI 能正常开启/关闭
2. JS RPC 完整
3. cleanup 可重复调用
4. 反复开关不会重复 Hook
5. 切房间不会继续用旧指针
6. 死亡/重生不崩
7. 退出游戏不刷异常
8. UI 调用方式和发行版一致
9. 不依赖 launcher.py
10. JS 注释或简要说明文档写清 RVA / 字段 / Hook 点
11. 如果依赖房间内对象，已实现 pendingApply / room-ready reapply
12. 如果缓存游戏对象指针，已覆盖对应生命周期清理场景
13. 调用游戏 NativeFunction 前，已做空指针和可读性检查
14. 如果按钮/RPC 已确认废弃或不对外开放，JS、单功能 UI、正式版入口和测试没有残留外部入口
15. 如果保留单功能调试按钮/滑块，已在说明文档标注用途和正式版接入状态
```
