功能目录 功能问答

它解决了什么游戏问题

正常开火会进入武器弹药消耗流程。这个功能不把弹药改成一个很大的数字，而是接管“消耗子弹”函数：普通枪械直接返回扣弹成功但不修改弹药；RPG/AT4 在开火前调用填弹函数，抵消特殊武器内部的扣弹逻辑。

Unity IL2CPPGameAssembly.dll Frida HookNative 指针 开火 / 弹药房间 / 回合 RVA 版本依赖
修改策略
  1. 基址 + RVA 定位 IL2CPP Native 函数
  2. 替换普通枪械与武器基类扣弹函数
  3. 单独 Hook RPG/AT4 开火并预先补弹
  4. 向修改器 UI 回传启用状态

代码作用

从游戏修改角度理解这个功能

核心逻辑流程

用户启用无限子弹 → 查找 GameAssembly.dll 并取得运行时基址 → base + RVA 得到 ConsumeAmmo / Fire / FillAmmo 地址 → 普通枪：replace ConsumeAmmo，直接返回 true → RPG/AT4：进入 Fire 前调用 FillAmmo → 游戏继续执行开火，但弹药不再正常减少

关键数据

数据含义
0xB61140WPN_Gun.ConsumeAmmo，普通枪械扣弹
0xB6C310Weapon.ConsumeAmmo，武器基类兜底
0xB670A0WPN_RPG.Fire，RPG/AT4 开火
0xB67070WPN_RPG.FillAmmo，特殊武器填弹
thisPtr / args[0]当前 IL2CPP 武器实例的 Native 指针

功能目录中的其他方案

plan1_memory_lock.js 从开火函数取得玩家武器指针，再通过 WPN_Gun + 0xF4 找到 ammoData，定时回写 ObscuredInt.hiddenValue。它需要处理玩家/Bot 过滤、缓存指针和房间切换后的失效指针。

plan2_nop_consume.js 直接把函数入口改为 mov eax, 1; ret。效果直接，但会改写 .text 机器码，面临代码校验、内存保护和版本偏移风险。

新人接手注意事项

  1. 游戏更新后优先重新确认四个 RVA，旧地址 Hook 错位可能导致崩溃。
  2. 普通枪有效、RPG 无效时，单独检查 WPN_RPG.Fire 和 FillAmmo。
  3. 换弹动画不触发是方案副作用，因为弹药不会进入空弹匣状态。
  4. 整合包禁用逻辑保存的是地址而非 attach listener，RPG Hook 可能无法正确解绑。
  5. 该实现没有区分玩家与 Bot；共享同一 Native 扣弹函数的对象可能一并受影响。
