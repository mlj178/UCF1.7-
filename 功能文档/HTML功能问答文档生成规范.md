# 穿越火线单机版功能问答 HTML 生成规范

## 规范使用方式

本规范包含生成 `功能问答.html` 所需的完整要求，可以独立使用，不要求先读取其他规范。

相关文件：

- `功能问答HTML模板.html`：功能问答页面的布局、问题编辑和持久化交互参考。
- `HTML代码解读文档生成规范.md`：需要生成完整业务逻辑解读的 `代码解读.html` 时使用。
- `代码解读HTML模板.html`：代码解读页面的布局参考。
- `功能文档体系说明.md`：只说明各文件之间如何配合，不承载本规范的必需生成规则。
- `index.html`：功能文档总入口；新增或调整问答页面后必须检查对应功能的入口和链接。

功能问答和代码解读可以共用页面视觉、完整源码与代码分段结构，但两份规范各自完整，不形成必须同时读取的强依赖。

`代码解读HTML模板.html` 是功能问答页面的视觉和尺寸基准。生成或调整问答模板时，应直接沿用其共享 CSS、顶部栏、左右栏比例、源码档案、关键行图例、完整代码导航、代码行和 Sticky 尺寸；不得另写一套仅仅“看起来相似”的共享样式。`功能问答HTML模板.html` 只在右侧内容区增加问题编辑、回答和数据文件操作所需的专属样式与交互。

## 页面生成时的源码读取与 token 约束

- 生成或维护功能问答页面的源码区和代码上下文时，默认只从 `D:\trae_project\ucf1.7-modifier\04-正式发行版\全功能整合包1.7-修复版\game_modifier\scripts` 读取实际代码，不从问答 HTML 的内嵌源码读取或推断，以减少重复内容和 token 消耗。
- 整合包版本以后可能变化；只有用户主动提出更新版本或更新源码目录时，才修改上述默认路径，不自行猜测或切换版本。
- 优先按页面涉及的文件、函数和行号局部检索，不扫描无关脚本。预计会明显消耗 token 的读取、分析或生成任务，必须在执行前告知用户。
- Codex 不负责回答功能问答页中的问题，用户不需要再把问答 JSON 文件发给 Codex 请求回答。Codex 仅在用户明确要求时维护页面、模板和规范。

## 文档目的

功能问答页用于长期记录某一个修改功能的疑问和回答。读者可以对照完整源码提出问题，在 ChatGPT 网页版获得回答后粘贴到页面中继续维护。

问答页不是代码解读页的复制品。左侧源码只负责提供准确上下文，右侧才是主要工作区。

## 目录与命名

- 一个功能对应一个编号文件夹，例如 `01-无限子弹`。
- 问答页面命名为 `功能问答.html`。
- 可交换的数据文件默认命名为 `编号-功能名称-功能问答.json`。
- 通用参考模板命名为 `功能问答HTML模板.html`。
- 页面提供到同文件夹 `代码解读.html` 和上级 `index.html` 的链接。

## 页面布局

问答页沿用代码解读页中便于核对源码的区域，但只保留以下布局职责：

- `01 功能标题区`：显示编号、功能名称、问答页身份和文档跳转。
- `05 源码档案`：显示源码文件路径和版本说明。
- `06 关键行图例`：蓝色定位、红色 Hook、绿色行为修改、橙色风险。
- `07 完整代码导航`：列出当前源码的全部代码段，并固定在顶部栏下方。
- `08 完整代码`：连续展示所选源码文件的全部代码，不因选择代码段而隐藏其他内容。

左侧用于阅读源码，右侧为固定的问答工作区。鼠标滚轮只负责滚动，不得自动切换代码段、问题或回答。

共享布局的颜色变量、字体、最小页面宽度、顶部栏高度、左右栏网格比例、内外边距、代码字号与行高、行号栏宽度、边框、圆角和 Sticky 偏移均以 `代码解读HTML模板.html` 的当前值为准。问答页不得自行使用另一套近似数值。

## 源码与代码上下文

- 问答页应嵌入与对应代码解读页相同版本的完整源码。
- 每个代码段必须具有稳定的 `sectionId`、标题和行号范围。
- 点击代码段只改变“当前代码上下文”和高亮状态，不替换右侧问答内容。
- 新增问题时，自动记录当前源码文件、代码段标题和行号范围。
- 问题的代码上下文属于辅助定位信息；问题仍可独立编辑。

## 问答数据结构

数据文件使用 UTF-8 JSON，顶层结构如下：

```json
{
  "schemaVersion": 1,
  "feature": {
    "number": "01",
    "name": "无限子弹",
    "sourceFile": "scripts/01-unlimited_ammo.js"
  },
  "updatedAt": "2026-06-19T10:00:00.000Z",
  "questions": []
}
```

每个问题至少包含：

- `id`：稳定且唯一的问题标识。
- `question`：用户提出的问题。
- `answer`：回答内容；允许暂时为空。
- `status`：`pending`、`answered` 或 `needs-review`。
- `questionRevision`：问题内容版本；新问题从 `1` 开始，问题文字改变时递增。
- `answeredRevision`：当前回答对应的问题版本；没有回答时为 `0`。
- `answeredAt`：页面中最后一次写入有效回答的时间；没有回答时为 `null`。
- `createdAt`、`updatedAt`：问题创建和最后编辑时间。
- `sourceContext`：提问时选中的源码文件、代码段和行号范围；允许为空。

不得把页面样式、完整源码或 HTML 内容写入问答 JSON。数据文件只保存可交换的问答数据和必要上下文。

## 持久化与文件交换

采用两层持久化，兼顾便捷和可移交性：

1. **浏览器自动保存**：新增、编辑和删除问题，以及编辑回答时，立即写入 `localStorage`；刷新或重新打开页面后可以继续编辑。
2. **JSON 文件保存**：用户通过“保存到文件”或“另存数据”生成可携带的问答文件，仅用于备份、换电脑或恢复页面数据，不再作为提交给 Codex 回答问题的载体。

文件操作规则：

- “打开数据”读取 JSON，并在替换现有问答前明确确认。
- 浏览器支持 File System Access API 时，保存按钮可继续写入当前已选择的文件。
- 浏览器不支持直接文件读写时，自动退回文件选择器和 JSON 下载，不得让核心流程失效。
- “另存数据”始终允许创建新的 JSON 文件。
- 页面明确显示“已自动保存到浏览器”或“文件待保存”等状态，区分浏览器保存与外部文件保存。
- 文件功能编号与当前页面不一致时必须提示，由用户确认是否继续读取。
- 无效 JSON、版本不支持或字段结构错误时，显示易懂的错误信息，不能覆盖当前数据。

浏览器安全规则不允许网页在没有用户授权的情况下静默写入任意磁盘文件，因此“自动保存”默认指浏览器本地保存；磁盘文件保存仍由用户点击触发。

## 问题交互

- 右侧顶部提供“打开数据、保存到文件、另存数据、新建空白”。
- 新问题输入框固定在问题列表上方。
- 点击“添加问题”后立即出现在列表中，并自动保存；问题按创建时间正序显示，第一个添加的问题始终位于第一个，后续问题依次追加到末尾。
- 支持 `Ctrl+Enter` 添加问题，但页面不显示大段快捷键说明。
- 每个问题可以直接修改问题文字；回答可以直接编辑，编辑后立即更新状态、修订号对应关系并自动保存到浏览器本地数据。
- 新问题输入框和已有问题编辑框必须根据文字多少自动撑高，并在输入时持续更新高度；不允许出现问题区域内部纵向滚动条，也不依赖用户手动拖动才能看全问题。
- 回答编辑框使用 `textarea`，必须根据文字多少自动撑高，不允许出现回答区域内部滚动条，也不依赖用户手动拖动才能看全回答。
- 每条回答提供“复制回答”按钮；回答为空时给出易懂提示，不复制占位文字。
- 代码上下文必须使用独立强调块，通过背景色、边框和加粗标签突出显示完整的“源码文件 · 代码段标题 · 行号范围”，不能退化为不醒目的普通灰色小字。
- 点击问题卡区域时，页面必须根据该问题保存的 `sourceContext.sectionId` 激活左侧对应代码段，并平滑自动滚动到对应代码段；点击复制、删除等按钮时只执行按钮自身操作，不触发代码跳转。
- 代码定位不得直接使用把目标顶端贴到视口顶端的固定对齐方式；滚动位置必须动态扣除顶部栏和代码导航的实际高度，并保留少量可视间距，避免目标代码被 Sticky 区域遮挡后出现定位偏下。
- 问题没有代码上下文或对应代码段已经不存在时，不得错误跳转，应显示易懂提示并保持当前代码位置。
- 回答为空显示“待回答”；回答版本与问题版本一致时显示“已回答”；问题修改后保留旧回答并显示“需重新回答”。
- 每个问题提供复制问题和删除操作；删除前必须确认。
- 新建空白或打开其他文件会覆盖当前问答时，先提醒用户另存并确认。
- 问题数量增多后，右侧工作区独立滚动，左侧代码阅读位置不受影响。

## ChatGPT 网页版回答流程

- 用户在问答页填写问题，使用“复制问题”按钮复制问题文字；需要时一并复制醒目显示的代码上下文。
- 用户自行前往 ChatGPT 网页版提问，不需要把问答 JSON 文件发送给 Codex，也不由 Codex 生成或回填回答。
- 获得回答后，用户把内容粘贴到对应的可编辑回答框；页面立即自动保存，并将 `answeredRevision` 更新为当前 `questionRevision`、`status` 更新为 `answered`，同时写入 `answeredAt` 和 `updatedAt`。
- 问题修改后，页面保留旧回答并显示“需重新回答”。用户应在 ChatGPT 网页版针对修改后的问题重新提问，再用新回答替换旧回答。
- 回答清空后，页面把状态恢复为“待回答”，并将 `answeredRevision` 设为 `0`、`answeredAt` 设为 `null`。
- JSON 导入和导出只负责备份与恢复，不触发自动回答，也不要求任何自动流程按问题版本批量处理。
- 旧格式 JSON 没有版本字段时：有非空回答的条目默认视为当前版本已回答；空回答默认视为待回答。页面导入后补齐版本字段，再按本地编辑流程继续维护。

## 生成具体功能问答页

从模板生成实际页面时必须替换：

- 页面标题、功能编号和功能名称。
- 源码文件路径、完整源码、代码段标题和真实行号。
- RVA 后的类与方法标注，以及关键业务行颜色。
- `feature` 数据和 `localStorage` 键，确保不同功能的数据不会混用。
- 默认 JSON 文件名。

实际功能页不显示 `01、05、06、07、08` 布局编号徽章；这些编号只用于模板和规范沟通。功能自身的编号仍正常显示，例如 `01 · 无限子弹`。

新生成功能默认可以没有问题。若已有问答数据，应保持问题 `id` 和原有回答，不得因为重新生成 HTML 而清空。

## 表达与边界

- 问题和回答使用简洁、明确的中文，技术名词保留英文。
- 问答内容从穿越火线单机版游戏修改角度组织，可以涉及 Unity、IL2CPP、Hook、线程、指针、玩家、Bot、房间、武器或模式，但只分析代码真实涉及的内容。
- 问答页不强制生成“代码解读页”的业务流程卡片，也不设置“分析补充”或“证据等级”区域。
- 问答页只要求提供准确的源码上下文，不强制生成完整业务逻辑分析。需要进一步编写代码解读页面时，可参考《HTML代码解读文档生成规范》，但它不是生成问答页的前置依赖。
