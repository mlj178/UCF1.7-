# 穿越火线单机版背景信息 HTML 生成规范

## 规范使用方式

本规范用于生成每个功能文件夹中的 `背景信息.html`。通用页面结构和交互参考 `背景信息HTML模板.html`；实际页面必须替换模板占位内容，不能直接保留示例章节。

相关文件：

- `背景信息HTML模板.html`：背景正文、背景上下文、问答区和页面快速跳转的完整参考。
- `功能问答HTML模板.html`：只用于核对问答交互的一致性，不作为背景信息页的布局基准。
- `HTML功能问答文档生成规范.md`：功能问答页规范；背景信息问答必须使用独立数据，不能与其混用。
- `代码解读HTML模板.html`：代码解读页面的视觉参考。
- `index.html`：功能文档总入口；新增实际背景信息页面后必须同步检查 `index.html`，补充或校正对应入口。

## 文档目的

背景信息页解释阅读功能代码前必须理解的知识，包括游戏对象、继承关系、配置数据、运行时状态、功能运行流程、适用范围和风险边界。它不是代码逐行解读，也不是固定问题答案的堆叠。

页面由两个部分组成：

1. 单栏背景正文，保证继承树、流程图和关系图有足够宽度。
2. 正文底部的“我的问题与回答”，用于记录用户阅读背景资料时产生的新问题。

## 目录与命名

- 一个功能一个编号文件夹，例如 `01-无限子弹`。
- 实际页面命名为 `背景信息.html`。
- 通用模板命名为 `背景信息HTML模板.html`。
- 规范命名为 `HTML背景信息文档生成规范.md`。
- 背景信息问答 JSON 默认命名为 `编号-功能名称-背景信息问答.json`。
- 页面必须链接上级 `index.html`，并链接同文件夹的 `代码解读.html`、`功能问答.html` 和 `背景信息.html`。

## 源码读取与 token 约束

- 生成背景资料时，默认只从 `D:\trae_project\ucf1.7-modifier\04-正式发行版\全功能整合包1.7-修复版\game_modifier\scripts` 读取实际功能脚本。
- 不从已有 HTML 的内嵌源码代替实际脚本；已有背景信息 HTML 只可作为内容和布局参考。
- 整合包版本路径只有在用户主动提出更新时才修改，不自行切换版本。
- 优先按当前功能涉及的文件、类、方法和关键词局部检索；预计明显消耗 token 的任务必须提前告知用户。
- 背景信息可以引用 dump、类关系或项目其他文件，但必须说明来源，不得把推断写成已经验证的事实。

## 页面布局

### 顶部栏

- 顶部显示功能编号、功能名称和“背景信息”。
- 提供功能目录、代码解读、功能问答、背景信息的导航。
- 当前“背景信息”入口必须有明确选中状态。
- 桌面端顶部栏保持 Sticky；窄屏时允许恢复普通文档流，避免导航挤压正文。

### 背景正文

- 正文使用居中的单栏宽内容区，不使用会压缩继承树和流程图的固定右侧栏。
- 开头提供文档目的和“点击章节可设为提问上下文”的提示。
- 每个章节使用 `data-background-section`、稳定的 `data-section-id` 和准确的 `data-section-title`。
- 章节标题、正文、重点结论、提示、风险、流程图和关系卡片应使用统一样式。
- 点击章节后显示选中状态，并把该章节设为新增问题的当前背景上下文。

### 问答区

- “我的问题与回答”位于所有背景正文之后，为全宽区域。
- 标题下显示“问题和回答都可编辑并自动保存；内容会按文字多少自动展开”。
- 显示浏览器保存和文件保存状态，例如“浏览器与文件已同步”或“已存浏览器，文件待保存”。
- 提供打开数据、保存到文件、另存数据和新建空白。

## 背景上下文联动

- 新增问题时自动保存当前选中背景章节的 `sectionId`、标题、页面文件和上下文类型。
- 问题卡底部使用独立强调块显示“背景上下文”，不能使用不醒目的普通灰字。
- 点击问题编辑框、回答编辑框、问题卡空白处或背景上下文时不得触发页面跳转，避免编辑过程中页面位置突然变化。
- 点击复制或删除按钮只执行按钮自身操作，也不得触发页面滚动。

## 独立问答数据

背景信息问答必须使用独立 `localStorage` 键和独立 JSON 文件，不得与 `功能问答.html` 共用问答数据。

推荐键格式：

```text
background-info-qa::编号::功能名称
```

禁止复用功能问答页的键。即使两个页面属于同一个功能，它们的问题、回答、文件句柄和保存状态也必须彼此独立。

JSON 顶层结构：

```json
{
  "schemaVersion": 1,
  "feature": {
    "number": "XX",
    "name": "功能名称",
    "sourceFile": "背景信息.html",
    "documentType": "background-info"
  },
  "updatedAt": "ISO-8601 时间",
  "questions": []
}
```

每个问题至少包含：

- `id`：稳定、唯一的问题标识，背景信息问题建议使用 `bgq-` 前缀。
- `question`、`answer` 和 `status`。
- `questionRevision`、`answeredRevision` 和 `answeredAt`。
- `createdAt` 和 `updatedAt`。
- `sourceContext`：背景章节 ID、标题、页面文件和 `background-section` 上下文类型。

导入数据时必须验证 `schemaVersion`、`questions` 数组和 `documentType`。功能编号不同要提示用户确认；非背景信息问答 JSON 必须拒绝导入。

## 问题和回答交互

- 新问题按创建时间正序显示，第一个问题保持在第一项，新问题追加到末尾。
- 新问题输入框、问题编辑框和回答编辑框随内容自动增高，不出现内部纵向滚动条。
- 问题和回答都可直接编辑；每次修改立即写入背景信息页自己的 `localStorage`。
- 问题修改后递增 `questionRevision`；存在旧回答时显示“需重新回答”。
- 回答写入后把 `answeredRevision` 设为当前问题版本并显示“已回答”；清空回答后恢复“待回答”。
- 每条问题提供复制问题和删除按钮；每条回答提供复制回答按钮。
- 删除前必须确认；空问题不能添加；空回答不能复制占位文字。
- 支持 `Ctrl+Enter` 添加问题，但不在页面中显示冗长快捷键说明。

## 持久化与文件交换

- 浏览器自动保存使用独立 `localStorage` 键，刷新后可以恢复。
- JSON 只用于背景信息问答的备份、迁移和恢复，不用于向 Codex 批量提交问题。
- 支持 File System Access API 时，“保存到文件”可继续写入用户已选择的文件。
- 不支持该 API 时，自动退回 JSON 下载和文件上传，核心功能不能失效。
- 打开数据、新建空白会覆盖当前内容时必须先确认。
- 无效 JSON、错误文档类型或不支持的版本不得覆盖当前数据。

## ChatGPT 网页版回答流程

- 用户复制问题，需要时同时参考问题卡中的背景上下文。
- 用户自行在 ChatGPT 网页版提问，再把回答粘贴到可编辑回答框。
- Codex 不负责接收背景信息问答 JSON 或批量回答问题。
- 页面只负责编辑、状态更新、自动保存和文件交换。

## 置顶与置底按钮

- 页面右下角固定提供“置顶”和“置底”按钮，名称和方向图标必须清楚。
- 点击置顶时平滑滚动到页面顶部；点击置底时平滑滚动到文档底部。
- 按钮不能遮挡正文、问答输入框、文件按钮或系统滚动条。
- 窄屏时缩小外边距，仍应保持可点击并避免覆盖主要内容。
- 按钮使用原生 `button`，包含 `title` 或等效无障碍名称。

## 从模板生成实际页面

必须替换：

- `XX`、功能名称、页面标题和导航路径。
- 背景正文的示例章节、稳定章节 ID 和真实标题。
- `feature` 数据、独立 `localStorage` 键和默认 JSON 文件名。
- 与当前功能有关的对象关系、运行流程、边界和风险。

不得修改：

- 问题和回答自动增高、编辑、复制、删除和状态逻辑。
- 背景上下文记录和醒目展示逻辑。
- 数据隔离、导入验证和文件回退策略。
- 置顶、置底按钮及平滑滚动行为。

新生成功能可以没有问题。重新生成页面时不得清空用户已经保存的背景信息问答数据。新增实际背景信息页面后必须同步检查 `index.html`，确认入口名称、路径和同功能其他页面链接正确。

## 表达与边界

- 使用简洁、明确的中文，类名、方法名、字段名和技术术语保留英文。
- 背景信息优先解释“是什么、为什么重要、对象之间如何连接、运行时会发生什么”。
- 不把完整源码塞入背景信息页，也不逐行重复代码解读内容。
- 无法由代码直接证明的内容要标记为推断或待运行时验证。
- 不恢复 Python 固定路径保存服务；浏览器保存和用户触发的 JSON 文件操作是唯一默认方案。
