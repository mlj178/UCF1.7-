## 一、一句话结论

UCF 1.7 的"地图"由**三层独立数据**决定，三层都改过才算真加图：

| 层 | 位置 | 决定什么 | 当前状态 |
|---|---|---|---|
| ① 场景名册 | `globalgamemanagers` → `BuildSettings.scenes` | 引擎允不允许加载、名字→索引 | ✅ **已加到 13 条，实测通过** |
| ② 地图注册表 | `sharedassets0.assets` ≈0x42CAF00 | 创建房间下拉框显示哪些图 | ❌ 未改 |
| ③ 场景文件 | `levelN` + `sharedassetsN` | 实际内容 | ⚠️ 用 level11 副本占位，从未被加载 |

**之前把"下拉框"和"场景名册"当成一回事，是错的。它们是两份完全独立的数据。**

## 三、地图注册表（本轮新发现，关键）

在下拉框里看到的地图**不是**从场景名册读的，而是来自
`sharedassets0.assets` 偏移 `0x42CAF00` 附近的一张 **mode → 地图列表** 表：

```
Normal
  DeathMatch          NY_TM                 胜利广场
Nano4                 NanoResort            生化酒店
                      DesertFort            沙漠要塞
Nano4_Terminator      Nano_DawnVillage      新寂静村
Nano6                 DesertFort            沙漠要塞
                      NanoResort            生化酒店
Special               Arena                 竞技场
                      GrimReaperKM          刀锋寨
                      DeathRing             死亡擂台
TeamDeath             TransportShip         运输船
                      Factory               小型工厂
                      Cebu_City             椰岛之巅
Weapon                （武器模式，条目未展开）
```

### 由此解释了两个现象

1. **"下拉框所有地图都有"** —— 因为注册表里本来就有这些条目，与名册无关
2. **"没有暴风"** —— `hidden_map` 是 MOD 的功能，而 MOD 没加载

### 结构

每项 = `int32 长度 + 场景名（无扩展名，如 NY_TM）` + `int32 长度 + 中文名`。
和名册用的是同一套"长度前缀 + 4 字节对齐"字符串格式。

**往名册加一条，不会自动出现在下拉框。必须同时往这张注册表加一条。**

## 四、场景名册的字节格式（已实测写出并跑通）

```
BuildSettings 对象（globalgamemanagers，path_id = 11）
+0x000  int32   场景数量
+0x004  n × (int32 len + len 字节路径 + 补零到 4 字节对齐，无结尾 \0)
+尾部 176 字节：16 字节 GUID / "2020.3.30f1c1" / buildGUID(80 hex) /
                "12369523391731" / 两个 int32
```

原始 12 条路径：

```
0  Assets/Scenes/GameStart.unity
1  Assets/Scenes/TeamDeath/TransportShip.unity
2  Assets/Scenes/TeamDeath/Factory.unity
3  Assets/Scenes/TeamDeath/Cebu_City.unity
4  Assets/Scenes/BlastingMode/NY_TM.unity
5  Assets/Scenes/Special/Arena.unity
6  Assets/Scenes/Special/GrimReaperKM.unity
7  Assets/Scenes/Nano/DesertFort.unity
8  Assets/Scenes/Nano/NanoResort.unity
9  Assets/Scenes/Nano30/Nano30_Storm.unity
10 Assets/Scenes/Nano30/Nano_DawnVillage.unity
11 Assets/Scenes/Special/DeathRing.unity
```

### 写入方法（已验证）

type tree 被剥离，UnityPy 的高层解析会失败，所以走**裸字节**：

1. `UnityPy.load` 打开 → 取 `BuildSettings` 对象 → `get_raw_data()`
2. 按上面的格式解析出 12 条
3. 拼新字节：数量 +1、末尾插入 `int32 len + 路径 + 补零`，**尾部 176 字节原样保留**
4. `set_raw_data(新字节)` → `sf.save()` 写回

结果：1,617,300 → 1,614,512 字节（`data_offset` 从 4096 变成 1264），实测可运行。

| 地址 | 作用 |

- **文件名是运行时从索引拼出来的**，磁盘上没有登记表

### 9.3 注册表对象的字节布局（实测）

以 TeamDeath（pathID 22391，316 字节）为例：

```
+0x00  12 字节  m_GameObject PPtr
+0x0c   4 字节  m_Enabled
+0x10  12 字节  m_Script PPtr (fileID=1, pathID=0x167)
+0x1c  string  模式名 "TeamDeath"
+0x2c  16 字节  固定字段
+0x3c  int32   地图条数 = 3
之后每条：
        string  场景名（无扩展名，如 TransportShip）
        string  中文名（如 运输船）
        ~48 字节 若干 PPtr / 数值字段
```

**字符串格式**：`int32 长度 + 字符 + \0 + 补零到 4 字节对齐`（与名册的格式不同，名册无 \0）
