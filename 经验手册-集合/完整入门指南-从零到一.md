## 一、你为什么会乱

你现在的处境，打个比方：

> 你在修一辆从来没见过的车。你不知道发动机在哪，不知道每根线是干什么的。然后你上来就跟 AI 说"帮我改个涡轮增压"。AI 可能改对了，但那根线到底接的是增压器还是刹车灯，你完全不知道。

**乱的根本原因只有三个：**

| 原因 | 表现 | 解法 |
|------|------|------|
| 不了解游戏的结构（类、字段、继承关系） | 不知道改哪个类；同功能不同模式不生效 | 读 `dump.cs`，画继承关系图 |
| 不了解 Frida 的工作原理 | hook 了没效果；影响 bot；换房间闪退 | 理解 Hook / Attach / Replace |
| **不了解真正的代码逻辑** | dump.cs 只有方法名，没有方法体；只能猜 | **用 IDA MCP 反编译看真实逻辑** |

### 为什么第 7 步如此重要？

**没有 IDA 之前**：你只能根据 `dump.cs` 里的字段名和方法名**推测**代码在做什么。比如你看到：

```csharp
void OnStartNewGameRound();
Nano4T_Attribute GetAttribute(bool isNano);
```

你猜"这个方法大概是选特性吧"。但你不知道：
- 它内部是不是先判断 `isBattleRound`？
- 是不是调了 `RandomItem.Get()`？
- `GetAttribute` 返回的是 ID 还是对象指针？
- 有没有人数限制（< 8 人禁止某些特性）？

**有 IDA MCP 之后**：按一下 F5（或 MCP 自动反编译），你看到的就变成：

```csharp
protected override void OnStartNewGameRound()
{
    this.isBattleRound = (this.thisRoundPlayer % 5 == 0);     // ← 真实逻辑！
    
    this.attribute_Nano  = this.attributeAsset.GetAttribute(true);   // ← 102行汇编的1行
    this.attribute_Human = this.attributeAsset.GetAttribute(false);  // ← 不再猜测！
    
    this.hud_Attribute.NewRoundReset(this.attribute_Nano, this.attribute_Human);
}
```

**这就叫从"猜代码逻辑"变成"读代码逻辑"。**

## 三、Frida 三个核心概念：Hook / Attach / Replace

### 3.1 用比喻理解

| Frida 概念 | 现实比喻 | 一句话 |
|-----------|---------|--------|
| **Interceptor.attach** | 快递员送快递时**门口放监控**，看他几点来、拿什么，但快递照送 | 监听函数，不改行为 |
| **Interceptor.replace** | 把快递员**换成你**，包裹可以不送到收件人 | 完全替换函数 |
| **NativeFunction** | **主动打电话叫快递员** | 主动调函数 |

### 3.2 什么时候用哪个

| 场景 | 用什么 | 示例 |
|------|--------|------|
| 只看看函数何时被调、传了什么参数 | `attach` | 调试追踪 |
| 阻止原函数，换成自己的逻辑 | `replace` | 无后座力、无限时间 |
| 主动调游戏函数 | `NativeFunction` | 英雄变身、加 Buff |

### 3.3 每次修改前三问

1. 我要拦截什么函数？ → 决定 attach 还是 replace
2. 原函数还要不要执行？ → 要=attach，不要=replace
3. 这个函数每帧都调用吗？ → 是的话 attach 可能掉帧，replace 不会

## 八、"我的要求" Checklist — 实现方案

### 要求 1：全模式适配

**规律**：优先找**基类**方法。`Weapon` > `WPN_XXX`，`Entity` > `Mode_Nano6`。

### 要求 2：主副武器都生效 + 全背包

✅ 不缓存指针，每次动态 `isMyWeapon` 判断。不设武器上限。

### 要求 3：区分玩家和 Bot

| 方法 | RVA | 用途 |
|------|-----|------|
| `Weapon.get_isMyWeapon()` | `0xB6E1D0` | 是不是我的枪 |
| `Player.get_isMyPlayer()` | `0xB55FD0` | 是不是我本人 |
| `Entity.team` (字段 0x20) | — | 0=潜伏者 1=保卫者 |

### 要求 4：退出房间不崩溃

**三步法**：① Hook `OnDestroy` → ② cleanup() 清空所有缓存指针 → ③ 每次用指针前先读一字节验证。

## 九、常见问题速查表

| 问题 | 原因 | 解决 |
|------|------|------|
| hook 没效果 | 地址不对/函数没被调 | console.log 确认；查 RVA |
| 换模式失效 | hook 了特定模式的类 | 用基类方法 |
| 主武器有效副武器无效 | 只处理了主武器 | Weapon 基类 + isMyWeapon |
| 换房间闪退 | 旧指针写到已释放内存 | Hook OnDestroy 清空缓存 |
| FPS 掉帧 | 高频 hook + 慢操作 | 慢操作移出热路径 |
| bot 也有效果 | 没过滤 isMyWeapon | 每个入口都加判断 |
| 写值无效 | 值被加密 | 写原始加密值或 replace 函数 |
| **猜的逻辑不对** | 没逆向看真实代码 | **用 IDA MCP 反编译** |
