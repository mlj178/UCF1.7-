### 7.3 分支策略提示词

```
我们使用简单的双分支策略：

main          ← 稳定版本（可发布的版本）
  └─ dev      ← 开发分支（日常开发用）

只需要 2 个分支！

开发流程：
1. 所有开发工作都在 dev 分支进行
2. 功能稳定后合并到 main 分支
3. 发布新版本时在 main 分支打标签

### 7.4 日常操作流程提示词

```
早上开始工作：
  1. git pull origin dev          ← 拉取最新代码

工作中：
  2. 修改代码
  3. git add .
  4. git commit -m "描述改动"      ← 每次有意义的改动都提交

中午/下午/下班前：
  5. git push origin dev          ← 推送到码云备份

发布新版本时：
  6. git checkout main
  7. git merge dev
  8. git tag -a v1.2 -m "版本说明"
  9. git push origin main --tags
  10. git checkout dev            ← 回到开发分支
```

### 7.5 提交频率提示词

```
| 操作 | 频率 | 分支 |
|------|------|------|
| commit | 每次有意义的改动 | dev |
| push | 每天 2-3 次 | dev |
| merge 到 main | 发布新版本时 | main |
| 打标签 | 发布新版本时 | main |
```

### 7.6 测试版管理提示词

```
文件结构：
dev 分支
  ├─ 测试版/无限时间/
  ├─ 测试版/快刀/

## 八、常见问题排查提示词

### 8.1 AI 多轮对话混乱提示词

```
trae对轮对话，思路已经晕掉了。目标和步骤完全不知道了。

trae把整个多轮对话导出成md，让deepseek网页版去分析我的需求和现状，分析我的目标和我现在遇到的问题，已经解决了什么，还有什么未解决，问题的解决方案有哪些？
```

### 8.2 创建新文件导致混乱提示词

```
RVA的地址为什么经常出错，不都是从dump.cs中读取到的吗？

创建新文件，不会沿用 v1.1 的正确实现，而是自行换了一套实现方式（改了地址、改了 Hook 方式、改了偏移）。

解决方案：
1. 在提示词中明确指示，原来的文件代码逻辑和数据一个字都不要更改。
2. 尽可能的减少创建新文件，版本更迭，不断创建新文件会消耗很多token，还有就是会造成上下文的混乱，逻辑混乱，数据混乱。
```

### 8.3 JS 转 PY 时代码被修改提示词

```

## 附录：核心原则

### 开发原则

1. **从"猜代码逻辑"变成"读代码逻辑"** - 使用 IDA Pro MCP 反编译
2. **优先使用 `Interceptor.replace`** - 性能优于 `attach`
3. **只修改玩家的，不影响Bot** - 必须添加玩家识别逻辑
4. **切换房间不崩溃** - 必须添加清理机制
5. **版本更迭保持逻辑一致** - 减少创建新文件

### 工作流原则

1. **需求分析** - 明确功能目标，拆解步骤
2. **游戏分析** - dump.cs 搜索，IDA 反编译
3. **脚本开发** - 选择修改方式，编写脚本
4. **Python UI** - 可视化界面，自动连接
5. **测试验证** - 全模式测试，区分玩家Bot
6. **打包发布** - JS 转 Python，整合打包
7. **版本管理** - dev/main 分支，Git 提交
