# speed_knife_v5 快刀脚本 — 只有团队模式能用，其他模式无效，而且卡顿

## 问题一：只在团队模式生效，其他模式完全无效

### 出问题的代码（原第58-67行）

```javascript
var MAX_PLAYER_WEAPONS = 2;

function isPlayerWeapon(weaponPtr) {
    var key = weaponPtr.toString();
    if (playerWeapons[key]) return true;       // 已缓存 → 放行
    if (playerWeaponCount < MAX_PLAYER_WEAPONS) { // 未缓存且 < 2 → 加入缓存
        playerWeapons[key] = true;
        playerWeaponCount++;
        return true;
    }
    return false;  // ❌ 超过2个后，所有新武器指针全部拒绝！
}
```

### 通俗解释

这个函数的作用是"认武器"——判断当前操作的是不是玩家的刀。它的逻辑是：

1. 如果这个武器指针之前见过（已缓存），放行
2. 如果没见过，但缓存里还没超过2个，就把它加进去，放行
3. **如果没见过，而且缓存里已经有2个了，直接拒绝**

### 为什么团队模式能用？

团队模式里，玩家的武器对象从开局到结束都是同一块内存，指针不变。前两次挥刀注册了2个指针，之后每次挥刀都是这2个老指针，都能在缓存里找到 → 一直放行 → 一直生效。

### 为什么其他模式不能用？

其他模式（个人战、生化等）有个关键区别：**玩家死亡重生后，武器对象会被游戏重新分配到新的内存地址**，产生新的指针。

问题链条如下：

1. 开局第一次挥刀，注册了武器指针A → 缓存已有1个
2. 开局第二次挥刀（或换刀），注册了武器指针B → 缓存已有2个，满了
3. 玩家死亡重生，武器对象变成新指针C
4. 挥刀时，`isPlayerWeapon(C)` 发现C不在缓存里，而且缓存已满（2个）→ **直接返回false，拒绝！**
5. 新武器永远无法注册，脚本对这个武器完全不生效

### 还有一个致命的"死锁"

缓存清理的代码是这样的：

```javascript
if (keys.length > 10) {  // 超过10个才清理
    playerWeapons = {};
    playerWeaponCount = 0;
}
```

但 `MAX_PLAYER_WEAPONS = 2` 限制了缓存最多只能有2条记录，**永远不可能超过10**，所以**缓存永远不会被清理**！旧指针变成悬空指针（指向已释放的内存），新武器永远进不来。

## 问题二：游戏严重卡顿

### 出问题的代码（原第127-137行）

```javascript
setInterval(function() {
    var keys = Object.keys(playerWeapons);  // 每16ms创建一个新数组
    for (var i = 0; i < keys.length; i++) {
        var weaponPtr = ptr(keys[i]);        // 每16ms创建新NativePointer对象
        setAllSpeeds(weaponPtr, "TIMER");    // 每次做2次指针解引用+2次内存写入
    }
}, 16);  // 16毫秒执行一次！
```

### 通俗解释

这个定时器的作用是"持续写入速度值，防止被游戏覆盖回去"。想法没错，但执行方式有严重问题：

### 卡顿原因逐条分析

| 因素 | 为什么卡 |
|------|----------|
| **16ms执行一次**（每秒62.5次） | 完全没必要这么快。Hook已经在每次挥刀时即时写入了，定时器只是保底防覆盖，100ms一次绰绰有余 |
| **`Object.keys()`每16ms调用** | 每次调用都创建一个新数组对象，用完就扔。每秒创建62个临时数组，垃圾回收器（GC）压力巨大 |
| **`ptr()`每16ms调用** | 每次创建一个新的NativePointer对象，同样是临时对象，加重GC负担 |
| **`Process.findRangeByAddress`** | 这是`isReadablePointer`内部调用的函数，它是一个**昂贵的系统调用**，每次都要遍历整个进程的内存区域列表来检查指针是否可读。每秒被调用上百次 |
| **Hook+Timer双重写入** | 同一个内存地址，Hook刚写入，16ms后Timer又写入同样的值，完全冗余 |
| **悬空指针写入** | 团队模式外的旧指针可能已经指向被释放的内存，`isReadablePointer`可能误判为可读，然后往随机内存写入数据，可能导致崩溃 |

### 打个比方

就像你家里有个水龙头在滴水（游戏覆盖速度值），你需要每隔一段时间拧一下。

- **原代码的做法**：每0.016秒拧一次，每次拧之前还要翻一遍整本电话簿确认这个水龙头还在（`Process.findRangeByAddress`），拧完把记录本撕一页扔掉（`Object.keys()`创建临时数组），结果手忙脚乱还把家里搞得满地废纸（GC压力）
- **正确的做法**：每0.1秒拧一次就够了，记录本用个带过期时间的列表，过期的自动划掉

## 修复方案

### 修复1：武器缓存改为动态注册+TTL过期

- 去掉 `MAX_PLAYER_WEAPONS = 2` 的硬限制，新武器随时可以注册
- 每个缓存条目记录最后活跃时间，30秒没被Hook触发就自动过期
- 每5秒检查一次，清理过期和无效的指针
- 这样无论重生多少次，新武器都能注册，旧武器自动清理

### 修复2：定时器降频+减少临时对象

- 定时器间隔从16ms改为100ms（每秒10次，足够防止覆盖）
- 直接遍历缓存数组，不再用`Object.keys()`创建临时数组
- 抽取`safeReadFloat`/`safeWriteFloat`统一处理异常，代码更清晰
