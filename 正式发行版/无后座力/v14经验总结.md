# 无后座力 v14 经验总结

**文件**：`AAAAA-no_recoil_v14.js`（摘自 `game_modifier.py` 的无后座部分）  
**实现方式**：`Interceptor.replace` + 清零4个后座力字段 + 不执行原函数  
**适用范围**：所有武器（主武器、副武器、拾取枪）、全模式  
**生效条件**：注入脚本后自动启用，无需区分玩家/Bot

---

## 1. 实现原理

游戏中的后座力由 `Recoil.OnGunShot()` 方法产生，该方法在每次开火时被调用，会向 `Recoil` 实例的四个浮点字段写入随机后座力值，随后驱动镜头抖动。

v14 的做法是**直接替换这个函数的实现**：用 Frida 的 `Interceptor.replace` 把 `Recoil.OnGunShot` 替换成一个自定义回调，回调中只做一件事——将后座力相关的四个字段全部清零，然后直接返回，**不让原始函数执行**。

### 清零的四个字段

| 偏移   | 字段名（IL2CPP）            | 说明             |
| ------ | --------------------------- | ---------------- |
| `0x68` | `<addYaw>k__BackingField`   | 水平后座力偏移量 |
| `0x6C` | `<addPitch>k__BackingField` | 垂直后座力偏移量 |
| `0x70` | `addYaw_Target`             | 水平后座力目标值 |
| `0x74` | `addPitch_Target`           | 垂直后座力目标值 |

**为什么必须清零全部四个？**  
`addYaw_Target` 和 `addPitch_Target` 是**私有字段**，外部 setter 无法访问，但原始函数会直接写入。如果只清零前两个暴露的属性，后座力仍然会通过这两个 target 字段生效，镜头依旧会抖动。只清2个字段等于剪了炸弹的两根线，剩两根照样引爆。

### 为什么用 `replace` 而不是 `attach`？
- `Interceptor.attach` 是在函数执行前后插入代码，但原函数依然会运行，并且后两个私有字段的写入**发生在原函数内部**，attach 无法拦截原始写入。
- `Interceptor.replace` 则完全接管函数，原函数根本不会执行，因此不会有任何后座力值被写入内存。

---

## 2. 优点

| 优点           | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| **零状态**     | 不缓存任何指针，不依赖玩家识别，无字典/定时器，内存占用极低。 |
| **全武器覆盖** | `Recoil.OnGunShot` 是所有枪械共用的方法，拾取的枪、副武器等都走同一个入口。 |
| **全模式通用** | 不依赖任何模式特定逻辑，团队、生化、纳米等模式均生效。       |
| **性能优异**   | 函数只在开枪时触发，替换后的回调仅执行四次内存写入，流畅无卡顿。 |
| **无泄漏风险** | 房间/模式切换时不会残留野指针，因为不存储任何对象引用。      |
| **即时生效**   | 脚本注入后立即生效，无需等待回合或切枪。                     |

## 3. 与旧版本的对比（V14 之前的尝试）

| 版本        | 做法                        | 结果                            |
| ----------- | --------------------------- | ------------------------------- |
| 早期 attach | attach OnGunShot 后清零字段 | 相机仍抖动（Target 字段未清零） |
| v14 replace | replace OnGunShot 清零4字段 | ✅ 完美无后座                    |

**教训**：修改一个功能时，必须完整分析它在内存中改动了哪些变量，不能仅凭公开属性或局部字段动手。

---

## 4. 代码关键点

- **`NativeCallback` 签名**：`'void'` 返回值，参数 `['pointer', 'pointer']` 对应 `Recoil_o* __this, MethodInfo* method`，与 IL2CPP 函数签名完全一致。
- **日志静默**：为减少控制台输出，只打印前3次抑制信息，后续静默。
- **错误处理**：内存写入用 `try-catch` 包裹，避免因意外情况导致脚本崩溃。
- **自动启用**：脚本加载后立即调用 `enable()`，无需手动操作。
