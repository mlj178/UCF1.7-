# 定点瞬移-简要说明
feature_id: fixed_point_teleport

## 目标

定点瞬移提供两个临时保存点：点位1和点位2。玩家保存点位1或点位2后，可以通过对应按钮或快捷键把本地玩家瞬移回该点位。

## 实现原则

1. Hook `Player.Update` 捕获当前本地 `Player`。
2. 保存时通过 `Component.get_transform` 和 `Transform.get_position_Injected` 读取本地玩家位置。
3. 瞬移时调用原游戏 `Player.SetPos(Vector3)`，不直接写 Transform。
4. 按钮 RPC 只设置 pending 槽位，真正保存/瞬移在下一次 `Player.Update` 内执行。
5. 保存点绑定当前 `roomGeneration`；同一房间内普通回合结束或新回合开始时保留点位，只取消尚未执行的 pending 动作。
6. `mode_base_changed`、房间对象销毁、关闭功能或执行 `cleanup()` 时清空点位。
7. 只处理本地玩家，不处理人机和其他玩家。

## RPC

标准 RPC：
- `enable()`
- `disable()`
- `status()`
- `cleanup()`
- `setconfig(config)`

点位动作 RPC：
- `savepoint()`：保存点位1。
- `teleporttopoint()`：瞬移到点位1。
- `savepoint2()`：保存点位2。
- `teleporttopoint2()`：瞬移到点位2。

## 快捷键

- `Alt+1`：保存点位1。
- `Alt+2`：瞬移到点位1。
- `F1`：保存点位2。
- `F2`：瞬移到点位2。

这四个快捷键固定给定点瞬移使用，不参与普通功能快捷键绑定。

## 边界

- 保存点只在当前房间生命周期内存在，同一房间内可跨普通回合使用。
- `GameManager.GameRoundEnd` 和 `GameManager.NewGameRoundStart` 只取消尚未执行的 pending 动作，不清空点位。
- `mode_base_changed`、房间对象销毁、关闭功能或执行 `cleanup()` 时会清空旧点位。
- 开关状态可恢复，但运行时指针、点位和 pending 动作不跨局信任。
- 点位2只新增一组保存/瞬移动作，不引入点位列表管理、重命名或持久化保存点。
