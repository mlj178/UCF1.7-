# 高跳空中移动只读探针设计

## 目标

在不修改游戏内存、不调用修改器功能、不替换游戏函数的前提下，自动等待并附加 `UnityCrossFire` 游戏进程，记录高跳期间 WSAD 水平移动的数据，为整合包 2.4 与 2.5 的运行时表现提供可比证据。

## 交付位置

探针、运行日志和摘要报告均位于：

`D:\trae_project\ucf1.7-modifier\06-测试\gravity_airmove_probe\`

整合包源码目录只保存本设计说明；探针不会写入或改动该目录中的现有代码。

## 运行方式

1. 运行探针并提供本次测试标签（`2.4` 或 `2.5`）。
2. 探针轮询本机进程，发现名称含 `unitycrossfire` 的游戏进程后附加。
3. 探针确认 `GameAssembly.dll` 已加载，再安装只读观察 Hook。
4. 用户在对局中复现：地面移动、起跳、空中按住 W/A/S/D、落地。
5. 游戏退出或用户按 Ctrl+C 后，探针写入本次日志摘要并安全脱离。

不会自动重试附加已退出的进程；下一次运行创建新的日志文件，避免混入不同对局的数据。

## 只读边界

- 只使用 Frida `Interceptor.attach` 观察调用参数与返回后的内存状态。
- 只执行 `readU8`、`readFloat`、`readPointer` 等读取操作。
- 禁止 `write*`、`Interceptor.replace`、修改代码页、调用修改器 RPC 或修改功能状态。
- 对每次读取、Hook 安装和异常均记录日志；无法验证的字段一律标记为 `unreadable`，不猜测其含义。

## 观测点与记录内容

| 观测点 | 依据 | 记录内容 |
| --- | --- | --- |
| `Player.MoveByLocalDirection`（RVA `0xB50A00`） | 当前穿墙功能已使用该移动入口 | 本地玩家指针、调用次数、进入/返回后的字段快照 |
| `CharacterController.Move`（RVA `0xAB8210`） | 当前穿墙功能已使用该角色控制器入口 | X/Z 位移参数、调用结果、每秒聚合的移动次数 |
| 本地 `Player` 字段 | 高跳脚本正在读取/写入这些地址 | `+0x70`、`+0x88`、`+0x90 -> +0x10` 的 Y 速度 |
| `GameAssembly.dll` | 所有 RVA 的基准 | 基址、模块大小、进程 ID、架构 |

探针先以安全的参数可读性检查识别 `CharacterController.Move` 的 X/Z 位移参数。若当前游戏调用约定与预期不符，只记录原始参数地址和“不可解析”状态，不会解引用未知地址。

## 日志与摘要

每次运行生成两个文件：

- `gravity_airmove_<标签>_<时间戳>.jsonl`：逐事件 JSON 日志，包含时间戳、事件类型和只读快照。
- `gravity_airmove_<标签>_<时间戳>_summary.json`：会话摘要，包含附加状态、模块信息、Hook 命中数、离地状态样本数、可解析的水平移动样本数、读取/Hook 错误。

日志会进行速率限制：字段快照按 100 ms 最多一条，移动事件按 50 ms 最多一条；相同错误按 1 秒最多一条。这样可以观察空中状态变化，同时避免日志影响游戏帧率。

## 成功标准

- 游戏启动前运行探针，探针能自动发现并附加目标进程。
- 日志明确说明每个 RVA 是否成功 Hook，所有读取是否成功。
- 一次高跳测试至少能得到起跳/空中/落地状态样本，以及空中期间的角色控制器水平移动事件或“未出现该事件”的证据。
- 2.4 与 2.5 分别运行后，两个摘要可直接按同一字段比较，不依赖猜测。

## 已知限制

该探针只能证明“水平输入/移动调用/字段状态在哪一阶段出现差异”，不能仅凭字段偏移名称判定其游戏语义。若 2.4 与 2.5 的数据仍无差异，下一阶段再针对已确认的异常调用路径添加更窄的只读调用追踪。
