# 角色变身动作快捷键设计

## 目标

让“角色变身”卡片的四个一次性动作可分别绑定到 Ctrl+1 至 Ctrl+5 的任一普通功能快捷键槽位。按下绑定的组合键时，行为必须与点击对应按钮一致。

四个可选动作如下：

- 本地玩家：选择英雄（`local_hero`）
- 本地玩家：选择超级终结者（`local_terminator`）
- 所有 Bot：随机英雄（`bot_hero`）
- 所有 Bot：随机超级终结者（`bot_terminator`）

## 交互与数据模型

“设置 → 快捷键”中，Ctrl+1～Ctrl+5 的下拉框保留现有普通功能选项，并追加以上四个明确命名的动作选项。

快捷键绑定值支持两类内容：

- 现有功能 ID 字符串：继续按原来的开关或默认动作逻辑执行。
- 动作绑定对象：包含 `feature_id: "role_transform"`、`action: "trigger"` 和对应的 `payload.action`。触发时原样转交给动作控制器。

读取已有 `hotkeys.json` 时，旧字符串配置继续有效。保存新配置时，普通功能保持原有字符串格式；角色变身动作以对象保存。这样不会破坏用户已有快捷键。

## 约束与冲突规则

- 四个动作彼此独立：可分别占用多个 Ctrl 槽位。
- 同一个具体动作不能重复绑定到两个槽位；已绑定的动作会从其他下拉框的候选项中隐藏。
- 角色变身动作与普通功能共享 Ctrl+1～Ctrl+5 的五个槽位，一个槽位只能绑定一项。
- F1、F2、Alt+1、Alt+2 仍是定点瞬移固定快捷键，不作任何改动。

## 实现边界

调整快捷键配置、设置页候选项与热键分派，使分派支持带 payload 的动作绑定。角色变身的 manifest、面板按钮、RPC 与 Frida 脚本不修改。

## 验证

- 对配置读取、候选项去重和分派分别添加或更新自动化测试。
- 覆盖旧字符串配置兼容性，以及四个动作分别生成正确的 `role_transform / trigger / payload.action` 请求。
- 运行相关 Python 测试，并做语法检查。
