# 定点瞬移 F1/F2 快捷键问题与解决方案

## 一、问题现象

- 定点瞬移点位2改为以下快捷键：
  - `F1`：保存点位2
  - `F2`：瞬移到点位2
- 鼠标点击“保存点位2”和“瞬移到点位2”按钮可以正常生效。
- 修改器位于前台时，按 F1/F2 可以正常生效。
- 游戏位于前台时，按 F1/F2 没有反应。
- 修改器和游戏使用相同权限运行后，问题依然存在。

## 二、原因分析

定点瞬移功能本身没有问题，故障出在后台快捷键监听层。

原来的实现有两条按键路径：

1. 修改器位于前台时，由 Tk 窗口按键绑定接收 F1/F2，因此可以生效。
2. 游戏位于前台时，只能依赖 Python `keyboard` 库的全局键盘钩子。该钩子在当前游戏前台环境中无法可靠接收 F1/F2。

因此，这不是以下问题：

- 不是键盘 Fn 模式问题。
- 不是游戏与修改器权限不同。
- 不是定点瞬移 RPC 或 Frida 脚本故障。
- 不是点位2的按钮逻辑故障。

## 三、解决方案

将 F1/F2 从第三方 `keyboard` 全局钩子改为 Windows 原生系统快捷键：

- 使用 `RegisterHotKey` 注册 F1、F2。
- 使用独立消息线程处理 `WM_HOTKEY`。
- F1 触发“保存点位2”。
- F2 触发“瞬移到点位2”。
- 使用 `MOD_NOREPEAT`，避免长按按键造成连续触发。
- 修改器退出或重新应用快捷键时，调用 `UnregisterHotKey` 解除注册。
- 如果原生快捷键注册失败，则自动回退到原来的 `keyboard.add_hotkey`，并记录错误码。
- 删除 Tk 层对 F1/F2 的重复绑定，避免修改器位于前台时一次按键触发两次。
- Alt+1、Alt+2继续使用原有逻辑，不受影响。

## 四、修改后的快捷键

| 快捷键 | 功能 |
| --- | --- |
| Alt+1 | 保存点位1 |
| Alt+2 | 瞬移到点位1 |
| F1 | 保存点位2 |
| F2 | 瞬移到点位2 |

已删除的快捷键：

- F3
- Alt+3
- Alt+4

## 五、验证结果

- Windows 原生 F1/F2注册成功。
- 原生快捷键消息分派测试通过。
- 注册失败回退测试通过。
- 退出时解除注册测试通过。
- Python 编译检查通过。
- 游戏位于前台时，F1保存点位2和F2瞬移到点位2均已实测生效。

## 六、相关代码

- `game_modifier/core/native_hotkey_listener.py`：Windows 原生快捷键注册、消息处理和清理。
- `game_modifier/core/hotkey_manager.py`：原生快捷键接入、动作分派和失败回退。
- `game_modifier/ui/app.py`：移除 Tk 的 F1/F2重复监听。
- `game_modifier/core/test_native_hotkey_listener.py`：原生快捷键回归测试。

## 七、注意事项

- 修改快捷键代码后必须完全退出并重新启动修改器，正在运行的 Python 进程不会自动加载新代码。
- 如果以后 F1/F2注册失败，应先检查日志中的 Windows 错误码，并确认是否被其他程序独占注册。
