🎯 项目简介

这是一个穿越火线游戏修改器，使用 Python + Frida + JavaScript + C++ DLL 技术栈开发。程序通过注入代码到游戏进程，实现各种游戏功能修改。

通俗理解：想象你有一个遥控器，可以控制游戏里的各种参数（比如移动速度、武器威力等）。这个项目就是制作这个遥控器的工具。

💡 设计巧思

1. 单例模式 - 全局唯一实例

👑 什么是单例？

通俗解释：单例就是"一个国家只有一个总统"。程序中的某些管理器（比如EventBus、FridaManager）只能有一个实例，不能创建多个。

单例模式代码：
class EventBus:
    _instance = None  # 类变量，保存唯一实例
    _lock = threading.Lock()  # 线程锁
    
    @classmethod
    def get_instance(cls):
        if cls._instance is None:  # 如果还没有实例
            with cls._lock:  # 加锁（防止多线程同时创建）
                if cls._instance is None:
                    cls._instance = cls()  # 创建实例
        return cls._instance  # 返回唯一实例

为什么使用单例？因为EventBus是"广播站"，如果有多个广播站，消息就会混乱。FridaManager是"注入管理器"，如果有多个，就会重复注入导致游戏崩溃。

2. 事件总线 - 模块间通信

📡 模块间的广播站

通俗解释：EventBus就像一个广播站，一个模块发送消息，所有订阅了该消息的模块都能收到。比如UI层发送"游戏已连接"消息，日志模块、音效模块都能收到并做出反应。

3. 功能注册表 - 统一管理功能

📋 功能的花名册

通俗解释：FeatureRegistry就像一个花名册，记录了所有功能模块。程序启动时，所有功能模块自动注册到花名册中，方便统一管理。

4. 状态持久化 - 自动保存用户设置

💾 自动保存和恢复

通俗解释：程序关闭时自动保存所有功能的开关状态和参数值，下次启动时自动恢复到上次的设置。用户不需要每次都重新设置。

1. game_session_manager.py - 游戏会话管理器

作用：检测游戏是否运行，自动连接/断开，管理整个游戏会话的生命周期。

核心代码解析：
class GameSessionManager:
    # 单例模式
    _instance = None
    _singleton_lock = threading.Lock()
    
    @classmethod
    def get_instance(cls):
        """获取单例实例"""
        if cls._instance is None:
            with cls._singleton_lock:
                if cls._instance is None:
                    cls._instance = cls()
        return cls._instance
    
    def __init__(self):
        # 初始化状态机
        self._state = SessionState.NO_GAME
        self._pid = None  # 游戏进程ID
        self._pid_create_time = None  # 进程创建时间
        self._lock = threading.Lock()  # 线程锁
        self._stop_event = threading.Event()  # 停止事件
        self._worker_thread = None  # 工作线程
        self._frida_manager = None  # Frida管理器
        self._universal_manager = None  # DLL管理器
        self._desired_states = {}  # 用户期望的功能状态
        self._applied_states = {}  # 实际应用的功能状态
    
    def start(self):
        """启动会话管理器"""
        self._load_desired_states()  # 加载用户期望状态
        self._stop_event.clear()
        # 启动后台线程，每2秒执行一次状态机
        self._worker_thread = threading.Thread(target=self._worker_loop, daemon=True)
        self._worker_thread.start()
    
    def _worker_loop(self):
        """后台线程循环"""
        while not self._stop_event.is_set():
            self._state_machine_step()  # 执行状态机的一步
            time.sleep(2)  # 每2秒执行一次
    
    def _state_machine_step(self):
        """状态机的一步"""
        current_state = self._state
        
        # 根据当前状态执行对应的步骤
        if current_state == SessionState.NO_GAME:
            self._step_no_game()  # 没有游戏，检测游戏进程
        elif current_state == SessionState.WAITING_GAME_READY:
            self._step_waiting_game_ready()  # 等待游戏稳定
        elif current_state == SessionState.CONNECTING_EXISTING_DLL:
            self._step_connecting_existing_dll()  # 连接现有DLL
        elif current_state == SessionState.INJECTING_DLL:
            self._step_injecting_dll()  # 注入DLL
        elif current_state == SessionState.SYNCING_FEATURES:
            self._step_syncing_features()  # 同步功能状态
        elif current_state == SessionState.CONNECTING_FRIDA:
            self._step_connecting_frida()  # 连接Frida
        elif current_state == SessionState.READY:
            self._step_ready()  # 准备就绪，监控游戏

为什么需要：如果没有这个文件，程序就无法自动检测游戏、自动连接、自动断开。用户需要手动点击"连接"按钮，而且游戏关闭后程序不会自动断开，可能导致错误。

等待0.5秒，确保进程稳定，避免刚启动就崩溃
⬇️

尝试通过命名管道连接游戏中已有的DLL
⬇️
4

如果游戏中没有DLL，则注入 Universal-ImGui-Hook.dll
⬇️
5

2. frida_manager.py - Frida注入管理器

作用：管理Frida注入过程，加载JavaScript代码，发送消息到游戏内部。

核心代码解析：
class FridaManager:
    _instance = None
    _lock = threading.Lock()

    def __init__(self):
        self._session = None  # Frida会话
        self._script = None  # 注入的脚本
        self._ready = False  # 是否准备就绪
        self._pid = None  # 游戏进程ID
        self._event_bus = EventBus.get_instance()
    
    def connect(self, pid):
        """连接到游戏进程"""
        # 1. 使用Frida附加到进程
        self._session = frida.attach(pid)
        
        # 2. 构建JavaScript代码（加载所有功能的JS代码）
        js_code = self._build_js_code()
        
        # 3. 注入JavaScript代码
        self._script = self._session.create_script(js_code)
        self._script.on('message', self._on_message)  # 设置消息回调
        self._script.load()  # 加载脚本
        
        self._ready = True
        return True, "连接成功"
    
    def _build_js_code(self):
        """构建JavaScript代码"""
        parts = []
        
        # 1. 加载通用函数
        common_path = os.path.join(SCRIPTS_DIR, '_common.js')
        with open(common_path, 'r', encoding='utf-8') as f:
            parts.append(f.read())
        
        # 2. 加载所有功能的JavaScript代码
        registry = FeatureRegistry.get_instance()
        for feature in registry.get_all():
            js_code = feature.get_js_code()
            if js_code:
                parts.append(js_code)
        
        # 3. 添加消息分发器
        parts.append(self._build_dispatcher())
        
        return '\n\n'.join(parts)
    
    def send_toggle(self, feature_id, enabled):
        """发送功能开关消息"""
        self._script.post({
            'type': 'toggle',
            'feature': feature_id,
            'enable': enabled
        })

3. event_bus.py - 事件总线

作用：模块间的消息广播站，一个模块发送消息，所有订阅的模块都能收到。

核心代码解析：
class EventBus:
    _instance = None
    _lock = threading.Lock()

    def __init__(self):
        self._subscribers = defaultdict(list)  # 订阅者列表
        self._lock = threading.Lock()
    
    def subscribe(self, event_type, callback):
        """订阅消息（收听广播）"""
        with self._lock:
            # 使用弱引用避免内存泄漏
            ref = weakref.WeakMethod(callback) if hasattr(callback, '__self__') else callback
            self._subscribers[event_type].append(ref)
    
    def emit(self, event_type, **kwargs):
        """发送消息（广播）"""
        with self._lock:
            subscribers = list(self._subscribers.get(event_type, []))
        
        # 在新线程中执行回调，避免阻塞
        for ref in subscribers:
            callback = self._resolve_ref(ref)
            if callback:
                threading.Thread(target=callback, kwargs=kwargs, daemon=True).start()

为什么需要：如果没有这个文件，模块间通信会非常困难。比如UI层要通知日志模块、音效模块、状态管理模块，需要分别调用每个模块的方法，代码会非常冗余。

1
模块A订阅消息
bus.subscribe('connection_status', callback)
⬇️
2
模块B订阅消息
bus.subscribe('connection_status', callback2)
⬇️
3
模块C发送消息
bus.emit('connection_status', status='connected')
⬇️
4
模块A和B收到消息
在新线程中执行回调，避免阻塞

4. feature_registry.py - 功能注册表

作用：统一管理所有功能模块，提供查询和遍历功能。

核心代码解析：
class FeatureRegistry:
    _instance = None
    _lock = threading.Lock()

    def __init__(self):
        self._features = {}  # 功能字典 {feature_id: feature_instance}
        self._lock = threading.Lock()
    
    def register(self, feature_instance):
        """注册功能到花名册"""
        with self._lock:
            self._features[feature_instance.feature_id] = feature_instance
    
    def get_all(self):
        """获取所有功能"""
        with self._lock:
            return list(self._features.values())
    
    def get(self, feature_id):
        """根据ID获取功能"""
        with self._lock:
            return self._features.get(feature_id)

# 装饰器：自动注册功能
def register_feature(cls):
    instance = cls()  # 创建功能实例
    FeatureRegistry.get_instance().register(instance)  # 注册到花名册
    return cls

为什么需要：如果没有这个文件，需要手动管理所有功能，容易遗漏。新增功能时需要修改多处代码，维护困难。

    def setup_hotkeys(self, toggle_callback, silent=False):
        """设置快捷键"""
        self._toggle_callback = toggle_callback
        
        # 清除旧的快捷键
        for handle in self._hotkey_handles:
            handle.unhook()
        self._hotkey_handles = []
        
        # 遍历所有快捷键位置
        for pos in HOTKEY_POSITIONS:
            feature = self._hotkeys.get(pos)  # 获取对应的功能ID
            if feature:
                # 绑定快捷键
                callback = functools.partial(self._on_hotkey_triggered, feature)
                handle = keyboard.add_hotkey(pos, callback)
                self._hotkey_handles.append(handle)
    
    def _on_hotkey_triggered(self, feature):
        """快捷键触发时的回调"""
        if self._toggle_callback:
            # 在主线程中执行切换（避免线程安全问题）
            self._app.after(0, lambda: self._toggle_callback(feature))

与用户点击开关的区别：

  • 触发方式不同：快捷键通过键盘事件触发，用户点击通过鼠标事件触发
  • 执行线程不同：快捷键回调在后台线程执行，需要用 app.after() 切换到主线程
  • 后续流程相同：都是调用同一个 toggle_callback 函数，执行相同的切换逻辑

❓ 问题6：IPC机制是什么，是否还有其他更好的方案？

答：IPC（Inter-Process Communication，进程间通信）是指不同进程之间交换数据的机制。在这个项目中，Python主程序和游戏内的DLL需要通信，就用到了IPC。

🔧 当前使用的IPC方案
命名管道（Named Pipe）：
# Python端（客户端）
pipe_name = f"\\\\.\\pipe\\UniversalHook_{pid}"
pipe_handle = kernel32.CreateFileW(
    pipe_name,
    GENERIC_READ | GENERIC_WRITE,
    0, None, OPEN_EXISTING,
    FILE_FLAG_OVERLAPPED, None
)

# 发送消息
message = json.dumps({"type": "set_esp", "enabled": True})
kernel32.WriteFile(pipe_handle, message.encode(), ...)

# DLL端（服务端）
# 创建命名管道
pipe_handle = CreateNamedPipe(
    "\\\\.\\pipe\\UniversalHook_1234",
    PIPE_ACCESS_DUPLEX | FILE_FLAG_OVERLAPPED,
    PIPE_TYPE_MESSAGE | PIPE_READMODE_MESSAGE,
    1, 0, 0, 0, NULL
);

// 监听连接
ConnectNamedPipe(pipe_handle, NULL);

// 读取消息
ReadFile(pipe_handle, buffer, sizeof(buffer), &bytesRead, NULL);

为什么选择命名管道？

  • ✅ Windows原生支持，无需额外依赖
  • ✅ 支持双向通信，Python和DLL都可以发送消息
  • ✅ 支持异步IO，不会阻塞主线程
  • ✅ 性能较好，适合频繁通信
  • ✅ 安全性高，只能本地访问
🔄 其他IPC方案对比
方案 优点 缺点 适用场景
命名管道
（当前方案）		 Windows原生，双向通信，异步IO，性能好 仅限Windows，需要手动处理序列化 本地进程间高频通信
共享内存 性能最高，适合大数据传输 需要同步机制（锁），编程复杂 大量数据传输
Socket 跨平台，支持远程通信 性能较低，需要端口管理 跨机器通信
消息队列 解耦，支持多对多通信 Windows消息队列性能一般 低频消息传递
COM/DCOM 功能强大，支持远程调用 复杂，学习成本高 企业级应用

结论：对于这个项目，命名管道是最合适的方案。因为：

  • 只需要本地通信，不需要跨机器
  • 需要频繁通信（每秒可能几十次）
  • 需要双向通信（Python发送指令，DLL返回结果）
  • Windows原生支持，无需额外依赖

def _build_js_code(self):
    """构建JavaScript代码"""
    parts = []
    
    # 1. 加载通用函数
    common_path = os.path.join(SCRIPTS_DIR, '_common.js')
    with open(common_path, 'r', encoding='utf-8') as f:
        parts.append(f.read())
    
    # 2. 加载所有功能的JavaScript代码
    registry = FeatureRegistry.get_instance()
    for feature in registry.get_all():
        js_code = feature.get_js_code()  # 读取 knife.js, movespeed.js 等
        if js_code:
            parts.append(js_code)
    
    # 3. 添加消息分发器
    parts.append(self._build_dispatcher())
    
    # 4. 合并所有代码
    return '\n\n'.join(parts)

# gravity.js (重力修改功能代码)
# ... (所有功能的代码)

  • ✅ 代码量小：所有功能的JS代码加起来也就几十KB

// _common.js
// 消息分发器：接收Python发来的消息，调用对应的功能模块
recv('toggle', function(data) {
    var featureName = data.feature;  // 功能名，如 'knife'
    var enable = data.enable;        // 开启或关闭
    
    // 根据功能名调用对应的模块
    if (featureName === 'knife') {
        if (enable) {
            modules.knife.enable();   // 开启快刀
        } else {
            modules.knife.disable();  // 关闭快刀
        }
    } else if (featureName === 'movespeed') {
        if (enable) {
            modules.movespeed.enable();
        } else {
            modules.movespeed.disable();
        }
    }
    // ... 其他功能
    
    recv('toggle', arguments.callee);  // 继续监听下一条消息
});

// knife.js
var modules = modules || {};
modules.knife = {
    enable: function() {
        // 修改游戏内存，提升挥刀速度
        Memory.writeFloat(speedAddress, 10.0);
        sendLog('success', '快刀已开启');
    },
    disable: function() {
        // 恢复游戏内存，还原挥刀速度
        Memory.writeFloat(speedAddress, 1.0);
        sendLog('info', '快刀已关闭');
    }
};

重要概念：

  • 开启 ≠ 注入：开启功能只是调用 enable() 方法，修改游戏内存。注入是在游戏启动时一次性完成的。
  • 关闭 ≠ 销毁：关闭功能只是调用 disable() 方法，恢复游戏内存。代码仍然在内存中，随时可以再次开启。
  • 销毁 = 断开连接：只有当游戏关闭或程序断开Frida连接时，JavaScript代码才会从内存中卸载。
