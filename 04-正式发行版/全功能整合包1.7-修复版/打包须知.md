# 打包须知

## 打包配置文件

### game_modifier.spec

这是 **PyInstaller 打包配置文件**，用于将 Python 项目打包成独立的 exe 可执行文件。

#### 主要功能

1. **数据文件收集**
   - 资源文件（音效、图片）来自 `资源` 目录
   - JavaScript 脚本来自 `scripts` 目录
   - 用户配置JSON不参与打包
   - 插件文件（DLL、inject.exe）来自 `plugins` 目录

2. **模块分析配置**
   - 主入口：`main.py`
   - 显式导入：`hiddenimports` 列表中指定的所有模块
   - 自动分析：PyInstaller 自动分析依赖关系

3. **EXE 生成配置**
   - 文件名：`UCF1.7修改器.exe`
   - 无控制台：`console=False`（窗口程序，不显示黑框）
   - 管理员权限：`manifest='app.manifest'`（请求 UAC 提权）
   - 压缩优化：`upx=True`（使用 UPX 压缩减小体积）

#### 打包流程
```
game_modifier.spec
       ↓
   PyInstaller
       ↓
   分析依赖关系
       ↓
   收集所有文件
       ↓
   打包成单个 exe
       ↓
UCF1.7修改器.exe (约 66 MB)
```

#### 为什么需要这个文件？

1. **单文件分发**：用户无需安装 Python 环境即可运行
2. **资源嵌入**：所有依赖文件都打包进 exe 内部
3. **路径处理**：通过 `sys._MEIPASS` 正确访问打包后的资源
4. **权限管理**：通过 manifest 确保以管理员权限运行

## 打包输出

- **输出目录**：`game_modifier/dist/`
- **可执行文件**：`UCF1.7修改器.exe`
- **用户数据目录**：EXE同目录下的 `data/`（首次运行时自动创建）

## 注意事项

1. 打包前确保所有依赖已安装：`pip install -r requirements.txt`
2. 打包后需要测试 exe 是否能正常运行

## 日志输出规范

### 开发环境 vs 打包后

| 环境 | 控制台日志 | 日志文件 |
|------|-----------|----------|
| **开发环境**（Python运行） | ✅ 输出 | ✅ 写入 `logs/game_modifier.log` |
| **打包后**（EXE运行） | ✅ 输出 | ❌ 不写入 |

### 实现原理

在 `core/log_manager.py` 中通过 `sys.frozen` 判断运行环境：

```python
# 只在开发环境写日志文件
if not getattr(sys, 'frozen', False):
    fh = RotatingFileHandler(log_file, ...)
    root.addHandler(fh)

# 所有环境都输出到控制台
ch = logging.StreamHandler(sys.stdout)
root.addHandler(ch)
```

### 设计理由

1. **打包后不写日志文件**：避免在用户机器上产生额外的日志文件，减少磁盘占用
2. **控制台日志保留**：方便用户在出现问题时通过控制台查看错误信息
3. **开发环境双输出**：开发时既能看到实时日志，又能通过文件回溯问题

## 发布版用户配置

- 发布目录不附带 `data` 文件夹，也不打包开发环境中的JSON。
- 首次启动时，程序自动创建空的 `data` 目录；代码默认所有功能关闭。
- `feature_state.json`、`desired_states.json`、快捷键和其他JSON在用户修改对应设置时按需生成。
- 打包前不需要清空或重置开发环境的JSON，避免破坏测试人员自己的功能状态。

## 1.7修复版重新打包检查

- 使用当前 `scripts/`，确保包含 `_common.js`、Buff选择、武器赋予、决战回合和时间加速脚本。
- Universal Hook只打包 `inject.exe`、`Universal-ImGui-Hook.dll`、`universal_hook.json`。
- 不打包 `esp_debug.log`、`inject_log.txt`、`esp_dllmain_test.txt` 等运行日志。
- `game_modifier.spec` 使用当前 `feature_01` 至 `feature_20` 模块名，不能继续使用旧隐藏模块名。
- 管理员权限使用 `uac_admin=True`，不再依赖缺失的 `app.manifest`。
- 发布版关闭UPX，减少注入器和DLL被安全软件误报的概率。
- `build/` 与 `build_release/` 都是PyInstaller中间目录；本次正确成品对应 `build_release/`，旧的 `build/` 可以删除。
- 发布时只需要 `dist_release/UCF1.7修改器.exe`，不需要携带任何build目录或data目录。
- 构建日志如果出现 `tkinter installation is broken`，该EXE不能发布；必须先确认PyInstaller已经处理 `hook-_tkinter.py` 和 `pyi_rth__tkinter.py`。
- 当前机器的Python原始Tcl目录无法直接初始化，打包时需临时复制Tcl/Tk到纯英文路径，并设置 `TCL_LIBRARY`、`TK_LIBRARY` 后再运行PyInstaller。

## 常见问题解答

### Q1: 控制台是什么？

**控制台**就是 Windows 的黑色命令行窗口（cmd 窗口）。

- `console=False`：程序启动时**不显示**黑色窗口，只显示 GUI 界面
- `console=True`：程序启动时会**显示**黑色窗口，可以看到 print 输出和错误信息

**本项目设置**：`console=False`（窗口程序，用户体验更好）


### Q3: 如果不压缩，程序大小大概是多少？

**当前状态**：
- 启用压缩（`upx=True`）：**66.27 MB**
- 不压缩（`upx=False`）：约 **90-100 MB**

**压缩效果**：
- 减小约 30-35% 的体积
- 启动速度基本无影响（UPX 解压很快）

**建议**：保持 `upx=True`（压缩后体积更小，分发更方便）

### Q4: 之前路径打包错误的原因是什么？

**问题**：打包后找不到 `inject.exe` 和 `Universal-ImGui-Hook.dll`

**原因**：
1. **路径硬编码**：代码中直接使用相对路径，没有适配打包后的环境
2. **缺少路径判断**：没有区分开发环境和打包环境



**关键点**：
- `sys._MEIPASS`：PyInstaller 打包后的临时解压目录
- `sys.frozen`：判断是否在打包环境中运行

**修复文件**：
- `core/config.py`：添加 `PLUGINS_DIR` 配置
- `core/universal_hook_manager.py`：使用 `PLUGINS_DIR` 查找插件文件
