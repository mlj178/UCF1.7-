# 正式发行版功能接入规范

这份规范用于 `04-正式发行版/`。

目标是让 `05-正式功能/XX-功能名/` 里的标准功能包可以低成本接入正式发行版。

正式发行版接入原则：

```text
只接标准功能包
只做复制、注册、配置、UI 挂载
不重写功能逻辑
不重写 JS
不重写 RPC
不为单个功能写特殊通道
```

------

## 1. 接入前置条件

一个功能必须满足以下条件，才能进入正式发行版：

```text
manifest.json 存在
manifest.json 中 status = release_ready
JS 文件存在
Python Feature 文件存在
UI Panel 或 UI 描述存在
RPC 接口完整
cleanup 完整
单功能测试通过
生命周期说明完整
经验总结完整
```

不满足条件的功能不得接入正式发行版。

------

## 2. 正式发行版标准目录

正式发行版建议保持以下结构：

```text
04-正式发行版/全功能整合包X.X/
├── core/
│   ├── config.py
│   ├── frida_manager.py
│   ├── feature_registry.py
│   └── lifecycle_manager.py
├── features/
│   ├── __init__.py
│   └── feature_id.py
├── scripts/
│   └── feature_id.js
├── ui/
│   ├── app.py
│   └── panels/
│       └── feature_id_panel.py
├── data/
│   ├── features.json
│   └── default_config.json
├── logs/
└── resources/
```

要求：

```text
JS 统一放 scripts/
功能定义统一放 features/
UI 面板统一放 ui/panels/
功能注册统一走 feature_registry.py 或 data/features.json
不要在 app.py 里硬写大量功能逻辑
```

------

## 3. 从 manifest.json 接入

正式发行版接入时，优先读取单功能的 `manifest.json`。

接入内容：

```text
feature_id
display_name
category
script 路径
feature_py 路径
ui_panel 路径
config 默认值
RPC 要求
生命周期要求
```

接入动作：

```text
复制 scripts/feature_id.js
复制 features/feature_id.py
复制 ui/feature_id_panel.py
注册 features.json
注册 default_config.json
更新 features/__init__.py
在 UI 中挂载对应 panel
```

不允许：

```text
重新命名 feature_id
修改 RPC 名称
把 JS 内容复制进一个大 JS
把功能逻辑写进 app.py
为了一个功能修改 frida_manager 的通用语义
```

------

## 4. 功能注册规范

正式发行版应该用统一注册表。

推荐 `data/features.json`：

```json
{
  "fast_stock": {
    "display_name": "极速枪托",
    "category": "weapon",
    "script": "scripts/fast_stock.js",
    "feature_class": "features.fast_stock.FastStockFeature",
    "ui_panel": "ui.panels.fast_stock_panel.FastStockPanel",
    "enabled_default": false,
    "status": "enabled"
  }
}
```

或者在 `core/feature_registry.py` 中注册：

```python
FEATURES = {
    "fast_stock": {
        "display_name": "极速枪托",
        "category": "weapon",
        "script": "fast_stock.js",
        "feature_class": "features.fast_stock.FastStockFeature",
        "ui_panel": "ui.panels.fast_stock_panel.FastStockPanel",
        "enabled_default": False,
    }
}
```

要求：

```text
UI 只能从注册表读取功能
app.py 不允许手写每个功能的开关逻辑
新增功能只加注册项，不改 UI 主流程
```

------

## 5. Frida Manager 统一调用规范

正式发行版必须提供统一调用方式。

标准调用：

```python
call_export(feature_id, export_name, *args)
```

示例：

```python
frida_manager.call_export("fast_stock", "enable")
frida_manager.call_export("fast_stock", "disable")
frida_manager.call_export("fast_stock", "set_config", config)
frida_manager.call_export("fast_stock", "status")
frida_manager.call_export("fast_stock", "cleanup")
```

要求：

```text
每个功能不能自己 attach
每个功能不能自己管理 Frida session
每个功能不能绕过 frida_manager
所有 RPC 调用都走 call_export
```

------

## 6. JS 加载规范

正式发行版加载 JS 时必须按 `feature_id` 管理。

要求：

```text
一个 feature_id 对应一个 JS script
script 加载状态要记录
script 重复加载要跳过或先 cleanup
游戏断开时统一 cleanup 所有 script
重新 attach 后重新加载所有需要的 script
```

建议内部状态：

```python
loaded_scripts = {
    "fast_stock": {
        "script": script_object,
        "loaded": True,
        "enabled": False
    }
}
```

------

## 7. UI 接入规范

UI 只负责显示和调用 Feature 类。

UI 不应该知道：

```text
RVA
字段偏移
Hook 地址
Frida NativeFunction
具体 JS 内部逻辑
```

UI 只允许做：

```text
显示开关
显示参数
调用 feature.enable(config)
调用 feature.disable()
显示 feature.status()
退出时 feature.cleanup()
```

不允许：

```text
UI 直接调用 script.exports.xxx
UI 直接写 Frida 逻辑
UI 为某个功能写特殊 enable 逻辑
UI 里散落功能状态变量
```

------

## 8. 配置规范

正式发行版统一管理配置。

推荐文件：

```text
data/default_config.json
data/user_config.json
```

配置 key 必须使用 feature_id。

示例：

```json
{
  "fast_stock": {
    "enabled": false,
    "multiplier": 1.5
  },
  "third_person_camera": {
    "enabled": false,
    "distance": 3.5,
    "height": 1.2
  }
}
```

要求：

```text
UI 修改配置后，调用 feature.set_config 或 feature.enable(config)
JS 内部不直接读取配置文件
Python Feature 类负责把配置传给 JS
```

------

## 9. 生命周期统一管理

正式发行版必须有统一生命周期管理。

建议新增：

```text
core/lifecycle_manager.py
```

职责：

```text
游戏连接成功：加载需要的 JS
功能开启：调用 enable
功能关闭：调用 disable
切房间：调用需要 reset 的功能
游戏断开：cleanup 所有功能
UI 退出：cleanup 所有功能
重新 attach：重新加载脚本并恢复用户配置
```

每个功能的生命周期需求来自 manifest：

```json
"lifecycle": {
  "uses_cached_pointer": false,
  "requires_room_reset": true,
  "requires_weapon_change_reset": true,
  "cleanup_required": true
}
```

------

## 10. cleanup 统一要求

正式发行版退出时必须按顺序 cleanup。

顺序：

```text
停止 UI 状态刷新 timer
disable 所有 enabled 功能
cleanup 所有 loaded script
detach Frida session
保存配置
关闭 UI
```

要求：

```text
一个功能 cleanup 失败不能阻塞其他功能
cleanup 异常必须记录日志
cleanup 可以重复调用
```

示例：

```python
def cleanup_all_features(self):
    for feature_id, feature in self.features.items():
        try:
            feature.cleanup()
        except Exception as e:
            self.logger.error(f"[{feature_id}] cleanup failed: {e}")
```

------

## 11. 正式版接入流程

每次从 `05-正式功能` 接一个功能到 `04-正式发行版`，按这个顺序：

```text
1. 检查 manifest.json
2. 检查 status 是否 release_ready
3. 复制 scripts/feature_id.js 到 scripts/
4. 复制 features/feature_id.py 到 features/
5. 复制 ui/feature_id_panel.py 到 ui/panels/
6. 更新 data/features.json 或 core/feature_registry.py
7. 更新 default_config.json
8. 更新 features/__init__.py
9. 运行静态测试
10. 启动正式版 UI
11. 测试开启/关闭/status/cleanup
12. 测试切房间/退出游戏/重开游戏
13. 更新发行版 CHANGELOG
```

------

## 12. 禁止事项

正式发行版接入时禁止：

```text
为了接一个功能改 app.py 大量逻辑
把单功能 JS 合并进一个巨大 JS
改 feature_id
改 RPC 名称
删除 cleanup
绕过 Feature 类直接调 JS
把临时 launcher.py 接进正式版
把测试版 JS 接进正式版
顺手重构其他旧功能
用特殊 if feature_id == xxx 处理单个功能
```

------

## 13. 硬规则

正式发行版必须遵守以下三条硬规则，不得违反：

### 13.1 script.js 自包含规则

每个功能的 `script.js` 必须**自包含**，但**只复制本功能需要的 helper**。

要求：

```text
每个 feature_id 有独立 script.js
script.js 不依赖外部 helper 文件
只复制本功能真正用到的 helper 函数
不复制整个 helper.js 全集
不依赖全局 modules 对象注入
```

示例：

```javascript
// fast_stock.js
// 自包含：只复制本功能需要的 helper

(function() {
  // 只复制需要的 helper
  function readPointer(addr) { ... }
  function writeFloat(addr, val) { ... }
  
  // 本功能逻辑
  modules.fast_stock = {
    enable: function() { ... },
    disable: function() { ... }
  };
})();
```

不允许：

```text
script.js 里 import 其他 JS
script.js 里依赖全局 modules.xxx
复制整份 helper.js（很多函数根本不用）
多个功能共享一个 script.js
```

### 13.2 中心文件禁止具体功能 ID 分支

正式发行版中心文件禁止出现具体功能 ID 分支。

中心文件定义：

```text
core/frida_manager.py
core/feature_registry.py
core/lifecycle_manager.py
ui/app.py
ui/main_controller.py
```

要求：

```text
中心文件只做通用逻辑
中心文件不得出现 if feature_id == "fast_stock"
中心文件不得出现 if feature_id == "knife"
中心文件不得出现 switch(feature_id) case "xxx"
```


### 13.3 新功能必须从模板复制

新功能必须从 `features/_template/` 复制，不允许手写散落文件。

要求：

```text
features/_template/ 必须存在
features/_template/ 必须包含完整模板文件
新功能开发必须从 _template 复制
新功能开发不允许手写散落 JS / Python / UI
```


## 14. 接入验收标准

功能进入正式发行版后，必须通过：

```text
1. UI 可以看到功能
2. 默认状态符合配置
3. 开启功能成功
4. 关闭功能成功
5. status 有结构化返回
6. cleanup 可以重复调用
7. 退出 UI 不报错
8. 游戏断开不报大量异常
9. 重新进入游戏可以重新 attach
10. 切房间不会继续使用旧指针
11. 日志能看到完整生命周期
12. 不影响其他功能
```

------

## 15. 一句话要求

```text
正式发行版不是功能试验田。
正式发行版只接收 release_ready 的标准功能包。
能通过复制、注册、配置完成接入，才说明单功能开发规范合格。
```
