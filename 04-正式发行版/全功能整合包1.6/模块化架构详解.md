# 游戏修改器模块化架构详解

> 版本: v1.6 | 架构: 模块化分层 | 文档日期: 2026-05-23

---

## 一、分层职责总览

整个项目按职责分为 **5 个层级**，每一层只关心自己的事情，层与层之间通过明确的接口通信：

```
game_modifier/
├── core/          ← 基础设施层：管连接、管事件、管配置、管快捷键、管音效
├── features/      ← 功能定义层：定义"有哪些功能"以及"怎么跟 Frida 通信"
├── scripts/       ← JS 脚本层：真正修改游戏内存的 Frida Hook 代码
├── ui/            ← 界面展示层：用户看到的窗口、按钮、开关
└── data/          ← 数据持久层：保存用户的设置和状态
```

用一个生活类比来理解：

| 层级 | 类比 | 职责 |
|------|------|------|
| **core/** | 公司的行政部门 | 不做具体业务，但管通信、管档案、管后勤 |
| **features/** | 公司的各部门经理 | 知道自己部门该干什么，能调动行政资源 |
| **scripts/** | 公司的一线员工 | 真正干活的人，直接操作游戏内存 |
| **ui/** | 公司的前台大厅 | 用户接触到的界面，负责展示和接收操作 |
| **data/** | 公司的档案室 | 把重要信息存下来，下次还能用 |

## 二、各层级详解

### 2.1 core/ — 基础设施层

这一层是整个系统的"骨架"，提供所有其他层都需要的基础能力。

| 文件 | 职责 | 通俗解释 |
|------|------|---------|
| `config.py` | 集中管理所有配置路径和常量 | 相当于"通讯录"，所有路径、功能元数据都在这里查 |
| `event_bus.py` | 发布/订阅事件系统 | 相当于"广播站"，谁想听什么消息就订阅，有消息就广播出去 |
| `feature_registry.py` | 功能注册中心 | 相当于"员工花名册"，所有功能都要来这里登记 |
| `frida_manager.py` | Frida 会话管理 | 相当于"翻译官"，负责 Python 和 JS 之间的沟通 |
| `hotkey_manager.py` | 快捷键管理 | 相当于"遥控器"，按快捷键就能触发对应功能 |
| `sound_manager.py` | 音效管理 | 相当于"音响师"，开关功能时播放提示音 |

#### config.py — 通讯录

```python
APP_DIR       # 程序根目录
DATA_DIR      # 数据存储目录（保存设置的地方）
SCRIPTS_DIR   # JS 脚本目录
FEATURES_INFO # 所有功能的元数据（名字、图标、分类）
NANO4T_ATTRS  # 多人生化特性定义
GRAVITY_PRESETS # 重力预设值
```

为什么需要它？因为路径和常量如果散落在各个文件中，改一个路径要改十几个地方。集中管理后，改一处就全局生效。

#### event_bus.py — 广播站

核心思想：**谁发消息的不用管谁听，谁听消息的不用管谁发**。

```python
# 发消息（广播）
event_bus.emit('log_message', level='info', module='快刀', message='已启用')

# 收消息（订阅）
event_bus.subscribe('log_message', self._on_log)
```

解耦的好处：FridaManager 收到 JS 消息后，只需要往 EventBus 一扔，不用关心 UI 是怎么显示的。UI 只需要订阅事件，不用关心消息是从哪来的。

#### feature_registry.py — 员工花名册

```python
# 注册功能（入职登记）
@register_feature
class KnifeFeature(FeatureBase):
    feature_id = 'knife'
    ...

# 查询功能（查花名册）
registry = FeatureRegistry.get_instance()
knife = registry.get('knife')
all_features = registry.get_all()

# 保存/加载状态（考勤记录）
registry.save_state(data_dir)   # 保存所有功能的开关状态
registry.load_state(data_dir)   # 下次启动时恢复
```

#### frida_manager.py — 翻译官

这是最核心的中间层，负责三件事：

1. **连接游戏**：找到游戏进程 → 附加 Frida → 注入 JS 脚本
2. **拼接 JS**：把 `_common.js` + 各功能 JS + 调度器 + RPC 导出 拼成一份完整脚本
3. **双向通信**：Python → JS（发指令）、JS → Python（收消息）

```python
# Python → JS：发送开关指令
fm.send_toggle('knife', True)          # 开启快刀
fm.send_toggle('knife_speed', 5.0)     # 设置速度

# Python → JS：调用 RPC 函数
fm.call_export('gather')               # 调用聚怪
fm.call_export('nano4tinit')           # 初始化多人生化

# JS → Python：消息自动路由到 EventBus
# JS 中 send({type:'log', ...})  →  EventBus.emit('log_message', ...)
# JS 中 send({type:'status', ...}) → EventBus.emit('feature_status_changed', ...)
```

### 2.2 features/ — 功能定义层

这一层定义了"有哪些功能"以及"每个功能怎么跟 Frida 通信"。

#### 基类 FeatureBase — 功能的"身份证模板"

```python
class FeatureBase:
    feature_id = ''        # 功能唯一ID（如 'knife'）
    js_filename = None     # 对应的 JS 文件名（如 'speed_gun.js'）
    name = ''              # 显示名称（如 '快刀'）
    icon = ''              # 图标（如 '🔪'）
    category = 'other'     # 分类（weapon/player/other）
    has_slider = False     # 是否有滑块
    slider_range = (...)   # 滑块范围
    has_combo = False      # 是否有下拉选择
    desc = ''              # 功能描述

    def enable(self):      # 开启功能 → 通过 FridaManager 发指令
    def disable(self):     # 关闭功能 → 通过 FridaManager 发指令
    def on_slider_change(self, value):  # 滑块变化时的处理
    def get_js_code(self): # 读取对应的 JS 文件内容
    def get_custom_ui(self, parent):    # 返回自定义 UI 标识
```

#### 具体功能示例 — 快刀

```python
@register_feature
class KnifeFeature(FeatureBase):
    feature_id = 'knife'
    name = '快刀'
    icon = '🔪'
    category = 'weapon'
    has_slider = True
    slider_range = (1.0, 10.0, 0.1)
    slider_value = 5.0

    def enable(self):
        fm = FridaManager.get_instance()
        fm.send_toggle('knife', True)           # 告诉 JS 开启快刀
        fm.send_toggle('knife_speed', 5.0)      # 告诉 JS 速度是多少

    def on_slider_change(self, value):
        # 用户拖动滑块时，实时通知 JS 更新速度
        fm.send_toggle('knife_speed', value)
```

#### 功能分类

| 分类 | 功能 |
|------|------|
| **weapon（武器）** | knife, recoil, ammo, ammoplus, range, aim, speedgun |
| **player（人物）** | time, movespeed, gravity, godmode, skillcd |
| **other（其他）** | gather, isbot, roundskip, nano4t |

#### 功能复杂度分级

| 级别 | 功能 | 特点 |
|------|------|------|
| **简单型** | ammo, recoil, time, aim, godmode, ammoplus, speedgun, isbot, skillcd | 只有 enable/disable，无额外参数 |
| **滑块型** | knife, movespeed, range | 有滑块，enable 时需要同时发送参数 |
| **复合型** | gravity | 有重力+跳跃两个滑块 + 模式选择 |
| **交互型** | gather, roundskip | 有按钮触发动作（聚怪/跳过回合） |
| **选择型** | nano4t | 有下拉选择框，需要初始化+设置属性 |

### 2.3 scripts/ — JS 脚本层

这一层是真正修改游戏内存的代码，运行在游戏进程内部。

#### _common.js — 公共函数库

所有 JS 模块共享的基础函数，由 FridaManager 在拼接脚本时**首先加载**：

```javascript
// 日志函数（限流：每个模块最多 10 条日志）
function sendLog(level, module, message) { ... }

// 状态上报函数
function sendStatus(feature, enabled) { ... }

// 获取 GameAssembly.dll（带缓存，避免重复查找）
function getGameAssembly() { ... }

// 通用内存读取函数
function readPtr(addr) { ... }
function readI32(addr) { ... }
function readF32(addr) { ... }
function readU8(addr) { ... }

// 模块注册表
var modules = {};
```

#### 功能 JS 文件 — 自注册模式

每个功能 JS 文件都通过 `modules.xxx = ...` 自注册到全局注册表：

```javascript
// knife.js
modules.knife = (function() {
    var enabled = false;
    var currentSpeed = 5.0;
    // ... 内部变量

    return {
        enable: function() { /* 安装 Frida Hook */ },
        disable: function() { /* 卸载 Frida Hook */ },
        setSpeed: function(speed) { /* 更新速度 */ }
    };
})();
```

#### JS 模块的统一接口

| 方法 | 说明 | 所有模块都有 |
|------|------|-------------|
| `enable()` | 安装 Hook，开始生效 | ✅ |
| `disable()` | 卸载 Hook，停止生效 | ✅ |
| `setSpeed/setConfig/...` | 模块特有的配置方法 | 部分模块有 |

#### 脚本拼接流程

FridaManager 在连接游戏时，会动态拼接一份完整的 JS 脚本：

```
_common.js          ← 公共函数（日志、状态上报、内存读取）
    +
knife.js            ← 快刀模块
time_freeze.js      ← 无限时间模块
recoil.js           ← 无后座力模块
...（所有已注册功能的 JS）
    +
dispatcher          ← 消息调度器（recv 'toggle', onToggle）
rpc_exports         ← RPC 导出（gather, roundskip, nano4t 等）
init_message        ← 初始化日志
```

### 2.4 ui/ — 界面展示层

| 文件 | 职责 |
|------|------|
| `app.py` | 主窗口，包含所有 UI 构建、事件订阅、用户交互处理 |
| `settings_window.py` | 设置窗口（快捷键绑定、关于页面） |
| `widgets.py` | 自定义控件（预留，目前为空） |

#### App 类的核心工作

1. **构建 UI**：状态栏 → 提示条 → 选项卡（武器/人物/其他/多人生化） → 连接按钮 → 日志面板
2. **订阅事件**：监听 EventBus 的 `log_message`、`connection_status`、`feature_status_changed` 等
3. **处理交互**：用户点击开关 → 调用 Feature 的 enable/disable → 通过 FridaManager 发指令
4. **更新 UI**：收到 JS 状态反馈 → 更新开关状态、显示日志

#### 设置窗口

独立为 `SettingsWindow` 类，包含：
- **快捷键 Tab**：Ctrl+1~5 / F1~F3 / Alt+1~3 绑定功能，互斥绑定（一个功能只能绑一个键）
- **关于 Tab**：版本信息、作者、B站链接、赞赏码

### 2.5 data/ — 数据持久层

| 文件 | 内容 | 何时读写 |
|------|------|---------|
| `hotkeys.json` | 快捷键绑定配置 | HotkeyManager 初始化时读取，修改后保存 |
| `settings.json` | 音效开关和音量 | SoundManager 初始化时读取，修改后保存 |
| `feature_state.json` | 所有功能的开关状态 | FeatureRegistry 保存/加载 |
| `Nano-4T-selector.json` | 多人生化特性选择 | nano4t 选择变更时保存 |

**作用**：用户下次打开程序时，之前的设置和功能状态都会恢复，不用重新配置。

## 三、架构优点

### 3.1 关注点分离

每个文件只做一件事：

| 以前（单文件版） | 现在（模块化版） |
|-----------------|-----------------|
| 4300+ 行代码挤在一个文件 | 最长的 app.py 也只有 ~1050 行 |
| 改快捷键要在 4000 行中找代码 | 直接改 `hotkey_manager.py` |
| 改音效要翻半天 | 直接改 `sound_manager.py` |
| 加新功能要改 3 处（JS + 功能字典 + UI） | 只需加 1 个 Feature 类 + 1 个 JS 文件 |

### 3.2 事件驱动解耦

```
传统方式（紧耦合）：
  FridaManager → 直接调用 App._log() → App 直接操作 UI

事件方式（松耦合）：
  FridaManager → EventBus.emit('log_message') → 谁订阅了谁处理
```

好处：
- FridaManager 完全不知道 UI 的存在
- 将来换 UI 框架（比如从 tkinter 换成 PyQt），core 和 features 层不用改
- 多个组件可以同时订阅同一个事件

### 3.3 功能注册机制

```python
# 加新功能只需要 3 步：

# 1. 创建 Feature 类
@register_feature
class NewFeature(FeatureBase):
    feature_id = 'new_feature'
    name = '新功能'
    ...

# 2. 创建 JS 文件
# scripts/new_feature.js
modules.new_feature = (function() { ... })();

# 3. 在 features/__init__.py 中导入
from features.new_feature import NewFeature
```

不需要改 config.py（FEATURES_INFO 会从注册表自动生成），不需要改 UI 代码（UI 从注册表动态构建）。

### 3.4 状态持久化

程序意外关闭或正常退出后，下次启动：
- 功能开关状态自动恢复（`feature_state.json`）
- 快捷键绑定自动恢复（`hotkeys.json`）
- 音效设置自动恢复（`settings.json`）
- 多人生化选择自动恢复（`Nano-4T-selector.json`）

### 3.5 线程安全

所有 Manager 都使用线程锁（`threading.Lock`），确保多线程环境下不会出问题：
- EventBus 的订阅/发布有锁
- FeatureRegistry 的注册/查询有锁
- FridaManager 的连接/发送有锁

### 3.6 JS 脚本动态拼接

不是一次性加载固定脚本，而是根据已注册的功能动态拼接：
- 只加载需要的功能 JS
- 公共函数只加载一份
- 方便单独调试某个功能的 JS

## 四、数据流全链路详解

### 4.1 用户开启"快刀"功能的完整流程

```
用户点击"快刀"开关
       │
       ▼
  App._toggle_feature('knife')
       │
       ▼
  从 FeatureRegistry 获取 KnifeFeature 实例
       │
       ▼
  KnifeFeature.on_ui_toggle(True)
       │
       ├── self._enabled = True          ← 记录状态
       │
       ▼
  KnifeFeature.enable()
       │
       ▼
  FridaManager.send_toggle('knife', True)
       │
       ▼
  script.post({type:'toggle', feature:'knife', enable:true})
       │                    │
       │                    ▼  (进入游戏进程的 JS 世界)
       │              onToggle(data)
       │                    │
       │                    ▼
       │              modules['knife'].enable()
       │                    │
       │                    ▼
       │              安装 Interceptor.replace Hook
       │              替换 PlayerWeapons.get_KnifeSpeed
       │                    │
       │                    ▼
       │              sendStatus('knife', true)
       │              sendLog('success', '快刀', '已启用')
       │                    │
       ▼                    ▼  (回到 Python 世界)
  FridaManager._on_message() 收到 JS 消息
       │
       ├── type='status' → EventBus.emit('feature_status_changed', feature='knife', enabled=True)
       │                        │
       │                        ▼
       │                   App._on_feature_status_changed() → 更新开关状态
       │
       └── type='log'    → EventBus.emit('log_message', level='success', module='快刀', message='已启用')
                              │
                              ▼
                         App._on_log_message() → 日志面板显示 "✅ [快刀] 已启用"
```

### 4.2 用户拖动"快刀速度"滑块的流程

```
用户拖动滑块到 8.0
       │
       ▼
  App._on_knife_speed_change(8.0)
       │
       ▼
  KnifeFeature.on_slider_change(8.0)
       │
       ├── self._current_speed = 8.0
       │
       ▼
  FridaManager.send_toggle('knife_speed', 8.0)
       │
       ▼
  script.post({type:'toggle', feature:'knife_speed', enable:8.0})
       │
       ▼  (JS 世界)
  onToggle(data)
       │
       ▼
  featureName === 'knife_speed' → modules.knife.setSpeed(8.0)
       │
       ▼
  currentSpeed = 8.0  ← JS 内部变量更新
       │
       ▼  (下次游戏调用 get_KnifeSpeed 时)
  NativeCallback 返回 8.0 而不是原来的速度
       │
       ▼
  游戏中刀的挥动速度变为 8 倍！
```

### 4.3 用户点击"一键聚怪"的流程

```
用户点击"📍 一键聚怪"按钮
       │
       ▼
  App._gather()
       │
       ▼
  GatherFeature.do_gather()
       │
       ▼
  FridaManager.call_export('gather')
       │
       ▼
  script.exports_sync.gather()     ← 调用 JS 的 RPC 导出函数
       │
       ▼  (JS 世界)
  rpc.exports.gather()
       │
       ▼
  modules.gather.gather()
       │
       ▼
  设置 ntp = true，等待下次 Player.Update 触发
       │
       ▼
  Player.Update Hook 触发 → executeTeleport()
       │
       ▼
  扫描所有玩家 → 跳过自己/真人/死亡 → 传送 Bot 到出生点
       │
       ▼
  send(JSON.stringify({type:'done', n:tn, bots:botOk, fail:botFail}))
       │
       ▼  (回到 Python 世界)
  FridaManager._on_message() → EventBus.emit('gather_result', data=...)
       │
       ▼
  App._on_gather_result() → 日志面板显示聚怪结果
```

### 4.4 程序启动自动连接的流程

```
main.py 启动
       │
       ▼
  import features → 触发所有 @register_feature → FeatureRegistry 登记所有功能
       │
       ▼
  App.__init__()
       ├── 创建所有 Manager 单例（EventBus, FridaManager, FeatureRegistry, SoundManager, HotkeyManager）
       ├── FeatureRegistry.load_state() → 从 feature_state.json 恢复功能状态
       ├── 构建 UI
       ├── HotkeyManager.setup_hotkeys() → 恢复快捷键绑定
       ├── 订阅 EventBus 事件
       └── 启动后台线程：
             ├── _auto_connect_bg()    → 每 5s 检测游戏进程，自动连接
             ├── _monitor_connection() → 每 2s 检测连接是否断开
             └── _nano4t_auto_health_bg() → 定期检测多人生化模式状态

自动连接线程检测到游戏：
       │
       ▼
  FridaManager.connect(pid)
       │
       ├── frida.attach(pid)           ← 附加到游戏进程
       ├── _build_js_code()            ← 动态拼接 JS 脚本
       ├── session.create_script(js)   ← 创建脚本
       ├── script.on('message', ...)   ← 注册消息回调
       ├── script.load()               ← 加载脚本到游戏进程
       │
       ▼  (JS 世界开始执行)
  _common.js 加载 → getGameAssembly() 缓存 GameAssembly.dll
       │
       ▼  (回到 Python 世界)
  EventBus.emit('connection_status', status='connected')
       │
       ▼
  App 收到连接成功事件 → 更新状态栏为绿色 → 恢复之前的功能开关状态
```

### 4.5 功能状态恢复的流程

```
程序启动 → FeatureRegistry.load_state()
       │
       ▼
  读取 feature_state.json: {"knife": {"enabled": true, "slider_value": 5.0}, ...}
       │
       ▼
  对每个 enabled=true 的功能：
       │
       ▼
  App 连接游戏成功后 → _restore_features()
       │
       ▼
  对每个之前开启的功能：
       ├── knife → send_toggle('knife', True) + send_toggle('knife_speed', 5.0)
       ├── movespeed → send_toggle('movespeed', True) + send_toggle('movespeed_speed', 3.0)
       ├── gravity → send_toggle('gravity', True) + send_config(...)
       └── 其他 → send_toggle(feature_id, True)
```

## 五、通信机制汇总

### 5.1 Python → JS 通信

| 方式 | 用途 | 示例 |
|------|------|------|
| `script.post(msg)` | 发送 toggle 指令 | `{type:'toggle', feature:'knife', enable:true}` |
| `script.exports_sync.xxx()` | 调用 RPC 函数并等待返回 | `gather()`, `nano4tinit()`, `roundskip()` |

### 5.2 JS → Python 通信

| 方式 | 用途 | 示例 |
|------|------|------|
| `send({type:'log', ...})` | 上报日志 | 日志面板显示 |
| `send({type:'status', ...})` | 上报功能状态 | 更新开关 |
| `send(JSON.stringify({...}))` | 上报结构化数据 | 聚怪结果、nano4t 事件 |
| RPC 返回值 | 返回函数执行结果 | `call_export` 的返回值 |
