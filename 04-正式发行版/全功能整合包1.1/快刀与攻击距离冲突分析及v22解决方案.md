# 快刀脚本与攻击距离脚本冲突分析及 v22 解决方案

## 问题现象

同时加载 `speed_knife_v16_speed13.js`（改刀速 13x）和 `AAAAA-knife_range_v21.js`（改攻击距离 50x），**其中一个功能会失效**。但开 10x 快刀时似乎没问题（实为加载顺序碰巧掩盖了问题）。

---

## 根因分析

### 两个脚本都用了 `Interceptor.replace` 挂钩同一个函数

| 脚本 | 挂钩地址 | 挂钩方式 | 目的 |
|---|---|---|---|
| speed_knife_v16 (speed13) | `PlayerWeapons.get_KnifeSpeed` @ `0xB170A0` | `Interceptor.replace` | 返回 13x 速度 |
| knife_range_v21 | `PlayerWeapons.get_KnifeSpeed` @ `0xB170A0` | `Interceptor.replace` | 捕获 myPlayer 指针 |

### Frida 规则：同一地址只能有一个 `replace` 生效

**后加载的 replace 会覆盖先加载的**。因此：

```
先加载 speed_v16  → 后加载 range_v21  → range 的 replace 覆盖 speed → 快刀失效
先加载 range_v21  → 后加载 speed_v16  → speed 的 replace 覆盖 range → 攻击距离失效
```

### range_v21 的原始代码（v21 问题代码）

```javascript
// knife_range_v21.js - 步骤1: replace get_KnifeSpeed 捕获 myPlayer
// ⚠️ 这里用了 Interceptor.replace，与快刀脚本冲突！
var getKnifeSpeedAddr = base.add(0xB170A0);
var origGetKnifeSpeed = new NativeFunction(getKnifeSpeedAddr, 'float', ['pointer']);
Interceptor.replace(getKnifeSpeedAddr, new NativeCallback(function(self) {
    var result = origGetKnifeSpeed(self);
    if (!myPlayerFound) {
        try {
            var owner = self.add(0x8).readPointer();
            if (owner && !owner.isNull() && isMyPlayerFn(owner)) {
                myPlayer = owner;
                myPlayerFound = true;
                sendLog('info', '近战', '捕获myPlayer @ ' + myPlayer);
            }
        } catch(e) {}
    }
    return result;  // 返回原始值，不修改速度
}, 'float', ['pointer']));
```

**关键点**：range_v21 的 replace 只是"借用"这个函数来捕获 myPlayer 指针，**并不需要修改返回值**——它原样返回 `origGetKnifeSpeed(self)`。既然如此，完全没必要用 `replace`，用 `attach` 就够了！

### speed_v16 的代码（必须用 replace）

```javascript
// speed_knife_v16.js - 必须用 replace 修改返回值
Interceptor.replace(getKnifeSpeedAddr, new NativeCallback(function(self) {
    try {
        var owner = self.add(0x8).readPointer();
        if (!owner || owner.isNull()) {
            return originalGetKnifeSpeed(self);
        }
        if (isMyPlayer(owner)) {
            return SPEED;  // ⚡ 必须修改返回值，所以必须用 replace
        }
        return originalGetKnifeSpeed(self);
    } catch(e) {
        return originalGetKnifeSpeed(self);
    }
}, 'float', ['pointer']));
```

**speed_v16 必须用 `replace`**，因为它需要把返回值改成指定的速度倍数。这是正当用途。

---

## 为什么 10x 似乎没问题？

并非速度值本身导致冲突不冲突的差别。你可能在测试 10x 时的加载顺序碰巧让 range 后加载，而 range 不修改速度返回值（原样返回），所以你**没察觉快刀其实已经失效了**（快刀的 replace 被覆盖后返回了原始速度）。

---

## v22 解决方案

### 核心思路

> **只需观察的函数用 `attach`，需要修改返回值的才用 `replace`**

range_v21 只需要观察 `get_KnifeSpeed` 来捕获 myPlayer，不需要修改返回值 → 改用 `Interceptor.attach`。

### range_v22 修复后的代码

```javascript
// AAAAA-knife_range_v22.js - 步骤1: attach get_KnifeSpeed 捕获 myPlayer
// ✅ 使用 attach，与快刀的 replace 完美共存
var getKnifeSpeedAddr = base.add(0xB170A0);
Interceptor.attach(getKnifeSpeedAddr, {
    onEnter: function(args) {
        this._self = args[0];       // 在 onEnter 里保存 self (PlayerWeapons)
    },
    onLeave: function(retval) {
        if (myPlayerFound) return;  // 只需要捕获一次
        try {
            var owner = this._self.add(0x8).readPointer();  // PlayerWeapons + 0x8 = owner
            if (owner && !owner.isNull() && isMyPlayerFn(owner)) {
                myPlayer = owner;
                myPlayerFound = true;
                sendLog('info', '近战', '捕获myPlayer @ ' + myPlayer);
            }
        } catch(e) {}
    }
});
// attach 不替换函数 → 不影响 speed_v16 的 replace → 两者共存！
```

### 对比总结

| | v21（冲突） | v22（兼容） |
|---|---|---|
| 挂钩方式 | `Interceptor.replace` | `Interceptor.attach` |
| 修改返回值 | 否（原样返回） | 否（仅观察） |
| 与 speed_v16 共存 | ❌ 互相覆盖 | ✅ 完美共存 |
| 禁用方式 | `Interceptor.revert` | `handle.detach()` |

---

## Frida 挂钩方式对比

| 方式 | 能否修改返回值 | 同一地址多个 | 用途 |
|---|---|---|---|
| `Interceptor.attach` | 可修改 `onLeave` 参数 | ✅ 多个共存 | 观察、日志、数据捕获 |
| `Interceptor.replace` | ✅ 完全替换 | ❌ 只有一个生效 | 修改函数行为 |

## v22 完整代码

文件路径：`测试版\AAAAA-knife_range_v22.js`

```javascript
// ============================================================
// 近战距离修改器 v22 — 用 attach 替代 replace，兼容快刀脚本共存
// 核心改动: 步骤1从 Interceptor.replace 改为 Interceptor.attach
//           只观察 get_KnifeSpeed 调用捕获 myPlayer，不替换函数
//           避免与 speed_knife_v16 的 replace 冲突
// ============================================================

(function() {
    'use strict';

    var KNIFE_RANGE_MULTIPLIER = 50.0;

    function sendLog(level, module, msg) {
        var logMsg = '[' + module + '] ' + msg;
        if (level === 'error') console.error(logMsg);
        else if (level === 'warn') console.warn(msg);
        else console.log(logMsg);
    }

    var mod = Process.findModuleByName('GameAssembly.dll');
    if (!mod) { sendLog('error', '近战', 'GameAssembly.dll 未找到'); return; }
    var base = mod.base;

    var isMyPlayerFn = new NativeFunction(base.add(0xB55FD0), 'bool', ['pointer']);
    var myPlayer = null;
    var myPlayerFound = false;

    var callCount = 0;
    var rangeLogCount = 0;

    // ============================================================
    // 步骤1: attach get_KnifeSpeed 捕获 myPlayer（仅观察，不替换）
    //        与 speed_knife_v16 的 replace 可共存
    // ============================================================
    try {
        var getKnifeSpeedAddr = base.add(0xB170A0);
        Interceptor.attach(getKnifeSpeedAddr, {
            onEnter: function(args) {
                this._self = args[0];
            },
            onLeave: function(retval) {
                if (myPlayerFound) return;
                try {
                    var owner = this._self.add(0x8).readPointer();
                    if (owner && !owner.isNull() && isMyPlayerFn(owner)) {
                        myPlayer = owner;
                        myPlayerFound = true;
                        sendLog('info', '近战', '捕获myPlayer @ ' + myPlayer);
                    }
                } catch(e) {}
            }
        });
        sendLog('info', '近战', 'get_KnifeSpeed attach @ ' + getKnifeSpeedAddr + ' (兼容模式)');
    } catch(e) {
        sendLog('warn', '近战', 'get_KnifeSpeed hook失败: ' + e.message);
    }

    // ============================================================
    // 步骤2: Hook GetKnifeAttackData 修改攻击距离
    // ============================================================
    try {
        Interceptor.attach(base.add(0xB63EC0), {
            onEnter: function(args) {
                this.wpnSelf = args[1];
                this.attackIdx = args[2].toInt32();
                try {
                    this.owner = args[1].add(0x30).readPointer();
                } catch(e) {
                    this.owner = null;
                }
            },
            onLeave: function(retval) {
                callCount++;
                try {
                    var orig = retval.add(0x4).readFloat();

                    var isOwnerMine = myPlayerFound &&
                        this.owner && !this.owner.isNull() &&
                        this.owner.equals(myPlayer);

                    if (!isOwnerMine) return;
                    if (!(orig > 0.3 && orig < 500)) return;

                    retval.add(0x4).writeFloat(orig * KNIFE_RANGE_MULTIPLIER);

                    rangeLogCount++;
                    if (rangeLogCount <= 10) {
                        sendLog('info', '近战',
                            '[玩家#' + rangeLogCount + '] idx=' + this.attackIdx +
                            ' range ' + orig.toFixed(2) +
                            ' → ' + (orig * KNIFE_RANGE_MULTIPLIER).toFixed(2));
                    }
                } catch(e) {
                    if (callCount <= 5) sendLog('error', '近战', '异常: ' + e.message);
                }
            }
        });
        sendLog('info', '近战', 'Hook GetKnifeAttackData @ ' + base.add(0xB63EC0));
    } catch(e) { sendLog('error', '近战', 'Hook 失败: ' + e.message); }

    // ============================================================
    // 房间切换
    // ============================================================
    var cleanupAddrs = [0xAFAA40, 0xAF5B30, 0xAF15D0];
    for (var i = 0; i < cleanupAddrs.length; i++) {
        try {
            Interceptor.attach(base.add(cleanupAddrs[i]), {
                onEnter: function() {
                    myPlayer = null;
                    myPlayerFound = false;
                    callCount = 0;
                    rangeLogCount = 0;
                    sendLog('info', '近战', '房间切换，全部重置');
                }
            });
        } catch(e) {}
    }

    sendLog('info', '近战', 'v22 已启用 (' + KNIFE_RANGE_MULTIPLIER + 'x) — 兼容快刀共存');
})();
```

## speed 脚本的修复方案

speed 脚本的修复思路：**将 speed 的 `replace` 与 range v22 的 `attach` 合并进同一个脚本**，用一个 `replace` 同时完成"修改速度"和"捕获 myPlayer"，加上独立的 `GetKnifeAttackData` hook 修改攻击距离。这样每个 speed 脚本都是自包含的完整近战修改器。

### speed_v16 原有 replace（仅改速度）

```javascript
Interceptor.replace(getKnifeSpeedAddr, new NativeCallback(function(self) {
    var owner = self.add(0x8).readPointer();
    if (isMyPlayer(owner)) return SPEED;
    return originalGetKnifeSpeed(self);
}, 'float', ['pointer']));
```

### 修复后：replace 中同时捕获 myPlayer + 修改速度

```javascript
Interceptor.replace(getKnifeSpeedAddr, new NativeCallback(function(self) {
    var result = originalGetKnifeSpeed(self);
    try {
        var owner = self.add(0x8).readPointer();
        if (owner && !owner.isNull()) {
            // 1️⃣ 捕获 myPlayer（给 range 用）
            if (!myPlayerFound && isMyPlayerFn(owner)) {
                myPlayer = owner;
                myPlayerFound = true;
            }
            // 2️⃣ 修改速度
            if (isMyPlayerFn(owner)) return SPEED;
        }
    } catch(e) {}
    return result;
}, 'float', ['pointer']));
```

### 修复后的脚本结构

```
AAAAA-speed_range_3x.js   ─┐
AAAAA-speed_range_5x.js    ├── 每个都是独立的完整脚本
AAAAA-speed_range_10x.js   │   包含: 快刀(指定速度) + 攻击距离50x
AAAAA-speed_range_v16.js  ─┘   加载一个即可，互不冲突
```

## 使用指南

| 场景 | 加载脚本 | 效果 |
|---|---|---|
| 只要快刀 3x | `speed_knife_v16_speed3.js` | 快刀 3x |
| 只要攻击距离 | `AAAAA-knife_range_v22.js` | 攻击距离 50x |
| 快刀 + 攻击距离 | `AAAAA-speed_range_3x.js` | 快刀 3x + 攻击距离 50x |
| 快刀 + 攻击距离 | `AAAAA-speed_range_5x.js` | 快刀 5x + 攻击距离 50x |
| 快刀 + 攻击距离 | `AAAAA-speed_range_10x.js` | 快刀 10x + 攻击距离 50x |
| 快刀 + 攻击距离 | `AAAAA-speed_range_v16.js` | 快刀 10x + 攻击距离 50x |

> **注意**：不要同时加载 speed_range_3x 和 speed_range_5x ——它们各自的 replace 仍会冲突。同一时间只加载一个 speed 脚本即可。
