# 多人生化模式闪退修复（2026-11-15 19:20）

## 现象

进入多人生化地图时游戏直接退出，弹出：

```
Microsoft Visual C++ Runtime Library
Runtime Error!
This application has requested the Runtime to terminate it in an unusual way.
```

Windows 事件日志对应两次崩溃：

- 18:49:47  KERNELBASE.dll 0xE06D7363（C++ 异常未捕获 -> abort，就是截图那个框）
- 18:50:07  GameAssembly.dll 0xC0000005，偏移 0x001290B1（GC 标记阶段读到坏对象）

## 第一层根因（有 dump 证据）

18:49 的 dump 栈：

```
GameAssembly+0x16F0C0   (抛出托管异常)
GameAssembly+0x32CF40   <- GetComponent<Transform>
ucf_mod.dll+0x7BF5      <- read_nano() 对 SpareAreaList 元素调用 comp_pos()
ucf_mod.dll+0xB0A9      <- editor_tick / NavProc
user32.dll ...          <- 主线程窗口消息
```

崩溃版本 DLL 中 0x7BF5 前后代码：

```
10007BEE  add eax, 0x32CF40
10007BF3  call eax                 ; GetComponent<Transform>(edi, 0)
10007BF5  add esp, 8
```

同版本 0x2AC48 处字符串正是 `SpareAreaList`，所以这个函数是
`read_nano()`（可视化层 LAY_C / 幽灵守区）。

切图后 `Bot_NanoGuardArea.SpareAreaList` 里仍留着上一张图的组件；这些组件
已经被 Unity 销毁（managed wrapper 还在，但 `m_CachedPtr` = 0）。对它们调用
`GetComponent<Transform>()` 会抛 `MissingReferenceException`。这是托管异常，
IL2CPP 无法把栈展开回原生 C 代码，直接 `abort()`。

原来的 `purge_guard_areas()` 只在检测到 AstarPath 变化的那一刻清一次列表，
清的时候旧场景对象可能还没被 Unity 销毁，所以没清掉；下一个 tick 做
`vis_rebuild()` 时它们已经销毁，`read_nano()` 就撞上了。

## 第二层根因（对应 0xC0000005 GC 崩溃）

修复版反汇编确认：链接守卫区时 `link_guard_areas()` 先 `arr_new()` 一个
`Bot_NanoGuardArea[]`，再 `arr_new()` 第二个数组。两个数组都只放在原生 C
局部变量里，**托管 GC 不扫描原生栈**；第二次分配如果触发 GC，第一个数组会被
回收，随后 `wfield()` 把野指针写进组件的 `neighborAreas` 字段。下一次 GC
扫描这个字段就跳到 `0x1290B1` 的 `mov eax,[ebx]`，读坏指针崩溃。

`plugin.c inject_one()` 也有同样问题：`p_array_new()` 之后又调
`p_string_new()`，新数组只存在原生局部变量里；旧数组写回 `MapAsset` 后，
下次 GC 可能扫到已释放的数组。

## 修复内容

### 1. 存活检查（防 MissingReferenceException）

所有从“游戏静态列表 / 单例 / FindObjectsOfType”拿到的 UnityEngine.Object，
在调用任何 Unity API 前先检查 `m_CachedPtr`（+0x8）：

```c
static int uobj_live(P o) { return o && *(P*)((char*)o + 0x8) != 0; }
```

- `editor.c`
  - 新增 `uobj_live()`。
  - `comp_tr()` 开头检查；`comp_pos()` 因此自动安全（read_nano / read_crouch /
    read_typed / probe 都走它）。
  - `read_jump()` 对 `endTr` 先检查再 `Transform.get_position`。
  - `read_spawns()` 对 `MapManager` 单例检查。
  - `vis_clear()` / `vis_label_tick()` 对 label 组件和主相机检查。
- `navfix.c`
  - 新增 `n_live()`；`astar_active()`、`get_mm()`、`point_graph()` 不再返回
    已销毁对象。
  - `purge_guard_areas()` 增加 bounds 检查（list size 不能超过 items 数组长度），
    只把 live 元素写回。
- `plugin.c`
  - 新增 `p_live()`；`UI_GameRoom` 单例、`MapAsset` 元素、`inject_one()`
    入参都先检查。

### 2. GC 句柄保护（防 0xC0000005）

跨分配存活的对象用 `il2cpp_gchandle_new/free` 钉住：

- `navfix.c` 加载 `il2cpp_gchandle_new/free`。
  - `link_guard_areas()`：`arr`、`esc` 各自 gchandle，用完释放。
  - `make_guard_area()`：`list`（List 不是原生对象）和 `nameStr` 钉住。
  - `build_waypoints()`：共享的 `childName` 字符串钉住；蹲守点 `nameStr` 钉住。
- `plugin.c` 加载 `il2cpp_gchandle_new/free`。
  - `inject_one()`：先建字符串并钉住，再建数组并钉住，写完 `MapAsset` 后释放。

## 验证

1. **完全退出游戏**（当前进程仍映射着旧 DLL，必须重启才会加载新 DLL）。
2. 重新启动游戏，进入多人生化模式。
3. 预期：不再弹 CRT 对话框；日志里能看到 `[edit] vis: ...` 正常走完。
4. 如果仍然闪退，把新的
   `%LOCALAPPDATA%\CrashDumps\UnityCrossFire.exe.*.dmp` 和
   `ucf_mod\ucf_mod.log` 尾部发回来。

静态校验：

- 修复版 `read_nano` 在调用 `GetComponent` 前有
  `cmp dword ptr [edi+8], 0`（反汇编地址 0x1000949A）；posList 元素同样检查
  （0x10009592）。
- 修复版 `link_guard_areas` 在两个 `arr_new` 之后都有 `il2cpp_gchandle_new`
  调用，写入组件前不会丢引用。

## 说明

- 这是“切图后旧组件仍被可视化层读取 + 托管数组跨分配未生根”的修复，
  不改变任何功能逻辑。
- 只进隐藏图（Nano30_Storm）不切图，也可能在退出/换图时遇到同样的异常；
  本次修复同样覆盖。
