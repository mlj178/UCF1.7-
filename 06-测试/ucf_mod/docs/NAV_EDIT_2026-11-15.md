# 路点手动编辑 + 进图自动套用（2026-11-15 18:10）

> 目标：在游戏里手动加/删路点、连/断边，改完立刻生效，自动存盘，
> 每张图一个文件互不干扰，下次进同一张图自动重新套用。

## 1. 快捷键（都要按住 Ctrl，字母键同时按 Shift）

| 快捷键 | 作用 |
| --- | --- |
| Ctrl+Shift+A | 选中 A 点（准星 3 m 内最近的路点） |
| Ctrl+Shift+N | 在准星地面加一个路点；若已选 A，自动把 A 与新点连上 |
| Ctrl+Shift+J | 连/断边：A 点与准星最近的点（已有边就断开，没有就加上） |
| Ctrl+Shift+D | 禁用准星最近的点（不可走 + 断开所有边，不改数组） |
| Ctrl+Shift+Z | 撤销上一条编辑（节点或边） |
| Ctrl+Shift+R | 强制重新套用本图的编辑清单（图被游戏重扫后用） |
| Ctrl+Shift+S | 手动再存一次（平时不用，改动会自动存） |

编辑要求 A 路点层打开、非 collect-only 模式；改完按 Ctrl+V 就能看到效果
（新点出现、被禁用的点变红、边即时重画）。

## 2. 文件落在哪、怎么区分地图

ucf_mod\nav\<图指纹>.txt，一张图一个文件，指纹格式和导出一致：
n<基础节点数>-<所有节点坐标的哈希>，例如 n786-57a46e3465c847cb.txt。

关键点：指纹是在套用编辑之前算的（即这张图的原貌），所以
“加了点 -> 节点数变了 -> 指纹变了 -> 下次找不到文件”不会发生。

文件内容（纯文本，一行一条，方便手改）：

    # ucf-navedit v1 fp=n786-57a46e3465c847cb
    node add 12.500 -15.500 4.250
    node del 10.000 -15.500 2.000
    edge add 12.500 -15.500 4.250 14.500 -15.500 4.250
    edge del 1.000 2.000 3.000 4.000 5.000 6.000

- node add / node del：坐标，匹配容差 0.35 m；
- edge add / edge del：两个端点坐标，按坐标找点（不是下标），重扫换序也不怕；
- 想整体撤销某张图的改动：删掉这个文件，下次进图就没有编辑了。

## 3. 自动保存 / 自动套用

- 自动保存：每次加点、删点、连边、断边、撤销，都立刻重写整份文件（日志 naved: saved N edits）。
- 自动套用：进图后 editor_tick 每帧检查，等节点数连续两次相同（稳定）后：
  1. 算该图指纹，定位 nav\<fp>.txt；
  2. 读清单；
  3. 按“坐标 -> 现成节点”的映射依次执行加点/删点/连边/断边；
  4. 调 RebuildNodeLookup() 刷新 A* 查找树，再重画可视化。
- 图被重扫：之后每 ~1 s 抽查清单还在不在图上，发现被游戏 Scan() 覆盖会自动再套用一遍
  （日志 naved: graph rebuilt, re-applied N edits）。

## 4. 为什么“删点”是禁用而不是从数组里删

PointGraph.nodes 是数组，GraphNode.nodeIndex 就是下标。真删会让后面所有节点下标平移，
A* 的 PathHandler 里还缓存着按旧下标的 PathNode，容易出脏数据。
所以删点 = walkable 位清零 + 清空 connections + 清掉别人指向它的边。
A* 的 GetNearest 用 NNConstraint.Default（constrainWalkability=true），
不可走的点不会被选中，人机也不会再走它。

## 5. 实现要点（x86 布局，来自 dump.cs）

| 东西 | 偏移 |
| --- | --- |
| PointGraph.nodes / nodeCount | +0xE8 / +0xEC |
| GraphNode: nodeIndex / flags / penalty / position | +0x8 / +0xC / +0x10 / +0x14（Int3，1/1000 m） |
| PointNode.connections / gameObject | +0x20 / +0x24 |
| Connection {node, cost, shapeEdge} | +0 / +4 / +8，步长 12 |

- 新节点：il2cpp_object_new(PointNode) 后填 nodeIndex/flags/position/connections，
  flags 沿用模板节点的 graph 编号（高位字节）并置 walkable；再按 AddNode<T> 的逻辑
  扩容数组（max(n+4, 2n)）挂到末尾。
- 边：双方各重建一个 Connection[]（容量 +1 或 -1），cost = 距离(m) x 1000，shapeEdge = 0xFF（直线）。
- 全程在 Unity 主线程（WndProc 的 tick）执行，不加锁；新对象用 il2cpp_gchandle_new 临时护住，
  挂到图上后再释放。

## 6. 已知限制

- 只改运行时点图，不动游戏文件；删掉 nav 里的文件就完全恢复。
- 跨沟/上下层要 Bot_JumpLink（跳链），本功能不建跳链。
- 普通图加点后，如果游戏自己重新 Scan，会在 1 s 内自动重套用；
  若走了别的加载路径把图覆盖了，按 Ctrl+Shift+R 手动补一次。
- collect-only（Ctrl+Shift+X 打开、目录里有 collect.flag）模式下不套用编辑。
