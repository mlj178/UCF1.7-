# 轨迹采集 v2：跳跃取证（2026-11-24）

> 用户的要求：日志要能回答「我这一跳从哪起、落在哪、多高、多远、多久」，
> 然后拿这些数去定「录制」的采样频率和判定参数。**速度不是目的**。
> 本文记录格式怎么改的、怎么验证、怎么用。

## 1. v1 为什么不够

| 问题 | 后果 |
| --- | --- |
| 记的是**相机**坐标（比脚底高 2.29 m，蹲下还会变） | y 不是"人在房间里的高度"；蹲一下像下落 0.6 m，跳高被带偏 |
| 没有 grounded / 竖直速度 | 跳跃只能靠「离地 0.3 m」猜，同一份数据两种算法能差 2 次 |
| 那个"脚下地面"是**相机向下的射线**，会穿过脚下的平台打到下一层 | 实测一帧从 2.29 m 跳到 11.78 m；旧日志里跳高出现 11.29 m 这种不可能值 |
| 字段一半和跳跃无关（相机朝向 fx/fy/fz、w/a/s/d/sh） | 文件大、读起来干扰 |

## 2. v2 格式

第一行 header：

    {"kind":"trace","schema":"ucf-trace/2","hz":30,"t0":"2026-11-24 20:30:00",
     "scene":"...","map":"level1","label":"运输船","pack":"...","fp":"...",
     "src":"player",
     "fields":["t","dt","x","y","z","g","vy","sp","ct"],
     "notes":"...","kind_note":"gap = 同高度跨缺口, mount = 跳上高台, down = 跳下, hop = 原地小跳"}

样本行（每帧一行）：

    {"t":31.770,"dt":0.033,"x":-8.120,"y":-16.640,"z":-19.600,"g":1,"vy":0.02,"sp":0,"ct":0}

| 字段 | 含义 |
| --- | --- |
| t | 从开始采集算起的秒（QPC） |
| dt | 距上一个样本的秒 |
| x / y / z | **玩家脚底**的世界坐标（Player.characterContainer） |
| g | 是否在地面（游戏自己的 Player.isGrounded） |
| vy | 竖直速度 m/s（Player.velData.velocity.y） |
| sp / ct | 空格 / Ctrl（判断助跑和蹲走用；方向键已删） |
| src | header 里的坐标来源：player = 真实玩家对象；camera = 没找到玩家，退回相机估算（有系统偏差，报告会标出来） |

跳事件行（落地那一帧由插件结算，一行一跳）：

    {"t":32.490,"ev":"jump",
     "a":[-8.120,-16.640,-19.600],"b":[-6.050,-16.640,-18.420],
     "h":2.310,"rise":1.900,"air":0.720,"v0":10.5,"run":8.4,"kind":"gap"}

| 字段 | 含义 |
| --- | --- |
| a / b | 起跳点 / 落点（都是脚底坐标） |
| h | 水平跳距（m） |
| rise | 跳高 = 峰值脚底 − 起跳脚底（m） |
| air | 滞空（s） |
| v0 | 起跳竖直速度（m/s，实测 10.3~11.6，和游戏 JumpPower=10.5 对得上） |
| run | 起跳瞬间的水平速度（m/s） |
| kind | gap 跨缺口 / mount 跳上高台 / down 跳下 / hop 原地小跳 |

其它行：分段行 ev=cam（换玩家对象/换图）、场景行 ev=scene、结束行 end（带 n/dist/missed/ticks）。

旧文件（ucf-trace/1）继续能读：缺的字段按缺省补，报告里会标「（估）」。

## 3. 数据从哪来（不用再靠相机反推）

dump.cs 里 Player 类现成就有：

| 成员 | 偏移 / RVA | 用途 |
| --- | --- | --- |
| Player.characterContainer | +0x58（Transform） | 脚底坐标 |
| Player.isGrounded | +0x70（bool） | g |
| Player.velData | +0x90 → PlayerVelocity +0xC（Vector3） | vy |
| Player.get_isMyPlayer | RVA 0xB55FD0 | 从一堆 Player 里挑出"我" |
| Player.JumpPower | 常量 10.5 | 起跳速度的参照 |

取实例：Object.FindObjectsOfType(Player) + get_isMyPlayer。每 2 s 最多扫一次，
指针用 m_CachedPtr 判活；**拿不到就自动退回相机估算**，并在 header 写明 src=camera。

## 4. 怎么用

1. 关游戏 → 控制台「开发调试 → 开发者选项 → 原始轨迹采集」→ 档位选 **30 Hz**（默认）；
2. 「开始采集」→ 进图跑你要量的一段（跳几下就行）→「停止」；
3. 点 **「生成跳跃报告(MD)」**：跑 app/tools/data/jump_stats.py，把目录里的日志汇成
   一份 Markdown（逐跳明细 + 分类统计 + 录制参数建议），生成完自动打开；
4. 命令行等价：python app/tools/data/jump_stats.py（默认当前目录全部日志）。

报告里第 4 节「对录制的参数建议」是按这批数据算的（最短滞空 → 需要多少 Hz、
跨缺口跳距中位/最大 → 跳链长度该卡在哪、跳上高台该不该建跳链），
等数据采完再一起定录制怎么改。

## 6. 已知边界

- characterContainer 是不是**正好在脚底**要第一次采完看日志里那行标定：
  trace: player=... feet=(x y z) ... cam=(x y z) dy=...
  dy 应该是 2.2~2.4（眼高）。就算它是模型胸口，也是常量偏移 —— 跳高、起落高差都是差值，不受影响；
  只有绝对 y 会整体偏一个常数。
- 如果日志里出现 src=camera，说明玩家对象没找到，这份数据的跳高/落点有系统偏差，报告会提示。
- 玩家在大厅/载入中时可能拿不到角色容器，跳事件自然也不会产生。
