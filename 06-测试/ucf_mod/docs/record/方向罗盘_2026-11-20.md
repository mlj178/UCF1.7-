# 方向罗盘：东南西北（2026-11-20）

> 用户要求：路点工作台的平面图 + 3D 地图都要有方向；游戏内也要能开关着看「东南西北」汉字；
> 控制台「可视化」页给一个开关；**工作台和控制台的方向必须统一**。
> 本文记录约定、三处实现位置和验证方式。

## 1. 结论

| 在哪 | 长什么样 | 开关 |
| --- | --- | --- |
| 工作台平面图（路点库 / 路线 / 区域） | 四边中点写 **北/东/南/西**；右下角罗盘：四方位字 + 圈心「你正对着哪」+ 顶上三角 = 画面正上方 | 地图左上「方向」按钮（默认开） |
| 工作台 3D 侧栏（`navview.html?embed=1`） | 同一个罗盘，**跟着视角转**（右侧居中，避开工具条 / 读数 / 提示） | 3D 工具条「方向」勾选（默认开） |
| 3D 查看器单独打开 | 俯视栏：四边方位字 + 罗盘（抬到右下提示条上方）；3D 栏：随视角转的罗盘 | 同上，两栏共用一个状态 |
| 游戏内 | 屏幕下方正中：四方位字 + 圈心汉字当前朝向（如「东北」） | 控制台「可视化」页「方向罗盘（东南西北）」；游戏内 **Ctrl+Shift+7**；默认开，与可视化总开关无关 |

工作台平面图的「方向」和 3D 侧栏的「方向」是**同一个状态**：工作台改 → `postMessage` 给 iframe
（不重载 3D）；在 3D 里改 → 反向消息，平面图按钮跟着亮/灭。

## 2. 方向约定（三处必须一致）

```text
北 = 世界 -Z（平面图 / 3D 俯视的正上方）    东 = 世界 +X（右）
南 = 世界 +Z（下）                         西 = 世界 -X（左）
```

为什么北是 -Z：平面图把世界 x 画到屏幕右、z 画到屏幕下；navview 3D 的「俯视」按钮
（yaw = 0）算出来的屏幕上方同样是 -Z（`cam3()` 的 up 基向量 = `(-sp·sin yaw, cp, -sp·cos yaw)`，
yaw=0、pitch=90° 时 = (0,0,-1)）。于是「图的上方 = 北」在平面图、3D 俯视、游戏内是同一件事。
游戏内相机 yaw 与 navview 同义（0 = 朝 +Z），所以罗盘用
`bucket = floor(((atan2(fwd.x, -fwd.z)·180/π) + 22.5) / 45) % 8`，0 = 北、2 = 东。

**改约定要三处一起改**：

| 文件 | 位置 |
| --- | --- |
| `workbench/nav-studio-app.js` | `DIR4 / DIR8 / dirScreen / dirHeading / drawCompassRose / drawCompass`，`drawMap` 末尾调用 |
| `tools/navview.html` | 同名函数；`render2`（俯视，yaw=0）与 `render3`（3D，`S.v3.yaw`，画在 `#cv3ui` 透明层） |
| `src/editor.c` | `compass_bucket / compass_update / compass_build`，`#define COMPASS_CY 96 / COMPASS_R 52` |

## 3. 游戏内实现要点（src/editor.c + src/cfg.c）

- 新开关 `vis_compass`（默认 1）：`cfg.c` 的 `g_defs[]` + `editor_start` 里 `cfg_bool("vis_compass", 1)`，
  启动日志多一行 `compass: vis_compass=...`。
- 罗盘挂在现有的 `UCF_HUD` Canvas 下（和出生点图例、F2 菜单同一张，排序 32000），
  锚点 = 屏幕下沿正中，1 单位 = 1 像素（ScreenSpaceOverlay，没有 CanvasScaler）。
- 只有朝向跨过 45° 扇区才 `SetText` / `SetColor`（UGUI 每次改字都要重排版），
  4 Hz 心跳（navfix 的 `WM_UCF_TICK`，250 ms）检查一次，不开就整块 `SetActive(0)`。
- 换图：Canvas 被 Unity 销毁 → `overlay_reset()` 里 `compass_reset()`，`overlay_refresh()` 重建
  （和出生点图例同一条生命周期）。
- 与 `visualizer` 无关：`editor_tick` 在 `nm_tick()` 旁边调 `compass_tick()`，可视化关着也显示。
- 字体：沿用 `find_cjk_font()` 验过中文字形的字体；没有中文字形时退化成 N/E/S/W。
- 热键 **Ctrl+Shift+7**（Ctrl+Shift+6 是可走面；字母组合已被路点编辑占满）。

## 5b. 顺手修掉一个旧崩溃：场景里没有 UGUI Text 时的 0xC0000005

2026-11-19 09:29 和 2026-11-20 19:04 两次车测崩在同一个地方：
`UnityPlayer.dll+0x76019d`、读 `0xfffffc4a`，调用链是
`editor_on_scene → load_file → overlay_refresh → overlay_init → Text.set_text`，
前面一行日志永远是 `ui: no cjk font among 0 Text objects`。

根因：`find_cjk_font()` 在场景里找不到任何 Text 时，`overlay_init` 会退回
`Resources.GetBuiltinResource(Font, "Arial.ttf")`，这个 Font 在 IL2CPP 里是
**fake-null / 不可用**的，拿去 `SetFont` + `SetText` 就把 UnityPlayer 打崩。

修法（`src/editor.c` `overlay_init`）：删掉这条兜底。场景里暂时没有 Text 就
`return 0`（日志 `ui: no font in scene yet (0 Text objects) - overlay skipped, retry on next tick`），
等 2 s 心跳在场景 UI 起来后再建覆盖层。车测立刻从「崩」变成「PASS」。

> 这条崩溃和方向罗盘无关（11-19 的构建里还没有罗盘），但罗盘让它更容易撞上 ——
> 现在第一个 `SetText` 是罗盘，以前是出生点图例。

## 6. 游戏内罗盘：和 3D 罗盘同一个样子（2026-11-20 二改）

用户要求「游戏里也要有指针、有颜色突出、圈会转」。实现（`src/editor.c` `compass_*`）：

```text
UCF_HUD_DirRoot           锚点 = 屏幕下沿正中，离底 112 px
├── DirDot ×32           表盘小点，半径 66 px，固定不动
├── DirRing              空 Text，只当 RectTransform；绕 Z 转 heading 度
│   ├── DirN/DirE/DirS/DirW   本地坐标 (0,52)(52,0)(0,-52)(-52,0)，不随转动改坐标
├── DirHead              圈心八向朝向（不转）
└── DirPtr               顶部金色 ▲（不转，离圈心 78 px）
```

- **圈会转**：只改 `DirRing` 的 `eulerAngles.z = heading`（0=北、90=东）。四个字的
  RectTransform 一个都不动，UGUI 不会重新生成文字网格 —— 转圈几乎不花 CPU。
- **指针**：`▲`（字体没有就 `△` / `^`），金色，固定指「画面正上方」。
- **颜色突出**：离正上方最近的方位字点亮成金色（`#ffd24a`），其余灰蓝；正好 45° 时取
  先出现的那个（北→东→南→西 顺序），网页端同一规则，两边不会出现「一个亮一个不亮」。
  圈心写八向朝向（`#e8f2ff`，同工作台）。
- **转速**：navfix 的 16 ms `WM_TIMER`（和自由视角同一个）里再调一次，函数内部 `spin++ & 1`
  节流到 ~30 Hz；镜头不动时 `|Δheading| < 0.08°` 连 set_euler 都不发。
- **表盘为什么是小点不是 ○**：实测 `○`（U+25CB）的墨迹在雅黑/Arial 里是 0.435 em、
  黑体是 0.90 em、宋体 0.75 em —— 同一个字号能算出 0.44~0.9 倍的半径，没法保证比方位字大。
  小点按坐标摆，任何字体都是同一个圆。
- 显隐只动根物体一次（`SetActive`），零件全挂在根下面。

## 7. 已知取舍

- 平面图罗盘在**右下角**（左下是比例尺、右上是缩放按钮）；3D 栏在**右侧居中**
  （顶上是工具条、左下是读数、右下是操作提示）；游戏内在**下方正中**。位置不同是为了不挡东西，
  方位语义完全一致。
- 游戏内表盘是 **32 个小点的虚线圈**，不是实线（原因见上一条）；改成更密的线只要调
  `COMPASS_DOTS`（32→64 更像实线，代价是多几十个 UGUI Text）。
