# 地图工程与本体补丁包（2026-11-24）

## 一、要解决的问题

两件事，同一个根因：

1. **看不见、备不上**：修游戏时改动直接落在游戏目录（`level9` 的 6 个字节、`level12` 的四个文件），
   工作区没有副本，`git status` 永远是干净的 —— 以为备份了，其实一点没进去。
2. **分发不了**：`06-测试\ucf_mod` 是要发给别人用的，别人的 UCF 是原版。
   只要有一部分"效果"只存在于我们自己的游戏目录，用户装完就和我们不一样。

根因：**游戏目录被迫当了第二份源码** —— 不在 git 里、不参与分发、删了就永久丢，而且没人知道。

## 二、这次定下的两条

| 图 | 方案 | 为什么 |
| --- | --- | --- |
| 风暴 / 飓风危城（`level9`） | **A：部署期改文件** | 效果 = 文件状态，可以静态校验；项目里备份/清单/写后校验/卸载还原全套已有；storm 本来就是插件注入才存在的图，不存在"没装插件也要有效果"的场景 |
| 龙城（`level12`） | **插件注入第 4 项 + 装 4 个文件** | 老做法改 `sharedassets0.assets` 会把第 3 项椰岛之巅顶掉；改成注入（`game_mode = 0` = `TeamMode.TeamDeath`），70 MB 那个文件一个字节都不用动 |

运行时 `SetActive`（方案 B，风暴）只作应急预案 —— 那 5 个对象全是 UI（Canvas / EventSystem），
跟人机没有可见因果，机制是黑箱；让效果依赖黑箱的时序，不如依赖可校验的文件状态。

## 四、工具

`app\tools\ledger.py`（只读）：

```powershell
python app\tools\ledger.py scan            # 副本 × 补丁矩阵 + 未纳管的本体改动
python app\tools\ledger.py scan --write    # 同时写 run\ledger\drift.json + 快照
python app\tools\ledger.py verify --game "D:\...\UnityCrossFire1.7.1"
```

判据只有四个：`✓ 已打补丁` / `✗ 原版（未装）` / `- 缺失` / `! 被改过`。
另有两条专治"会丢"：

- **未纳管的本体改动**：`UnityCrossFire_Data` 顶层里 mtime 不是 2023-04-06、又不在 `run\gamepatch` 里的文件；
- **已知·旧方案遗留**：`_index.json` 的 `known_body_changes`，比如 D 副本里那个 19 字节注册表补丁，
  明确写出"为什么曾经改、现在为什么不用、怎么还原"。
