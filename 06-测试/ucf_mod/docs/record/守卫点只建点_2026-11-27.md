# 守卫点只建点，不再连带建守卫区_2026-11-27

## 用户需求（原话）

> 这个是不对的，修复一下。守卫点只是设立点。

（上文是我核对「守卫区 / 守卫点 是不是在菜单里反了」时列出的第 ① 条：一次点击在同一个
坐标生成了「区 + 点」两个对象。）

## 之前的行为

「加守卫点」有两条入口，两条都走同一套「区外就顺手建区」的逻辑：

| 入口 | 旧代码 |
| --- | --- |
| `F2 → 3 守卫区工具 → 2 加守卫点` | `menu_activate()`：`else { make_area(30, p); if (g_curArea >= 0) make_nanopos(...); }` |
| 控制台笔刷 `brush guard` + 左键/5 | `wp_place()`：`int okArea = make_area(30, p); if (okArea && ...) make_nanopos(...);` |

于是准星不在任何 3 m 区框里时，**一次点击 = 新建守卫区 + 往里挂一个守卫点**，
两个对象坐标完全相同。日志实证（2026-11-27 11:02:53 那次实测）：

```
area #11 (aid=5 scale=3.0) at -60.41 -16.59 -7.66 -> current（等第一个守卫点再激活）
area aid=5 激活（第一个守卫点）posList=1
nanopos #13 at -60.41 -16.59 -7.66 aid=5 safety=3 areaPosList=1
```

用户看到的是：想放一个点，场上冒出来的却是一整个区（而且新区立刻被激活成绿框），
所以第一反应是「守卫区 / 守卫点的设置反了」。

## 为什么不对

1. **守卫点是"设立点"**：它只是区下面的一个站位 + 朝向（`Bot_NanoGuardPos`），
   本身不构成任何范围。区的建/删是独立的一步操作，不该被「加点」隐式触发。
2. **同坐标两个对象**：删除、撤销、计数（`vis: features (area=… pos=…)`、markers.txt 的
   `area=` / `nanopos=`）都各算一个，事后很难解释「我明明只点了一下」。
3. **一个点只有一个归属区**：游戏模型是「区 → posList → 点」，先有区才有点；
   把「建区」藏进「加点」里，反而让人以为两种东西可以互相替代。

## 改法

| 位置 | 改动 |
| --- | --- |
| `wp_place()`（笔刷 3） | 函数开头、`ed_step()` **之前**判 `g_wpBrush == 3 && area_at(&p) < 0` → `toast_bad("这里没有守卫区：先按 1 建区，再在区里加点")` + 日志，直接 return |
| `menu_activate()`（sub 3 第 2 项） | `i == 1 && area_at(&p) < 0` 同样早退（在 `ed_step()` 之前，`menu_refresh()` 后 return） |
| 两条路径的 case 分支 | 删掉 `else { make_area ... make_nanopos ... }` / `okArea` 那套连招，只保留「挂到已有区」 |
| `ghost_tick()` | `if (ok && brush == 3 && area_at(&p) < 0) ok = 0;` —— 区外预览框变灰（slot 13），和按下去会被拒绝一致；朝向预览箭头也一起收起来 |
| 菜单文字（sub 3 第 2 项） | 「准星不在任何守卫区里：按 5 不会建点（守卫点只挂在区里）—— 先按 1 建区，再回来加点」 |
| `app/tests/test_guard_no_auto_area.py` | 新增 28 项静态自检 |
| `app/tests/test_guard_preview.py` | 第 103 项断言跟着改成「按 5 不会建点」 |

**早退放在 `ed_step()` 之前**是刻意的：被拒绝的操作不留空撤销步，也不会点亮
F2 菜单第一行的「● 未保存 · Ctrl+S 保存」。

## 不变的部分

- **建区照旧**：`3 守卫区工具 → 1 新建守卫区` 和笔刷 4 仍然是「按 5 立刻建 3 m 区」。
- **区必须先激活**：新区挂上第一个守卫点时才激活（金框 → 绿框），人机这时才认，见
  `守卫区绿框与待激活_2026-11-26.md`。
- **归区规则不变**：仍然按落点 `area_at()`（3 m 框、每轴 1.6 m 容差）找区，
  不认「最后新建的那个区」，见 `守卫点按落点归区_2026-11-26.md`。
- **读档不变**：markers.txt 的 `nanopos` 行必须排在它所属的 `area` 行之后；aid 对不上
  时 `make_nanopos` 只写一行 `nanopos: no area aid=%d` 并跳过（本来就不会自己造区）。

### 游戏内验证清单

1. 找一块空地（附近 1.6 m 内没有任何守卫区）→ `F2 → 3 → 2`，虚线框应是**灰色**，
   菜单里那行写「按 5 不会建点」，按 5 只弹红字「这里没有守卫区：先按 1 建区」；
   图里标记数不变，F2 首行**不出现**「未保存」。
2. `F2 → 3 → 1` 在同一个位置按 5：立刻出现 3 m 金框（未激活），标记数 +1。
3. 站进金框内（准星落在框里）→ `3 → 2` 按 5：虚线框变回绿色，只增加一个守卫点，
   **区数不变**，金框变绿框（激活）。
4. 在同一个区里再按 3 次：区数还是 1，点数是 4。
5. `Ctrl+S` → 重进图：区 1 个、点 4 个，坐标和刚才一致。
