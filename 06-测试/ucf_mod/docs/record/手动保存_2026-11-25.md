# 游戏内编辑必须手动保存（Ctrl+S）_2026-11-25

## 需求（用户原话）

> 地图内的编辑，必须手动保存，否则，做一个 Ctrl+S 的保存按钮，必须保存了，退出房间才能保存，
> 如果没有保存，那么退出房间就没了，其他快捷键的保存都不要，只要这个。
> 录制里面也是，必须要点了保存才算保存。

拆成四条：

1. 游戏内所有编辑（路点 / 连线 / 跳链 / 蹲守点 / 守卫区 / 标签 / 出生点）默认**只在内存和当前场景里生效**；
2. 只有 **Ctrl+S** 才写文件；F2 菜单里的「保存」是同一个入口（按钮），**不保存就退房间 = 改动丢弃**；
3. 其他快捷键的保存全部删掉（Ctrl+6、Ctrl+Shift+S 不再存档）；
4. 录制侧不点「保存增量」就什么也不写（复盘页只预览）。

## 结论 / 行为

| 动作 | 以前 | 现在 |
| --- | --- | --- |
| 加点 / 删点 / 连线 / 跳链 | 每次编辑立刻 `nav_save()` | 只置 `g_dirtyNav`，Ctrl+S 才写 `<指纹>.txt` |
| 蹲守 / 守卫区 / 标签 | 菜单动作后立刻 `save_file()` | 只置 `g_dirtyMk`，Ctrl+S 才写 `markers.txt` |
| 出生点 BL/GR 增删 | 立刻 `save_file()` | 同上（只改运行时数组 + 内存清单） |
| Ctrl+6 | 保存 markers | 取消，日志提示用 Ctrl+S |
| Ctrl+Shift+S | 手动 nav_save | 取消，日志提示用 Ctrl+S |
| Ctrl+S | （无） | **唯一保存入口** `editor_save_all()` |
| F2 → 8 撤销 / 保存 → 3 | 只 `nav_save()` | `editor_save_all()`（点图 + 标记一起，改名「保存（Ctrl+S）」） |
| 退出房间 | 已经落盘，所以都在 | 丢弃未保存编辑，日志一行「退出房间，丢弃未保存的编辑」 |
| 录制复盘 | 已经要求点「保存增量」 | 不变，但复盘页明确写「只预览、还没写进草稿」 |

**只写脏的那一边**：控制台 / 录制会直接改盘上的同一个文件（录制是 Python 追加），
如果 Ctrl+S 把没改过的那份内存重写一遍，就会把刚追加的录制行盖掉。所以
`g_dirtyNav` / `g_dirtyMk` 分开记，只写改过的文件；两边都没改时 Ctrl+S 只打一行日志。

**Ctrl+S 在菜单开着时也要能用**：菜单把 S 留给游戏走路（`editor_menu_key` 对 S 返回 0），
但 navfix 原来只在「菜单没开或按住 Shift」时才把 Ctrl+字母送进编辑器；这次在
`WM_KEYDOWN` 里单独放行 `Ctrl+S`。

## 边界与取舍

1. **不保存就退房间**：插件不需要「拦截退房间」——不写盘，文件自然还是上一次保存的内容；
   下次进图 `load_file()` / `nav_edit_load()` 读到的就是旧数据。日志留一行方便对账。
2. **Ctrl+S 不在房间时拒绝**（`navfix_point_graph() == 0`）：否则大厅里按一下会把上一张图的
   内存状态写进上一张图的文件。
3. **重读 / 切包 / 录制保存后的 apply**：都以磁盘为准，会丢弃内存里未保存的编辑；这些是用户
   主动发起的动作，日志提醒但不拦截（拦截会让「重新应用」「录完自动套用」没法用）。
4. **没有改动时 Ctrl+S 不重写文件**：防止把控制台 / 录制刚追加的内容盖掉（见上）。
5. **markers.txt 与包 `.txt` 分开存**：Ctrl+S 只写脏的那份；某一边写失败（例如正式版
   `UCF_NAV_READONLY`）时保留对应脏标记，菜单仍显示未保存。
