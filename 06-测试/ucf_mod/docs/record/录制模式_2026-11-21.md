# 路点录制模式：控制台「录制」页（2026-11-21）

> 用户要求：玩家在运动过程中就把路线设计好（走位 / 双选线 / 单选项 / 跳箱 / 高台落下），
> 不要先记坐标再回家画。设计稿 `design/record-mode.html` 已按「放进控制台」重做，
> 本文记录落地实现：控制台页、C 侧采样器、识别规则、保存格式与验证。

## 1. 三条链路

```text
玩家在游戏里走 / 跳 / 跳下
        │  相机位置 + 朝向 + 脚下地面 + 空格/Ctrl
        ▼
src/editor.c  rec_tick()  ── 20 Hz ──▶  navdata\dev\vis\rec\<图>_<包>_<时间>.jsonl
        ▲                                        │
        │ ucf_navcmd.txt: cmd=rec act=start/stop │ 控制台每 0.25~0.35 s 读
        │                                        ▼
console/控制台.pyw「录制」页  ◀── console/ucf_rec.py（重采样 + 事件识别）
        │
        └─ 复盘确认 ──▶ ② navdata\dev\packs\<图>\<包>\<指纹>.txt（只追加）
```

插件只负责**采样**，不判断「这是不是一条路」。节点怎么落、哪里算跳箱、哪里算跳下高台，
全在控制台 `ucf_rec.py` 里按下面的阈值算；阈值改了不用重编 DLL。

## 2. 控制台页（console/控制台.pyw）

页签位置：**人机路点 → 录制 → 数据**。三态共用一个顶部常驻条（状态徽标 + 主操作）：

| 状态 | 徽标 | 主操作（右上） | 次操作 |
| --- | --- | --- | --- |
| ① 录前准备 | 绿 | 开始录制 | 打开游戏 |
| ② 录制中 | 红 | 结束并复盘 | 暂停 / 继续 |
| ③ 复盘 | 蓝 | 保存增量 | 重新采样 |

录前准备：
- 启动档**只显示、不给选**：录制只写 ② 开发版，固定 **编辑中（packs·可写）**；全局停在成品档时显示「成品（只读）」并给一键「切到编辑中」（2026-11-21 用户要求：录制页保留成品选项只会让人点了才发现录不了）。
- 开发包、地图、只对这张图生效 —— 和「人机路点」页是**同一份状态**（两个下拉互相同步，不各存一份）。
- 采样间距 2.5 / 4 / 6 m（默认 4）。
- 六个识别开关：跳跃 / 落下 / 岔路 / 蹲点 / 静止 / 传送（写 `ucf_mod.json` 的 `rec.sw`，插件不读，纯控制台识别用）。
- 预检：插件总开关、编辑中、开发包、地图、游戏在跑。缺哪项就红字列出来，开始按钮禁用。
- 顶部「打开游戏」走现有 `launch_game()`：启动档 / 包 / 图与「人机路点」完全同一套环境变量。

录制中：
- 每 0.35 s 重新读 jsonl、调一次 `analyse()`；显示时长 / 距离 / 样本 / 节点 / 边 / 跳 / 落 / 岔，2D 轨迹图与最近事件实时刷新。
- 暂停 / 继续写 `act=pause|resume`；结束写 `act=stop`，等 0.7 s 读整个文件进复盘。
- 游戏退出时自动收尾（`game_running(fresh=True)` 变 false）。

复盘：
- 2D 图：绿线 = 走路双向边，黄虚线 = 跳链，橙虚线 = 单向落下，黄圈 = 跳跃起跳点，橙圈 = 落下起跳点。
- 问题清单：断段 / 长边 / 可能摔伤 / 蹲点 / 静止 / 岔路候选 / 太短的跳链。
- 「跳链 / 落下也建反向边」勾选（默认关）：跳箱和跳下高台默认单向，勾上后同一处能走回来。
- 「重新采样」按新间距/开关重算，不重录。

## 3. C 侧采样（src/editor.c）

- 新增 `rec_tick()` / `rec_start()` / `rec_stop()`；navfix 的 16 ms 定时器（`WM_TIMER 0xF3C1`）和 `editor_tick()` 都会调 `rec_tick()`，函数内部按 `hz` 用 `GetTickCount64()` 节流。车测路径里 `editor_tick()` 只有 4 Hz，靠定时器补到 20 Hz（2026-11-21 实测：14 s 记 281 条）。
- 每行一个 JSON：

```json
{"t":12.345,"x":-52.80,"y":-15.02,"z":3.63,"gy":-16.59,
 "fx":0.71,"fy":0.02,"fz":0.70,"sp":0,"ct":0}
```

| 字段 | 含义 |
| --- | --- |
| t | 从开始录制算起的秒数 |
| x y z | 相机（玩家眼睛）位置 |
| gy | 相机正下方射线打到的地面高度；没打到 `-9999` |
| fx fy fz | 相机朝向（单位向量） |
| sp / ct | 空格 / Ctrl 是否按下（`GetAsyncKeyState`） |

- 结束写 `{"end":1,"t":..,"n":..,"dist":..}` 并 fclose；游戏退出（`editor_on_quit`）也会收尾。
- 换图不断录：位置跳变由控制台按「单帧 > 15 m」断段，段间不连边。
- 命令（`ucf_navcmd.txt`，0.5 s 轮询）：

```text
seq=<毫秒>
cmd=rec
act=start | stop | pause | resume
out=D:\...\navdata\dev\vis\rec\level1_xxx_20261121-133000.jsonl
hz=20
```

## 4. 识别规则（console/ucf_rec.py）

| 事件 | 条件 | 落边 |
| --- | --- | --- |
| 跳跃 | 空格 + 离地 > 0.30 m，水平 ≥ 1.50 m | `jump add A B` + A→B（可选反向） |
| 落下 | 没按空格，下降 ≥ 1.5 m 且落差 ≥ 2.0 m | 单向 A→B（可选反向） |
| 岔路 | 2.5 m 内第二次经过，且中间绕 ≥ 8 m | 只是候选标记；保存本来就是双向 |
| 蹲点 | Ctrl > 0.8 s 且位移 < 1 m | 只提示，不落点 |
| 静止 | 2 s 没位移 | 复盘写一句；采样照常 |
| 传送 | 单帧位移 > 15 m 或间隔 > 3 s | 断段，段间不连边 |

重采样：在脚下地面轨迹上每 `step` 米落一个节点；转角 > 55°（前后各看 1.2 m）强制补点；
相邻节点 < 0.3 m 的边丢掉；默认 4 m 时一条 88.8 m 的演示轨迹为 48 节点 / 44 边。

## 5. 保存格式

目标：`navdata\dev\packs\<图>\<包>\<指纹>.txt`（只写 ② 开发版 · 编辑中）。

```text
# ucf-navedit v1 fp=n786-57a46e3465c847cb
grow                       ← 新建文件时按 manifest 写 grow / keep
node add -50.401 -16.590 6.626
edge add A B
edge add B A               ← 走路是双向
jump add A B
edge add A B               ← 跳链默认单向
```

- **只增不覆盖**：先读现有 txt，节点按 0.35 m、边按坐标串去重；没有新行就提示「包里已经有了」，不写盘。
- 有改动：先复制 `<指纹>.txt.bak-rec-<时间>`，写 `.tmp` 再 `os.replace`；任何 OSError 都保留原文件。
- 游戏在跑：保存成功后再写 `cmd=apply`，插件 0.5 s 内重载包，不用重进图。

## 7. 还没做 / 已知边界

- 游戏内没有「录制中」HUD：开录后只能看控制台。后续可在 UCF_HUD 上加一行红点 + 距离。
- 岔路目前只标候选，没有「确认双选」的单独落盘（走路边本来就双向）。
- 原始 jsonl 不自动清理（`dev\vis\rec\`）；确认保存后可手动删，或以后加「保留最近 N 份」。
- 录制的节点都按脚下地面落点；需要半空中的路点（跳箱落点）仍要在 F2 菜单里补。
- 车测/自由视角的相机不跟玩家，录出来的轨迹不能当路线用。
