# 「加了守卫点为什么不绿」：点挂错区 + 重建闸门（根因 + 修复）_2026-11-26

## 用户提问（原话）

> 那我加上了守卫点，为什么没变绿呢？是你的问题吗？延迟了，还是bug

## 结论

**两条原因，第一条是设计缺陷（算我的），第二条是既有的进图保护窗口。**

### 原因 1（主因）：点挂到了「当前区」，不是准星所在的区

旧规则：`make_nanopos` 只认 `g_curArea`（= 最后新建的那个守卫区），
**完全不看准星落在哪个 3 m 框里**。于是：

- 你在 A 处建区 → A 成为「当前区」；
- 走到 15 m 外，在别的金框旁边按「加守卫点」→ 点其实挂到了 A 上（A 早在第一个点时就绿了）；
- 你眼前那些框一个点都没收到 → **永远不会变绿**，而且整场颜色一点变化都没有。

日志（19:32，同一场）：

```
19:32:03  area #42 (aid=16) at -55.50 -20.09 -19.27 -> current（等第一个守卫点再激活）
19:32:06  area aid=16 激活（第一个守卫点）posList=1     ← aid=16 这时就绿了
19:32:06  vis: ... (area=8 pos=27 ...)
19:32:17  nanopos #52 at -41.61 -20.09 -18.69 aid=16    ← 距区中心 14 m
19:32:17  nanopos #53 at -38.52 -20.09 -18.76 aid=16    ← 17 m
19:32:18  nanopos #54 at -35.42 -20.09 -18.88 aid=16    ← 20 m
19:32:18  vis: ... (area=8 pos=37 ...)                  ← 加了 3 个点，激活区数还是 8
19:32:22  area #54 (aid=17) ... -> current（等第一个守卫点再激活）
19:32:24  area #55 (aid=18) ... -> current（等第一个守卫点再激活）
19:32:27  area #56 (aid=19) ... -> current（等第一个守卫点再激活）
```

后面 17/18/19 三个金框是你「没看到变化」又连按建出来的，它们同样一个点都没收到。

### 原因 2：进图头 22 秒的可视化重建闸门（真实存在的延迟）

`VIS_SCENE_WAIT = 90` 个心跳（心跳 4 Hz ≈ **22 秒**）内，整层可视化重建被推迟
（读游戏组件表会撞上一张图正在销毁的对象，2026-11-17 沙漠要塞的闪退因此而来）：

```
19:31:26  vis: defer rebuild (scene age 48/90)
19:31:27  area aid=13 激活（第一个守卫点）posList=1     ← 已挂点、已激活
19:31:31  vis: defer rebuild (scene age 68/90)          ← 仍然推迟
19:31:33  （Ctrl+V 关再开触发重建）area=7               ← 绿框这时才出现
```

所以「延迟」确实存在，但它是固定的进图保护窗口，不是每帧刷新慢。
旧 DLL 的金框也在这一层画，同样吃这个闸门；新版已把「我们自己的框」改成每 tick 维护。

## 改动

| 位置 | 改动 |
| --- | --- |
| `area_at()`（新增） | 按落点找区：`|dx|,|dy|,|dz| ≤ 1.6`（3 m 框半宽 1.5 + 0.1 容差）即算在这个区里，多个重叠取最近的 |
| 菜单「加守卫点」 | 先 `area_at(&p)`：找到就挂那个区（并把 `g_curArea` 改成它）；一个都不在才新建区 —— 和笔刷路径同一套规则 |
| 笔刷放守卫点（`wp_place` case 3） | 同上，日志写明挂到哪个区 / 为什么新建区 |
| 菜单文字 | 第 2 项改成「准星在守卫区 #N（aid=…）里：按 5 就挂进这个区」/「准星不在任何守卫区里：按 5 会在该点新建一个区」 |
| 守卫区线框（`pend_draw_set` / `pend_area_tick`） | 两套框：**金=未挂点**；**绿=已挂点但这一轮 `read_nano` 还没读到**（重建被推迟时我们自己顶上，避免「一点下去框就消失」）。`g_nanoSeen` 记录本轮真正读到的区组件，避免和可视化层的绿框重叠 |

## 行为对照

| 场景 | 之前 | 现在 |
| --- | --- | --- |
| 站在 A 区里给 B 区（十几米外是「当前区」）加点 | 点静默进 B，A 永远不绿 | 点进 A（准星所在的框），A 挂上首个点后变绿 |
| 准星不在任何区里加点 | 挂到「当前区」（可能在很远） | 在该点新建一个区 + 挂点（和以前一样是唯一合理的做法） |
| 刚进图 20 秒内挂上第一个点 | 金框还在，绿框要等重建（最长 22 s） | 旧框立刻退场、**新绿框立刻出现**（我们自己的那套），重建后交给可视化层 |
| 已经进入 `SpareAreaList` 的区 | 只有一份绿框 | 仍然只有一份（`g_nanoSeen` 判重让位） |

## 进游戏核验

1. 进图后随便找个地方「新建守卫区」→ 金色线框；站**这个框里**按「加守卫点」→ 应该立刻变绿（不用等 22 秒）；
2. 站到 20 m 外的另一个金框里加点 → 只有你脚下那个框变绿，远处那个不动；
3. 菜单第 2 项应显示「准星在守卫区 #N（aid=…）里」；把准星移到没有区的地方应显示「准星不在任何守卫区里」；
4. 日志应出现 `wpmenu: 准星落在守卫区 #N（aid=…）里，改成挂这个区`（跨区加点时）或
   `area: 守卫区线框 N 个（已挂点、可视化还没重建：先画绿框）`。
