## 用户报障与决定（原话）

第一次：

> 怎么我路点菜单添加普通路点都添加不进去了，半天都不显示，怎么回事，修复一下

看完根因（运输船 786 个点全可走、没有空槽位；测试包是飓风危城的、本图被跳过）后，用户决定：

> 撤回一下你的修复，之前的问题是交互问题，确实应该禁止用户做点，不过应该给用户反馈，
> 可以有文字提示，可以弹出来或者怎么样，在游戏内部的文字弹出文字，你看怎么设计合适呢？
> 弹出的位置放在屏幕中央，也不是弹出弹窗，就是显示文字，并且颜色明显一些。

所以：**「没有空槽位就不能加点」是正确行为，要保留；缺的是反馈。**

## 新增：屏幕中央提示（toast）

### 设计

| 项 | 取值 |
| --- | --- |
| 位置 | **屏幕正中**，锚点/轴心都 0.5/0.5；Y 上移 90 px，免得压住准星（`TOAST_Y`，改 0 就是正中） |
| 样子 | 一行（太长自动折行）**亮红**文字 + **黑色影子**（两个 Text 叠 2 px），34 px，居中 |
| 时长 | 3 s 自动隐藏（`TOAST_MS`）；同一条消息 0.5 s 内连按不重复闪 |
| 不是弹窗 | 就是 Canvas 上的文字，不挡准星、不接输入、不暂停游戏 |
| 挂在哪 | 和 F2 菜单、图例同一张 `UCF_HUD` ScreenSpaceOverlay Canvas（sortingOrder 32000） |
| 换图 | 场景销毁时 `overlay_reset()` 清零指针，下一次 `toast_show()` 自动重建整张 Canvas |

### 两种颜色 / 两种结果

| API | 颜色 | 停留 | 用在哪 |
| --- | --- | --- | --- |
| `toast_ok(fmt, …)` | 亮绿 `#59F273` | 1.6 s | 放点 / 连边 / 删点 / 贴地 / 撤销 / 保存 成功 |
| `toast_bad(fmt, …)` | 亮红 `#FF3B29` | 3.0 s | 禁止操作、选不中、没草稿、「按了但图上没变化」 |

> 2026-11-26 晚第二版调整：**黄字「提示下一步」整类删掉**（用户："这个不需要，去掉"）。
> 删的是 `已选 A，对准下一个点` / `当前类型：…` / `连线方向：…` / `起跳点已锁定…` 四类 ——
> 这些下一步怎么做菜单里本来就写着，屏幕上再弹只会挡视线。
> 「按了但没效果」那几个（没有可撤销的、这个点本来没连线、已经在地面高度）保留，
> 但改成**红字**：它们不是"下一步提示"，是"这次按键没产生变化"。

**加点的禁止提示（本轮的起因）**：

- 没有可写草稿：`加不了点：本图没有空槽位，也没有可写的点图草稿（测试包是别的图的）`
- 有草稿但点全可走：`本图 786 个点全都可走、没有空槽位：先删一个点，或用 keep 测试包`
- 准星没地面 / 这里已有点：`准星下面没有地面，换个位置再放` / `这里已经有一个路点了`

新增一个动作时，只要在成功/失败分支各写一行 `toast_ok(...)` / `toast_bad(...)` 就行，
不用再碰 UI 代码。

## 边界

1. **大厅 / 没有 PointGraph**：`overlay_refresh()` 本来就不建 UI，toast 打不出来（日志里一行
   `toast: ui not ready: …`）。大厅也放不了点，不影响。
2. **只读采集（Ctrl+Shift+X）**：`toast_show` 只写日志，不建 UI —— 采集模式不应该有插件 UI。
3. **toast 是"提示"不是"确认"**：不拦截输入、不需要玩家点掉，3 s 自己消失。
4. **颜色/位置都可调**：`COL_TOAST` 改颜色，`TOAST_Y` 改上下位置，`TOAST_MS` 改停留时间。
