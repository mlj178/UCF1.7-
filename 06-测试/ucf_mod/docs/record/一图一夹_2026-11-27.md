# 一图一夹（2026-11-27）

> 类型：**记**（历史证据）。现状看 README.md 与 docs/guide/地图对照表.md。
> 本文路径统一写成 `/`，实际在 Windows 上是同一个位置。

## 为什么要改

同一张图（例：运输船）的东西散在 4 处：

    data/navdata/native/01_TransportShip运输船/map.json          ① 冻结副本
    data/navdata/dev/01_TransportShip运输船/map.json             ② 开发数据
    data/navdata/dev/packs/01_TransportShip运输船/<指纹>.txt     点图草稿
    data/navdata/dev/packs/01_TransportShip运输船/manifest.json  草稿状态
    data/navdata/dev/markers/01_TransportShip运输船/markers.txt  蹲守/守卫区/守卫点/标签/出生点
    data/navdata/dev/final/<指纹>.txt                            成品（平铺，按指纹不按图）

想凑齐「运输船的全部文件」要翻 4 个目录；编辑标记和点图甚至不在同一个根。
（2026-11-21 已经做过一次「一张图一个文件夹」，但那一次只收拾了 ①②，草稿和标记还在外面。）

## 改成什么样

    data/maps/
    ├── 00_公共/                     names.json / _index.json / INDEX.md / SHA256SUMS.txt / .frozen.json
    ├── 01_TransportShip运输船/
    │   ├── map.json                 点图元数据（指纹 n786-…、786 点 / 1391 边、bbox）
    │   ├── navmesh.bin              可走面（原生没有 NavMeshGraph 的图就没有这个文件）
    │   ├── n786-57a46e3465c847cb.txt 点图草稿
    │   ├── markers.txt              蹲守点 / 守卫区 / 守卫点 / 标签 / 出生点
    │   ├── manifest.json            草稿状态（grow / keep / 建成时间）
    │   ├── native/                  ① 冻结副本：map.json + navmesh.bin（只读位）
    │   └── final/<指纹>.txt         成品（发布后才有，只读位）
    ├── …（02 / 03 / 05 / 06 / 08 / 09 / 10 / 11）
    ├── 04_NY_TM胜利广场/  07_DeathRing死亡擂台/    原生没有点图，只有 navmesh.bin
    ├── _inbox/                      可走面导出 / 录制轨迹（派生，可重建）
    └── _archive/                    删草稿 / 清标记 / 发布前快照 / 迁移日志

**唯一源 = 每张图的文件夹；`_inbox` / `_archive` 是派生目录。** 这条边界决定了下面两件事为什么这么改。

## 为什么不能简单地 mv

1. **C 侧 `UCF_PACK` 只能是单段目录名**（`pack_ok_id()` 拒绝第二段）。
   所以「草稿 + 标记 + 成品」不能靠 `UCF_PACK=a/b` 这种写法指进去。
2. **成品档要在一个进程里读全 11 张图**（进游戏后换图不会重启）。
   平铺的 `final/<指纹>.txt` 正是为这个存在的；改成每图一份以后，必须让插件**按当前图指纹找**。
3. `.gitignore` 里 `/maps/` 是「根目录不许出现 maps」的规则（2026-11-21 之前部署端的旧目录），
   所以新目录叫 `data/maps/`，不能叫根目录 `maps/`。
4. `test_layout.py` 钉死了根目录只有 8 个文件夹 —— 同上，必须放在 `data/` 里。

## 怎么改的（三步）

### 1) 搬文件：`app/tools/_oneoff/migrate_one_map_one_folder.py`

    python app/tools/_oneoff/migrate_one_map_one_folder.py           # dry-run，只打印要搬什么
    python app/tools/_oneoff/migrate_one_map_one_folder.py --apply   # 真搬，逐文件比 sha256
    python app/tools/_oneoff/migrate_one_map_one_folder.py --undo    # 按日志原路退回

- 170 个文件 / 约 1.8 MB（`_inbox/rec` 的 32 MB 录制 jsonl 原样不动）。
- 每个文件搬前搬后各算一次 sha256，对不上就停下（`--undo` 可退）。
- 撞名（两份 `names.json` 内容不同）自动改存 `names.native.json`，不覆盖。
- 顺带改写两份清单里的路径前缀：`<图>/map.json` → `<图>/native/map.json`，并重算 `manifest_sha256`。
- 搬空的 `data/navdata/` 整个删掉（**没有兼容期**，用户 2026-11-27 明确不要）。
- 迁移日志：`data/maps/_archive/migrate_onemap_<时间>.json`（`test_mapfolders.py` 会检查它在）。

### 2) 路径真相：`app/core/ucf_paths.py`

新增/改写：

    MAPS       = data/maps          # 唯一源
    COMMON     = 00_公共
    NATIVE_SUB = native             # <图>/native/
    FINAL_SUB  = final              # <图>/final/
    INBOX      = data/maps/_inbox
    ARCHIVE    = data/maps/_archive

    folder_dir / native_dir / final_dir / folder_names
    native_files() / native_navmesh_files() / map_files(root, sub) / navmesh_files(root, sub)

`NATIVE` / `DEV` / `PACKS_DIR` / `MARKERS` / `FINAL` 这些旧名**保留但现在指向同一个根**，
老调用点指得动；「① 冻结副本」必须走 `native_files()` / `native_dir()`、`map_files(MAPS, "native")`。

### 3) C 侧：成品档按指纹找图（`src/editor.c`）

成品档不设 `UCF_PACK`（没有「唯一一张图」），改设：

    UCF_PACK_DIR   = <data/maps>
    UCF_NAV_SEARCH = 1
    UCF_NAV_SUB    = final

新增 `nav_find_fp_file()`：扫 `<packRoot>/<图>/final/<指纹>.txt`，命中就把
`g_nedPath` 指过去、`g_mapDirName` 记下图文件夹名；`mk_set_path()` 于是在
`<markers根>/<图>/markers.txt` 读标记 —— **顺手修掉一个老缺陷**：
以前成品档包名是 `final`，标记会被算到 `markers/final/markers.txt`，
那张图一份都没有，所以**成品档下蹲守点/守卫区一直加载不到**（因为 `final/` 一直是空的，没人发现）。

编辑中档完全没变：`UCF_PACK_DIR=data/maps` + `UCF_PACK=<图>`，C 侧照旧拼
`<根>/<图>/<指纹>.txt` 和 `<根>/<图>/markers.txt`。
