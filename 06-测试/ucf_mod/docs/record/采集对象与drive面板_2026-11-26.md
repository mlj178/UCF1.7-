## 1. 采集对象

| 项 | 玩家 | 人机（新增） |
|---|---|---|
| 开关 | 控制台「录制」页 → 采集对象：玩家 / 人机 / 全部 | 同左 |
| 频率 | 30 Hz | 10 Hz（`REC_BOT_HZ`） |
| 行标记 | `"k":"p"` | `"k":"b"` |
| 文件 | 同一个 jsonl（`vis\\rec\\<场景>__<时间>.jsonl`） | 同左 |
| 字段 | t,dt,x,y,z,g,vy,sp,ct | t,id,x,y,z,g,vy,spd,j,en,act,tgt |

- 实现：`editor.c` 的 `rec_bot_tick()`（放在 bot probe 工具函数之后），复用 `bot_type_get / pr_readable / type_name` 和 Bot 的字段偏移；
  `rec_start(path,hz,who)` 增加 `who`（1=玩家 2=人机 3=全部），控制台通过 navcmd `who=player|bots|all` 传进来。
- 只采人机时（who=2）不写玩家样本，但 header 照写（`rec_tick` 里补）。
- 控制台：`ucf_rec.parse_lines` 跳过 `k=="b"`（轨迹分析只用玩家），新增 `parse_bots()` 按 id 分组；
  录制中标题会多一段「· 人机 N 台」。
- id 是 Bot 指针（同一次录制内稳定，换图会变）。

## 2. drive 验证面板

- 位置：控制台「录制」页最下面，新卡片 **人机验证（drive）**。
- 内容：状态（开/关 + 最近 3 条 `drive:` 日志）、按钮 开启/关闭/刷新、卡点统计
  （最近日志里 `beh` 行同时满足 `spd=0.00` 与 `nearD>3` 的条数）。
- 开启/关闭发 `cmd=drive act=on|off`，插件侧 `ucf_drive_set()` 直接改运行期开关，**不用重启游戏**。
- drive 只对测试包（`g_nedBlank`）生效，正常地图一行不执行。

## 3. 开 / 关对比（看什么）

> 关着是「观察原版 AI」，开着是「强制压测你画的路线」。

| | 关（默认） | 开 |
|---|---|---|
| 谁的 AI 在动 | 游戏自己的 AI | 游戏 AI 没有 path 时，我们每秒补一条路径（Seeker.StartPath + Bot.OnPathComplete） |
| 空白图里的表现 | `path=0`、`spd=0`、`tgt=(0,0,0)`，人机原地站 | `path` 非空、`spd` 有值、沿点图走 |
| 能测出什么 | 只能看"游戏 AI 自己会不会走" | 能测"点图通不通"：断口处 spd 会掉回 0、nearD 变大 |
| 面板统计 | 卡点行数偏高（人没被赶着走） | 卡点行数只出现在真正走不通的地方 |
