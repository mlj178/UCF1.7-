# grow：真·新建节点（2026-11-19）

> 回答两个问题：① 能不能做到「纯空白 + 任意点数」的路点图；② 能不能完全不改游戏原版资源。
> 结论：都能。本文记录实现、依据和边界。

## 1. 结论

| 问题 | 回答 |
| --- | --- |
| 786 是路点上限吗 | 不是。它是**运输船场景里 tag=20022 的 WayPoint 物体数**（扫描时按物体建点） |
| blank 为什么只能借槽位 | 那是实现方式，不是引擎限制。blank = 原生点标死 + 借槽位改坐标 |
| 能新建任意数量节点吗 | 能。`PointGraph.AddNode` + 阻塞窗口，见下文 |
| 要改游戏资源吗 | 不要。只改运行时内存里的 `PointGraph` / `GraphNode` / `PathHandler` |

## 2. 依据（GameAssembly.dll 静态核对，base 0x10000000，x86 32-bit）

| 函数 | RVA | 结论 |
| --- | --- | --- |
| `PathHandler..ctor` | 0x5E6990 | `nodes = new PathNode[0]` —— **不是进图时按 786 分配** |
| `PathHandler.InitializeNode` | 0x5E67F0 | index ≥ len 时 `Max(len*2, 0x80)` 扩容 |
| `PathProcessor.InitializeNode` | 0x5E9440 | 先查 `queue.AllReceiversBlocked`，不满足就抛异常 |
| `PathProcessor.Lock(bool)` | 0x5E9660 | `queue.Block()` 后自旋等线程停，返回 lock id |
| `PathProcessor.Unlock(int)` | 0x5E9910 | 释放；锁表空了才真正 Unblock |
| `GraphNode..ctor` | 0x5248A0 | 建点时会 `AstarPath.InitializeNode` → 注册进每条 PathHandler |
| `PointGraph.AddNode(Int3)` | 0x5EE7D0 | 自己扩 `nodes` 数组（`Max(len*2, len+4)`）并追加 |
| `PointGraph.IsValidConnection` | 0x5EF4D0 | 两端必须 walkable，死点不会被自动连边连回来 |

**2026-11-16「append 后只会直走」的解释**：不是数组不能长，而是**建点没在阻塞窗口里**。
`PathProcessor.InitializeNode` 抛异常后，节点已经拿到 nodeIndex 却没进 handler，
寻路线程在 `PointNode.Open → GetPathNode(idx)` 越界，A* 打
"Unhandled exception during pathfinding. Terminating." 后停摆。

## 3. 实现（src/editor.c）

- 文件指令：`blank` + `grow`（grow 隐含 blank，且只对测试包生效）。
- `nav_apply_grow`：
  1. `PathProcessor.Lock(true)` —— 等到所有寻路线程停住；
  2. 原生点全部 `walkable=0` + 清连接（索引不动，安全）；
  3. 每个 `node add` 调 `PointGraph.AddNode`；
  4. `RebuildNodeLookup` + 按坐标套 `edge add`；
  5. 同 id `Unlock`。
- 日志：`naved: grow: N native disabled, M new nodes, K adds skipped, E edges (graph X -> Y nodes)`。
- 开关：`UCF_NAVGROW=0` 关掉（回落到 blank 的借槽位行为）。

## 5. 边界（step 1 故意不做）

| 边界 | 说明 | 后续 |
| --- | --- | --- |
| 节点只增不减 | 同一张图只新建一次；重套只补边 | 需要「重建」入口：先 `AstarPath.Scan` 还原原生图，再重放 |
| 不能 promote | grow 包只在 ④ 测试包 | 正式版链路要先改成「全量节点表」 |
| 坐标容差 0.35 m | 点位之间太近，边匹配会串 | 边缘情况再加 node id |
| 0 点图不行 | 暴风这类原生 0 点的图没有稳定指纹 | 先把指纹逻辑改成「场景名 + 0 点」 |
| 原版点仍在内存 | 786 个不可走节点还在，只是不参与 | 想彻底干净：Scan 前把 tag 物体 SetActive(false) |

## 10. B 方案：从原版点图播种（seed，2026-11-19）

> 「把原版路点复制到测试包，再在原版基础上新增」——现在是一条命令/一个选项。

### 10.1 原理

seed 包 = `blank` + `grow` + **原版全部点** + **原版全部边**（从 ① 备份版 `maps/*.json` 展开）：

```
# ucf-navedit v1 fp=n786-...
# seed: 原版点图全量重放
blank
grow
node add ...   × 786
edge add ...   × 1391
```

进图后插件先把 786 个原生点标死，再按这些行**新建** 786 个点（位置一模一样）+ 连边，
之后你继续加点就是「原版 + 新增」，不受原生点数限制。

### 10.2 用法

```
python core\navdata.py pack seed <包名> --level 1
```

或控制台：新建测试包 → 新建方式选 **复制原版路点（seed）**。

### 10.3 限制

- 只复制**点图**（PointGraph）；`Bot_JumpLink` / `PointNodeTagModifier` 是场景组件，
  不会跟着复制（它们的边可能已经在原生边里，但"跳跃动作"/tag 需要另做）。
- 包体积：运输船 ≈ 90 KB（2181 行），生化酒店 ≈ 400 KB（8647 行）。
- 只能对**有原生点的图**用；0 点图没有可复制的数据。

## 11. 0 点图现在能用 grow 了（2026-11-19）

暴风（level9，原生 0 点）以前两种都建不了，现在：

| 方式 | 0 点图 |
| --- | --- |
| blank（借槽位） | ❌ 没有槽位 |
| grow（真·新建） | ✅ 控制台/CLI 都可建，文件是 `n0-0000000000000000.txt` |
| seed（复制原版） | ❌ 没有原版点 |

插件侧改动：原生点数在"图稳定"那一刻记下来（`g_fpBaseN`，空图记 0），
0 节点图要求「文件里有 grow + 连续 5 帧都是 0」才放行，避免图还没扫出来就误建点；
底图快照允许 0 个点，所以「回正式版」能把 grow 出来的点全部收回。

控制台对 0 点图：选 blank/seed 会提示，只有 grow 能创建。

## 13. keep（保留原生）与寻路诊断（2026-11-20）

### 13.1 起因

seed 包（786 原生点标死 + 786 个新点，位置一模一样）进图后**人机全程不动**：

| 现场 | 原生图（11-19 12:50） | seed 包（11-20 12:30） |
| --- | --- | --- |
| 进图多久后 bot 有 path | **4 秒**（pts=50） | 30 秒一直 `path=00000000` |
| 最近节点 | 正常 | 正常（0.2~1.0 m） |
| 可走点数 | 786/786 | 786/1572 |

图是 1:1 的、最近节点找得到、Unity 和插件日志都没有 A\* 异常 —— 所以问题只可能是
「新节点游戏侧不认」或「我们动图的方式把寻路弄停了」。光靠猜会来回改，
所以加了 ① keep 模式（把两个变量拆开）② 一行诊断日志（直接看寻路有没有在跑）。

### 13.2 keep 是什么

| 指令 | 原生点 | 新增点 | 用途 |
| --- | --- | --- | --- |
| `blank` | 全部标死 | 借被标死的槽位 | 空白底图，点数 ≤ 原生 |
| `grow` | 全部标死 + 清边 | `AddNode` 真·新建 | 空白底图，点数不限 |
| `keep` | **一个都不动** | `AddNode` 真·新建 | 诊断：原版图照常能走，只追加新点 |

- 文件里写 `keep` 即隐含 grow（只新建、不借槽位），且**不会**再写 `blank`；
  插件里 `g_nedKeep` 与 `g_nedBlank` 互斥（解析完统一清掉 blank）。
- 只对测试包生效，和 blank/grow 同一条规矩（正式版永远不碰）。
- keep 包里运行中加点（Ctrl+Shift+N）走 `nav_add_live` → `AddNode`，
  不再借槽位（原生点全占着，本来也没槽位可借）。
- 日志：`naved: keep: 786 native kept, M new nodes, ...`。

### 13.3 诊断日志（nav_diag，1 s 一行）

只在「测试包 + blank/grow/keep」时输出，正式版一行都没有。字段：

```
diag: bots=8 path=0 ask=37 phSum=1024 phN=6 qHead=0 qBlk=0 qBr=0 qRcv=6 walk=786/1572 b0 near=1571/1 next=1571/1 p=0 blk=0.00
```

| 字段 | 含义 |
| --- | --- |
| `ask` | 1 s 内 `Bot.nextFindPathTime`(+0xB8) 变了几次 —— 只有 `Bot.PathSetting` 会写它 |
| `phSum` | 所有 `PathHandler.pathID`(+0x8) 之和，**每开始算一条路 +1** |
| `qHead` | 队列里有没有待算的 Path |
| `qBlk` | `ThreadControlQueue.blocked`(+0x18)：1 = 还停在 blocked（我们的 Lock 没解开） |
| `qBr` / `qRcv` | `blockedReceivers`(+0x1C) / `numReceivers`(+0x14) |
| `path` | 当前有 `Bot.path`(+0x80) 的 bot 数 |
| `b0 near/next` | 第一个 bot 的 `gNode_Nearset`/`gNode_Next` 的 nodeIndex 和是否可走 |

判读（这就是加日志的全部目的）：

| 现象 | 结论 |
| --- | --- |
| `ask` 涨、`phSum` 不动 | 人机请求了，但 path 没开始算 → `StartPath` 被拒 / 队列卡住 |
| `ask` 涨、`phSum` 涨、`path=0` | 算完了没装车 → 回调没触发 / `OnPathComplete` 丢弃 |
| `ask` 恒 0 | 上层 AI 压根没请求移动 → 和寻路无关，往行为/AI 侧查 |
| `qBlk=1` | 我们的 `Lock` 没解开，A\* 全停 —— 插件 bug |
| `b0 near=idx/0` | bot 缓存指向了一个**不可走**的节点（被标死的原生点） |

### 13.6 根因（2026-11-20 13:37 那次车测 + IDA 核对）

A/B/C 三组实测（同一份日志里的 `diag`）：

| 组 | walk | diag |
| --- | --- | --- |
| A keep + 0 点 | 786/786 | `path=8 bad=0 ask=8` `b0 near=577/1` |
| B keep + 786 点 | 1572/1572 | `path=8 bad=0 ask=8` `b0 near=446/1` |
| C seed（blank+grow） | 786/1572 | `path=0` **`b0 near=43/0 next=43/0`** |

C 组里人机缓存的「最近节点」是 **43 号原生点，而且不可走**。核对源码：

- `Bot.UpdateNearestGraphNode` @ `0xB33260` 调的是 `AstarPath.GetNearest(Vector3)`
  单参重载（反汇编里只压了一个 Vector3 + sret，没有 NNConstraint）；
- 这个重载等价 `GetNearest(pos, NNConstraint.None)`，**不检查可走性**。

所以：原生点只是「标死」，位置还在原地 → 人机脚下永远有一个死点 → 它把这个死点
当成起点/下一跳 → 永远不动。keep 组没有死点所以一切正常；blank 组里被禁用的原生点
同样留在原地，只是人机不一定正好站在它们附近，所以表现为「有时能走、有时站桩」。

**修法**：`grow` 禁用原生点时，把点搬到地下 5000 m（`y -= 5000`），索引和连接表都不动，
只是不再参与就近查询；`nav_base_restore` 会用快照把坐标改回去，`nav_fp` 也改成用快照
坐标算指纹。日志：`naved: grow: ... （死点已挪走）`，`diag` 里新增 `bad` = 最近节点
不可走的人机数（修好后应为 0）。

> blank 模式同样有这个问题（死点留在原地），已按 13.8 一起修。

### 13.8 同步修掉 blank（同一根因）

blank 模式里被禁用的原生点也留在原地，只是人机不一定正好站在旁边，所以表现为
"有时能走、有时站桩"。现在三处统一挪走死点（`NAV_DEAD_DY = 20000`）：

| 位置 | 场景 |
| --- | --- |
| `nav_apply_core` 第 3 步 | blank 底图 / `node del` 的增量改动 |
| `nav_apply_grow` | grow / seed 禁用原生点 |
| `nav_kill_node` | 游戏里就地删点（立即生效） |

配套：
- `nav_find_any` 对死点会按 "原高度 + 20000" 再匹配一次 → 撤销、重套、`node del` 仍找得到；
- `nav_undo` 撤销删点时把坐标写回原位；
- `nav_base_restore` 用快照恢复全部原生坐标（"回正式版"照旧）；
- `nav_fp` 用快照坐标算指纹，挪点不会改指纹；
- `freecam_center` 的 y 过滤（±5000）天然把死点排除在外。

> 结论：**seed 保留**。它现在是最省事的"原版底图"来源；grow 也才算真正可用。
> blank（借槽位）继续保留，但已不需要靠它绕开"点数上限"。

## 14. 收敛成两个建法：空白地图 / 原版基础 + 新增（2026-11-20 15:30）

### 14.1 为什么砍

新建弹窗一路加到 4 个选项（blank / grow / seed / keep），到 2026-11-20 用户已经
分不清该选哪个。回头看，实际需求只有两个：

| 需求 | 做法 |
| --- | --- |
| 新建一张空白图，从 0 画 | 原生点全禁 + `AddNode` 新建 = **grow** |
| 在原版路线基础上加点 | 原生点不动 + `AddNode` 新建 = **keep** |

另外两个都是历史中间产物：

- **blank（借槽位）**：grow 之前的实现方式，点数天花板 = 原生点数（运输船 786），
  没借到槽位的点等于不存在。grow 跑通后它只剩缺点。
- **seed（复制原版点）**：= blank + 把 786 个原生点整份复制一遍。keep 出现后它更笨：
  同样的效果多造 786 个重复节点。

### 14.2 现在的行为

| 建法 | 文件指令 | 原生点 | 新点 | 点数上限 |
| --- | --- | --- | --- | --- |
| 空白地图（新建节点） | `grow` | 全部禁用 + 挪到地下 20000 m | `PointGraph.AddNode` | 20000（NAV_MAXN） |
| 原版基础 + 新增 | `keep` | 一个都不动 | `PointGraph.AddNode` | 20000 |

控制台弹窗只剩这两个按钮；`navdata.py pack new --grow / --keep` 保持可用；
`--blank` 与 `pack seed` 已删除（argparse 直接报 unrecognized arguments / invalid choice）。

### 14.3 删了什么

- `src/editor.c`：删掉 blank 的借槽位应用块（`nav_apply_core` 里"整张图当已删 + 借槽位"那段）、
  `nav_needs_apply` 的 blank 专用复核块、保存时写 `blank` 行；`nav_revive_slot` 保留
  （正式版"删点再补点"仍靠它借空槽），grow / keep 链路不动。
- `core/navdata.py`：删掉 `pack seed` 子命令、`seed_pack_lines` / `native_map_doc`、`--blank`；
  `pack new --grow / --keep`、`pack list`、`pack promote` 拦截照旧。
- `console/控制台.pyw`：弹窗砍到两个选项、删掉 `seed_lines()` 与 `out["seed"]` / `summ["blank"]` 分支；
  两选项弹窗、清空包保留模式、启动条带 / 预检文案保留。
- `tests/test_blank_pack.py`：4 选项相关断言全部改写，另加"blank 借槽位路径不能回来"的反向断言。

### 14.4 兼容（重要）

旧文件里的 `blank` 行**照旧认**，按 grow 读：

```
# ucf-navedit v1 fp=...
blank        <- 旧写法，等价 grow（loader 里 nav_tok 同时认 grow / blank）
grow
node add ...
```

- 老的 seed 包（`blank + grow` + 786 点）行为不变：原生点禁用 + 新点新建；
- 老的 blank-only 包也能用，只是从"借槽位"变成"新建节点"，点数不再受 786 限制；
- 网页端 `navview.html` 仍然写 `blank`（它把空底图叫 blank），不用改也能被插件读；
- 游戏内保存一律写 `grow` / `keep`，不再写 `blank`；
- `UCF_NAVGROW=0`：借槽位没了，现在只剩「整包先不套用」（日志
  `grow/keep disabled by UCF_NAVGROW=0; pack not applied`），不会再退化成增量套用。
