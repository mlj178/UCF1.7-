# 玩家坐标记录：只在本次画方块（2026-11-21）

> 用户要求（原话）：黄色是玩家坐标记录的。我希望在游戏中展示这个黄色的方块，只在本次展示，
> 下一次就不展示了，以后也都不展示。也不需要连线。只在日志里面持久化坐标记录即可。
>
> 起因：空白地图（grow）测试包里，运输船地道的两个金色方块 + 一条金线被当成了「跳点」。
> 追下去发现那条金线是 `player_marks.txt` 里 11-20 记的两条旧坐标连成的折线，跟测试包无关。

## 1. 改之前的行为

- `pm_load()` 每次可视化重建都把 `player_marks.txt` **整份读进来**；
- `vis_draw()` 把 `g_pmP[]` 里所有历史点全画成 0.22 m 金色方块，再把相邻两条连成 0.06 m 金线
  （2026-11-20 的「顺序折线」）；
- 同一个文件是全局的：在运输船记的点，去生化酒店也照样画在同样坐标上。

结果就是：任何一张图、任何一个测试包，屏幕上都会一直有历史记录，换图/重开也还在，
而且「线 + 两端方块」看起来和 Bot_JumpLink 的跳点一模一样。

## 2. 现在的行为（src/editor.c）

| | 改前 | 改后 |
| --- | --- | --- |
| 画什么 | 文件里全部历史点 | 只有**本次（当前场景）**记下的点 `g_pmSesP[]` |
| 折线 | 有（按记录顺序连） | **删除**，只剩方块 |
| 换图 / 重开游戏 | 继续画 | 不再画（`vis_scene_reset()` 清 `g_pmSesN`） |
| player_marks.txt | 显示用 | **只当日志**（控制台列表 / 删除 / 补蹲守点照旧读它） |

要点：

- `pm_mark()` 追加文件成功后，把同一个坐标压进 `g_pmSesP[]`，日志多一行
  `pmark: session #N, drawn in this scene only (file keeps the log)`；
- `vis_draw()` 只遍历 `g_pmSesP[]`，`vis_pmark_line` 那段整段删掉；
- `g_pmP[] / g_pmN` 保留：控制台读文件、navfix「补蹲守点」还要用，只是不再画。

界面文字同步：`src/cfg.c` 的开关说明、控制台 `vis_player_marks` 的说明、
「玩家坐标记录」卡片说明和「全部删除」提示都改成「只显示本次、不连折线、文件当日志」。

- `navfix.c` 的「补蹲守点」仍读文件里**全部**历史坐标（含别的图记的），
  和这次「文件只是日志」不完全一致；要改成只认本次，等用户确认再动。
- 控制台「全部删除」清的是文件；已经画出来的方块要换图才会消失（提示文字已注明）。
