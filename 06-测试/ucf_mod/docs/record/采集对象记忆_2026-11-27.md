# 采集对象记忆：原始轨迹采集保留上一次的选择（2026-11-27）

> 用户要求：「原始轨迹采集，采集对象你做一个记忆，保留上一次的选择。」
> 位置：控制台「开发调试 → 开发者选项 → 原始轨迹采集」卡片。

## 1. 行为

| 场景 | 结果 |
| --- | --- |
| 第一次打开 / 配置里没有 `trace.who` | 默认「玩家」 |
| 选「人机」或「全部」 | **立刻**写进 `run\runtime\ucf_mod.json` 的 `trace.who`，卡片下面一行显示「上次的采集对象：…（记在 trace.who…）」 |
| 关掉控制台再打开 | 分段按钮和卡片提示都恢复到上次的选择，不再跳回「玩家」 |
| 点「开始采集」 | 以**界面当前选择**为准发 `cmd=trace ... who=player|bots|all`；若控件和内存状态不一致，先按控件落盘再开始 |
| 采集中 / 停止后 | 状态行分开报「玩家 N 样本 · 人机 M 条」，停止摘要带「采集对象：…」和人机条数，不再只有玩家一个数 |
| 旧配置写的是中文 / 1·2·3 / 大小写英文 | 照样认（`玩家` / `1` / `PLAYER` → `player`），认不出的值退回默认 |

「记住的」只是**下一次用什么**；已经开始的那一份日志不受改选影响（卡片会提示「下一份生效」）。

## 2. 存在哪、怎么走

```text
控制台（app/tabs/dev/tab.py）
  on_trace_who(显示名)
    -> ucf_trace.who_value()          # 玩家/人机/全部 -> player/bots/all
    -> cfg["trace"]["who"] = ...
    -> save_cfg(cfg)                  # run/runtime/ucf_mod.json（原子替换）
    -> 卡片提示「上次的采集对象：…」

重新打开控制台
  init_trace_state()
    -> trace["who"] = ucf_trace.who_value(trace.get("who"))   # 兼容旧写法
  build_trace_card()
    -> tr_who_seg.set(ucf_trace.who_label(self.trace["who"])) # 恢复选中
    -> refresh_trace_who_memo()                               # 恢复提示

开始采集
  trace_who_now() -> who -> ucf_navcmd.txt（cmd=trace, who=...）-> 插件 header
```

配置片段（`run\runtime\ucf_mod.json`）：

```json
"trace": { "hz": 60, "who": "all" }
```

- `hz` 和 `who` 都在这一节：档位本来就会记，这次把采集对象也做成同一份记忆。
- 插件只读配置；真正生效靠开始采集时那条命令里的 `who=`（`src/editor.c` 的 `ss_begin`）。
- 3 版日志 header 会写 `"who"`；旧 DLL 写的 2 版没有这个字段，但控制台照样显示/发送记忆值，不影响选。

### 日志里怎么区分玩家和人机

同一个 `ucf-trace/3` 文件里，**玩家样本和人机样本是两种行**，不是混在一起：

```text
header   {"kind":"trace","schema":"ucf-trace/3","who":"all",...}
玩家行   {"t":12.345,"dt":0.033,"x":..,"y":..,"z":..,"g":1,"vy":0.02,"sp":0,"ct":0}
人机行   {"t":12.4,"k":"b","id":"0a1b2c3d","x":..,"y":..,"z":..,"spd":6.2,
          "act":"Move|Chase","tgt":[..],"j":0,"en":0,...}
末行     {"end":1,"t":42.0,"n":1260,"bots":37,...}
```

- **人机行自带 `k:"b"`**；玩家行没有 `k`（键集合 = header 的 fields）。所以 `who=all` 的文件里，
  看 `k` 就能分开，`who=player` 的文件里不会有人机行。
- header 的 `who` 说明这一份选的是什么；末行 `bots` 是这一份累计的人机条数。
- 旧 DLL（2 版）不写 `who`、也没有人机行 —— 看起来「整份只有玩家」，不是读取器没区分，
  是插件没升级；重新编译后才是 3 版（见 §4）。

## 5. 边界

- 录制页也有「采集对象」，存的是 `rec.who`，和这里**各自记各自的**（两页用途不同：
  录制页看人机怎么走，采集页做批量取证）。录制页现在也会分开报玩家 / 人机计数，
  但保存只写玩家路点（见 `录制_人机区分_2026-11-27.md`）。
- 「记住」不等于「强制」：开始采集时仍以界面当前值为准；想换回玩家点一下即可。
- 人机样本固定 10 Hz，**不计入**玩家样本的「实测 Hz」；界面上的「人机 M 条」是行数，不是玩家样本数。
- 控制台自己写配置；插件不写 `ucf_mod.json`，所以不会被游戏进程覆盖。
- 如果 `ucf_mod.json` 被删掉或手改成非法值，下次打开按默认「玩家」，不会崩。
