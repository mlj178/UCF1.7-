# 录制也分玩家和人机（2026-11-27）

> 用户问：「那录制里面呢，你有区分吗」
> 位置：控制台「录制」页（`app/tabs/record/tab.py`）；文件格式和「原始轨迹采集」共用。

## 1. 结论

- **文件层面**：录制和采集共用 `ucf-trace/3` —— header 的 `who` 说明这一段选了什么，
  人机行带 `"k":"b"`，玩家行不带 k，end 行 `bots` 是累计人机条数。
- **旧录制日志**（15:27 之前、合并采样器之前）是另一套：schema 2、header 没有 `who`，
  玩家行带 `"k":"p"`、人机行带 `"k":"b"` —— 也能分，但和现在的新日志不是同一种写法。
- **控制台录制页以前其实没分**：只解析玩家样本；`self.rec_bots` 从来没有赋值，
  第一次成功识别时算「人机 N 台」就会 `AttributeError`（pythonw 看不见，表现为实时刷新停住）。
  现在补齐：初始化、解析、实时/复盘显示、只采人机的复盘都有。
- **人机样本不进草稿**：录制保存只写玩家的 `node add` / `edge add` / `jump add`；
  人机只做观察和日志。

## 2. 现在的行为

| 场景 | 结果 |
| --- | --- |
| 采集对象 = 玩家 | 和以前一样：玩家样本 → 识别 → 保存路点 |
| 采集对象 = 全部 | 实时显示「采集对象：全部 · 玩家 N 样本 · 人机 M 台 / K 条」；保存仍只用玩家 |
| 采集对象 = 人机 | 文件里有人机行、没有玩家样本；实时显示「人机 M 台 / K 条」，**不生成路点**；结束复盘会说明日志保留，回录前准备 |
| 录制中改采集对象 | 当前这一段仍按开始时的 `who`；改选只对下一段生效（状态条会提示） |
| 复盘页 | 摘要带「采集对象：…」；有人机时追加「人机 M 台 / K 条（只观察，不进草稿）」 |
| 旧录制日志 | `k:"p"` 玩家行 / `k:"b"` 人机行都还能读，不要求改文件 |

## 3. 控制台怎么分

```text
rec_start
  rec_who_active = rec["who"]           # 这一段固定用开始时的选择
  -> ucf_navcmd.txt（cmd=rec, who=...）

rec_poll（每 350 ms 重读文件）
  samples, events = ucf_rec.parse_rec(lines)   # 只玩家 -> 识别
  bots = ucf_rec.parse_bots(lines)             # 只在 who != player 时解析
  samples 有 -> rec_update_live()              # 玩家 N / 人机 M 台 K 条
  samples 空、bots 有 -> rec_update_bots_only()# 只采人机，不报错

rec_review_from_file（结束复盘）
  玩家样本 -> analyse -> 复盘页（摘要带人机计数）
  只有人机 -> 回录前准备 + 说明「没有玩家样本，不能生成路点；日志保留」
```

- `rec_bot_stats()` -> `(台数, 条数, 最后时间)`，台数 = 不同 `id` 数，条数 = 行数。
- `rec_bots` 的形状是 `{id: [人机样本行]}`，由 `ucf_rec.parse_bots()` 从 `k:"b"` 行分组得到。
- 人机 10 Hz，不参与玩家样本数 / 实测 Hz。

## 4. 代码改动

- `app/tabs/record/tab.py`：
  - `build_record_tab` 初始化 `rec_bots = {}`、`rec_who_active`；
  - `rec_poll` 解析人机行并更新；只采人机走 `rec_update_bots_only()`；
  - `rec_update_live` 显示「采集对象 / 玩家 N / 人机 M 台 K 条」，并修掉原来
    `self.rec_bots` 未初始化导致的 AttributeError；
  - `rec_review_from_file` 解析人机、只人机时给出人话说明而不是「复盘失败」；
  - `rec_fill_done` 摘要带人机计数；
  - `rec_start` 发送 `who=self.rec_who_active`，状态条显示采集对象；
  - `on_rec_who` / 分段按钮改用 `ucf_trace.who_value / who_label`（认中文 / 1·2·3）。
- `app/tests/test_ucf_rec.py`：新增 `check_bots()` —— `parse_bots` 分组 / `parse_rec` 不混人机，
  并静态钉住 `rec_bots` 初始化、`parse_bots(lines)`、`who=self.rec_who_active`、人机计数文案。

## 6. 边界

- **人机样本只用于观察**：不进 `node / edge / jump`，不改变草稿；要人机行为分析直接读 jsonl。
- 只选「人机」时录制页不会生成路点；结束复盘会说明原因，原始日志仍在 `data/maps/_inbox/rec/`。
- 新格式玩家行不带 k（和采集完全同一行）；旧录制日志的 `k:"p"` 仍可读。
  如果希望**每一行都显式带 `p` / `b`**，那是格式升级（录制 / 采集 / 读取器 / 报告一起改），当前没做。
- 录音中改「采集对象」只影响下一段；当前段以开始时的 `who` 为准。
