# 录制 v2：按「人机真能跳的窗口」落点（2026-11-24）

> 用户原话：录制只用来记**人机行动点位**，主要是**跳跃点、跳高点**；
> 「跳高、跳箱子」用录制一直弄不好，所以先采自己的运动数据找常规值，再改录制。
> 蹲点、传送断段两个开关没用，删掉。

## 1. 从真实数据量出来的常规值（2026-11-24 两份 trace，32 次跳）

| 项 | 常规值 | 说明 |
| --- | --- | --- |
| 起跳竖直速度 v0 | **9.5 ~ 10.5 m/s** | 和游戏 `JumpPower = 10.5` 完全对上 |
| **跳高 rise** | **1.9 m**（实测 1.2 ~ 2.3） | 由 v0 和重力决定，基本是常量 |
| 跳上高台 mount | 水平 1.3 m / 高差 **+1.8 ~ +2.0 m** / 3D 中位 **2.34 m** / 滞空 0.34 s | 你 32 次跳里 28 次是这种 |
| 跨缺口 gap | 3D 6.1 ~ 6.6 m | 人机跳链最长 3.0 m，这种做不了 |
| 跳下 down | 落差 4 ~ 9 m | 走单向边，不建跳链 |

**人机跳链的硬窗口（游戏规则）**：两端 1 m 内吸附到路点、两点之间要有 A→B 边、
**3D 长度 1.5 ~ 3.0 m**。你这 32 跳里只有 **16 跳**落在窗口内（全是跳上高台）——
所以以前"录了跳点人机不跳"，一大半原因是**录出来的跳链根本不在游戏能用范围内**。

## 2. 录制侧改了什么

### 2.1 数据格式（和轨迹采集同一套 ucf-trace/2）

    header {"kind":"rec","schema":"ucf-trace/2","hz":30,"t0":"...","src":"player",
            "fields":["t","dt","x","y","z","g","vy","sp","ct"]}
    样本   {"t":12.345,"dt":0.033,"x":-52.80,"y":-16.59,"z":3.63,
            "g":1,"vy":0.02,"sp":0,"ct":0}
    跳事件 {"t":12.9,"ev":"jump","a":[起跳点],"b":[落点],"h":..,"rise":..,
            "air":..,"v0":..,"run":..,"kind":"mount"}

- 坐标是**玩家脚底**（不再是相机 + 向下射线），采样 **20 Hz → 30 Hz**；
- 起跳/落地由插件按 `vy > 6 m/s` + 游戏 `isGrounded` 结算，
  复盘不再靠"离地 0.3 m"去猜（这套在跳箱子时最容易错）。

### 2.2 自动识别的开关（删了两个）

| 开关 | 现在 |
| --- | --- |
| 自动识别跳跃 / 跳上高台 | 保留：**3D 1.5~3.0 m 才建跳链**，超出的只写进"问题"里，不落盘 |
| 自动识别落下 | 保留：down 事件落差 ≥ 2 m → 单向边 |
| 自动识别岔路 | 保留 |
| 静止提示 | 保留（只提示，不加节点） |
| ~~记录蹲点位置~~ | **删除**（用户要求：没用） |
| ~~传送断段~~ | **删除**（用户要求：没用）；只把单帧位移 > 15 m 的那条边跳过 |

### 2.3 落地规则

| 事件 | 落点 |
| --- | --- |
| mount（跳上高台/箱子）3D 1.5~3.0 | `jump add A B` + `edge add A B`（A=起跳点，B=台面上的落点） |
| mount / gap 超出窗口 | **不建链**，复盘里写「第 x.x s 那一跳太长/太短，3D x.xx m —— 人机用不了」 |
| down | 只 `edge add A B`（单向），落差 ≥ 6 m 标"可能摔伤" |
| 走路 | 节点 + 双向边（4 m 默认间距；转角强制补点） |

另外加了一条稳健处理：相机兜底模式下射线偶尔打空（站在台阶边/斜坡上），
**不在跳事件时间窗内、丢地 < 0.25 s** 的片段会补回走路，避免把一条路切成好几段。

## 3. 怎么用（录制页）

1. 关游戏 → 控制台启动 → 「录制」页：选图/包 → 开始录制；
2. 游戏里照目标走、该跳就跳（空格）；跳上箱子也算，插件会记成 mount；
3. 结束 → 复盘会显示：`N 节点 / M 边 · 跳链 x（没用 y）/ 落 z / 岔 w`；
   "没用 y" 就是超出 3D 1.5~3.0、**没有落盘**的跳；
4. 看「问题」一栏，确认没有"这一跳人机用不了"再保存；
5. 保存只增不覆盖，落进包 txt；进图套包时插件会建 `Bot_JumpLink`。

## 4.1 当晚追加修复（2026-11-24 21:5x）

用户实测反馈「人机在跳点来回转头」「地道口落地没连线」，查出三个问题：

1. **重采样累加写错**：每个样本按"到上一个节点"的距离累加，
   实际节点间距只有 ~1 m（运输船 271.7 m 生成 287 个点）。修好后同样数据 **74 个点**。
2. **同层近点抢吸附**：落点与下一跳起跳点只隔 0.56~0.60 m，
   游戏按最近点吸附（半径 1 m）→ 路径点与跳链起点可能不是同一个，人机原地打转。
   现在自动合并同层 ≤1.05 m 的节点（`MERGE_NEAR`），跳链端点一起改写。
3. **高处落地没连线**：走下落差不产生事件；按空格跳下的 down 事件也没写边。
   现在补了「离地 → 落到更低处」的识别，保存成**单向边**（不是跳链）。

运输船包已按新逻辑重生成（旧文件备份为 `*.txt.bak_20261124_215928`）：
**309 点 / 667 边行 / 4 跳** → **71 点 / 145 边行 / 4 跳 / 1 条落地单向边**，
连通分量从 21 个变 **1 个**，同层 1 m 内的节点对 **0 对**。

## 5. 已知边界

- 如果日志 header 是 `"src":"camera"`（玩家对象没抓到），坐标是"相机 − 眼高"估的：
  跳高/高差这类差值不受影响，但**绝对高度**有常数偏差、`g` 会抖（已用 0.25 s 补齐兜住）。
  抓取失败的原因还没查（下次可以单独修）。
- 跳链窗口 3.0 m 是游戏原生上限；真实上限（尤其配 `needSpeed` 之后）还没实测。
  要做的话得在人机上做一组 3.0 / 4.5 m 的对照。
