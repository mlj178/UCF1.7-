# 守卫区的绿框为什么「不是立刻出现」（根因 + 修复）_2026-11-26

## 用户提问（原话）

> 你看一下我刚才的编辑的地图，为什么在添加守卫区，并不会立即显示绿色的方框，
> 一个会立即显示，一个不会。另外就是守卫区显示绿色方框，是不是必须里面有守卫点才会显示呢？
> 告诉我结论，为什么不会立即显示，反馈速度太慢了，还是什么原因。

## 结论（三句话）

1. **绿框不是守卫区自己画的**，是可视化层从游戏的 `Bot_NanoGuardArea.SpareAreaList` 里读出来画的
   （`read_nano` → `K_NAREA` → `draw_vf(K_NAREA, 2, 1, 2.4f, 1.7f, 2.4f)`）。
2. **新建的守卫区是「故意不激活」的**：要等第一个守卫点挂上才 `SetActive(1)`，激活时游戏自己
   的 Awake 才会把这个区登记进 `SpareAreaList`。没登记 = 读不到 = 没有绿框。
   **所以「必须里面有守卫点才有绿框」是对的，不是显示 bug。**
3. **还有一个时间闸门**：进图后前 `VIS_SCENE_WAIT`(=90) 个心跳（心跳 4 Hz，**≈22 秒**）整层可视化
   重建是推迟的（那段时间读游戏组件表会撞上一张图正在销毁的对象，2026-11-17 的闪退就是这么来的）。
   这段时间里新建的东西**只有标记球是立刻可见的**（球是我们自己建的 GameObject），
   节点方块 / 连线 / 绿框都要等这一层重建。**不是逐帧慢，是这道闸门。**

两个事实一眼能对上：

- **10 个区里只有 6 个进了 `SpareAreaList`**（`area=6`），其余 4 个没挂守卫点 → 没有绿框 → 「一个会显示、一个不会」；
- **19:12:00~19:12:14 之间没有任何 `vis:` 行**，因为 `g_sceneAge` 还没到 90：这段时间你建了两个区、
  按了四五次，画面上除了标记球什么都没变 → 你连按了 4 次「新建守卫区」，在 `-61.x` 那一点叠了
  aid=7/8/9 三个区（互相只差半米）。

另外顺带发现一个真实数据问题（这次不擅自改归属）：**「加守卫点」只认「当前守卫区」，不看距离**。
aid=6 的区中心在 `z=-6.76`，而挂上去的点在 `z=-12.41`，相差 **5.65 m**，早出了 3 m 的框。

## 改动

| 位置 | 改动 |
| --- | --- |
| `pend_area_tick()`（`editor_tick` 每 tick 调） | 新增「待激活守卫区」金色线框：只用**我们自己的标记表** + `bs_wbox` 建网格，不读任何游戏组件表，因此**不受 22 秒闸门影响**；尺寸和绿框一致（半尺寸 2.4/1.7/2.4），颜色槽 14（金）vs 绿框槽 2 |
| 何时消失 | 挂上第一个守卫点（`g_areaLive` 置 1）→ 不再属于「待激活」，金框自动收起，换成 `read_nano` 画的绿框 |
| 开关 | 跟 `g_visOn`（Ctrl+V）、`g_visNano`（守卫区图层）、`g_collectOnly` 一致 |
| 不污染导出 | 不进 `g_vf`，导出 JSON 里的 `nano_area` 仍然只有 `SpareAreaList` 里那些 |
| 菜单文字 | 「建好后场上立刻出现金色线框；挂上第一个守卫点才变绿框（激活，人机才认）」；加点页写明「挂上这个点后，所在守卫区被激活：金色线框 → 绿框」 |
| 加点页距离提示 | 显示准星落点到当前区中心的距离；> 2 m 时直说「已超出 3 m 框（半宽 1.5 m）；点仍会挂到这个区」——只提示，不擅自改归属 |
| 日志格式检查 | `elog` 加 `__attribute__((format(printf,1,2)))` |
| 顺带修的真 bug | `vis:` 汇总行的 `guard=%d` 在删旧守卫后没删干净：参数整体错位，`badtr` 打出 `1691022496` 这种垃圾值、`missing` 把**野指针**交给 `%s` 打印（随时可能崩）。删掉该字段，格式符与参数数量恢复相等（13/13） |

## 边界

- 金色线框**不是**「守卫区已可用」的信号：它恰恰表示「还没挂守卫点，人机不会用这个区」。
- 绿框出现的时机没变（`read_nano` 读 `SpareAreaList`，仍受进图 22 秒闸门约束）；本次只是**补上了这段空窗期的可见性**。
- 「加守卫点」的归属规则在当天晚些时候改掉了：现在按**准星落点**归区（`area_at`），见
  `docs/record/守卫点按落点归区_2026-11-26.md`。
- 金框最多同时画 8 个（`PEND_MAXA`），超过只显示前 8 个并写一行日志。

## 进游戏核验

1. 重进图，**20 秒内**就放一个「新建守卫区」：应立刻出现**金色线框**（蓝球同时在）；
2. 这时不要加点，转视角看：金框应该一直跟着那个点（它画的是解算出的落点，不是跟着准星）；
3. 按「加守卫点」挂一个点：菜单显示距离；距离 > 2 m 会警告；挂完后金框消失，等这层重建后出现**绿框**；
4. 再建一个区但**不加点**：金框在，绿框不在 —— 这就是「必须里面有守卫点」的证据；
5. Ctrl+V 关可视化：金框和绿框都收起；打开恢复；
6. 看日志应有 `area: 待激活守卫区 N 个（金色线框…）`，且 `vis:` 行不再出现垃圾 `badtr`。
