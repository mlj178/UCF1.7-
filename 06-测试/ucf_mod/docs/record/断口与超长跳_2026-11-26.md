# 断口统计 + 超长跳开关（录制算法）2026-11-26

> 起因：09:07 重录风暴，4 次跳只建了 2 条，路线断成 3 截。用户问「是不是采样频率/距离的问题」。
> 结论：**不是采样的问题**。跳点都被捕到了（起跳/落点都在），是两跳 3D 长度超过 3.0 m，被窗口挡掉，
> 而工具只在 issues 里写一句、汇总行不显示，看起来就像「没捕捉到」。

## 2. 改动

1. **断口统计**：`analyse()` 新增 `gaps`（相邻两段路之间没有跳链/落地边时记一条），
   - 汇总行加 `· 断口 N`；
   - issues 写「路线在 N 处断开（5.3 m / 3.9 m）：要么把跳分成两跳，要么打开『超长跳也建链』实测」。
2. **超长跳开关**：`SWITCHES` 加 `long_jump`（默认关）。打开后窗口从 1.5~3.0 放到 1.5~**5.0**，
   3~5 m 的跳也生成 `jump add`，给实测用；`_merge_nodes` 的跳点保护也跟着用这个上限。
3. 修了开关默认值：`SW_DEFAULT` 是「全部 True」，新开关必须显式设成 False，否则会默认建超长链。

## 4. 采样策略的结论（回答「按频率还是按距离」）

- **走路**：按**距离**（现在 1.5 m）。按频率会在站立/慢走时堆点、快跑时漏拐角，节点密度还跟帧率走。
- **跳跃**：按**事件**（有跳就记起跳/落点）。频率和距离都抓不到「哪一帧离地、落在哪」，事件是唯一的源头。
- 所以「老是遗漏」不是采样策略问题，是**建链窗口**问题：长度超过 3.0 m 的跳默认不建链。

## 7. 2026-11-26 10:25 复测：两处断开 + 一个「普通点」

那次录制 4 跳：5.22 / 2.74 / 2.60 / 5.08 m。默认只建 2 条，留下 2 处断口（7.7 m / 5.1 m），
落地后立刻停止录制，还多出 1 个「没有边的普通点」。三个现象是同一件事：**两跳超过 3.0 m 被窗口挡掉**。

这次补的三处：

1. **断口按链判定**：连续两跳（上一跳落点就是下一跳起点）时，单条 link 盖不住整段，
   以前会误报断口；现在沿「跳链/落地边」最多走 8 步判断连通。
2. **孤立点直接丢**：录完一跳马上停、落地只有 1 个样本时会留下 1 节点 0 边，
   这种点写进包里也没用，现在从路点里去掉，issues 里记一句「丢掉 N 个孤立点」。
3. **超长跳上限 5.0 → 6.0**，勾上开关后 5.2 m 的跳也能建链（实测用）。

复测同一份录像：默认 2 链 / 2 断口 / 0 孤儿；打开「超长跳也建链」→ **4 链 / 0 断口**。
