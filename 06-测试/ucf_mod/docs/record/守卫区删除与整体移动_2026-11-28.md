## 1. 为什么之前“缺”

- 删除的底层其实早就够用：marker_unregister() 对 MT_ENTRY / MT_ESCAPE 会从
  area.entrancePos / escapePos 里摘掉并刷新守卫点方向；delete_nearest_of() 也支持按类型。
  但菜单没有入口，只能走「5 删除点位 → 任意点位」盲删（容易顺手删掉守卫点/蹲守点），或删整个区连带。
- 全局没有任何“区 + 子项一起平移”的代码；撤销记录也只有加/删，没有移动。

## 3. 删除入口 / 删除逃跑点（严格准星）

用户确认：只认准星 0.6 m 内，否则拒绝，不做老的 12 m 兜底。

- 新函数 delete_marker_strict(want)（src/editor.c，delete_nearest_of 之后）：
  - 射线垂直距离 <= 0.6 m 才算对准；
  - 射线没压中时，退到准星落点 <= 2.5 m（bestHit <= 6.25f）；
  - 再没有就红字拒绝：准星没对准 xxx：靠近到 0.6 m 内再按 5；
  - 选中后才 ed_step() + del_index(target)（选不中不占撤销步号）。
- 菜单第 5/6 项调用它；停在这两项时按 Delete 也走同一条（不会落到“任意最近”的旧逻辑）。
- 真正删除仍由 marker_unregister() 完成：从 entrancePos@0x0C / escapePos@0x1C 摘掉，
  入口删完立刻 refresh_area_guard_dirs() 重算已有守卫点的 zoomPos；删最后一个点写空数组，不写 null。
- 菜单里写清图里现有几个、只从 area.entrancePos / escapePos 摘一个、不连带守卫点/区、可撤销。

## 4. 整体移动守卫区（两步确认）

  第 1 次按 5：准星对着区的 3 m 框 → 选中
    → 菜单/日志：已选守卫区 #idx（aid）· 守卫点 N · 入口 E · 逃跑点 S
    → 蓝框跟到准星 = 预览新区中心
  走到新位置、准星瞄地面
  第 2 次按 5：确认移动
  0 / Esc：取消（只清待移动，不离开页面）
  8/2 / 数字键切走：自动取消

实现：area_move_whole(ai, to)（src/editor.c，refresh_area_guard_dirs 之后）：

1. 先移区本体：g_mk[ai].p = to + 区 GameObject 的 SetPosition(to)（BoxCollider 跟 transform 走）；
2. 再遍历 parent == ai 的子标记（守卫点 / 入口 / 逃跑点）：g_mk[].p += delta、
   子物体 SetPosition(新位置)、可视化球 mk_vis_move() 单独挪（球是根对象，不跟区 transform）；
3. vec3_arr_shift(areaComp, 0x0C/0x1C, delta)：entrancePos / escapePos 是世界坐标数组，
   游戏真正读它，必须一起平移；
4. refresh_area_guard_dirs(ai)：入口挪了，按新入口重刷每个守卫点的 zoomPos（方向不变）；
5. g_visDirty = 1，菜单/日志报 Δ；原地不动（Δ<1 mm）直接拒绝，不产生空动作。

顺序很重要：守卫点 GameObject 是区的子节点；如果先把子物体挪到新位置、再挪区 transform，
子物体会被二次位移。所以固定“先区、后子”。

只处理 g_mk 里的 MT_AREA（插件自己建的区）。原生场景的区 / 入口 / 逃跑点保持只读，
和“原生守卫点不能改方向”同一条边界。

## 5. 撤销 / 恢复

- 新增 #define MKE_MOVE 3，复用 MKE 现有的 p / b：
  p = 旧中心、b = 新中心、aid 用来找区（下标会随删除左移，不能存下标）。
- mke_note_area_move(ai, &old, &new) 在移动成功后记一笔；一次移动 = 一步撤销。
- mke_undo_one：area_marker_of_aid(aid) → area_move_whole(ai, &e->p)；
  mke_redo_one：同样但移到 e->b。撤销栈文字：「移动 守卫区 (x y z) -> (x y z)」。
- 区如果已经被删：撤销这条移动只提示“没有变化”，不崩。

## 6. 落盘

不新增 markers.txt 行类型。area / nanopos / entrance / escape 行本来就写坐标，
移动后 Ctrl+S 直接写新坐标；旧版插件读新文件仍兼容（只是菜单少三项）。

## 9. 已知边界（真机注意）

- 移动不会让已经出发/已站位的人机瞬移；它们下一次取点才去新位置（和改点图一样）。
- 只移动插件自己建的区；原生区不动。
- 删除入口/逃跑点只删插件建的（黄球/白球）；原生入口没有球、也不可删。
- 移动后如果又把区删了，撤销这条移动只会提示“没有变化”。
