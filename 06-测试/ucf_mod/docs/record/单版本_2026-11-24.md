# 单草稿 / 单成品：一张图一条线（2026-11-24）

## 一、需求

用户判断：同一张图同时有 4 个测试包、成品又有多个版本，两个下拉各自独立，
用的人不知道“这次启动到底读的是哪一份”。要求：

- **一张图一个草稿、一份成品**，从编辑 → 发布 → 成品 → 部署不再出现“选包/选版本”；
- 逻辑上一张图只有一个当前版本；物理上保留“草稿”和“成品”两份文件，
  是为了游戏内编辑不直接改线上数据；
- 创建草稿的名称带创建日期（如 `TransportShip_20261124`）；
- 旧数据不迁移、不备份，全部删除，重新手动做；
- 成品保留发布前快照（每图最近 5 份），界面上不出现；
- 部署保持“只装插件，数据读工程端”，不再复制一份地图数据。

## 二、目录

```text
data/navdata/dev/
├─ packs/                         草稿：一张图一个，可写
│  └─ 01_TransportShip运输船/
│     ├─ manifest.json            {name,level,label,fp,mode,created,...}
│     ├─ n786-....txt
│     └─ nogen.txt
├─ final/                         成品：一张图一份，平铺，只读
│  ├─ n786-....txt
│  ├─ _index.json                 {format:"ucf-final-single", maps:{fp:{...}}}
│  ├─ _publish.log
│  └─ nogen.txt
├─ archive/final_prev/<指纹>/     发布前旧成品（最近 5 份，界面不出现）
└─ vis/                          导出收件箱
```

不再有：

- `packs/<图>/<包名>/` 第二层；
- `final/<版本>/`、`final/_current.txt`、版本台账的 `versions` 数组；
- “只对这张图生效”勾选（草稿天生只对一张图生效）。

## 三、启动

| 档 | 环境变量 | 插件读 |
| --- | --- | --- |
| 编辑中 | `UCF_PACK_DIR=<dev>\packs` + `UCF_PACK=<地图文件夹>` + `UCF_FP=<指纹>` | `packs<图><指纹>.txt` |
| 成品 | `UCF_PACK_DIR=<dev>` + `UCF_PACK=final` + `UCF_NAV_READONLY=1` | `final<指纹>.txt` |
| 原版 | 总开关关 | 插件待机 |

C 侧不用改：`pack_ok_id` 本来就允许一层地图目录，中文目录按 GBK 传。
HUD 仍写“测试包 <图名>”，只影响文案。

## 四、发布

1. 覆盖 `final<指纹>.txt`（原子替换）；
2. 覆盖前把旧成品复制到 `archive\final_prev<指纹><时间>.txt`，每图只留最近 5 份；
3. 成品文件设只读；
4. 更新 `final\_index.json` + 追加 `final\_publish.log`。

界面只有一个「发布这张图到成品」；成品里已有同图时提示会覆盖，没有“新建一版/更新当前版/版本名/备注”。

## 五、界面

- 「人机路点」顶部：启动档 + 当前地图（编辑/成品共用）；
- 编辑中页：本图草稿状态（名称/建法/点数/创建时间）+ 开始编辑 / 打开草稿目录 / 重置本图草稿；
  没有草稿时，创建弹窗三选一：从成品继续改（默认）/ 空白地图 / 原版基础 + 新增；
- 成品页：本图已发布状态 + 已发布地图列表 + 打开成品目录 / 撤销这张图的发布；
- 「草稿 ↔ 成品」表：每张图一行，sha256 相同 = 同一个文件；
- 录制页去掉“开发包”下拉，直接用当前地图的草稿；
- 启动条/按钮不再显示版本名，只显示“成品（N 张图）”或“编辑中 <图名>”。

## 六、清理

按用户要求删除（不迁移、不备份）：

- `dev/packs` 下 4 个旧测试包 + 空地图目录；
- `dev/final` 的旧台账/只读文件；
- `dev/archive`、`dev/vis`、`dev/nav`；
- 各图 `导出\` 里的历史导出；
- `data/navdata/_before_*.zip`、`_migrate_mapfolders_*`、`_logs/navdata.log`。

保留：① `navdata\native` 原生备份、每张图的 `map.json` / `navmesh.bin`、`00_公共` 的 names/index。

## 七、代码

- `app/core/navdata.py`：新增 `final_store_*`（平铺成品、发布、快照、撤销）；
  `pack new` 改为一张图一个草稿；`pack promote` 改为覆盖同图；`final list/rm` 改为按图；
  删除版本新增/改名/选版路径（旧函数保留未调用，后续可清）。
- `app/ui/packs.py`：去掉包/版本下拉；`prepare_final_root()`；单草稿/单成品 UI。
- `app/tabs/waypoint.py`：共用地图选择；本图草稿/成品两页。
- `app/控制台.pyw`：`game_env()` 改 `UCF_PACK=final` + `UCF_PACK_DIR=dev`；启动条/按钮/预检。
- `app/tabs/record/tab.py`、`data.py`、`dev/tab.py`：跟随单草稿。
- `app/workbench/navserver.py` + web：成品读平铺 `final\`；编辑中按图自动取唯一草稿；隐藏“选包”下拉。
- 测试：`test_blank_pack.py`、`test_mapfolders.py` 更新断言；其余静态自检保持通过。

## 八、验收

- `python app/tests/test_*.py` 全过；
- `navdata.py pack new --level 1 --grow` → `packs/01_TransportShip运输船/`；
- `navdata.py pack promote 01_TransportShip运输船` → `final/n786-....txt` 只读、sha 与草稿一致；
- 再发一次 → `archive/final_prev/n786-.../时间.txt` 出现，成品仍只有一份；
- 控制台构建：草稿面板、成品面板、按钮文案与实际文件一致；
- 工作台 `/api/workbench`：`packs` 一张图一条、`final.maps` 等于成品文件数、无“选包”下拉。
