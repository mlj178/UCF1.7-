# 路点菜单选点：以准星为准（不再「落点 3 m 内」）_2026-11-26

## 用户报障（原话）

> 另外就是我路点菜单中，连接路径，选取路点的时候，预选的时候，起始路点，终点，
> 并不是根据屏幕中心的准星来的，是有偏差的，我的意思是我的准星和路点之间有偏差
> 才能选上，而不是根据准星来选取的。你懂我的意思吗？我希望是以准星的位置为选择的。

## 结论先说

**准星压着方块选不中，是因为旧判据根本没用准星，用的是「准星射线打中的那层表面」。**

旧流程：`cam_point()` 沿相机 `transform.forward` 打一条射线，取**第一个撞到的碰撞体**当落点，
再找「落点 3 m 内最近的可走路点」。这条路只有在「路点正好长在那一层表面上」时才等价于
「准星压在方块上」；方块在半空、台阶边缘、隔一层楼、半嵌在墙里的时候，落点和方块差几米，
就只能把准星偏过去凑那个「3 m 球」。

现在：**按键选点和虚线框预览都改成「准星射线」判据** —— 取屏幕中心那条射线
（`Camera.ScreenPointToRay(屏幕中心)`），算每颗路点到这条射线的**垂直距离**，谁最近选谁。

`no node near crosshair` 只在**准星射线打到了地面/墙、但没有可走路点在落点 3 m 内**时才会打
（打不到地面时打的是 `no ground under crosshair`）。也就是说：射线没打空，只是落点离方块太远。
旧代码里这条扣了 6 次，和用户描述的「准星和路点之间有偏差才能选上」完全对得上。

### 2) 旧判据为什么会漏

```
     相机 ●
          │＼
          │  ＼ 准星射线（穿过方块）
          │    ＼
    ┌─────┼──────┼────┐  ← 方块正下方的表面（台阶 / 天花板 / 箱顶）
    │     │      ▼    │
    │     │     落点 ★ │  ← 射线穿过方块后继续飞，撞在更远的一层上
    └─────┴───────────┘
```

方块（`vis_nodes` 的立方体，半边长 0.14 m）是**画在节点坐标上的**，节点不一定贴在射线打中的
那层表面上：

| 场景 | 落点在哪 | 旧判据 |
| --- | --- | --- |
| 跳点 / 半空的点 | 方块正下方很低的地面，或根本没有 | 落点离方块 > 3 m |
| 站在台阶上往下看边缘的点 | 射线越过边缘打到下面一层，落点在方块后面几米 | 漏 |
| 隔一层楼：上面一层的点 | 落点在这层的地面（方块在上一层） | 漏 |
| 方块半嵌在墙里 / 贴着栏杆 | 射线先打到墙 | 漏（或选到墙后更远的点） |

### 3) 还有一条：屏幕中心射线 ≠ `transform.forward`

`forward` 只有在相机 projection 矩阵严格居中时才等于屏幕中心那条线。这游戏是 Cinemachine
相机（`Cinemachine3rdPersonAim` / `CinemachineCameraOffset` 都在 dump 里），投影矩阵是运行时
算的，完全可能带一点位移。**旧代码只认 `forward`，等于拿一条「屏幕中心偏一点」的线当准星使。**
所以这次两条一起修，并且把「屏幕中心射线和 forward 差多少度」写进日志 —— 下次日志能直接看出
到底是哪一条在偏。

## 行为对照

| 动作 | 以前 | 现在 |
| --- | --- | --- |
| 准星压在方块正中间 | 落点不在方块那层就选不中（日志里 6 连败） | 一定选中（偏 0.00 m） |
| 准星压在方块边缘 | 时灵时不灵 | 容差 ≈ 方块半径的 3 倍，边缘也稳 |
| 准星明显偏开（比如 20 m 外偏 1.5 m） | 偶尔被「3 m 球」误抓 | 不选，画灰框 |
| 两颗点一前一后叠在准星上 | 先找到谁算谁 | 取近的那颗（看得见的那颗） |
| 预览 | 绿了按下去可能不选中（规则不同） | 绿 = 一定选中，灰 = 一定拒绝 |
| 选点日志 | `no node near crosshair`（不说差多少） | `准星没压住路点（最近 #12 偏 2.31 m；屏幕中心射线和 forward 差 0.42°）` |

## 容差怎么定的

`tol = 0.45 m + 2% × 距离`（上限 3 m）。方块半边长 0.14 m，所以「垂直距离」天然就是
**方块半径的倍数**：近处（3~10 m）大约是方块周围 3~4 个方块半径；远处的方块在屏幕上
只剩几像素，所以再按 2% 放宽一点，保证 60 m 外还有二十几像素的可瞄范围。

| 距离 | 容差 | ≈ 方块半径 | 屏幕上（1080p / 60° FOV） |
| --- | --- | --- | --- |
| 3 m | 0.51 m | 3.6 倍 | 159 px |
| 10 m | 0.65 m | 4.6 倍 | 61 px |
| 30 m | 1.05 m | 7.5 倍 | 33 px |
| 60 m | 1.65 m | 11.8 倍 | 26 px |

## 边界 / 取舍

- **准星没压住就不选**（这是用户要的语义）。想「就近抓一个」的话，把准星往方块上挪 ——
  以前那种「偏开也能选」正是这次要修掉的东西。
- 方块在墙后也能选中：可视化网格是穿墙可见的，屏幕上看得见就该能选。
  如果要「只选没被挡住的」，得再打一条相机→节点的射线做遮挡测试，本轮没做。
- 已删除（不可走）的点不参与选点，和原来一致。
- `ScreenPointToRay` 每帧调一次（`ghost_tick`），和原来每帧的射线比只多两个 native 调用。
- 取不到 `Camera.main` / 屏幕尺寸时自动退回 `transform.forward`，不会因为新调用把菜单搞死。

## 游戏内验证清单（我这边进不了游戏，麻烦实测）

1. 路点菜单 →「连接路径」→ 5 选 A：准星压在方块上，框变绿，日志 `准星选中 #n（偏 0.0x m…）`；
   准星挪开一格，框变灰，日志 `准星没压住路点（最近 #n 偏 x.xx m…）`。
2. 在台阶/平台边缘、半空的跳点、隔一层楼的点上各试一次：只要能看见方块、准星压上去就能选中。
3. 选 B 连边：连完 A 自动前进，行为不变。
4. 删点（菜单里那一项）：准星压住方块按 5 就删，不用再偏。
5. 「贴地」：准星压住方块按 5，Y 对齐到准星落点的地面。
6. 开一次菜单，日志会打一行：

   ```
   wpmenu: 准星射线 o=(x y z) d=(x y z)，和 forward 差 0.03°（相机 'Main Camera'）
   ```

   三个信息各有用：
   - **和 forward 差 N°**：N ≈ 0 = 投影本来就居中，以前的问题纯属「落点 ≠ 方块」；
     N > 0.2° = `forward` 确实偏，这条就是修复起作用的地方。
   - **相机名**：如果是 `WeaponCamera` 之类不是真正渲染画面的相机，说明 `Camera.main`
     拿错了对象（那就还得再改一处：换成玩家身上那台相机）。
   - **o/d**：相机位置和准星方向，和游戏里看到的朝向对不上就是这行有问题。

   把这一行发我，我能判断到底是哪一条，并据此把容差调细。
