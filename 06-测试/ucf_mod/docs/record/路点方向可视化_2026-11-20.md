# 路点方向可视化_2026-11-20

## 需求（用户原话）

> 连接路点，可以让用户看出来哪里是起点，哪里是终点，可能用户搞不清楚是从哪里开始的。

确认方案：**方案 1 全做**——起点有标记、落点有方向、边上有箭头；
颜色约定：起点绿 / 终点红 / 单向橙箭头 / 双向蓝线；**箭头只在 F2 菜单打开时显示**。

## 改动（src/editor.c）

| 块 | 位置 | 说明 |
| --- | --- | --- |
| ① 起点 A 标记 | `a_mark_mesh` / `a_mark_tick` | 绿色方块 + 0.07 m 粗竖条（1.7 m 高），网格建一次，每帧只改坐标/显隐；A 取消或关菜单就收起 |
| ② 落点预览 | `ghost_tick` | 这一步会变成起点 → 准星框绿（slot 2）；会变成终点 → 红（slot 12）；位置非法仍灰（13） |
| ② 方向箭头 | `ghost_arrow_mesh` / `ghost_arrow_tick` | 本地 +Z 的「>」形网格，按 `atan2(dx,dz)` 设 euler Y 转向；单向时摆在落点端指向落点（B->A 时摆起点端指回起点），双向不画；<0.9 m 不画 |
| ② 菜单文字 | `menu_refresh` | `起点 A #12 (x y z)` / `终点 B #34 (x y z)  4.2 m  单向 A->B`；跳跃点提示也带 A 的编号 |
| ③ 建成边箭头 | `VE.dir` + `read_nav` + `edge_arrow` | 扫边时用 `nav_conn_has(other, nd)` 判断反向：双向 dir=0、只有正向 dir=1、只有反向 dir=2；只给 dir!=0 的边画橙色小箭头，双向保持蓝线 |
| ③ 显隐 | `edge_dir_sync` | 箭头层单独一个网格（slot 7），每 tick 按 `g_wpMenuOpen` 开关，状态不变不碰 SetActive |

### 顺手修的一个洞：单向边会被整条漏画

旧 `read_nav` 只记 `oi > i` 的边，所以「大索引指向小索引」的单向边根本不会进 `g_ve`，
画面上看着像这条路不存在。现在两个方向都记：`oi > i` 直接记；`oi < i` 且对方没连回来时补一条 dir=2。

## 验证

- 编译：`tools/build.ps1`（mingw gcc 15.2.0，`-Werror=unused-*` 全过），22:01 已部署。
- 车测 level1（运输船 786 点 / 1391 边）：边数与原数据一致（说明扫边没有多记/漏记），无 crash。
- 车测 level7：菜单 2→2（单向 A->B）→ 5 选 A，日志 `ghost: A 起点标记已创建`、`link step=2 A=1`；
  因准星没有移动，A 与落点是同一个点（自环跳过），所以方向箭头没有生成——符合 `<0.9 m 不画` 的规则。
- 运输船原生 1391 条边全部是双向（没有 `vis_edge_dir` 层），单向箭头要在**含 `edge out` 的测试包**里才看得到。

## 已知限制

- 箭头只在菜单打开时显示，且只给单向边画；双向边保持蓝线（否则 1000+ 条的图会糊）。
- 竖直方向的边箭头仍按水平朝向摆（不做俯仰），这是省四元数的取舍。
- 菜单里的节点编号是实时 `nav_find` 出来的；REAPPLY / 换图后编号可能变，以坐标为准。
