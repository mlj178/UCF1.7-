# 守卫区入口 / 逃跑点接菜单（2026-11-28）

> 用户：守卫区工具里的「3 加入口 / 4 加逃跑点」以前按 5 没反应，帮我加上。
> 结论：3/4 已接线，写 markers.txt；入口只影响张望方向，不决定进区路线；逃跑点是被压时的随机落点。

## 1. 入口 entrancePos 不是“进区的门”

IDA 里 Bot_NanoGuardPos.Init() 把 area.entrancePos 追加到每个守卫点的 zoomPos
（世界目标点数组）；NanoGuard.SetAreaTarget / Destination_Listener 都不读它。
所以：

- 不加入口，人机照样靠 A* 走到区/守卫点；
- 加入口 = 守卫点站定后多一个张望方向；
- 改入口后已有守卫点要重新 Init 才生效，插件加入口时自动刷新（重写自己的 yaw + 再 Init）。

原生新寂静村的守卫点多数没有自己的 zoomPos，方向来自入口点，所以看起来在“东张西望/巡逻”。

2026-11-28 同步改：**我们菜单建的守卫点也不写自己的方向了**（zoomPos 留空）；
没有 entrance 时插件自动补一个「区中心」入口，避免 zoomPos 空；方向工具只剩蹲守点，
storm 的 markers.txt 里所有 nanopos 的 yaw 列已删除（当时 46 个点 / 6 个区）。

## 2. 逃跑点 escapePos / 逃跑区 escapeAreas

GoToSaferGuardPos() 的顺序：

1. 当前区里找 _safety > 当前 的守卫点；有就换点。
2. 没有：随机一个 escapeAreas（逃跑区），没满就整队过去。
3. 没有：随机一个 escapePos（逃跑点），isEscaping = true，优先级 10 跑过去。
4. 再没有：随机另一个区。

- escapePos 是你摆的落点，人机随机选。
- escapeAreas 是你摆的区引用，人机只在你给的这些区里随机选。
- neighborAreas 只有 getter，没找到运行时调用；当前版本可以不管。

插件新建区的 escapeAreas / neighborAreas 仍是空数组（没有区引用 UI）；入口/逃跑点的
entrancePos / escapePos 现在可以直接加。

## 3. 菜单行为

```text
3 守卫区工具
  1 新建守卫区              （3 m BoxCollider，和以前一样）
  2 加守卫点 → 子页：
      1 安全等级 0 / 2 等级 1 / 3 等级 2 / 4 等级 3
      5 放一个守卫点（安全等级 N，N 动态显示） · Esc 回守卫区工具
  3 加入口（站定后朝这看）  （加到当前区/准星所在区）
  4 加逃跑点（被压时跑这）  （加到当前区/准星所在区）
```

- 3/4 落点可以在区外（入口常在门口，逃跑点在区外/角落）；准星在别的区里就归那个区，否则归当前区。
- 3/4 都进 g_mk，可用「5 删除点位 → 任意点位」或删整个区连带删除；也进撤销/重做。
- 删除入口会从 entrancePos 数组摘掉并刷新守卫点方向；删除逃跑点从 escapePos 摘掉。
- 加守卫点子页里 **1~4 直接换等级**（不用 Esc），**5 放点**；第 5 项文字会随等级变成“放一个守卫点（安全等级 N）”；放完仍留子页可连续放；Esc 只回上层。
- F2 菜单打开、朝向显示开着时，准星指向守卫点，屏幕中间显示「守卫点 · 安全等级 N」；自己建的和原生守卫点都支持。
- 等级存 `markers.txt` 的 `# nano_safety N` 行；老文件没有就按 3；只影响之后新建的点。
- safety 语义：0~3，越大越靠里；被压时只换 **严格更高** 的点；全 3 = 不换，只能去逃跑区/逃跑点/别的区。

## 4. 文件格式

```text
# ucf_mod markers v1  ... entrance=2 escape=1 ...
# nano_safety 3
entrance <areaId> <x> <y> <z>
escape   <areaId> <x> <y> <z>
```

- 入口/逃跑点都按 areaId 挂区；旧版插件读到未知行会忽略。
- 数组按“保留旧元素 + 新点”重建；删最后一个点写空数组，不写 null（游戏 Init 会 AddRange）。

## 5. 与原生新寂静村的差距（结论）

| | 原生新寂静村 | 我们插件新建 |
| --- | --- | --- |
| 区范围 | 关卡作者摆的 Collider | 3 m BoxCollider（scale 3，默认 size 1） |
| 入口 | 场景里多个 entrancePos | 现在可加，默认 0 |
| 守卫点方向 | 多个入口 + 部分点自带 zoomPos，随机轮换 | 不写自己的方向；全来自入口（无入口自动补中心入口） |
| safety | 有高有低 | 可选默认 0~3（菜单 5，新建用）；仍没有逐点编辑 UI |
| 逃跑点/逃跑区 | 场景里有 | 逃跑点可加；逃跑区引用仍空 |
| 邻居区 | 字段有，当前无运行时调用 | 空数组，不用管 |

## 7. 可视化页的三个开关（2026-11-28）

控制台「插件开关 → 可视化」新增：

| 勾选 | cfg 键 | 游戏里控制什么 |
| --- | --- | --- |
| 守卫区入口点（Entrance） | `vis_entry` | 黄色小球（`g_mk` 的 `MT_ENTRY`）；总开关/这个开关都开才显示 |
| 守卫区逃跑点（Escape） | `vis_escape` | 白色小球（`MT_ESCAPE`） |
| 入口连线（粉色） | `vis_eline` | 粉色 `vis_entr` 线（区/守卫点 → entrancePos）；不读不画由它单独管 |

- 实时下发走 `ucf_navcmd.txt` 的 `cmd=vis`，字段是 `entry=` / `escape=` / `eline=`；0.5 s 内生效。
- 只开「入口连线」、关掉「守卫区/守卫点」时，仍会读一次 `SpareAreaList` 拿 entrancePos，只画线。
- 这三个只影响画面，不影响 markers 数据、寻路、人机行为。
