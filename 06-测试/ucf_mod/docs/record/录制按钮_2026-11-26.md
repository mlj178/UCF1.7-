# 录制页按钮整理：保存一段 / 不要这段 / 重算（2026-11-26）

> 用户原话：「录制的重新采样，重新录制，放弃，这三个按钮把我搞晕了，我都糊涂不知道怎么使用了。」
> 根因三条：
> 1. 「重新录制」和「放弃」在代码里是**同一个回调** `rec_reset`，行为完全一样；
> 2. 「重新采样」在复盘页看不到「采样间距 / 识别开关」，只能按同一套参数重算，结果当然不变；
> 3. 「暂停」不是存档点；暂停后右上角仍然只有「结束并复盘」，复盘页才有保存。

## 1. 新按钮

| 位置 | 按钮 | 行为 |
| --- | --- | --- |
| 右上（复盘） | **保存增量** → 接着录下一段 | 只保存。保存成功后主按钮直接变成「接着录下一段」，不自动开录；这样不滚动复盘卡片也能接着录 |
| 右上（复盘） | **重算（不重录）** | 用同一份原始数据、按当前参数再算一遍；不重录 |
| 复盘卡片 | **保存并接着录下一段** | 没保存就先保存，然后回①并等 1.2 s 自动开始下一段；已保存后叫「接着录下一段」 |
| 复盘卡片 | **不要这段，回准备** | 丢掉这次复盘回①；已保存后变灰叫「回录前准备」，**不会撤销已写入包的行** |
| 复盘卡片 | 重算参数 | 采样间距（1.5 / 2.5 / 4 / 6 m，按最大段长）+ 5 个识别开关；改完立即重算 |

旧的两颗按钮（「重新录制」「放弃」）已删除，不再有同名同行为的两个入口。

## 2. 两个场景

### A. 存一段，再接着录

```text
暂停（可选）→ 结束并复盘 → 保存并接着录下一段 → 接着走
```

也可以分两步：`结束并复盘 → 保存增量 → 接着录下一段`。

- 不用重开游戏或重进图：插件 `rec_start` 会先 `rec_stop("restart")` 再开新文件；
- 保存只增不覆盖，节点按 `MERGE_NEAR = 1.05 m` 合并；从暂停处接着走，第二段首点通常会被并到上一段末点，边能接上；
- 保存时会写 `cmd=apply`，绿按钮统一等 1.2 s 再发 `rec act=start`，避免 `ucf_navcmd.txt` 里后一条命令覆盖前一条。

### B. 这段没录好，不要了

- **还没保存**：`结束并复盘 → 不要这段，回准备 → 开始录制`。包里不会写任何行。
- **已经保存**：红按钮（此时是灰的「回录前准备」）只离开复盘，不会撤销。到 `dev\packs\<图>\<包>\` 找最近一份 `<指纹>.txt.bak-rec-<时间>`，复制回去覆盖；还原最近一份 = 只撤掉最近一次追加。
- 原始 jsonl 不会被删，还在 `dev\vis\rec\`；没点保存就不影响包，想清理可手动删。

## 3. 代码

`app/tabs/record/tab.py`：

- `build_rec_done`：复盘卡片新增「重算参数」行和开关网格；旧的两颗 `rec_reset` 按钮换成 `rec_btn_next` / `rec_btn_discard`；
- `rec_sync_step_seg`：① 和 ③ 的两个「采样间距」条保持同一个值；
- `rec_sync_saved_ui`：按 `rec_saved` 切换右上主按钮（「保存增量」↔「接着录下一段」）和卡片按钮的文案/颜色；
- `rec_next_segment`：先 `rec_save()`，成功后 `rec_reset()` + `after(1200, rec_start)`；
- `rec_review_from_file`：补存 `self.rec_events`，复盘后重算不会丢跳事件；
- `rec_save`：去重提示从写死的 0.35 m 改成 `ucf_rec.MERGE_NEAR`；
- `rec_reset`：回①时在状态栏说明「已保存的包内容不变 / 这段没有写进包」。

`app/tests/test_manual_save.py`：补 5 条静态检查（旧按钮已删、新按钮存在、重算改名、复盘可改参数、绿按钮先存后录）。
