## 需求（用户原话）

> 可以，帮我做进路点菜单里，里面的添加点位。删除点位也帮我放进去。删除标记帮我拆分成删除点位和删除区域。

## 结论

- **BL/GR 出生点不是场景物体**，是 `MapManager` 上的两个托管数组：
  `SP_BL@0x10` / `SP_GR@0x14`（`SpawnPoint[]`，16 B/个 = Vector3 + 朝向 float）。
- 菜单改的是**运行时数组**（不写 `levelN` 原图）：进图后拍一份原生快照，
  之后按「原生 - 删除 + 新增」重建数组写回字段；离开插件即恢复原版。
- 改动记在每张图自己的 `markers.txt`，下次进图自动重放。
- 只影响**玩家重生**：`MapManager.GetSpawnPoint`（RVA `0xAEB6E0`）反编译里
  只有一个代码调用者（`Player.MoveToRespawnPos`），人机不读这两个数组。

## 菜单变化（F2）

```text
1 添加点位
2 建立路径
3 守卫区工具
4 删除点图连线 / 路点
5 删除点位（按类型选）
6 删除区域（守卫区）
7 落地 / 贴地
8 撤销 / 保存
9 显示图层
0 关闭菜单（Esc 逐级返回）
```

- **1 添加点位** → 1 普通路点 / 2 跳跃点 / 3 蹲守点 / **4 出生点 BL** / **5 出生点 GR**
  - 出生点落在准星地面 +0.05 m，朝向 = 当前相机水平朝向（yaw）。
  - 连续放置：选完类型后一直按 5/左键；0/Esc 结束。
- **5 删除点位** → 1 蹲守点 / 2 守卫点 / 3 跳链 / 4 标签 / **5 出生点 BL** / **6 出生点 GR** / 7 任意点位
  - 7「任意点位」**不含守卫区**（区域只在第 6 项删），防手滑。
- **6 删除区域** → 1 守卫区（连带它下面的守卫点）。
  - 从「删除区域」回主菜单再进「删除点位」时，会把旧的 MT_AREA 选择清掉，
    避免在点位页按 5 把守卫区删了。

## markers.txt 新增行

```text
# spawn <team 0BL/1GR> <x> <y> <z> <yaw>   / spawndel <team> <x> <y> <z>
spawn 0 12.345 6.780 -3.210 90.0      # 用户新增的 BL 出生点
spawndel 1 -60.000 -15.000 5.000      # 删掉的原生 GR 出生点（按坐标匹配）
```

- 删除原生点按坐标匹配（容差 0.02 m），不依赖下标；删新增点直接摘 `spawn` 行。
- 每张图一份：`markers\<包名>\markers.txt`（和蹲守点/守卫区同一套路径）。

## 关键坑（为什么这样做）

1. **Awake 会重建数组**：`MapManager.Awake` 从 `pointDic` 拆出 `SP_*`。
   所以覆盖必须在地图加载后；`spawn_tick` 每 tick 比较字段指针，
   指针既不是上次写回那份、也不是快照那份 → 重新拍快照再套。
2. **至少保留 1 个**：`GetSpawnPoint` 在数组长度为 0 时会走越界异常路径。
3. **删点后计数器清零**：`SPID_BL/SPID_GR` 是静态计数器，长度变小后可能落在
   新长度外；写回后统一 `il2cpp_field_static_set_value(..., 0)`。
4. **新数组要钉住**：分配后到写字段之间是原生代码，GC 不知道数组是活的；
   用 `il2cpp_gchandle_new` 钉住，写完字段再释放（`plugin.c` 注入数组同款）。
   另外用 `il2cpp_array_get_byte_length` 校验新数组必须正好 n×16 B，
   元素类一旦拿错就放弃写入，不会把 memcpy 写到托管堆外。
5. **不碰 pointDic**：字典仍指原生数组；场景重载就回原版，插件不在 = 原版。
6. **换图 / 换包 / Ctrl+7**：都先 `spawn_restore_orig()` 再 `reset_markers()+load_file()`。
   否则会把「我们写回去的数组」当成本图原生快照，新增点被叠加一次；
   换图时也不会把上一张图的出生点改动静默留在新图的数组里。
