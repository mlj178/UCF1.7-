# 守卫点闪退修复：菜单「守卫区工具 → 加守卫点」一点就崩（2026-11-25）

> 用户反馈：F2 菜单 → 守卫区工具 → 加守卫点，游戏直接弹
> 「Microsoft Visual C++ Runtime Library — This application has requested the
> Runtime to terminate it in an unusual way」并闪退。同一入口「新建守卫区」也在闪退
> 范围里（2026-11-25 16:16:16 造了一个区，20 秒后进程没了）。

## 1. 结论

`Bot_NanoGuardPos.Init(area)` 被调用时，两个 `Vector3[]` 字段还是 `null`，
`List.AddRange(null)` 抛 `ArgumentNullException`；这个托管异常是在我们自己的
C 线程里抛的，IL2CPP 没有托管栈帧可以展开 → `std::terminate` → CRT 直接弹窗终止。

`editor.c` 里 2026-11-14 的注释早就写明了这个前提（`ED_AREA_ENABLED 0`），
但菜单在 2026-11-25 把守卫点/守卫区移回「守卫区工具」时没有再补字段，于是必崩。

| # | 字段 | 偏移 | 运行时 AddComponent 之后 | Init/Awake 里的后果 |
| --- | --- | --- | --- | --- |
| 1 | `Bot_NanoGuardPos.zoomPos` | 0x10 | `null` | `Init` 第一句 `AddRange(zoomPos)` 抛异常 |
| 2 | `Bot_NanoGuardArea.entrancePos` | 0x0C | `null` | `Init` 第二句 `AddRange(area.entrancePos)` 抛异常 |
| 3 | `posList` | 0x10 | `.ctor` 里 new 过，非空 | Awake 只数一次子物体，后来新建的点必须在代码里 `List.Add` |
| 4 | `neighborAreas / escapeAreas / escapePos` | 0x14/0x18/0x1C | `null` | 那几个 getter 本身判空，补空数组语义相同 |

## 2. 证据

### 2.1 反编译（IDA，GameAssembly base 0x10000000）

```
Bot_NanoGuardPos.Init        RVA 0xB30E80  (VA 0x10B30E80)
  this.area = area;
  l = new List<Vector3>();
  l.AddRange(this.zoomPos);       // null -> ArgumentNullException
  l.AddRange(area.entrancePos);   // null -> ArgumentNullException
  this.zoomPos = l.ToArray();

Bot_NanoGuardArea.Awake      RVA 0xB300A0
  posList -> GetComponentsInChildren<Bot_NanoGuardPos>() -> posList.AddRange(...)
  最后 SpareAreaList.Add(this)
Bot_NanoGuardArea..ctor      RVA 0xB30D10  -> posList = new List<Bot_NanoGuardPos>()
Bot_NanoGuardArea.GetPos     RVA 0xB303E0  -> posList 空时把自己从 SpareAreaList 摘掉
```

字段偏移与 `Il2CppDumper/dump.cs`（TypeDefIndex 5105 / 5106）一致。

## 3. 改法（`src/editor.c`）

新的创建顺序（`make_area_aid` / `make_nanopos`）：

```
新建守卫区：  new GameObject → SetActive(false) → AddComponent(Bot_NanoGuardArea)
              → area_fields_ok()：entrancePos / neighborAreas / escapeAreas /
                escapePos 全部补成空数组（posList 由 .ctor 建）
              → 加 BoxCollider(trigger) → 先不激活（Awake 留到第一个点）

加守卫点：    new GameObject → SetActive(false) → AddComponent(Bot_NanoGuardPos)
              → _safety=3、zoomPos = 两个方向 {(0,0,1),(1,0,0)}
              → 挂到守卫区下面、摆世界坐标
              → Init(area)     ← 两个数组都非空，不再抛
              → SetActive(true)
              → 第一个点：这时才 SetActive(区)，Awake 一次把子点收进 posList 并登记
                          SpareAreaList（再用 List.Add 判重兜底）
                之后的点：List<Bot_NanoGuardPos>.Add(comp) 自己挂进去
```

配套的小改动：

1. `ed_init()` 里从字段类型反查 `List<Bot_NanoGuardPos>.Add` /
   `List<Bot_NanoGuardArea>.Add`（泛型实例拿不到名字，做法同 `navfix.c`）。
   `runtime_invoke` 传 `&exc`，真抛异常也只是记日志，不会闪退。
2. `markers.txt` 的 `area` 行补第 5 列 aid（旧 4 列文件照样读）：
   以前 aid 靠「建的顺序」推，删过守卫区再进图，`nanopos` 的 areaId 就对不上，
   点位会静默丢掉。
3. 删守卫区不再 `g_areaCount--`（那会让下一个新建的区拿到别人还在用的 aid，
   `g_aidMk` 互相覆盖，守卫点挂到错的区上）。改用独立的 `g_aidUsed[]` 占用表。
4. `g_areaLive[]` 记录「这个区激活过没有」，换图 / 删区时清零。

## 4. 验收（怎么确认修好了）

重新从「启动控制台」启动游戏（`UCF_MOD_DLL` 指向 `run\build\ucf_mod.dll`，
编译即生效），进图后看 `log\ucf_mod.log`：

```
init: posList=... posList.Add=... SpareAreaList.Add=...     ← 三个都非 0
area #0 (aid=0 scale=3.0) at ... -> current（等第一个守卫点再激活）
area aid=0 激活（第一个守卫点）posList=1                     ← 关键：=1
nanopos #1 at ... aid=0 safety=3 areaPosList=1
```

- 有 `area aid=... 激活（第一个守卫点）posList=1` 且游戏不退出 → 修好。
- 若出现 `area: entrancePos 补空数组` 说明确实走了补齐分支（正常首次都会打）。
- 若出现 `nanopos: posList(Awake 没收到)`，说明 Awake 没数到子物体、走了兜底，
  点位仍然可用，但需要记一笔。
- 若出现 `List.Add 不可用` / `List.Add 抛异常`，说明泛型方法没解析出来，报给开发。
