# 纯面图补点图（2026-11-27）

> 类型：**记**（用户问题 → 结论 → 插件/控制台改动 → 车测证据）。现状看 README.md 与 docs/guide/地图对照表.md。

## 用户问的

> 「胜利广场这张图我也选择不了，是怎么回事」
> 「这两个地图是有些特殊是吗，所以我们新建地图添加补上点。」

结论：**这两张图特殊** —— 场景的 A* 里连 PointGraph 对象都没有（不是「0 个点」）。
按用户选择，做成「插件运行时补一张点图 + grow 时摘掉可走面」，让它们能像飓风危城一样画点。

飓风危城能画，是因为它有空的 PointGraph，插件能 AddNode；这两张没有对象，插件没地方落点。
控制台原来只收「有 map.json + 指纹」的图，所以它们连下拉都进不去 —— 看起来就像「选不了 / 数据丢了」。

## 二、插件侧（C，已编译并车测通过）

`src/navfix.c`：

- **`navfix_add_point_graph()`** —— 场景没有 PointGraph 时手工造一张挂进 `AstarData.graphs`：
  造 `PointGraph` 对象 → 填 `NavGraph.active / name / graphIndex` → 新数组（旧内容整段复制）挂到
  `data.graphs`（0x20）→ 调这张图自己的 `NavGraph.Scan()` 建 nodes / lookupTree。
  不走 `AstarData.AddGraph(Type)`：它按 serialized `graphTypes` 找类型，纯面图里没有 PointGraph 这一项，
  而且 string / Type 两个重载同名同参数个数，`class_get_method_from_name` 取不准。
- **`navfix_drop_navmesh()`** —— grow/空白模式下把这张图的 `NavMeshGraph` 用
  `AstarData.RemoveGraph` 摘掉：A* 多图共存不跨图连边，人机取「脚下最近节点」永远落在三角网上，
  不摘的话画的点等于没画。**只在「本图的点图是插件现场补的」时调用**，正常图永远不碰。
- `navfix_pg_reset()`：换图时清「试过一次」的标记。

`src/editor.c`：

- `nav_edit_tick()`：`navfix_point_graph()` 为空且**选了测试包**（或 `UCF_PG_TEST=1` 试验开关）时调补图；
  补完就走原来的「0 点图 + grow」流程。
- `nav_apply_grow()`：`!keep && g_pgSynthetic` → 先 `navfix_drop_navmesh()` 再套文件。
  （keep = 原版 + 新增不摘，因为它要保留原版路线。）

## 五、限制与注意事项

1. **只能停在「编辑中」**：成品档是「按指纹找 <图>/final/<指纹>.txt」，而飓风危城 / 胜利广场 / 死亡擂台
   三张 0 点图指纹都是 `n0-0000000000000000`，会互相覆盖。控制台把这三张的「发布」都挡住了（纯面图那两张），
   要做成品得先解决指纹撞车（比如让插件在构建时把图名混进指纹）。
2. **grow 时会摘掉可走面**：草稿里一个点都没有时，人机在这张图会站着不动 —— 这是「空白地图」的既有语义
   （飓风危城同样）。keep（原版 + 新增）不摘可走面，但那时点图也不会被人机用到。
3. **摘掉的图只对这一次进图有效**：退房间 / 换图后场景重载，原版可走面自己回来。
4. 没在真人对局里跑过（车测只切图不打架）—— 需要进图实打实看一次人机走你画的点。
