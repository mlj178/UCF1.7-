# 删草稿只搬草稿（2026-11-27）

> 类型：**记**（事故 + 修复，历史证据）。现状看 README.md 与 docs/guide/07-地图对照表.md。
> 本文路径统一写成 `/`，实际在 Windows 上是同一个位置。

## 用户看到的现象

> 「人机路点，编辑中的运输船的地图怎么没了？修复一下。我想创建运输船的新地图，都选择不了运输船。」

两句话是同一个根因：

1. 「编辑中」页顶部的**当前地图**下拉里没有「运输船」（也没有「小型工厂」）；
2. 没有这张图就选不了它、也就点不了「开始编辑这张图」——**建不了新草稿**。

## 根因：一图一夹之后「删草稿」还在整份搬目录

2026-11-27 上午刚把数据改成**一图一夹**（见 `一图一夹_2026-11-27.md`）：
点图 / 可走面 / 草稿 / 标记 / 成品现在都躺在**同一个** `data/maps/<序号_场景名中文名>/` 里。

但「删除本图草稿」走的还是老逻辑 —— `navdata.py` 的 `pack_store_remove()` 把**整个目录**
`shutil.move` 进 `_archive/pack_trash/`。一图一夹以前这个目录里只有草稿三件
（`manifest.json` / `<指纹>.txt` / `nogen.txt`），所以整份搬没问题；一图一夹以后
**`map.json`、`native/map.json`、`navmesh.bin`、`markers.txt`、`final/` 都在里面**，一搬全带走。

地图下拉（`app/ui/maps.py` 的 `load_maps()`）只收「有 `map.json` + 指纹」的图，
`P.folder_names()` 也是同一判据 —— 于是这张图从「地图总览」「人机路点」「数据」页一起消失，
看起来就是「地图没了」。

## 代码修复

| 文件 | 改了什么 |
| --- | --- |
| `app/core/navdata.py` | 新增 `pack_draft_files()`（**只有** `manifest.json` / `nogen.txt` / `<指纹>.txt` + `.bak-*` 算草稿）、`is_map_folder()`（有点图 / 可走面 / 标记 / `native/` / `final/` 就是图文件夹）、`_pack_trash_dst()`；`pack_store_remove()` 改成**逐个搬草稿文件**，图数据一个字节不动；老布局（`packs/<图>/<包>/`，里面没有图数据）仍然整份搬；`--hard` 也只删草稿文件，不再 `rmtree` 整个图文件夹 |

## 自检

`app/tests/test_draft_delete.py` 从「只读源码」升级为**临时目录真跑**：

- 造一张完整的图（`map.json` + `navmesh.bin` + `markers.txt` + `native/` + `final/` + 草稿三件 + 一个 `.bak`），
  跑 `pack_store_remove()`；
- 断言：草稿四件全进 `pack_trash`；`map.json` / 可走面 / 标记 / `native/` / `final/` 一件不少；
  这张图不再算「有草稿」，但仍然算图文件夹；
- 再删一次要明确报错（不乱搬）；`--hard` 只删草稿；老布局仍然整份搬。

真机侧还没跑（改的是控制台数据台账，插件与 C 侧一个字节没动）。

## 教训

1. **目录语义变了，所有「整份搬目录」都要重审一遍**：一图一夹把「草稿目录」升级成了「图目录」，
   删草稿的动作没跟着变，代价是两张图的点图。
2. **「文件没了」先看回收站**：本项目所有删除都是「挪到 `_archive/`」，这次 6 个文件全在，
   而且逐字节可核（`git hash-object` 对 `HEAD`）。
3. **下拉里少一张图 = 数据判据没满足**：`load_maps()` 只认 `map.json` + 指纹；
   界面已有的「为什么少了几张图」提示只解释「原生没有点图」，这次的情况它说不出来。
