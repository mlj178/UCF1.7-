## 之前是什么行为

1. 每个点位在场景里只有一个**球**（`spawn_vis`）+ 一个小方块/线框：球是各向同性的，看不出朝哪。
2. **蹲守点根本没写方向**：`make_crouch` 只设了 `team`，`zoomPos` 一直是 null ——
   人机在这个点蹲下后「朝哪架枪」是未定义的（原生点都有值）。
3. **守卫点写的是两个固定占位值** `{(0,0,1), (1,0,0)}`。而游戏按**世界目标点**解释这两个值
   （下面有实测），所以每个新建守卫点的人机都朝**世界原点方向**看 —— 和点位在哪完全无关。
   这就是「设了方向也看不出来」的真正原因：不是没画，是数据本身没有你的意图。
4. 出生点 `yaw` 存了、也写回游戏了，但**没画**（本次不做，见「不在本次范围」）。

## 这次核实的关键事实（UnityPy 直接解原版场景）

用 `globalgamemanagers.assets` 的 MonoScript 表把 level2 / level7 / level8 的
MonoBehaviour 对上类名，再按字段偏移解 `zoomPos`：

| 关卡 | 类 | 数量 | zoomPos 情况 |
| --- | --- | --- | --- |
| level2 小型工厂 | `Bot_CrouchPos` | 8 | 8 个都带 1 个方向；目标点距点位 7.3~39.7 m |
| level7 沙漠要塞 | `Bot_NanoGuardPos` | 51 | **49 个是空的**，2 个带 2 个方向；目标点距点位 18~53 m |
| level8 生化酒店 | `Bot_GuardPos`（旧守卫点，死数据） | 25 | 全部带 1 个方向；多个点共用同一个目标点 |

**结论**：`zoomPos` 里存的是**世界坐标（要看向哪）**，不是单位方向向量。
证据：数值量级 7~53 m；`Bot_NanoGuardArea.Init()` 把 `entrancePos`（世界坐标的入口点）
`AddRange` 进每个守卫点的 `zoomPos` —— 只有当它是世界点时，这一步才说得通。
所以守卫点的「张望方向」多数来自**守卫区的入口点**，自己带方向的很少（51 个里只有 2 个）。

## 显示规则（用户选定的方案 C）

| 项 | 规则 |
| --- | --- |
| 画哪些点 | **只画准星正对着的那一个**（射线垂直距离 ≤ 0.9 m，60 m 内取最近）。自己放的点优先，其次读游戏里的点 |
| 射线 | 主方向：1.4 m 粗线（宽 0.06）+ 箭头尖；次方向：0.9 m 细线（0.035）+ 末端小方块，**最多 3 条** |
| 扇形 | 半角 30°、半径 1.8 m 的**线框**弧 + 两条边 + 中心射线 + 箭头（不做半透明：游戏材质 Opaque，alpha 不生效） |
| 未知 | 半径 0.35 m 的**虚线小圈**（8 段）+ 浮字「朝向未知（读不到 zoomPos）」 |
| 度数文本 | 准星下方 58 px 一行：「蹲守点 · 朝向 东北 42°」/「守卫点 · 朝向 东北 42° · 3 个方向」 |
| 颜色 | 沿用调色板：蹲守点红（槽 1）、守卫点绿（槽 2） |
| 何时不画 | **F2 菜单没开**（和单向边箭头同一个口径：关菜单 = 正常游玩画面干净）、朝向工具选「关」、Ctrl+V 关可视化、没对准任何点 |

方向约定和屏幕罗盘同一套：**0° = 北（-Z）、90° = 东（+X）**，八分区中文直接用「北 / 东北 / 东 …」。

## 编辑规则

| 入口 | 行为 |
| --- | --- |
| 放置（按 5） | 朝向 = **当前相机朝向**；按 5 之前虚线框旁就有橙色箭头预览，所见即所得 |
| 朝向工具第 1 项 | 设为相机朝向（你看着哪，它就朝哪） |
| 第 2 / 3 项 | 顺时针 / 逆时针 15°；**← / → 直接转**（按住 Shift = 1°） |
| 第 4 项 | 清空方向：显示回到「未知」；游戏侧留一个正北兜底（见限制） |
| 第 5 项 | 显示样式：射线 → 扇形 → 关 → 射线 |
| 原生点 | 明确拒绝：「这是原生点位，朝向改不了（只能改自己放的）」 |

改完的朝向算「未保存」（`editor_dirty_mk`），**Ctrl+S** 才写 `markers.txt`；撤销 / 重做带朝向。

## 持久化格式

```
crouch  <team> <x> <y> <z> [yaw]              第 5 列可选：老文件没有 = 未知
nanopos <areaId> <x> <y> <z> <safety> [yaw]   第 6 列可选：同上
```

`yaw` 单位度、0 = 北、90 = 东。未知就不写这一列，旧版插件读新文件也不会乱（多一列会被忽略）。

## 边界与已知限制

- **只能改自己放的点**。原生点位是场景资产，改了不落盘、重进图就没了，所以直接拒绝，
  不给「看着改了其实没改」的假象。
- **刷新率跟 `editor_tick` 走（4 Hz）**：快速甩视角切换目标点时，箭头最多晚 0.25 s 才换。
  固定住不动时是准的。
- **浮字是屏幕固定位置**（准星下方），不是贴在点位上方。贴点位要 `Camera.WorldToScreenPoint`
  的调用约定，这个仓库里只有 RVA 定义、没有实际调用过，没验证前不冒险（崩了不值得）。
  需要的话下一步单独验证再改。
- **扇形只画主方向**（多方向时只看第一条）；多方向仍会在射线样式下画全 3 条。
- **清空方向 ≠ 游戏里没有方向**：游戏侧留一个正北目标点兜底（`GetRandomZoomPos` 要按
  下标取数组，写空数组有抛异常的风险）。插件显示、保存都按「未知」处理。
- **守卫区的入口 / 逃跑点仍未接线**（老限制）。注意 `Init` 会把 `entrancePos` 并进每个守卫点的
  `zoomPos`，所以原生守卫点显示的「N 个方向」里通常就包含入口方向 —— 这是游戏行为，不是 bug。
- **显示样式不在游戏内落盘**：`wp_dir_style` 只有控制台能写，朝向工具里切「射线 / 扇形 / 关」
  只在本次运行有效，重启回默认「射线」。地图数据（朝向本身）不受影响，Ctrl+S 照常保存。
- **出生点朝向仍未显示**（`SpawnPoint.yaw` 早就写进去了）：本次按用户范围只做蹲守点 / 守卫点。

## 进游戏核验清单

1. F2 → 1 添加点位 → 3「蹲守点」：准星处出现虚线框 + **橙色箭头**，箭头方向 = 你看的方向；
2. 按 5 放下：红球旁出现**红色射线 + 箭头**，准星下方一行「蹲守点 · 朝向 东北 xx°」；
3. 走开、回头再瞄这个点：箭头和度数应和放下时一致（说明读回来的是同一份数据）；
4. F2 → 9 朝向工具：菜单显示当前朝向；按 **→** 转 15°，**Shift+→** 转 1°，箭头跟着转；
5. 该页按 1「设为相机朝向」：箭头转到你正看的方向；按 3「逆时针」再转回去；
6. Ctrl+S 保存 → 退出重进图：方向还在（`markers.txt` 的 crouch/nanopos 行末尾多一列）；
7. 守卫区工具 → 加守卫点：预览也有橙色箭头；放完是绿射线；
8. 进沙漠要塞 / 新寂静村，准星对着**原生**守卫点：浮字显示「守卫点 · 朝向 xx° · N 个方向」；
   在朝向工具里按 1 → 应提示「原生点位，朝向改不了」；
9. 朝向工具第 5 项切「扇形」：变成 30°/1.8 m 的线框扇；再切「关」：整层消失；
10. Ctrl+V 关可视化 / 按 F2 关掉菜单：方向层一起消失；再开回来恢复；
11. 日志 `ucf_mod.log` 里应有 `dir: ...`、`crouch: 朝向 ... → zoomPos`、`nanopos: 朝向 ...`。
