# 删除本图草稿：编辑中那张图怎么退场（2026-11-25）

## 需求

「编辑中」一张图一个草稿。原来卡片上只有「重置本图草稿」——它只把点/边清空，
草稿还留着，图还在。用户要的是**把正在编辑的那张图整份删掉**：
删完这张图回到「还没有草稿」，要重做才重新建。入口要看得见、点得到、不会误删。

## 设计

位置不动，只加一个红按钮：`人机路点 → 编辑中 → 本图草稿` 卡片右侧的危险区。

| 状态 | 左边（日常） | 右边（危险区） |
|---|---|---|
| 有草稿 | 打开草稿目录（蓝）· 重置本图草稿（橙） | 本图标记：守卫区 9 · 清空本图标记（琥珀）· **删除本图草稿（红）** |
| 没有草稿 | 开始编辑这张图（蓝）· 打开草稿目录（灰）· 重置（灰、不可点） | 本图标记：无 · 清空（灰、不可点）· 删除（灰、不可点） |

- 颜色沿用控制台既有危险色 `#8a1c1c`（和成品页「撤销这张图的发布」同色）：
  正常 `#8a1c1c` / 悬停 `#a32424` / 禁用 `#3a3f47`。
- 贴右边、和橙色「重置」拉开距离：两个都带破坏性，但「重置」可后悔、「删除」要慎重。
- 顺手收掉一个老毛病：有草稿时蓝色主按钮本来就变成「打开草稿目录」，
  灰色那个同名按钮纯重复 —— 有草稿时 `pack_forget()`，没草稿时按原位置放回
  （`pack(..., before=btn_reset_draft)`），按钮顺序不会乱。
- 卡片说明补一句区别：**重置 = 只清内容（草稿还在）**，**删除 = 整份挪走（回到「还没有草稿」）**。

示意（真实窗口截图，用户当前数据）：

```text
本图草稿                                   一张图只有一个；可写
[ 打开草稿目录 ] [ 重置本图草稿 ]     本图标记：守卫区 9  [清空本图标记] [删除本图草稿]
```

## 确认与去向

点下去先弹一个**自绘的危险确认框**（`ui/kit.py` 的 `confirm_danger()`），当场列清楚要删的是什么：

```text
⚠ 删除本图草稿

「飓风危城」这张图的草稿整份删掉。

草稿：26 点 / 49 边 · 空白地图 · 创建于 2026-11-24 15:50
目录：packs\10_Nano30_Storm飓风危城\

删完这张图回到「还没有草稿」，要重做点「开始编辑这张图」。
成品里已发布的那份不动（要撤发布去「成品」页）。
整份目录先移到 archive\pack_trash\，误删可以挪回来。

                              [ 取消 ]  [ 删除草稿 ]
```

- **为什么不用 `messagebox.askyesno`**：实测（Python 3.12 + Tk 8.6，Win11）——
  把 askyesno 关掉（标题栏 × 或 WM_CLOSE）返回的是 **True**，点 Esc 也是 True；
  `if not askyesno(...)` 这类写法在「×=取消」的直觉下会把删除放行。
  删除这种动作不能赌默认按钮，所以自绘 Toplevel：只有点红色「删除草稿」才返回 True，
  × / Esc / 取消一律 `close(False)`，默认焦点给「取消」。
- 同类问题（本次没动，只记录）：`重置本图草稿`、`撤销这张图的发布`、`从备份还原`、
  `_guard_game` 仍用 askyesno —— 点 × 等于「是」。建议后续统一换成 `confirm_danger()`。

- 游戏开着先问一句（`_guard_game`）：这一局已经读进内存的不会变，提示关游戏再生效。
- **不真删**：`packs\<图>\` 整份挪到 `data\navdata\dev\archive\pack_trash\<图>__<时间>\`，
  和成品发布前的 `archive\final_prev\` 一个思路（界面不出现，误删能挪回）。
- 成品 `final\<指纹>.txt` 一个字节都不碰；要撤发布走成品页「撤销这张图的发布」。
- 删完刷新草稿状态行 / 启动条 / 对比表 / 按钮态。启动档还停在「编辑中」时，状态栏补一句：
  「这张图会走原版，要做新的点『开始编辑这张图』」。

## 草稿之外：守卫区 / 守卫点 / 蹲守点 / 标签（20:49 用户反馈后补）

用户按新按钮删了草稿、又建了空白草稿，进图后发现「守卫区还在，是不是没删干净」。查到的实事：

- 草稿 txt：`node/edge/jump` 全没了（`naved: loaded 0 edits ... (blank base)`），草稿干净；
- `markers\10_Nano30_Storm飓风危城\markers.txt`：**9 个 `area`（守卫区）**，守卫点/蹲守点/标签/出生点都是 0；
- 插件日志 20:47:52：`loaded 9 markers ...`，9 个守卫区逐个建出来（都「等第一个守卫点再激活」）。

结论：**守卫区这些不在草稿里**。草稿只装路点/边/跳跃；蹲守点、守卫点、守卫区、标签、出生点
是「编辑标记」，按图存在 `dev\markers\<图>\markers.txt`，插件每次进图重放，所以删草稿不会带走。

因此先加了可见性和单独出口（同一行，窗口矮也不会被滚动视口裁掉）：

- `本图标记：守卫区 N`（琥珀）+ `清空本图标记` 按钮：把 `markers.txt` 挪到
  `dev\archive\markers_trash\<图>__<时间>\`（不真删），然后刷新这一行；
- 清空后重进图或按 Ctrl+7 才按新文件重放（日志 `loaded N markers`）。

## 21:09 用户再反馈：删除草稿要连标记一起清

用户的原话：「新建了一个编辑中的 storm 地图，空白的，进去里面就有几个守卫区……删除草稿一定要删除干净。」
时间线对得上：**21:06 他在图里又加了 2 个守卫区**（aid 17 / 18，`saved 10 → 11 markers`），
21:07 删草稿 + 建空白草稿，21:07:21 进图时插件把 **11 个守卫区**重新建出来 —— 草稿是空的，标记一直在。

于是把删除做成一件事（不再要求用户记得点两次）：

- `删除本图草稿` 的确认框多一个**默认勾上**的勾选框：`同时清空本图标记（守卫区 11）`；
- 勾着：先 `clear_markers(ask=False)`（标记挪 `archive\markers_trash\`），再 `pack rm`（草稿挪
  `archive\pack_trash\`）；**标记没挪成功就不删草稿**（免得草稿没了、旧标记还挂着）；
- 取消勾选：只删草稿，标记留着（想保留守卫区只重画路点时用）；
- 弹窗正文也写清：「本图标记：守卫区 11 …… 它们在 markers\<图>\markers.txt，不在草稿里 ——
  不清的话，新建空白草稿进图还会看到。」

`confirm_danger()` 为此加了可选勾选框参数（`checkbox_text` / `checkbox_checked` / `out`），
取消/关窗时 `out["checked"]` 不会被写上，调用方拿不到 True 就不会清。

游戏内其实也有入口：**F2 → 删除区域（守卫区）**（菜单子页 8），准星对准守卫区再按 5 / Delete。
用户之前的日志全是「这张图没有守卫点标记」「没有蹲守点标记」——在「删除点位」页按，不碰守卫区。

另外：20:47:34 被删掉的那份旧草稿（26 点 / 49 边 + 3 个 `.bak-*`）整份在
`archive\pack_trash\10_Nano30_Storm飓风危城__20261125_204734\`，要找回就整目录挪回 `packs\`。

## 代码

- `app/core/navdata.py`
  - `PACK_TRASH`：默认 `dev\archive\pack_trash\`；`UCF_PACK_TRASH` 只给自检指临时目录。
  - `pack_store_remove(name, hard=False)`：`shutil.move` 整份挪；
    跨盘 / 占用时退回 `copytree` + `final_delete_dir`（去掉只读再 rmtree）。
  - `cmd_pack_rm`：`python navdata.py pack rm <地图文件夹> [--hard]`，输出删了什么、挪到哪、怎么找回。
- `app/ui/kit.py`：`confirm_danger(title, lines, ok_text, cancel_text, checkbox_text, checkbox_checked, out)`
  —— 危险操作专用确认框；勾选框结果写 `out["checked"]`（只有点红色按钮才会写）。
- `app/ui/packs.py`
  - `delete_draft()`：没草稿直接说；游戏守卫 → `confirm_danger()`（列点数/建法/创建时间/目录 +
    「同时清空本图标记」勾选框，默认勾上）→ 按勾选先 `clear_markers(ask=False)` →
    `run_navdata(["pack", "rm", folder], "删除本图草稿")`。
  - `clear_markers(ask=True)`：单独按钮用 `ask=True`（自己弹框）；删草稿时 `ask=False` 复用，返回成败。
  - `_navdata_done`：删完给「启动档还是编辑中」的提示。
- `app/tabs/waypoint.py`：`btn_delete_draft` + 有/无草稿两态 + 卡片说明；
  同一行加 `本图标记：…` + `btn_clear_markers`（有标记才亮）。
- `app/ui/packs.py` 的标记三件：`marker_path()` / `marker_counts()` / `marker_summary()` / `clear_markers()`；
  `delete_draft()` 的确认框会带上标记条数。
- `app/tests/test_draft_delete.py`：新自检（三处链路 + 两态 + 不动成品）。
- `app/tests/test_marker_clear.py`：标记可见 / 只挪不删 / 两态 / 删草稿提示。

## 踩坑（已恢复）

第一版截图脚本想让真弹窗自己关掉：`PostMessage(WM_CLOSE)` 收尾。结果关窗被 askyesno 当成「是」，
草稿整份被挪进了 `archive\pack_trash\10_Nano30_Storm飓风危城__20261125_202231\`。
发现后把 6 个文件原样移回 `packs\`（git 状态与移动前一致；成品 `final\` 本来就是空的，没受影响），
顺手删掉空的 `pack_trash`。截图脚本改成：`confirm_danger` 固定返回 False + `run_navdata` 空壳，
两条保险都在，重复跑一百次也不会动数据。
