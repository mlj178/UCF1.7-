# 删除标记「按类型」_2026-11-25

## 需求（用户原话）

> 蹲守点 / 守卫点 / 守卫区 / 跳跃点 / 标签(范围 tag)，这几个的删除，我希望也是可以分支选择的，
> 1，2，3，这样分开，要不然容易删错。

原来的删除只有一个入口：F2 主菜单第 4 项「删除标记（准星最近 · Delete）」（现在是第 5 项），删
**准星最近的那个标记，不分类型**。守卫点就落在守卫区那个 3 m 框里，蹲守点也常贴着守卫点放，
按"最近"挑很容易删错对象。

## 各类型的实际效果

| 类型 | 删掉什么 | 注意 |
| --- | --- | --- |
| 蹲守点 | 组件从 `Bot_CrouchPos.SpareList_BL/GR` 摘掉 + 销毁对象 | `markers.txt` 的 `crouch` 行一起删 |
| 守卫点 | 从 `area.posList` 摘掉 + 销毁对象 | 守卫区保留；删空后游戏在 `GetPos` 里自己把区摘出 `SpareAreaList` |
| 守卫区 | **先递归删它下面所有守卫点**，再摘 `SpareAreaList`、销毁对象 | 想清掉一整片守卫区就删区，一步到位 |
| 跳跃点 / 跳链 | 从 `Bot_JumpLink.linkDic` 反登记、销毁对象，并把点图日志里对应那条 `jump add` 摘掉 | 不做反登记的话 `GetLink` 仍能查到已销毁对象，人机照用（见下） |
| 标签 / 范围 | 只删标记记录和可视化小球 | 节点上的 `tag` 位是会话级的，重进图本来就会清 |

### 跳链为什么要动 `linkDic`

反编译 `Bot_JumpLink.GetLink`（GameAssembly `0x10B2F5E0`）只看字典：

```csharp
if (linkDic.TryGetValue(graphNode, out jumpLink)) return true;   // 不判 Unity 假空
*jumpLink = 0; return false;
```

`linkDic` 是静态字段（`.cctor` 建一次），销毁 GameObject 不会把它摘掉。所以老的"任意删除"
删跳链其实是假删：可视化了、对象没了，人机照样取到那个组件的 `links`。
现在删除时先调 `Dictionary<GraphNode, Bot_JumpLink>.Remove(startNode)` 反登记
（`jump_unregister`，[:4312](src/editor.c#L4312)），再从点图日志里摘 `jump add`
（`nav_drop_jump`，[:5812](src/editor.c#L5812)），重进图就不会再建。

用游戏自己的 `Remove`、不手写字典布局：2026-11-17 的闪退就是手写摘除 List 时踩到写花槽位
（`SpareAreaList.Remove`）；这里托管异常走 `runtime_invoke` 的 `exc` 出参，抛了也只记日志。

## 现在的操作

```text
F2 → 5 删除标记（按类型选）
   → 1 蹲守点 / 2 守卫点 / 3 守卫区 / 4 跳跃点 / 5 标签 / 6 任意
   → 准星对准对象，小键盘5 或 Enter 或 Delete 删除（停在类型页，可连续删）
   → 1-6 直接换类型（换类型不会触发删除）
   → Esc / 0 回主菜单
```

菜单页会显示「图里现有：蹲守 N · 守卫点 N · 守卫区 N · 跳链 N · 标签 N」，
删之前先扫一眼数量，删完看日志：

```text
wpmenu: 删除类型 = 守卫点（准星对准对象后 5 / Delete 删除，可连续）
delete: removing #12 type=2(守卫点) at 17.06 13.92 5.34
delete: nanopos removed from area.posList
```

`type=` 后面括号里就是类型名（2 守卫点、3 守卫区、4 跳链…），一眼能核对有没有删错。
