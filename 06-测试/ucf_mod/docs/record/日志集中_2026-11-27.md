# 日志集中到 log\（2026-11-27）

> 目标：**运行日志只有一处** —— 工程端 `log\`。排查问题不再要在三个目录里挨个翻。
> 本文只讲「哪个文件从哪搬到哪、为什么有些没搬」，细节看 `README.md` 的「日志」一节。

## 1. 搬了什么

| 旧位置 | 新位置 | 谁写的 | 格式 |
| --- | --- | --- | --- |
| `data/navdata/_logs/navdata.log` | `log\navdata.log` | `app/core/navdata.py` 的 `_Tee` | 纯文本（命令行 stdout 抄本） |
| `data/navdata/dev/final/_publish.log` | `log\publish.log` | `app/core/navdata.py` 的 `final_store_publish` | TSV：时间 / 指纹 / 标签 / node/edge / sha12 / 备注 |
| `run/build/ucf_mod.install.log` | **删除** | 已无写入点（历史部署脚本的残留） | ISO8601 文本 |

搬之前 `log\` 里只有插件那三件（`ucf_mod.log` / `autotest.txt` / `player_marks.txt`，
2026-11-23 收的）。现在 `log\` 是唯一入口。

## 2. 历史日志不会丢：一次性合并

两个新文件都带老位置常量，**第一次写入前把老文件按字节并进来再删掉**：

- `navdata_migrate_log()` —— `data\navdata\_logs\navdata.log` → `log\navdata.log`，
  目录空了顺手 `rmdir`
- `publish_log_migrate()` —— `dev\final\_publish.log` → `log\publish.log`

用**字节级**追加（`rb` / `ab`），不经解码 —— 老日志里有半行截断或旧编码也不会整个读不出来。
迁移是幂等的：文件不在就返回 `False`，什么都不做。

## 3. 为什么这几类**故意没搬**

| 东西 | 留在哪 | 理由 |
| --- | --- | --- |
| `%TEMP%\ucf_mod_proxy.log` | %TEMP% | 加载器 `LoadLibrary` 失败时才写 —— 那一刻工程端路径和权限都不可信。搬进 `log\` 会在最需要它的场景失效 |
| `dev\vis\rec\*.jsonl`（30 个 / 30 MB） | 原位 | **是数据不是日志**：录制原始取样，会被 `ucf_rec` 反复读、复盘后写回 packs。塞进 `log\` 会让"日志目录"变成几十 MB 的数据仓库 |
| `dev\vis\trace\*.jsonl` | 原位 | 同上，是 `跳跃报告_*.md` 的原始证据 |
| `跳跃报告_*.md` | 原位 | 给人看的**分析成品**，不是日志 |
| `archive\*.bak-*`、`run/build\*.old-*.dll` | 原位 | 回滚快照，语义归数据/产物，不归日志 |
| `final\_index.json` | 原位 | 每张图的**权威**发布台账（published / sha256 / from）。`publish.log` 只是按时间排的流水账 —— 所以 `log\` 被清掉也不影响成品追溯 |

## 4. 顺带做的两件事

1. **`navdata.log` 加了 16 MB 轮转**，`navdata.log` → `navdata.prev.log`，只保 1 代 ——
   和 `cfg.c` 的 `UCF_LOG_MAX_BYTES` 同一个阈值、同一套命名。以前它无上限追加。
2. **`.gitignore` 把 `dev/vis/trace/` 的意图写清了**：它和 `rec/` 长得像但**故意入库**
   （体量小、是跳跃报告的原始证据）。别照 `rec/` 的规则顺手加进去。

## 5. 改了哪些文件

- `app/core/navdata.py`：`NAVDATA_LOG` / `PUBLISH_LOG` / `LOG_MAX_BYTES` / `LEGACY_*` 常量，
  `rotate_log` / `_append_file` / `navdata_migrate_log` / `publish_log_migrate`，
  `_setup_console` 改落点 + `UCF_NO_LOG_TEE` 开关；`FINAL_PUBLISH_LOG` 常量**删除**
- `app/ui/env.py`、`app/core/ucf_paths.py`：注释里的日志清单
- `app/tests/test_logpaths.py`：新增第 6 节（落点 / 轮转 / 合并 / `UCF_NO_LOG_TEE`），
  并在 import 前设 `UCF_NO_LOG_TEE=1` —— 否则跑一次自检就往真日志糊一屏
- `.gitignore`、`README.md`：说明
- 删：`run/build/ucf_mod.install.log`
