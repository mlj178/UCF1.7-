## 3. 怎么用

**UCF 控制台是唯一入口**（`启动控制台.bat` → 「数据」页）：

| 控制台里的位置 | 等价命令 | 作用 |
| --- | --- | --- |
| 「数据」页四张卡（①②③④） | `navdata.py status` | 绝对路径 / 文件数 / 体积 / 最近写入时间 / 编辑条数 |
| 卡片下面那行「一致性…」 | `navdata.py diff`（同一套比法） | ①=②、②=③ 还是差几个文件 |
| 按钮 **部署到游戏 ②→③** | `navdata.py publish` | ② 开发版 → ③ 部署版 |
| 按钮 **还原原生 ①→②** | `navdata.py restore` | ① 备份版 → ② 开发版（先弹确认，开发版改动会丢） |
| 按钮 **校验备份版** | `navdata.py verify` | ① 的 SHA256 + 只读属性有没有被动过 |
| 按钮 **刷新** / 切到该页签 | `navdata.py status` | 重算四张卡（切换页签会自动刷新） |
| `tools\启动导航编辑器.bat` | `navserver.py` | 打开编辑器（编的是 ② 开发版） |

命令行（先 `cd ucf_mod\tools`）：

    python navdata.py status            三版状态（路径 / 文件数 / 大小 / 最近改动）
    python navdata.py verify            校验 ① 备份版：SHA256 + 只读属性
    python navdata.py restore           ② <- ①（丢掉开发版改动）
    python navdata.py publish           ③ <- ②（推给游戏）
    python navdata.py diff              ② vs ①、② vs ③ 差哪些文件
    python navdata.py freeze --force    用当前数据重建 ①（只在确认重新冻结时用）

## 4. 只读是怎么保证的

1. `freeze` 写完后把 ① 里每个文件 `chmod 0444`（Windows 上就是只读属性）；
2. ① 里放 `SHA256SUMS.txt`、`.frozen.json`（冻结时间 / 来源 / 文件表），`verify` 逐个比对；
3. `navdata.py` 没有任何写 ① 的代码路径 —— 只有 `freeze` 会写，而它必须先 `--force` 删旧；
4. 编辑器用 `UCF_PROFILE=native` 启动时是只读模式：`/api/save`、`/api/name` 直接返回 403，保存按钮禁用。

## 6. 和服务端的关系

`tools\ucf_paths.py` 是唯一路径真相，新增：

| 变量 | 含义 |
| --- | --- |
| `UCF_PROFILE` | `dev`（默认）/ `native` / `deploy` |
| `NATIVE` / `DEV` / `DEPLOY` | 三个根目录 |
| `DATA` | 当前生效的根（`MAPS`、`NAV` 由它派生） |
| `VIS` | **固定**指向部署版 `vis\`：插件把新导出写这里，任何版本都只读它 |
| `DATAVIS` | 当前版本自带的可走面 |
| `READONLY` | 是否是只读的备份版 |

`organize_maps.py` 的自动归档仍然读部署版 `vis\`、写当前生效版本的 `maps\`（默认开发版），
所以「游戏刚导出的新数据」照样会出现在编辑器的列表里。
