# 人机（BOT）与路线设计 · 看懂这一篇

> **给谁看**：想改人机行动路线、又不想先啃 25 万行 IL2CPP 的人。
> **回答什么**：人机的路是谁定的、由哪些东西组成、不同模式和地图差别在哪、我能改哪一层、怎么验证改成功了。
> **数据来源**：游戏原始资料（`dump.cs` 类/字段、IDA 反编译的关键函数、游戏安装目录 `UnityCrossFire_Data` 里的场景文件和 `globalgamemanagers` 的场景表）。
> 凡标 **（推断）** 的是从代码结构推出来的、没有逐帧打日志确认，旁边都给了 30 秒验证法。
> **配套文档**：每张图有什么 → [地图对照表.md](地图对照表.md)；动手画点 → [学习_路点入门.md](学习_路点入门.md)。

---

## 0. 一句话结论

**人机的路线不是"手画的一条线"，而是三样东西拼出来的：**

1. **场景里摆的点**（路点、蹲点、守点……）——决定"能站在哪"；
2. **A\* 自己连出来的边**（按距离 + 视线自动连）——决定"能走到哪"；
3. **少量手工补丁**（跳跃链接 / 节点连线 / 聚集区 / 箱子点）——修自动连不出来的地方。

所以想改路线，99% 的活儿是**摆点和连边**，不是改代码。

## 1. 三层结构

```
┌─ 行为层  BotAction（"想干什么"）
│    Saunter 闲逛 / GoCrouchPos 去蹲点 / NanoGuard 守区 / BA_PickUpUpgradeBox 抢补给
│    BA_WantInfected 想被感染(送死) / BA_BecomeHero 变英雄 / MechanicHero
│    每帧各 Action 通过 Destination_Listener 报"我想去哪 + 优先级"，最高优先级赢
├─ 寻路层  A* Pathfinding（"怎么去"）
│    Bot.Seeker → StartPath(start,end) → OnPathComplete → PathInterpolator 沿 vectorPath 走
│    途中遇到 Bot_JumpLink 就在路径里插入跳跃段；到点 1.5 米内算到达；0.25~0.5 秒重算一次
└─ 地图数据层（"地图里有什么"）—— 全部是场景里的组件
     点图节点 / 出生点 / 蹲点 / 守点 / 聚集区 / 补给箱点 / 跳跃链接 / tag 区
```

| 层 | 游戏里长什么样 | 谁决定 | 改它要动什么 |
| --- | --- | --- | --- |
| 行为层 | `Bot` 组件里一个 Action 列表 | 脚本 | Hook 或改 Action 列表（**代码层**，风险最高） |
| 寻路层 | `AstarPath` / `Seeker` 组件 | A\* 插件 + 图数据 | 改图之后重扫（`AstarPath.Scan`） |
| 地图数据层 | 场景里一堆带组件的空物体 | **关卡策划** | 摆点/挪点/改参数（**数据层**，最安全） |

**关键认识**：行为层只说"想去哪"，具体怎么绕、走哪条路，全由地图数据层决定。
**所以测路线时，你几乎不需要碰行为层**（见第 5 节）。

## 2. 目的地优先级（谁抢到"去哪"）

每帧所有 Action 都会通过 `BotEvent.RefPosition` 报一次"我想去这个点，优先级 N"，最后留下最大的那个。

| 优先级 | 常量 | 来源 | 说人话 |
| --- | --- | --- | --- |
| 999 | `GoDie` | `BA_WantInfected` | 生化里"想被感染"的兵，直接冲向幽灵送死 |
| 51 | `UpgradeBox` | `BA_PickUpUpgradeBox` | 升级箱/补给箱 |
| 50 | `SupplyBox` | 补给箱 | 捡补给 |
| 10 | `EscapeEnemy` | `NanoGuard` | 守区被压时逃跑 |
| 7 | `Saunter` | 闲逛 | 随便走走 |
| 6 | `GuardPos` | 守点/聚集区 | 回守点 |
| 5 | `Enemy` | 追敌 | 追人打 |
| 0 | `SimpleMove` | 普通移动 | 兜底 |

> **箱子 > 逃跑 > 闲逛 > 守点 > 追敌。**
> 这就是为什么生化模式里人机看到补给箱会"突然不打了"——51 盖掉一切。
> 反编译核对过：`BA_PickUpUpgradeBox` 的监听器只在 `*priority < 51` 时写入 51；
> `NanoGuard` 的监听器在"正在逃跑"时写 10、否则 `*priority < 6` 时写 6。

### 3.2 线（"能走到哪"）——**分两种，别混**

| 种类 | 是谁 / 怎么来的 | 使用场景（什么时候用） | 玩家视角表现 | 人机内部表现 |
| --- | --- | --- | --- | --- |
| **自动边** | `PointNode.connections` → `Connection{ node, cost, shapeEdge }`（步长 12 字节）；`PointGraph.Scan` 时按 `maxDistance` + 射线 + `limits` 自动连 | 所有点图，进图扫描自动生成，不用手摆 | 人机沿地面"点→边→点"走直线段，拐角贴点转向；断一条边可能绕远，断关键边就原地转圈 | 沿边直着走，A\* 按总代价选路 |
| **通用连线 `NodeLink`** | A\* 插件自带；挂在场景里把**附近已有节点**互相补连 | 同层相邻平台 / 走廊原本没连上的缝；运输船 22、生化酒店 447、新寂静村 262 | 基本看不出来——人机只是走了一条原本没连的捷径，不会腾空 | 只加边，不加点 |
| **两点连线 `NodeLink2`** | A\* 插件自带；物体 A ↔ 物体 B 直连一条边，另建 `PointGraph (used for node links)` 图放端点 | 跨缺口 / 断桥 / 矮墙；小型工厂 6（12 端点）、刀锋寨 9（18）、沙漠要塞 2 | 人机贴着地面 / 空中**平移**过缺口，**不跳、没有腾空动作**，看着像滑过去 | 沿直线过去，路径里没有跳跃段 |
| **跳跃链接 `Bot_JumpLink`** | 游戏自写 `GraphModifier`；`links[]` → `Link{ endTransform, endNode, needSpeed, accuracy, direction }`，`linkDic` 记起点节点 | 必须真跳的地方（箱子、跳台、上下层）；竞技场 21、刀锋寨 18、生化酒店 33、新寂静村 58 | 人机跑到边缘**起跳、有腾空**，落地继续跑；速度不够 / 角度不对会跳失败掉下去 | `OnPathComplete` 插跳跃段，`JumpCheck` / `Jump` 执行；`needSpeed` 决定助跑速度、`accuracy` 决定对点精度 |
| 不可走 | `GraphNode.flags` bit0（walkable） | 手动禁用节点（编辑模式里关） | 人机绕开这个点走 | A\* 直接不考虑这个点 |

**验证得到的交叉证据**（都来自场景文件统计，能互相对上）：

- 小型工厂：6 个 `NodeLink2` → 点图 12 个节点（6×2）✔
- 刀锋寨：9 个 `NodeLink2` → 点图 18 个节点（9×2），场景里 0 个 WayPoint ✔
- 沙漠要塞：8 个 WayPoint + 2 个 `NodeLink2`（4 个端点）= 12 个节点 ✔

### 3.3 面（"哪一片"）

| 种类 | 类 / 字段 | 是什么 | 出现在哪 | 玩家视角表现 | 触发 / 怎么生效 |
| --- | --- | --- | --- | --- | --- |
| **生化聚集区** | `Bot_NanoGuardArea`：`entrancePos[]`、`posList`、`neighborAreas[]`、`escapeAreas[]`、`escapePos[]` | 一块带 Trigger 的体积 + 区内守点 + 邻区 / 逃区，组成"区网" | 生化图：沙漠要塞 3、新寂静村 10 | 玩家走进守区，里面的人机开始反应（换点、集火、被压就跑）；区里的人机满员后新来的转去隔壁区 | `OnTriggerEnter/Exit` 通知区内人机（`Bot.OnEnterNanoGuardArea`）；`isFull` 看守点是否被占满 |
| **tag 区** | `PointNodeTagModifier`：`points[]`@0x20、`pathTag`@0x24 | 把落在这批坐标附近的节点打 tag（存在 `flags` bit19~23） | 只有沙漠要塞 1 个 | 几乎看不出来；如果人机 `Seeker` 配了 `traversableTags / tagPenalties`，人机会"不愿意走"某些路、绕远 | `OnLatePostScan` 打 tag；认不认取决于人机预制体上的 `Seeker` |
| 动态挖洞 / 补面 | `NavmeshCut` / `NavmeshAdd`（A\* 插件） | 运行时把一块可走面挖掉 / 补上 | 本包 11 张图都没挂 | 挂了的话：门关着人机就不过去、门开才走（电梯 / 可破坏物） | `GraphModifier` 在运行时修改可走面，进图后重建导航 |
| ~~旧守卫区~~ | `Bot_GuardArea` | 老版本守卫区 | 生化酒店 2 个 | 改了没反应 | 空类，没人用 |

### 3.4 参数（同一个点，行为不同）

| 参数 | 存在哪 | 效果 |
| --- | --- | --- |
| walkable | `GraphNode.flags` bit0 | 关掉=这个点不可走 |
| tag | `GraphNode.flags` bit19~23（掩码 `0x1F00000`） | 给点分类；惩罚值由 `Seeker.tagPenalties` 决定 |
| penalty | `GraphNode.penalty`@0x10 | 加大 = 绕开（A\* 按总代价选路） |
| cost | `Connection.cost`@0x4 | 单条边的代价 |
| needSpeed / accuracy / direction | `Bot_JumpLink.Link` | 跳跃要多少速度、多准、朝哪 |
| safety | `Bot_NanoGuardPos._safety` | 守点的"安全度"，逃/守的判断依据 |
| team | `Bot_CrouchPos.team` | 0=潜伏者（BL），1=保卫者（GR） |

## 4. 各模式需要什么（模式中文名 + 地图中文名）

模式名来自游戏自己的选图表（`sharedassets0.assets` 里一段连续字符串：模式 / 场景 / 中文名，模式只在每组第一行写一次），
地图中文名与 [地图对照表.md](地图对照表.md) 完全一致。

| GameMode | 中文 | 地图（选图表里同组） | 路线必需 | 额外 |
| --- | --- | --- | --- | --- |
| 0 `TeamDeath` | **团队模式** | 运输船 / 小型工厂 / 椰岛之巅 | 路点图 + 双方出生点 | 蹲点、跳跃/连线（可选增强）；tag（可选） |
| 1 `DeathMatch` | **个人竞技** | 胜利广场 | 路点图（或可走面）+ 出生点 | 同上 |
| 2 `Special` | **特殊战** | 竞技场 / 刀锋寨 / 死亡擂台 | 路点图 + 出生点 | **跳跃链接**为主（竞技场 21 个） |
| 3 `Nano3` | **生化模式**（推断） | 本包无对应场景 | 路点图 + 出生点 + **聚集区 + 守点** | 补给箱点位、蹲点、跳跃 |
| 4 `Nano4` | **生化剑客模式**（推断） | 生化酒店 / 沙漠要塞 | 同上 | 同上 + 抢箱/变英雄行为 |
| 5 `Nano6` | **多人生化模式**（推断） | 沙漠要塞 / 生化酒店 | 同上 | 同上 |
| 6 `Nano4_Terminator` | **终结者模式**（推断） | 新寂静村 | 同上 | 同上 + "想被感染"送死行为 |

**（推断）的 30 秒验证法**：进游戏看选图界面上模式页签的中文（或进图看左上角/结算面板）；
也能看场景里 `ModeXxx` 物体名——例如新寂静村里有 `Mode_Nano4_Terminator` 组件，说明它属于 `Nano4_Terminator` 模式。

**核心结论**：**路点图（或可走面）是所有模式共用的同一套东西**。
模式差异 = 「场景里多挂了哪些组件」+「多给它挂了哪些 Action」，不是另造一套导航。

## 5. 能不能在"启动控制台.bat"里预设人机行为？

> **已实现（2026-11-17 18:41）**：控制台里选「正式版 / 测试包 + 只对哪张图生效」，点开始游戏即可。
> 实机车测：选测试包进沙漠要塞 / 新寂静村，日志打 `pack: skip …`，人机行为一点不变；
> 不选包则与以前完全一致。

**边界（必须分清）**：

| | 能不能 | 为什么 |
| --- | --- | --- |
| 启动前决定「读哪套路线数据、只对哪张图生效」 | **能** | 这是配置，进程启动时用环境变量递进去就行 |
| 启动前决定「人机想干什么」 | **不能** | Action 列表是进图、人机被生成之后才 new 出来的对象；要改只能进图后由插件改（§5.4） |

## 7. 坑（都验证过）

1. **`Bot_GuardPos` / `Bot_GuardArea` 在本版本是死数据**：`TryGetZoomPos` 只有元数据引用、没有调用点，`Bot_GuardArea` 是空类。
   **生化酒店里那 25 个守卫点 + 2 个守卫区，改了不会有反应**；要改就改 `Bot_NanoGuardArea` / `Bot_NanoGuardPos`。
2. **有两套"地面"**：点图（`PointGraph`）和可走面（`NavMeshGraph`）。有的图只有点（运输船、生化酒店），
   有的图只有面（胜利广场、死亡擂台）。**在只有面的图上加点，人机不会去走**——它走的是三角网。
   每张图有哪套，看 [地图对照表.md](地图对照表.md) 的「原生可通行空间」表。
3. **tag 区不配参数就是死的**：`PointNodeTagModifier` 只负责打 tag，认不认取决于人机预制体上的 `Seeker`。
4. **A\* 在后台线程算路**：改图时别正好有路径在算；改完统一重扫一次，别边改边扫。
5. **换图/换模式会重载场景**：运行时的改动全部丢失，要按"进图后重放"设计（现有插件就是这么干的）。
6. **别写混淆字段**：`Bot.hangoutTag`、`Player.nanoClothCount` 这类是 Anti-Cheat 的 `Obscured*`，直接写会读出乱值。
   路线相关字段（Vector3 / Transform / 数组元素）不受影响。
