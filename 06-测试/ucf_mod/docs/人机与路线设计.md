# 人机（BOT）与路线设计 · 看懂这一篇

> **给谁看**：想改人机行动路线、又不想先啃 25 万行 IL2CPP 的人。
> **回答什么**：人机的路是谁定的、由哪些东西组成、不同模式和地图差别在哪、我能改哪一层、怎么验证改成功了。
> **数据来源**：游戏原始资料（`dump.cs` 类/字段、IDA 反编译的关键函数、游戏安装目录 `UnityCrossFire_Data` 里的场景文件和 `globalgamemanagers` 的场景表）。
> 凡标 **（推断）** 的是从代码结构推出来的、没有逐帧打日志确认，旁边都给了 30 秒验证法。
> **配套文档**：每张图有什么 → [地图对照表.md](地图对照表.md)；动手画点 → [学习_路点入门.md](学习_路点入门.md)。

## 0. 一句话结论

**人机的路线不是"手画的一条线"，而是三样东西拼出来的：**

1. **场景里摆的点**（路点、蹲点、守点……）——决定"能站在哪"；
2. **A\* 自己连出来的边**（按距离 + 视线自动连）——决定"能走到哪"；
3. **少量手工补丁**（跳跃链接 / 节点连线 / 聚集区 / 箱子点）——修自动连不出来的地方。

所以想改路线，99% 的活儿是**摆点和连边**，不是改代码。

## 1. 三层结构

```
┌─ 行为层  BotAction（"想干什么"）
│    Saunter 闲逛 / GoCrouchPos 去蹲点 / NanoGuard 守区 / BA_PickUpUpgradeBox 抢补给
│    BA_WantInfected 想被感染(送死) / BA_BecomeHero 变英雄 / MechanicHero
│    每帧各 Action 通过 Destination_Listener 报"我想去哪 + 优先级"，最高优先级赢
├─ 寻路层  A* Pathfinding（"怎么去"）
│    Bot.Seeker → StartPath(start,end) → OnPathComplete → PathInterpolator 沿 vectorPath 走
│    途中遇到 Bot_JumpLink 就在路径里插入跳跃段；到点 1.5 米内算到达；0.25~0.5 秒重算一次
└─ 地图数据层（"地图里有什么"）—— 全部是场景里的组件
     点图节点 / 出生点 / 蹲点 / 守点 / 聚集区 / 补给箱点 / 跳跃链接 / tag 区
```

| 层 | 游戏里长什么样 | 谁决定 | 改它要动什么 |
| --- | --- | --- | --- |
| 行为层 | `Bot` 组件里一个 Action 列表 | 脚本 | Hook 或改 Action 列表（**代码层**，风险最高） |
| 寻路层 | `AstarPath` / `Seeker` 组件 | A\* 插件 + 图数据 | 改图之后重扫（`AstarPath.Scan`） |
| 地图数据层 | 场景里一堆带组件的空物体 | **关卡策划** | 摆点/挪点/改参数（**数据层**，最安全） |

**关键认识**：行为层只说"想去哪"，具体怎么绕、走哪条路，全由地图数据层决定。
**所以测路线时，你几乎不需要碰行为层**（见第 5 节）。

## 2. 目的地优先级（谁抢到"去哪"）

每帧所有 Action 都会通过 `BotEvent.RefPosition` 报一次"我想去这个点，优先级 N"，最后留下最大的那个。

| 优先级 | 常量 | 来源 | 说人话 |
| --- | --- | --- | --- |
| 999 | `GoDie` | `BA_WantInfected` | 生化里"想被感染"的兵，直接冲向幽灵送死 |
| 51 | `UpgradeBox` | `BA_PickUpUpgradeBox` | 升级箱/补给箱 |
| 50 | `SupplyBox` | 补给箱 | 捡补给 |
| 10 | `EscapeEnemy` | `NanoGuard` | 守区被压时逃跑 |
| 7 | `Saunter` | 闲逛 | 随便走走 |
| 6 | `GuardPos` | 守点/聚集区 | 回守点 |
| 5 | `Enemy` | 追敌 | 追人打 |
| 0 | `SimpleMove` | 普通移动 | 兜底 |

> **箱子 > 逃跑 > 闲逛 > 守点 > 追敌。**
> 这就是为什么生化模式里人机看到补给箱会"突然不打了"——51 盖掉一切。
> 反编译核对过：`BA_PickUpUpgradeBox` 的监听器只在 `*priority < 51` 时写入 51；
> `NanoGuard` 的监听器在"正在逃跑"时写 10、否则 `*priority < 6` 时写 6。

## 3. 路线元素清单（点 / 线 / 面 / 参数 / 行为）

### 3.1 点（"能站在哪"）

| 种类 | 类 / 关键字段 | 谁用 | 备注 |
| --- | --- | --- | --- |
| **A\* 路点（核心）** | `PointNode`（`position`@0x14、`connections`@0x20、`gameObject`@0x24） | 所有寻路 | 每个路点 = 场景里一个对象；位置是毫米整数（`Int3`，÷1000 得米） |
| 出生点 | `MapManager.SP_BL / SP_GR / SP_Netural`、`pointDic` | 回合开始/重生 | 团队图必挂；BL/GR 各自轮流取 |
| 补给箱点位 | `SP_SupplyBox / SP_RedBox / SP_BlueBox` + `SupplyBox` 实例 | 生化 | 箱子类型 Yellow=0 / Red=1 / Blue=2 |
| 蹲点 | `Bot_CrouchPos`（`team`@0xC、`zoomPos[]`@0x10、`crouchDisabled`、`always`） | `GoCrouchPos` | 分 BL/GR 两个静态表，`GetRandomPos(team)` 随机取 |
| 生化守点 | `Bot_NanoGuardPos`（`zoomPos[]`@0x10、`_safety`@0x1C、`area`@0xC） | `NanoGuard` | 必须挂在 `Bot_NanoGuardArea` 下才会被收集 |
| 聚集区入口 | `Bot_NanoGuardArea.entrancePos[]`@0xC | `NanoGuard` | 数组，可以有多个入口 |
| 逃跑点 | `Bot_NanoGuardArea.escapePos[]`@0x1C | `NanoGuard` | 守区被压时用（优先级 10） |
| ~~旧守卫点~~ | `Bot_GuardPos` / `Bot_GuardArea` | **没人用** | 见第 7 节"坑" |

### 3.2 线（"能走到哪"）——**分两种，别混**

| 种类 | 是谁 | 怎么来的 | 人机的表现 |
| --- | --- | --- | --- |
| **自动边** | `PointNode.connections` → `Connection{ node, cost, shapeEdge }`（步长 12 字节） | `PointGraph.Scan` 时按 `maxDistance`（距离）+ 射线（视线）+ `limits` 自动连 | 沿边直着走 |
| **通用连线 `NodeLink`** | A\* 插件自带组件 | 挂在场景里，把**附近已有节点**互相补连 | 只加边，不加点 |
| **两点连线 `NodeLink2`** | A\* 插件自带组件 | 物体 A ↔ 物体 B 直接连一条边；A\* 会为此新建一张叫 `PointGraph (used for node links)` 的图来放端点 | 跨缺口/翻越用，沿直线过去，**没有跳跃动作** |
| **跳跃链接 `Bot_JumpLink`** | 游戏自己写的 `GraphModifier` | `links[]` → `Link{ endTransform, endNode, needSpeed, accuracy, direction }` | 路径经过它时，`Bot.OnPathComplete` 插入跳跃段，**人机会真的起跳** |
| 不可走 | `GraphNode.flags` bit0（walkable） | 扫描或手动写 | 绕开这个点 |

**验证得到的交叉证据**（都来自场景文件统计，能互相对上）：

- 小型工厂：6 个 `NodeLink2` → 点图 12 个节点（6×2）✔
- 刀锋寨：9 个 `NodeLink2` → 点图 18 个节点（9×2），场景里 0 个 WayPoint ✔
- 沙漠要塞：8 个 WayPoint + 2 个 `NodeLink2`（4 个端点）= 12 个节点 ✔

### 3.3 面（"哪一片"）

| 种类 | 类 / 字段 | 作用 |
| --- | --- | --- |
| **生化聚集区** | `Bot_NanoGuardArea`：`entrancePos[]`、`posList`、`neighborAreas[]`、`escapeAreas[]`、`escapePos[]` | 一块区域 + 若干守点；带相邻区和逃跑区，组成"区网"。进出触发通知人机 |
| **tag 区** | `PointNodeTagModifier`：`points[]`@0x20、`pathTag`@0x24 | 把落在这批坐标上的节点打 tag（tag 存在 `flags` 的 bit19~23）。**只有人机预制体上的 `Seeker.traversableTags / tagPenalties` 认它才有意义** |
| 动态挖洞/补面 | `NavmeshCut` / `NavmeshAdd` | 运行时把某块可走面挖掉/补上（本包场景里没挂） |
| ~~旧守卫区~~ | `Bot_GuardArea` | 空类，没人用 |

### 3.4 参数（同一个点，行为不同）

| 参数 | 存在哪 | 效果 |
| --- | --- | --- |
| walkable | `GraphNode.flags` bit0 | 关掉=这个点不可走 |
| tag | `GraphNode.flags` bit19~23（掩码 `0x1F00000`） | 给点分类；惩罚值由 `Seeker.tagPenalties` 决定 |
| penalty | `GraphNode.penalty`@0x10 | 加大 = 绕开（A\* 按总代价选路） |
| cost | `Connection.cost`@0x4 | 单条边的代价 |
| needSpeed / accuracy / direction | `Bot_JumpLink.Link` | 跳跃要多少速度、多准、朝哪 |
| safety | `Bot_NanoGuardPos._safety` | 守点的"安全度"，逃/守的判断依据 |
| team | `Bot_CrouchPos.team` | 0=BL，1=GR |

### 3.5 行为层（"各类人机想要什么"）

`Bot.Awake` 里固定创建一串 Action（反编译可见逐个构造）：

| Action | 触发条件（要点） | 优先级 |
| --- | --- | --- |
| `Saunter` | 没敌人/没在打 | 7 |
| `CrabStep` | 交火时左右碎步 | — |
| `NanoGuard` | 生化、有守区 | 6（逃跑 10） |
| `BA_PickUpUpgradeBox` | 生化、场上有对应颜色箱子、自己是英雄/幽灵 | 51 |
| `BA_WantInfected` | 终结者局非战局回合、自己是兵、士兵太多 | 999 |
| `BA_BecomeHero` | 生化、能变英雄 | — |
| `GoCrouchPos` | 出生延迟事件触发 | — |
| `MechanicHero` | 变身机械英雄时追加 | — |

> **小彩蛋（推断）**：`Bot.Awake` 里有一次 `RandomRangeInt(0,20)==10`（约 5%）把人机扔进 `hangoutList` 变成"挂机人机"，上限由 `maxHangoutCount` 控制。
> **验证法**：进图看有没有人机站着不动且不巡逻；或 hook `Bot.Awake` 打印是否进表。

## 4. 各模式需要什么（模式中文名 + 地图中文名）

模式名来自游戏自己的选图表（`sharedassets0.assets` 里一段连续字符串：模式 / 场景 / 中文名，模式只在每组第一行写一次），
地图中文名与 [地图对照表.md](地图对照表.md) 完全一致。

| GameMode | 中文 | 地图（选图表里同组） | 路线必需 | 额外 |
| --- | --- | --- | --- | --- |
| 0 `TeamDeath` | **团队模式** | 运输船 / 小型工厂 / 椰岛之巅 | 路点图 + 双方出生点 | 蹲点、跳跃/连线（可选增强）；tag（可选） |
| 1 `DeathMatch` | **个人竞技** | 胜利广场 | 路点图（或可走面）+ 出生点 | 同上 |
| 2 `Special` | **特殊战** | 竞技场 / 刀锋寨 / 死亡擂台 | 路点图 + 出生点 | **跳跃链接**为主（竞技场 21 个） |
| 3 `Nano3` | **生化模式**（推断） | 本包无对应场景 | 路点图 + 出生点 + **聚集区 + 守点** | 补给箱点位、蹲点、跳跃 |
| 4 `Nano4` | **生化剑客模式**（推断） | 生化酒店 / 沙漠要塞 | 同上 | 同上 + 抢箱/变英雄行为 |
| 5 `Nano6` | **多人生化模式**（推断） | 沙漠要塞 / 生化酒店 | 同上 | 同上 |
| 6 `Nano4_Terminator` | **终结者模式**（推断） | 新寂静村 | 同上 | 同上 + "想被感染"送死行为 |

**（推断）的 30 秒验证法**：进游戏看选图界面上模式页签的中文（或进图看左上角/结算面板）；
也能看场景里 `ModeXxx` 物体名——例如新寂静村里有 `Mode_Nano4_Terminator` 组件，说明它属于 `Nano4_Terminator` 模式。

**核心结论**：**路点图（或可走面）是所有模式共用的同一套东西**。
模式差异 = 「场景里多挂了哪些组件」+「多给它挂了哪些 Action」，不是另造一套导航。

## 5. 能不能在"启动控制台.bat"里预设人机行为？

> **已实现（2026-11-17 18:41）**：控制台里选「正式版 / 测试包 + 只对哪张图生效」，点开始游戏即可。
> 实机车测：选测试包进沙漠要塞 / 新寂静村，日志打 `pack: skip …`，人机行为一点不变；
> 不选包则与以前完全一致。

**边界（必须分清）**：

| | 能不能 | 为什么 |
| --- | --- | --- |
| 启动前决定「读哪套路线数据、只对哪张图生效」 | **能** | 这是配置，进程启动时用环境变量递进去就行 |
| 启动前决定「人机想干什么」 | **不能** | Action 列表是进图、人机被生成之后才 new 出来的对象；要改只能进图后由插件改（§5.4） |

### 5.1 这个 bat 现在到底做什么

`tools\启动控制台.bat` 只有一件事：找到 `pythonw`，打开 `控制台.pyw`（开关面板）。它不碰游戏进程。

真正管事儿的是三件事：

| 动作 | 谁做 | 结果 |
| --- | --- | --- |
| 面板勾选 / 选测试数据 | `控制台.pyw` → 写 `ucf_mod\ucf_mod.json` | 开关进配置；测试包选择也在里面（插件不读这段，只是记忆） |
| 面板点"开始游戏" | 给子进程加 `UCF_MOD=1`（+ 测试包的两个变量） | 只有这么启动，`ucf_mod.dll` 才干活；双击 exe = 原版 |
| 进图 | `ucf_mod.dll` 挂进 il2cpp | 读配置、采点、按"数据来源"读 `nav\` 或 `packs\<包名>\`，指纹不符就跳过 |

### 5.2 已实现：正式版 ↔ 测试包

```
<游戏目录>\ucf_mod\
├── nav\                       正式版：不选包时读这里（一直以来的行为）
└── packs\
    ├── chain_a\               测试包：只对某一张图生效
    │     n0-0000000000000000.txt
    │     manifest.json
    └── chain_b\
```

| 环境变量 | 谁设 | 作用 |
| --- | --- | --- |
| `UCF_PACK` | 控制台 | 读 `packs\<包名>\`；不设 = 读 `nav\` |
| `UCF_FP` | 控制台 | 只有当前场景指纹等于它才套用，**别的图整包跳过** |
| `UCF_FPLABEL` | 控制台 | 只用于 HUD / 日志显示（图的中文名） |

HUD 第 5 行会固定写明数据来源，出问题先看这一行：

- `数据 正式版（nav）`
- `数据 测试包 chain_a · 只对 暴风 生效 · 包内 0 项改动`
- `数据 测试包 chain_a · 只对 暴风 生效 · 当前图已跳过`

**三个切换时点**

| 时点 | 操作 | 生效 |
| --- | --- | --- |
| 启动前（推荐） | 控制台 → 测试数据 → 选包 + 选图 → 开始游戏 | 进图即生效 |
| 游戏运行中 | 改包里的 `<指纹>.txt` 后按 `Ctrl+Shift+R` | 重读当前图（换包要重开游戏，环境变量在启动时定死） |
| 验证通过 | `navdata.py pack promote <包名>` | 备份旧文件后写进正式版 `nav\` |

### 5.3 只改地图测一条路线（推荐路径，零代码）

1. **选图**：新手用暴风（原生 0 点，插件铺的点可用 `nogen.txt` 关掉）；要真实感用运输船（786 点）。
2. **画/改**：编辑器里把测试链连成"唯一通路"（删掉别的边，或把那些点设成不可走）→ `Ctrl+S` 保存（进开发版）。
3. **存包**：顶栏 **存为测试包** → 填 `chain_a` → 包里只含这张图的改动。
4. **启动**：控制台 → 测试数据 → 测试包 `chain_a` → 地图选同一张 → 开始游戏。
5. **判定**：按第 6 节的表看人机走位；HUD 第 5 行确认"已套用"而不是"已跳过"。

> 这五步的意义：把"人机想干什么"变成常量，剩下的变量只有"路线通不通"。

### 5.3.1 空白底图：原生点全禁用，从 0 画（2026-11-17 20:52）

上面 5.3 是「在原生路线上改」；如果要从**一张完全空白的图**开始设计，用空白底图测试包：

1. **建包**：控制台「测试数据」选好地图 → **新建空白包**（填 ASCII 包名）。
   会生成 `packs\<包名>\<指纹>.txt`（只有表头 + `blank`）、`nogen.txt`（关自动铺点）、`manifest.json`。
2. **进图**：控制台选中这个包 + 同一张图 → **开始游戏**。HUD 第 5 行会显示
   `数据 测试包 <包名> · 只对 <图> 生效 · 包内 N 项改动 · 空白底图`。
3. **画**：**不再需要网页编辑器**，直接在游戏里画：
   - `Ctrl+Shift+N` 准星处加点；
   - `Ctrl+Shift+A` 选中起点 A，`Ctrl+Shift+J` 把 A 和准星点连/断；
   - `Ctrl+Shift+D` 删准星点，`Ctrl+Shift+Z` 撤销；
   - 每次改动自动写回 `packs\<包名>\<指纹>.txt`（只写测试包，正式版一个字节不动）。
4. **控制台里的应用/载入**（「测试数据」页，游戏运行中不用重启）：
   - **载入到游戏**：把当前包（空白底图）切到正在跑的地图；
   - **重新应用**：重读 `packs` 里的 txt 再套一遍（外部改过文件时用）；
   - **保存路线**：让游戏把内存里的改动写回文件（正常加点/删点已经自动存）；
   - **清空当前图**：把当前包重写成表头 + `blank`，从 0 重画；
   - **回正式版**：还原原生底图并改读 `nav\`。
   这五个按钮通过 `<插件目录>\ucf_navcmd.txt` 传给插件；插件每 0.5 s 查一次 seq，
   不会在游戏里弹窗，也不要求重启。
5. **改**：在游戏里继续加点/连线；控制台点「重新应用」可强制重读文件。

**机制**：插件读到 `blank` 后，先把这张图的原生节点全部标不可走、摘掉连接，
再把文件里的 `node add` / `edge add` 套上去 —— 所以原生路线不会漏回来。
第一次套用前会拍一份原生底图快照（位置 / 可走位 / 连接，连接按 nodeIndex 存），
所以运行中切包、回正式版时能先还原再套新文件；场景重建后快照仍按 index 还原，不会指到旧对象。
`nogen.txt` 让插件不自动铺路点；没有它的话，暴风这种 0 点图会被自动填满。
空白底图**不能** `pack promote` 到正式版（正式版没有清空整张图的机制，会拒绝）。

> **范围**：blank 清的是**路点图 PointGraph**。运输船 / 生化酒店 / 暴风这种只有点图的图，
> 清完就是真正完全空白；胜利广场 / 死亡擂台这种同时有 **NavMeshGraph** 可走面的图，
> 原生可走面还在（那层是烘焙三角网，不在 `blank` 的清理范围）。  
> 所以「完全空白」测试请优先用**运输船**（786 点、无 NavMeshGraph）。

### 5.4 真要强制行为：三个挂点（进图之后）

| 想达到的效果 | 挂哪个函数（RVA，VA=+0x10000000） | 怎么做 |
| --- | --- | --- |
| 不让人机抢箱/守区 | `BA_PickUpUpgradeBox.CanDo` / `NanoGuard.Update` | attach 后改返回值 / 跳过 |
| 强制所有人机去某个点 | `Seeker.StartPath(Vector3,Vector3,callback)` `0x105A4260` | attach 后改写第 2 个参数（终点） |
| 让路径"绕一下" | `Bot.OnPathComplete` | attach 后改 `path.vectorPath` |
| 清空/替换行为 | `Bot.Awake` 之后 | 清 `actionList`（`Bot.actionList`@0x58）再塞自己的 |

> ⚠️ 游戏带 CodeStage Anti-Cheat Toolkit，`Interceptor.replace` 有被还原的先例（整合包里 42 号功能因此改成纯数据写入）。
> **优先数据写，少用 replace。**

## 6. 怎么判断"我画的路线成了"

进图后给每台人机记 3 个量就够了：**位置**、**当前路径点数**、**下一个目标点**。

| 现象 | 说明 | 先查什么 |
| --- | --- | --- |
| 按预期顺序走完全程 | 链通了 | —— |
| 走到某个点后停住 | 后面断了 | 该点之后有没有边；边长是否超过 `maxDistance`（本游戏多数图 2.1 米）；射线被墙挡住 |
| 原地一步不动 | 这个点是孤立的 | 点有没有边；`walkable` 是不是 0；点是不是埋在墙里 |
| 绕远路 | 有更短的边 | 用编辑器看有没有"穿墙的假边" |
| 来回抖动 | 两个点太近 / 边上成环 | 人机 0.25~0.5 秒重算一次，环会导致反复变道 |
| 明明该走却"穿墙" | 边穿墙（射线没拦住） | 该边两点之间加一道墙/挪点 |

**自动化**：`src\autotest.c` 已经能不用鼠标键盘把游戏切到指定关卡（`UCF_AUTOTEST=7,10`，
序号见 [地图对照表.md](地图对照表.md)）。想批量验证路线，最省事的是在这里加一段：
每 tick 把所有人机的坐标打进日志，再和期望链做比对。

## 7. 坑（都验证过）

1. **`Bot_GuardPos` / `Bot_GuardArea` 在本版本是死数据**：`TryGetZoomPos` 只有元数据引用、没有调用点，`Bot_GuardArea` 是空类。
   **生化酒店里那 25 个守卫点 + 2 个守卫区，改了不会有反应**；要改就改 `Bot_NanoGuardArea` / `Bot_NanoGuardPos`。
2. **有两套"地面"**：点图（`PointGraph`）和可走面（`NavMeshGraph`）。有的图只有点（运输船、生化酒店），
   有的图只有面（胜利广场、死亡擂台）。**在只有面的图上加点，人机不会去走**——它走的是三角网。
   每张图有哪套，看 [地图对照表.md](地图对照表.md) 的「原生可通行空间」表。
3. **tag 区不配参数就是死的**：`PointNodeTagModifier` 只负责打 tag，认不认取决于人机预制体上的 `Seeker`。
4. **A\* 在后台线程算路**：改图时别正好有路径在算；改完统一重扫一次，别边改边扫。
5. **换图/换模式会重载场景**：运行时的改动全部丢失，要按"进图后重放"设计（现有插件就是这么干的）。
6. **别写混淆字段**：`Bot.hangoutTag`、`Player.nanoClothCount` 这类是 Anti-Cheat 的 `Obscured*`，直接写会读出乱值。
   路线相关字段（Vector3 / Transform / 数组元素）不受影响。
