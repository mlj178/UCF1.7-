# 路点入门 · 90 分钟动手课（0 基础）

> 全部操作都在**练习场**里做，练习场是空的、指纹是假的，**画坏了不影响任何真地图**。
> 编辑器里点顶栏「新手引导」按钮，会一步一步提示；本文件是它的完整版（含"为什么"）。

---

## 0. 你要先记住三个词

| 词 | 一句话 | 例子 |
| --- | --- | --- |
| **点（node / 路点）** | 人能站住的一个位置 | 大厅里 (3.5, 0, -7.2) 这个位置 |
| **边（edge）** | 两个点之间能**直着走过去** | A 点和 B 点之间没有墙、距离够近，就连一条边 |
| **指纹（fingerprint）** | 这张图上所有点坐标算出来的一个校验码 | `n786-57a46e3465c847cb` |

游戏里的机器人（幽灵、BOT）就是沿着这些点和边走路的。**没有点，它就不会动；没有边，它就走不过去。**

## 第 0 课 · 心智模型（5 分钟，不动手）

想象一张俯视的地图：

```
    A ────── B          A、B、C、D = 路点（点）
    │        │          A─B、B─D、D─C、C─A = 边
    │        │          中间的方块 = 墙
    C ────── D
```

- 机器人从 A 出发想去 D，它只会沿着**边**走：A→B→D 或 A→C→D。
- 如果你只放了 A、B、C、D 却没连边，机器人会**站在原地**（因为它不知道怎么走过去）。
- 如果你把一条边连到了墙的两边，机器人会**撞墙**（因为边代表"能直着走"，这条边是假的）。

**✅ 自检**：如果一张图有 100 个点、0 条边，机器人能走路吗？
（答：不能。点只是"位置候选"，边才是"路"。）

## 第 1 课 · 打开练习场（10 分钟）

**动手**

1. 双击 `ucf_mod\tools\启动导航编辑器.bat`，浏览器会自动打开编辑器。
2. 看左边「打开」区域，有一组叫 **练习场（空白）**，点它下面的那一行。
3. 中间出现一块灰色空地，右边出现 3D 场景。

**你会看到**

- 顶栏右边：`节点 0` `边 0`（这就是这张图的全部内容）。
- 右上方 3D：一块 40×40 的空地、3 个箱子、5 级台阶、一根柱子。

**为什么**

练习场是专门造出来的空图，它的指纹是 `n0-0000000000000000`——意思是"这张图本来一个路点都没有"。
所以你在上面加的任何东西都是**从零开始**的，不会覆盖任何真实数据。

**顺手动一动（不记录成绩，纯熟悉）**

- 中间 2D：滚轮缩放、按住左键拖动平移。
- 右边 3D：**右键**拖动转视角、滚轮拉近。
- 左栏「显示」里把「地形」勾掉再勾上，看看有什么区别。

**✅ 自检**：顶栏的「节点 0 / 边 0」分别代表什么？
（答：这张图现在有 0 个路点、0 条边。）

## 第 2 课 · 放点（15 分钟）

**动手**

1. 左栏「编辑」里点 **加点**（快捷键 <kbd>A</kbd>）。
2. 在中间空地上**单击**一下。

**你会看到**

- 出现一个小点，顶栏从 `节点 0` 变成 `节点 1`。
- 点被选中，左栏「点信息」显示它的坐标，比如 `p = (2.50, 0.00, -4.00)`。

**关键的三个数字**

- 第一个数字 = 东西方向（X），第二个 = **高度（Y）**，第三个 = 南北方向（Z）。
- **1 个单位 = 1 米**。箱子高 1.5 m，台阶每级 0.25 m，你可以用这些参照物判断坐标对不对。
- Y 是高度：站在地面上的点 Y≈0；站在 1.5 m 高的箱子上，Y 应该≈1.5。

**动手（继续）**

3. 再点 3 下，把 4 个点摆成一个大概 10×10 米的方框（顶栏 `节点 4`）。
4. 选中一个点，把左栏「高度 Y」改成 `0`，点「设」——它会被抬到/压到地面高度。
5. 选中一个点，点「落地」：编辑器会沿着地形往下打一条射线，把点**贴到地板/箱子顶上**。

**常见错误**

- 点在 3D 里看是悬空的 → 说明 Y 不对，用「落地」修。
- 点跑到墙里面 → 换个位置放，或者先删掉重放。

**✅ 自检**：站在 1.5 m 的箱子上，这个点的 Y 大概应该是多少？
（答：约 1.5。）

---

## 第 3 课 · 连线（15 分钟）

**动手**

1. 点 **连线**（<kbd>E</kbd>）。
2. 先点 A 点，再点 B 点 —— 两点之间出现一条边。
3. 依次把 A→B、B→C、C→D、D→A 连起来，形成一圈。顶栏 `边 4`。

**你会看到**

- 边是另一种颜色，鼠标放上去会显示长度。
- 「显示」里关掉「连接边」，边就消失了（只是不画，不是删掉）。

**为什么边不能乱连**

| 规则 | 为什么 |
| --- | --- |
| 两点之间要"能直着走过去" | 边代表一条真实可走的路，穿墙的边会让机器人撞墙 |
| 太长要拆成几段 | 游戏里 A* 的 `maxDistance` 是 2.1 m（部分图 4.6 m），超过就不认这条边 |
| 上下楼层要分开 | 一层楼的点和二层的点直接连起来，机器人会"穿楼板" |

所以真实地图里，一条长长的走廊会被拆成很多个点、每段 1~2 m。

**动手（继续）**

4. 故意连一条"穿墙"的边：把箱子左边的点和右边直接连起来。
5. 点 **孤立点**（<kbd>G</kbd>）：它会告诉你有没有"一个边都没有的点"，有的话标红。

**✅ 自检**：一条 5 米长的边，游戏会认吗？
（答：不认。超过 maxDistance（2.1 m 或 4.6 m）就会被丢弃 —— 拆成 3 段更稳。）

## 第 4 课 · 改坏，再修好（10 分钟）

**动手**

1. 选中一个点 → 点 **删点**（<kbd>Delete</kbd>）。
2. 你会看到：点没了，**连着它的两条边也一起没了**（因为边不能只有一头）。
3. 点 **撤销**（<kbd>Ctrl</kbd>+<kbd>Z</kbd>）：点回来，边也回来。
4. 点 **重做**（<kbd>Ctrl</kbd>+<kbd>Y</kbd>）：再删一次。
5. 撤销回去。

**为什么**

- 编辑器的每一步都是一次可撤销的操作，你可以放心试。
- 删点会连带删边，这是**正确行为**，不是 bug。

**还有一个按钮：可走（W）**

它**不是删除**。按下后这个点变成**红方块 = 不可走**（`walk=0`）：点和边都还在，只是告诉机器人"别把这里当落脚点"。

| 你想干什么 | 点哪个 | 结果 |
|---|---|---|
| 这个点不要了 | **删点**（`Delete`） | 点**真的消失**，连着的边一起断（`Ctrl+Z` 撤回） |
| 点留着，机器人别来 | **可走**（`W`） | 点变红，还在；再按一次恢复 |
| 自己加的点加错了 | **删点** | 一样消失，保存后清单里那条 `node add` 也没了 |

红点（不可走）**不能连边** —— 连了也没意义，游戏会忽略它；要连就先按 `W` 恢复。

> 注意：v1 格式只记 `node add/del`、`edge add/del` 四种，**不记录 walk**。
> 对游戏里原有的点，"不可走"保存后会写成 `node del` —— 游戏里它真的就没了。

**✅ 自检**：删掉一个连着 3 条边的点，会少几条边？
（答：3 条。）

## 第 5 课 · 保存：看它到底写了什么（10 分钟）

**动手**

1. 点顶栏 **保存并应用**（<kbd>Ctrl</kbd>+<kbd>S</kbd>）。
2. 打开 `ucf_mod\nav\` 文件夹，找到 **n0-0000000000000000.txt**，用记事本打开。

**你会看到**类似这样几行：

```
# ucf-navedit v1 fp=n0-0000000000000000
node add 2.50 0.00 -4.00
node add 12.50 0.00 -4.00
edge add 2.50 0.00 -4.00 12.50 0.00 -4.00
```

**三个必须懂的点**

1. **它只写"改动"，不写整张图**。
   加一个点写一行 `node add`，连一条边写一行 `edge add`，删一个点写 `node del`。
2. **文件名就是指纹**。
   游戏进图时先算这张图的指纹，再去 `nav\<指纹>.txt` 找改动。指纹对不上 = 改动不会生效（这是保护机制，防止套错图）。
3. **坐标为 0.01 精度**，误差 0.35 m 以内算同一个点。

**✅ 自检**：为什么编辑文件不能用"地图中文名"命名？
（答：中文名可能重复/改；指纹是这张图所有点坐标算出来的，天然唯一且能防止套错图。）

## 第 6 课 · 进游戏验证（15 分钟）

> 这一课会真的进游戏。用**暴风**（隐藏图）做验证台：它本来就没有官方路点，坏了也不心疼。

**准备工作（做一次就行）**

1. 关掉游戏。
2. 打开 `ucf_mod\nav\` 文件夹，新建一个**空文本文件**，文件名改成 `nogen.txt`
   （记事本里"另存为"，文件名填 `nogen.txt`，保存类型选"所有文件"，内容留空）。
3. 这个文件的意思是：**插件不要在暴风上自动铺那 694 个点**。删掉它，694 个点就会回来。

**动手**

4. 启动游戏，用你原来的方式进 **暴风**。
5. 编辑器这边**不用切图**，继续停在「练习场（空白）」就行——但要看一眼顶栏「目标指纹」是不是 `n0-0000000000000000`。
   （暴风在 `nogen.txt` 生效后一个点都没有，它的指纹就正好是 `n0-0000000000000000`；
   所以你在练习场里画的东西，进暴风后会原样出现。这就是把空图当草稿纸的原理。）
6. 按第 2、3 课的方法，画 4 个点和 4 条边。
7. 保存并应用；「目标指纹」选 `n0-0000000000000000`。
8. 切回游戏，按 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd> **重新套用**。
9. 按 <kbd>Ctrl</kbd>+<kbd>V</kbd> 打开可视化，你应该在游戏里看到自己画的 4 个点和 4 条线。

**你会看到（HUD 上）**

- 第 4 行：`导出 点4 边4 n0-...` 之类，说明插件认到了你的数据。
- 第 5~7 行：最近日志（<kbd>Ctrl</kbd>+<kbd>M</kbd> 开关）。看不到日志再也不用去翻文件了。

**收尾**

10. 验证完，把 `nogen.txt` 删掉，下次进暴风 694 个点自动回来。

**✅ 自检**：为什么保存后要在游戏里按 Ctrl+Shift+R，而不是重启游戏？
（答：插件在进图时套用一次；改完文件后按 R 是"重新读一遍并套用"，比重启快。）

## ★ 毕业任务（10 分钟）

给暴风铺一条**从 A 点到 B 点的小路**，要求：

1. 5 个点，连成一条线（每段 1~2 m，不要超过 2.1 m）。
2. 每个点都要"落地"（不要悬空、不要穿墙）。
3. 保存 → 进游戏按 Ctrl+Shift+R → 用 Ctrl+V 看到这条线 → 走一遍，确认能沿路走通。
4. 做完把 `nogen.txt` 删掉。

做完这一套，你已经会：**看坐标、放点、连线、判断合理性、保存、进游戏验证**。
这正好是给任何一张真图加路点的全部流程。

## 卡住了怎么办

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 地图列表里没有「练习场」 | 服务没起 / 文件被移走 | 重开 `启动导航编辑器.bat`；跑 `python tools/make_practice.py` 重新生成 |
| 3D 里只有点，没有地形 | 没有 `geo/web/practice.bin` | 跑 `python tools/make_practice.py` |
| 保存报错"目标指纹" | 没选目标 | 「目标指纹」下拉里选 `n0-0000000000000000` |
| 游戏里没有变化 | 没按 Ctrl+Shift+R / 指纹对不上 | 看 HUD 第 4 行的指纹是否和文件一致 |
| 顶栏一直显示"离线" | 没连上本地服务 | 重开 bat，确认浏览器地址是 `127.0.0.1:8765` 开头 |

## 名词表

| 名词 | 含义 |
| --- | --- |
| 路点 / node | 机器人可以站的位置 |
| 边 / edge | 两个路点之间能直着走过去 |
| 孤立点 | 一条边都没有的点，机器人不会去 |
| walk | 这个点是否"可走" |
| tag / 特征 | 出生点、补给箱、蹲守点这类特殊标记（不是路点本身） |
| 指纹 / fp | 整张图坐标的校验码，用来把编辑文件配到对的图 |
| maxDistance | A* 允许连边的最大距离（本游戏 2.1 m / 4.6 m） |
| 采集模式 | 进图自动把这张图的路点导出成 JSON（Ctrl+Shift+X） |
