# UCF 插件 · 部署与直读总览

> 一句话：游戏目录只放"必须有的文件"（加载器 + 本体补丁），插件、配置、日志、路点、地图数据全在工程端。

| | 位置 | 放什么 | 进 git |
|---|---|---|---|

| **游戏目录** | `D:\...\UnityCrossFire1.7.1\` | `winhttp.dll`、`winhttp_orig.dll`、`UnityCrossFire_Data` 里的本体补丁 | ❌ |

## 二、一键部署到底做什么

控制台「部署」页 / 命令行 `deploy_mod.py` 只铺两类"游戏目录必须有的文件"：

1. **加载器**：`winhttp.dll` + `winhttp_orig.dll`
   - 游戏只会从自己目录加载 `winhttp.dll`；这个 52 KB 代理只负责读 `UCF_MOD_DLL` 并把工程端的插件拉进来。
2. **游戏本体补丁**：`run\gamepatch\<包>\patch.json` 里登记的文件
   - 例如 `10_Nano30_Storm飓风危城` 的 `UnityCrossFire_Data/level9`；
   - 例如 `12_TestMap12龙城` 的 `level12` / `sharedassets12*` / `globalgamemanagers`。

### 状态

| 字样 | 意思 | 部署动作 |
|---|---|---|
| 一致 | 已经是目标文件 | 跳过 |
| 原版 | 哈希等于 patch.json 的 `orig.sha256`（或是已知旧加载器） | 备份 → 覆盖 → 写后校验 |
| 新增 | 目标不存在，且 patch.json 的 `orig` 为 null | 直接写入 |
| 缺失 | 目标不存在，但 patch.json 要求有原版 | **拒绝**（先找原版文件） |
| 冲突 | 既不是原版，也不是我们的补丁 | **拒绝**，零写入 |
| 已禁用 | 该地图开关没开（如龙城） | 跳过；要铺加 `--all-packs` |

### 备份 / 清单 / 卸载

- 覆盖前备份：`run\deploy_backup\<game_id>\<时间>\<相对路径>`
- 部署清单：`run\runtime\deploy\<game_id>.json`
- 卸载：按清单还原（优先现场备份，其次 `patch.json` 的 `orig_file` 包内原件），新增文件删除；
- **都不写游戏目录**。

## 三、启动时从工程端直读

控制台「开始游戏」注入：

```text
UCF_MOD=1
UCF_MOD_DLL=<工程>\run\build\ucf_mod.dll
UCF_MOD_DIR=<工程>\run\runtime
UCF_LOG_DIR=<工程>\log
UCF_MARKERS_DIR=<工程>\data\navdata\dev\markers
UCF_EXPORT_DIR=<工程>\data\navdata\dev\vis
UCF_PACK_DIR=<工程>\data\navdata\dev\packs
```

插件启动日志第一行会写明：

```text
log: dir=...\log env=1 fallback=0 mod=...\run\runtime
```

- `mod=` 必须是工程端 `run\runtime`；
- 游戏目录不出现 `ucf_mod\`；
- 直接双击 `UnityCrossFire.exe`：没有 `UCF_MOD` 通行证，加载器什么都不做，等于原版；
- 加载器载入失败只写 `%TEMP%\ucf_mod_proxy.log`，不往游戏目录写日志。

## 四、会往游戏目录里放什么

| 文件 | 说明 |
|---|---|
| `winhttp.dll` | 代理加载器；没有它插件不会被加载 |
| `winhttp_orig.dll` | 系统自带 winhttp 的副本，从本机取 |
| `UnityCrossFire_Data\level9` 等 | `run\gamepatch` 登记的本体补丁（按开关部署） |

**不会放**：插件 dll、`ucf_mod.json`、`ucf_navcmd.txt`、README、uninstall、部署清单、日志、路点。

不碰：存档、`GameAssembly.dll`、`UnityPlayer.dll`、别的 mod 的文件（`UnityCrossFire.dll` / `InjectDll.exe` / `esp_config.ini` / `imgui.ini`）。

## 五、多份游戏、多个位置

一台电脑上可以有好几份 UCF。控制台「部署」页的「历史位置」记住最近 6 份，一份两行：

- 第一行：状态点、名字、备注、行尾「编辑 / 切换 / 忘记」；
- 第二行：路径；
- 名字和备注存在 `%LOCALAPPDATA%\UCFMod\deploy.json`，只影响显示；
- 当前在用的那份绿色边框 +「在用」；目录不存在标红、禁用切换；
- 换位置 = 重启控制台（一两秒），因为它启动时就把路径算成常量了。

## 六、命令

```powershell
# 编译（产物进 run\build\，不写游戏目录）
.\app\tools\build.ps1

# 可选：同步到 payload（防止干净检出没有 build）
.\app\tools\build.ps1 -Payload

# 一键部署（只铺加载器 + 启用的本体补丁）
python app\tabs\deploy\deploy_mod.py --game-exe "D:\...\UnityCrossFire.exe"

# 连未启用的地图补丁一起铺
python app\tabs\deploy\deploy_mod.py --game-exe "..." --all-packs

# 校验 / 卸载 / 干跑
python app\tabs\deploy\deploy_mod.py --game-exe "..." --verify
python app\tabs\deploy\deploy_mod.py --game-exe "..." --uninstall
python app\tabs\deploy\deploy_mod.py --game-exe "..." --dry-run
```

## 七、常见问题

### 1. 游戏目录里还有旧 `ucf_mod\` 怎么办

直读模式不需要它。确认 `ucf_mod.json` 已经搬进 `run\runtime\` 后，整个目录可以删；
`deploy_mod.py --verify` 会提示"发现旧部署目录"。不要直接删游戏本体文件。

### 2. 加载器源码 / 历史版本

加载器源码在 `src\proxy\`。每次重编后把旧的 SHA256 追加到
`run\payload\loader_history.json`，部署器就不会把旧版当成"第三方 winhttp"。

### 3. 哪些文件不是我们的

游戏根目录里的 `baselib.dll`、`InjectDll.exe`、`UnityCrossFire.dll`、`esp_config.ini`、`imgui.ini`
是另一套 ESP/ImGui mod 留下的，本工程不部署、也不清理。

## 八、案例：storm 的机制跟着 `level9` 走

storm（飓风危城 / `Nano30_Storm`）能不能加载人机，差别只在 `UnityCrossFire_Data\level9`：

| | 原版 | 打过补丁 |
|---|---|---|
| 大小 | 192,140 B | 192,144 B |
| SHA256 | `7d6785dc…` | `a0eeebc7…` |
| 差在哪 | — | 5 个 UI 对象 `m_IsActive` 1→0：Canvas1 / Canvas2 / Canvas3 / EventSystem / SniperCrosshariBG |

旧部署直接改游戏目录，工程端没有副本，游戏一重装就丢。现在：

- 补丁后的整份文件进 `run\gamepatch\10_Nano30_Storm飓风危城\UnityCrossFire_Data\level9`；
- 原版进同包 `orig\`（`_rescue\level9.orig` 也保留）；
- 部署器校验原版哈希 → 备份 → 覆盖 → 校验新哈希；卸载按 `orig\` 还原；
- 是否部署由 `ucf_mod.json` 的 `hidden_map` 开关决定（默认开）。

> 2026-11-25 的清理记录见 `docs/record/游戏目录清理_2026-11-25.md`。
