# 地图数据标准 · 取用与核对

> **类型**：写（规范）+ 查（数据）——以后任何程序要「地图点位 / 坐标 / 可走面」，一律从这里取数、按这里核对。
> **给谁看**：写工具的、做对接的、要拿点位做二次开发的，也包括以后忘了细节的自己。
> **怎么来的**：2026-11-23 把现有几路数据源做了一次全量交叉验证（原版场景 ↔ 运行时点图 ↔ 可走面 ↔ 离线网格 ↔ 第三方 AssetRipper），把结论固化成标准。
> **一句话**：**点位/坐标以 data/navdata/native/（冻结快照）为准；坐标的终极裁判是原版场景文件；data/navdata/dev/ 和 geo/ 都是可改或派生的，不是标准。**
> **不回答什么**：每张图的点/边明细（[07-地图对照表.md](07-地图对照表.md)）、点与面为什么混用（[04-点图与可走面_为什么每张图不一样.md](04-点图与可走面_为什么每张图不一样.md)）、游戏里怎么改点（[09-人机与路线设计.md](09-人机与路线设计.md)）。

## 0. 三条硬规则

1. **只读 + 有哈希 + 能重算**，三条都满足才能叫标准；缺一条只能当参考。
2. **程序先读 native，再读 dev**；dev 里是「我们改过的」，不是原版。
3. **坐标一律是 Unity 世界坐标**（左手系、Y 向上、单位米），**不要自己加偏移**；显示需要抬升时在渲染层做，别写回数据。


### 3.2 map.json（点图）

格式：`format: "ucf-navgraph"`、`version: 1`。

| 字段 | 说明 |
|---|---|
| `map.name` | 场景名相关（如 `level1_TransportShip`） |
| `map.level` | `level1`…`level11` |
| `map.fingerprint` | `n<节点数>-<哈希>`，判定「是不是同一张图」的唯一凭据 |
| `map.source` | `game` = 游戏自己 Scan；`ours`/`practice` = 我们造的；`native-empty` = 原生为空 |
| `map.original` | `true` = 未被编辑过 |
| `map.bbox` | 节点包围盒（米，2 位小数） |
| `counts` | nodes / edges / features / spawn / jump … |
| `nodes[]` | `{id, p:[x,y,z], tag, walk, pen}`，`p` 是**世界坐标，米** |
| `edges[]` | `["<id>","<id>"]`，无向边两端 id（id 由位置哈希得到，可反查 nodes） |
| `features[]` | `{id, kind, name, aux, p}`，kind 如 `spawn` |
| `lines` | `nano_neighbor` / `entrance_escape` / `jump`，坐标对数组 |

精度：游戏内部 Int3 = 1/1000 m；JSON 按 `%.2f` 落盘 → **1 cm 量化，误差 ≤ 5 mm**。

### 3.3 navmesh.bin（可走面，UCFNM3）

| 偏移 | 类型 | 内容 |
|---|---|---|
| 0 | 7 字节 | `UCFNM3\0` |
| 7 | int32 | nv 顶点数 |
| 11 | int32 | nt **索引数**（= 三角形数 × 3） |
| 15 | int32 | ntile |
| 19 | uint8[4] | GraphTransform 标志（identity / onlyTranslational / isXY / isXZ） |
| 23 | float[16] | GraphTransform.matrix |
| 87 | float[3] | translation |
| 99 | int32[nv*3] | 世界坐标，**1/1000 m** |
| 99 + nv*12 | int32[nv*3] | 图空间坐标（同上，备用） |
| 99 + nv*24 | int32[nt*3] | 索引：**只有前 nt 个有效**，后 2·nt 个是未初始化内存（历史 bug） |

文件长度恒等于 `99 + 24·nv + 12·nt`（8 个文件全部实测通过）。

读取建议：只取前 nt 个索引；三角形 = `(idx[3i], idx[3i+1], idx[3i+2])`；顶点 ÷ 1000 = 米。

```python
import struct
b = open(p, "rb").read()
assert b[:7] == b"UCFNM3\x00"
nv, nt, ntile = struct.unpack_from("<iii", b, 7)
vert = struct.unpack_from("<%di" % (nv * 3), b, 99)           # 毫米
idx  = struct.unpack_from("<%di" % nt, b, 99 + nv * 24)        # 只要前 nt 个
```

### 3.4 data/geo/web/<level>.bin（3D 灰模，UCFG v1）

**派生数据，只给显示用，不要进业务逻辑。**

| 偏移 | 类型 | 内容 |
|---|---|---|
| 0 | 4 字节 | `UCFG` |
| 4 | u32 | version = 1 |
| 8 | u32 | jsonLen |
| 12 | utf-8 json | `{level, nverts, ntris, bbox, ambient, chunks[]}` |
| 12 + jsonLen + pad | f32[n*3] | 顶点（米） |
| … | i8[n*3] | 法线 ×127 |
| … | u32[t*3] | 三角形索引（4 字节对齐） |

`chunks[] = {name, start, count, color}`，`start/count` 是**三角形**区间。**没有 UV**，所以现在贴不了图。

### 3.5 geo/<level>.npz（内部缓存，别给下游）

键：`p, n, uv, c, i, g, b, meta`（v7）。`meta` 里有 `chunks`（含 shadow / card / blocker / water 标记、材质号）和 `mats`（贴图名 / 尺寸 / 格式）。**格式会变，只在本仓库内部用。**

## 4. 精度与误差

| 数据 | 存储 | 实测 | 依据 |
|---|---|---|---|
| 路点坐标 | Int3 1 mm → JSON 1 cm | 场景 ↔ 运行时，6 张有双方的图逐点 **0.000 m** | 2026-11-23 比对 |
| 边 | 节点 id 引用 | 依赖运行时 `Scan()`（距离 ≤ maxDistance + 射线） | **不可离线复现** |
| 特征点 | 1 cm | 与游戏组件一致 | — |
| 可走面 | Int3 1 mm | 与 `resources.assets` 的 `*_NavMesh` 同源 | nm840… |
| 静态网格 | f32 | 无缩放 / 无拟合，误差 0 | UnityPy 世界矩阵 |
| 贴图 | — | **当前未落盘** | `data/geo/tex/` 为空 |

## 5. 交叉验证 SOP

### 第 1 步：验基线

```text
cd 06-测试/ucf_mod/app/core
python navdata.py verify
```

通过 = 18 个文件 SHA256 全绿。不通过先查谁动了 native，别继续。

### 第 2 步：比指纹

新采集的 `map.fingerprint` 必须等于 `.frozen.json` 里的 `fp`。不同 = 游戏版本、扫描条件或数据来源变了。

### 第 3 步：场景扫描（离线，不碰游戏）

```text
python scan_native_nav.py --json out.json
```

输出每张图的原生 PointGraph（区分 WayPoint 物体总数 / 激活数）、NavMeshGraph 网格名 / 顶点 / 三角。

判据：**激活 WayPoint 数 + 运行时端点 = `.frozen.json` 的 nodes**。
纯点图端点为 0（运输船 786、生化酒店 3063、新寂静村 180、竞技场 17、椰岛之巅 2）；带端点图的差值 = 小型工厂 +12、刀锋寨 +18、沙漠要塞 +4。

### 第 4 步：场景 ↔ 点图 逐点比对

UnityPy 读场景 → 取 `m_Tag == 20022` 的 GameObject → 沿 Transform 父链乘矩阵得世界坐标 → 与 `nodes[].p` 求最近距离。

通过：**每点 < 0.05 m**；数量差 = 场景里 `m_IsActive = false` 的 WayPoint 数（生化酒店正好 7）。

### 第 5 步：网格 ↔ 路点

用 `geo2web.py` 的 `_pass_cover()`（1 m 栅格，统计路点落在几何上的比例）。参考：运输船 ≥ 0.99；低于 0.8 且集中在一小片 → 查分块取舍或导出缺失。

### 第 6 步：争议裁决

AssetRipper 导出同名 mesh / 贴图，比顶点数、三角数、bbox、像素。两套读取器一致 = 数据没问题，差异出在派生环节。

## 7. 已知陷阱

1. **生化酒店 3070 vs 3063**：少的是 7 个 `m_IsActive = false` 的 WayPoint（父物体 `Pool`），A* `Scan()` 跳过 —— 数据是完整的。
2. **小型工厂 12 / 刀锋寨 18 个点**：场景里 0 个 WayPoint，这些是 `NodeLink` 端点图，不是路网；改了不起作用。
3. **沙漠要塞 12 = 8 + 4**：8 个真路点 + 4 个端点。
4. **胜利广场 / 死亡擂台没有 map.json**：原生纯面图，正常。
5. **飓风危城 0 / 0**：原生没点没面，靠插件铺。
6. **路点比静态地板高约 1.14 m**（运输船 99% 吻合）：这是游戏 A* 节点的真实高度，**显示时别减**；只有做「落地」功能才用中位数。
7. **运输船船头（x 51…70）没有点**：原生如此，不是错位。
8. **3D 灰模只含场景静态网格**：运行时道具 / 可破坏物不在，点看起来悬空 ≠ 坐标错。
9. **navmesh.bin 索引段写了 3 倍长**：只有前 `nt` 个有效，后 2/3 是未初始化内存，读取必须截断。
10. **dev 的 map.json 可能被编辑过**：要原版去 native；dev 只给工作台用。
