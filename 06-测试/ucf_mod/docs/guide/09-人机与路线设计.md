## 0. 一句话结论

**人机的路线不是"手画的一条线"，而是三样东西拼出来的：**

1. **场景里摆的点**（路点、蹲点、守卫点……）——决定"能站在哪"；
2. **A\* 自己连出来的边**（按距离 + 视线自动连）——决定"能走到哪"；
3. **少量手工补丁**（跳跃链接 / 节点连线 / 守卫区 / 箱子点）——修自动连不出来的地方。

所以想改路线，99% 的活儿是**摆点和连边**，不是改代码。

## 0.5 名词：三个出生点数组

`SP_BL` = 潜伏者（生化里是**幽灵 / 终结者**方）、`SP_GR` = 保卫者（生化里是**人类 / 佣兵**方）、`SP_Netural` = 中立（个人竞技全员共用）。
三个数组都是 `MapManager.pointDic`（场景里真正存点的字典）在运行时拆出来的。

完整的阵营表、每张图字典里有哪些 key、运行期改 `SP_*` 为什么会丢，见 [01-游戏基础信息.md](01-游戏基础信息.md) §3。

## 1. 三层结构

```
┌─ 行为层  BotAction（"想干什么"）
│    Saunter 闲逛 / GoCrouchPos 去蹲点 / NanoGuard 守卫区 / BA_PickUpUpgradeBox 抢补给
│    BA_WantInfected 想被感染(送死) / BA_BecomeHero 变英雄 / MechanicHero
│    每帧各 Action 通过 Destination_Listener 报"我想去哪 + 优先级"，最高优先级赢
├─ 寻路层  A* Pathfinding（"怎么去"）
│    Bot.Seeker → StartPath(start,end) → OnPathComplete → PathInterpolator 沿 vectorPath 走
│    途中遇到 Bot_JumpLink 就在路径里插入跳跃段；到点 1.5 米内算到达；0.25~0.5 秒重算一次
└─ 地图数据层（"地图里有什么"）—— 全部是场景里的组件
     点图节点 / 出生点 / 蹲点 / 守卫点 / 守卫区 / 补给箱点 / 跳跃链接 / tag 区
```

| 层 | 游戏里长什么样 | 谁决定 | 改它要动什么 |
| --- | --- | --- | --- |
| 行为层 | `Bot` 组件里一个 Action 列表 | 脚本 | Hook 或改 Action 列表（**代码层**，风险最高） |
| 寻路层 | `AstarPath` / `Seeker` 组件 | A\* 插件 + 图数据 | 改图之后重扫（`AstarPath.Scan`） |
| 地图数据层 | 场景里一堆带组件的空物体 | **关卡策划** | 摆点/挪点/改参数（**数据层**，最安全） |

**关键认识**：行为层只说"想去哪"，具体怎么绕、走哪条路，全由地图数据层决定。
**所以测路线时，你几乎不需要碰行为层**（见第 5 节）。

> 完整运行链路（进图建图 → 每帧决策 → 寻路 → 沿路走 → 到点行为）见 [08-寻路全流程_从建图到蹲下.md](08-寻路全流程_从建图到蹲下.md)。

## 2. 目的地优先级（谁抢到"去哪"）

每帧所有 Action 都会通过 `BotEvent.RefPosition` 报一次"我想去这个点，优先级 N"，最后留下最大的那个。

| 优先级 | 常量 | 来源 | 说人话 |
| --- | --- | --- | --- |
| 999 | `GoDie` | `BA_WantInfected` | 生化里"想被感染"的兵，直接冲向幽灵送死 |
| 51 | `UpgradeBox` | `BA_PickUpUpgradeBox` | 升级箱/补给箱 |
| 50 | `SupplyBox` | 补给箱 | 捡补给 |
| 10 | `EscapeEnemy` | `NanoGuard` | 守卫区被压时逃跑 |
| 7 | `Saunter` | 闲逛 | 随便走走 |
| 6 | `GuardPos` | 守卫点/守卫区 | 回守卫点 |
| 5 | `Enemy` | 追敌 | 追人打 |
| 0 | `SimpleMove` | 普通移动 | 兜底 |

> **箱子 > 逃跑 > 闲逛 > 守卫点 > 追敌。**
> 这就是为什么生化模式里人机看到补给箱会"突然不打了"——51 盖掉一切。
> 反编译核对过：`BA_PickUpUpgradeBox` 的监听器只在 `*priority < 51` 时写入 51；
> `NanoGuard` 的监听器在"正在逃跑"时写 10、否则 `*priority < 6` 时写 6。

## 3. 路线元素清单（点 / 线 / 面 / 参数 / 行为）

**先记一句话**：路线 = **点**（能站在哪）+ **线**（能走到哪）+ **面**（哪一片）；**参数**微调这几样，**行为层**决定去不去。

每类先给一张小结表（"查"用），再按元素分块（"读"用）；每块回答同样几个问题——**是什么、场景里长什么样、玩家看到什么、谁在用、怎么改**，用不上的直接省掉。"出现在哪"一列来自 [07-地图对照表.md](07-地图对照表.md) 的原生组件统计（2026-11-17）；标 **（推断）** 的是从代码结构推出来的、没打日志逐帧确认的。

### 3.1 点（"能站在哪"）

| 种类 | 一句话 | 出现在哪 |
| --- | --- | --- |
| **A\* 路点（核心）** | 人机能站的坐标，点图的最小单位 | 除胜利广场 / 死亡擂台（纯面图）外都有 |
| 出生点 | 开局 / 复活的落点 | 每张图 `MapManager` 必挂 |
| 补给箱点位 | 生化箱子刷在哪 | 沙漠要塞 / 生化酒店 / 飓风危城 / 新寂静村 |
| 蹲点 | 人类蹲坑位 + 观察方向 | 团队 / 个人图（哪几张见地图对照表） |
| 生化守卫点 | 守卫区里的固定驻守位 | 只有沙漠要塞 / 新寂静村 |
| 守卫区入口（朝向点） | 给守卫点提供张望 / 枪口方向，**不是进区落脚点** | 同上 |
| 逃跑点 | 守不住时的撤退点 | 同上 |
| ~~旧守卫点~~ | 老版本遗留，**没人用** | 只剩生化酒店（死数据，见 §7） |

#### 3.1.1 A\* 路点（核心）

- **是什么**：`PointNode`——点图的节点，就是"人机能站的坐标"。位置是毫米整数（`position`@0x14，÷1000 得米），出边在 `connections`@0x20，对应场景物体在 `gameObject`@0x24。
- **场景里长什么样**：`PointGraph.root` 下一个带 `tag = WayPoint`(20022) 的空物体；进图 `AstarPath.Scan` 时被收成节点、自动连边。
- **玩家看到什么**：人机沿"点 → 边 → 点"走直线段，拐弯贴点；点太稀或关键边被断，就绕远、甚至原地转圈。
- **谁在用**：A\* 自己。人机只拿它算路，不关心"点"长什么样。
- **怎么改**：挪物体的 `Transform.position` 后重扫（见 §6 路线 A）；在 `root` 下增删 `WayPoint` 物体就是加 / 删点。**只有点图能这么干**，纯面图加点是无效的（§7 第 2 条）。

#### 3.1.2 出生点

- **是什么**：`SP_BL / SP_GR / SP_Netural` 三个数组 + `pointDic` 字典，存坐标和朝向角（名字对应关系见 §0.5）。
- **场景里长什么样**：`MapManager` 上的 `pointDic`——场景里只存这个字典，`SP_*` 是运行时 `Awake` 拆出来的缓存（推断）。
- **玩家看到什么**：开局 / 复活时人机成排出现在**本方**出生点、朝向固定；两边不会刷到对面。
- **谁在用**：回合开始或死亡重生 → `MapManager.GetSpawnPoint(team)`；静态计数 `SPID_*` 轮转，不会连着两次同一点。
  **人机也走这条路**：`Mode_*.DeathEvent` → `Player.Respawn` → 协程 → `Player.Spawn`（里面就调 `GetSpawnPoint`），
  所以改运行期数组对人机重生一样生效（2026-11-27 反编译核实，见 `record/出生点三阵营_2026-11-27.md`）。
- **哪个队读哪个数组**：`GameManager.AddPlayer` 按 `GameMode` 定队 ——
  团队（0）/ 特殊战（2）用 `ClientData.joinTeam`（BL/GR）；**个人竞技（1）全员 Neutral → `SP_Netural`**；
  生化（3-6）全员 GlobalRisk → `SP_GR`（被感染后 SetTeam(BL) 的幽灵重生走 `SP_BL`）。
  生化还有 `respawnType` 覆盖：`ModeBase_Nano.RespawnPlayer` 把它设成 2（敌方队），
  `Mode_Nano4_Terminator.RespawnPlayer` 设成 1（原地，不取点）。
- **怎么改**：改 `pointDic` 里的坐标 / 朝向（场景数据，走离线）；运行期改 `SP_*` 只是改缓存，换图重载就没了（§7 第 5 条）。
  游戏内菜单（`docs/record/出生点三阵营_2026-11-27.md`）改的就是这三份缓存：新增点会排到数组**最前面**并
  清零 `SPID_*`，所以按完 5 之后的下一次重生就用它；`Ctrl+S` 落 `markers\<图>\markers.txt`。

#### 3.1.3 补给箱点位

- **是什么**：`SP_SupplyBox / SP_RedBox / SP_BlueBox` 三个数组 + `GetSupplyBoxPoint` / `ReleaseSupplyBoxPoint` 取还接口；颜色就是下标（黄 0 / 红 1 / 蓝 2，字段 `SupplyBox.type`@0x30）。
- **场景里长什么样**：`pointDic` 里 key 就叫 `SupplyBox` / `RedBox` / `BlueBox`（只有沙漠要塞 / 生化酒店 / 飓风危城 / 新寂静村有）。
- **玩家看到什么**：箱子在这些点刷；人机看到箱子会**丢掉当前目标**冲过去（优先级 51 / 50，见 §2）。
- **谁在用**：刷箱时占一个空闲点、记进 `IDList_*`；箱子被捡或消失再 `Release` 归还。
- **怎么改**：运行期直接写 `SP_SupplyBox` 数组元素（纯 `Vector3`，最安全）；要给某张图**新增**箱子点，得改场景里的字典（离线）。

#### 3.1.4 蹲点

- **是什么**：`Bot_CrouchPos`（`team`@0xC、`zoomPos[]`@0x10、`crouchDisabled`@0x20、`always`@0x21）。`zoomPos[]` 是蹲下后"往哪看 / 往哪瞄"的**方向点**，不是站位。
- **场景里长什么样**：一个空物体挂一堆子物体，子物体就是 `zoomPos[]`；运行时按阵营拆进 `SpareList_BL` / `SpareList_GR` 两张静态表。
- **玩家看到什么**：人机跑到掩体 / 墙角蹲下，朝一个方向架枪；玩家进了视野才起身开火。
- **谁在用**：开局 / 重生延迟一过，`GoCrouchPos` 用 `GetRandomPos(team)` 随机取一个走过去，到点 `TryCrouch` 蹲下。
- **怎么改**：挪组件本体换站位、挪 `zoomPos` 子物体换架枪方向、改 `team` 换归属阵营；`always` = 常驻不换点、`crouchDisabled` = 只站位不蹲（推断）。走不到会按 `giveUpTime` 放弃。

#### 3.1.5 生化守卫点

- **是什么**：`Bot_NanoGuardPos`（`area`@0xC、`zoomPos[]`@0x10、`_safety`@0x1C）。`_safety` 越高越靠里 / 越安全。
- **场景里长什么样**：**必须挂在 `Bot_NanoGuardArea` 下**才会被收集——区 `Awake` 把子物体收进 `posList`，挂错父节点等于没挂。
- **玩家看到什么**：生化里几只人机分散站在房间 / 高台固定点，玩家一露头就被集火；被压时换更安全的点。
- **谁在用**：`NanoGuard.GetPos()` 随机占一个，**占一个就从区 `posList` 移除**（`isFull = posList.Count <= 0`）；离开时 `Leave()` 放回。被压时 `GetSaferPos(safety)` 只找 **`_safety > 当前`** 的点，所以全填同一个 safety = 不会换点。
- **怎么改**：挪本体换驻守位、改 `_safety` 改"多容易被打就跑"；守卫点自己的 `zoomPos` 不再写（原生多数也空），观察方向由守卫区 `entrancePos` 提供。
- **容量**：一个区能同时站几台 = `posList` 里剩几把椅子（守卫点数量），和人类人数无关。
- **安全等级**（2026-11-28）：每个点 `_safety` 0~3，越大越靠里/越安全；`GetSaferPos` 只找 **严格更高** 的点。想让人机被压往里退，就外层 1 / 中层 2 / 里层 3；全填 3 = 没有更安全点，只能去逃跑区/逃跑点。
  菜单「守卫区工具 → 2 加守卫点」会进子页：**1~4 直接选 0~3，5 放一个，Esc 返回**；第 5 项会动态写成“放一个守卫点（安全等级 N）”；放完仍留在子页可连续放，等级保持到改选/退出；只影响新建点，存 `markers.txt` 的 `# nano_safety` 行。
  F2 菜单打开、朝向显示开着时，准星指着任意守卫点，屏幕中间会显示「守卫点 · 安全等级 N」（自己建的和原生点都支持）。

#### 3.1.6 守卫区入口（更准确叫“朝向点 / 瞭望点”）

> **一句话**：字段名 `entrancePos` 直译确实是“入口位置”，但它在逻辑里不是入口，而是“**守卫点的枪口 / 视线朝向点**”。
> 人机不会走到它，也不从它进区；它只提供一个方向——**守卫点 → 入口点**。
> 名字的来历（推断）：原版关卡通常把点放在守卫区入口外，让人机盯着玩家可能来的方向，所以叫 entrance；
> 意思是“**盯着那个入口**”，不是“人机进入的入口”。

- **是什么**：`Bot_NanoGuardArea.entrancePos[]`@0xC，**不是进区路线 / 落脚点**。`Bot_NanoGuardPos.Init()` 会把它并进每个守卫点的 `zoomPos`（世界目标点），所以它只决定**站定后往哪看**。
- **只是方向，不是位置约束**：真正起作用的是从守卫点 / 人机位置指向该点的方向；点放在区内、区外、远处都能生效，不要求落在守卫区 Trigger 里，也没有“人机必须到达”这一步。它不改变站位、不参与 A\* 寻路。
- **只影响谁**：数据挂在哪个区，就只改哪个区的守卫点人机；巡逻、散步、逃跑和普通路线人机都不读它。**它是“这个区的火力朝向”，不是全图通用的朝向设置。**
- **场景里长什么样**：区组件下的子物体数组（原生）；插件 2026-11-28 起可以在 F2「守卫区工具 → 3 加入口」追加，存 `entrance <aid> x y z`。
- **玩家看到什么**：人机站到守卫点后朝入口方向张望 / 瞄准；不是从入口“鱼贯进区”。人机进区靠 A\* 走到区 / 守卫点，和 entrancePos 无关。
- **谁在用**：只在 `Bot_NanoGuardPos.Init` 里被拼进 `zoomPos`；改入口后已有守卫点要重新 Init 才生效（插件加入口时会自动刷新）。
- **怎么改**：加多个入口 = 一个守卫点有多个张望方向；只有入口没有守卫点的区仍然是空区。删除入口：`3 守卫区工具 → 5 删除入口`（准星 0.6 m 内才删，删完立刻重算已有守卫点的张望方向）。

#### 3.1.7 逃跑点

- **是什么**：`Bot_NanoGuardArea.escapePos[]`@0x1C，配套 `GetRandomEscapePos`；插件 2026-11-28 起可以在 F2「守卫区工具 → 4 加逃跑点」追加，存 `escape <aid> x y z`。
- **场景里长什么样**：区组件下的子物体数组；区跟区之间还有 `escapeAreas`（逃跑区）和 `neighborAreas`（邻居区）两个引用数组。
- **玩家看到什么**：玩家压进守卫区、当前区又没有更安全的守卫点时，人机随机取一个逃跑点，优先级 10 跑过去。
- **谁在用**：`GoToSaferGuardPos()`：先找 `_safety > 当前` 的点；没有 -> 随机一个 `escapeAreas`（未满就整队过去）；没有 -> 随机一个 `escapePos` 并 `isEscaping=1`；再没有 -> 随机另一个区。`neighborAreas` 目前只找到 getter，没找到运行时调用，当前版本基本不用。
- **怎么改**：加逃跑点改撤退落点；`escapeAreas` 是**你摆的区引用**，人机只在这些区里随机选；插件新建区目前这两个引用数组是空的。删除逃跑点：`3 守卫区工具 → 6 删除逃跑点`（同样只认准星 0.6 m 内）。
- **整区搬家**：`3 守卫区工具 → 7 整体移动守卫区`，两步确认；区加下面的守卫点 / 入口 / 逃跑点、以及 `entrancePos` / `escapePos` 数组会一起平移，不用逐个重摆。

#### 3.1.8 ~~旧守卫点~~（死数据）

- **是什么**：`Bot_GuardPos` / `Bot_GuardArea`，老版本的守卫点 / 区。
- **场景里长什么样**：只剩生化酒店还挂着（数量见 [07-地图对照表.md](07-地图对照表.md) 的组件统计表）。
- **玩家看到什么**：改了没有任何反应。
- **谁在用**：**没人用**——`TryGetZoomPos` 只有元数据引用、没有调用点，`Bot_GuardArea` 是空类（§7 第 1 条）。

### 3.2 线（"能走到哪"）——**先分层，别混**

线分三类：**点图连线**、**场景连线组件**（`NodeLink` / `NodeLink2`）、**跳跃链接**（`Bot_JumpLink`）。

| 种类 | 谁连出来的 | 用在哪 |
| --- | --- | --- |
| **点图连线** `PointNode.connections` | `PointGraph.Scan` 自动连 + 菜单「建立路径」手动连 | 所有点图，人机真正走的边 |
| 通用连线 `NodeLink` | A\* 插件自带 | 同层相邻平台 / 走廊的缝 |
| 两点连线 `NodeLink2` | A\* 插件自带 | 跨缺口 / 断桥 / 矮墙 |
| **跳跃链接 `Bot_JumpLink`** | 游戏自写 `GraphModifier` | 必须真跳的地方（箱子 / 跳台 / 上下层） |
| 不可走 | `GraphNode.flags` bit0 | 手动禁用节点 |

> **点图连线**是 `PointNode.connections` 这一层的总称：
> - **自动连边**：`PointGraph.Scan` 按距离 / 射线自动生成，进图就有
> - **手动连线**：游戏内菜单「建立路径」直接加 / 删，和自动连边是同一个 `Connection` 结构

**"跳"和"滑"是两回事**：`NodeLink` 只加边不加点；`NodeLink2` 会在两端补 `PointNode` 再连边；两者都不产生真正的起跳，人机是**平移 / 掉落**过去的；只有 `Bot_JumpLink` 才会插真正的起跳段。这是本包最容易看错的地方。

#### 3.2.1 点图连线（PointNode.connections）

- **是什么**：`PointNode.connections` → `Connection{ node, cost, shapeEdge }`（步长 12 字节）。
- **两个来源**：
  - **自动连边**：`PointGraph.Scan` 时按 `maxDistance` + 射线 + `limits` 自动连，不用手摆。
  - **手动连线**：游戏内菜单「建立路径」直接加 / 删 `connections`，不创建 `NodeLink` / `NodeLink2`。
- **玩家看到什么**：人机沿地面"点→边→点"走直线段，拐角贴点转向；断一条边可能绕远，断关键边就原地转圈。
- **人机内部**：沿边直着走，A\* 按总代价选路。
- **怎么改**：删 / 加单条边 = `PointNode.RemoveConnection` / `AddConnection`；整体重连 = 改 `maxDistance` 后重扫。

#### 3.2.2 通用连线 `NodeLink`

- **是什么**：A\* 插件自带组件，挂在场景里，把**附近已有节点**互相补连。
- **用在哪**：同层相邻平台 / 走廊原本没连上的缝（各图个数见地图对照表）。
- **玩家看到什么**：基本看不出来——人机只是走了一条原本没连的捷径，不会腾空。
- **人机内部**：只加边，不加点。
- **怎么改**：挪它自己的位置或两端物体，进了范围就自动生效，重扫后可见。

#### 3.2.3 两点连线 `NodeLink2`

- **是什么**：A\* 插件自带，物体 A ↔ 物体 B 直连一条边；另建一张 `PointGraph (used for node links)` 图放两端端点。
- **用在哪**：跨缺口 / 断桥 / 矮墙（哪几张图有、各几个见地图对照表）。
- **玩家看到什么**：人机贴着地面 / 空中**平移**过缺口，**不跳、没有腾空动作**，看着像滑过去。
- **人机内部**：沿直线过去，路径里没有跳跃段。
- **怎么改**：挪两端物体。端点会自己折成点图节点，所以点图里那些孤立端点不用手动摆。

#### 3.2.4 跳跃链接 `Bot_JumpLink`

- **是什么**：游戏自写的 `GraphModifier`；`links[]` → `Link{ endTransform, endNode, needSpeed, accuracy, direction }`（`Link` 0x1C 字节），`linkDic` 记起点节点。
- **用在哪**：必须真跳的地方——箱子、跳台、上下层（各图个数见地图对照表）。
- **玩家看到什么**：人机跑到边缘**起跳、有腾空**，落地继续跑；速度不够 / 角度不对会跳失败掉下去。
- **人机内部**：`OnPathComplete` 遍历路径的节点序列——只有「路径里 **起点节点 的下一个节点** 正好是这条跳链的 `endNode`」时才插跳跃段（`Bot_JumpLink.GetLink` 查 `linkDic[startNode]`，`GetLinkEndByGraphNode(nextNode)` 比对 `endNode`），然后 `JumpCheck` / `Jump` 执行；`needSpeed` 决定助跑速度、`accuracy` 决定对点精度。
- **触发条件（2026-11-20 反汇编确认，改数据必须满足）**：① 起点、落点都要吸附到图上节点（1 m 内）；② 这两个节点之间**必须有 A->B 的边**，否则 A* 永远不会把它们连着排，跳链一次都不触发；③ 长度 >= 1.5 m；④ 长度 <= 3.0 m——原生 41 条跳链最长 2.91 m，超过就是"会触发但跳不过去"，Bot 起跳后掉回原地。体检用 `python app/tools/data/check_jumps.py`（逐条打「同点 / 缺路点 / 无连线 / 太短 / 超长」）。菜单里建跳链会自动补落点路点和 A->B 单向边。
- **跳太远怎么办**：在起落点之间按实际地形补 1~2 个中间路点，每条跳链控制在 2.5~2.9 m；补的点必须真能站人（对着台子 / 斜坡打），否则 Bot 跳到空中节点照样掉。
- **怎么改**：挪起点 / 终点物体、调 `needSpeed` / `accuracy`；改完必须重扫，否则 `linkDic` 还指着旧节点。

#### 3.2.5 不可走节点

- **是什么**：`GraphNode.flags` bit0（walkable）。
- **玩家看到什么**：人机绕开这个点走，像那里有个看不见的障碍；如果它是唯一通道，人机会卡住或绕远。
- **怎么改**：编辑模式里关掉，或运行期清 bit0 再重扫。A\* 直接不考虑这个点——做"临时封路"最省事。

**交叉证据**（都来自场景文件统计，能互相对上）：

- 小型工厂：6 个 `NodeLink2` → 点图 12 个节点（6×2）✔
- 刀锋寨：9 个 `NodeLink2` → 点图 18 个节点（9×2），场景里 0 个 WayPoint ✔
- 沙漠要塞：8 个 WayPoint + 2 个 `NodeLink2`（4 个端点）= 12 个节点 ✔

### 3.3 面（"哪一片"）

| 种类 | 是什么 | 出现在哪 |
| --- | --- | --- |
| **生化守卫区** | 带 Trigger 的体积 + 区内守卫点 + 邻区 / 逃区 | 只有沙漠要塞 / 新寂静村 |
| tag 区 | 把一批坐标附近的节点打 tag | 本包只有沙漠要塞挂了 1 个 |
| 动态挖洞 / 补面 | 运行时挖掉 / 补上一块可走面 | 本包 11 张图都没挂 |
| ~~旧守卫区~~ | 老版本遗留，空类 | 生化酒店（死数据） |

#### 3.3.1 生化守卫区

- **是什么**：`Bot_NanoGuardArea`——`entrancePos[]`、`posList`、`neighborAreas[]`、`escapeAreas[]`、`escapePos[]`。一块带 Trigger 的体积 + 区内守卫点 + 邻区 / 逃区，组成"区网"。
- **场景里长什么样**：带 Trigger 的组件，子物体是守卫点，数组里是朝向点（entrancePos）/ 逃点。
- **玩家看到什么**：玩家走进守卫区，里面的人机开始反应（换点、集火、被压就跑）；区里人机满员后，新来的转去隔壁区。
- **谁在用**：`OnTriggerEnter / Exit` 通知区内人机（`Bot.OnEnterNanoGuardArea`）；`isFull` 看守卫点是否被占满。
- **怎么改**：挪体积 / 守卫点 / 入口，或改 `neighborAreas` / `escapeAreas` 重排区网。**区是"容器"，改守卫点优先于改区。**

#### 3.3.2 tag 区

- **是什么**：`PointNodeTagModifier`——`points[]`@0x20、`pathTag`@0x24，把落在这批坐标附近的节点打 tag（存在 `GraphNode.flags` bit19~23）。
- **玩家看到什么**：几乎看不出来；如果人机 `Seeker` 配了 `traversableTags` / `tagPenalties`，人机会"不愿意走"某些路、绕远。
- **谁在用**：`OnLatePostScan` 打 tag；**认不认取决于人机预制体上的 `Seeker`**——只打 tag 不改 `Seeker` 就是死的（§7 第 3 条）。
- **怎么改**：挪 `points[]` 或改 `pathTag`，再配合 `Seeker.tagPenalties`。

#### 3.3.3 动态挖洞 / 补面

- **是什么**：`NavmeshCut` / `NavmeshAdd`（A\* 插件自带），运行时把一块可走面挖掉 / 补上。
- **出现在哪**：本包 11 张图都没挂。
- **玩家看到什么**：挂了的话——门关着人机就不过去、门开才走（电梯 / 可破坏物）。
- **谁在用**：`GraphModifier` 在运行时改可走面，进图后重建导航。
- **怎么改**：挂一个 `NavmeshCut` 在会动的物体上（门 / 升降台）；它只对可走面生效，对点图无效。

#### 3.3.4 ~~旧守卫区~~（死数据）

- **是什么**：`Bot_GuardArea`，老版本守卫区，**空类**。
- **出现在哪**：生化酒店还挂着（数量见 [07-地图对照表.md](07-地图对照表.md) 的组件统计表）。
- **玩家看到什么**：改了没反应。

### 3.4 参数（同一个点，行为不同）

| 参数 | 存在哪 | 效果 |
| --- | --- | --- |
| walkable | `GraphNode.flags` bit0 | 关掉=这个点不可走 |
| tag | `GraphNode.flags` bit19~23（掩码 `0x1F00000`） | 给点分类；惩罚值由 `Seeker.tagPenalties` 决定 |
| penalty | `GraphNode.penalty`@0x10 | 加大 = 绕开（A\* 按总代价选路） |
| cost | `Connection.cost`@0x4 | 单条边的代价 |
| needSpeed / accuracy / direction | `Bot_JumpLink.Link` | 跳跃要多少速度、多准、朝哪 |

| team | `Bot_CrouchPos.team` | 0=潜伏者（BL），1=保卫者（GR） |

## 4. 各模式需要什么

模式枚举与中文名见 [01-游戏基础信息.md](01-游戏基础信息.md) §1；哪几张图属于哪个模式见 [07-地图对照表.md](07-地图对照表.md) 的「模式 ↔ 地图」。

| 模式 | 路线必需 | 额外 |
| --- | --- | --- |
| 团队模式 | 路点图 + 双方出生点 | 蹲点、跳跃 / 连线（可选增强）；tag（可选） |
| 个人竞技 | 路点图（或可走面）+ 出生点 | 同上 |
| 特殊战 | 路点图 + 出生点 | **跳跃链接**为主（竞技场最多，个数见地图对照表） |
| 救世主模式 | 路点图 + 出生点 + **守卫区 + 守卫点** | 补给箱点位、蹲点、跳跃 |
| 终结者 / 生化剑客 / 多人终结者 | 同上 | 同上；多人终结者另有"想被感染"送死行为（优先级 999） |

**别搞混**：社区说的"多人生化" = 多人终结者模式（枚举 **6**），不是生化剑客（5）。

**核心结论**：**路点图（或可走面）是所有模式共用的同一套东西**。
模式差异 = 「场景里多挂了哪些组件」+「多给它挂了哪些 Action」，不是另造一套导航。

## 6. 能改哪一层？三条路线

> 一句话：**改"数据"最安全，改"行为"风险最高，改"场景文件"最费劲。** 新手从路线 A 开始。

| 路线 | 改什么 | 动哪一层 | 生效时机 | 风险 / 代价 |
| --- | --- | --- | --- | --- |
| **A. 运行期改数据**（推荐） | 挪点 / 加点、删边、改 tag、改跳跃链接、挪蹲点 / 守卫区 / 箱子点 | 地图数据层 | 改完重扫一次即生效；换图会丢 | 低。只写 `Vector3` / 数组元素 / `Transform`，不碰代码 |
| **B. 运行期改行为** | 拦截寻路请求、改目的地、改 Action 列表 | 行为层 | 即时 | 中。游戏带 Anti-Cheat Toolkit，代码 patch 有被还原的风险；优先纯数据写入（读点图、改队伍字段这类纯数据方案） |
| **C. 离线改场景文件** | 直接改 `UnityCrossFire_Data\levelN` | 地图数据层（静态） | 重开游戏 | 高。IL2CPP 没有 MonoBehaviour 的 TypeTree，要按 `dump.cs` 自己重建字段布局，且场景数据在压缩块里 |

**路线 A 的两个动作**（其余都是它的变体）：

1. **挪一个已有的点 / 区**：改 `Transform.position`（或直接写 `Vector3[]` 元素），然后 `AstarPath.Scan(该图)`，让边和 `Bot_JumpLink.linkDic` 重新绑定。
2. **加 / 删一个点**：点图节点 = `PointGraph.root` 下带 `WayPoint`（tag 20022）的物体；在 root 下增删物体后重扫即可。
   **只有点图能这么干**；只有可走面的图（胜利广场 / 死亡擂台）加点是无效的（见 §7 第 2 条）。

**路线 B 的挂钩点**（改行为，不改地图）：

- `Seeker.StartPath(start, end, callback)`：所有人机寻路的总入口，改 `end` 就能改变"去哪"；
- `Bot.OnPathComplete(path)`：拿到路径后改 `vectorPath`，可以加绕行 / 拖路径；
- `Bot.UpdateAction()`：每帧推进 Action 列表的地方。

偏移和函数地址见 [record/逆向速查_版本偏移与地址.md](../record/逆向速查_版本偏移与地址.md) §4~§5。

> 本文只讲"改哪一层、为什么"。怎么把改动做成一个功能（manifest / RPC / UI / 持久化），见 `02-开发规范` 与 `04-正式发行版` 里的同类功能目录。

## 7. 坑（都验证过）

1. **`Bot_GuardPos` / `Bot_GuardArea` 在本版本是死数据**：`TryGetZoomPos` 只有元数据引用、没有调用点，`Bot_GuardArea` 是空类。
   **生化酒店里挂的那批守卫点 / 守卫区（数量见 [07-地图对照表.md](07-地图对照表.md) 的组件统计表），改了不会有反应**；要改就改 `Bot_NanoGuardArea` / `Bot_NanoGuardPos`。
2. **有两套"地面"**：点图（`PointGraph`）和可走面（`NavMeshGraph`）。有的图只有点（运输船、生化酒店），
   有的图只有面（胜利广场、死亡擂台）。**在只有面的图上加点，人机不会去走**——它走的是三角网。
   每张图有哪套，看 [07-地图对照表.md](07-地图对照表.md) 的 §4「按原生给了什么分四类」；
   两种图为什么不一样、改法差在哪，见 [04-点图与可走面_为什么每张图不一样.md](04-点图与可走面_为什么每张图不一样.md)。
3. **tag 区不配参数就是死的**：`PointNodeTagModifier` 只负责打 tag，认不认取决于人机预制体上的 `Seeker`。
4. **A\* 在后台线程算路**：改图时别正好有路径在算；改完统一重扫一次，别边改边扫。
5. **换图/换模式会重载场景**：运行时的改动全部丢失，要按"进图后重放"设计（现有插件就是这么干的）。
6. **别写混淆字段**：`Bot.hangoutTag`、`Player.nanoClothCount` 这类是 Anti-Cheat 的 `Obscured*`，直接写会读出乱值。
   路线相关字段（Vector3 / Transform / 数组元素）不受影响。
