## 0. 当时的疑问（原文）

> 运输船和小型工厂，这两个地图为例，还有其他地图，为什么作者用不同的技术，一个是用点构成网，一个是用 nav，这是训练不同的技术，还是什么？这两个一样吗？

---

## 1. 问：这是两套 AI 吗？还是在练手？

**都不是。**

- **同一套插件**：11 张图全是 A\* Pathfinding，同一个 `AstarPath`、同一个 `Seeker`、同一套 `BotAction`。
- **同一套代码路径**：`StartPath(start, end)` → `Path` → `OnPathComplete` → 沿 `vectorPath` 走，一行都不分叉。
- **区别只在数据**：场景里给插件喂的是"点"还是"三角面"。
- **也不是 mod 作者选的**：点/面是游戏原厂做进场景和资源里的，mod 只能适配。

---

## 2. 问：这两种图分别是什么？

| | 点图 `PointGraph` | 面图 `NavMeshGraph` |
| --- | --- | --- |
| **数据来源** | 场景里 `tag = 20022（WayPoint）` 的物体，`Scan()` 时连成图 | 美术烘焙的三角网（`resources.assets` 里的 `*_NavMesh` 网格） |
| **人机走哪** | 点与点之间的直线 | 三角面上的任意位置 |
| **可控性** | 高：每个点、每条边都能钉死 | 低：只能"大致"走，不能精确控制走位 |
| **代价** | 手工摆，几百上千个点很贵 | 烘焙一次就行，但几何脏 / 有高度差就难烘 |
| **典型问题** | 点断了人机就绕远/卡住 | 门、电梯、可破坏物要 `NavmeshCut/Add` 动态改 |

两者都是 `NavGraph` 的子类，`Seeker.StartPath(start, end)` 对它们一视同仁。

---

## 3. 问：11 张图各用哪套？

**分四类，不逐张抄表**（每张图的点 / 边、网格 / 三角形数见 [07-地图对照表.md](07-地图对照表.md) 的 §1~§3 与 §4「按原生给了什么分四类」）：

- **纯点图**：运输船、生化酒店 —— 多层、楼梯、集装箱 / 房间多，需要精确走位；
- **纯面图**：胜利广场、死亡擂台 —— 平坦、封闭、层数少；
- **两者都有**：小型工厂、椰岛之巅、竞技场、刀锋寨、沙漠要塞、新寂静村 —— 走路靠面，点图多半只做 node link / 补充；
- **两者都没有**：飓风危城 —— 原生 0 点、无面，人机会僵住，插件才给它铺点。

---

## 4. 问：为什么原厂要混着用？

**不是"训练不同的技术"，是不同关卡交上来的导航资产形态不同。**（以下为工程推断）

1. **多层/垂直结构**：老版本 A\* 的 NavMesh 是单层三角面，楼梯、跳下、集装箱顶面很难烘进去；点图可以一个点一个点地表达"这层走这条、从这跳下去"。
2. **精度需求**：需要人机"死死卡住掩体/门口"的图，点图能钉死；面图只能让它大致走到位置。
3. **关卡来源不同**：不同时期、不同外包交付的导航资产，没有统一规范——所以同一款游戏里才会有的纯点、有的纯面。
4. **成本**：摆几百上千个点很贵；几何干净的图烘焙一次就完事，所以小图/平地图都给了面。

---

## 5. 问：运输船和小型工厂，具体差在哪？

### 运输船（纯点图）

- 纯点网、`maxDistance = 2.1`（2.1 米内两两连边），**没有三角网**；规模和边数见 [07-地图对照表.md](07-地图对照表.md) §2。
- 人机走的每一步都在点上，脚下没有"面"兜底——点断了/点太稀，人机就绕远或卡住。
- 你改一个点、断一条边，**立刻**改变路线。这是最适合练手的图。

### 小型工厂（面图 + 端点图）

- 人机实际踩的是 `nm840` 三角网（名字里的 840 就是 A\* 合并同位置顶点后的顶点数；顶点 / 三角形明细见 [07-地图对照表.md](07-地图对照表.md) §3）。
- 那几个点、那几条边是 `NodeLink2` 自己建的**端点图**（数量见 [07-地图对照表.md](07-地图对照表.md) §2）：图名就叫 `PointGraph (used for node links)`，`searchTag` 为空、`maxDistance = 0`。
- 它们不是给人机铺的路，是给离线连接（`WayLink*` / `JumpLink*`，跳/翻越）当端点用的；数据上它和三角网是**两张分开的图**。
- 所以：**你在小型工厂改点，基本没反应**；要改得改 navmesh（或加 `NavmeshCut/Add`）。

> **一个要实测的点**：这些端点会不会被人机真的用到？A\* 里跨图必须显式连接，数据上没看到这种连接，所以"人机在面上走时通常走不到它们"是合理推断；要确认就 hook `Seeker.StartPath` 看路径里有没有点图节点。

---

## 6. 问：那"这两个一样吗"？

- **数据结构**：不一样。一个是"点 + 边"，一个是"三角形"。
- **对上层**：完全一样。同一个 `Seeker`、同一个 `Path`、同一个 `OnPathComplete`、同样的 1.5 米到达判定，`BotAction` 根本不知道自己在哪种图上跑。
- **改法**：完全不一样。点图改点/边；面图改网格或动态挖补。

用一句更直白的话：

> 点图是"画好站位的连线图"，面图是"铺好的地板"。人机只会问"从 A 到 B 怎么走"，底下是连线还是地板，它不关心。

---

## 7. 问：对我改路线有什么影响？

| 你想干的事 | 运输船（点图） | 小型工厂（面图） |
| --- | --- | --- |
| 改一条路线 | 改点/连边就行 | 改点没用，得改网格或加 `NavmeshCut` |
| 让人机卡住某个门口 | 加点、调节点 `penalty` | 很难精确控制 |
| 加跳跃/跨缺口 | 加 `Bot_JumpLink` | 端点图与三角网不相连，通常走不到（要实测） |
| 测"点断了会怎样" | 最直观 | 测不出来 |

**先看这张图有哪套图，再决定改哪一层**——在只有面的图上加点，人机不会去走。

## 8. 怎么验证这些数字

- 每张图的点/边、网格顶点/三角形：[07-地图对照表.md](07-地图对照表.md) 的 §2 / §3 明细表；
- 自己重扫一遍：`python app\tools\data\scan_native_nav.py`（读场景 + `resources.assets`）；
- 看运行时图：进图后数 `PointGraph.nodeCount` 与 tag 20022 的物体数，或让插件把点图画出来。
