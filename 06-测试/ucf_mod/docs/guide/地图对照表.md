bin 是插件自己写的 `UCFNM3` 格式（`src\editor.c` 的 `nm_dump()`）：

```
"UCFNM3" 0x00 | int32 nv | int32 nt | int32 ntile | uint8 flags[4]
               | float matrix[16] | float translation[3]
               | int32 verts[nv*3]   （世界坐标 Int3，1/1000 m）
               | int32 gverts[nv*3]  （图空间，同上）
               | int32 tris[nt*3]
```

为什么顶点表写两份：A* 的 `verts` 已经是世界坐标，`vertsInGraphSpace` 是图空间；
万一某张图的 `verts` 不是世界坐标，离线还能用 `matrix/translation` 自己算回来。

编辑器里看这张面：进图按 `Ctrl+Shift+6`（F 层）把 navmesh 画成白色线框；HUD 的
`walk-srf yes 1236 tris / 944 verts` 就是这一行读数，`none` 表示这张图原生没有 NavMeshGraph。

### 4. 按「原生给了什么」分四类

| 类别 | 地图 | 说明 |
| --- | --- | --- |
| 只有 PointGraph（点就是路面） | 运输船 786 · 生化酒店 3063 | 没有 navmesh，人机全靠点网走 |
| 只有 NavMeshGraph（没有路点图） | 胜利广场 `nm716` · 死亡擂台 `nm60` | 场景里 0 个 WayPoint，**永远采不到路点** |
| 两者都有 | 小型工厂 · 椰岛之巅 · 竞技场 · 刀锋寨 · 沙漠要塞 · 新寂静村 | 点图多半只做 node link / 补充，人机主要走 navmesh |

```
python app\tools\data\scan_native_nav.py                  # 静态：读游戏场景 + assets，列出两张图的原生参数
```

`python app\tools\data\organize_maps.py --archive` 把新导出归档进 ② 开发版，确认没问题再
`publish` 到 ③、`freeze --force` 回 ①（顺序必须是 organize → publish → freeze）。

### 怎么验证这张表（可复现）

`assets.xml` 里每一条 `<Asset>` 都有 `<Name>`（脚本类名）和 `<Source>`（哪个场景文件）。
数「`<Source>` 含 `levelN` 且 `<Name>` 等于某脚本」的条目，就是上表一格。

三处能和上文对上，说明数的是同一套东西：

| 交叉核对 | 算法 | 实测 |
| --- | --- | --- |
| 小型工厂点图 12 点 | `NodeLink2` × 2 | 6 × 2 = **12** ✔ |
| 刀锋寨点图 18 点（场景 0 个 WayPoint） | `NodeLink2` × 2 | 9 × 2 = **18** ✔ |
| 沙漠要塞点图 12 点（场景 8 个 WayPoint） | 8 + `NodeLink2` × 2 | 8 + 2×2 = **12** ✔ |

### 由这张表直接得出的三个结论

1. **不是每张图都靠点图走路**：胜利广场、死亡擂台只有可走面；运输船、生化酒店只有点图。改错层 = 没反应。
2. **生化图才有人机组件**：`NanoGuardPos / NanoGuardArea / PointNodeTagModifier` 只出现在沙漠要塞(7)和新寂静村(10)。
   团队图（运输船/小型工厂/椰岛之巅）最多只有蹲点 + 跳跃/连线。
3. **旧守卫系统（`Bot_GuardPos` / `Bot_GuardArea`）只活在生化酒店(8)**，而它在当前版本里是死数据——
   想给生化酒店加"守区"，必须自己造 `Bot_NanoGuardArea`（插件的 `act_guard()` 就是干这个的）。

## 模式 ↔ 地图（工作台下拉的分组口径，2026-11-19 按 `ToChinese` 复核）

| 3 | `StringLiteral_3340` | 救世主模式 |
| 4 | `StringLiteral_3493` | 终结者模式 |
| 5 | `StringLiteral_3451` | 生化剑客模式 |
| 6 | `StringLiteral_3244` | 多人终结者模式 |

工作台下拉按「一张图只进一个主模式」分组（组之间可以重叠，见下面的备注）：

| 模式 | 地图 | 依据 |
| --- | --- | --- |
| 团队模式（0） | 运输船 · 小型工厂 · 椰岛之巅 | `sharedassets0.assets` 选图表 TeamDeath 组（3 条） |
| 个人竞技（1） | 胜利广场 | 选图表 DeathMatch 组（1 条） |
| 特殊战（2） | 竞技场 · 刀锋寨 · 死亡擂台 | 选图表 Special 组（3 条） |
| 救世主模式（3） | —（本包无场景） | 选图表没有 Nano3 组 |
| 终结者模式（4） | 生化酒店 · 沙漠要塞 | 选图表 Nano4 组（2 条） |
| 生化剑客模式（5） | 沙漠要塞 · 生化酒店 | 选图表 Nano6 组（2 条） |
| 多人终结者模式（6，社区叫"多人生化"） | 新寂静村（+ 隐藏图 飓风危城） | 选图表 Nano4_Terminator 组（1 条）；隐藏图默认只注入这一组 |

- **不能按“组”反推模式归属**：`Nano4`（终结者）和 `Nano6`（生化剑客）两组都同时列了「生化酒店 · 沙漠要塞」，
  这两张图对两个模式都成立。旧版把「生化模式 = 生化酒店 / 生化剑客 = 沙漠要塞」拆开是错的（游戏里也没有叫
  “生化模式”的 `GameMode`，生化系是 3 救世主 / 4 终结者 / 5 生化剑客 / 6 多人终结者）。
- **“多人生化”不是 `Nano6`**：`IsMultiPlayerMode` 只有 `gameMode == 6` 为真；
  `IsTerminatorMode` = `4 或 6`；`IsNanoMode` = `3..6`。
  所以 `Nano6` 的中文是**生化剑客模式**，`Nano4_Terminator` 才是**多人终结者模式**。
- 隐藏图 `level9`（场景名 `nano30_storm`，中文 **飓风危城**）**不在游戏自带选图表里**：插件按
  `ucf_mod.json` 的 `scene` / `label` 把它追加进 `MapAsset`，`plugin.c` 的 `gGameMode = 6` 默认只注入
  多人终结者（6）那一组，所以它出现在“多人生化”下拉里。`maps\10_暴风.json` 的「暴风」是旧称呼，文件名暂不改。
