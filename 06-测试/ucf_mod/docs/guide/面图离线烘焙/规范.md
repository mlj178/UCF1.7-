# 面图（navmesh）制作规范 · 从数据到可走点网

> 适用：任何一张图（storm 是第一个跑通的样本）。目标是把"哪里能站、怎么走"变成插件能吃的点图，
> 并且**每一步都有数据依据**，不靠猜。

## 1. 数据源（按可信度从高到低）

| 优先级 | 数据 | 怎么来 | 说明 |
| --- | --- | --- | --- |
| ① 真值（唯一） | `log/ground_samples_<地图>.txt` | 控制台 → 开发者选项 → **跟随式采样**（人走一圈） | **玩家脚下的碰撞面**：土丘 / 斜坡 / 楼梯 / 室内地板都在；跳上去才够得着的屋顶天然采不到 |
| ② 几何 | `data/geo/web/<map>.bin`（UCFG） | 工作台/地图导出 | 视觉网格，可能缺地面、含屋顶；**不是碰撞面** |
| ③ 中间件 | `data/geo/<scene>.npz` | extract_geo.py | 与 ② 同源，只多法线/分组信息 |
| ④ 场景 | `levelN` + `sharedassetsN.assets` | 游戏目录（只读） | 用来核对"场景里到底有几个网格/有没有碰撞体" |

**判定顺序**：① 跟随采样 > ② 几何。两者冲突时以 ① 为准。

**为什么 ② 不能当主数据（2026-11-28 实测）**：用导出的视觉网格烘 Recast，只能覆盖游戏里量出来的
2 669 个地面点里的 **33%**，分岛 48 块、平均三角形 2.4 m²（原生 DesertFort 是 1 块、0.31 m²）。
所以"面补不齐 / 土丘和室内地板漏掉"的根因不是参数，是**数据源错**。

> 2026-11-28 还删掉了一条路：「地面扫描」——从天上（300 m / 4 m）往下打射线扫整图。
> 删掉的原因就是它本身：**4 m 以上的室内地板打不到**，土丘的侧面也打不到，
> 扫出来的"整图地面"看着有、烘成面却是漏的。地面真值只认跟随采样。
> 历史产物 `<图>/ground_low.txt`、`<图>/ground_sweep.txt` 还留在图文件夹里（不能再生成了），
> 只当旧数据参考，不再进流程。

### 1.1 跟随式采样（player-follow sampling）怎么用

```text
控制台 → 开发者选项 → 「跟随式可通行性采样」→ 开始采样
→ 切回游戏，把地图走一圈（地面 / 楼梯 / 室内 / 土丘 / 斜坡都走一下，5~10 分钟）
→ 走完点「停止采样」
```

采集口径（参数写在数据文件第一行，可复现）：

| 项 | 值 | 为什么 |
| --- | --- | --- |
| 网格 | 1.00 m | 0.5 m 数据翻 4 倍；1 m 对寻路够用（土丘/斜坡照样一个格一个高度） |
| 半径 | 8.00 m | 玩家周围一圈；走一条 16 m 宽的带子 |
| 射线起点 | 脚底 + 1.20 m | **低于天花板**，所以室内打到的一定是脚下那块地板；抬到天上就会把屋顶/上层楼板当地面 |
| 向下长度 | 6.00 m | 覆盖台阶和缓坡 |
| 容差 | 3.00 m | 落点比脚低超过 3 m 的不算这一层（桥下/悬崖下另算） |

游戏里能直接看到（采样开着就显示，不用 Ctrl+V）：

- **青色小方块** = 已经采到的地面格
- **亮绿小方块** = 最近 2 秒刚采到的格（走动时能看到一片片从脚下冒出来）
- **黄色圆环**（半径 8 m，带竖柱）= 采样范围
- **左上角一行字** = `跟随采样 ON · 已采 N 格 · 本次 +M`

产物（都在工程端 `log\`，控制台启动游戏时 `UCF_LOG_DIR` 指过去，游戏目录不落任何文件）：

| 文件 | 内容 |
| --- | --- |
| `log/ground_samples_<地图文件夹>.txt` | 每行 `x z y`（米），`sweep2navmesh.py` 直接吃 |
| `log/ground_follow.log` | 会话日志：开/关、每 10 s 一行统计、换图（换图会自动停） |
| `log/ground_follow.status` | 每秒刷一次的 `on/cells/sess`，控制台卡片读它显示计数 |

**边界（必须知道）**：没走过的地方就是空的。它采不到"玩家没去过的地方"，
这是它的定义，不是 bug —— 想补哪块就走进哪块。

## 2. 能站/不能站的判定

- 坡度 ≤ 45°（`--slope 45`）
- 头顶净空 ≥ 1.8 m（`--head`）；有低矮雨棚的地方会被剔掉
- 埋在墙里的格子不算（墙带与站立空间相交）
- **地面层**：面积最大的高度 ±3~4 m；要"多层"就按高度分组各铺一层
- 单格高差上限 `--max-rise`：**2026-11-28 起默认 1.2 × 格子边长**（≈50°）。
  老默认是 0.9（按 1.5 m 手调的），会把 31° 以上的斜坡整片丢掉 ——
  用户明确要求"可走斜坡要"，所以改成跟格子走；要更严就显式给 `--max-rise`。

**格子边长按数据源定，别混用**：

| 数据 | 边长 | 说明 |
| --- | --- | --- |
| `ground_samples_<图>.txt`（跟随采样） | **1.00 m** | 每格记的是**该格自己打到的实际高度**，不做插值，土丘/斜坡/台阶都保留 |

`sweep2navmesh.py` 会自动认（`--cell` > 文件头 `cell=` > 从数据推），不用手填。

## 3. 标准流程（每张图照抄）

```powershell
# ① 进图，控制台 → 开发者选项 → 跟随式采样 → 走一圈 → 停止（生成 log/ground_samples_<图>.txt）
# ② 用真值点烘面（1 m 格，--cell 1.0）
python 代码/sweep2navmesh.py --sweep ..\log\ground_samples_<图>.txt --out out/<map>.navmesh --cell 1.0
#    没有采样数据才退回几何：
python 代码/bake_navmesh.py --map <map> --geo data/geo/<scene>.npz --cell 0.5 --ground-tol 4
# ③ 面 → 点（grow 包；跳行原样照抄）
python 代码/mesh2points.py --navmesh out/<map>.navmesh --user <图>/<fp>.txt --gap 3.0 --dist 3.4
# ④ 装：先备份，再覆盖 <图>/<fp>.txt；面放 <图>/navmesh_auto.bin
```

> ② 的 `--cell` 要和采样口径一致：跟随采样是 **1.00 m**（文件第一行写着），
> 拿 0.5 m 去插值只会把三角形切碎，不会变准。

## 3.5 建图之后必须"重绑"（2026-11-28 实测）

grow 包是"清空重造"，人机身上记的 `GraphNode` 引用会变成野指针，表现为
**每帧 NullReferenceException at Bot.Update、人机直走不拐弯**（只加 1 个点也会出现）。

插件现在的做法：应用完成后调 `bot_rebind_after_apply()`，把每只 Bot 的
`path / gNode_Nearset / gNode_Next / nextJumpStartNode / nextJumpLink` 清空、
`nextFindPathTime` 归零，让它下一帧重新找路。日志：`rebind: 清空 N 只人机`。

要点：**必须用 `FindObjectsOfType(Bot)` 取全部人机**；`Bot.hangoutList` 只是闲逛名单（实测只有 1 只）。

## 4. 校验清单（装之前逐条对）

1. 面：三角形数、面积、分岛数（日志里有）
2. 点：`node add` + `edge add` + `jump add` **总数 < 8192**（插件编辑上限）
3. 跳：`jump add` 行必须**原样照抄**——跳蹲参数在行尾（例：`0.57 -1.00 0`）
4. 边：每条都是**双向**；单向会出现"一半方向走不通"
5. 进图后 trace 看 `near`：不动的人机如果 `near=00000000`，说明那里没节点

## 5. 已知坑（都踩过）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 人机全部不动 | 运行期加点超过进图时节点数，A* 寻路线程崩 | 只用 grow 包建点，别在运行期 append |
| 跳点丢失、跳蹲失效 | 编辑数超 4096 被截断；或跳行被重写 | 跳行放最前、原样照抄；上限已提到 8192 |
| 部分人机不动 | 边单向 / 节点被截断 | 双向边 + 控制在编辑上限内 |
| 游戏闪退 | 自建图只被 C 变量引用，被 GC 回收 | 用 `il2cpp_gchandle_new` 钉住 |
| 面图挂上但人机更糟 | 半成品 NavMeshGraph 参与寻路，最近节点踩空 | 面图只显示、不挂 `AstarData.graphs` |
| 地面像一整块平板 | 1 m 栅格把土丘抹平 | 0.5 m + 顶点中位 + 高差过滤 |
| 明明有地面却没铺 | 导出网格缺地面（水面/远景板/没导到） | 以 `ground_samples_<图>.txt` 为准 |
| 室内地板整片漏掉 | 从天上往下扫打不到 4 m 以上的室内地面（那条路已删） | 用跟随采样（射线起点是脚底 +1.2 m，在室内也在天花板下） |
| 土丘 / 斜坡被抹平 | 1 m 栅格 + 顶点取中位数会把小起伏吃掉 | 跟随采样每格记的是**该格自己打到的实际高度**，不插值；不够细就再把 `--cell` 降到 0.5 补采 |
| 采样开着换了图 | 换图会自动停（加载那几秒玩家位置是假的） | 换图后重新点「开始采样」；数据按图名分文件，不会串图 |
| 采了半天数字不动 | ①没进图（大厅读不到玩家位置）②DLL 是旧的 | 看 `log\ground_follow.log` 有没有 `拿不到位置`；先 `app\tools\build.ps1 -Payload` 再重开游戏 |

## 6. 迁移到新图（清单）

1. 确认场景号与中文名（地图对照表）
2. 进图开"跟随式采样"，把图走一圈，拿 `log/ground_samples_<图>.txt`
   （走不了才退回几何）
3. 跑 `sweep2navmesh.py` 或 `bake_navmesh.py`，看面积/分岛是否合理
4. 跑 `mesh2points.py`，检查编辑数 < 8192、跳行原样
5. 备份原包 → 安装 → 进图 → 抓一份 trace
6. 看 `diag: path=` 与 trace 的 `near`，不动的人机定位到坐标

## 8. 追加：不要调用 PointGraph.Scan（2026-11-28 实测）

想用 A* 自己的"距离 + 射线"重建连接，调了 `PointGraph.Scan()`，结果：

- 日志 `naved: applied ... (nodes 0 -> 0)` —— 整张图被清成 0 节点；
- 游戏日志 NRE 从 224 涨到 6,104。

原因：A* 的 Scan 会把节点当"自己的子对象"重建，运行时 `AddNode` 加进去的点不在它的名单里，
于是先把图清空。**射线过滤必须自己做**：遍历边，对每条边打一根射线，被挡就删这条边，
既不动节点也不调用 Scan。

### 9.1 两个必须知道的坑

**① 屋顶那层采不到（占用户路线的 40%）。** 196 个路线点，水平方向 **196/196** 都落在采到的地面上
（说明平面范围走全了），但高度上：15 个 ±0.5 m、97 个 ≈ +1.4 m、**78 个高出 3 m 以上**（屋顶 / 二楼）。
玩家没上去过的层，采样就是空的 —— 这是方法的边界，不是 bug。要那层就再走一遍楼梯/屋顶。

**② 旧路线点整体浮在地面上 1.4~1.5 m。** 拿两套独立的地面参照（本次跟随采样、旧的 4 m 扫描）比，
196 个点的 dy 中位数都是 +1.4 / +1.5 m。这不是采样错（两套地面互相吻合，见上表），是**路线点本身**的性质。

后果：`mesh2points.py` 的桥接条件是「水平 ≤2.2 m 且 |dy| ≤0.9 m」，
所以新铺的地面点跟老路网点几乎接不上 —— 原样 11 条桥，把老点贴到地面后 31 条。
**新点网会自成一片，人机不会用。** 铺完必须先把两张网连起来（下一步：每个老点就近连到 4 m 内的新地面点），
否则装了等于没装。

2. **桥接换方向**：从"面图点找最近的用户点"改成"**每个用户点**就近连到面图点"（水平 ≤3.0 m、高度差 ≤1.8 m）。

**这一版还差什么**：屋顶/二楼那 91 个手摆点没有对应的采样（玩家没站上去的地方采不到）；

这就是第二遍只多出 55 格的原因。要补顶层得改采样表结构（按 (x,z,层) 存 + 分层烘面），不是参数问题。


## 10. 人机不动 / 不去守卫区 —— 2026-11-28 18:22 那份 trace 的结论

数据：`data/maps/_inbox/trace/level9_20261128-182205.jsonl`（29 只人机 × 126 帧，20.8 s）
+ `log/ucf_mod.log` 里同期的 `beh: bot=...`（504 条行为采样）。

### 10.1 结论：**点图碎了，不是人机的锅**

| 证据 | 数字 |
| --- | --- |
| 人机本身正常 | 29 只里 10 只跑得好：位移 56~79 m、最高速度 9.0~9.4 m/s |
| 不动的 20 只拿到的是**退化路径** | 全程 `pts` 最大只有 **2**（= 起点到终点是同一个节点，"我已经到了"），`spd` 恒 0 |
| 点图连通块 | 装进去的包 **52 块**：街面 **379** 点 / 中层平台 **166** 点 / 屋顶各 1~44 点，另有 **31 个孤立点** |
| 守卫点可达性 | 46 个守卫点，最近的节点分别落在 #1(12) #25(10) #2(9) #4(7) #7(6) #13(1) #6(1) —— **没有一个是街面那块（#0）** |
| 守卫任务 | 504 条行为采样，动作栈只有 `Saunter` + 生化动作（WantInfected / PickUpUpgradeBox / BecomeHero），**零条守卫动作** |

所以顺序是：① **游戏这一局根本没派守卫任务**（全是闲逛）；② **就算派了也到不了** —— 6 个守卫区全在
y 8.6~15.5 的高层，而那些点各自成孤岛，街面出发的 A* 找不到路，返回 1 节点路径，人机就站着。

### 10.2 为什么会碎（三条，按责任大小）

1. **手工删点把主干切断了**：18:13 装进去是 799 点、最大连通块 **714** 点；18:15~18:21 用户在游戏里
   删了 **80 个点**（日志里 80 条 `node disabled idx=`），保存后变成 719 点，
   最大块 **379 + 166** 两块 —— 删掉的正是连接两块的关键点。
2. **手摆点比地面高 1.4~1.5 m**，天然不属于地面那一层；桥接只连了 55 个，剩下的高层手摆点
   靠自己的 354 条边自成网络（#2 有 42 个手摆点、y 4.8~14.5）。
3. **面图本身有 23 个岛**（悬崖/楼层之间没有可走连接），这是高度表的本质，不是参数问题。

### 10.3 该怎么做（别删点）

「把面图铺的点删掉、只留手摆点」这个想法，量一下就知道不行：

| 方案 | 29 只人机到最近节点的距离中位 | 超过 3 m 的 |
| --- | --- | --- |

3. 守卫区在 y 8.6~15.5，必须在那一层铺点，否则那 46 个守卫点永远连不到街面；
4. **不要在游戏里手工删点**：删掉的往往是割点，删一个能把整张图切成两半。

### 10.4 新手怎么自查（一分钟）

1. 数连通块：把 `<图>/<fp>.txt` 的 `node add` / `edge add` 读进来做并查集 —— 块数 > 5 基本就有问题；
2. 看 `beh:` 里的 `pts`：**pts=2 且 spd≈0 = 目标不可达**（不是没点，是那个点上不去）；
3. 看 `nearD`：一直 > 3 m 说明脚下就是空的。


### 10.5 跳点为什么救不了（2026-11-28 实测 12 条跳线）

用户问："我不是做了跳跃点连到守卫区了吗？" 量了一遍 12 条跳线各自两端节点落在哪个连通块：

| 跳线 | 两端所在块 |
| --- | --- |
| #1~#4 | 都在 **#1（18 点）** 的高层小块里 |
| #5~#11 | 都在 **#2（44 点）** 的高层小块里 |
| #12 | 都在 #0（街面块）里 |
| **跨块的** | **0 条** |

结论：这些跳点是"**屋顶跳屋顶**"，不是"楼下跳楼上"。

插件里跳点只做一件事（`nav_apply_jumps`）：给「起点节点 → 落点节点」补**一条单向边**
（`nav_conn_set(ia, ib, 1)`）。它不会把两块互不相连的图拼起来 ——
A* 必须先能走到跳点的**起点**，路径里才会出现"下一段该跳"；
起点所在那块到不了，跳链一次都不会触发。

**要连通楼上楼下，只有一条路：在楼梯/坡/缺口上铺普通路点并连边**（点 → 边），
跳点只是在"已经能走到的地方"提供一个更快的过法。
