# 部署与首次设置（2026-11-22）

> 目标：任何一台装了 UnityCrossFire 1.7.1 的机器，选一次 `UnityCrossFire.exe`，
> 点一下就把插件装进游戏目录，不需要手工拷 dll。

## 一、一键部署

**主路径就是控制台的「部署」页**：选 `UnityCrossFire.exe` → 看状态 → 点「一键部署」。

命令行只在排查 / 脚本化时才用（`一键部署.cmd` 已删除，不需要它了）：

```powershell
python tools\deploy_mod.py --pick                          # 弹窗选 exe
python tools\deploy_mod.py --game-exe "D:/games/UnityCrossFire.exe"
```

常用参数：

```powershell
--dry-run      # 只打印计划，不写盘（第一次建议先跑这个）
--verify       # 只校验已部署的文件
--repair       # 哈希相同也强制重拷
--uninstall    # 按部署清单卸载，并还原覆盖前的文件
--allow-cjk    # 放行中文路径（有风险）
--force        # 允许覆盖别人的 winhttp.dll（比如 BepInEx 的）
```

## 二、六道闸门（任何一道不过 → 整体中止，一个文件都不写）

| # | 检查 | 不过时 |
|---|---|---|
| 1 | `UnityCrossFire.exe` 存在 | 中止 |
| 2 | `UnityCrossFire_Data\globalgamemanagers` 存在 | 中止 |
| 3 | `GameAssembly.dll` MD5 = `fab04426…` | **中止**（只支持 1.7.1，换版本要改 `deploy_mod.py` 里的常量） |
| 4 | 游戏进程没在跑 | 中止，提示先退出 |
| 5 | 目录可写 / 不在 Program Files / 路径不含中文 | 前两项中止；中文只警告，加 `--allow-cjk` 放行 |
| 6 | 磁盘 ≥ 50 MB | 中止 |

另外多一道：目标里已有**别人的** `winhttp.dll`（比如 BepInEx 的 22,016 B 那个）→ 中止，加 `--force` 才覆盖。

## 三、会往游戏目录写什么

```
<游戏目录>\
  winhttp.dll            代理加载器（51,603 B，sha256 见 payload/MANIFEST.json）
  winhttp_orig.dll       部署时从 %WINDIR%\SysWOW64\winhttp.dll 现取，不随包发
  ucf_mod\
    ucf_mod.dll          插件本体
    uninstall.ps1        插件自带的卸载脚本
    README.txt           给用户的说明
    deploy_manifest.json 本次部署清单（由工具生成，别手改）
    backup\deploy_<时间戳>\  被覆盖文件的原件，卸载时还原
```

**不写**：`ucf_mod.json`（缺省走内置默认，控制台首次保存时生成）、`markers\`、`navdata\`、任何场景文件。

## 四、幂等 / 修复 / 卸载

- 目标文件 sha256 与 payload 一致 → 跳过。再点一次就是"修复"。
- `--uninstall` 只删清单里登记过、**且哈希没被改过**的文件；改过的不动，会列出来。
- 卸载会把 `backup\deploy_<时间戳>\` 里的原件还原回去（例如拷回来一个 BepInEx 的 winhttp.dll）。

## 四点半、控制台里的「部署」页

控制台现在有一个 **部署** 页签（在「数据」右边），不用再去找 cmd：

| 区域 | 内容 |
|---|---|
| 游戏位置 | 显示当前游戏目录 + 来源（环境变量 / 用户设置 / 工程配置）；「选择 UnityCrossFire.exe」换位置 |
| 部署状态 | 5 个运行件逐个列状态：一致 / 缺失 / 不一致 |
| 操作 | 一键部署 · 修复（强制重拷）· 校验 · 卸载 · 首次设置向导 |
| 输出 | 部署过程的完整输出 + 退出码 |

### 启动位置看得见、记得住（2026-11-22）

- 底部「开始游戏」按钮末尾固定带一个短标签：`［test-1］`、`［BaiduNetdiskDownload］`
  —— 多份游戏副本共存时，一眼看出点的是哪一份。
- 按钮上方的启动条件条多一行 `启动位置：D:\...\UnityCrossFire.exe`；文件不在会变红。
- 「部署」页有「历史位置」下拉框：**当前生效的那条永远排第一**（哪怕它不是我们写进配置的，
  而是程序从环境变量 / `tools\deploy.json` 解析出来的），后面才是最近用过的记录（最多 6 条）：
  - 下拉项是 **短标签 + 盘符**（`test-1（D:）`），下面单独一行显示**完整路径**——
    路径太长做中间省略时容易把 `test-1` 这种关键层级吃掉，光看下拉框会选错；
  - 「切换并重启」= 把它设成当前位置并重启控制台（`DEPLOY` 是 import 时算的常量，必须重启）；
  - 「忘记」删掉一条记录；当前正在用的那条删不掉。
- 记录存在 `%LOCALAPPDATA%\UCFMod\deploy.json` 的 `history` 数组里，最多 6 条。
- 部署成功会自动把它写成当前位置（即「记住这次部署的那份」），并问一句要不要立刻重启切过去。

换了游戏位置后，点「重启控制台」让其它页签也跟着换（`DEPLOY` 是 import 时算的常量）。
## 五、控制台首次设置

控制台启动时如果发现游戏位置没配好（或配的路径已经不在了），会先弹**首次设置**窗口：

选 `UnityCrossFire.exe` → 六道闸门 → 一键部署 → 「完成并启动控制台」（自动重启一次，因为路径常量是 import 时算的）。

配置写在哪里、优先级：

| 顺序 | 位置 | 说明 |
|---|---|---|
| 1 | 环境变量 `UCF_DEPLOY` | 最高，临时覆盖用 |
| 2 | `%LOCALAPPDATA%\UCFMod\deploy.json` | **用户在向导里选的**，写的就这 |
| 3 | `tools\deploy.json` | 开发机自己的路径（已 gitignore） |
| 4 | 工程根 | 兜底 |

`ucf_paths.game_dir_of()` 可以把部署根（`<游戏>\ucf_mod`）还原成游戏目录。

## 六、加载器源码（曾经丢失过）

`src\proxy\` 是 2026-11-22 从 `payload\winhttp.dll` 反推复原的源码，重编：

```powershell
powershell -File src\proxy\build_proxy.ps1
```

它会从参考 DLL 的导出表重建 `winhttp.def`（92 个转发），编译后自动比对导出名。
细节和复原依据见 `src\proxy\README.md`。

## 七、坑

| 现象 | 原因 / 处理 |
|---|---|
| 装完进游戏没有任何变化 | 必须从控制台「开始游戏」启动（会注入 `UCF_MOD=1`）；直接双击 exe 是原版 |
| 启动就报 `winhttp.dll` 加载失败 | 缺 `winhttp_orig.dll`。重跑一次部署即可（会从 SysWOW64 现取） |
| 部署后游戏启动更慢/闪退 | 先用 `--uninstall` 退回，再看 `ucf_mod\ucf_mod.log` |
| 提示"已是别人的 winhttp.dll" | 装了 BepInEx。两者只能留一个：要么先卸 BepInEx，要么 `--force`（会备份原件） |
