# 面图：需求、失败方案、成功方案（2026-11-28 · storm 首图）

## 一、需求

- **目标**：给 UCF 1.7 的图做出真正能让人机走的"面图（navmesh）"，最好是离线一条命令批量生成，
  不靠人手工摆点，并且人机真的按它走路。
- **约束**：游戏目录一个字节不改；资源/日志/产物全在工程里；可分发、可备份 GitHub；
  每一步要有数据依据，不做盲目调参。
- **这条路实际拐了三个弯**：
  1. 先做**点图**（按路线铺点）→ 人机走不了
  2. 改做**真面图**（烘焙三角网）→ 数据源错了
  3. 最后落到**玩家脚下的碰撞地面采样**（跟随式采样）→ 成了

## 二、哪些方案失败

| # | 方案 | 怎么失败的（证据） | 留下的产物 |
| --- | --- | --- | --- |
| F1 | 导出视觉几何 → Recast/Unity 烘面 | 烘出来的面只覆盖游戏自扫地面的 **33%**，48 个岛、平均三角形 2.4 m²（原生 0.31）；土丘、室内、二楼全缺。**根因：视觉网格不是碰撞面** | `unity-navmesh/` 整个工程、`bake_navmesh.py`、`export_*.py`、`map_geometry.obj`、`out/` 里一堆 `.navmesh/.png` |
| F2 | AssetBundle 加载面图 | 游戏里崩在 `LoadFromFile` 内部 | `navmesh_bundle`、C 里 `if (0 && …)` 的死分支、`资产化方案.md` |
| F3 | 从天上扫整图 | 4 m 以上的室内地板、土丘侧面打不到 | `ground_sweep.txt`、`ground_low.txt`（留作交叉校验） |
| F4 | 运行期加节点 / 点图变体 | 超过进图时的节点数 → `PathHandler` 越界 → 寻路线程死 → 人机僵直 | `*_grow.txt` 一堆变体包 |
| F5 | `PointGraph.Scan()` | 把图清成 0 节点，NRE 从 224 涨到 6,104 | 无（代码已删） |

> 除 F3 的数据（留作校验）外，其余产物 **2026-11-28 已全部清理**，详见
> [`面图离线烘焙/清理记录.md`](面图离线烘焙/清理记录.md)；需要找回用 git。

## 三、哪些方案成功

| # | 方案 | 结果 |
| --- | --- | --- |
| S1 | 跟随式可通行性采样（插件 `gf_*` + 控制台"开发者选项"卡片） | 6,238 格 / 5,639 m²、99.9% 连成一片、0–15.4 m 多层，游戏里能看到青色/绿色方块和采样环 |
| S2 | `sweep2navmesh.py`（1 m 格 → UCFN v2） | `navmesh.bin`：6,400 顶点 / 11,026 三角 / 204 KB |
| S3 | `mesh2points.py`（面 → grow 点图，分层桥接修正） | 点图 768 点 / 2,000 边 / 21 跳；主块 85%→95%，孤立点清零（v5 待装） |
| S4 | 文档：`规范.md` + `README.md` | 数据源优先级、采样口径、10 条坑、逐次实测数据 |

## 四、现在跑的是哪条

```
控制台「开始采样」→ 走一圈 → log/ground_samples_<地图>.txt
        → sweep2navmesh.py   → navmesh.bin   （面图：负责显示 + 地面真值）
        → mesh2points.py     → n0-….txt      （点图：人机实际走的就是它）
```

细节（采样口径、参数、坑、实测数据）看 [`面图离线烘焙/规范.md`](面图离线烘焙/规范.md)。
