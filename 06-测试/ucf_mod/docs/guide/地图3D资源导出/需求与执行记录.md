## 1. 背景与目标

路点工作台的 3D 原来只有灰模，或者贴图位置明显不对。目标是：

1. 3D 地形按游戏原贴图渲染，能认出船体、建筑、箱子、地面；
2. 贴图位置有明确的数据来源，不靠猜；
3. 以运输船为样板，推广到全部地图；
4. 数据、代码、截图可追溯，资源集中存放，别人也能复用；
5. 做完逐图复查，并在工作台 3D 里实测。

## 2. 需求清单

- 贴图位置必须正确；要说明依据是 UV、世界坐标还是别的东西。
- 先给结论和反馈，再判断是否理解需求。
- 要查清是数据源问题、选择问题还是其他问题，不能只修表面。
- 允许用 **AssetRipper 的持久化导出工程**做数据源；**不需要打开 Unity Editor**。

- 修掉“箱子贴图不合理”（绿色帆布像碎片）的问题。
- 04 胜利广场、07 死亡擂台不能加载成新寂静村。
- 完成后多检查、多复查。

## 3. 根因与结论

### 3.1 最初贴图为什么不对

- 贴图位置由**游戏网格自带的 UV0** 决定，不是按世界坐标投影。
- 最初 3D 画的是 `X (1)` + `CrossFire/Shadow` 的**影子/碰撞代理**，贴图是从可见的 `X` 网格按名字借的。
- 这是**选择问题**：应该画可见的 `X`（真实材质 + MeshCollider），而不是影子代理。

### 3.2 绿色帆布像碎片

- `SBOX_01`、`SBOX_02`、`TSHIP_012` 等材质在游戏里是 **Opaque（不透明）**，`_AlphaClip=0`。
- 早期 shader 对所有贴图都做 `alpha < 0.5 discard`，把不透明帆布的透明通道也抠掉了，所以看起来像网格碎片。
- 修复：只有 `_AlphaClip=1` 的材质才镂空；绳网、铁栅栏保留镂空，不透明帆布保持实体。

### 3.3 其他地图的 UV 问题

- 有的网格 UV 是 **Float32**（offset 24），有的是 **Float16**（offset 20/28）；早期只认 Float16，导致条纹/NaN。
- 个别网格 UV 是未初始化的垃圾值（如 level2 的 `factory_tanklorry01`、`factory_bl_a`）。
- 修复：按 `m_Channels` 的 `format` 区分 Float32/Float16；垃圾 UV 用 XZ 平面投影兜底。

### 3.4 04 / 07 加载成新寂静村

- 04 胜利广场、07 死亡擂台没有 `map.json`，只有 `navmesh.bin`（工作台显示「仅可走面」）。
- 3D 侧栏原来只在有 `map.json` 时才拼 `&open=...`，没有 `open` 时 navview 的 `autoOpen()` 回退到上一张快照，结果停在新寂静村。
- 修复：工作台 3D URL 始终带 `&level=<level>`；navview 支持 `?level=`，没有 map.json 也能直接加载对应地形和可走面。

### 3.5 复刻时最容易踩的坑

| 现象 | 原因 | 正确做法 |
| --- | --- | --- |
| 3D 是影子/黑色空洞 | 画了 `X (1)` + `CrossFire/Shadow` 的影子/碰撞代理 | 只取可见 `X`：材质不是 `CrossFire/Shadow`，且有 MeshCollider |
| 箱子/帆布像碎片 | 对所有贴图都做 `alpha < 0.5 discard` | 只对 `_AlphaClip=1` 的材质镂空；Opaque 帆布保持实体 |
| 墙面条纹、UV 乱飞 | 只按 Float16 读 UV | 按 `m_Channels` 的 `format`：0=Float32，1=Float16 |
| 物体位置翻倍/偏移 | 合并网格顶点已经是世界坐标，又乘了一次 Transform | 合批物体直接用子网格世界坐标；单体物体才乘 Transform |
| 贴图串图 | 不同目录有同名 PNG，互相覆盖 | 同名但源文件不同时，加 6 位 hash 后缀 |
| 04/07 3D 显示上一张图 | 没有 `map.json`，URL 也没带 `level` | 工作台 URL 带 `&level=levelN`，navview 支持 `?level=` |
| 地图缺灯片/水面/少量小物件 | 内置 Quad/Plane 不在 AssetRipper 导出工程里 | 明确跳过，或用简单面片补；不要误判为导出失败 |
| 运输船位置对但贴图不对 | 贴图是从同名可见块借的，材质本身是 Shadow | 改画可见 `X`，不要给 Shadow 代理贴图 |

## 5. 执行过程

1. **定位根因**：3D 画的是 `X (1)` Shadow 影子代理，贴图从可见 `X` 借；确认不是 UV/贴图文件本身错。
2. **导出工程文件**：用 AssetRipper.GUI / HTTP API 导出 Unity Project 格式的工程（1.33 GB）；`ProjectVersion` 为 2020.3.30f1c1，仅作记录，未启动 Unity。
3. **运输船跑通**：写 `scene_export2web.py`，生成 level1 的 bin + 68 张贴图；替换 `geo/web/level1.bin`。
4. **修 alpha**：不透明帆布不再被抠；绳网/铁栅栏仍镂空。
5. **推广全地图**：批量生成 level2..level11；修 UV Float32/Float16、垃圾 UV、内置 Quad、贴图重名。
6. **逐图复查**：贴图缺失、UV 范围、bbox、路点覆盖、近景/拼图、工作台实测。
7. **修 04/07**：工作台 3D URL 带 `level=`；navview 支持无 map.json 直接加载。
8. **资源集中**：AssetRipper 工程、截图、最终 bin/贴图副本移到 `00-游戏逆向分析-相关信息\地图3D资源导出`；代码和文档收进 `docs/guide/地图3D资源导出`。
9. **清理中间态**：删除日志、`guid_map.json` 缓存、测试 bin/贴图、旧 v1 备份、旧贴图备份。
