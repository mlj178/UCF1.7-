# 寻路全流程 · 从建图到蹲下

> **类型：读（原理）**——讲一条链路，不查数据；要查模式 / 阵营去 [游戏基础信息.md](游戏基础信息.md)，查偏移 / 地址去 [record/逆向速查_版本偏移与地址.md](../record/逆向速查_版本偏移与地址.md)。

> **回答什么**：`A*`、`A* Pathfinding`、`PointGraph`、`PointNode`、`WayPoint`、`NodeLink`、`BotAction` 各是什么关系；人机从进图到蹲下，中间到底跑了哪几步。

## 0. 一句话

**A\* Pathfinding 提供"图 + 最短路"，游戏自己决定"想去哪"；路点是图里的节点，蹲点/守点是目的地标记，`BotAction` 是决定目的地的裁判，`Seeker` 是两者之间的翻译。**

---

## 1. 先分三层，别把"数据"和"逻辑"混着看

三层的完整表（每层在游戏里长什么样、谁决定、改它要动什么）在 [人机与路线设计.md](人机与路线设计.md) §1，这里不再抄一遍。
这里只留边界——把"谁负责什么"记牢，后面看流程就不会混：

- **插件层**（第三方 `Pathfinding`）：把场景 / 网格变成"图"，回答"**怎么走**"；
- **游戏数据层**（关卡策划摆的组件）：只提供**坐标**，"能站哪"由插件决定；
- **行为层**（`BotAction`）：只决定"**想去哪**"。

**关键**：这三层之间只靠**一个 `Vector3` 坐标**通信。行为层不碰图，插件不知道"蹲点"是什么。

## 2. 类关系树（一眼看清谁继承谁）

```
A* Pathfinding Project（插件）
├─ AstarPath            场景单例，管所有图，Scan() 入口
│   └─ graphs[]
│       ├─ PointGraph ── nodes[] ── PointNode : GraphNode
│       │                              └─ connections[] ── Connection{node, cost}
│       └─ NavMeshGraph（三角网，另一套）
├─ Seeker               挂在人机身上，StartPath(start, end) → Path(ABPath)
└─ GraphModifier        扫描后回调：NodeLink / NodeLink2 / Bot_JumpLink / PointNodeTagModifier

游戏（UCF）
├─ Bot                  actionList、seeker、path、nanoGuard
├─ BotActionBase 子类    每帧 Destination_Listener(ref pos, ref priority)
└─ 场景标记物            Bot_CrouchPos（蹲点）、Bot_NanoGuardArea/Pos（守区/守点）、MapManager（出生点）
```

> **蹲点 / 守点不在这棵树的"图"那半边**——它们是游戏自己的组件，只提供坐标，不是可走性。

## 3. 整个流程怎么跑起来（五个阶段）

### 阶段 A：进图建图（一次性，几秒）

1. `AstarPath.Scan()` → `PointGraph.Scan()`
2. 遍历场景里 **tag = `WayPoint`（20022）** 的物体 → 读世界坐标（毫米整数 `Int3`）→ 每个物体 `new PointNode`，塞进 `nodes[]`
3. `ConnectNodes()`：两两判断 **距离 ≤ `maxDistance`**（本游戏 2.1 / 4.6 m 两档）+ **射线没被挡**（`raycast` + `mask`）+ **轴向差在 `limits` 内** → `AddConnection()`，`cost` 按距离算
4. `GraphModifier.OnLatePostScan()`：`NodeLink` 补边、`NodeLink2` 建端点图、`Bot_JumpLink` 把"起点节点 → 终点"登记进 `linkDic`、`PointNodeTagModifier` 打 tag
5. 结果：**一张静态图**。之后所有寻路都在这张图上，不再看场景物体——所以改场景里的路点物体**不重扫，图不会变**

> 本节以点图为例。只有可走面的图（胜利广场 / 死亡擂台）在阶段 A 换成 `NavMeshGraph` 载入三角网，**B–E 完全一样**。

### 阶段 B：每帧决定"去哪"（行为层，跟图无关）

1. `Bot.UpdateAction()` 遍历 `actionList`
2. 每个 Action 通过 `Destination_Listener` 报 `(坐标, 优先级)`
3. **优先级最高的赢**（箱子 51 > 逃跑 10 > 闲逛 7 > 守点 6 > 追敌 5；完整表见 [人机与路线设计.md](人机与路线设计.md) §2）
4. 赢家给出目标坐标——可能来自蹲点、守点、敌人、箱子、随机闲逛点

### 阶段 C：寻路（插件）

1. `Bot.PathSetting()` → `Seeker.StartPath(当前位置, 目标坐标, OnPathComplete)`
2. `Seeker` 在后台线程跑 A\*：起点/终点**吸附到最近节点**，按 `cost + penalty` 搜最短路
3. 产出 `Path`：节点序列 + `vectorPath`（世界坐标折线）

### 阶段 D：沿路走（插件 + 游戏）

1. `OnPathComplete` 回调 → `Bot` 拿到路径
2. 若路径里 起点节点 的**下一个节点**正好是某条 `Bot_JumpLink` 的 `endNode`（=两点在图上连着）→ **插入跳跃段**（`JumpCheck` / `Jump`）；只有起点没有边不会触发，见 [人机与路线设计.md](人机与路线设计.md) §3.2.4
3. `Move()` 沿 `vectorPath` 走，**到点 1.5 米内算到达**，0.25~0.5 秒重算一次

### 阶段 E：到了之后干什么（行为层的"后半段"）

- **蹲点**：`TryCrouch()` 蹲下，朝 `zoomPos` 方向架枪
- **守点**：站定扫视、开火；被压 → `isEscaping` → 跑 `escapePos`
- **闲逛/追敌**：到了再挑下一个目标，循环

> 蹲点/守点只负责"终点"，**走不走得过去是图的事**。

## 4. 一次真实经历（运输船 / 小型工厂）

```
进图 Scan：运输船是纯点图 → 场景里的 WayPoint 物体变成 PointNode，自动连出边
    （点数 / 边数见《地图对照表》§2）
   ↓
人机在 SP_BL 出生
   ↓
Bot.Awake 建 actionList
   ↓
重生延迟到 → 某个 Action 抢到目的地
   （运输船没有蹲点，通常是 Saunter 闲逛 / 追敌；
     小型工厂有蹲点，才会轮到 GoCrouchPos）
   ↓
Seeker.StartPath(脚下, 目的地) → A* 在图上搜一条路
   ↓
沿 vectorPath 跑，路上遇到跳链就起跳
   ↓
到点 1.5m 内算到达 → 该干什么干什么
   （蹲点则 TryCrouch 蹲下，朝 zoomPos 架枪）
```

整条链上，**蹲点只贡献了一个坐标，路点只贡献了"能不能走过去"**，两边互不知道对方存在。

> 本例用到的点数 / 边数 / 蹲点数量都在 [地图对照表.md](地图对照表.md)（§2 点图明细、§3 面图明细、组件统计表），本文不重复维护。

## 5. 五个最容易混的点

1. **蹲点/守点不是路点**：它们是"目的地"，不是"可走性"。人机站的地方附近必须有路点（或可走面），否则它会走到最近节点然后卡住/来回转。
2. **`WayPoint` 是 tag，`PointNode` 是类，路点物体是 GameObject**：三者一一对应，但一个是标记、一个是运行时对象、一个是场景里的空物体。
3. **点图节点数 ≠ 场景 WayPoint 数**：`NodeLink2` 的端点也是节点。刀锋寨场景 0 个 WayPoint、却有 18 个节点（9 个 `NodeLink2` × 2）；数字与端点明细见 [地图对照表.md](地图对照表.md) §5。
4. **`NodeLink` 不加点，`NodeLink2` 加点，`Bot_JumpLink` 不加点**（只给已有起点节点挂一条特殊跳跃记录）。
5. **「A\*」有两个意思**：算法本身，和这个插件。文档里说"A\* 图"，指的是插件的图数据（`PointGraph` / `NavMeshGraph`）。

## 6. 怎么自己验证（30 秒级）

- **节点数**：没有 `NodeLink2` 的图，数 tag = 20022 的物体数应等于 `PointGraph.nodeCount`（运输船的"786 点"就是这么对上的）；有 `NodeLink2` 的图还要加端点数（刀锋寨场景 0 个 WayPoint、运行时 18 个节点）。数字见 [地图对照表.md](地图对照表.md) §2；对不上就是有物体没激活 / 被过滤。
- **目的地**：hook `Seeker.StartPath`，把 `start`/`end` 打出来——`end` 会是你认识的蹲点/守点/敌人坐标。
- **可走性**：在编辑器里把一个点 `walkable = 0`，看人机是否立刻绕路；不绕说明它走的是可走面，不是点图。
