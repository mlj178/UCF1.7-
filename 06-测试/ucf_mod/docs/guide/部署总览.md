# UCF 插件 · 部署总览

> 一句话：别人的 UCF 是干净的原版，我们一键把 mod 装进去，他就能直接用。

---

## 一、这个东西是干什么的

管两件事：

### 1. 让新人一键装上我们的 mod

别人装好的 UnityCrossFire 是**原版**：没有 `winhttp.dll`、没有 `ucf_mod` 文件夹，什么都没有。
以前想用我们的 mod，得手动把几个文件拷进游戏目录——位置要拷对、版本还得对，大部分人搞不定。

现在：在控制台里选中他的 `UnityCrossFire.exe`，点一下，文件自动装好。

### 2. 让本机的多份 UCF 能切换启动

我们自己电脑上通常有好几份 UCF（不同测试环境，放在不同位置）。
控制台把这些位置记下来，启动前选一份，「开始游戏」就从那一份启动——按钮上还会写着是哪一份。

### 装好之后

- 从控制台点「开始游戏」→ 带 mod 玩；
- 直接双击游戏图标 → 原版，mod 不介入。

## 二、需求

1. **新人开箱即用**：他手里只有原版游戏，不知道文件该放哪，点一下就装好；
2. **多份能切换**：一台电脑上可能有好几份 UCF（不同测试环境、不同位置），启动前要能选从哪一份启动；
3. **记得住**：选过的要记住，下次打开还在，也能切回上一份；
4. **看得见**：点「开始游戏」时能看出这次是从哪个 exe 启动的；
5. **装得对、退得出**：版本不对就别装；装坏了要能卸掉、还原。

## 三、怎么用

全部在控制台窗口里点，不用敲命令。

### 第 1 步：打开控制台

双击 `tools\启动控制台.bat`。第一次打开会直接弹「首次设置」窗口，按提示选游戏、点部署就行。

### 第 2 步：切到「部署」页

窗口上方是一排页签：地图 / 可视化 / 导出 / 快捷键 / 人机路点 / 录制 / 数据 / **部署** / 车测 / 开发者选项。

### 第 3 步：选游戏

点蓝色的「**选择 UnityCrossFire.exe**」。
在弹出的窗口里找到游戏目录，选中里面的 `UnityCrossFire.exe` —— **选文件，不是选文件夹**。

选完输入框下面会多出一行完整路径：`启动用这个 exe：D:\...\UnityCrossFire.exe`，确认没选错。

### 第 4 步：看状态

「部署状态」里有五行，每行前面写着：

| 字样 | 意思 |
|---|---|
| 一致 | 这个文件已经装好了 |
| 缺失 | 还没有，需要部署 |
| 不一致 | 有文件但版本不对，需要修复 |

### 第 5 步：点「一键部署」

绿色按钮。装完五行都会变成「一致」，下面的输出框会列出每个文件写到了哪里。

以后再点一次就是「修复」：已经一致的会跳过，不会重复拷。

部署前它会自己先检查一遍（游戏版本对不对、游戏是不是开着、目录能不能写）。
有问题会停下来说原因，**不会写坏东西**。

### 第 6 步：开始游戏

回到底部点「**开始游戏**」。按钮上会写：

> 开始游戏 · 编辑中 xxx ［test-1］

方括号里就是这次启动的那份游戏；按钮上方还有一行完整路径。

> 一定要从这里点「开始游戏」才会加载 mod。直接双击游戏图标是原版。

### 其他按钮

| 按钮 | 作用 |
|---|---|
| 修复（强制重拷） | 文件对不上时强制重写一遍 |
| 校验 | 只检查，不装 |
| 卸载 | 删掉装进去的文件，覆盖前的原件还原回去 |
| 首次设置向导 | 重新走一遍「选游戏 → 检查 → 部署」 |
| 打开游戏目录 | 打开这份游戏所在的文件夹 |
| 重新检查 | 重新读一遍状态 |
| 重启控制台 | 换了游戏位置之后，让整个控制台跟着换过去 |
| 切换并重启 | 切到「历史位置」下拉框里选中的那一份 |
| 忘记 | 删掉这条历史记录（当前在用的那条删不掉） |

## 四、会往游戏目录里放什么

| 文件 | 说明 |
|---|---|
| `winhttp.dll` | 代理加载器，没有它插件不会被加载 |
| `winhttp_orig.dll` | 系统自带 winhttp 的副本，从本机取，不随包发 |
| `ucf_mod\ucf_mod.dll` | 插件本体 |
| `ucf_mod\README.txt` | 给用户看的说明 |
| `ucf_mod\uninstall.ps1` | 卸载脚本 |
| `ucf_mod\deploy_manifest.json` | 部署记录，工具自动生成 |

不碰：存档、场景文件、已经在用的配置。

## 五、多份游戏、多个位置

一台电脑上可以有好几份 UCF，比如 `D:\...\test-1\UnityCrossFire1.7.1` 和 `D:\...\UnityCrossFire1.7.1`，
它们是不同测试环境。控制台一次只认一份：

- 「部署」页的「**历史位置**」记住最近用过的 6 份，当前这份后面带 `· 在用`；
- 下拉框里显示短标签（`test-1（D:）`），下面一行是它的完整路径 ——
  路径太长会被省略，一省略 `test-1` 这种关键名字就看不清了；
- 想换一份：重新点「选择 UnityCrossFire.exe」，或者在下拉框里选好再点「切换并重启」。

**为什么换位置要重启**：控制台是启动时就把游戏位置记下来的，运行中改了不会整个窗口都跟着变。
所以换位置 = 重启一次（一两秒）。选的时候它会自动问你要不要立刻切换。

## 六、遇到的问题

### 1. 有些文件只在游戏目录里，工程里没有

不少文件当初是直接扔进游戏目录的，工程里没有源码、也没有备份：

- `winhttp.dll`（插件加载器）
- `ucf_mod\uninstall.ps1`、`ucf_mod\README.txt`（卸载脚本和用户说明）
- `ucf_mod\manifest.json`（旧的部署记录）
- `ucf_mod\backup\level9.orig`（唯一一份没被打过补丁的场景）

工程的 `.gitignore` 又把所有 dll 都排除了，所以它们从来没进过 git。

**后果**：游戏目录一旦被清理、覆盖、重装，这些文件就永久没了 —— 没有源码没法重编，没有备份没法找回。

### 2. 加载器的源码也丢过一次

`winhttp.dll` 连源码都没留下，只剩游戏目录里那一个文件。
后来是从这个文件本身反推回来的（它没被裁剪过，符号和导出表都还在），源码现在放在 `src\proxy\`。

### 3. 顺带确认：有两个文件不是我们的

游戏目录里的 `baselib.dll` 和 `InjectDll.exe`，是别的项目留下的（后者的字符串里写着它自己的名字和一个已经不存在的工作目录），
跟这个 mod 无关，部署时不会带它们。
