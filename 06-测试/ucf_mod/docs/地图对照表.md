## 怎么改 / 怎么加

1. 直接改上面表格的「中文名」或「场景名」（保持 5 列）。要调顺序就把整行搬过去再按 01…11 重新编号，
   `关卡` 一列（levelN）是给脚本认图用的，别写错；
2. 跑一次整理，让文件名和索引跟上：

   ```
   cd ucf_mod\tools
   python organize_maps.py --archive
   ```

3. 打开编辑器（`启动导航编辑器.bat`）就能看到新名字。

说明：

- `maps\` 里的文件名 = `序号_中文名.json`，改了名字脚本会写新文件，旧文件留在 `backup\` 里不会丢。
- `maps\INDEX.md` 和 `maps\_index.json` 是**自动生成**的（含节点数、是否有数据），别手改。
- 每个关卡在 `geo\web\` 里要有一份地形网格，编辑器 3D 才能显示；缺了就 `python geo2web.py <关卡>`。

### 几条必须记住的解释

1. **PointGraph 的节点 = 场景里 tag = 20022（WayPoint）的物体**，不是“扫描到哪儿算哪儿”。所以：
   - 胜利广场 / 死亡擂台场景里一个 WayPoint 都没有 → 这两张图**永远采不到路点**，`待采集` 对它们是错的；
   - 暴风配了 PointGraph（searchTag = WayPoint），但场景里 0 个 WayPoint → 原生 0 点；
   - 生化酒店场景里 3070 个，其中 7 个未激活（`FindGameObjectsWithTag` 扫不到）→ 运行时 3063。
2. **小型工厂 / 刀锋寨的 PointGraph 不是路点网**：图里它的名字就叫 `PointGraph (used for node links)`，
   给 `WayLink*` / `JumpLink*` 这类离线连接（跳/翻越）当端点用。运行时它里面 12 / 18 个节点就是这些 link 的端点
   （2026-11-16 21:23、12:52 的 `[nav] diag` 日志实测；插件没往这两张图加过点）。
   小型工厂这 12 个点能逐位对上：6 个 `WayLink1..4` 的世界坐标
   `(2.74,-4.5,-20.08) (20.35,-4.5,-17.36) (3.67,-4.5,19.25) (20.52,-4.5,21.32) (7.24,-4.5,3.21) (17.31,-4.5,-1.79)`
   与导出里的 6 个节点完全一致，剩下 6 个是每个 link 的 `end`（带 pen=1000/2000）。它们的路面是 navmesh。
3. **「顶点 843 → 840」**：左边是网格顶点数，右边是 A* 运行时合并同位置顶点后的数量（三角形数不变）。
   三角形 = 网格索引数 ÷ 3。
4. 插件 HUD / 日志里的 `tris=3417` 是**索引数**（= 三角形 × 3），别当三角形数用。
5. 合计：原生路点 **4056** 个（786+2+17+8+3063+180）；原生 navmesh **8 个网格 / 7496 个三角形**。
