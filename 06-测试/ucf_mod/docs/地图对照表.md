1. 直接改上面表格的「中文名」或「场景名」（保持 5 列）。要调顺序就把整行搬过去再按 01…11 重新编号，
   `关卡` 一列（levelN）是给脚本认图用的，别写错；

### 0. 先把两个词讲清楚：路点图 和 可走面

游戏里人机（A* Pathfinding 4.2.17）用的是**两套图**，统计和用途都不一样：

| 名词 | 游戏里是什么 | 数据集里存成什么 | 干什么用 |
| --- | --- | --- | --- |
| **路点图 PointGraph** | 场景里 `tag = 20022 (WayPoint)` 的物体；进图 `Scan()` 时把这些物体连成图 | `maps\NN_中文名.json`（点 + 边 + 特征） | 寻路的「站点」：A* 在点上算路径；编辑器加点/删点/连边 |
| **可走面 NavMeshGraph** | 美术烘焙的三角网（`resources.assets` 里的 `*_NavMesh` 网格），A* 里是 `NavMeshGraph` | `vis\navmesh_nm<顶点数>-<指纹>.bin` | 人机**真正踩的地面**；编辑器 3D 里画成白色线框（Ctrl+Shift+6） |

- 「可走面」不是点，是**三角形拼出来的地面**。判断一张图有没有可走面，看的是 NavMeshGraph，跟路点无关。
- 路点图本身不带地面：它只有点和连边，人机沿边走的时候，脚下位置要靠可走面兜住。
- 所以「只有路点图」不是没地面（地面就是点本身）；「只有 navmesh」也不是没采到路点，
  而是**原生场景里一个 WayPoint 物体都没有**（胜利广场 / 死亡擂台）。
- bin 文件名里的 `nm840` = A* 运行时合并同位置顶点后的顶点数；`40749e0342e84cbd` 是顶点/三角形内容算出来的指纹，
  同一张图重复采集指纹不变。

bin 是插件自己写的 `UCFNM3` 格式（`src\editor.c` 的 `nm_dump()`）：

```
"UCFNM3" 0x00 | int32 nv | int32 nt | int32 ntile | uint8 flags[4]
               | float matrix[16] | float translation[3]
               | int32 verts[nv*3]   （世界坐标 Int3，1/1000 m）
               | int32 gverts[nv*3]  （图空间，同上）
               | int32 tris[nt*3]
```

为什么顶点表写两份：A* 的 `verts` 已经是世界坐标，`vertsInGraphSpace` 是图空间；
万一某张图的 `verts` 不是世界坐标，离线还能用 `matrix/translation` 自己算回来。

编辑器里看这张面：进图按 `Ctrl+Shift+6`（F 层）把 navmesh 画成白色线框；HUD 的
`walk-srf yes 1236 tris / 944 verts` 就是这一行读数，`none` 表示这张图原生没有 NavMeshGraph。

### 5. 几条必须记住的解释

1. **PointGraph 的节点 = 场景里 `tag = 20022（WayPoint）` 且激活的物体**，不是“扫描到哪儿算哪儿”。所以：
   - 胜利广场 / 死亡擂台场景里一个 WayPoint 都没有 → 这两张图**永远采不到路点**，`待采集` 对它们是错的；
   - 飓风危城配了 PointGraph（searchTag = WayPoint），但场景里 0 个 WayPoint → 原生 0 点（数据集里留一份
     0 点空档，表示“查过了，真没有”）；
   - 生化酒店场景里 3070 个，其中 7 个未激活（`FindGameObjectsWithTag` 扫不到）→ 运行时 3063。
2. **小型工厂 / 刀锋寨的 PointGraph 不是路点网**：图里它的名字就叫 `PointGraph (used for node links)`，
   给 `WayLink*` / `JumpLink*` 这类离线连接（跳/翻越）当端点用。运行时它里面 12 / 18 个节点就是这些
   link 的端点（2026-11-16 21:23、12:52 的 `[nav] diag` 日志实测；插件没往这两张图加过点）。
   小型工厂这 12 个点能逐位对上：6 个 `WayLink1..4` 的世界坐标
   `(2.74,-4.5,-20.08) (20.35,-4.5,-17.36) (3.67,-4.5,19.25) (20.52,-4.5,21.32) (7.24,-4.5,3.21) (17.31,-4.5,-1.79)`
   与导出里的 6 个节点完全一致，剩下 6 个是每个 link 的 `end`（带 pen=1000/2000）。它们的路面是 navmesh。
3. **沙漠要塞静态 8 个 WayPoint、运行时导出 12 点**：多出来的 4 个是 `WayLink/JumpLink` 端点
   （和刀锋寨一个道理），不是插件加的。同理刀锋寨静态 0 个、运行时 18 点。
4. **「顶点 843 → 840」**：左边是网格顶点数，右边是 A* 运行时合并同位置顶点后的数量（三角形数不变）。
   三角形 = 网格索引数 ÷ 3；所以“索引数 = 三角形 × 3”这一列和 HUD 里的 `tris` 是同一口径。
5. 插件 HUD / 日志里的 `tris=3417` 是**索引数**（= 1139 三角形 × 3），别当三角形数用。
6. **三版一致，但游戏会重写 bin**：每进一次图，插件都会重写该图的 `navmesh_nm*.bin`。
   内容指纹（文件名里的 16 位）不变，但三角形索引的写入顺序偶尔会轮转，字节可能和备份不同
   —— 这**不是数据变了**，是同一张面的等价写法。以 ① 备份为准；重新同步用
   `python tools\navdata.py publish`（②→③）和 `python tools\navdata.py freeze --force`（③→①）。
7. 合计：
   - 原生路点 **4056** 个（786 + 2 + 17 + 8 + 3063 + 180，不含 node link 端点的 12 + 18）；
   - 数据集 9 个地图文件共 **4090** 个节点 / **7119** 条边 / **445** 条特征（含暴风 0 点空档）；
   - 原生 navmesh **8 个网格 / 7,496 个三角形 / 22,488 个索引 / 5,253 个 A* 顶点**（bin 共 396,720 字节）；
   - 三版文件：① 备份 = 9 图 + 8 面 + 校验清单（只读）；② 开发 = 同样 17 份 + `INDEX.md`/`_index.json`；
     ③ 部署 = 同样的规范化文件 + 原始导出（`<图>__<时间>.json/.navmesh.bin`）、`_seen_*` 标记、日志
     —— 后三类是采集痕迹，不参与一致性校验。

### 6. 数据从哪来（复现）

```
python tools\scan_native_nav.py                  # 静态：读游戏场景 + assets，列出两张图的原生参数
```

`vis\<场景>__<时间>.json`，navmesh → `vis\navmesh_nm*.bin`。跑

`publish` 到 ③、`freeze --force` 回 ①（顺序必须是 organize → publish → freeze）。

### 怎么验证这张表（可复现）

`assets.xml` 里每一条 `<Asset>` 都有 `<Name>`（脚本类名）和 `<Source>`（哪个场景文件）。
数「`<Source>` 含 `levelN` 且 `<Name>` 等于某脚本」的条目，就是上表一格。

三处能和上文对上，说明数的是同一套东西：

| 交叉核对 | 算法 | 实测 |
| --- | --- | --- |
| 小型工厂点图 12 点 | `NodeLink2` × 2 | 6 × 2 = **12** ✔ |
| 刀锋寨点图 18 点（场景 0 个 WayPoint） | `NodeLink2` × 2 | 9 × 2 = **18** ✔ |
| 沙漠要塞点图 12 点（场景 8 个 WayPoint） | 8 + `NodeLink2` × 2 | 8 + 2×2 = **12** ✔ |

### 由这张表直接得出的三个结论

1. **不是每张图都靠点图走路**：胜利广场、死亡擂台只有可走面；运输船、生化酒店只有点图。改错层 = 没反应。
2. **生化图才有人机组件**：`NanoGuardPos / NanoGuardArea / PointNodeTagModifier` 只出现在沙漠要塞(7)和新寂静村(10)。
   团队图（运输船/小型工厂/椰岛之巅）最多只有蹲点 + 跳跃/连线。
3. **旧守卫系统（`Bot_GuardPos` / `Bot_GuardArea`）只活在生化酒店(8)**，而它在当前版本里是死数据——
   想给生化酒店加"守区"，必须自己造 `Bot_NanoGuardArea`（插件的 `act_guard()` 就是干这个的）。

## 模式 ↔ 地图（工作台下拉的分组口径，2026-11-18 复核）

`GameMode` 枚举（`dump.cs`，IDA 里 `GameModeExpand::ToChinese` 按它取中文）：
`TeamDeath=0 / DeathMatch=1 / Special=2 / Nano3=3 / Nano4=4 / Nano6=5 / Nano4_Terminator=6`。
工作台下拉按「一张图只进一个主模式」分组：

| 模式 | 地图 | 依据 |
| --- | --- | --- |
| 团队模式 | 运输船 · 小型工厂 · 椰岛之巅 | `sharedassets0.assets` 选图表 TeamDeath 组 |
| 个人竞技 | 胜利广场 | 选图表 DeathMatch 组 |
| 特殊战 | 竞技场 · 刀锋寨 · 死亡擂台 | 选图表 Special 组 |
| 生化模式 | 生化酒店 | 2012 年经典生化图；`Nano3` 在本包选图表里没有对应场景 |
| 生化剑客模式 | 沙漠要塞 | 选图表 Nano4 组；官方页面写「沙漠要塞（生化剑客）」 |
| 多人生化模式 | 新寂静村 · 飓风危城（隐藏注入） | 新寂静村 = `Nano4_Terminator` 组；飓风危城 = `Nano30_Storm`，`hidden_map` 注入 |

- 选图表里 `Nano4` / `Nano6` 两组都同时列了「生化酒店 · 沙漠要塞」——同一张图能进多个模式池，
  下拉为了避免重复只取一个主模式，所以按上表拆开（`Nano3` 没有场景，`Nano4_Terminator` 并入多人生化）。
- 隐藏图 `level9`（`Nano30_Storm`）的正式中文名是 **飓风危城**，归多人生化模式；此前文档和
  `maps\10_暴风.json` 里的「暴风」是旧称呼，数据文件名暂不改，显示名以本表为准。
