# ucf_mod · UCF 1.7 导航/人机插件

UnityCrossFire 1.7.1（Unity + IL2CPP）的文件化插件。
形态：游戏目录的 `winhttp.dll` 代理加载器 → 加载 `ucf_mod\ucf_mod.dll`（原生 C，mingw 编译，运行时挂 il2cpp）。

> **只想玩游戏 / 只想改路点？** 不用看本文件，看游戏目录里的 `ucf_mod\README.txt`（三句话讲完）。
> 本文件是开发说明，给改代码的人看。

## 三个目录、四版数据，别搞混

数据分四版（2026-11-18 起）：

| 版 | 在哪 | 谁写 |
| --- | --- | --- |
| ① 备份版（只读） | 工程端 `navdata\native` | 只有 `navdata.py freeze` |

数据流：**游戏导出 → ④ →（导入）→ ② →（部署）→ ③**；① 随时冻结。详细规则见

## 构建与部署

```powershell
# 编译（产物进 build/，带日期与 git 短哈希）
.\tools\build.ps1

# 部署到游戏目录（会先关游戏，再备份旧 dll 为 .deployed_<时间>）
.\tools\build.ps1 -Deploy
```

部署端 `uninstall.ps1` 只移除部署物（dll/加载器/还原场景），**不会删源码**。

## 只读查看

打开 UCF 控制台，点「路点工作台（查看）」→ 浏览器打开路点工作台（只读）：
俯视 + 3D、可走面、特征点、路线/区域、文件列表、关卡切换；网页端不提供编辑。
部署 / 建测试包仍用控制台「数据」「测试数据」页，或 `python tools/navdata.py publish|pack`。
`geo/web` 缺失时会自动用 `geo2web.py` 重建。

## 控制台「人机路点」+ 游戏内菜单（2026-11-18）

- 控制台新页签「人机路点」：选图 / ④ 测试包 / ③ 正式版、六项开关、节点/边计数、清空本图；撤销/重做/保存/重读在游戏内 F2 菜单。
- 游戏内按 **F2** 打开路点菜单；**长按 E 0.45 s** 备用（UCF 没有 E 交互，用户已确认）。按 F2 / 小键盘前先点一下游戏画面，让游戏窗口拿到焦点。
  菜单键位（2026-11-18 二次调整，避开游戏内的 Enter/Esc/W/S）：`1-9` 直选；小键盘 `8/2` 上下、`5` 确认、`0` 返回（滚轮也可上下）；左键确认、右键返回。
  菜单打开时只拦菜单键和会误触的武器/功能键（数字、Q/R/G/F/Tab 等）；小键盘专供菜单；W/A/S/D、空格、Shift、Ctrl 仍交给游戏，选完 A 可以走到 B 再按小键盘 5 连边；回车/Esc 只作用于菜单，不再触发游戏。鼠标左右键和滚轮也被菜单消费。
- **加点前提**：运行期不能增长 PointGraph 节点数组，只能复用「不可走」槽位。原生点全可走的图（沙漠要塞 12 点、运输船 786 点）直接加点会打 `no free slot`；先建 **空白底图测试包**（运输船 / 新寂静村，把原生点全禁用），或先删一个点。**飓风危城原生 0 点，建不了空白包**（没有可借槽位）。
- 菜单动作：添加普通/蹲守/守点/聚集区/标签区；跳跃点用 `Bot_JumpLink`（Link[] 一个元素，`OnLatePostScan` 挂 `startNode`，**本轮是 session-only，重启不保留**）；建立双向/单向路径（文件里 `edge out` / `edge in`）；删除路径/点；落地；聚集区新建/加守点；撤销/重做/保存；显示图层。
- 点/边仍写 ④ 包或 ③ `nav\<指纹>.txt`；蹲守/守区/守点/标签写 `ucf_mod\markers\markers.txt`（**目前不分图，按指纹分文件还没做**）。
- 新增配置键：`wp_menu`、`wp_autoground`（bool）、`wp_brush`（字符串 normal/jump/crouch/guard/area/tag；2026-11-19 起只在游戏内 F2「设置笔刷 / 标记」切换，控制台已移除点类型卡片）。
- **为什么“铺到对面”仍可能不动（2026-11-18 22:53，blank_a 当前 138 点）**：
  - `blank` 不是“在原生图旁边加一段”：它把运输船 786 个原生点全部禁用，整张图只剩清单里的点。人机的起点（出生点）和终点（敌人/目标）都必须落在这张连通图里。
  - 当前包：**138 点**（130 条 `edge add` + 17 条 `edge del`），主连通块 **105 点**；仍有 **31 个孤立点 + 1 个 2 点小块**，共 33 个连通块。主路线确实从我家门口连到敌方区域了，问题不在“没连到对面”。
  - 第一大成因是 **切换边留下的 del→add 历史**：例如先 `edge del A-B` 再 `edge add A-B`。旧 `nav_needs_apply` 逐条判断，看到前面的 del 就认为“没删掉”，每 ~4 秒重套整图；日志 22:28–22:37 每 4 秒刷 `naved: applied in place`。人机刚拿到路径就被重置，所以完全不动。新 DLL 改成“按文件顺序折叠，最后一条为准”，22:52 实测只套一次。
  - 第二大成因是 **孤立点被 Bot 当成最近点**：(-25.75,6.19)、(-7.19,10.31)、(13.68,10.54)、(16.43,9.63) 就在主路线中间却没边；敌方一侧 (43.56,1.66)、(47.74,-5.59)、(47.25,-2.30)、(42.38,-7.92)、(46.80,-7.18)、(47.45,0.59)、(46.32,-8.20)、(41.70,-12.09)、(48.67,-13.89)、(46.73,-15.51) 也孤立；`幽灵 (49,2)` 最近点就是孤立点 (47.45,0.59) 2.63 m，A* 直接失败。
  - 出生点距离（3D）：我方 (-60,1)=2.29、(-64,5)=5.24、(-64,1)=2.37；敌方 (49,6)=4.55、(46,4)=2.30、(49,-8)=2.39、(49,2)=2.63。若游戏最近点上限是 2.1 m，这些出生点直接挂不上图。
  - 11 个蹲守标记全在 y≈2.2、z=-40…37，离运输船图 **18.8–49 m**，明显不是这张图（`markers.txt` 全局不分图）。Bot 选蹲守点会失败；测试前先把 `ucf_mod\markers\markers.txt` 备份并清空，或只保留运输船点。
  - 39 条边 >2.1 m（最长 7.94 m），可能穿墙；A* 有路不等于人机能走过去。8 条自环边仍在文件里，新 DLL 会跳过，但数据最好清掉。
  - **新 DLL 只修“每 4 秒重套 / 切图崩”**；孤立点、出生点、蹲守标记、长边仍要改数据。只测局部仍建议切 ③ 正式版保留原生图，先删 3–5 个远处点腾槽位再加线。
- 菜单实测（2026-11-18 21:46）：F2 开 → 小键盘 2 两次（`sel=2`）→ 小键盘 5 进「建立路径」→ 小键盘 8 一次从 1 回绕到 3（`subsel=2`）→ 小键盘 5（`path dir=2`）；小键盘 0 先取消放置、再关菜单；Esc 关闭菜单；主键盘 `3` 连按两次也能直选路径方向；W 仍交给游戏（选完 A 可走到 B），滚轮 / 右键 / 回车 / Esc 都被菜单消费。
- 崩溃/重套修复实测（2026-11-18 22:53）：138 点 blank_a 只套用一次（不再每 4 秒刷）；autotest `level1 → level2` 两张图连续切换 **PASS**，旧的 `PointNode.ClearConnections` 0xc0000005 不再出现。除写屏障外，现在给每个 nodeIndex 的 connections 数组保留一个 gchandle，切图期间数组不会被 GC 回收。

- **2026-11-18 新增 blank_b 清理版**（未做车测，静态校验通过）：从 blank_a 保留 105 点主连通块，删掉 31 个孤立点 + 1 个 2 点小块（共 33 点），补 7 个出生点节点（我方 -60/1、-64/5、-64/1；敌方 49/6、46/4、49/-8、49/2）。结果 **112 点 / 111 条边 / 1 个连通块 / 0 自环 / 0 del 历史**；16 个出生点最近点均 ≤2.0 m。文件：navdata\test\packs\blank_b\n786-57a46e3465c847cb.txt。主线本身仍有 42 条 >2.1 m 的边（最长 7.94 m），这次没动主路；如果某段卡墙再拆。
