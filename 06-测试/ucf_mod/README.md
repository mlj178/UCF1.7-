# ucf_mod · UCF 1.7 导航/人机插件

UnityCrossFire 1.7.1（Unity + IL2CPP）的文件化插件。
形态：游戏目录的 `winhttp.dll` 代理加载器 → 加载 `ucf_mod\ucf_mod.dll`（原生 C，mingw 编译，运行时挂 il2cpp）。

> **只想玩游戏 / 只想改路点？** 不用看本文件，看游戏目录里的 `ucf_mod\README.txt`（三句话讲完）。
> 本文件是开发说明，给改代码的人看。

## 构建与部署

```powershell
# 编译（产物进 build/，带日期与 git 短哈希）
.\tools\build.ps1

# 部署到游戏目录（会先关游戏，再备份旧 dll 为 .deployed_<时间>）
.\tools\build.ps1 -Deploy
```

部署端 `uninstall.ps1` 只移除部署物（dll/加载器/还原场景），**不会删源码**。

- **跳跃点为什么需要连线（2026-11-20，反汇编确认）**：`Bot.OnPathComplete` 遍历 A* 路径的节点序列，只有「路径里 起点节点 的下一个节点 正好是该跳链的 `endNode`」才插跳跃段（`Bot_JumpLink.GetLink` 走 `linkDic`，`GetLinkEndByGraphNode` 比对 `endNode`）。所以一条跳链要能触发，必须同时满足：① 两端都解析到图上节点（起点进 `linkDic`，落点解析成 `endNode`）；② 这两个节点之间有 **A->B 的边**，否则 A* 永远不会把它们连着排；③ 长度 >= 1.5 m；④ 起点自己要连进主图（没有边 = Bot 走不到），落点也要能继续走（只连着起点 = 跳过去是死胡同，除非落点就是目标）。菜单现在①②③全包（落点没路点就补一个、缺边就补 `edge out`）；④ 只打日志提醒，不替你猜路线（`wpmenu: jump landing node N 目前只连着起点…`），旧数据用 `python tools/check_jumps.py` 体检：它会逐条打「同点 / 缺路点 / 无连线 / 太短」。可视化里跳链画成「两个端点方块 + 一条线」，就是因为它本来是一对点而不是单点。
