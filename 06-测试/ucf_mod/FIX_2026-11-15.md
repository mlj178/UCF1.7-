## 1. 根因

### 1.1 幽灵卡在复活点：隐藏图没有任何 AI 行为数据

用 UnityPy 直接扫 `UnityCrossFire_Data/level9`：

- 383 个 GameObject，**只有 5 个 MonoBehaviour**；
- `Bot_NanoGuardArea` / `Bot_NanoGuardPos` / `Bot_JumpLink` / `Bot_CrouchPos` / `AirPoint` 数量全部为 **0**；
- 作为对比，正常生化图 `level10` 有 GuardArea1_1…4_2、JumpLink、AirPoint 等 292 个标记对象。

运行时证据（修复前 probe）：

```
bot 0x4233b720 ... guardArea=0x0 guardPos=0x0
bot 0x423525f0 ... nano=0x0
[med] 之前会话 status: SpareAreaList=0
```

`BotAction_NanoGuard.UpdateArea()` 的逻辑是：

1. 自己没有 guardArea → `Bot_NanoGuardArea.GetRandomArea()`；
2. `GetRandomArea()` 从静态 `SpareAreaList` 随机取；**列表为空就返回 null**；
3. `SetAreaTarget(null)` → 没有目标 → 每帧重复，永远不移动。

所以“幽灵出不来”不是寻路算法问题，是**地图里根本没有幽灵守卫区和守点**。

### 1.2 Bot.Update 每帧 NRE

反汇编 `Bot.Update`（RVA 0xB33370）确认：进入 `!isStopped` 分支后：

- 0x10B33557 / 0x10B335A4 把 `AstarPath.active.GetNearest(...)` 的结果写入 `gNode_Nearset(+0x88)` / `gNode_Next(+0x8C)`；
- 0x10B338DD `mov (%ebx),%eax` 直接解引用 `gNode_Nearset`，为 0 就跳到 0x10B33A6B 抛 NRE。

隐藏图原本 0 个 A* 节点，且出生点位置没有节点 → 每帧 NRE，后面 PathSetting/Move 全部不执行。修复前两处 Bot 的 `gNode=0x0`，每帧 NRE。

### 1.3 退出卡死

复现：进图后 `CloseMainWindow()`，10.5 s 后进程 `Responding=False`，不退出。

抓进程转储（comsvcs MiniDump）后扫线程栈，后台线程栈里能看到：

```
TID 20900 ... ucf_mod.dll+0x14c0
TID 9532  ... ucf_mod.dll+0x2000
```

即 `navfix.c` 的 `nav_worker`（for(;;) 每 500 ms 调 `il2cpp_field_static_get_value`）和 `plugin.c` 的 `worker`（每 1 s 调 il2cpp）在 Unity/IL2CPP 收尾时仍在调运行时；同时 `NavProc` 子类化窗口后从不恢复。修复采用交接文档建议的架构：

- `g_appQuit` 闸门，WM_CLOSE / WM_QUERYENDSESSION / WM_DESTROY / WM_NCDESTROY / DllMain detach 置位；
- 两个后台线程**只 PostMessage，不再调用任何 il2cpp API**；
- 所有 il2cpp 调用（场景检测、建图、注入、编辑器）全部搬回主线程 WndProc（WM_APP+0x50 tick / +0x54 inject）；
- WM_DESTROY 里先恢复旧 WndProc，再 CallWindowProc。

## 2. 改了什么

### navfix.c（11784 → 24485 字节）

1. `g_appQuit` + `navfix_hwnd()`；`nav_worker` 循环只 `PostMessage(WM_APP+0x50)`，退出即 break 并写 `[nav] quit: nav worker stop`。
2. `NavProc`：
   - WM_CLOSE / WM_QUERYENDSESSION / WM_ENDSESSION / WM_DESTROY / WM_NCDESTROY 置 quit；
   - WM_DESTROY 恢复旧 WndProc 并写 `[nav] quit: wndproc restored`；
   - WM_APP+0x50 → `nav_tick()`（主线程）；WM_APP+0x54 → `plugin_tick()`（主线程）。
3. `nav_tick()`：检测 AstarPath 变化 → 清死守卫区 → editor_on_scene → **立即建图**；点图节点为 0 时重试。
4. 建图：
   - **多层射线采样**：每列从 y=300 打第一次命中后，再从其下方 1.5 m 继续向下打，最多 5 层，解决“只采到屋顶、室内没有节点”；
   - 过滤 y<-30 或 y>15 的“天空盒/天花板碰撞体”；
   - **把 MapManager 的 SP_BL(30) / SP_GR(30) / SP_SupplyBox(25) 出生点全部加成节点**（另加地面投影点），共 170 个，保证出生点附近 GetNearest 一定非空；
   - `PointGraph.maxDistance = 4.6`，开启 `raycast=1` + `mask=-1`，让 ConnectNodes 做连线遮挡（减少穿墙连边）；
   - 建图期间把 `Bot.stopAllBot` 临时置 1，建完恢复，避免 Bot 在空图上刷 NRE。
5. **运行时造幽灵守卫区**：
   - 在可走地面点中每 11 个节点取一个，最多 64 个，y 限制[-3,9]；
   - 用 inactive GO + AddComponent 延迟 Awake；先造 `List<Bot_NanoGuardPos>`、`entrancePos/escapePos/neighborAreas/escapeAreas` 空数组、每个 pos 的 `zoomPos=Vector3[1]`；
   - 用 `il2cpp_runtime_invoke` 调 `List<Bot_NanoGuardPos>.Add` 把 pos 放进 posList，再激活 area 触发 Awake（Awake 会补 area 引用、合并 zoomPos、注册 SpareAreaList）；
   - 激活后给每个 area 写 3 个 neighborAreas + 2 个 escapeAreas（相邻/远邻），让幽灵到达后还会换区。
   - 场景切换时清理 SpareAreaList 里已销毁的条目（避免上个隐藏图的死 area 污染普通图）。

### plugin.c（6481 → 7005 字节）

- 注入逻辑抽成 `plugin_tick()`，由主线程 WM_APP+0x54 调用；
- worker 线程只负责解析导出/找 UI_GameRoom 单例字段，之后每秒 PostMessage，不再直接调 il2cpp；
- DllMain PROCESS_DETACH 置 `g_appQuit=1`；
- 退出时写 `quit: inject worker stop`。

### editor.c（33752 → 33830 字节）

- 新增 `editor_on_quit()`，WM_DESTROY 时写 `[edit] quit: editor stop (markers=N)`。

## 4. 缺什么（回答“幽灵聚集点、路点”）

| 数据 | 隐藏图 level9 原本 | 现在 |
| --- | --- | --- |
| A* PointGraph 节点 | 0 | 694（524 多层采样 + 170 出生点） |
| Bot_CrouchPos 蹲守点 | 0 | 147（原有功能） |
| **Bot_NanoGuardArea 幽灵守卫区** | **0** | **42（运行时造）** |
| **Bot_NanoGuardPos 幽灵守点** | **0** | **每个区 1~2 个（运行时造）** |
| 守卫区 neighbor/escapeAreas | 0 | 每区 3 + 2 个（运行时连） |
| Bot_JumpLink 跳跃链接 | 0 | **仍缺**（需要按 A* 节点对绑定，未做） |
| SP_BL / SP_GR / SP_SupplyBox | 30 / 30 / 25（有） | 有，并已加成导航节点 |
| **SP_RedBox / SP_BlueBox** | **null** | **仍缺**（升级补给箱 NRE 的来源） |
| pointDic | 有（非空） | 有 |

结论：**最缺的是幽灵方的“聚集点/守卫区”和“守点”**；路点由插件补；跳跃链接和红/蓝补给点仍缺。

## 5. 未解决

1. **仍有 7/29 个 Bot 60 s 内原地不动**。它们集中在 y≈1.3 的出生洞穴；可能是洞穴出口几何/门，或目标区不可达。没有 `Bot_JumpLink`，垂直/跳跃路线走不了。
2. **补给箱 NRE 未修**：`SP_RedBox/SP_BlueBox` 为 null，`Mode_Nano4_Terminator.StartGenerateSupplyBox` 仍会抛 `GetSupplyBoxPoint` NRE（本局 0 条，但条件触发时仍会出现）。
3. **27 条建图窗口 NRE**：冻结 `stopAllBot` 生效前约 1 帧的 Bot.Update；不增长，不影响游玩。
4. 60 s 内 65~110 m 的大位移里可能混有**死亡重生**，未逐帧区分“走路”与“重生”；但 19 个 >15 m 已明显区别于修复前的全 0。
5. 未实现 `Bot_JumpLink`（需要 A* 节点对 + GraphModifier，工作量大）。
