## 3. BUG A：生化幽灵卡在复活点出不来

### 3.1 已经拿到的硬证据（不要重复挖）

1. Player.log 里 **1074 条** NullReferenceException，全是这两条栈，从进图刷到当前：

```
at Bot.Update () [0x00000]
at MapManager.GetSupplyBoxPoint (SpawnPoint& point, SupplyBox+Type type)
at Mode_Nano4_Terminator.<StartGenerateSupplyBox>g__GenerateUpgradeBox|31_1 (int count, SupplyBox+Type boxType)
at Mode_Nano4_Terminator+<<StartGenerateSupplyBox>g__UpgrandeBoxGenerator|31_0>d.MoveNext ()
```

2. probe_bot2.log：6 个 Bot 的 `path = 0x0`（**从来没生成过路径**），而 `nanoGuard / seeker / interpolator` 都在 → 就是没发 path 请求。
3. probe_nn.log：GetNearest 能返回节点（0x2263d570 等），说明图不是空的，"找不到节点"不是主因。

### 3.2 关键地址（dump.cs 已确认）

| 符号 | RVA | 说明 |
| --- | --- | --- |
| Bot.Update | **0xB33370** | 每帧；NRE 就出在这里（栈被 strip 成 [0x00000]，必须反汇编看第几个解引用） |
| Bot.Awake | 0xB2CEF0 | |
| Bot.PathSetting | 0xB31E90 | 发路径请求的地方 |
| Bot.UpdateNearestGraphNode | 0xB33260 | |
| Bot.Move | 0xB2FBE0 | |
| Bot.OnPathComplete | 0xB31950 | |
| MapManager.GetSpawnPoint(Team) | 0xAEB6E0 | 出生点 |
| MapManager.GetSupplyBoxPoint | 0xAEB8A0 | 刷 NRE 的那个 |
| MapManager.Awake | 0xAEB2B0 | |

**MapManager 字段偏移（32 位）**：pointDic +0xC、SP_BL +0x10、SP_GR +0x14、SP_Netural +0x18、SP_SupplyBox +0x1C、SP_RedBox +0x20、SP_BlueBox +0x24、IDList_SupplyBox +0x28、IDList_RedBox +0x2C、IDList_BlueBox +0x30、mapGunIndex +0x34、knifeHitStun +0x38、minimap +0x3C、radarOriginPos +0x40、pixelPerDistance +0x4C

**SpawnPoint 结构** = `{ Vector3 position; float rotaion; }`（16 字节，blittable，可直接 memcpy 造数组）

**Bot 关键字段**：thisPlayer +0x24、enemyInfo +0x28、actionList +0x58、seeker +0x78、path +0x80、gNode_Nearset +0x88、gNode_Next +0x8C、nextPathPos +0xA0、interpolator +0xBC、nanoGuard +0xC4、blockedTime +0xEC

### 3.3 假设（按可信度排序，逐条排除）

**H1（最可能）：隐藏图没有 MapManager 的出生点/补给点数据。**
SP_BL / SP_GR / SP_SupplyBox 全是 null → GetSpawnPoint 退化到同一个默认点（所有幽灵挤在一个「复活点」），补给箱协程每轮 NRE。
验证：Frida 读 MapManager.instance（Singleton 基类）的 +0x10 / +0x14 / +0x1C，看是否 0x0。
修：按几何自己造 `SpawnPoint[]`（il2cpp_array_new + memcpy），用 wbarrier 写回字段，再置 SPID_*。

**H2：Bot.Update 里的 NRE 就是「幽灵永远不动」的直接原因**（Update 抛异常 → 后面的 PathSetting / Move 全不执行 → path 永远 0x0，与证据 2 完全吻合）。
验证：`mcp__ida__decompile_function 0x10B33370`，看前几个解引用哪个可能为 null；再用 Frida 在 0x10B33370 hook 对比字段。
**先做这个对比实验**：切一张正常图，看 Player.log 还有没有 Bot.Update NRE。
- 还有 → 是我们注入污染（重点查那 147 个运行期 AddComponent 出来的 Bot_CrouchPos：组件缺序列化字段，Bot.Update 遍历 SpareList_* 时踩空）；
- 没有 → 是地图数据缺失，走 H1。

**H3：waypoint 覆盖不到出生点/室内。** build_waypoints() 从 y=300 向下 Raycast，**先打到屋顶**；粗采样 676 点只命中 35 个（日志 `coarse hits=35 bounds x[-50,30] z[-130,90]`），说明大多几何体没有 Collider 或不在 layer 0（Raycast 的 layerMask 传的是 1）。室内地面的节点可能其实是「屋顶上的节点」。
验证：在幽灵出生点正上方做一次 Raycast，打印命中体名字/layer/高度；再照抄 editor.c 的 `spawn_vis()` 把 826 个节点全画成小球截图，看是不是浮在屋顶。

**H4：跨层直线连边。** ConnectNodes() 按 3D 直线距离 ≤ 6 m 连边、不判高低差 → 屋顶节点与地面节点被连起来，A* 给出「穿楼」路径，bot 撞墙直到 `blockedTime (+0xEC)` 涨满就原地不动。
验证：hook `Bot.OnPathComplete (0xB31950)` 打印 path.vectorPath 前几个点，看 y 是否跳到屋顶高度。

### 3.4 建议修法顺序

1. 先做 H2 的「普通图对比」实验（5 分钟），决定方向；
2. 再做 H1（造 SpawnPoint 数组）；
3. 最后才动 waypoint 生成（改多高度分层采样 + slope 与高度差过滤）。

**别一次改三样**：每改一样进图看 Player.log 的 NRE 条数是否下降。

## 4. BUG B：退出游戏卡死

### 4.1 现有证据

- 现象：退出（回主菜单或关进程）时进程不退出 / 无响应。
- 代码现状：三个**游离后台线程**，退出时都没有停：
  - plugin.c 的 `worker()` —— `for (t < 100000) { ...; Sleep(1000); }`，每轮调 `il2cpp_field_static_get_value`；
  - navfix.c 的 `nav_worker()` —— **`for(;;)`** 每 500 ms 调 `astar_active()` → il2cpp_field_static_get_value，并 PostMessageA；
  - editor.c 的主线程侧工作（HUD / 材质 / GameObject 创建）。
- `NavProc` 用 `SetWindowLongPtrA(GWLP_WNDPROC)` 子类化窗口，**从不恢复**（没有 WM_DESTROY / WM_CLOSE / WM_ENDSESSION 处理）。
- DllMain 的 DLL_PROCESS_DETACH 是空的，线程不 join（DllMain 里也不该做）。

### 4.2 假设（按可信度）

**H1（最可能）：后台线程在 il2cpp 关闭过程中还在调 il2cpp API → 死锁。**
Unity 退出时 runtime 正在收尾，我们的线程正好在 il2cpp_field_static_get_value 里，或持有 runtime 锁 → 主线程等它、它等主线程。
**修法（推荐架构）**：后台线程**只做纯内存读**（`*(void**)addr` 这种）和 PostMessage，**所有 il2cpp 导出调用一律搬到主线程 WndProc 里执行**。加 `static volatile LONG g_quit` 闸门：在 WM_CLOSE / WM_QUERYENDSESSION / WM_DESTROY 里置 1，两个 worker 看到就 `Sleep(200); ExitThread(0)`，并且**绝不再进 il2cpp**。

**H2：WndProc 没恢复。** 退出时窗口销毁仍经过 NavProc → `CallWindowProcA(g_oldProc, ...)`，若旧 proc 已失效就是崩溃或挂死。
修：`case WM_DESTROY:` 里先 `SetWindowLongPtrA(h, GWLP_WNDPROC, (LONG_PTR)g_oldProc)` 再 CallWindowProcA，并把 g_oldProc 置 0。

**H3：NRE 洪泛本身拖慢退出**（1074 条 + 每秒格式化堆栈 + 写盘）。这条会随 BUG A 一起消失，不是独立 bug。

**H4：我们造的 826 + 147 个 GameObject / HUD Canvas / 材质在场景卸载时被 Destroy，后台线程还持有裸指针** → 退出时访问已释放对象。

### 4.3 排查顺序（按顺序，别猜）

1. **二分**：分别注释掉 plugin.c / navfix_start / editor_start 重建一次（只有 plugin、只加 navfix、只加 editor、全开），各退出 1 次，先定位模块。
2. 卡住时抓线程栈：任务管理器 → 右键 UnityCrossFire → 创建转储文件，或 `procdump -ma <pid> out.dmp`，看主线程等在哪个临界区 / 等哪个线程。
3. 看 Player.log 尾部有没有 OnApplicationQuit / Unloading / 异常。
4. 修完必须**连按 3 次退出**都干净（进程 5 s 内消失，任务管理器无残留），用 `Get-Process UnityCrossFire` 验证。

## 5. 硬约束（踩过的坑，别重犯）

1. 游戏在跑时**不要覆盖 ucf_mod.dll**（文件锁），先 Stop-Process UnityCrossFire -Force。
2. 用户可能同时在游戏里手动测试（放点、Ctrl+6 保存），标记数量会漂移 → 自动化测试要短促，别假设索引。
3. 脚本里别用 String.raw 包 Windows 路径，`\\ucf_mod` 里的 `\\u` 会被当 unicode 转义（本会话已踩）。
4. **所有 Unity/il2cpp API 必须在主线程调**（Transform / GameObject / Material / Physics）——现在是后台线程 PostMessage(WM_APP+0x5x) 到窗口线程执行。
5. CreatePrimitive 在运行期拿到的是 Hidden/InternalErrorShader（build 把 Standard 裁了）：必须自己 `Shader.Find` 建材质，`Universal Render Pipeline/Unlit` 可用（已按颜色缓存 4 个）。
6. 场景相机 `cullingMask = 0x1f3`（**layer 2 被剔除**）：编辑器标记球放 layer 0，碰撞体 Destroy 掉，别放 layer 2。
7. 中文 HUD 字体要从现有 UI Text 借 `font`（借不到才退 Arial.ttf 并切英文）。
8. 运行期 `AddComponent(Bot_NanoGuardArea)` 会崩（posList 为 null → Bot.Update 每帧 NRE），幽灵守点 / 区域 / 跳跃点三种标记**当前禁用**。要启用得先按规则造 `posList = List<Bot_NanoGuardPos>`、entrancePos / escapePos 非 null、zoomPos.Count ≥ 1，并让邻居互指。
