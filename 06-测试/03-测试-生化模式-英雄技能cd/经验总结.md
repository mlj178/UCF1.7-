**目标**：在《CF》生化模式中，让英雄技能（如幽灵之刃、苦行僧护盾等）无冷却，可连续使用。

**核心难题**：

## 二、方案探索：从定位实例到选择修改方式

### 2.1 定位 `Skill_Common` 实例的路径

根据 dump.cs 中的类型定义：

| 类             | 字段名         | 偏移（64位） | 说明                        |
| -------------- | -------------- | ------------ | --------------------------- |
| `Player`       | `playerSkills` | 0xB0         | `PlayerSkills*`             |
| `PlayerSkills` | `all`          | 0x08         | `Skill[]` 数组对象指针      |
| `System.Array` | 长度           | 0x10         | `int32`                     |
| `System.Array` | 元素列表       | 0x18         | 连续 `void*`，每元素 8 字节 |

因此，获取所有技能实例的流程为：
```
Player → +0xB0 → PlayerSkills → +0x08 → Skill[] → 遍历每个元素
```

### 2.2 类型筛选：如何只取 `Skill_Common`？

数组中可能包含多种技能类型（`Skill_Common`, `Skill_ModeChange`, `Skill_SentryGun` 等）。需要筛选。

#### 方案 A：通过虚表比对（最可靠）
- 原理：每个 C# 对象的前 8 字节指向其类的虚表（vtable），同一类的实例虚表相同。
- 步骤：
  1. 通过 il2cpp-bridge 获取 `Skill_Common` 类的虚表地址（或硬编码 RVA）。
  2. 遍历技能数组时，读取每个对象的前 8 字节，若与目标虚表相等，则确定为 `Skill_Common`。
- 优点：100% 准确，不受字段偏移变化影响。
- 缺点：需要 il2cpp-bridge 支持（或手动寻找虚表 RVA）。

#### 方案 B：通过特征字段值猜测（快速但粗糙）
- 原理：`Skill_Common` 特有字段 `coldFinishTime` 通常为一个浮点数（0 或很大的未来时间）。
- 实现：读取每个对象 `+0x28`（猜测偏移）处的浮点值，若在合理范围（0~999999）内，则认为是 `Skill_Common`。
- 缺点：偏移不固定，且可能与其他类型的浮点字段混淆。

#### 最终选择：优先采用虚表比对，若无 bridge 则退化为特征值 + 运行时偏移校准。

### 2.3 修改 CD 的三种技术路线

在定位到实例后，如何实现“无 CD”？你与 AI 讨论了三种可能的方法。

#### 方法 1：直接修改 `coldFinishTime` 字段（最简单，最终采用）

**原理**：游戏逻辑中，每次尝试使用技能时，会比较当前时间与 `coldFinishTime`，若当前时间大于等于 `coldFinishTime`，则允许使用。将该字段写为 0（或当前时间 - 1），即可绕过检查。

**实现**：
```js
skillCommonPtr.add(coldFinishOffset).writeFloat(0);
```

**优点**：
- 实现简单，一条汇编指令即可。
- 不需要深入理解技能调用的完整逻辑。
- 修改后立即生效，无副作用。

**缺点**：
- 需要知道 `coldFinishTime` 的精确偏移（不同版本可能不同）。
- 如果技能在持续期间多次检查冷卻（例如持续引导技能），可能需要每帧都写入。

#### 方法 2：Hook 技能可用性判断函数

**原理**：找到 `Skill_Common.CanUse()` 或 `Skill_Common.get_IsCoolingDown()` 等属性 getter，Hook 其返回值，强制返回 `true`。

**优点**：
- 不依赖具体字段偏移，只依赖方法 RVA。
- 即使冷卻逻辑复杂（如多个条件组合），也能一刀切。

**缺点**：
- 需要定位正确的方法 RVA（可能内联或优化后难以找到）。
- Hook 后可能破坏其他逻辑（如 UI 显示冷卻进度）。

#### 方法 3：主动调用技能结束方法

**原理**：找到 `Skill_Common.OnCooldownEnd()` 或 `ResetCooldown()` 等方法，在技能使用后立即主动调用，强制结束冷卻。

**优点**：
- 理论上最“合法”的修改方式，完全按照游戏设计的流程。

**缺点**：
- 需要逆向出正确的方法及调用约定。
- 可能涉及更复杂的游戏对象状态，容易出错。

#### 讨论与取舍

你与 AI 经过讨论后认为：
- **方法 1（直接改字段）** 是最简单、最直接的，且风险最低。即使字段偏移不确定，也可以运行时动态搜索。
- **方法 2（Hook）** 可以作为备用，如果字段偏移变化频繁，而方法 RVA 相对稳定，则 Hook 更优。
- **方法 3（主动调用）** 过于复杂，不值得在初期尝试。

最终，AI 为你提供了基于**修改字段**的完整脚本，并同时给出了**如何通过虚表或特征值定位偏移**的自适应方法。

## 三、实现过程中的关键决策与演变

### 3.1 第一阶段：直接从内存读取（参考已有 `get_myplayer`）

你提供了 `get_myplayer` 脚本，其中已经实现了安全读取指针、读取字符串等功能。AI 在此基础上扩展了技能数组遍历函数。

**代码雏形**：
```js
function getSkillCommonInstances(playerSkillsPtr) {
    let arr = readPtr(playerSkillsPtr.add(0x8));
    let len = readI32(arr.add(0x10));
    let instances = [];
    for (let i = 0; i < len; i++) {
        let elem = arr.add(0x18 + i * 8).readPointer();
        if (elem) instances.push(elem);
    }
    return instances;
}
```

**问题**：没有类型筛选，会包含所有技能类型。

### 3.2 第二阶段：增加虚表比对（推荐）

你希望更准确地只取 `Skill_Common`。AI 建议使用 il2cpp-bridge 获取虚表。

```js
if (typeof Il2Cpp !== 'undefined') {
    let klass = Il2Cpp.Domain.assembly('Assembly-CSharp').image.class('Skill_Common');
    let vt = klass.vtable;
    // 然后比对
    if (elem.readPointer().equals(vt)) { /* 正确类型 */ }
}
```

**讨论**：你担心 il2cpp-bridge 在某些环境下不可用。AI 提供了备选方案：**通过读取 `coldFinishTime` 特征值**，并建议运行时动态搜索该字段的偏移。

### 3.3 第三阶段：运行时动态定位 `coldFinishTime` 偏移

为了避免硬编码偏移，AI 设计了**自动校准**函数：
```js
function findColdFinishOffset(skillCommonPtr) {
    for (let off = 0x20; off <= 0x40; off += 4) {
        let val = readF32(skillCommonPtr.add(off));
        if (val > 0 && val < 1000000) { // 合理范围
            return off;
        }
    }
    return null;
}
```
这样即使游戏更新导致偏移变化，脚本也能自适应。

### 3.4 第四阶段：实现“无 CD”的持续写入 vs 一次性写入

你提出一个问题：如果修改一次 `coldFinishTime` 后，技能使用后该字段会被游戏重新赋值为未来时间（冷卻开始），那么一次写入只能使技能免 CD 一次。

解决方案有两种：
- **定时器持续写入**：每隔 0.1 秒将所有 `Skill_Common` 的 `coldFinishTime` 强制置 0。缺点是小幅性能开销。
- **Hook 技能使用后的重置函数**：在技能被调用后立即再次写 0，更为精准。

经过讨论，你选择了 **定时器持续写入**（因为实现简单，且对性能影响极小）。AI 给出了代码：
```js
setInterval(() => {
    let skills = getAllSkillCommon();
    skills.forEach(s => s.add(offset).writeFloat(0));
}, 100);
```

### 3.5 关于主动调用方法的最后考虑

你曾问：“是否可以直接调用 `Skill_Common.ResetCooldown()` 这样的函数？” AI 分析后指出：
- 该函数可能不存在于基类中，需要具体分析子类。
- 主动调用需要传入 `this` 指针，且可能涉及其他状态重置，风险较大。
- 因此不作为主要方案，但可以作为扩展点（如果未来需要更精细的控制）。

## 四、最终脚本核心逻辑（集成版）

```js
// 等待游戏模块加载，Hook isMyPlayer 获取本地玩家
// 然后执行以下逻辑：

function disableAllSkillsCooldown() {
    let playerSkills = myPlayer.add(0xB0).readPointer();
    let arr = playerSkills.add(0x8).readPointer();
    let len = arr.add(0x10).readS32();
    let coldOffset = 0x28; // 可由 findColdFinishOffset 动态获得
    for (let i = 0; i < len; i++) {
        let skill = arr.add(0x18 + i * 8).readPointer();
        if (isSkillCommon(skill)) {   // 虚表比对或特征值判断
            skill.add(coldOffset).writeFloat(0);
        }
    }
}

// 可选：启动定时器持续写入
let timer = setInterval(disableAllSkillsCooldown, 100);
```

**导出函数供 Python 调用**（通过 `rpc.exports`）：
```js
rpc.exports = {
    no_cd: function(enable) {
        if (enable) {
            timer = setInterval(disableAllSkillsCooldown, 100);
        } else {
            clearInterval(timer);
        }
    }
};
```

## 六、经验总结与注意事项

| 问题                                 | 解决方案                                | 理由                                     |
| ------------------------------------ | --------------------------------------- | ---------------------------------------- |
| 如何定位技能实例                     | 通过 `Player → PlayerSkills → all` 数组 | 已知偏移，简单可靠                       |
| 如何区分 `Skill_Common`              | 虚表比对（优先）或特征值                | 准确无误                                 |
| `coldFinishTime` 偏移不确定          | 运行时动态扫描                          | 自适应游戏版本                           |
| 技能使用后冷卻重新开始               | 定时器持续写入                          | 简单有效                                 |
| 是修改字段还是 Hook 还是主动调用     | 修改字段                                | 最小侵入，稳定性最高                     |
| 主线程阻塞问题（Python 调用 RPC 时） | 将 RPC 调用移到子线程                   | 避免 UI 卡顿（与 JS 无关，但提醒你注意） |
